
# Zprotect Vm 代码的 2 种处理方法

> 原文：[`www.pediy.com/kssd/pediy11/97066.html`](https://www.pediy.com/kssd/pediy11/97066.html)

ZP 的 VM 比较简单,只模拟 PUSH 和 JCC 这 2 种类型指令,其他的全部都是明文保留,用乱序 JMP 连接.由于没有 ANTI DUMP,所以可以补区段,把 ZP 的 SHELL DLL 所在区段以及后面的几个段一起补到 DUMP+FIX IAT 之后之后的程序中即可,包括 VISO 引擎处理过的代码也可以这样处理,一般脱壳这样也就可以了,如果被处理的代码中有我们感兴趣的地方,于是不得不寻求修复代码的方法.

由于我对 VM 一无所知,所以我将其当做代码变形来处理.

这里原本是乱序过的 跟起来比较累,处理方法有 2 种,一是修改主程序,强迫它不变形;第二种是提取主程序中的功能 DLL,这个 DLL 是裸体的,修改下重定位,把对应代码贴过来即可.

通过

```
引用: 00A5A863    8BFF            mov edi,edi
00A5A865    E9 7A210000     jmp 00A5C9E4                       ; 00A5C9E4
```

连续 4 个 `mov edi,edi` 分支判断是哪种指令,分别跳往各自的处理流程.

`ECX` 中对应的是寄存器类型参数,对应关系如下

```
引用: eax  25
ecx  26
edx  27
ebx  28
esp  29
ebp  2a
esi  2b
edi  2c
```

如果 PUSH 后面的操作数是常数则不执行此流程,直接在 `FF15` 后给出数值.
