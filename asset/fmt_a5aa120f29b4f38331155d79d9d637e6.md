
# 逆向工程还原指南

## 一、导入表还原

从 `.idata:00403098` 获取导入信息，主要包含以下 API 函数：

```
.idata:0040309C ; LRESULT __stdcall CallWindowProcA(WNDPROC lpPrevWndFunc,HWND hWnd,UINT Msg,WPARAM wParam,LPARAM lParam)
.idata:0040309C                 extrn __imp_CallWindowProcA:dword
.idata:0040309C                                 ; DATA XREF: CallWindowProcAr

.idata:004030A0 ; BOOL __stdcall ShowWindow(HWND hWnd,int nCmdShow)
.idata:004030A0                 extrn __imp_ShowWindow:dword ; DATA XREF: ShowWindowr

.idata:004030A4 ; int wsprintfA(LPSTR,LPCSTR,...)
.idata:004030A4                 extrn __imp_wsprintfA:dword ; DATA XREF: wsprintfAr

.idata:004030A8
```

通过分析可知，程序使用了四个 DLL：`comdlg32.dll`、`gdi32.dll`、`kernel32.dll` 和 `user32.dll`。因此，还原的 `include` 和 `includelib` 指令必须包含这几个 DLL。

将汇编头部指令：

```
.686p
.mmx
.model flat
```

还原为：

```
.686p
.mmx
.model flat,stdcall
option casemap:none
include WINDOWS.INC
include comdlg32.inc
includelib comdlg32.lib
include gdi32.inc
includelib gdi32.lib
include kernel32.inc
includelib kernel32.lib
include user32.inc
includelib user32.lib
```

同时，删除代码中前面的 `.idata` 段。

## 二、删除结构定义

在 `RadASM` 中按 `Ctrl+F5` 尝试构建并运行，出现如下错误提示：

```
D:\masm32\Include\WINDOWS.INC(9666) : error A2163:  : LOGFONTA
D:\masm32\Include\WINDOWS.INC(9667) : error A2163:  : LOGFONTA
D:\masm32\Include\WINDOWS.INC(9668) : error A2163:  : LOGFONTA
D:\masm32\Include\WINDOWS.INC(9669) : error A2163:  : LOGFONTA
D:\masm32\Include\WINDOWS.INC(9670) : error A2163:  : LOGFONTA
```

由此判断是 `1.asm` 中的 `LOGFONTA` 定义导致出错。需删除开头的 `LOGFONTA` 结构定义，并将 `tagOFNA` 结构移动到 `includelib user32.lib` 之后。

## 三、移动 `_data` 段

在 `_text` 段前增加 `.data` 段声明。

将 `_data` 段的所有内容移到 `.data` 之后。

删除 `_data` 段开头的定义：

```
_data    segment  para public 'DATA' use32
        assume cs:_data
```

以及 `_data` 段末尾的结束符：

```
_data    ends
```

**注意：** 中间的代码不要删除。

## 四、修改 `_text` 段

在 `_text` 段前加上 `.code` 段声明：

```
_text    segment  para public 'CODE' use32   ; 在这之前加上 .code
```

删除 `_text` 段开头的定义：

```
_text    segment  para public 'CODE' use32
        assume cs:_text
        ;org 401000h
        assume es:nothing, ss:nothing, ds:_data, fs:nothing, gs:nothing
```

以及 `_text` 段末尾的结束符：

```
_text    ends
```

**注意：** 中间的代码不要删除。

## 五、修改 `hWnd` 变量冲突

在 `RadASM` 中按 `Ctrl+F5` 构建并运行，出现以下错误：

```
D:\crack\国外工具\tf10\1.asm(834) : error A2005:  : hWnd
D:\crack\国外工具\tf10\1.asm(1286) : error A2005:  : hWnd
D:\crack\国外工具\tf10\1.asm(1499) : error A2005:  : hWnd
D:\crack\国外工具\tf10\1.asm(1640) : error A2005:  : hWnd
D:\crack\国外工具\tf10\1.asm(2609) : error A2189:  : 128
D:\crack\国外工具\tf10\1.asm(821) : error A2005:  : hWnd
D:\crack\国外工具\tf10\1.asm(1277) : error A2005:  : hWnd
D:\crack\国外工具\tf10\1.asm(1489) : error A2005:  : hWnd
D:\crack\国外工具\tf10\1.asm(1629) : error A2005:  : hWnd
```

### 1. 定位全局变量

在 `.data` 段寻找 `hWnd`：

```asm
; HWND hWnd
hWnd    dd 0      ; DATA XREF: DialogFunc+241r
                 ; DialogFunc+264w DialogFunc+26Dr
                 ; DialogFunc+28Br DialogFunc+29Dr
                 ; sub_401500+9r ...
```

提示两个函数 `DialogFunc` 和 `sub_401500` 用到了这个全局变量 `hWnd`。其他函数中出现的 `hWnd` 错误是由于局部变量与全局变量冲突。

### 2. 修改 `sub_401500`

错误位置：`1.asm(834) : error A2005:  : hWnd`

找到 `sub_401500` 定义：

```asm
sub_401500  proc near    ; CODE XREF: DialogFunc+21Fp

var_18    = dword  ptr -18h
var_14    = dword  ptr -14h
var_10    = dword  ptr -10h
var_C     = dword  ptr -0Ch
hWnd      = dword  ptr -8    ; 这里出错，局部变量 hWnd 与全局变量 hWnd 冲突
lpMem     = dword  ptr -4
hDlg      = dword  ptr  8
```

在 IDA 中打开 Functions 窗口，找到 `sub_401500`：

```
sub_401500            .text 00401500 00000291 R . . . B T .
```

双击进入 `sub_401500`，查看对应地址代码：

```asm
.text:00401500 sub_401500     proc near               ; CODE XREF: DialogFunc+21Fp
.text:00401500
.text:00401500 var_18         = dword ptr -18h
.text:00401500 var_14         = dword ptr -14h
.text:00401500 var_10         = dword ptr -10h
.text:00401500 var_C          = dword ptr -0Ch
.text:00401500 hWnd           = dword ptr -8    ; 修改这里为 hWnd1
.text:00401500 lpMem          = dword ptr -4
.text:00401500 hDlg           = dword ptr  8
```

在 IDA 中对 `hWnd` 右键重命名为 `hWnd1`。

**建议：** 推荐在 IDA 中重命名，经过修改后 IDA 能自动识别全局变量 `hWnd` 和 `hWnd1` 的区别，比手动修改更快且正确率更高。

### 3. 修改 `sub_401810`

错误位置：`1.asm(1286) : error A2005:  : hWnd`

找到 `sub_401810` 定义：

```asm
sub_401810  proc near    ; CODE XREF: sub_401380+130p

hWnd      = dword  ptr -8    ; 在 IDA 中修改为 hWnd1
lpMem     = dword  ptr -4
hDlg      = dword  ptr  8
```

### 4. 修改 `sub_401A10`

错误位置：`1.asm(1499) : error A2005:  : hWnd`

找到 `sub_401A10` 定义：

```asm
sub_401A10  proc near    ; CODE XREF: DialogFunc+233p

var_8     = dword  ptr -8
hWnd      = dword  ptr -4    ; 在 IDA 中修改为 hWnd1
hDlg      = dword  ptr  8
```

### 5. 修改 `sub_401B6C`

错误位置：`1.asm(1640) : error A2005:  : hWnd`

找到 `sub_401B6C` 定义：

```asm
sub_401B6C  proc near    ; DATA XREF: DialogFunc+9Eo
                         ; DialogFunc+CBo sub_401380+57o

hWnd      = dword  ptr  8    ; 这个不是局部变量
Msg       = dword  ptr  0Ch
wParam    = dword  ptr  10h
lParam    = dword  ptr  14h
```

因为这里不是局部变量冲突，需先修改前面的三个函数 `sub_401500`、`sub_401810`、`sub_401A10`。

保存修改后的代码为 `2.asm`，接着把 `1.asm` 里的 `sub_401500`、`sub_401810`、`sub_401A10` 这三个函数全部用 `2.asm` 里的对应版本替换。

接着在 `RadASM` 中按 `Ctrl+F5` 构建并运行，剩余错误：

```
D:\crack\国外工具\tf10\1.asm(1640) : error A2005:  : hWnd
D:\crack\国外工具\tf10\1.asm(2609) : error A2189:  : 128
D:\crack\国外工具\tf10\1.asm(1629) : error A2005:  : hWnd
```

看来 `sub_401B6C` 中的 `hWnd` 也需要修改。在 IDA 中修改后覆盖回 `1.asm`。

此时 `hWnd` 相关错误已消除，剩余错误：

```
D:\crack\国外工具\tf10\1.asm(2609) : error A2189:  : 128
```

## 六、删除 `align` 指令

错误位置：`1.asm(2609) : error A2189:  : 128`

这里的 `128` 是由 `align` 指令导致的，直接删除该 `align` 指令即可。
