
## 引用

得到木马存放路径的地址：`"C:\\WINDOWS\\system32\\dbr07028.ocx"`

`Decrypt_PostAddress` 函数参数为当前模块的执行路径。

功能：读取当前执行文件的末尾 `0x21C` 个数据，执行解密另存。其实就是移位运算。

解密的数据是盗取帐号存入的地方。

继续创建路径：`"C:\\WINDOWS\\fonts\\dbr07028.ttf"`，应该是另存的地方。

`_CreateFile_Encryption` 函数创建 `"C:\\WINDOWS\\fonts\\dbr07028.ttf"`。

然后以系统时间创建个临时文件，并调用 `GetTempPath_Set` 函数得到当前用户运行临时目录 `\\xxx.temp`。当返回值传出。

调用 `CreateTempFile` 函数，首先查找名为 `66` 的资源，得到资源大小为 `9200`，装载之。然后把此数据写入到刚刚创建的临时目录中。

然后将此文件 `MoveFile` 到 `"C:\\WINDOWS\\system32\\dbr07028.ocx"`。

在创建 `XXime.temp` 的临时文件，继续调用 `GetTempPath_Set` 函数。再调用 `CreateTempFile`。

调用 `MyGetWindowsDirectory`，得到一个 `C:\\WINDOWS\\system32\\winnt.com` 的文件。继续调用 `movFile`，移动临时文件到这个 windows 目录改名为 `winnt.com`。

又重复上个步骤，得到 `XX.temp`...复制到 `C:\\WINDOWS\\system32\\dbr99005.ocx`。

得到 `rundll32.exe` 的路径，想拷贝到 `C:\\WINDOWS\\system32\\gbvgbv07.exe`。

下面则 (HOOK) 注入 `explorer.exe`。`FindExplorer` 函数，参数有 2 个，字符型数组。

`LoadLibrary`：`kernel32.dll` `GetProcAddress`。得到下面 3 个函数地址。存到全局变量。

```
0x7C865B1C  得到 CreateToolhelp32Snapshot
0x7C864DF3  得到 Process32First
0x7C864F65  得到 Process32Next
```

发现下，是不是系统函数的前 3 字节都是 `nop`...直接调用，这样是不是可以不被杀软杀到....

`CreateToolhelp32Snapshot`

`Process32First`

`Process32Next`

这 3 个函数合起来可以干什么，你想想可以干什么呢..

注入 `explorer.exe` 然后向进程写入 `C:\\WINDOWS\\system32\\winnt.com`，先调用 `VirtualAllocEx`，申请空间。

创建远程线程，`CreateRemoteThread`，运行的函数为 `LoadLibraryA`，参数是刚申请的空间地址，就是 `winnt.com` 所在的地址。

看过核心编程的里面应该知道这种方法。

用的是输入法注入，来截帐号密码... 。
