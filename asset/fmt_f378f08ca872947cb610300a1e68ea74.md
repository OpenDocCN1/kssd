### 密码表与处理逻辑分析

系统内包含两套密码表，均经过动态改变：
1. 第一套用于处理用户名。
2. 第二套有两处用途：
   - 处理输入码标志位时；
   - 还原由用户名计算出的结果时（此时还需使用标志位赋值）。

这两处的函数逻辑是互相可逆的。

**输入码格式**：
前 4 位 - 中间 8 位 - 后 4 位，共计 16 位。在计算过程中，将其分为前 8 位和后 8 位两部分。

**处理流程**：
1. **第一步**：获取输入码，使用内部密码表动态修改后的密码表 1（包含 1024 个密码）进行取值和运算，得到 16 位值。取前三位（内存中可见的值）作为标志位（实际上只有一位起作用）。
2. **第二步**：获取用户名，使用内部密码表动态修改后的密码表 2（包含 1024 个密码）进行取值和运算，得到 16 位值。将第一步得到的标志位赋予第二步结果的前 3 位（内存中可见的值），记为 `A`。
3. **第三步**：对 `A` 在密码表 1 中进行一系列运算，再次得到 16 位值（此过程实为第一步的逆过程）。

最后，将第三步得到的值与原始输入码进行比较。若不等，则触发读狗；若相等，则进一步比较标志位，以确定所属版本。

unsigned long int zhi, mimabiao[];
{
    unsigned long int a12, a34, a56, a78, jieguo;
    a12 = zhi >> 24;
    a34 = zhi << 8;
    a34 = a34 >> 24;
    a56 = zhi << 16;
    a56 = a56 >> 24;
    a78 = zhi << 24;
    a78 = a78 >> 24;

void chucun(yhm)
