
## 1. Enable FFF80000h-FFFDFFFFh Decoding

Enable `FFF80000h`-`FFFDFFFFh` decoding. Access to this address will be routed directly to the `bios rom` chip via the `PCI-to-ISA` bridge. The `PCI-to-ISA` bridge ROM decode control register manages this here. This is necessary because my 256KB `bios` chip has only 128KB copied to RAM; for example, `original.tmp` and `bootblock` are currently located at addresses `1000:0000h`-`2000:FFFFh`.

### 7.1.6.2. Copy lower 128KB of BIOS code from ROM chip into RAM

Copy the lower 128KB of `bios` code from `ROM` chip at `FFFC_0000h`-`FFFD_FFFF` to RAM at `8000:0000h` - `9000:FFFFh`.

### 7.1.6.3. Disable FFF8_0000h-FFFD_FFFFh decoding

Disable `FFF8_0000h`-`FFFD_FFFF` decoding. Access to this address will no longer go through the `PCI-to-ISA` bridge to the `bios rom` chip.

### 7.1.6.4. Verify checksum of the whole compressed BIOS image

Modify the checksum of the entire `bios` image. Calculate the 8-bit checksum of the compressed data in memory RAM (e.g., `8000:0000h` - `9000:FFFFh` + `1000:0000h` - `2000:7FFDh`) and compare the result with the value stored at `2000:7FFEh`. If the 8-bit value does not match, jump to `_sysbios_chksum_err`; otherwise, continue with the decompression routine.

### 7.1.6.5. Look for the decompression engine

Find the decompression engine by searching for `*BBSS*` in segment `2000h`.

### 7.1.6.6. Decompress the compressed BIOS components

Decompress the compressed `bios` sections by calling the decompression engine described above. Note that in this step, only `original.tmp` and its extensions (`awardext.rom`) are decompressed (other versions of `awardext.rom` may also apply, but I have not verified this). Other sections are handled via different methods. This decompression routine only processes its own decompression and compression areas, placing them in specific locations in RAM. We need some preliminary information before delving into this step:

#### 7.1.6.6.a. The format of the LZH level-1 compressed bios components

**A. LAH level-1 compressed bios component format**

The address ranges of these `bios` sections after decompression also follow this structure. The structure is as follows (applicable to all compressed sections):

| Offset from 1st byte | Offset in Real Header | Contents |
| :--- | :--- | :--- |
| `00h` | N/A | The header length of the component. It depends on the file/component name. |
| `01h` | N/A | The header 8-bit checksum, not including the first 2 bytes (header length and header checksum byte). |
| `02h` - `06h` | `00h` - `04h` | `LZH` Method ID (ASCII string signature). In my BIOS it's `"-lh5-"` which means: `8k` sliding dictionary (max `256` bytes) + `static` `Huffman` + improved encoding of position and trees. |
| `07h` - `0Ah` | `05h` - `08h` | Compressed file/component size in little endian `dword` value, i.e., `MSB` at `0Ah` and so forth |
| `0Bh` - `0Eh` | `09h` - `0Ch` | Uncompressed file/component size in little endian `dword` value, i.e., `MSB` at `0Eh` and so forth |
| `0Fh` - `10h` | `0Dh` - `0Eh` | Decompression offset address in little endian `word` value, i.e., `MSB` at `10h` and so forth. The component will be decompressed into this offset address (real mode addressing is in effect here). |
| `11h` - `12h` | `0Fh` - `10h` | Decompression segment address in little endian `word` value, i.e., `MSB` at `12h` and so forth. The component will be decompressed into this segment address (real mode addressing is in effect here). |
| `13h` | `11h` | File attribute. My BIOS components contain `20h` here, which is normally found in `LZH` level-1 compressed file. |
| `14h` | `12h` | Level. My BIOS components contain `01h` here, which means it's a `LZH` level-1 compressed file. |
| `15h` | `13h` | Component filename length in byte. |
| `16h` - `[15h+filename_len]` | `14h` - `[13h+filename_len]` | Component filename (ASCII string) |
| `[16h+filename_len]` - `[17h+filename_len]` | `[14h+filename_len]` - `[15h+filename_len]` | File/component `CRC-16` in little endian `word` value, i.e., `MSB` at `[HeaderSize - 2h]` and so forth. |
| `[18h+filename_len]` | `[16h+filename_len]` | Operating System ID. In my BIOS it's always `20h` (ASCII space character) which doesn't resemble any known `LZH` OS ID to me. |
| `[19h+filename_len]` - `[1Ah+filename_len]` | `[17h+filename_len]` - `[18h+filename_len]` | Next header size. In my BIOS it's always `0000h` which means no extension header. |

**Notes:**

1. The addresses in the leftmost column and those used in the table are calculated from the first byte of the section. This "Real Header offset" is used as explained in the "Note RAM" above.
2. Each section ends with an `EOF` byte, e.g., `00h` byte.
3. In my `bios`, there is a `read_header` routine containing routines to read and write this header content. Accessing `Calc_LZH_hdr_CRC16` has a critical "procedure call"; it reads this `bios` section header into "Notebook" RAM starting from `3000:0000h` (`ds:0000h`). This notebook area is filled with "real-LZH-header value", excluding the first 2 bytes (header size, header 8-bit checksum), but including the third byte (offset `02h`) until `HeaderSize+02h`.

#### 7.1.6.6.b. The location of various checksums

**B. Different checksum locations before and during decompression:**

| Location | Calculation Method |
| :--- | :--- |
| Right after compressed `original.tmp` | `original.tmp` 8-bit checksum. This value is calculated after it's copied to RAM at segment `1000h` and `2000h`. The code is as follows: |

```assembly
; Address  Assembly Code
2000:E307  ; verify System_BIOS checksum
2000:E307    mov   ax, 1000h
2000:E30A    mov   ds, ax              ; ds = E_seg_in_RAM
2000:E30C    assume ds:_1000h
2000:E30C    mov   bx, cmprssd_size_hi_word
2000:E310    mov   cx, cmprssd_size_lo_word
2000:E314    add   cl, hdr_len         ; cl = LZH hdrlen
2000:E318    adc   ch, 0
2000:E31B    adc   bx, 0
2000:E31E    add   cx, 3
2000:E321    adc   bx, 0
2000:E324    jz    short hi_word_zero
2000:E326    mov   bx, cx
2000:E328    xor   cx, cx
2000:E32A  hi_word_zero:               ; CODE XREF: 0002E324
2000:E32A    xor   si, si
2000:E32C    xor   ah, ah
2000:E32E  _next_byte:                 ; CODE XREF: 0002E331 0002E343
2000:E32E    lodsb
2000:E32F    add   ah, al
2000:E331    loop  _next_byte
2000:E333    or    bx, bx              ; compressed BIOS bigger than 64kb ?
2000:E335    jz    short cmp_chksum
2000:E337    mov   cx, bx
2000:E339    mov   bx, ds
2000:E33B    add   bx, 1000h           ; proceed to F_seg in RAM
2000:E33F    mov   ds, bx
2000:E341    assume ds:_2000h
2000:E341    xor   bx, bx
2000:E343    jmp   short _next_byte
2000:E345  ; ---------------------------------------------------------------------------
2000:E345  cmp_chksum:                 ; CODE XREF: 0002E335
2000:E345    cmp   ah, [si]            ; cmp calc-ed original.tmp chksum with
                                        ; chksum in BIOS image
2000:E347    jnz   _sysbios_chksum_error
```

| Location | Calculation Method |
| :--- | :--- |
| Right after the decompression engine | This is the 8-bit checksum of the decompression engine which starts at `F000:7000h` (`2000:7000h` after copied to RAM) in my BIOS. I guess this is the thing that some people call Decompression Block. The code is as follows: |

```assembly
; Address  Assembly Code
2000:E35E  ; Verify checksum of decompress engine
2000:E35E    mov   ds, ax              ; ds = 2700h (2000:7000h)
2000:E360    assume ds:nothing
2000:E360    xor   ah, ah
2000:E362    xor   si, si
2000:E364    mov   cx, 0FFFh           ; cx = size of BBSS_engine (4KB-1)
2000:E367  __next_byte:                ; CODE XREF: 0002E36A
2000:E367    lodsb
2000:E368    add   ah, al
2000:E36A    loop  __next_byte
2000:E36C    cmp   ah, [si]            ; decompression engine chksum OK ?
2000:E36E    jnz   short _sysbios_chksum_error
```

| Location | Calculation Method |
| :--- | :--- |
| 1 byte before decompression engine checksum (that's explained above) | This is the 8-bit checksum of all compressed BIOS plus the 8-bit checksum of the decompression engine (not including its previously calculated checksum above). The code is: |

```assembly
; Address  Assembly Code
2000:E512    call  Copy_C_seg_n_D_seg  ; copy lower 128 KByte bios code from ROM (at FFFC_0000h -
                                        ; FFFD_0000h) to RAM (at 8000:0000h-9000:FFFFh)
2000:E515    xor   ah, ah
2000:E517    xor   cx, cx
2000:E519    mov   bx, 8000h
2000:E51C    mov   ds, bx              ; ds = 8000h, contains compressed
                                        ; lower 128KB bios components (awdext,etc.)
2000:E51E    assume ds:nothing
2000:E51E    xor   si, si
2000:E520  next_Cseg_Dseg_byte:        ; CODE XREF: Decompress_System_BIOS+11
                                        ; Decompress_System_BIOS+1F
2000:E520    lodsb
2000:E521    add   ah, al              ; calc 8-bit chksum of C_seg n D_seg
2000:E523    loop  next_Cseg_Dseg_byte
2000:E525    mov   bx, ds
2000:E527    cmp   bh, 90h             ; are we in seg 9000h?
2000:E52A    jnb   short done
2000:E52C    add   bh, 10h            ; move to next higher segment
2000:E52F    mov   ds, bx
2000:E531    assume ds:nothing
2000:E531    jmp   short next_Cseg_Dseg_byte
```
