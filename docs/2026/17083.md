三、内网穿透
dockerfile通常会作为dockers容器部署开发环境的时候会使用的一个模板开发文件。这个模板文件中包含如何去引入docker映像，如何对这个映像进行配置和安装软件包，修改服务项 等都会在这个模板文件中存在。利用这个文件可以在生产的服务器上大量的批量的部署docker容器。
![图片描述](upload/attach/202305/878276\_3SWP4MY43W2Y6R8.png)
查看该文件，可以看到标准的docker模板的操作指令
![图片描述](upload/attach/202305/878276\_B5HBSFVX3FQYZAD.png)
使用命令：ls /.dockerenv 或者 cat /proc/1/cgroup（1表示初始化文件） 如果有结果那说明是一个docker系统而不是安装在服务器上的系统
如何检测是否是docker系统？
通过查看是否存在dockerenv这个文件，如果存在则大概率就是一个docker容器系统。
查看/proc/1/cgroup文件：（1代表系统的初始化进程id 当初始化进程id的cgroup文件中包含着明确的docker信息则百分百是个docker容器） 随后想办法从隔离的docker容器中突破出来找到宿主机，拿到root权限
![图片描述](upload/attach/202305/878276\_FMG2QSNP8KF5WMH.png)
可以将docker容器所处的网段视为当前的内网网段 可以对内网网段进行主机发现，看看该网段中是否还存在其他主机
![图片描述](upload/attach/202305/878276\_DAVVG564CKRJ62A.png)
16个网段，存在65535个ip
主机发现：ping -c 对内网中的每个ip都ping一遍 或者通过脚本循环ping：for i in $(seq 1 10); do ping -c 1 ip.$i;done
![图片描述](upload/attach/202305/878276\_CRC2NT4RA8MMP6M.png)
# 四、内网穿透
扫出来的172.17.0.1和172.17.0.1位于内网网段，利用kali上的工具去探测内网网段默认情况下道路不通，此时要使用内网穿透技术。
使用内网穿透技术，将内网和kali的网络路由打通 常用的工具：venom
利用venom可以在内网和kali之间建立一个隧道，通过这个隧道生成一个代理 让其他工具可以基于这个代理对内网进行扫描
首先将这个隧道的客户端程序传输拷贝到目标系统上，再与kali上的服务端程序建立隧道
在Kali主机Venom目录启动Python3 Http Server 再回到目标容器系统，通过wget去访问kali主机上的http服务
![图片描述](upload/attach/202305/878276\_994N4G6U9KD65EB.png)
venom报错：zsh: 没有那个文件或目录: /home/chey/桌面/Venom 排查后发现是因为文件名有空格 将空格删掉之后就能正常运行了
运行服务端，本地监听9999端口等待目标容器系统建立监听：
![图片描述](upload/attach/202305/878276\_9JCUYRAM33PC2PU.png)
![图片描述](upload/attach/202305/878276\_QP2EPRHTGAZZAY4.png)

![图片描述](upload/attach/202305/878276\_373SABYFRFKW88F.png)
如果wget失败就重启一遍服务（应该在kali装一个nginx之类的server端 开http 然后配置文件里会有一个类似root\_dir的配置 还是web\_dir 类似的 配好了重新起一下服务 不出意外的话应该不会出现这种问题 ）

三、内网穿透
dockerfile通常会作为dockers容器部署开发环境的时候会使用的一个模板开发文件。这个模板文件中包含如何去引入docker映像，如何对这个映像进行配置和安装软件包，修改服务项 等都会在这个模板文件中存在。利用这个文件可以在生产的服务器上大量的批量的部署docker容器。
 ![图片描述](https://bbs.kanxue.com/upload/attach/202305/878276_3SWP4MY43W2Y6R8.png)

 ![图片描述](https://bbs.kanxue.com/upload/attach/202305/878276_B5HBSFVX3FQYZAD.png)
使用命令：ls /.dockerenv 或者 cat /proc/1/cgroup（1表示初始化文件） 如果有结果那说明是一个docker系统而不是安装在服务器上的系统
如何检测是否是docker系统？
通过查看是否存在dockerenv这个文件，如果存在则大概率就是一个docker容器系统。
查看/proc/1/cgroup文件：（1代表系统的初始化进程id 当初始化进程id的cgroup文件中包含着明确的docker信息则百分百是个docker容器） 随后想办法从隔离的docker容器中突破出来找到宿主机，拿到root权限
 ![图片描述](https://bbs.kanxue.com/upload/attach/202305/878276_FMG2QSNP8KF5WMH.png)
可以将docker容器所处的网段视为当前的内网网段 可以对内网网段进行主机发现，看看该网段中是否还存在其他主机
 ![图片描述](https://bbs.kanxue.com/upload/attach/202305/878276_DAVVG564CKRJ62A.png)
16个网段，存在65535个ip
主机发现：ping -c 对内网中的每个ip都ping一遍 或者通过脚本循环ping：for i in $(seq 1 10); do ping -c 1 ip.$i;done
