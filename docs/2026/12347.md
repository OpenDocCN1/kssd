# 文件系统过滤驱动

每个文件系统I / O操作（创建，读取，写入，重命名等）被称为文件系统过滤驱动程序，因此，它可以修改文件系统的行为。文件系统过滤器驱动程序， S是几乎相似的遗留驱动小号，但他们需要做一些特殊的步骤。使用反病毒，安全，备份，快照软件等驱动秒。

IrpDispatch.c

发送请求

这个IRP处理程序，除通过要求进一步下一个什么驱动。我们的下一个驱动程序对象存储在我们的设备扩展。


```
/////////////////////////////////////////////////////////////////
// PassThrough IRP Handler

NTSTATUS FsFilterDispatchPassThrough(
    __in PDEVICE_OBJECT DeviceObject,
    __in PIRP           Irp
    )
{
    PFSFILTER_DEVICE_EXTENSION pDevExt =
      (PFSFILTER_DEVICE_EXTENSION)DeviceObject->DeviceExtension;

    IoSkipCurrentIrpStackLocation(Irp);
    return IoCallDriver(pDevExt->AttachedToDeviceObject, Irp);
}
```

    (((_FastIoDispatchPtr) != NULL) && \
    (((_FastIoDispatchPtr)->SizeOfFastIoDispatch) >= \
    (FIELD_OFFSET(FAST_IO_DISPATCH, _FieldName) + sizeof(void *))) && \

快速IO请求

```
BOOLEAN FsFilterFastIoQueryBasicInfo(
    __in PFILE_OBJECT       FileObject,
    __in BOOLEAN            Wait,
    __out PFILE_BASIC_INFORMATION Buffer,
    __out PIO_STATUS_BLOCK  IoStatus,
    __in PDEVICE_OBJECT     DeviceObject
    )
{
    //
    //  Pass through logic for this type of Fast I/O
    //

    PDEVICE_OBJECT    nextDeviceObject =
      ((PFSFILTER_DEVICE_EXTENSION)DeviceObject->DeviceExtension)->AttachedToDeviceObject;
    PFAST_IO_DISPATCH fastIoDispatch   = nextDeviceObject->DriverObject->FastIoDispatch;

    if (VALID_FAST_IO_DISPATCH_HANDLER(fastIoDispatch, FastIoQueryBasicInfo))
    {

        return (fastIoDispatch->FastIoQueryBasicInfo)(
            FileObject,
            Wait,
            Buffer,
            IoStatus,
            nextDeviceObject);
    }

    return FALSE;
}
```

notification.c

一个典型的文件系统包括控制设备和卷设备。卷设备连接到存储设备栈。注册为一个文件系统的控制装置。
![](https://bbs.kanxue.com/upload/attach/201204/508799_s3iwro3m9g9v5qd.png)

我们有一个回调，这是所有活动的文件系统调用和一个文件系统时，已注册或未经注册的本身作为一个活跃的地区之一。这是一个好地方，我们的过滤装置连接/分离。当一个文件系统激活本身，我们重视它的控制装置（只有当我们尚未连接），列举其体积设备，他们太重视。对文件系统的失活，我们检查文件系统控制设备栈，找到我们的设备，并取下。从文件系统卷的设备拆卸的FsFilterFastIoDetachDevice例行前面所述。


```
////////////////////////////////////////////////////////////////////////////
// This routine is invoked whenever a file system has either registered or
// unregistered itself as an active file system.

VOID FsFilterNotificationCallback(
    __in PDEVICE_OBJECT DeviceObject,
    __in BOOLEAN        FsActive
    )
{
    //
    //  Handle attaching/detaching from the given file system.
    //

    if (FsActive)
    {
        FsFilterAttachToFileSystemDevice(DeviceObject);
    }
    else
    {
        FsFilterDetachFromFileSystemDevice(DeviceObject);
    }
}
```

附上

执行附加，我们创建新的设备对象与设备扩展（调用IoCreateDevice），我们正在试图连接到（从设备对象的传播设备对象的标志DO\_BUFFERED\_IO FILE\_DEVICE\_SECURE\_OPEN，DO\_DIRECT\_IO，）。然后，我们呼吁IoAttachDeviceToDeviceStackSafe在一个循环，在失败的情况下延迟。这是本附件的要求可能失败，因为还没有完成初始化设备对象。如果我们尝试安装过滤器，体积只有加载，就会出现这种情况。当安装完成后，我们保存的设备对象的设备扩展“连接”，并清除DO\_DEVICE\_INITIALIZING标志。设备扩展如下：

派遣
派遣是很简单。“”从设备扩展和呼叫设备对象IoDetachDevice和IoDeleteDevice。

void FsFilterDetachFromDevice(
    __in PDEVICE_OBJECT DeviceObject
    )
{
    PFSFILTER_DEVICE_EXTENSION pDevExt =
