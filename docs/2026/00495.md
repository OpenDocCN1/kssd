# [原创]自己动手恢复显示OllyICE数据栏地址偏移

**一、问题的起源**

从看雪首页下载OllyICE1.1，分别加载调试记事本，发现原版OD数据窗口双击会显示地址偏移，而OllyICE双击却无反应。

![](https://bbs.kanxue.com/upload/attach/201703/89687_54q8zvgkce95lki.png)

    这个双击显示地址偏移的功能非常实用，这么好的功能为什么OllyICE里面给去掉了呢？我真想不通。难不成为了使用这个功能我得另外下载其它修改版的OD？不行！我不喜欢那种被改得面目全非的OD，害得我强迫症又犯了！我必须要把它分析明白。

**二、分析****OD****显示偏移功能**

   在OD的汇编窗口、堆栈窗口双击地址，都可以显示$+偏移量，那说明可能都是同一个功能函数调用。怎么分析呢？可以用OllyICE加载原版OD（原版OD加载记事本），这样就开始测试吧：

![](https://bbs.kanxue.com/upload/attach/201703/89687_yl4zsk3s3trm8n8.png)

![](https://bbs.kanxue.com/upload/attach/201703/89687_w64z4lvmcgowfhh.png)

![](https://bbs.kanxue.com/upload/attach/201703/89687_17xnruo7l2w9zol.png)

    双击原版OD数据窗口地址，OllyICE中立即断下了，来到这里：

![](https://bbs.kanxue.com/upload/attach/201703/89687_cfq2vzv3j1euz89.png)

    F8向下单步走，在这里我主要关心的是它的消息处理函数在哪里：

![](https://bbs.kanxue.com/upload/attach/201703/89687_jwrtkj97l1pbhoq.png)

    向下走一会，不远处就发现一个Tablefunction调用。这名字很是可疑，应该看看：

![](https://bbs.kanxue.com/upload/attach/201703/89687_5oqkkzi4pttdigy.png)

![](https://bbs.kanxue.com/upload/attach/201703/89687_8i0a6kovj24j2hi.png)

![](https://bbs.kanxue.com/upload/attach/201703/89687_1m19991b5uvxb9k.png)

    顺着流程继续走，看来离目标不远了：

![](https://bbs.kanxue.com/upload/attach/201703/89687_s6mish318uasxoc.png)

    好了，终于来到了鼠标双击消息的处理处：

![](https://bbs.kanxue.com/upload/attach/201703/89687_2p6qpj0a4jb9ltc.png)

看来这里就是其发送显示地址偏移的地方了。此处是调用SendMessage发送自定义消息，lParam为双击的行，wParam为双击时相对于行首的字符偏移数。至于它是如何画出$和计算偏移的，我就不关心了。这里主要是摸清它处理双击时的一个消息流程。那么为什么OllyICE双击没有反应呢，很可能就是因为消息没有走到此处来。

    好了，是时候让原版OD调试OllyICE了！（原版OD笑了，小样，也该让我来调戏调戏你了！）主要是找出为什么OllyICE中这个“表格函数”会没反应。用原版OD加载OllyCE，OllyICE加载记事本。（记事本：我冤枉啊，为什么次次都让我来垫底!）然后同样用上面的消息断点。

![](https://bbs.kanxue.com/upload/attach/201703/89687_fzjnmten2uz0c95.png)

被断下来以后，来到这里，发现有个“三连跳”，第一个还是无条件跳转，这难道就是它绕过了“表格函数”？为验证这一点，先不打草惊蛇，继续顺着原路向下走走看：

![](https://bbs.kanxue.com/upload/attach/201703/89687_gq6nqkad7epkieb.png)

看来0x425E57处的无条件跳转应该是造成双击不显示偏移的罪魁祸首。直接NOP掉吧！不行！！！NOP以后左下的数据窗口无响应了。怎么办？唉，还得拿原版OD来看，重点关注0x425E57处的代码。（原版OD：你干脆折腾死我算了！）不过这一次可以不用加载记事本了（记事本：555~），直接CTRL+G到指定地址处。

![](https://bbs.kanxue.com/upload/attach/201703/89687_bk0qmmflx3gcq7i.png)

 原版OD里面0x425E57处的代码为cmp eax,200，是进入到一个select分支。而OllyICE1.1中却是直接跳转后最终转入了默认处理。

 知道了原因了就好处理了。因为原版OD没有Dump插件，只好用OllyICE加载自己进行处理。（OllyICE：我错了，我自己动手解决！）

![](https://bbs.kanxue.com/upload/attach/201703/89687_p1mkcxonz0tnj5y.png)

修改此处无条件转移为原版的比较语句,然后用dump插件进行处理：

![](https://bbs.kanxue.com/upload/attach/201703/89687_wsiqe6p7x2o15de.png)

运行DUMP后的OllyICE，最后一次加载记事本。（记事本：我已的泪已干，不哭了！）双击数据窗口地址栏，看到偏移终于恢复了：

![](https://bbs.kanxue.com/upload/attach/201703/89687_32r0qjshfrokf07.png)

    大功告成！谢谢记事本兄弟的鼎力支持。有了这个功能，调试时计算地址方便多了！
