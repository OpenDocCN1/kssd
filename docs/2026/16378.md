
# [原创]实战：AliCrackme

## 1.1 分析 AliCrackme

将 AliCrackme 程序拖入 `jdax-gui` 进行分析。

1. 从 `xml` 中找到程序入口点，如下图所示。

![](upload/attach/202009/880306\_BBD4TCM2AXU6EN9.png)

2. 分析 `Oncreate`，前面是布局初始化和设置监听的操作，如下图所示。

![](upload/attach/202009/880306\_3TMC5VJK56P8UFW.png)

3. 点击 `onclick` 里的内容，如果这个函数返回值为真，就进行页面跳转，否则显示弹窗失败，如下图所示。

![](upload/attach/202009/880306\_3ZGH2DHG27P5ZKE.png)

4. 点击函数，发现被 `native` 修饰，说明是使用 NDK 开发，直接分析 `so` 库，如下图所示。

![](upload/attach/202009/880306\_2VGNZRAHH5RPS83.png)

5. 加载这个 `so` 库，如下图所示。

![](upload/attach/202009/880306\_VGKGEKG4YNQEWYG.png)

## 1.2 使用 IDA 分析 so 库

1. 使用压缩打开程序的压缩包，在 `lib` 中找到 `so` 库，如下图所示。

![](upload/attach/202009/880306\_4G4RKZTZ5MJ7PUJ.png)

2. 将 `so` 拖入 IDA，在模块列表中查找 `JNI_Load` 或者 `JAVA_` 函数，搜索找到 JNI 函数，如下图所示。

![](upload/attach/202009/880306\_EVSGNN8PBJTVAWV.png)

3. 进来后，直接按 `F5`，查看伪代码，修改参数类型和类名，如下图所示。

![](upload/attach/202009/880306\_24CY6PJNB97EUEC.png)

4. 根据伪代码分析逻辑，找到动态注册函数 `RegisterNative`，最后一个函数调用了 `GetEnv`，也就是说，Java 的调用的方法并不是通过静态注册，如下图所示。

![](upload/attach/202009/880306\_6NDXSVG72R88FAP.png)

5. 继续寻找静态注册，如下图所示。

![](upload/attach/202009/880306\_85F8G2FAFPPDE25.png)

6. 修改前面两个参数，如下图所示。

![](upload/attach/202009/880306\_2D8NZHDVJS6XKJ2.png)

7. 查看最后一个参数，看到 Java 代码对这个方法的调用处，发现一个字符串，如下图所示。

![](upload/attach/202009/880306\_WT6NH3ZHEBQ69SG.png)

8. 修改第三个参数，修改的效果如下图所示。

![](upload/attach/202009/880306\_3SSDXBVRWP5FDK6.png)

9. 将 `str` 给 `v4`，然后作为参数给 `GetStringUTFChars` 函数传进去，将返回值给 `v5`，如下图所示。

![](upload/attach/202009/880306\_CWHUYVF3GGEFP4W.png)

10. 接着是一个 `while` 死循环，如下图所示。

![](upload/attach/202009/880306\_EMZQKG5W8C9EWZ7.png)

11. 对比 `v6` 和 `v7`，如果不相等，直接 `break`，然后返回给 Java `0`，如下图所示。

![](upload/attach/202009/880306\_WHYSBSAHV5A42MG.png)

12. 如果 `v7` 为空，取反为真，就表示结束对比，直接返回 `v7`；否则 `v7` 取反一直为 `0`，不会执行这里，继续比较。如图 8.17 所示，直接动态调试，查找 `v7` 的地址即可。

![](upload/attach/202009/880306\_JYGGYCVAVWBR87J.png)

## 1.3 IDA 动态调试

1. 在 `JNI_load` 里面，在执行完这个函数时，程序直接 `FFFFFFFFF`，传了四个参数，如下图所示。

![](upload/attach/202009/880306\_2AKPYRXGHP3Q75W.png)

2. 按 `F7` 进入该函数，显示是创建一个线程，如下图所示。

![](upload/attach/202009/880306\_ED6DRC4S3BJENR8.png)

3. 直接 `nop` 掉即可，继续向下执行，如下图所示。

![](upload/attach/202009/880306\_8S27GYJHU6FURP6.png)

4. 继续往下走，如下图所示。

![](upload/attach/202009/880306\_VPFHSP6Z7HJZ87V.png)

5. 一路按 `F8` 到底，发现程序没什么变化，如下图所示。

![](upload/attach/202009/880306\_FQKH5KM6T3T8CKX.png)

6. 与密钥有关的逻辑肯定是在静态注册，已经分析过静态注册的伪代码，直接在这里下断，然后按 `F5` 识别伪代码，同步伪代码到汇编窗口。通过静态分析已经知道字符串对比的地方，直接在这里下断点，如下图所示。

![](upload/attach/202009/880306\_Y9A27HYP4HV3UWA.png)

7. 观察此时寄存器的值，`R2` 是要对比的值（这个就是正确密钥），如下图所示。

![](upload/attach/202009/880306\_Q2H77HJAFJFP35A.png)

8. 取 `R2` 地址处的第一个值，`a` 的 ASCII 码为 `0x61`，如下图所示。

![](upload/attach/202009/880306\_K7MSTMJXW2J2WKW.png)

9. `R0` 地址处的是我们自己输入的，如下图所示。

![](upload/attach/202009/880306\_6YGJ5GM7SMSNATH.png)

10. `R1` 就是我们自己输入字符的第一个字母，`z` 的 ASCII 码，如下图所示。

![](upload/attach/202009/880306\_5AKNCXWHUQ6SMRV.png)

其实，这里就是将正确的字符和我们自己输入的字符进行比较，到此为止，整个程序也就分析完成了。
