**漏洞介绍**
使用IE调用SWF，IE Crash信息如下
![](https://bbs.kanxue.com/upload/attach/201209/449761_pmg2qef5bzlwq8f.png)

出错函数如下
![](https://bbs.kanxue.com/upload/attach/201209/449761_8o48jtprgjt30sh.png)

查看SWF文件格式，文件包含DefineFont4 Tag，DefineFont4是在SWF10中添加的。DefineFont4仅支持新的Flash文本引擎，嵌入的字体数据是以CFF格式存储的。
![](https://bbs.kanxue.com/upload/attach/201209/449761_hjl2dvcb96qij89.png)

本次漏洞产生原因为整型溢出， 恶意数据存在于FontData数据偏移0x8344中， 位于kern Table中。文件中出现的0x1000为version，0x10000000为nTables（subtables数量），正因为错误的nTables值导致了异常的产生
![](https://bbs.kanxue.com/upload/attach/201209/449761_05clsu0ih5omlxm.png)

**漏洞分析**
在TTF文件格式中有许多Table，其中有一处为'kern' Table，Adobe Flash Player在处理'kern' Table存在问题，也是本次漏洞的产生原因。程序中有牵扯到几个重要结构，在这里简单介绍其格式

'kern' Table
struct kernTableInfo  (sizeof=0x10)
{
        +0  objBufAlloctor        // 内存池对象
        +4  kernStreamObj        // kernStream对象
        +8  nTables                        // kernTable中subtables数量
        +C  ptrSubtables                // 存储subtables的buffer
}

subtable
struct subtableInfo  (sizeof=0x10)
{
+0  bKernFormatMask
+4  start\_offset        // 当前table起始偏移
+8  data\_offset        // table中数据起始偏移
        +C  field\_C
}

进入kernTableHandler()函数内部，程序会读取'kern' Table中的nTables，并根据nTables申请内存，用于存放subtables
![](https://bbs.kanxue.com/upload/attach/201209/449761_1troi6i3umuli5n.png)

首先分配一块0x10的内存，存放kernTable信息
![](https://bbs.kanxue.com/upload/attach/201209/449761_7r2is13cv2wo4hb.png)

然后分配Size = nTable \* 0x10 的内存，用于存放subtables，但由于nTables被恶意修改，致使nTable \* 0x10产生整型溢出，分配了错误Size的内存
![](https://bbs.kanxue.com/upload/attach/201209/449761_vt1e3cpjss3mqwy.png)

接下来程序会循环填充ptrSubtables，简单还原kernTableHandler函数代码
![](https://bbs.kanxue.com/upload/attach/201209/449761_ql2w0898vvm33ww.png)

循环次数为nTables = 0x10000000，这个过程中会覆盖关键数据。在循环至第0x4F8次时，恰好覆盖至kernTableInfo.nTables，导致循环退出，之后进入vul\_func()触发漏洞.
![](https://bbs.kanxue.com/upload/attach/201209/449761_x32c2gye3ucbxrs.png)
