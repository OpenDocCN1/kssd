# [原创]WannaRen病毒逆向分析报告

# 写在前面：

这个病毒作者已经公开了私钥，解密工具也制作出来了，我就当是学习逆向对整个病毒进行分析一下。

虚拟机环境：win10x64    网络状态：飞行模式（因为不知道会不会内网感染）

病毒样本放在百度网盘了，在后面有下载链接。

# 勒索复现：

下载之后有三个文件，一开始我以为运行exe就会完蛋，但是想的太简单了。

![](https://bbs.kanxue.com/upload/attach/202005/856851_W5RGPFYR4VRUT9U.jpg)

更具火绒发的报告，程序传输途径可以是某西下载园，所以exe需要放在C:\ProgramData目录下，然后还是不行，调用的的dll也要放到C:\ProgramData下，因为调用的是硬编码，应该是编程的时候放在项目文件下调用的，然后运行还是没啥动静，那个you文件是虚拟保护过的，没啥变化，最后根据收集到的信息，才知道you文件需要放到C:\Users\Public，下才可以。

第一次运行exe会在C:\Users\Public生成一个fm文件：

![](https://bbs.kanxue.com/upload/attach/202005/856851_94DP924J7WVVX3M.jpg)

里面记录了第一次运行的时间:

![](https://bbs.kanxue.com/upload/attach/202005/856851_BNPD9EWEMZG5EDA.jpg)

然后第二次运行，病毒就开始工作了，表现就是虚拟机的文件全部被加密了，包括文档和压缩包，后缀多一个.WannaRen:

![](https://bbs.kanxue.com/upload/attach/202005/856851_MJYMRCFHT26RFG2.jpg)

# 逆向分析

首先康康这个exe，很干净：

![](https://bbs.kanxue.com/upload/attach/202005/856851_AP92EGWSAC8EWTU.jpg)

就一个导入结构，调用lib文件。

动态调试一下：

RVA1272检查路径是否在指定路径下：

![](https://bbs.kanxue.com/upload/attach/202005/856851_4WXDV9R3R69FT7V.jpg)

然后调用这个DLL之后，就退出了程序，他用的是硬编码，编程的时候dll应该是和程序放在同一个目录下：

![](https://bbs.kanxue.com/upload/attach/202005/856851_FNFPAK2QTVBPR7A.jpg)

然后就退出程序了，连createfile都没调用，看来fm文件是在这个dll里面创建。

od载入这个病毒wwlib.dll:

![](https://bbs.kanxue.com/upload/attach/202005/856851_GDV8DUC2QGC4Z5N.jpg)

如果第一次动态调试的话，应该停在下面位置：

![](https://bbs.kanxue.com/upload/attach/202005/856851_DE3JXW92DPG4ZDC.jpg)

单步几下看看，程序被vmp过，而且没找到中心调度（可能有我没看到），也没找到跳转表，估计是保护全开了，程序大小也着实很大：

![](https://bbs.kanxue.com/upload/attach/202005/856851_T7G8295MS9KD2XF.jpg)

run跟踪也没什么看的，可读性很低：

![](https://bbs.kanxue.com/upload/attach/202005/856851_UDCZQMRNHRS4GTQ.jpg)

另辟其他路，之前运行的时候有创建fm这个文件，那就对CreateFileA，CreatFileW, readfile都下断点，调用这些win api是需要出虚拟机的：

![](https://bbs.kanxue.com/upload/attach/202005/856851_E7HNURZ9C3ARKM5.jpg)

然后运行，有点收获，create文件，读写权限：

![](https://bbs.kanxue.com/upload/attach/202005/856851_WD6J296PSVPMFE3.jpg)

之后又是读取此文件，不知道干什么。

继续f9肯定会在readfile断下：

![](https://bbs.kanxue.com/upload/attach/202005/856851_ZGYJFQ4FCSHGD9F.jpg)

数据窗口跟随buffer，运行到ret，说明之前的create函数就是写入时间的：

![](https://bbs.kanxue.com/upload/attach/202005/856851_AK6G5FJ88CWXKK4.jpg)

再f9 程序退出。

在之前提到，第一次运行是在public文件下创建fm文件，然后第二次才是加密，就是对这块逆向分析得到的结果，ctrl  f2一下，程序停在莫名其妙的地方：

![](https://bbs.kanxue.com/upload/attach/202005/856851_3VYM6HST783UWQM.jpg)

不用管他，应该是哪个api函数的断点，两次f9到入口处。

然后第一个问题出现了，程序调用依旧读取两次fm就退出了，这块浪费了时间，不知道什么操作，在第一次createfile   这个fm文件的时候，跑到文件夹删除这个fm文件，就

可以了。

此时删除：
![](https://bbs.kanxue.com/upload/attach/202005/856851_6NCAQ5NZQ3ZXZ5W.jpg)

然后开始读取这个you文件：

![](https://bbs.kanxue.com/upload/attach/202005/856851_ASH25B4JK93H556.jpg)

这个就是加密文件，读取之后，开始read：

![](https://bbs.kanxue.com/upload/attach/202005/856851_CHH757KCNT32CPP.jpg)

然后buffer跟随，运行到ret，可以看到这个buffer就是you这个加密文件的数据：

![](https://bbs.kanxue.com/upload/attach/202005/856851_WP64PZ2BWBY4RCB.jpg)

再f9跑飞，重新来一遍对这个位置下硬件访问断点：

![](https://bbs.kanxue.com/upload/attach/202005/856851_UMMAXX58XWZ79TD.jpg)

f9到一个位置：

![](https://bbs.kanxue.com/upload/attach/202005/856851_AQWN8RCCW56DV3U.jpg)

简单分析一下这块代码，992位置读取加密的数据，下面开始调用解密函数，jmp这个不要去跟踪，因为也是一个解密操作，但是没有用函数封装，跟着容易跑没了。

解密之后保存到ebx指定的位置，数据窗口中跟到：

![](https://bbs.kanxue.com/upload/attach/202005/856851_5ET7TJGM9AG4A3Q.jpg)

对9C0位置下断点，f9运行到，可以取消之前下的硬件断点，不然手抖一下就要重来，下面这张截图的地址和上面不一样就是因为手抖：

![](https://bbs.kanxue.com/upload/attach/202005/856851_H3UWFP4CRMG9QZW.jpg)

MZ，，DOS stub 安逸，dum出来：

![](https://bbs.kanxue.com/upload/attach/202005/856851_QB9QP9Z5TZ9G32T.jpg)

![](https://bbs.kanxue.com/upload/attach/202005/856851_XRT4ZBAJYZJN6RU.jpg)

程序还不能直接改成exe，因偏移地址在028处，用二进制编辑器删掉前面的东西：

![](https://bbs.kanxue.com/upload/attach/202005/856851_FJ9GW383XKEDP42.jpg)

保存好，修改成exe后缀，就出现了一个真正病毒程序：

![](https://bbs.kanxue.com/upload/attach/202005/856851_SASPFCBJ4U22FGS.jpg)

这是一个易语言写的程序：

![](https://bbs.kanxue.com/upload/attach/202005/856851_SX28AS9ZHP9KEM7.jpg)

现在没什么保护措施了，静态分析一下，框架不适合start开始分析，从加密位置找找：

![](https://bbs.kanxue.com/upload/attach/202005/856851_R9US2KX52EV2ZY7.jpg)

![](https://bbs.kanxue.com/upload/attach/202005/856851_DNRKGS7VV2M5U8A.jpg)
