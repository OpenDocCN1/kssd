
# [分享]动态调试：IDA 绕过 Native 层反调试

## 0x1 为什么需要调试 SO

### 1. 背景

使用 Java 实现的功能很容易被攻击者逆向分析。出于安全考虑，通常重要的功能会放在 Native 层，也就是 SO 里面，而 SO 是由 C/C++ 代码开发的，IDA 可以实现对 C/C++ 代码编写的程序进行调试。

## 0x2 IDA 中地址的概念

### 1. 物理地址 = 基地址 + 偏移地址

实际生活当中，假如说你要找 308 房间，肯定需要在三楼找，三楼就是基地址，08 就是偏移地址。

而在 IDA 动态调试中，要找某个函数在内存里的位置，需要先找到函数所在的 SO 的起始地址，也就是基地址，再找到函数在 IDA 里面的偏移地址，两者相加。

## 0x3 动态调试中的常用概念

### 1. 概念

1. **断点**：程序运行至断点时，暂停。
2. **下断**：在代码某一处打上断点。
3. **单步步入**：一行行执行代码，遇到函数进入。
4. **单步步过**：一行行执行代码，遇到函数跳过。

## 0x4 IDA 调试步骤

1. 将 `android-server` 拷贝到手机，赋予可执行权限并运行。
2. 执行命令 `adb shell am start -D -n 包名/.入口界面`。
3. 使用 IDA 附加目标进程，下断点。
4. 执行命令 `jdb -connect com.sun.jdi.SocketAttach:hostname=localhost,port=8700`（端口可在 DDMS 中查看）。

## 0x5 实战

1. 将 APK 安装到模拟器，然后进入 IDA 的安装目录，找到 `dbgsrv` 目录。因为模拟器是 32 位的，所以这里需要将 `android_x86_server` 文件放到模拟器上。

![upload/attach/202202/859914_CN8DYCS3NZGPVUW.jpg](upload/attach/202202/859914_CN8DYCS3NZGPVUW.jpg)

2. 打开 CMD 窗口，执行 `adb devices` 和 `adb push android_x86_server /sbin`，然后报错：

```text
C:\Users\LENOVO\Desktop\IDA_Pro_v7.5_Portable\dbgsrv>adb push android_x86_server /sbin
adb: error: failed to copy 'android_x86_server' to '/sbin/android_x86_server': remote couldn't create file: Read-only file system
android_x86_server: 1 file pushed, 0 s...d. 37.7 MB/s (1130104 bytes in 0.029s)
```

3. 再打开一个 CMD 窗口，执行 `adb shell` 和 `mount -o rw,remount /`，重新挂载文件系统。然后回到之前的 CMD 窗口，执行 `adb devices` 和 `adb push android_x86_server /sbin`，文件传输成功。

```text
C:\Users\LENOVO\Desktop\IDA_Pro_v7.5_Portable\dbgsrv>adb push android_x86_server /sbin
android_x86_server: 1 file pushed, 0 s...d. 53.9 MB/s (1130104 bytes in 0.020s)
```

4. 进入 Shell 模式，输入 `chmod +x /sbin/android_x86_server`，赋予文件可执行权限，然后输入 `android_x86_server`。运行成功后，默认监听 `23946` 端口。

```text
aosp:/ # chmod +x /sbin/android_x86_server
aosp:/ # android_x86_server
IDA Android x86 32-bit remote debug server(ST) v7.5.26. Hex-Rays (c) 2004-2020
Listening on 0.0.0.0:23946...
```

5. 如果遇到 APK 无法打开的情况，先打开 DDMS，需要以 Debug 模式启动 App。使用 AndroidKiller 反编译，打开 `AndroidManifest.xml` 文件，找到程序主界面 `com.kanxue.kctfso.MainActivity`。

原来我们是加载 SO 文件，可以静态修改 `jz` 为 `jnz`：

```asm
cmp eax, 0FFFFFFFFh
jz loc_607
; 按一下空格，000005EB 就是偏移地址
.text:000005EB jz loc_607
```

6. 输入命令 `adb forward tcp:23946 tcp:23946`，将手机上的 `23946` 端口转发到电脑本地的 `23946` 端口。再打开一个 `adb shell` 窗口，输入 `am start -D -n com.kanxue.kctfso/.MainActivity`，以 Debug 模式启动 App。注意 `/` 不要漏掉。

```text
C:\Users\LENOVO\Desktop\IDA_Pro_v7.5_Portable\dbgsrv>adb forward tcp:23946 tcp:23946
23946
aosp:/ # am start -D -n com.example.checkroot/.MainActivity
Starting: Intent { cmp=com.example.checkroot/.MainActivity }
```

8. 按 `F9` 运行，但是程序没有动静。查看 DDMS 中的端口 `8618`，输入命令 `jdb -connect com.sun.jdi.SocketAttach:hostname=localhost,port=8618`，让 App 继续运行。

```text
C:\Users\LENOVO>jdb -connect com.sun.jdi.SocketAttach:hostname=localhost,port=8618
设置未捕获的java.lang.Throwable

正在初始化jdb...

```

9. 在右边的 Module 窗口，可以看到加载了 SO 文件：

```text
C3C3C0DF: thread has started (tid=3960) m.kanxue.kctfso
B91F5000: loaded /data/app/com.kanxue.kctfso-1/lib/x86/libnative-lib.so
/data/app/com.kanxue.kctfso-1/lib/x86/libnative-lib.so B91F5000 0EBB7000
```

双击 `libnative-lib.so` 进入，可以看到 `root` 这个反调试函数。

![upload/attach/202202/859914_GHZ3SJJTUPDY6QC.jpg](upload/attach/202202/859914_GHZ3SJJTUPDY6QC.jpg)

10. `B91F5000` 就是这个 SO 文件的基地址。基地址加偏移地址，即 `B91F5000 + 000005EB = B91F55EB`，就是物理地址。按 `G` 键输入 `B91F55EB`，跟随过去：

![upload/attach/202202/859914_E6BMJ3SSNPY2CAK.jpg](upload/attach/202202/859914_E6BMJ3SSNPY2CAK.jpg)

11. 按 `F2` 下断点，按 `F9` 运行过去，程序会断下来。左边是反汇编窗口，右上角是寄存器窗口。

![upload/attach/202202/859914_976DBD64EU5V9E3.jpg](upload/attach/202202/859914_976DBD64EU5V9E3.jpg)

12. 选择 `Edit -> Patch program -> Assemble`，将 `jz` 修改为 `jnz`，即可完成绕过。

![upload/attach/202202/859914_UK7WBWNRQ34XT8F.jpg](upload/attach/202202/859914_UK7WBWNRQ34XT8F.jpg)
