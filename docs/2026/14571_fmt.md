![函数原型](upload/attach/202010/880306_P3R9QVEMTR3FNUM.png)

这是 `getText` 的函数原型。

## 分析 `getText` 函数

1. 找到 `getText` 函数，如下图所示。

   ![找到 getText 函数](upload/attach/202010/880306_D99AM4W7TZPGYHG.png)

2. 双击打开该函数，开始分析汇编指令。箭头所指位置是指令的开始处，如下图所示。

   ![分析汇编指令](upload/attach/202010/880306_7GAG7N7PTHVTYMH.png)

```asm
.text:00001148 STMFD SP!,{R3-R5,LR}
```

压栈操作，把 `R3-R5`、`LR` 分别压到栈顶。

```asm
.text:0000114C MOV R5, R1
```

把 `R1` 赋值给 `R5`。

```asm
.text:00001150 LDR R3, [R0]
```

将 `R0` 的地址给 `R3`。

```asm
.text:00001154 MOV R4, R0
```

将 `R0` 给 `R4`。

```asm
.text:00001164 BLX R3
```

跳转带链接状态切换到 `R3`。

```asm
.text:0000117C ADD R3, PC, R3
```

将 `PC` 和 `R3` 相加给 `R3`。

![操作流程](upload/attach/202010/880306_5SVJHXQKTETPR4G.png)

已经知道它的操作流程，那么它的这些操作为了实现什么逻辑呢？带着这个疑问继续分析。

## 对比分析源码、伪代码、汇编指令三者对应关系

1. 如下图所示为源代码的逻辑，它在获取字段的值。

   ![源代码逻辑](upload/attach/202010/880306_AU74MMJJTMUUJ2S.png)

2. 在反汇编窗口中找到 `getText` 函数，按“F5”，将汇编指令切换为伪代码。通过查看 IDA 里的伪代码发现：默认传入的参数类型需要修改才能查看，如下图所示。

   ![伪代码](upload/attach/202010/880306_FT4FTN2HE5QR47K.png)

3. 选中 `getText` 函数的参数，右键 N 对名称进行修改。第一个参数就是刚刚看到的 `env`，直接改为 `env`；右键 Y 对类型进行修改，将类型修改为 `JNIEnv*`。这样就识别完成了，效果如下图所示。

   ![修改参数类型](upload/attach/202010/880306_CP2UDFQG9WRPWYV.png)

分析此处的逻辑：

- 第一个跳转是：`Findclass`
- 第二个跳转是：`GetFindID`
- 第三个跳转是：`GetObjectFieId`
- 第四个跳转是：`GetStringUTFChars`
- 第五个是返回一个：`NewStringUTF`

接着修改参数，如下图所示。

![修改参数](upload/attach/202010/880306_KZYEUAAT6XJG8B6.png)

4. 参数修改完成后，右键选择 copy，将伪代码拷贝到反汇编窗口，也就是 `getText` 函数的汇编指令，如下图所示。

   ![拷贝伪代码](upload/attach/202010/880306_FQBSRHSGE7H796S.png)

这就是最终的效果。分析最终效果，便可以了解这些指令的作用，如下图所示。

![最终效果](upload/attach/202010/880306_JGYJTNYU8S79QAY.png)

## 小结

本次主要分享了静态分析的流程：

1. 分析函数，查看 ARM 汇编指令。
2. 对比分析源码、伪代码、汇编指令三者对应关系。
3. 查看跳转，理清逻辑。
4. 总结逻辑、实现过程。
