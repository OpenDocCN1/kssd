
# [原创]小试了一把bpf在android逆向中的辅助效果

## 起因

其实，这是一篇水文，没什么技术含量，都是些基础东西。样本是某比较流行的app，之前听说它有frida检测，正好有空就搂出来看看了。

## 初试(完结)

frida检测常规的手段一般都是

1. `frida_server`名字检测
2. 端口号检测
3. D-Bus检测
4. maps检测
5. 线程检测
6. 内存特征检测

而1、2、3都有个特征，那就是在`frida_server`运行的时候才存在，不论是否附加进程，因为这个app是在附加时退出，所以直接就排除了这几个。

然后就从所有检测的共同点入手了，所有检测的共同点就是字符串检测，而字符串匹配最常见的就是`strstr`函数

![](upload/attach/202305/719948_WH9NNJWQPQUEE5T.png)

然后就hook掉修改返回值，之后就尴尬了。。。

![](upload/attach/202305/719948_9MC98GBEJRZ5FUN.png)

当然还有一些其它的检测，比如里面还对`.dex`进行了比较，不过目的是处理frida挂不上去的问题，所以就没有细看比较这东西是干嘛的，盲猜可能是检测dex注入的。

这时候使用bpf检直就是降维打击，主要用到了bcc里面的`opensnoop`及`trace.py`脚本

```
python3 opensnoop -u 10094
python3 trace.py --uid 10094 'do_sys_openat2 "%s", arg2@user' -U --address -v -f maps
```

`opensnoop`观察访问的文件日志 ，`trace`查看堆栈

比如，这里是对这个app进行进行文件追踪的日志

![](upload/attach/202305/719948_R83MF9AE2JHGU37.png)

你会频繁的看到这类日志，而循环读取这类文件的，那最有可能就是检测点了

既然找到了切入点，那自然是通过`trace`的栈信息来定位了，`trace`的用户栈信息有几个问题，一个是栈信息不全，其次就是总是显示`unknow`的问题，这个有兴趣研究的可以参考大佬的文章 https://bbs.kanxue.com/thread-274546.htm

而我采用的是最笨最简单的一种方式，就是直接解析maps，将文件偏移与文件名关联起来直接替换`trace`脚本中的相关内容就行了，虽然没有解决特殊情况下栈不全的问题，但也勉强能用了，毕竟我的要求不高

def __init__(self, startAddr, endAddr, fOffset, path):

self.startAddr = startAddr
if endAddr is not None:
self.endAddr = endAddr
if path is not None:
self.path = path
def __str__(self):
return "MapsItem{%s-%s %s %s}" % (hex(self.startAddr), hex(self.endAddr), hex(self.fileOffset), self.path)

lst_segments = [] # MapsItem
def __init__(self, pid):

pass

try:

KKStackCache.pidmap[pid] = PidItem(pid)
mapsdata = []

if match:

mapsdata.append(mapsItem)
else:
print("No match:" + line)
KKStackCache.pidmap[pid].lst_segments = sorted(mapsdata, key=lambda x: x.startAddr)
f.close()
except:
pass
print("parser %d over." % pid)
@staticmethod

pidmap = KKStackCache.pidmap.get(pid)

lst = pidmap.lst_segments
bg = 0;
end = len(lst) - 1
while bg <= end:

bg = mid + 1

offset = itm.fileOffset + (addr - itm.startAddr)
return True, addr, offset, path
return False, None, None, None

def printLst(pid):

if pidmap is not None:
pidmap.printLst()
