适用版本：`glibc2.34+`

利用条件：能触发 `__malloc_assert` + 有一个任意地址写原语

[1]：

在`_IO_wfile_seekoff`这个函数中有如下的代码

```
  /* POSIX.1 8.2.3.7 says that after a call the fflush() the file
     offset of the underlying file must be exact.  */
  int must_be_exact = ((fp->_wide_data->_IO_read_base
                        == fp->_wide_data->_IO_read_end)
                       && (fp->_wide_data->_IO_write_base
                           == fp->_wide_data->_IO_write_ptr));
```

这个变量的作用从字面上也能看得出来

如果 `must_be_exact` 变量为 `1`

也就是`_wide_data`结构体的`read_base == read_end`且`write_base == write_ptr`

表示这个流现在既没有未消费的读缓存，也没有未刷新的写缓存

那么 `glibc` 认为这次 `fflush` 之后，底层文件偏移必须被精确校准

那我们的 `fake_IO` 就很有可能被检查出问题，所以这个变量必须为 `0`

尽管我们之后伪造的 `write_base` 一定不等于 `write_ptr`

但为了保险起见，还是令 `_wide_data->_IO_read_base = 1`

[2]：

在`_IO_wfile_seekoff`和`_IO_switch_to_wget_mode`两个函数中都有

`fp->_wide_data->_IO_write_ptr > fp->_wide_data->_IO_write_base`这个检查

所以`fp->_wide_data->_IO_write_base`一定要取小值，最简单的就是`0`了

> 与本 `house` 无关的一点小 `tip` ：
>
> 这里需要注意一下在 部分题目 中因为调用链不同
>
> 该处的数值反而不能为 `0` ，只要不为 `0` 且不大于`fp->_wide_data->_IO_write_ptr`均可
>
> 各位大佬们在使用的时候可以把这里改成1或者2，防止出现链跑不通的情况

[5]：

注意到`_IO_fflush`函数中有以下代码

```
int _IO_fflush (FILE *fp)
{
  if (fp == NULL)
    return _IO_flush_all ();
  else
    {
      int result;
      CHECK_FILE (fp, EOF);
      _IO_acquire_lock (fp);
      result = _IO_SYNC (fp) ? EOF : 0;
      _IO_release_lock (fp);
      return result;
    }
}
```

可以看到`_IO_acquire_lock(fp)`和`_IO_release_lock (fp)`

说明 `glibc` 会把 `fake IO` 里的 `_lock` 变量当作一个实际意义上可用的锁变量来用

所以 `fake IO` 里的 `_lock` 必须满足

- 可写，非只读段
- 已映射
- 受控制
- 不会和别的关键 `fake` 结构冲突

这里就直接找了 `heap_base + 0x200`

[6]：

由于 `wide_data` 的起点我们是可控的，这里放到了 `fd + 0x30`

因为我们最终是要把整个 `fake IO` 结构体放入 `chunk` 中并且经历反复的 `add` 与 `delete` 的

所以 `fd + 0x00` 到 `fd + 0x30` 会被 `fd bk` 之类的东西替换掉，所以我们选择 `fd + 0x30` 作为 `wide_data` 的起始点

[7]：

在正常 `glibc` 语义里，`_mode` 用来表示这个流的方向：

- `0`：还没定向
- `>``0`：`wide-oriented`，走宽字符路径
- `< 0`：`byte-oriented`，走普通窄字符路径

所以这里必须设置为大于 `0` 的值

[8]：

执行到`__vfwprintf_internal`的时候，按照正常情况最终会调用`vtable`指针的`xsputn`指针

但是如果我们对其进行了一个小偏移，例如`0x10`，那么他就会调用`seekoff`指针,

而如果我们修改`vtable`为`_IO_wfile_jumps`，那么就会调用到`_IO_wfile_jumps`函数

```
locked_vfxprintf (FILE *fp, const char *fmt, va_list ap,
                  unsigned int mode_flags)
{
  if (_IO_fwide (fp, 0) <= 0)
    return __vfprintf_internal (fp, fmt, ap, mode_flags);

  /* We must convert the narrow format string to a wide one.
     Each byte can produce at most one wide character.  */
  wchar_t *wfmt;
  mbstate_t mbstate;
  int res;
  int used_malloc = 0;
  size_t len = strlen (fmt) + 1;

  if (__glibc_unlikely (len > SIZE_MAX / sizeof (wchar_t)))
    {
      __set_errno (EOVERFLOW);
      return -1;
    }
  if (__libc_use_alloca (len * sizeof (wchar_t)))
    wfmt = alloca (len * sizeof (wchar_t));
  else if ((wfmt = malloc (len * sizeof (wchar_t))) == NULL)
    return -1;
  else
    used_malloc = 1;

  memset (&mbstate, 0, sizeof mbstate);
  res = __mbsrtowcs (wfmt, &fmt, len, &mbstate);

  if (res != -1)
    res = __vfwprintf_internal (fp, wfmt, ap, mode_flags);

  if (used_malloc)
    free (wfmt);

  return res;
}
```

[1]：

可以发现程序执行到`setcontext + 61`之后的 `rdx` 是由我们之前[3]中自己控制的

`rsp = [chunk2_header + 0xb0 + 0xa0] = [chunk2_header + 0x150]`

而根据我们之前 `fake IO` 表的最后一行，可以知道 `fake IO` 在`chunk2_header + 0x118` 结束

所以需要再补 `0x150-0x118 = 0x38` 也就是 `7` 个 `0x8` 再布置劫持地址

而这个劫持地址也需要我们把实际存储 `ROP` 链的 `chunk` ，也就是 `chunk10` 创建出来之后才能通过调试得知

### 第二条调用链

特攻题目：有 `exit` 函数

所以构造相对简单，只需要伪造 `IO` 结构体和 rop 链并写入`__IO_2_1_stderr`即可，无需手动触发，等待程序自动执行到exit函数即可

`exit` -> `__run_exit_handlers` -> `_IO_cleanup` -> `_IO_flush_all_lockp` -> `_IO_wfile_seekoff` -> `_IO_switch_to_wget_mode`

经过调试可以发现`_IO_flush_all_lockp`会调用 `vtable` 中的 `IO_wfile_underflow`

所以 `fake IO` 有两处改动

`fake IO` 中的 `_IO_wfile_jumps`的地址 + `0x10` 要变成 `_IO_wfile_jumps`的地址 + `0x30`

除此之外，原本的`_wide_data->_IO_write_base`也要改成非 `0` 但较小的值

还有就是有时候libc.sym['stderr']可能会失灵，可以换成libc.sym['\_IO\_list\_all']
