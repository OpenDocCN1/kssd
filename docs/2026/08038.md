# SafeSEH保护原理
SafeSEH的基本原理比较简单，即在调用异常处理函数之前，对要调用的异常处理函数进行一系列的有效性校验，如果发现异常处理函数不可靠（被覆盖了或被篡改了），立即终止异常处理函数的调用。
# S.E.H区别
Visual Studio 2003和后续版本默认是启用SafeSEH功能的，通过VS2008的命令行工具中输入dumpbin /loadconfig命令查看，可以明显看到，VC++6.0和VS2008编译后的S.E.H表的区别：
![](upload/attach/201902/3\_SKUDFVWYERVCEXX.png)
![](upload/attach/201902/3\_JH22FHNTDHHHQ2V.png)
## SafeSEH的保护流程：
1. 首先检查异常处理链是否位于程序栈中，若不在当前栈中，程序将终止异常处理函数的调用
2. 检查异常处理函数指针是否指向当前程序的栈中，若指向当前栈中，程序将终止异常处理函数的调用
3. 完成前两项检查后，程序将调用RtlIs ValidHandler() 对异常处理函数进行有效性验证
## RtlIs ValidHandler处理流程：
![](upload/attach/201902/3\_CCY3F5JNBAHV69S.png)
1. 判断程序是否设置了NO\_SEH标识，若设置了该标识，这个程序内的异常会被忽略，因此当该标识被设置时，函数直接返回校验失败
2. 检测程序是否包含安全的S.E.H表，若程序中包含安全的S.E.H表，则讲当前的异常处理函数地址与该表进行匹配，匹配成功则返回校验成功，匹配失败则返回校验失败
3. 判断程序是否设置了ILonly标识，如果设置了这个标识，则说明该程序只包含.NET编译人中间语言，函数直接返回校验失败
4. 判断异常处理函数地址是否位于不可执行页上，当位于不可执行页上时，校验函数将检测DEP是否开启，如果系统未开启DEP则返回校验成功，否则程序抛出访问违例异常
5. 若异常处理函数地址没有包含在加载模块的内存空间，校验函数将直接进行DEP相关检测
6. 判断异常处理函数地址是否位于不可执行页上，当异常处理函数位于不可执行页上时，校验函数将检测DEP是否开启，若系统未开启DEP则返回校验成功，否则抛出访问违例异常
7. 判断系统是否允许跳转到加载模块的内存空间外执行，若允许则返回校验成功，否则校验失败。
