
# SDProtector 1.1保护脱壳

这是RCE Message Board上贴的一个unpackme,留的MSN是mm@digitalnuke.com,不会是骨灰mm吧J。用SDProtector 1.10保护,从壳代码看好象不是注册版,但运行时并没有Nag screen,也许是破解版本。

我是脱壳新手,这次好歹全程跟完了一回。壳的anti-debug比较强,在`OllyDbg`下不能运行,要是先运行再attach,也会被杀掉。全程跟也是没办法。

运行几步,就会解出完整的壳代码。用`WinHex`拷出来,贴回程序,用`IDA`编译。写了个`IDC`脚本,去掉大部分花指令。因为程序中充斥大量的自校验,跟的过程中没有改代码,对照着`IDA`跟的。另外,壳中反复检查运行时间,为了能在上一次停下的地方继续,写了`OllyScript`脚本。即使这样,有一处的检测有时候仍然通不过,多试两次就好了。

用的是自己修改过的`OD 110c`来调试。在`W2K`下脱的。

## 3. anti-dump

壳代码在解出原程序时,把内存属性设为`PAGE_NOACCESS`,使在`OEP`处dump失败。修改一下脚本,改属性为`PAGE_READWRITE|PAGE_EXECUTE`。

## 4. 修复IAT

在这里处理`IAT`。

![](https://www.kanxue.com/sdprotector.files/image038.jpg)

这里检查当前处理的dll名。如果匹配,会得到特殊照顾。包括`kernel32`,`user32`,`gdi32`,`advapi32`,`shell32`以及`sdprotector.dll`。在这里手工使dll都不满足检测。这里会置标记`Magic JumpJ`。

![](https://www.kanxue.com/sdprotector.files/image039.jpg)

`sdprotector.dll`还有另一个标记:

![](https://www.kanxue.com/sdprotector.files/image040.jpg)

前面手工使所有的dll都不匹配,到这里`esi->IAT`:

![](https://www.kanxue.com/sdprotector.files/image042.jpg)

这里还有两处检查。当处理的是`user32.dll`时,注意`MessageBoxA`和`MessageBoxW`必须跳走,否则`IAT`被破坏,想必是用emulated API替代。

![](https://www.kanxue.com/sdprotector.files/image044.jpg)

对于不在列表中的dll,直接取出API地址送到`IAT`(这正是我想要的J):

![](https://www.kanxue.com/sdprotector.files/image046.jpg)
