
# [原创]Xposed高级用法  实现Tinker热修复

Hi，大家好，我是珍惜。

给大家简单介绍一下，如何用 Xposed 实现对某个类的替换覆盖：在不编译源码的情况下，直接修改原 `Class` 内容。

之前的这篇帖子也不错：[Xposed 实现 Native 层 Hook](https://bbs.pediy.com/thread-251171.htm)。

## 实现原理

当我们在 `findClass()` 的时候，其实我们最终都会去 `dexElements` 数组里面寻找我们需要的类。

![](https://bbs.kanxue.com/upload/attach/201911/819934_FKU5HN5SSW62W7P.jpg)

路径为：

`ClassLoader.java -> BaseDexClassLoader.java -> DexPathList.java -> dexElements`

这个寻找其实是遍历，如下图：

![](https://bbs.kanxue.com/upload/attach/201911/819934_VHJNFD9AG4PCGEK.jpg)

也就是说，我们只需要把我们想加载的类放在前面，再通过反射 `set` 即可做到热修复。

腾讯的 Tinker 其实大概原理也是这样；阿里的是动态修改了 `insns` 数组，直接修改某个方法的字节码。这也是热修复分为冷插拔和热插拔的区分（是否需要二次启动）。后面会详细跟大家说具体原因。

## 注意事项

这块有几个坑，跟大家说一下：

### 问题1：为什么不用一个静态方法作为 `Test`？

![](https://bbs.kanxue.com/upload/attach/201911/819934_8QX4D2FBMVGKF24.jpg)

![](https://bbs.kanxue.com/upload/attach/201911/819934_C27T2GN8D98YNVF.jpg)

如果这个方法是静态的，在 `MainActivity` 的时候就会进行初始化，这个时候这个类已经被初始化了。再次调用的时候，它就不会去 `findClass()`，也就不会遍历 `element` 数组，所以会修复无效。因为我现在每一次都是 `new` 一个新的对象，这个对象是未经过初始化的，所以需要遍历 `element` 数组拿到 `class`，这个时候可以完成热修复。

### 问题2：热修复的方式为什么分为冷插拔和热插拔？

Tinker 属于冷插拔，就是在错误的类的 `element` 数组前面加入我们自己需要的正确的类，这种方式需要 App 重启才可以。阿里的方式属于热插拔，它是直接修改错误方法的字节码 `Insns` 数组，可以直接修改对应的 Bug，这种不需要重启。

### 问题3：这个 Xposed 修复的作用是什么？它有什么价值？

我可以在不编译源码的情况下，直接修改源码里面的内容，随时可关，随时可开。只需要拿到系统的 `classloader`，再加载自己修改过的内容，如上述操作即可。
