
# [原创]新手DIY笔记——去除UltraEdit17.30中的一个讨厌的ToolTip

最终的完美解决在5楼，ue的作者可以去吃*了。

我用的是`UltraEdit17.30`，里面的一个功能令人极为不爽，那就是

![](https://bbs.kanxue.com/upload/attach/201203/492945_1n1y0e8c4oe41h6.jpg)

这个`ToolTip`把后面的文字都挡住了，只要一碰到那个标题就会显示，真不知道作者是不是脑袋进*了啊，具体情况咱不太了解，但是确实是很不舒服。那么就要发扬pediy论坛域名的精神，咱自己动手改一改。

`PEiD`查壳，无壳，.Net做的。

好了，`OD`载入，试了几下只要主程序中一断点，整个程序就终止退出，原因就不管他了。

先给出提前设好的断点，状态都是禁止的，因为我们要`F9`。

```
Breakpoints

地址       模块       激活                       反汇编                                注释

77D18A01   user32     已禁止                        mov     edi, edi                      DispatchMessageW

77D18C2E   user32     已禁止                        mov     eax, 121E                     SetTimer

77D196B8   user32     已禁止                        mov     edi, edi                      DispatchMessageA
```

`F9`运行，一段时间之后，程序跑起来了，但是不能按暂停，否则立即退出。我们就在它运行时在断点窗口激活`DispatchMessageA`，这样就断在`user32`里了，不影响程序。

```
Breakpoints

地址       模块       激活                       反汇编                                注释

77D18A01   user32     已禁止                        mov     edi, edi                      DispatchMessageW

77D18C2E   user32     已禁止                         mov     eax, 121E                     SetTimer

77D196B8   user32     始终                         mov     edi, edi                      DispatchMessageA
```

好了断下来了，将鼠标移到文本文件的标题上，然后按`F9`会看到一个`MouseMove`消息，看来它知道我们的鼠标移上来了。

![](https://bbs.kanxue.com/upload/attach/201203/492945_ph7x5nubcmytllo.jpg)

`F9`看下一条消息

![](https://bbs.kanxue.com/upload/attach/201203/492945_4gygvywooo45fq4.jpg)

哈哈，看这个类名就知道找到关键了，因为是一个`Timer`事件，所以清除`DispatchMessageA`断点，激活`SetTimer`断点。

```
Breakpoints

地址       模块       激活                       反汇编                                注释

77D18A01   user32     已禁止                        mov     edi, edi                      DispatchMessageW

77D18C2E   user32     始终                         mov     eax, 121E                     SetTimer

77D196B8   user32     已禁止                         mov     edi, edi                      DispatchMessageA
```

`F9`运行，程序跑起来，鼠标移到标题上，断下来了

![](https://bbs.kanxue.com/upload/attach/201203/492945_llbzuyhc12aswmk.jpg)

查看调用堆栈，


在最下方的栈底右击鼠标，在弹出的菜单中单击“显示调用”

```
0024FD3C   004AE909   ? Uedit32.00735660                                          Uedit32.004AE904
```

好了，反汇编窗口转到了一个`call`处的下一行代码，就是它了，向上翻，找到了一个刚好跳过它的条件跳转，凭我的感觉知道，八成是它了。



改为`jmp`绝对跳转。取消`SetTimer`断点，`F9`跑起来，试了下，`ToolTip`不再弹出，喜悦之情溢于言表，但事情还没做完。

```
004AE867    837D F4 00      cmp     dword ptr ss:[ebp-C], 0

004AE86B    E9 99000000     jmp     Uedit32.004AE909

004AE870    90              nop

004AE871    8B5424 1C       mov     edx, dword ptr ss:[esp+1C]
```

将改好的语句选中，右键复制到可执行文件

![](https://bbs.kanxue.com/upload/attach/201203/492945_27su3an38ku8xpe.jpg)

右键保存文件。

![](https://bbs.kanxue.com/upload/attach/201203/492945_zho5ew8nmf1u3al.jpg)

关闭`OD`，将原来的`Uedit32.exe`改名`Uedit32_0.exe`，保存的修改后的程序改为`Uedit32.exe`，执行，测试，`ToolTip`没有弹出，而且其他功能一切完好，终于大功告成，修得正果，终于不再有那个讨厌的框框了。

最然后总结经验，整理思路，上传到看雪论坛。

=======================瘦削的分割线=======================

补充：本来是想胡乱写写作为笔记的，没想到受到各位如此的厚爱，既然如此也不能辜负了大家的期望，我就来说一说这背后的故事。

首先，文章中说的一下断点就退出是不对的，其实是断下来以后再运行才退出的。

其次，说说突破口。因为平时破解我都是用传说中的`F12`断点法，即“`nag`-暂停-调用堆栈”，而这个`ToolTip`显然对此方法免疫，我也没有好的思路，所以就直捣黄龙——跟踪它的消息循环——想必大家都知道每一个`windows`程序的核心就是一个消息循环，这是最直接的想法，实现方式就是在`user32.DispatchMessageA`和`user32.DispatchMessageW`处下断点，观察它的每一个消息分发，这样无论什么情况都能应付（实际上后来发现上面贴出的核心代码在`PreTranslateMessage`的时候就已经执行了，所以说万事不绝对）。

再次，说说`bypass`的思路，事实上在`OnTimer`的头部直接`ret`也是一种方法，只不过一般的消息回调都要经过`user32`绕来绕去方见庐山真面目，因此实际上这个回调并不好找。由于`bypass`首个`SetTimer`更具美感，再加上前面的分析，使得我顺理成章地将其作为主攻方向。

最后，讲讲过程。台上十分钟，台下十年功，实际上整个过程并不像想象中那样来的顺利。就连`WM_TIMER`消息那里，我也是断下然后思考了不下20次才来灵感的；`SetTimer`断下的时候，我也并不是直接查看栈底，而也是一层一层跟上去之后才发现的。

其余的就跟文中的一样了，时间差不多了，这次就补充到这里吧，再次感谢各位的关注，欢迎交流。
