
不更改 `q` 的内容直接请求是可以正常返回内容的,看来校检参数不在请求头里(因为我没加请求头).应该在请求链接上.

我更改不同的单词查询,就发现只有 `tk` 是不同的,看来校检参数是 `tk`.

看来谷歌对链接里的 `tk` 参数进行了校检.下面我们就需要分析其 js 文件进行分析,看一下它是如何生成 `tk` 的.

### 分析

切换到开发者工具得 source 选项,如下图所示

![](upload/attach/201811/793792_JTFHHPRVWYBVJ5Z.png)

发现其只有一个`desktop_module_main.js`文件.

1. 在该 js 文件中搜索与 url 相关的字符串.

![](upload/attach/201811/793792_65AGQYYPXNE4YGG.png)

发现 `oa` 这个变量就是请求的 url路径.

2. 查看哪里引用了 `oa`(搜索)

![](upload/attach/201811/793792_ZGUYEPP953S9EJF.png)

发现 `ps` 函数使用了 `oa`,但没有发现 `tk` 函数,我们在其中下一个断点

![](upload/attach/201811/793792_TGRDME9MVUB9WNQ.png)

继续输入单词,使其断下来.

断下来后跟进 `ns` 函数,单步跟踪到第2行,发现 `tk` 是由 `ms` 函数返回的,而传入的参数是我们输入的内容.

![](upload/attach/201811/793792_R75VB5RUNCJBV75.png)

查看 `ms` 函数

![](upload/attach/201811/793792_QJ9ZVRJG5JGXNJT.png)

发现其是取出 `q` 参数(我们输入的内容)的内容,调用 `Hr` 函数

查看 `Hr` 函数

![](upload/attach/201811/793792_G6A7GVWHUMRH63J.png)

发现 `Hr` 就是根据输入的单词生成 `tk` 的最终函数.前面的 if 是获取 `TKK` 的值,`TKK` 时固定的,在 index 页面可以查找到.

![](upload/attach/201811/793792_VU7P3JAWB3NZ7FV.png)
