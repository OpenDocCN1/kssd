## 四、漏洞利用

### 1、堆风水

如何使`strcpy(event->name, file_name)`可以覆盖`iov_base`，向其写入`kernel_addr`。

首先我们看一下我们要布局的对象的大小。

`iov = kmalloc(nr_segs * sizeof(struct iovec), GFP_KERNEL);` // `nr_seg`需要大于 8，我这里选择 10，`iov`对象的大小是 160 个字节，从`kmalloc-192`中分配。如果要覆盖`iov`，下面的`event`、`file_name`就得选比较大的文件名，所以这个漏洞不能通过短文件名触发。

`event = kmalloc(alloc_len, GFP_KERNEL);` // 分配`sizeof(struct inotify_event_info) + strlen(file_name) + 1`内存，44 + 144 + 1 = 189 字节，从`kmalloc-192`中分配。

`kfree_rcu(old_name, u.head)`，`old_name`也是 144 个字节，从`kmalloc-192`分配，这里是释放。

`sendmsg`堆喷，172 个字节，从`kmalloc-192`分配。

为什么是 172 个字节？

`sizeof(struct inotify_event_info) = 44`个字节，`event`总的长度是 192 个字节，如果想覆盖`iov`，那么`file_name`被堆喷重新占位后的大小应该是`192 - 44 + 8`（`iov_addr`的字节数）= 156。由于`file_name`的值大于`old_name`的值 16 个字节，所以`sendmsg`应该堆喷 156 + 16 = 172 个字节。

堆风水步骤：

1. 首先起大量线程分配`iov`对象（通过`readv`函数，会阻塞线程，所以需要大量线程）。
2. 每隔一个对象释放`iov`，形成空洞。
3. 通过以下竞争，`event`落在空洞上，并且旁边就是另一个`iov`对象：

   ![](https://bbs.kanxue.com/upload/attach/201902/620204_MFHEAFVEQJJ4AGV.jpg)

4. 堆喷占位`old_name`，`strcpy`覆盖旁边`iov`对象的`iov_addr`。
