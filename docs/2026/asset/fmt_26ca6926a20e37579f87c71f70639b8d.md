
# MSGetInstructionWithThumb

调用`used += MSGetInstructionWithThumb(reinterpret_cast<uint8_t *>(area) + used);`

`MSGetInstructionWithThumb`的参数为`uint16_t*`。

返回结果为这条指令的字节数（4或2）。

`T$32bit$i`的作用：

`(指令(ic) & 1110 0000 0000 0000) && (ic & 0001 1000 0000 0000 != 0x0000)`

第一个判断用于确定高位3个bit（即`bit[15]`、`bit[14]`、`bit[13]`）为1。第二个判断用于确保`bit[12]`、`bit[11]`有值（即至少这两位中有1位为1）。

其实就是判断该Thumb指令是否为Thumb-32指令。

Thumb-32指令的判断依据是`b[15:11]`为`0b11101`、`0b11110`或`0b11111`。

`MSGetInstructionWithThumb`：

```cpp
static size_t MSGetInstructionWidthThumb(void *start) {
    uint16_t *thumb(reinterpret_cast<uint16_t *>(start)); //
    return T$32bit$i(thumb[0]) ? 4 : 2;
}
```

`T$32bit$i`：

```cpp
static inline bool T$32bit$i(uint16_t ic) {
    return ((ic & 0xe000) == 0xe000 && (ic & 0x1800) != 0x0000);
}
```

## 分析MemHelper类

有4个方法：

1. `static bool isFunctionAddr(void* addr);`
2. `static bool unProtectMemory(void* addr, uint32_t size);` remove写保护
3. `static bool protectMemory(void* addr, uint32_t size);` add写保护
4. `static void* createExecMemory(uint32_t size);` 创建一个可执行的内存

有4个field：

1. `std::vector<void*> all_memory_page;`
2. `void* current_page = nullptr;`
3. `uint32_t page_ptr = 0;`
4. `static uint32_t page_size;` 构造函数`page_size = sysconf(_SC_PAGESIZE)`。

我们现在分析一下`createExecMemory(uint32_t size)`：

1. 可以看到，分配内存的操作是通过`mmap`实现的。
2. `all_memory_page`是一个vector，每个单位保存一个指针，指向`mmap`的内存。

### createExecMemory

```cpp
void *FAHook::MemHelper::createExecMemory(uint32_t size) {
    if(size & 1) {
        size++;
    }
    if(size > page_size) {
        return nullptr;
    }
    if(gMemHelper.current_page != nullptr && page_size - gMemHelper.page_ptr_ >= size) {
        auto funPtr = (void*)((size_t)gMemHelper.current_page + gMemHelper.page_ptr_);
        gMemHelper.page_ptr_ += size;

        // Align 4
        while(gMemHelper.page_ptr_ & 0x3) {
            gMemHelper.page_ptr_++;
        }
        return funPtr;
    }

    // scroll to next page
    auto newPage = mmap(nullptr, page_size, PROT_READ | PROT_WRITE | PROT_EXEC, MAP_ANONYMOUS | MAP_PRIVATE, 0, 0);
    if(newPage != MAP_FAILED) {
        gMemHelper.alloc_memory_page_.push_back(newPage);
        gMemHelper.current_page = newPage;
        gMemHelper.page_ptr_ = 0;
        return createExecMemory(size);
    }
    return nullptr;
}
```

### 分析`enableJumpStub(info)`

```cpp
bool FAHook::Instruction::enableJumpStub(FAHook::HookInfo *info) {
    auto origAddr = getOriginalAddr(info);
    auto len = info->getJumpStubLen();
    auto stubAddr = info->getJumpStubBack();
    return patchMemory(origAddr, stubAddr, len);
}
```

可以看到，在得到了`origAddr`、`stubAddr`和`len`之后，我们会进入`patchMemory`函数。根据我们前面的分析，它会patch原函数入口指令的前（8或10？）个字节。

### patchMemory

```cpp
bool FAHook::Instruction::patchMemory(void *dest, void *src, uint32_t len) {
    if(dest == nullptr || src == nullptr || len == 0) {
        return false;
    }
    if(!MemHelper::unProtectMemory(dest, len)) {
        return false;
    }
    memcpy(dest, src, len);
    MemHelper::protectMemory(dest, len);
#ifdef __arm__
    cacheflush((Elf_Addr)dest, (Elf_Addr)dest + len, 0);
#endif
    return true;
}
```

首先会调用`unProtectMemory`函数，将对应内存修改为`rwx`；然后调用`memcpy`来修改内存；最后调用`protectMemory`，将对应内存修改为`r-x`。

## 总结

现在我们就基本对该项目进行了简单的分析，这里总结一下：

1. `registerHook`

   主要操作其实就是：

   - `createStub`：创建代理（这个代理就是要执行跳转到`newFuncAddr`函数）。
   - `createCallOriginalStub`：创建callback代理（这个代理就是执行回调，回调我们的`originalFunAddr`）。主要涉及处理PC相关指令，原因在文中已经有介绍。

2. `doInHook`

   - 主要就是`patchMemory`，将`originalFunAddr`函数起始处的几个指令patch为`stubInstruction`。之后函数涉及PC相关指令的修复，方便继续执行原函数。

3. `unHook`

   - 也是`patchMemory`，就是将原函数的原始指令进行复原。

### registerHook函数

我们现在主要分析`registerHook`函数。

先来分析参数。

在Hook之前我们首先要注册这个函数。

函数声明：

```cpp
HOOK_STATUS registerHook(Elf_Addr orginalFunAddr, Elf_Addr newFunAddr,
                         Elf_Addr* callOrigin);
```

参数为原始函数地址、新函数地址、调用原始函数。

函数主要流程：

1. 注册函数信息，计算Hook stub。

   首先判断`originFunAddr`和`newFunAddr`是否是函数地址。

   `auto info = getHookInfo(originFunAddr);` 得到函数信息。

   然后判断函数是否已经被Hook。

2. 检查判断指令类型（Thumb、ARM或x86等）。

3. `createStub(info)`：创建stub，就是在Thumb下创建`ldr.w pc, [pc], addr`来执行跳转到`newFuncAddr`的功能。

4. `createCallOriginalStub(info)`：创建`originalFunAddr`的stub，主要会涉及一些对PC相关指令的处理。
