
两者的区别是，`KeServiceDescriptorTable`仅有`ntoskrnl`一项，`KeServieDescriptorTableShadow`包含了`ntoskrnl`以及`win32k`。一般的Native API（原生API）的服务地址由`KeServiceDescriptorTable`分派，`gdi.dll/user.dll`的内核API调用服务地址由`KeServieDescriptorTableShadow`分派。还有要清楚一点的是`win32k.sys`只有在GUI线程中才加载，一般情况下是不加载的，所以要Hook `KeServieDescriptorTableShadow`的话，一般是用一个GUI程序通过`IoControlCode`来触发（想当初不明白这点，蓝屏死机了N次都想不明白是怎么回事）。（此段摘抄自网络）

### SSDT HOOK 原理

1. 首先是关于内核函数地址是怎么计算的。这里以`NtOpenProcess`为例：

   首先是用IDA加载`ntdll.dll`，查找`NtOpenProcess`查看函数对应的`SystemId`，这个值可以理解为地址表内的一个下标。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202102/889500_JFCG858PQMNRHAD.png)

2. 查看`KeServiceDescriptorTable`（服务描述表）：

   是要用`WinDbg`调试本地内核或者双机调试，执行命令`dd KeServiceDescriptorTable`。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202102/889500_U2BT78UEUBQA2SV.png)

   ![图片描述](https://bbs.kanxue.com/upload/attach/202102/889500_E9KCHTHXTGPR4VR.png)

3. 利用函数表首地址和`SystemId`（下标）计算出目标函数（`NtOpenProcess`）对应的地址。

### 修改SSDT表

实现对`SSDT`表的修改，首先要确保这个表是可写的。可以通过以下3种方法实现对`SSDT`的内存保护机制的修改。

#### 修改方式

**1. 修改注册表**

- 恢复页面保护：`HKLM\SYSTEM\CurrentControlset\Control\Session Manger\Memory Management\EnforceWriteProtection=0`
- 去掉页面保护：`HKLM\SYSTEM\CurrentControlset\Control\Session Manger\Memory Management\DisablePagingExecutive=1`

**2. 改变`CR0`寄存器的第一位**

Windows对内存的分配，采用的是分页管理。其中有个`CR0`寄存器，如下图：

![图片描述](https://bbs.kanxue.com/upload/attach/202102/889500_9534C3FZVRFDZZG.png)

其中第一位叫做保护属性位，控制着页的读写属性。如果为1，则页面可进行读写和执行，如果为0，则只能进行读和执行操作。`SSDT`、`IDT`的页属性默认情况下是只读可执行的。

```cpp
// 设置为不可写
void DisableWrite()
{
    __try
    {
        _asm
        {
            mov eax, cr0
            or eax, 10000h
            mov cr0, eax
            sti
        }
    }
    __except(1)
    {
        KdPrint(("DisableWrite执行失败！"));
    }
}

// 设置为可写
void EnableWrite()
{
    __try
    {
        _asm
        {
            cli
            mov eax, cr0
            and eax, not 10000h // and eax, 0FFFEFFFFh
            mov cr0, eax
        }
    }
    __except(1)
    {
        KdPrint(("EnableWrite执行失败！"));
    }
}
```

**3. 第三种方法就是使用`Memory Descriptor List`（`MDL`）**

获取`SSDT`中函数的地址的方式：

获取`SSDT`内函数的地址需要使用到两个宏，分别是：

- 指定服务的索引：`SYSCALL_INDEX`
- 指定服务的当前地址：`SYSCALL_FUNCTION`

定义如下：

```c
// 根据 ZwServiceFunction 获取 ZwServiceFunction 在 SSDT 中所对应的服务的索引号
#define SYSCALL_INDEX(ServiceFunction) (*(PULONG)((PUCHAR)ServiceFunction + 1))

// 根据 ZwServiceFunction 来获得服务在 SSDT 中的索引号，然后再通过该索引号来获取 ntServiceFunction 的地址
#define SYSCALL_FUNCTION(ServiceFunction) KeServiceDescriptorTable->ntoskrnl.ServiceTableBase[SYSCALL_INDEX(ServiceFunction)]
```

`SSDT HOOK`流程：

![图片描述](https://bbs.kanxue.com/upload/attach/202102/889500_5FU5FY9VZ9UC4A4.png)

在驱动函数的入口函数中，对未进行`SSDT HOOK`前的`SSDT`表进行备份（使用数组保存）。备份时，一个索引号对应一个当前地址。

在卸载`HOOK`的时候，就可以从全局数组中根据索引号恢复为`HOOK`前的服务名的当前地址。
