![](https://bbs.kanxue.com/upload/attach/201805/722644_V8UYES3246H358K.jpg)

那我们来深入探索一下看看其中到底发生了什么.

在获取必要权限后, 程序会检查是否有`-install`参数, 如果没有, 程序就会执行`copy_tmp_with_install_arg`函数跟`collect_encrypt_send`函数, 否则继续执行`iaStorE_and_files`函数

![](https://bbs.kanxue.com/upload/attach/201805/722644_T2Q6Y5UKTMTU5DD.jpg)

在函数`copy_tmp_with_install_arg`里, 它将自身复制到`%TEMP%`目录下并带参数`-install`继续执行

![](https://bbs.kanxue.com/upload/attach/201805/722644_APH55CW72RJMAER.jpg)

有趣的是, 使用`CreateProcess`函数我们有两种方式来运行程序: `CreateProcess(exePath, nullptr, ...);`和`CreateProcess(nullptr, exePath, ...);`. 如果我们通过第一种方法来运行程序, 我们得到的命令行字符串会带有双引号, 第二种则不带.

![](https://bbs.kanxue.com/upload/attach/201805/722644_9CQG9UCPGP96E47.jpg)

该样本使用第二种方式调用`CreateProcess`, 并在进程开始时检查没有引号的参数, 在正常环境下这是可行的, 但是在hybrid analysis沙盒中却没法正常工作. 最可能的原因是hybrid analysis在某种程度上钩取了`CreateProcess`并在检查完参数后, 修改了某些东西后将参数传递给更底层的函数去, 因此在最后我们得到了不同的命令行字符串, 也就是这个字符串导致了样本的反复递归执行

我们也可以使用这种简单的技术来绕过hybrid analysis沙盒(当然any.run除外).

![](https://bbs.kanxue.com/upload/attach/201805/722644_5FQTTPE6RGPE8H6.jpg)

这也是为什么hybrid analysis失效的原因, 让我们回来继续分析样本.

![](https://bbs.kanxue.com/upload/attach/201805/722644_JURG5WKVWXMZHAQ.jpg)

```
def decrypt_traffic(content):
    key = content[:8] + b"1Q2a3k79"
    key = hashlib.md5(key).digest()
    base64_encoded = content[8:]
    encrypted_content = base64.b64decode(base64_encoded)
    IV = 16 * b'\x00'
    mode = AES.MODE_CBC
    decryptor = AES.new(key, mode, IV)
    dec_content = decryptor.decrypt(encrypted_content)

    print(dec_content)
```
