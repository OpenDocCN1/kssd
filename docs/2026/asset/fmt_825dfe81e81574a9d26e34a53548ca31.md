## 三、动静态分析

首先分析原样本，突破口可以从给`MessageBoxA`下断后返回拿到关键点。

![](https://bbs.kanxue.com/upload/attach/202110/826671_C8CF7PQBZRJJHXP.jpg)

这里直接返回到call的位置，直接计算call地址的相对地址，然后扔进IDA进行分析。

![](https://bbs.kanxue.com/upload/attach/202110/826671_H7V8KCYE23REZ2M.jpg)

![](https://bbs.kanxue.com/upload/attach/202110/826671_W28658PVH5XCM4B.jpg)

这个样本在静态分析时之所以没有看到敏感字符串是因为他的字符串都是以字符数组初始化的，

![](https://bbs.kanxue.com/upload/attach/202110/826671_F72DXABJ6SHTT73.jpg)

在分析的时候可以通过先转义这些字符数组的内容，再去分析这个地方执行了什么。比如这里的字符数组为`SetEvent error`，那么说明调用`SetEvent`失败。并且他这个样本调用函数的方式是通过一个类似shellcode的方法获取，然后把函数存放放到一个全局变量里。

我们来到调用了`MessageBoxA`后，直接到函数头部进行一直交叉引用，最后来到了`WinMain`的最初调用处。

![](https://bbs.kanxue.com/upload/attach/202110/826671_SFXVGTG25ZRRCSR.jpg)

这个过程中会发现整个代码中存在很多这种形式的代码。

![](https://bbs.kanxue.com/upload/attach/202110/826671_WTB6WF6WMS5Q82U.jpg)

这些代码看似是在获取`TEB`和`PEB`操作，但是经过简单分析后，发现这些其实就是垃圾代码，只是为了通过增大代码量，用来增加分析时间。

### [1] `StartMainWork`分析

在这个`StartMainWork`函数执行前，会执行几个数据初始化的函数，包括有crc32和crc64表的生成，动态库函数的获取，还有样本之后所需要用到的数据。这里crc32和64生成的函数很好识别，因为其算法固定，且带有常量值，下面是样本生成crc的关键代码。

```c
for ( i = 0; i < 256; ++i )                   // 开始生成crc32表
  {
    crcValue = i;
    for ( j = 0; j < 8; ++j )
    {
      ......垃圾代码........
      if ( crcValue & 1 )
        crcValue = (crcValue >> 1) ^ 0xEDB88320;// 搜索这个值，可以知道这里是CRC算法的常量值
      else
        crcValue = crcValue >> 1;
      g_crc32Table[i] = crcValue;
    }
  }
for ( jj = 0; jj < 256; ++jj )                // 开始生成crc64表
  {
    v45 = jj;
    for ( kk = 0; kk < 8; ++kk )
    {
      ......垃圾代码........
      if ( v45 & 1 )
      {
        LODWORD(v0) = (v45 >> 1) ^ 0xAC4BC9B5;  // 根据这个常量值，搜索后发现是crc64的常量值
        HIDWORD(v0) = (v45 >> 1 >> 32) ^ 0x95AC9329;
        v45 = v0;
      }
      else
      {
        v45 >>= 1;
      }
      g_crc64Table_Low[2 * jj] = v45;
      g_crc64Table_Hight[2 * jj] = HIDWORD(v45);
```

然后比较有意思的就是动态库函数的获取了，该样本采取了类似shellcode的方式获取，通过`Ldr`来遍历自身的dll模块，然后通过都PE文件的解析寻找函数地址，并添加到全局函数表中。该方式在《恶意代码分析实战》一书中第十九章的shellcode符号解析有讲解，这里就不详细解释了。以下是关键代码。

```c
peb = readPEB();
*functionTable = peb;
if ( peb )
{
    // 通过动态调试得知这里获取的是Kernel32.dll地址,参数二为字符串Kernel32.dll通过crc32计算后的结果
    ModuleBase = getModuleBaseByCrcValue(*functionTable, 0xF7784A01);
    functionTable[1] = ModuleBase;
    if ( KernelBase )
    {
        // 直接从目录项里获取参数三对应的函数地址
        procCreateFileA = getProcAddrByDirArray(functionTable[1], -1, (int)&strCreateFileA, 0);
        ....往下的也是一样
    }
    ............
}
```
