## 什么是ETW？

>Event Tracing for Windows (ETW) 是一种高效的内核级跟踪工具，可以让您记录内核或应用程序定义的事件记录到日志文件。您可以实时或从日志文件使用事件，并使用它们来调试应用程序或确定应用程序中发生性能问题的位置。ETW使您可以动态地启用或禁用事件跟踪，从而使您可以在生产环境中执行详细的跟踪而无需重新启动计算机或应用程序。

根据<a href="elink@e7dK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3g2@1N6#2)9J5c8X3q4T1L8%4g2@1i4K6u0V1k6i4k6W2L8Y4c8Q4x3X3c8@1M7X3q4U0K9h3&6Y4">MS docs</a>，事件跟踪API分为三个不同的组件：

+ <a href="elink@7f4K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3g2@1N6#2)9J5c8X3q4T1L8%4g2@1i4K6u0V1k6i4k6W2L8Y4c8Q4x3X3c8@1M7X3q4U0K9h3&6Y4i4K6t1K6j5$3!0F1N6s2u0G2L8r3I4W2M7Y4x3`.">Controller</a>，用于启动和停止事件跟踪会话并启用provider

+ <a href="elink@16cK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3g2@1N6#2)9J5c8X3q4T1L8%4g2@1i4K6u0V1k6i4k6W2L8Y4c8Q4x3X3c8@1M7X3q4U0K9h3&6Y4i4K6t1K6M7s2u0G2N6X3W2V1k6i4u0K6">Provider</a>，提供事件

## 探索ETW组件

### Controllers

诸如<a href="elink@63bK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3X3c8K6k6i4u0$3k6i4u0Q4x3V1k6S2k6r3#2A6L8X3W2K6N6s2u0S2N6r3W2G2L8W2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3X3c8U0L8$3#2E0j5h3&6V1M7#2)9J5c8X3I4G2k6$3#2S2L8R3`.`.">Logman</a>之类的工具是ETW模型中controller的一个很好的例子，因为它创建并管理**事件跟踪会话**和**性能日志**。另外，您可以使用Controller来查询每个组件（即Providers）的元数据。

创建新的事件跟踪会话并启用 ETW providers 的另一种方法是通过位于"控制面板\系统和安全\管理工具\计算机管理\性能"中的内置Windows Performance System Tool。例子稍后给出。

### 列出事件跟踪会话

可以使用logman列出系统中正在运行的事件跟踪会话

```
logman query -ets
```

![](upload/attach/201911/793242_3S9RVT6UGYMGPTH.png)

还可以使用Windows Performance System Tool来查看启用了哪些`事件跟踪会话`以及为它们提供事件的providers。

![](upload/attach/201911/793242_HARBA8RCPTWRXA6.png)

如果还想通过logman知道某个特定事件跟踪会话绑定了哪些事件provider，则可以运行以下命令：

```
logman query "EventLog-System" -ets
```

![](upload/attach/201911/793242_GQZ8APFXW7QRX3B.png)

### 列出ETW Providers

接下来，您可以使用logman列出系统中所有可用的providers：

```
logman query providers
```

![](upload/attach/201911/793242_9KFQYTNP7CBFV49.png)

### 查询指定Providers

如果我想寻找特定的ETW Providers怎么办？可以过滤`logman query providers`结果并查找特定的字符串。例如，我们可以寻找名称中带有单词**Security**的provider，如下所示：

```
$ETWProviders = logman query providers
$ETWProviders | Where-Object { $_ -Like "*Security*" }
```

![](upload/attach/201911/793242_DS3TUJQKJEUNSPE.png)

例如，我们可以选择Microsoft-Windows-Security-Auditing， 并查询其元数据以获取有关它的更多信息。

```
logman query providers Microsoft-Windows-Security-Auditing
```

![](upload/attach/201911/793242_YRQA75VQBGVD24W.png)

还可以通过名为<a href="elink@696K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6D9j5h3I4D9L8%4g2K6P5o6R3$3i4K6u0r3g2$3W2F1g2r3!0G2L8s2y4Q4x3V1k6@1M7X3g2W2i4K6u0r3L8h3q4K6N6r3g2J5i4K6u0r3g2@1g2b7c8i4S2H3L8r3!0J5k6i4t1`.">Windows Events Providers Explorer（WEPExplorer）</a>的工具获取有关特定ETW providers的信息。

![](upload/attach/201911/793242_WHSHTA8TYASQM54.png)

还可以使用<a href="elink@040K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3X3c8K6k6i4u0$3k6i4u0Q4x3V1k6S2k6r3#2A6L8X3W2K6N6s2u0S2N6r3W2G2L8W2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3X3c8U0L8$3#2E0j5h3&6V1M7#2)9J5c8Y4N6W2N6Y4c8#2N6r3W2D9">wevtutil.exe</a>检索有关事件日志和发布者的信息（感谢<a href="elink@05fK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6@1N6$3W2@1N6r3g2J5i4K6u0W2j5$3!0E0i4K6u0r3L8i4y4Z5k6i4u0E0j5h3^5I4z5e0M7H3">Marc Sherman</a>）

## 可以通过事件日志处理任何ETW事件吗？

据<a href="elink@31cK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6@1N6$3W2@1N6r3g2J5i4K6u0W2j5$3!0E0i4K6u0r3L8h3q4@1N6r3W2X3k6i4y4@1j5i4c8A6L8$3^5`.">Matt Graeber</a>的研究，只有有Channel特性的ETW provider适可以通过事件日志被处理。

例如，来自<a href="elink@411K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6T1L8r3!0Y4M7#2)9J5k6h3#2K6k6r3&6Q4x3X3g2E0K9h3y4J5L8%4y4G2k6Y4c8Q4x3X3g2U0L8$3#2Q4x3V1k6F1N6r3c8W2j5Y4g2Y4k6$3W2F1k6#2)9J5c8R3`.`.">Microsoft Ntdebugging blog</a>的<a href="elink@b56K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6T1L8r3!0Y4M7#2)9J5k6h3#2K6k6r3&6Q4x3X3g2E0K9h3y4J5L8%4y4G2k6Y4c8Q4x3X3g2U0L8$3#2Q4x3V1k6F1N6r3c8W2j5Y4g2Y4k6$3W2F1k6#2)9J5c8U0t1H3x3o6W2Q4x3V1j5H3z5g2)9J5c8U0l9^5i4K6u0r3M7r3q4J5N6q4)9J5k6o6u0Q4x3X3c8W2P5s2m8D9L8%4u0A6L8X3N6Q4x3X3c8S2L8X3c8Q4x3X3c8V1k6h3y4G2k6r3W2F1k6#2)9J5k6r3g2@1N6#2)9J5k6s2m8J5L8%4k6A6k6r3g2J5M7#2)9J5k6s2g2K6K9h3&6Y4i4K6u0V1k6i4k6W2L8Y4c8Q4x3X3c8D9L8$3N6Q4x3X3c8U0K9r3q4F1L8X3g2D9M7#2)9J5c8R3`.`.">这篇文章</a>是按步骤的教程，关于通过Analytic channel如何为`Microsoft-Windows-WinINet provider`启用事件跟踪。

我们可以从使用<a href="elink@a05K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6D9j5h3I4D9L8%4g2K6P5o6R3$3i4K6u0r3g2$3W2F1g2r3!0G2L8s2y4Q4x3V1k6@1M7X3g2W2i4K6u0r3L8h3q4K6N6r3g2J5i4K6u0r3g2@1g2b7c8i4S2H3L8r3!0J5k6i4t1`.">WEPExplorer</a>工具开始，以获取有关应用于每个ETW事件的特定Channels的更多详细信息。从下面可以看到，Microsoft-Windows-WinINet/Analytic Channel已应用于Microsoft-Windows-WinINet provider中的大多数事件。因此，它们应由事件日志实时处理。
