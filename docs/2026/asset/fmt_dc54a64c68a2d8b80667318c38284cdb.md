
# [翻译]逆向分析Bandios/Colony木马

SHA256: `59c662a5207c6806046205348b22ee45da3f685fe022556716dbbd6643e61834`

你可以在沙盒网站 `ANY.RUN` 获取该样本

![](upload/attach/201805/722644_FFZ9AHCQSSAMEP3.jpg)

在 `ANY.RUN` 沙盒中我们可以看到, 样本程序使用参数 `-install` 创建了一个子进程, 子进程则在 `%SYSTEM_DIRECTORY%` 目录下生成了多个文件.

![](upload/attach/201805/722644_K3DEMFJGWR2SP7C.jpg)

但如果我们在 `hybrid analysis` 平台运行该样本我们却几乎无法得到任何信息, 并且程序只会反复递归执行不会停下.

![](upload/attach/201805/722644_V8UYES3246H358K.jpg)

那我们来深入探索一下看看其中到底发生了什么.

`注意: 我在分析完后将一些函数重命名了`

在获取必要权限后, 程序会检查是否有 `-install` 参数, 如果没有, 程序就会执行 `copy_tmp_with_install_arg` 函数跟 `collect_encrypt_send` 函数, 否则继续执行 `iaStorE_and_files` 函数

![](upload/attach/201805/722644_T2Q6Y5UKTMTU5DD.jpg)

在函数 `copy_tmp_with_install_arg` 里, 它将自身复制到 `%TEMP%` 目录下并带参数 `-install` 继续执行

![](upload/attach/201805/722644_APH55CW72RJMAER.jpg)

有趣的是, 使用 `CreateProcess` 函数我们有两种方式来运行程序: `CreateProcess(exePath, nullptr, ...);` 和 `CreateProcess(nullptr, exePath, ...);`. 如果我们通过第一种方法来运行程序, 我们得到的命令行字符串会带有双引号, 第二种则不带.

![](upload/attach/201805/722644_9CQG9UCPGP96E47.jpg)

该样本使用第二种方式调用 `CreateProcess`, 并在进程开始时检查没有引号的参数, 在正常环境下这是可行的, 但是在 `hybrid analysis` 沙盒中却没法正常工作. 最可能的原因是 `hybrid analysis` 在某种程度上钩取了 `CreateProcess` 并在检查完参数后, 修改了某些东西后将参数传递给更底层的函数去, 因此在最后我们得到了不同的命令行字符串, 也就是这个字符串导致了样本的反复递归执行

我们也可以使用这种简单的技术来绕过 `hybrid analysis` 沙盒(当然 `any.run` 除外).

![](upload/attach/201805/722644_5FQTTPE6RGPE8H6.jpg)

这也是为什么 `hybrid analysis` 失效的原因, 让我们回来继续分析样本.

`2018.4.17更新: 该绕过hybrid analysis的方法现已被修复`

在带参数(`-install`)执行子进程后, 它会调用 `collect_encrypt_send` 函数并开始收集系统信息

获取windows版本信息:

![](upload/attach/201805/722644_XQSXCRWRWAPPADE.jpg)

收集系统已安装的浏览器信息:

![](upload/attach/201805/722644_Z84NHZT7BQ39R9G.jpg)

`注意: 就算没有安装Chrome浏览器, Windows 10版本的注册表中也含有 HKEY_CURRENT_USER\Software\Google\Chrome 键, 因此这个方法并不可靠`

通过检查 `HKEY_LOCAL_MACHINE\\SOFTWARE\\%AV_NAME%` 键来收集系统已安装的杀毒软件信息:

![](upload/attach/201805/722644_SCHYVNC5APPTPNW.jpg)

获取网卡的MAC地址和系统语言:

![](upload/attach/201805/722644_JEVY22RK2B8HJGJ.jpg)

它将收集到的信息传递给 `machine_info_AES_base64` 函数, 并对信息进行 `AES` 加密和 `base64` 编码(以下将详解这一部分的过程):

![](upload/attach/201805/722644_7W799ZM8BYK55C2.jpg)

在函数 `machine_info_AES_base64` 内它调用 `CoCreateGuid` 来生成8字节的随机数据并加上另一个8字节硬编码值 `1Q2a3k79`:

![](upload/attach/201805/722644_DBUDQ4AERNHB2H9.jpg)

样本使用 `advapi32.dll` 的 `MD5` 函数来计算上述的16字节长字符串的 `md5` 哈希值(在 `8_rand_bytes_8_hard_coded` 函数中)

![](upload/attach/201805/722644_2HQZYHSCB2RM5E5.jpg)

随后, 它使用哈希值作为密钥, 使用 `AES` 算法对系统信息进行加密, 并使用 `base64` 编码已加密内容.

![](upload/attach/201805/722644_R725SQAYCHBHK6E.jpg)

`注意:` `IDA Pro` 插件 `IDAScope` 可以极大地帮助我们检测样本中使用了哪些加密算法.

程序随后将已加密并编码过的数据发送给 `iostream.system.band/dump/io/time.php`:

![](upload/attach/201805/722644_DA4V33P2H8R74SW.jpg)

![](upload/attach/201805/722644_ADU5UYREQTETBDZ.jpg)

首部的8个字节是通过调用 `CoCreateGuid` 函数生成的. 我们可以编写简单的解密代码来解密流量内容.

![](upload/attach/201805/722644_JURG5WKVWXMZHAQ.jpg)

```python
def decrypt_traffic(content):
key = content[:8] + b"1Q2a3k79"
key = hashlib.md5(key).digest()
base64_encoded = content[8:]
encrypted_content = base64.b64decode(base64_encoded)
IV = 16 * b'\x00'
mode = AES.MODE_CBC
decryptor = AES.new(key, mode, IV)
dec_content = decryptor.decrypt(encrypted_content)
print(dec_content)
```

发送完系统信息后, 父进程终止, 但带参数 `-install` 的子进程会继续执行, 在本例中它是继续执行 `iaStorE_and_files` 函数

在调用 `GetNativeSystemInfo` 函数后, 它会根据 `SYSTEM_INFO.dwOemId` 域来解压出对应的32位或64位可执行文件.

![](upload/attach/201805/722644_QZGSBSSN4MD8TH9.jpg)

检查完系统架构后, 它继续调用 `write_spoolsr_and_MSdat` 函数, 在该函数内它使用 `0xDD` 作为密钥, 从 `byte_443870`(在64位系统情况下)位置开始解密出PE文件, 生成 `0x40` 字节的随机数据添加到解密文件末尾, 解密后的文件保存为 `%SYS_DIR%\\spoolsr.exe`, 而之前的加密文件存为 `%SYS_DIR%\\MS.dat`

![](upload/attach/201805/722644_B5QU6TY7FVTJ24A.jpg)

![](upload/attach/201805/722644_YYTAMBPV6PTX6H9.jpg)

类似地, 函数 `KeyHook_usp20_n_dats` 解压, 解密并生成了如下文件: `KeyHook64.dll`, `KH.dat`, `usp20.dll` 和 `UP.dat`:

![](upload/attach/201805/722644_H6828MZA46GEJ29.jpg)

![](upload/attach/201805/722644_V4P6VY8GVVQ74UF.jpg)

`KeyHook64.dll` 由 `KH.dat` 解密得到, `spoolsr.exe` 则是由 `MS.dat`, `usp20.dll` 由 `UP.dat` 解密得到.

随后, 它继续从资源中解压出样本数据(在64位系统是 `0x110` 位置, 32位系统是 `0x108` 位置). 这些数据看上去也都是已加密或已压缩的数据:

![](upload/attach/201805/722644_VGKM4R8H65BDBGB.jpg)

它随后以提取出的数据和数据长度做参数调用 `decompress_` 函数, `IDAscope` 告诉我们该函数使用了 `zlib` 算法的相关常量.

![](upload/attach/201805/722644_PP2KYGY8DJFRZCT.jpg)

![](upload/attach/201805/722644_WEAQBAZ749GY8T8.jpg)

看上去这像是一个驱动文件, 保存至 `C:\Windows\System32\drivers` 目录下, 文件名为 `iaStorE.sys`:

![](upload/attach/201805/722644_JMRH5F24JMQ489D.jpg)

在64位系统中, 它简单地将驱动名填入注册表键 `\HKEY_LOCAL_MACHINE\SYSTEM\CurrentControlSet\Control\CrashControl\DumpFilters`, 将该驱动作为崩溃转储过滤器安装. 在下次重启后, `crashdmp.sys` 将会载入该过滤器驱动到转储栈里, 更多有关 `转储过滤器驱动` 的信息请点击这里:

![](upload/attach/201805/722644_RFRKHKDC4ACRJTX.jpg)

在32位系统中, 它会以创建名为 `iaStorE` 服务的方式来安装该驱动

![](upload/attach/201805/722644_C8TNDBTRDH6Z5E4.jpg)

在解压完文件和安装完驱动后, 该样本退出执行.

所有的相关文件都经过签名, 包括驱动文件. 证书虽然已被其发行机构撤销, 但在Windows上这并不是什么大问题.
