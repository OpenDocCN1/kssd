
# [原创]搭建物理隔离的虚拟网络用于病毒调试

最近突发奇想，想用本机的 `Windbg` 符号调试远程虚拟机中的病毒程序，于是就有了这篇文章。虽然结局是不能使用本机符号调试虚拟机的进程，但是学会了如何搭建隔离网络，先作此笔记记录分享。

## 使用 dbgsrv.exe 远程调试并加载物理机符号

虽然搭建完成了隔离环境，但是我们还面临一个问题：这种远程调试方法要求调试符号必须在被调试机器上（虚拟机）。相信用过虚拟机 `Windbg` 调试病毒的小伙伴都很清楚，符号下载很麻烦。那么有没有什么办法可以让我们调试病毒的同时，使用物理机器上的符号加载？这样一来既可以防止病毒对符号文件的破坏，还能方便代理下载。（想要在虚拟机中的 `windbg` 下载符号，需要额外配置代理，很浪费时间。）

其实微软早就考虑到了这种调试需求，提供了另外一种远程调试的技巧：既能调试远程机器上的 R3 进程，还可以使用本地机器上的物理符号，一举两得。原理就是通过 `dbgsrv.exe` 工具将所有调试信息转发给物理机的 `windbg` 处理。

首先，找到吾爱破解工具包中的 `dbgsrv.exe`。

![图片描述](https://bbs.kanxue.com/upload/attach/202011/784955_65NAC34X4VTB2ZN.png)

在命令行中输入 `dbgsrv -t tcp:port=2:7,password=1234`。含义是：使用 `dbgsrv` 启动 `tcp` 网络监听，开启 2 到 7 中的任意一个端口（当 `windbg` 主动连接时会筛选查找到调试服务端口），设置连接的密码为 `1234`。

![图片描述](https://bbs.kanxue.com/upload/attach/202011/784955_P5XS5X9FWTJFTDZ.png)

启动监听服务后，查看服务端的 IP 地址。

![图片描述](https://bbs.kanxue.com/upload/attach/202011/784955_RF2T3M2ETKH4G3A.png)

然后将吾爱破解中的 `windbg` 拷贝一份到物理机上，因为微软规定必须使用对应版本的 `windbg` 和 `dbgsrv` 才能适配，否则会报错。

在命令行中输入以下指令：

```
windbg.exe -premote tcp:server=192.168.171.131,port=2:7,password=1234
```

![图片描述](https://bbs.kanxue.com/upload/attach/202011/784955_QU9VV23UXVAEXBU.png)

按下回车会发现只是单纯启动了 `Windbg`，并没有任何明显的提示。

![图片描述](https://bbs.kanxue.com/upload/attach/202011/784955_GCR4GC6TR4DG3N9.png)

这时候不要慌，按下快捷键 F6 就可以看到所有可以附加的进程列表，其中有我们熟悉的 `dbgsrv.exe` 和吾爱破解工具包，证明我们确实已经开启了远程调试连接到了虚拟机。

![图片描述](https://bbs.kanxue.com/upload/attach/202011/784955_PFJJZZWCQ7S74YU.png)

随便选择一个 R3 进程进行附加调试，可以看到标题栏已经显示远程调试的配置信息，符号路径也已经变为了我们物理机的路径。

![图片描述](https://bbs.kanxue.com/upload/attach/202011/784955_FMVHZD45QTDQRYX.png)

如果我们要远程创建某个进程进行调试，只需要输入以下命令选项即可：`-c` 选项为创建进程，`-s` 选项表示挂起。这里以剪贴板工具为例：

```
dbgsrv -t tcp:port=2:7,password=1234 -cs [要调试的进程完整路径]
```

输入以下命令：

```
dbgsrv -t tcp:port=2:7,password=1234 -cs clipbrd.exe
```

当连接到远程调试服务器时，会发现进程被挂起，接下来只需要用 `windbg` 附加并恢复挂起进程即可。

![图片描述](https://bbs.kanxue.com/upload/attach/202011/784955_UGTYP5EAD6RTFGH.png)
