嗯，就是解方程嘛！第一式得到`0xB*(v1-v0)=0xc0000000+x*0x100000000`.  第二式`0x7*(v1-v0)=0x60000000+y*0x100000000`

先算`v1-v0`,当`v1-v0>0` 即 `0x0<v1-v0<0xFFFFFFFF` 上式化简为`0xB*(v1-v0)=0xc0000000`, `0x7(v1-v0)=0x60000000`.

当`v1-v0<0`,即 `0x0<v0-v1<0xFFFFFFFF` ——>

`0x0<v1-v0<0xFFFFFFFF`.

`0xB*(v1-v0)=0xc0000000`, `0x7(v1-v0)=0x60000000`.

写个循环![](https://bbs.kanxue.com/upload/attach/201710/759174_bgbt1iq2jwt9ls2.jpg)

发现`i`无解，由此判断可能是作者整人的，真正的算法可能隐藏了起来，仔细检查发现程序存在栈溢出（因为那个算法只要求8个字符有没有限制字数）正确的跳转位于`40102f`

所以可以构造字符串`12345678^p`（`ctrl+p`）`@`发现可以过。

但是题意要求字母和数字所以不对。可以大致推断范围`413030~413939`，`414141~415050`，`416161~417A7A`

输入字符串（`12345678abcd11A`）在`413131`处发现一大堆乱码（第一印象：作者不会这么无聊吧往自己程序弄乱码来整我们吧）

分析一下第一句就是`add esp, -0x10` 嗯？刚好提高栈到第一输入的字符。不会这么巧吧![](https://bbs.kanxue.com/upload/attach/201710/759174_rx40ejjeuooura6.jpg)

！运行一下发现回到了主程序里面。又是这么巧？

还是慢慢跟吧，一大堆的花指令，看得我头皮发麻。反正无聊，慢慢跟吧！。

经过一番慢慢的`F8` ，得到了三个方程

![](https://bbs.kanxue.com/upload/attach/201710/759174_jnzaeu550o5iapw.jpg)

![](https://bbs.kanxue.com/upload/attach/201710/759174_e6eh61n7pyri2oa.jpg)

![](https://bbs.kanxue.com/upload/attach/201710/759174_9asd1ahcobx2ogq.jpg)

得到方程组`(v0-v1)*4+v0+v2=0xeaf917e2`；`(v0-v1)*3+v0+v2=0xE8F08C8`；

`(v0-v1)*3+v0-v2=0xca3c68`;

继续跟下去

程序在`0x413835`处解密出`You get it !`字符串

![](https://bbs.kanxue.com/upload/attach/201710/759174_conjl595q1i2yc6.jpg)

![](https://bbs.kanxue.com/upload/attach/201710/759174_zz9o2jjjqu11t71.jpg)

最后`jmp eax` （`eax=401044`）此处为（打印函数）字符指针为`0x413835`!

最后解方程

```
v2 = (0xe8f508c8 - 0xc0a3c68) / 2;
vd = 0xeaf917e2 - 0xe8f508c8;
v0 = 0xEaf917e2 - v2 - vd * 4;
v1 = v0 - vd;
```

得到字符串`Just0for0fun`   最后添加`11A`溢出字符！
