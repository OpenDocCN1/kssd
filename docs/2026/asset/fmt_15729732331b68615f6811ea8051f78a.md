
# [原创]微信聊天备份加密原理

## 微信聊天备份加密原理

从 14 年某月起，电脑管家提供了微信聊天记录备份的功能，这为我们研究微信聊天记录及微信的加密算法提供了一个研究方向。

1. 和大家分享。

## 准备工具

- `idaq pro`（静态编译工具）
- `ultraedit`（十六进制编辑器）
- `filemoniter`（文件操作监控工具）
- `regmonitor`（注册表操作监控工具）

## 相关算法

`RC4`、`CRC32`

## 分析及定位过程

### 1. 功能由哪个模块提供

首先我们得知道微信聊天记录是腾讯电脑管家的哪个模块提供服务的。这样我们就能够对症下药，减少分析环节的弯路。

大公司的产品都基本模块化，像腾讯电脑管家这种需要不断增加功能的软件，基本为一个大排档，提供入口而已。

而功能是由不同的 `plugin` 来提供，也就是说是由一些小 `EXE` 或 `DLL` 来提供服务。

通过使用该软件查找关键字 `backup`，我们发现是 `plugins\WechatBackup\WechatBackup.exe` 提供了服务。

### 2. 软件运行时的输入、输出及调用情况

在我们静态分析代码前提前做这些工作，就相当于外围扫描，可以精确定位。

这一步是关键，是高手和小白的主要区别。学习这些内容可以减少小白的摸索过程。

#### 主要工具

我们的主要工具是 `idaq`、`ultraedit`、`filemoniter`、`regmonitor`、VC 的 `depends`。

#### 文件及目录分析

通过 `filemoniter`，我们发现 `wechatBackup.exe` 在运行过程中创建了 `WechatBackup.log` 文件，然后又删除了。这里面一定有我们想要的东西。

在 `C:\Documents and Settings\All Users\Application Data\Tencent\WechatBackup\Data\wxid\_XXXXX\2015年04月26日16点58分49秒` 下有三个怪文件。

这里面可能存在备份的聊天记录内容。有些文件的长度不为 8 的整数倍，而且是奇数。在我们的知识结构里，这比较可能是采用了 `RC4` 加密算法。

通过 `regmonitor`，我们发现 `wechatBackup.exe` 打开了注册表项 `[HKEY_LOCAL_MACHINE\SOFTWARE\Tencent\WechatBackup]` 的 `"EnableLog"` 键值。

通过注册表我们发现，该键值不存在，于是直接创建了该键值，并将其置为 `1`。

通过 `idaq` 的 Import 视图，我们发现 `WechatBackup.exe` 没有静态引用 `Decrypt`、`Encrypt`、`MD5`、`RC4`、`AES`、`DES` 之类的函数，但引用了 `KERNEL.DLL` 的 `LoadLibraryW`。

这可能是通过动态加载动态库实现的。我们通过查找关键字 `LoadLibrary`，可以发现使用了 `QMCommon.dll` 动态库中的 `RC4` 和 `CRC32` 函数。

直接用 `idaq` 在相关函数上下断点即可。

### 3. 软件可能的保护措施

作为腾讯电脑管家，本身提供了杀毒和安全保护功能，为此一定会为自身的程序提供保护措施。

一般的保护措施包括：

#### 3.1 加壳加密

我们通过 `ULTRAEDIT` 查看 `WechatBackup.exe`，没有发现 `UPX` 之类的关键字，相关的资源情况正常，没有加密。

如果大公司使用这种方式，则有可能会被一些杀毒软件认为是病毒，从而出现误报。

#### 3.2 提高进程权限或转移到其他内核空间

这种方法会导致反编译及调试工具无法 `attach` 到进程，比较适合腾讯电脑管家这类软件。

在实际调试中，我发现腾讯电脑管家采用了这种方式，阻止了 `idaq` 进行动态分析。

我们有个小办法可以绕开它：就是把 `WechatBackup` 目录单独拷贝到硬盘的其他目录，在新目录下运行 `WechatBackup.exe`，然后用 `idaq` `attach` 到该进程，顺利解决。

#### 3.3 软件加签名

防止被病毒感染。

## 算法分析

1. 备份在电脑中的加密文件有 `WeChatMagicCode` 文件（聊天记录索引）、`data` 文件（聊天记录内容）、`WechatGenInfoCode` 文件（记录用户的 ID、手机类型等信息）。

   这些文件保存在目录 `C:\Documents and Settings\All Users\Application Data\Tencent\WechatBackup\Data\wxid\_XXXXX\XX年XX月XX日XX分XX秒` 下。

2. 我们感兴趣的是 `data` 文件。该文件采用块加密方式，结构是：长度 `XX` + `CRC32`（四字节）+ 聊天记录内容。

3. 加密密钥是 `0123456789abcdef`（重大安全缺陷喔）。

## 总结

1. 反编译分析是比较苦 `B` 的工作，而通过一些外围的分析，可以帮助我们快速地定位到感兴趣的模块。
2. 程序的模块化及完善的日志记录，在正式分析程序前，将这些开关打开，可以为我们分析代码提供许多便利的通道。
3. 直接打开程序的 HEX，可以了解程序的信息。
4. `RC4` 是一种快速的加密算法，特点是加密速度快，字节不需要整 8 补位，减少冗余。这一点可以作为我们区别 `AES`、`DES`、`RSA` 算法的一个突破点。
