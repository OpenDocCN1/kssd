## 4.4 制作一个动态方法

传输给`calli`指令的token方法有一定的调用约定，我们现在要创建符合该方法调用约定的动态方法。从[10]中可知：

方法描述符也是一个metadata token，其中的内容包含：要调用的方法，要放置在堆栈中的参数的数量、类型、顺序，使用的调用约定。

所以，为了创建一个满足token中方法签名的方法，我们要使用一个强大的.NET能力，通过该能力我们可以定义动态方法。通过本流程可实现：

1. 创建一个与被编译的方法签名相同的方法。确保metadata token提供的信息合法。

2. 在当前执行环境中创建了新的动态类型后，就可以定制一个有效的metadata token了。

该动态方法会调用另一个方法（一个调度器），该方法有两个参数：一个标识要加载的汇编文件位置的`string`，一个包含要传给方法的参数的对象数组。创建该方法过程中要多注意创建对象数组，在.NET中不是所有东西都是对象。下面的伪代码创建有正确签名的动态方法：

## 4.5 调用用户定义的代码

为了方便扩展，我们实现了一个机制来加载一个用户定义的汇编文件并调用一个指定的方法。就像一个基于插件的体系结构。我们称插件为：监控器。每个监控器配置来拦截一个特定方法。为了定位监控器，我们使用软件定义范式“约定优于配置”，这表示所有名字以`Monitor`结尾的类都被加载。最后这个方法很简单，只是从栈中取得`MethodBase`对象，传给监控器并调用它。`assemblyLocation`参数指定用户的汇编文件在哪里。

```
------#------#------#------<START CODE>------#------#------#------

let dispatchCallback(assemblyLocation: String, argv: Object array) =

    if File.Exists(assemblyLocation) then

        let callingMethod =

            try

                // retrieve the calling method from the stack trace

                let stackTrace = new StackTrace()

                let frames = stackTrace.GetFrames()

                frames.[2].GetMethod()

            with _ -> null



        // invoke all the monitors, we use "convention over configuration"

        //调用所有监控器

        let bytes = File.ReadAllBytes(assemblyLocation)

        for t in Assembly.Load(bytes).GetTypes() do

            try

                if t.Name.EndsWith("Monitor") && not t.IsAbstract then

                    let monitorConstructor =

                        t.GetConstructor([|

                            typeof<MethodBase>;

                            typeof<Object array>|])

                    if monitorConstructor <> null then

                        monitorConstructor.Invoke([|callingMethod; argv|]) |> ignore

            with _ -> ()

------#------#------#------<END   CODE>------#------#------#------

```

## 4.6 修复SHE表
