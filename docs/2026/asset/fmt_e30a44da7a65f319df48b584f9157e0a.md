
## 1、查找相关指令

通过`OllyFindAddr`插件中的`Overflow return address -> POP RETN+N`选项查找相关指令。

作者建议`Number of pop = 1`、`Number of ret = 0x28`。

![图片描述](https://bbs.kanxue.com/upload/attach/201903/713428_EMYT2C2GW7WJHMR.png)

在搜索过程中，选取指令时要求不能对`ESP`和`EBP`操作，否则将失去对程序的控制权。这里我们选择`0x7C974A19`。

```c
char shellcode[] = {"\x90\x90\x90\x90\x90\x90\x90\x90"\

"\x90\xc1\x80\x7c"

"\x85\x8b\x1d\x5d"

"\x19\x4a\x97\x7c"

"\x24\xcd\x93\x7c"};
```

## 2、OD 载入

此时`ESP = 0x0012FF34`。

![图片描述](https://bbs.kanxue.com/upload/attach/201903/713428_23MVGSYQR7WNEE8.png)

单步，发现`ESP`变成了`0x0012FF3C`，相差了 8 个字节！为什么？

![图片描述](https://bbs.kanxue.com/upload/attach/201903/713428_RRJGBTNJCZVVXNV.png)

这是因为执行`retn ESP-4`，但指令是`retn 0x4`，因此`ESP-8`。所以执行完`retn 0x28`之后的返回地址在`0x0012FF3C`处！

单步，果然！

![图片描述](https://bbs.kanxue.com/upload/attach/201903/713428_ZTFB74569TV67M4.png)

因此在调整`ESP`大小时要留出 4B 的大小。

## 为什么返回到 `0x41414141` 了？

也就是为什么`ESP`会是`0x0012FF38`而不是`0x0012FF3C`呢？

因为`leave`指令等价于`mov esp, ebp`和`pop ebp`。

### 当执行 `leave` 之前

![图片描述](https://bbs.kanxue.com/upload/attach/201903/713428_WQRDRPW5VY42R39.png)

所以执行`leave`之后，`esp = 0x0012FF34`，然后`esp + 4 = 0x0012FF38`。

在执行`retn 0x4`后，`esp + 8 = 0x0012FF40`。

## 第四阶段

一般来说，这个空档用进程空间中的`jmp esp`指令地址填充，使得关闭 DEP 后，`shellcode`进入堆栈继续执行。

### 1、查找 `jmp esp` 指令地址
