### Pwn1

这道题包含了一个可以直接利用的可以返回shell的函数，现在的任务就是计算偏移，然后将shell函数的地址覆盖到相应的位置上就可以利用成功。

首先来查看一下该程序的保护情况，发现开启了堆栈保护（NX），是一个32bit的程序，因此需要在32位的linux环境下测试。

![](https://bbs.kanxue.com/upload/attach/202002/823237_HJ4ZE45TMW5A5F2.png)

![](https://bbs.kanxue.com/upload/attach/202002/823237_NGPQMWMWBW7NYBB.png)

![](https://bbs.kanxue.com/upload/attach/202002/823237_F38JSXZ6KE36VH4.png)

可以明显看到漏洞是在`gets`里面，`gets`接收输入存在缓冲区溢出漏洞，可以通过超长字符串溢出来利用此漏洞。

为了可以利用此漏洞，我们需要先计算输入的字符串的堆栈地址距离栈底`ebp`的位置，`ebp`的下一个地址就是返回地址的位置，在32位程序中是`ebp+4`。

由两种方法可以得到字符串距离返回地址的距离：1.手工计算；2.利用`pattern offset`计算

先说手工计算：利用gdb的插件gef可以查找`esp`的地址，gdb附加程序，然后在`gets`函数位置下断点：`b 0x080486AE`

![](https://bbs.kanxue.com/upload/attach/202002/823237_2BQ8E89TS6SGSWR.png)

可以看到`esp`的地址是0xbfffeed0，`ebp`地址是0xbfffef58，字符串（`eax`）相对于`esp`的索引为`[esp+80h-64h]`= `[esp+0x1c]`，字符串的地址是0xbfffeeec，所以字符串相对于`ebp`的偏移为 0x6C（108），相对于返回地址的偏移为 0x6c+4（112）。

![](https://bbs.kanxue.com/upload/attach/202002/823237_ZYVPERP749P3BDC.png)

另一种方法是用工具`pattern offset`来计算，直接下载就可以，262K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6V1k6i4y4%4L8%4u0V1i4K6u0r3M7$3S2W2L8r3I4U0L8$3c8W2i4K6g2X3N6r3!0G2L8s2x3`.

### Pwn2

这里没有可以直接利用的`system()`函数，现在就只能使用系统调用来操作了，Syscall函数的调用规范是：`execve("bin/sh",0,0)`

对应的汇编代码是：

```
pop eax,   # 系统调用号载入， execve为0xb
pop ebx,     # 第一个参数， /bin/sh的string

pop edx, # 第三个参数，0
int 0x80,  # 执行系统调用
```

```
#!/usr/bin/env python
```
