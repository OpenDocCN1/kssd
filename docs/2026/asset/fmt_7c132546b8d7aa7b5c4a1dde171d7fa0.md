### 高级登记

上面我们简要介绍了一些与“高级”登记有关的逻辑，并表示我们不会故意使用它们。但是，值得一提的是，尽管我们没有明确地将它们用于开发利用，但我们仍会滥用一些与逻辑相关的功能来帮助我们进行调试。

高级登记用于“分布式”事务场景，其中一些登记分散在某个分布式渠道中，而一个登记负责其他登记。我们认为，在 <a href="elink@60fK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3E0@1L8g2)9J5c8X3E0W2M7X3&6W2L8q4)9J5k6s2c8J5j5h3&6K6j5h3y4@1K9h3!0F1i4K6u0V1L8h3q4F1j5h3N6W2M7W2)9J5k6s2m8G2M7Y4c8S2L8l9`.`.">MSDN KTM 门户上</a> 对它们的描述有些欠缺，因为没有一个地方可以简洁地对其进行解释。它在传递各种函数描述时更容易被提及。

最重要的是，当您试图了解KTM API并选择要使用的函数时，了解某些功能仅适用于高级登记，而另一些功能用于非高级登记是很有用的, 这可能会有些混乱。特别是，仅高级函数的命名通常看起来像您想使用的名称。区别的方法是任何以`Enlistment`结尾的 API 名称通常只能在高级登记中使用。但是，如果API名称以`Complete`结尾，则适用于非高级登记。API文档中对此进行了详细的技术描述，但是如果您不熟悉KTM，并不一定总是很清楚。例如，对于诸如 <a href="elink@f36K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3E0@1L8i4M7K6x3W2)9J5c8X3&6X3i4K6u0V1K9%4c8E0N6K6x3J5i4K6u0V1j5$3!0E0L8h3W2@1k6h3&6D9K9i4y4@1L8h3g2F1N6l9`.`.">`CommitEnlistment()`</a>之类的内容，它的含义如下：

```

```

将它与 <a href="elink@708K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3E0@1L8i4M7K6x3W2)9J5c8X3&6X3i4K6u0V1K9%4c8E0N6K6x3J5i4K6u0V1j5$3!0E0L8h3W2@1j5$3!0E0M7r3I4W2N6r3f1`.">`CommitComplete()`</a>相对比，后者表示以下内容：

## 恢复和回滚

在任何时候，内核结构都会跟踪所有登记以及相关的工作。根据API的请求，或发生其他错误时，可以还原部分提交的事务（称为回滚）。相反，请求将登记或与资源管理器关联的所有登记恢复到某个以前的状态称为<a href="elink@9cfK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3E0@1L8g2)9J5c8Y4u0W2j5$3!0$3k6i4u0&6i4K6u0V1M7s2u0G2j5$3g2K6M7$3W2F1k6H3`.`.">恢复</a>。

两者之间的主要区别在于，回滚意味着正在回滚的事务实际上已被搁置，而恢复是尝试使活动事务中涉及的所有登记表都达到某种已知的同步状态，以便事务可以继续进行。这种区别足以围绕我们将要讨论的内容进行讨论。

为了恢复与资源管理器关联的所有登记，我们调用 <a href="elink@110K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3E0@1L8i4M7K6x3W2)9J5c8X3&6X3i4K6u0V1K9%4c8E0N6K6x3J5i4K6u0V1M7X3g2U0L8%4k6W2M7Y4u0W2M7$3!0#2M7X3y4W2L8h3q4F1j5h3N6W2M7R3`.`.">`RecoverResourceManager()`</a>。同样，<a href="elink@cedK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3E0@1L8i4M7K6x3W2)9J5c8X3&6X3i4K6u0V1K9%4c8E0N6K6x3J5i4K6u0V1M7X3g2U0L8%4k6W2M7Y4c8J5j5h3&6K6j5h3y4@1K9h3!0F1L8h3q4F1j5h3N6W2M7R3`.`.">`RecoverTransactionManager()`</a>触发与事务管理器关联的所有内容的恢复。或者，可以使用<a href="elink@924K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3E0@1L8i4M7K6x3W2)9J5c8X3&6X3i4K6u0V1K9%4c8E0N6K6x3J5i4K6u0V1M7X3g2U0L8%4k6W2M7X3g2F1L8r3W2K6N6r3#2W2L8Y4b7`.">`RecoverEnlistment()`</a> 恢复单个登记。

我们使用 <a href="elink@aa2K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3E0@1L8i4M7K6x3W2)9J5c8X3&6X3i4K6u0V1K9%4c8E0N6K6x3J5i4K6u0V1M7X3!0D9L8r3u0S2j5$3E0@1M7X3q4F1M7$3q4U0N6r3W2G2L8R3`.`.">`RollbackTransaction()`</a> 回滚事务，或者，我们可以通过 <a href="elink@851K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3E0@1L8i4M7K6x3W2)9J5c8X3&6X3i4K6u0V1K9%4c8E0N6K6x3J5i4K6u0V1M7X3g2U0L8%4k6W2M7X3g2F1L8r3W2K6N6r3#2W2L8Y4b7`.">`RollbackEnlistment()`</a>使用与该事务关联的登记来回滚事务。

对于理解CVE-2018-8611，我们在测试期间注意到的最重要的一点是，为了进行资源管理器恢复，此资源管理器必须已经具有至少一个已提交的事务要回滚。
