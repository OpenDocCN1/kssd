### BIOS 解包

首先我们需要对 Dump 数据进行解包，并且拿到我们的 BIOS 分区。在主板中并没有开启 DCI 接口的选项，所以我们需要通过魔改 BIOS 来做到。

首先根据 Intel SPI Flash 规范可以写一个检查脚本。规范可以查询文档：Intel® 100 Series and Intel® C230 Series Chipset Family Platform Controller Hub (PCH)。这里我用 AI 和我自己写的 PDF MCP 让 AI 扫描了一下，快速了解了一下内存布局。

```text
┌─────────────────────┬───────────┬──────────────────────────────────────────────────────┐
│ 字段                │ 偏移      │ 内容                                                 │
├─────────────────────┼───────────┼──────────────────────────────────────────────────────┤
│ FD Signature        │ 0x10      │ 固定 4 字节 5A A5 F0 0F                              │
├─────────────────────┼───────────┼──────────────────────────────────────────────────────┤
│ FLMAP0              │ 0x14      │ 中间字节 << 4 = FRBA（Region 表偏移）                 │
├─────────────────────┼───────────┼──────────────────────────────────────────────────────┤
│ Region Table (FRBA) │ 通常 0x40  │ 5 条 ×4 字节，分别描述 FD / BIOS / ME / GbE / PDR 区 │
└─────────────────────┴───────────┴──────────────────────────────────────────────────────┘
```

整理一下就如上表格，主要有魔术字段和 `FLMAP0` 偏移以及 `Region Table` 组成。有这些才能把 BIOS 从 Bin 中切出来。

#### FFS 介绍

```text
SPI Flash 物理芯片
└── Region 1 = BIOS 区（我们关心的部分，13.5MB）
    └── Firmware Volume (FV) ← UEFI 标准的容器格式，一个 BIOS 区可能有多个 FV
        └── Firmware File (FFS) ← FV 里的“文件”
            └── Section（节）← FFS 里再分若干节，可能有压缩
                └── PE32 代码 / 数据 / IFR / 字符串 ...
```

解包出来就是这个：

![图片描述](upload/attach/202605/992284_KSC2B55W9SKM3UT.webp)

FFS 的命名是 GUID 标注，也就是不同厂家里面的 GUID 都是一样的，属于标准了。FFS 说白了就是 BIOS 的各种模块的标准，主板厂太多了，标准必须要统一。

`899407d7-99fe-43d8-9a21-79ec328cac21` 这个 GUID 是 AMI Setup FFS 的，我们需要的 DCI 选项就在这个里面。

AMI FFS 结构如下：

```text
file-899407d7-.../
├── file.obj ← FFS 原始内容（含 24B FFS header）
├── section0.dxe.depex ← Section 0：DXE 依赖描述
├── section1.guid ← Section 1 的 GUID（告诉你 section1 用什么算法封装）
├── section1/ ← Section 1 解开后的子目录
│   ├── guided.certs
│   ├── guided.preamble
│   ├── section0.pe ← 解出来的 PE32（1.4MB）
│   └── section1.version
```

![图片描述](upload/attach/202605/992284_F2VTDRBVH4TTGRX.webp)

![图片描述](upload/attach/202605/992284_FCWJY77RDV67YW2.webp)

FFS 里有 2 个 section：

| Section | 类型 | 内容 |
|---|---|---|
| `section0` | DXE Dependency Expression | 一段几字节的小数据，告诉 BIOS“我这个 Setup 模块依赖 PCH_INIT 完成后才能加载”。 |
| `section1` | GUID-Defined Section | 这里是个被特定 GUID 算法压缩的容器，里面又套了一层 PE32。 |

核心实际上就是这个：`section0.pe`

![图片描述](upload/attach/202605/992284_BCY5XJJDNM2E2ZZ.webp)

标准的 `4D5A` PE 头。

```text
section0.pe（1.4MB）
├── PE Header ← 标准 PE 头
├── .text 段 ← Setup 模块的 x86 机器码（BIOS 启动时跑的）
├── .data / .rdata 段 ← 静态数据
└── HII Resource 区 ← 重点
    ├── HII Package List Header
    ├── String Package（类型 0x04）← 8000+ 个菜单字符串
    └── Forms Package（类型 0x02）← 4000+ 个 IFR Question 定义
```

我们的核心就是解析 String Package 和 Forms Package，并且将它们映射起来，就能找到我们想要的开关。
