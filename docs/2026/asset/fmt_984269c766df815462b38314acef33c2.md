这是接下来一系列关于通过驱动漏洞进行 Windows 内核驱动攻击里的第一部篇。

在这个项目里我将会使用的带漏洞驱动是 [HackSys Extreme Vulnerable Driver](https://bbs.kanxue.com/elink@aa3K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6Z5j5h3y4C8M7%4W2K6N6r3g2S2L8g2)9J5c8V1S2S2j5$3E0e0P5i4y4q4P5s2c8J5k6h3#2W2g2Y4g2D9L8X3g2J5j5h3u0D9k6f1c8J5K9i4k6W2M7R3`.`.)，你可以写一系列的基于 IOCTL 的攻击。

这个驱动可以下载 x86 和 amd64 两个已编译版本。这篇文章中我将使用 x86 版本，因为会更好理解。

为了热插拔加载驱动到 Windows 里，HackSys 推荐使用 [OSR Driver Loader](https://bbs.kanxue.com/elink@066K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6%4N6%4N6Q4x3X3g2G2M7%4u0G2L8X3I4A6L8X3g2Q4x3X3g2U0L8$3#2Q4x3V1k6S2M7Y4c8A6j5$3I4W2i4K6u0W2j5$3k6E0i4K6y4r3j5i4u0@1K9h3y4D9k6g2)9K6c8o6p5#2y4H3`.`.)。

## 虚拟机通信设置

我的操作系统是 Linux，所以我无法在我的电脑上运行 WinDbg 来与 Windows 7 虚拟机通信。

所以我最后设置了两个虚拟机，均使用相同的 Windows 7 SP1 x86 镜像。然后我使用 VirtualBox 在我的 Linux 上设置了一个文件，通过这个文件来建立两个虚拟机之间的通信。

在虚拟机电源关闭的情况下，我设置了第一个虚拟机的 Serial Port。这个虚拟机将被用于运行 WinDbg 的调试。

![](https://bbs.kanxue.com/upload/attach/201709/760945_0ro0cvqtbbotgdl.png)

第二个用于安装 HackSys 驱动的虚拟机的设置和第一个类似。

![](https://bbs.kanxue.com/upload/attach/201709/760945_5gj6aovln3ksgp7.png)

这样，两个虚拟机间通过 `/tmp/win_link` 的通信就完成了！

## 虚拟机调试设置

现在虚拟机配置好了，我们要做些设置来让通信运行起来。

打开用于调试的虚拟机并且安装 WinDbg。完成后我们需要设置环境变量来告诉 WinDbg 内核符号的来源。

设置 `_NT_SYMBOL_PATH` 环境变量到 [8eaK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6E0M7$3c8D9i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6r3!0%4L8X3I4G2j5h3c8Q4x3V1k6K6P5h3#2T1L8$3I4K6](https://bbs.kanxue.com/elink@fe7K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6E0M7$3c8D9i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6r3!0%4L8X3I4G2j5h3c8Q4x3V1k6K6P5h3#2T1L8$3I4K6)，搞定！

现在打开被攻击的虚拟机，我们需要打开 Windows 调试启动选项。

首先我们到 command prompt 里把现在的启动设置复制到一个我们将编辑的新入口：

```text
bcdedit /copy {current} /d "Debug"
```

这个命令会产出一个我们将要用于引用新的调试选项的 GUID。现在我们开通启动选项的调试模式。

```text
bcdedit /debug <GUID> on
```

搞定！我们在这个虚拟机上现在拥有一个打开了调试选项的开机设置，它将会通过我们的通信文件传递信息给用于调试的虚拟机。

现在我们回到用于调试的虚拟机并打开 WinDbg。去到 File -> Kernel Debug 并输入 115200 来进行通信，使用 `com1` 当接口。

![](https://bbs.kanxue.com/upload/attach/201709/760945_mwitwtwn9s4oeg0.png)

重启被攻击的虚拟机，并在启动菜单里选择“Debug”。让它进入到桌面，之后通过选择 Debug -> Break 在 WinDbg 里创建一个中断，使被调试的 Windows 虚拟机中断。

如果 WinDbg 给你一个 `kd>` 命令行，并且被攻击的虚拟机卡住了，那恭喜你，成功中断了！

![](https://bbs.kanxue.com/upload/attach/201709/760945_uf546201yqrpbbj.png)

## 安装 HackSys 驱动

现在虚拟机已经被设置成可以调试，我们将要把 HackSys 驱动装到被攻击的虚拟机来攻击它。

驱动默认不会有很多调试信息，所以我们要打开这些调试信息。

当虚拟机被中断时，我们可以通过以下命令来改变 WinDbg 里的 Default Mask。

```text
ed nt!Kd_Default_Mask 8
```

你可以通过在 `kd>` 里输入 `g` 来继续虚拟机的运行。我们将这样做，进而安装驱动。

假设你已经有了一开头我提到的那些驱动以及安装程序，我们就可以开始装驱动了。打开 OSR，你可以设置浏览到驱动路径并且让服务自动开启，然后注册这个服务。当注册完成直接开始服务。

![](https://bbs.kanxue.com/upload/attach/201709/760945_s9nnkph56rf5rjk.png)

做了这些以后，WinDbg 会有些调试的信息。

![](https://bbs.kanxue.com/upload/attach/201709/760945_ryn36w5xbxprpja.png)

现在驱动安装好了并且在运行了，我们将安装 HackSys 驱动的符号，这样 WinDbg 才可以更有用。

我们可以通过以下命令在 WinDbg 里找到 HEVD 模块。

![](https://bbs.kanxue.com/upload/attach/201709/760945_kjwovu7tsbx3tpg.png)

最后一行就是 HEVD 驱动，`deferred` 代表 WinDbg 没有加载任何符号。

我们可以通过以下命令打开路径调试信息来找到放 HEVD 的 PDB 的位置：

```text
1: kd> !sym noisy

noisy mode - symbol prompts on
```

尝试打印全部 HEVD 的函数，我们可以找到 WinDbg 需要我们放 HEVD PDB 文件的位置。

```text
1: kd> x HEVD!*

*** ERROR: Module load completed but symbols could not be loaded for HEVD.sys

DBGHELP: HEVD - no symbols loaded
```

`C:\ProgramData\dbg\sym\HEVD.pdb\D241CC04CE0B472CB88B1476958369FB1\HEVD.pdb`

在调试的虚拟机上存个和你的驱动版本相同的 PDB 文件并且运行 `.reload` 来重新加载符号。所以你现在可以运行：

