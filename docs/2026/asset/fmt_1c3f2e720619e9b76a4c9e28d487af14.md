
# [原创]某聊天工具消息记录数据库文件解密逆向分析

## 0x00 简介

每一个聊天工具账号登入后，会在“`\Document\Tencent Files\账号`”目录下的`Msg3.0.db`文件里写入加密后的聊天记录信息。

![image-20210308211235793](https://bbs.kanxue.com/upload/attach/202103/870016_HQ6NYCK4DZ5GPPG.jpg)

查看该工具的`Bin`目录下的 Dll 文件可以知道它用的是 sqlite 的数据库，sqlite 默认没有实现加密的函数，只是提供了接口，网络上有一些开源的加密库，比如`wxsqlite3`、`sqlcipher`等。

## 0x01 前期准备

先在 IDA 中分析`sqlite.dll`，查找含有`version`字符串的函数，然后交叉引用，找到上一个函数就可以发现当前程序使用的 sqlite 的版本号，可以从网上下载源码方便进一步分析，下载链接在文末。

## 0x02 获取加密所需的函数

在`sqlite.dll`里对这些函数下断点动态调试，发现没有断下来。结合网络上前辈的分析，在 IDA 中打开`KernelUtil.Dll`，函数名字都很类似，猜测这个 Dll 就是 tx 自己对 sqlite 的具体实现。

![image-20210308215913751](https://bbs.kanxue.com/upload/attach/202103/870016_RWWBAAXN6UCQGZQ.jpg)

我们可以先在`CMultiSQLite3DB::innerOpen()`等`open()`函数下断点，并打开火绒剑对文件操作进行监控。具体下断点的方法就是附加进程，然后在模块里找到`KernelUtil.Dll`，在 IDA 找到要下断点的函数的偏移，`[KernelUtil.Dll + 偏移]`就是要下断点的位置。

![image-20210308220930031](https://bbs.kanxue.com/upload/attach/202103/870016_X8VQDTUZP95QPSS.jpg)

然后观察堆栈传递的参数，结合火绒剑和 x96dbg 单步步过，就可以找到是哪个函数真正打开 db 文件。

![image-20210308221236907](https://bbs.kanxue.com/upload/attach/202103/870016_VXVJZJ3UC9ZRA33.jpg)

![image-20210308221339573](https://bbs.kanxue.com/upload/attach/202103/870016_XHMXCV7QATA6C2S.jpg)

结合 sqlite 源码和 IDA 分析，可以还原参数和函数名。

![image-20210308221501155](https://bbs.kanxue.com/upload/attach/202103/870016_EG6WY8HV8RA3APS.jpg)

在`innerOpen()`这个函数中，我们可以看到`CppSQLite3DB::execDML()`这个函数，可以大胆猜测它是封装了`sqlite3_exec()`，结合源码进行重命名。`sqlite3_exec()`的第三个参数和第四个参数是回调函数，主要作用是接收 SQL 语句执行的结果，这在后续编写 Demo 时会用到，具体用法可参考文末的链接。

![image-20210309103313016](https://bbs.kanxue.com/upload/attach/202103/870016_MGX7GSYNH268RNR.jpg)

`sqlite3_key()`的具体实现函数，我们可以在 IDA 中观察`CppSQLite3DB::key()`这个函数，并结合 sqlite3 的源码推测真实设置 key 的函数，不妨在此处下断点，后续抓取 Key 时会起大作用。

![image-20210309101320776](https://bbs.kanxue.com/upload/attach/202103/870016_YUN74JPPMGYVMSJ.jpg)

![image-20210309112638238](https://bbs.kanxue.com/upload/attach/202103/870016_VH3N4WXS6MHM9BB.jpg)

至此，我们获得了后续抓取解密 Key 所需要的几个函数地址，在 x96dbg 的对应偏移位置下上断点。

## 0x03 抓取解密 Key

Key 是云端生成的，理论上**没有账号的密码是打不开这个聊天记录文件的**，并且每次打开程序后的密钥都不一样，所以这里得注意：**抓到密码后关闭程序得备份`Msg3.0.db`**这个文件，文件与 Key 是一一对应的。

我们先让它正常登入，然后在火绒剑观察它是什么时候对`Msg3.0.db`进行操作的。可以发现是在比较靠前的位置就打开了`Msg3.0.db`，所以大胆猜测是在进程刚启动的时候执行解密操作。接下来附加进程开始调试。

![image-20210309110939236](https://bbs.kanxue.com/upload/attach/202103/870016_H7D8Y22XG4W2YPU.jpg)

在附加进程的时候得注意，选择上面那个进程；下面那个是登入进程，在登入成功后会自动销毁。

![image-20210309105352740](https://bbs.kanxue.com/upload/attach/202103/870016_6Z8D296G4NCVACC.jpg)

在`CreateFileW()`下断点，观察火绒剑和 x96dbg 堆栈，直到发现它打开了`Msg3.0.db`这个文件。

![image-20210309111748114](https://bbs.kanxue.com/upload/attach/202103/870016_3B6WX3GP3FBDUEP.jpg)

一直按 F9，直到调用`sqlite3_open()`函数时其参数有`Msg3.0.db`（期间可能有多个地方调用了 open，真实的是先调用 `open()` 后调用 `key()`，多次尝试可以试到真实获取解密 Key 的地方）。根据上文可知，sqlite 会先打开对应 db 文件，并在后面再设 Key。根据 IDA 分析结果可以知道原始 Key 是 16 位的，扩展之后变成 16 * 17 位了。

![image-20210309112339132](https://bbs.kanxue.com/upload/attach/202103/870016_PFB7NE36Y5EC5F4.jpg)

![image-20210309114248259](https://bbs.kanxue.com/upload/attach/202103/870016_4XYS57DNMZB74DS.jpg)

![image-20210309114359748](https://bbs.kanxue.com/upload/attach/202103/870016_XMZKR27ND3RRH97.jpg)

有了扩展 Key，可以直接调用`sqlite3_key_impl()`这个实现函数，也可以使用原始 16 位 Key 直接调用`sqlite3_key()`。备份好`Msg3.0.db`和 Key，开始编写 demo。

## 0x04 总结

总的来说，主要是要找到 sqlite 解密各个函数的偏移地址和解密 Key。有个小坑就是 Key 是动态的，而且和`Msg3.0.db`一一对应，每次抓到 Key 得记得备份`Msg3.0.db`。所以我们可以直接调用 tx 的`KernelUtil.Dll`，在 Load `KernelUtil.Dll` 时要注意放在`\Bin`目录下，不然会导入失败，因为`KernelUtil.Dll`还有导入其他的 Dll。
