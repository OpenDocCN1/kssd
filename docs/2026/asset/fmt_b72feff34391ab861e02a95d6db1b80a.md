# KdDebuggerEnabled检测

对CC进行`gn`之后，我们发现虽然系统正常运行，但是调试机再次'失联'了，并且应用提示检测到'调试模式'，查看dump，可以发现`nt!KdDebuggerEnabled`被清零了，这是一个对内核调试很重要的字段，清零就意味着客户机不会再响应调试器的任何请求。

机制很简单，我不打算继续深究其具体实现，打补丁，过校验等，也许可以用一种相对通用的思路来解决这种检测（考虑到TP等也有类似的检测机制）：

1. 将`nt!KdDebuggerEnabled`及`nt!KdDebuggerNotPresent`换个位置存储
2. 找到系统对这两个变量的引用，重定向到我们指定的位置
