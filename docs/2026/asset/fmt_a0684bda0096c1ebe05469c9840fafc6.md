
```
8053e54d 8b0d40f0dfff      mov     ecx,dword ptr ds:[0FFDFF040h]
8053e553 8b6104            mov     esp,dword ptr [ecx+4]
8053e556 6a23              push    23h
```

这个！`ffdff040` 就是 `KPCR` `TSS`指针所指向的 `KTSS` 的指针，所以他将这个值给了 `ecx`，再通过 `ecx+4` 获得 `ESP0` 的地址，因为当前的 `esp` 所在的是 `KTRAP_FRAME` 的 `V86Es`，所以 `push 23` 修改了 `V86Es` 上层成员 `HardwareSegSs`。

##### `KTRAP_FRAME` 结构

在 `KiFastCallEntry()` 中将 context 信息保存在一个被称为 `KTRAP_FRAME` 的结构里，因为我们已经获取到了 `ESP0` 的地址，`KTRAP_FRAME` 的基址为 `Esp0 - 0x7c`

![image-20210817164718816](https://bbs.kanxue.com/upload/attach/202109/873515_KJMJ2MRQGJ7QW3T.png)
