
# 文件系统过滤驱动

文件系统过滤驱动程序会在每个文件系统 I/O 操作（创建、读取、写入、重命名等）中被调用，因此它可以修改文件系统的行为。文件系统过滤驱动程序与传统驱动程序几乎相似，但它们需要执行一些特殊的步骤。反病毒软件、安全软件、备份软件和快照软件等都会使用这类驱动程序。

## `IrpDispatch.c`

### 发送请求

这个 IRP 处理程序只是将请求传递到下一个驱动。我们的下一个驱动对象存储在我们的设备扩展中。

```
/////////////////////////////////////////////////////////////////
// PassThrough IRP Handler

NTSTATUS FsFilterDispatchPassThrough(
    __in PDEVICE_OBJECT DeviceObject,
    __in PIRP           Irp
    )
{
    PFSFILTER_DEVICE_EXTENSION pDevExt =
      (PFSFILTER_DEVICE_EXTENSION)DeviceObject->DeviceExtension;

    IoSkipCurrentIrpStackLocation(Irp);
    return IoCallDriver(pDevExt->AttachedToDeviceObject, Irp);
}
```

### 派遣创建

//////////////////////////////////////////////////////////////////////////////
// IRP_MJ_CREATE IRP Handler

NTSTATUS FsFilterDispatchCreate(

## `FastIo.c`

为了验证 Fast I/O 调度表例程的有效性，我们将使用下面的辅助宏（并不是所有的 Fast I/O 例程都必须由底层文件系统实现，所以我们必须确保相关例程是有效的）。

```
//  Macro to test if FAST_IO_DISPATCH handling routine is valid
#define VALID_FAST_IO_DISPATCH_HANDLER(_FastIoDispatchPtr, _FieldName) \
    (((_FastIoDispatchPtr) != NULL) && \
    (((_FastIoDispatchPtr)->SizeOfFastIoDispatch) >= \
    (FIELD_OFFSET(FAST_IO_DISPATCH, _FieldName) + sizeof(void *))) && \
    ((_FastIoDispatchPtr)->_FieldName != NULL))
```

### 快速 I/O 请求

```
BOOLEAN FsFilterFastIoQueryBasicInfo(
    __in PFILE_OBJECT       FileObject,
    __in BOOLEAN            Wait,
    __out PFILE_BASIC_INFORMATION Buffer,
    __out PIO_STATUS_BLOCK  IoStatus,
    __in PDEVICE_OBJECT     DeviceObject
    )
{
    //
    //  Pass through logic for this type of Fast I/O
    //

    PDEVICE_OBJECT    nextDeviceObject =
      ((PFSFILTER_DEVICE_EXTENSION)DeviceObject->DeviceExtension)->AttachedToDeviceObject;
    PFAST_IO_DISPATCH fastIoDispatch   = nextDeviceObject->DriverObject->FastIoDispatch;

    if (VALID_FAST_IO_DISPATCH_HANDLER(fastIoDispatch, FastIoQueryBasicInfo))
    {

        return (fastIoDispatch->FastIoQueryBasicInfo)(
            FileObject,
            Wait,
            Buffer,
            IoStatus,
            nextDeviceObject);
    }

    return FALSE;
}
```

## `notification.c`

一个典型的文件系统包括控制设备和卷设备。卷设备连接到存储设备栈，控制设备则注册为文件系统控制设备。

![](https://bbs.kanxue.com/upload/attach/201204/508799_s3iwro3m9g9v5qd.png)

我们有一个回调，所有活动的文件系统在注册或注销自身为活跃文件系统时都会调用它。这是连接/分离我们的过滤设备的好地方。当一个文件系统激活自身时，我们挂接到它的控制设备（只在尚未挂接时），枚举其卷设备，并同样挂接到这些卷设备。当文件系统停用时，我们检查文件系统控制设备栈，找到我们的设备并取下。从文件系统卷设备分离则通过前面介绍的 `FsFilterFastIoDetachDevice` 例程完成。

```
////////////////////////////////////////////////////////////////////////////
// This routine is invoked whenever a file system has either registered or
// unregistered itself as an active file system.

VOID FsFilterNotificationCallback(
    __in PDEVICE_OBJECT DeviceObject,
    __in BOOLEAN        FsActive
    )
{
    //
    //  Handle attaching/detaching from the given file system.
    //

    if (FsActive)
    {
        FsFilterAttachToFileSystemDevice(DeviceObject);
    }
    else
    {
        FsFilterDetachFromFileSystemDevice(DeviceObject);
    }
}
```

## `AttachDetach.c`

此文件包含用于挂接、分离以及检查我们的过滤器是否已经连接的辅助例程。

### 挂接

执行挂接时，我们通过 `IoCreateDevice` 创建一个新的设备对象，并设置设备扩展；同时复制要挂接设备对象的设备对象标志（`DO_BUFFERED_IO`、`DO_DIRECT_IO`、`FILE_DEVICE_SECURE_OPEN`）。然后在一个循环中调用 `IoAttachDeviceToDeviceStackSafe`，失败时延时重试。挂接请求可能失败，因为目标设备对象尚未完成初始化；例如当我们试图挂接的卷设备刚刚加载时就会出现这种情况。挂接完成后，我们将被挂接的设备对象保存在设备扩展中，并清除 `DO_DEVICE_INITIALIZING` 标志。设备扩展如下：

```
//////////////////////////////////////////////////////////////////////////
// Structures

typedef struct _FSFILTER_DEVICE_EXTENSION
{
    PDEVICE_OBJECT AttachedToDeviceObject;
} FSFILTER_DEVICE_EXTENSION, *PFSFILTER_DEVICE_EXTENSION;
```
