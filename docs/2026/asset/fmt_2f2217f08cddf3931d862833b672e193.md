
终于，`老朋友ollydbg`要登场了，让`test.py`跑起来，然后“附加”`python.exe`进程，`ctrl^M`，在`ctlutil`的`.text`段下断点。

能看到`i386`的汇编代码真是让人泪流满面啊。

关键算法在`10001020`，整个执行逻辑清晰易懂，不愧是做`python`开发的啊。

我相信有`crack`经验的同学，10分钟内就能理解是怎么运作的。

为了保护原作者，毕竟开发这么好的软件也很不容易，这里对具体的注册算法就不啰述了。

## 尾声

完全破解以后，给开发公司的`support`发了一份信，附上了`keygen`源码，告诉他们我没有恶意，只是提醒一下，他们的注册系统不够安全。

他们说，他们感谢提醒，但是不是很在意，使用`crack`版本的都是无力承担费用的用户，不会对他们的销售造成很大的影响。

多好的公司啊。

于是，我给了他们一些保护软件的建议，希望对使用`python`开发商用软件的同学，也有同样的帮助。

1. 对于关键的代码，尝试用混淆器保护起来。
   可以在`google`里搜索"`obfuscater code python`"。不过，我没使用过，不知道具体的效果会怎么样。
2. 不要用`c`来写关键的算法，编译成`native code`不会有任何帮助，甚至更加糟糕。
   一个`cracker`更加乐意看到汇编代码，而不是陌生的`op code`。
3. 不要把鸡蛋放在一个篮子了。不要一次性的，在一个地方，检查完注册码，激活码。
