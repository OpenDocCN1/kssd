
由于 `state=WEBS_CONTENT`，进入到 `processContent()` 函数处理：先进行 `filterChunkData` 函数的 chunk 过滤处理。当用户在 HTTP 头部使用 `Transfer-Encoding: chunked` 时，数据以一系列分块的形式进行发送。分块传输不是分析重点，并且后续 POC 也不用分块传入，就不深入分析了。简而言之，`filterChunkData` 会设 `canProceed=1`，`wp->eof=1`；后续由于 `cgifd>0`，因此进入到函数 `websProcessCgiData()`。`websProcessCgiData` 处理完后，由于 `eof=1`，因此 `state=WEBS_READY`。

![](https://bbs.kanxue.com/upload/attach/201801/591834_q49b03476wacxc5.jpg)

`websProcessCgiData` 函数也就是把用户 POST 提交的数据保存到 `cgifd` 中。`cgifd` 是先前通过 `cgiStdin=websGetCgiCommName()` 获得的，也就是文件 `/tmp/cgi***`。

![](https://bbs.kanxue.com/upload/attach/201801/591834_x3hw1tlthjqqmc7.jpg)

此时由于 `state=WEBS_READY`、`canProceed=1`，进入到 `websRunRequest(wp)` 函数中。该函数中会先提取 URL 中的 `var` 变量，然后设置 `state=WEBS_RUNNING`，接着调用 `(*route->handler->service)(wp)`，即 `cgiHandler(wp)`。该函数位于 `cgi.c` 中。

![](https://bbs.kanxue.com/upload/attach/201801/591834_mysyaskt7jdu2i6.jpg)

由于 `cgiHandler()` 在处理 CGI 扩展时，只对 `REMOTE_HOST` 和 `HTTP_AUTHORIZATION` 进行了过滤，其他 `var` 变量都会被当成可信环境变量，传入到 CGI 扩展处理进程中。

![](https://bbs.kanxue.com/upload/attach/201801/591834_m033siqhg116ems.jpg)

`cgi.c` 中在处理完参数之后，会将标准输入、输出重定向到 `/tmp/cgi***`，也就是 POST 数据保存的地方，代码详情如下：

![](https://bbs.kanxue.com/upload/attach/201801/591834_4mfl2pykzb24cfx.jpg)

输入、输出重定向完成后，`cgi.c` 中就调用 `launchCgi`，开始调用 CGI 的扩展处理进程，并传入上述 `envp` 生成的环境变量。

> 注意：`launchCgi` 分三个版本：Windows、Unix 和 VXWORKS，函数标注别定位错误。

找到 `launchCgi` 处理函数，代码如下：

![](https://bbs.kanxue.com/upload/attach/201801/591834_6huwt14vgrowrxn.jpg)

执行到函数 `vfork()` 后，会将子进程（也就是 CGI 的处理进程）的标准输入、输出重定向到前文分析到的 `/tmp/cgi***` 文件，也就是 POST 数据存放的文件；然后调用 `execve()` 调用 CGI 处理进程，并传递 `envp` 中的系统环境变量。结合上文分析的 `LA_PRELOAD` 变量，可以实现任意代码执行。

但是现在还存在一个问题：通过环境变量 `LA_PRELOAD` 可以指定加载本地的共享库，进行代码执行，但是如何变成远程危害命令执行呢？也就是如何上传恶意代码，并且通过环境变量 `LA_PRELOAD` 进行指定呢？

在前面分析中我们得知，由于 GoAhead WebServer 在处理 CGI 扩展时，当用户 POST 提交了数据，GoAhead WebServer 会将其存到 `/tmp/cgi***` 中，这不就是可以作为恶意代码了吗？

但是如何知道上传的全路径名称呢？爆破还是其他方法，都不是好的方法。由于 CGI 处理进程中，将标准输入、输出重定向到了 `/tmp/cgi***`，所以现在的问题是：我们能不能找到一个路径连接，使其指向标准输入或输出呢？

Linux 上刚好存在这种符号链接：`/proc/self/fd/0` 和 `/dev/stdin`。于是我们可以在 HTTP 参数中内置 `?LD_PRELOAD=/proc/self/fd/0` 命令。
