
因此，理论上如果想要覆盖数组长度，可以做类似`o.e = 0xFFFFFFFF`的事情，然后使用`some_array [1000]`从数组的基地址访问一些远程地址。

但是有几个问题：

1. 除“a”和“b”之外的所有其他属性尚未定义。这意味着为了在正确的数组中定义`o.e`，我们首先需要分配所有其他属性，这个操作会破坏比需要的内存更多的内存，从而使我们的数组无法使用。

2. 原始的`auxSlots`数组不够大。它最初只分配了4个，如果我们定义了4个以上的属性，`Js :: DynamicTypeHandler :: AdjustSlots`函数将分配一个新的`slot`数组，设置`auxSlots`指向它而不是我们的`JavascriptArray`对象。

3. 计划放在`JavascriptArray`对象的`length`字段中的`0xFFFFFFFF`值将不会完全按原样写入。

4. 即使能够覆盖一些大值的长度，同时避免破坏内存的其余部分，这只会得到一个相对地址。

5. 实际上，覆盖`JavascriptArray`的长度字段是没有用的。在这种特殊情况下实际需要做的是破坏数组的段大小。尽管如此，我们假设覆盖长度字段是有用的，因为它很好地展示了漏洞利用的一些细节。

因此，需要一些特殊技术来克服上述问题，首先讨论问题1和2，首先想到的是在触发漏洞之前预先在`'o'`对象中预先定义更多属性。然后，当覆盖`auxSlots`指针时，我们已经在正确的数组中定义了`oe`。不幸的是，在提前添加更多属性时，会发生以下两种情况之一：

- 过早地更改对象内存布局（＃1），这样就不会由漏洞发生了，因为不再有机会覆盖`auxSlots`指针。

- 只是创建了更多内联函数，在触发漏洞后最终保持内联。该对象最终布局（＃2），大多数属性都位于新的内联函数中。

`Bruno Keith`在他的演讲中提出了一个很好的想法，一起解决问题1和2。首先破坏预先准备好的具有许多属性的另一个`DynamicObject`，而不是直接破坏目标对象（在示例中为`JavascriptArray`），并且已经在内存布局中（＃1）：

```
obj.d = 4;

obj.f = 6;
```
