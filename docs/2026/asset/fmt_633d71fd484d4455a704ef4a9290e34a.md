## 利用步骤

0, 清空对应的工作目录

![图片描述](upload/attach/202311/865065\_7Q5FPDVZBFF2FWN.png)

1, 通过 `HKEY_LOCAL_MACHINE\Software\Microsoft\Windows NT\CurrentVersion` 获得系统版本，根据系统版本判断是否支持利用，并确定 Token 和 PreviousMode 偏移。

![图片描述](upload/attach/202311/865065\_RJV7WGH8BVSCKWR.png)

2, 获得一些基础信息。

获取系统版本

![图片描述](upload/attach/202311/865065\_3XFBDTA6JN42WFT.png)

之后获取对应系统及当前进程的内核偏移，并初始化一系列内存。

通过动态地址获取的方式分别从 `clfs.sys` / `ntoskrnl.exe` 中获取函数 `ClfsEarlierLsn`，`ClfsMgmtDeregisterManagedClient`，`RtlClearBit` / `PoFxProcessorNotification`，`SeSetAccessStateGenericMapping`

![图片描述](upload/attach/202311/865065\_64FZ7XDVY937MQE.png)

![图片描述](upload/attach/202311/865065\_WGP2T5ZMWR7XUWH.png)

3, 检测当前进程的访问令牌的句柄是否存在于系统句柄列表中。

![图片描述](upload/attach/202311/865065\_X6H25EXFDB33G9E.png)

![图片描述](upload/attach/202311/865065\_SZ9GKUQVBT9BS42.png)

之后在 `0x5000000` 位置分配 `0x1000000` 长度的内存

![图片描述](upload/attach/202311/865065\_K6Y3QQJ8C83GCSK.png)

4, 创建 `C:\Users\Public\p\_%08d` 文件并获得其 `_FILE_OBJECT` 的地址。

![图片描述](upload/attach/202311/865065\_XY3KYVBF9EZHG6J.png)

之后获取 `NtFsControlFile` 函数地址，并通过 `ZwQuerySystimeInformation` 获取 `PipeAttributer` 的内核对象地址，在 `0xFFFFFFFF` 上分配长度为 `4096` 的内存，并以此部署 `system` Process token。这个位置使用于辅助 `ClfsEarlierLsn` / `SeSetAccessStateGenericMapping` 进行最终的内存写入。

![图片描述](upload/attach/202311/865065\_RHD437EFQMT3F3K.png)

与 `CVE-2022-37969` 相似

![图片描述](upload/attach/202311/865065\_FN3VTKGGE2W8WJP.png)

5, 创建基础日志 `LOG:C:\Users\Public\MyLog\_%08d` 并修改其日志文件中的数据

通过 `CreateLogFile` 创建第一个 `log file`

![图片描述](upload/attach/202311/865065\_3B9MAQWKKYB8ZH9.png)

![图片描述](upload/attach/202311/865065\_F88SYENMHKAB2QT.png)

修改文件中的位置

![图片描述](upload/attach/202311/865065\_GJX3R2CH7MRXQEV.png)

![图片描述](upload/attach/202311/865065\_43K8S7V528JFVGW.png)

最后调用 `AddLogContainer` 增加一个 `log container`，需要注意对应的 `trigger clfs base block` 内核地址 `para_clfsKerneladdress` 通过 `ZwQuerySystemInforation` 搜索的方式获取，其原理是通过搜索 `0x7a00` 大小标志位 `clfs` 的 `pool`，类似包括 `pipeAttribute` 的内核地址也是通过该方式获取。

6, 后再次创建 `10` 个 `log file`，这里称之为 `spray clfs[i]` 并修改其日志文件中的数据

![图片描述](upload/attach/202311/865065\_FUT29JKSUQHNE7F.png)

![图片描述](upload/attach/202311/865065\_86XRCAV9UY5BNRK.png)

`Spray clfs[i]` 生成之后，在这个位置并没有调用 `AddLogContainer`

7, 使用匿名管道对内核进行内存布局。

首先 `trigger clfs` 对应的内核 `base block` 内核地址 `+0x30` 的位置被循环赋值到一个数组中，然后两次调用函数 `fun_pipeSpray`，对应的参数分别为 `0x5000` 及 `0x4000`。

![图片描述](upload/attach/202311/865065\_X4UHKFWZQF4C76S.png)

`pipeSpray` 为一个 `pipe` 的 `spray`，其根据参数传入的数量生成指定数量对数的 `pipe(read/write)`，第一次 `pipeSpray` 调用传入 `0x5000`，因此生成了 `0x5000` 对 `pipe(read/write)`，这里统一将这 `0x5000` 对 `pipe` 称之为 `pipeA`，第二次的 `0x4000` 称之为 `pipeB`。

![图片描述](upload/attach/202311/865065\_ZPGVSDUKDVVNC7H.png)

遍历 `0x5000` 对 `pipeA`，并调用其 `writepipe` 写入包含 `trigger clfs base block + 0x30` 的数组

![图片描述](upload/attach/202311/865065\_S9M57ARSHJ5VP4F.png)

遍历结束，从 `pipeA(0x2000` 偏移)，第 `174` 对 `pipe` 开始释放，一共释放 `0x667` 对 `pipe` 对。

![图片描述](upload/tmp/865065\_KNZ62QEFREDT3XE.png)

释放结束后，紧接着通过前面的 `spray[i] clfs` 循环调用 `CreateLogFiles`，用 `CreateLogFiles` 调用中某一处内存对象占据前面 `pipA` 中释放的 `pipe` 对。

`CreateLogFiles` 循环占位结束后，遍历 `0x4000` 对 `pipB`，并调用其 `writepipe` 写入前面数组。

![图片描述](upload/attach/202311/865065\_UR8A9SQ9JXPKFXY.png)

8, 为 `LOG:C:\Users\Public\MyLog%d%08d` 添加容器，触发漏洞篡改 `LOG:C:\Users\Public\MyLog\_%08d` 日志的 `rgContainers[0]`。

![图片描述](upload/attach/202311/865065\_ZKS9G3ACK8MWDDT.png)

9, 对 `0x5000000` 进行内存布局。

![图片描述](upload/attach/202311/865065\_YKU7T4MZ9YSQ6HZ.png)

10,1 替换 `token`

对 `clfs` 对象 `trigger clfs`，调用 `CreateLogFile`，通过 `NtFsControlFile` 读取 `system process` 的 `token`，执行了内存 `0x50000000` 中的内容，完成了对 `PipeAttribute` 内核对象的修改，从而使得 `NtFsControlFile` 能实现任意地址读取。

![图片描述](upload/tmp/865065\_8HQ56PU4K4G6EB5.png)

之后重复调用 `CreateLogFile` 触发漏洞，完成进程 `token` 的替换。

![图片描述](upload/tmp/865065\_KHZSRH3TVNECPDJ.png)

10,2

此外样本中同样也支持修改 `priviousMod`，实现任意地址读写来提权的方式。

在 `CClfsBaseFilePersisted::CheckSecureAccess` 中使用了 `fake pContainer(0x5000000)`，并最终调用 `RtlClearBit` 将当前线程的 `PreviousMode` 置 `0`。

将当前线程的 `PreviousMode` 置 `0` 后便可使用 `NtWriteVirtualMemory` 进行内核地址的任意读写。

![图片描述](upload/attach/202311/865065\_G9CABX2ZUC292QT.png)
