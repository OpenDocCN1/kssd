#### 提取频率数组

代码：

```python
# 使用librosa进行频谱分析，并将能量值转换为分贝单位
spectrogram = librosa.amplitude_to_db(librosa.stft(audio_data), ref=np.max)

# 设置阈值，只记录强度大于-10dB的频率
threshold = -10

# 初始化空的频率数组
frequencies = []

# 遍历每个时间帧
for i in range(spectrogram.shape[1]):
    # 获取当前时间帧的能量值
    frame = spectrogram[:, i]
    # 获取强度大于阈值的频率索引
    freq_indices = np.where(frame > threshold)[0]
    # 将符合条件的频率添加到频率数组中
    frequencies.extend(freq_indices)

# 去除重复的频率，并按升序排列
frequencies = sorted(set(frequencies))

print(frequencies)
```

## 编码协议分析

![img](upload/attach/202312/943085_DUNSG4BP6BP2VJQ.jpg)

其中`is64Char`其实是对前三个的汇总，然后多了"-"(45)和"_"(95)，其实就是把"+/"换成"-_"的base64字符串

仔细分析`encodeType`可以做出如下归纳：

```plaintext
type0:全是数字(1111)
type1:前面是小写后面是数字（aa11）
type2:前面是除数字外的base64后面全是数字的(_A11)
type3:含有非base64的(@#$%)
type4:前面全是数字然后出现不是数字的base64的(11_a)
type5:全是小写(aaaa)
type6:只要是由base64组成的(a-_b)
type7:全是大写(AAAA)
```

看上去有些重叠，比如`type6`涵盖了除`type3`的所有。这是因为它返回的时候也是有先后顺序的：

![img](upload/attach/202312/943085_DGZNHDMMPTJK2V9.jpg)

对于8种不同的`type`的详细encode，感兴趣的师傅可以查阅一下csdn上的源码，这里挑两个比较有意思的

首先是`ssid`和`passwd`全是数字的情况，通过下面这个js脚本可以打印encode前后的字符串（这里是对csdn上demo的hook）：

## 后续的工作以及收尾

原生库中的内容其实主要是对编码后的字符进行播放，这涉及的是一个比较庞大的框架，以及涉及很多的信号与系统的原理

而对于我们安全研究人员，其实更关心的是如何控制发送的数据，然后这些数据传入到设备后有没有可能产生漏洞，所以对声波和字符的对应关系笔者就浅尝辄止了

而在知道如何编码`ssid`和wifi以及手上有`so`文件的情况下，我们可以编写一个demo一样的app，调用原生库函数来向目标设备发送配网信息，所以对声波的分析就没有再进行下去了（其实是笔者在经历长时间被c++虚函数的折磨后啥都没有发现的借口罢了23333）
