
如果你使用`Impactor`，你可以直接执行命令来设置这个文件的内容。否则，你需要花更多的时间来使用`jdb`来传递一些字符串来执行，或者上传一个`shell`脚本来间接执行，或者通过以`system`权限运行的`telnetd`来运行命令。

`system@android:/ $ echo ro.kernel.qemu=1 >/data/local.prop`

现在，你可以重启你的设备。当系统起来后，由于模拟器的兼容性问题可能会有一些错误提示。不过你可以使用`adb`了，它会以`root`运行。你只需要将`su`（[可以从我的服务器下载](https://bbs.kanxue.com/elink@199K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8X3y4S2j5$3S2W2i4K6u0W2M7$3q4#2M7X3W2C8i4K6u0W2j5$3!0E0i4K6u0r3j5h3&6V1M7X3!0A6k6q4)9J5c8X3N6D9j5i4y4K6i4K6u0r3M7%4f1`.)）`push`到手机，设置`setuid`，去掉破解文件，然后重启手机。

```

```

```

```

## 检查漏洞

现在，用户可能会想知道他们是否存在这个漏洞。就目前的情况来看，大部分设备是这样的。但你也可能使用的是比较新的设备，是没有这个漏洞的。你可能使用的是第三方`ROM`（比如`CyanogenMod`），可能此漏洞被修复了（假设你经常升级）。

不爽的是，`Bluebox`发布了一个可以检查你的设备是否有此漏洞（文章：[Scan Your Device for Android “Master Key” Vulnerability](https://bbs.kanxue.com/elink@22aK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8X3u0D9N6h3g2T1L8%4S2Q4x3X3g2U0L8$3#2Q4x3V1k6U0L8%4u0H3L8%4u0S2N6r3g2Q4x3X3c8T1L8r3!0Y4i4K6u0r3k6Y4u0W2k6g2)9J5k6s2y4U0j5h3&6F1k6i4u0Q4x3X3c8@1L8#2)9J5k6r3#2S2L8X3q4Y4k6g2)9J5k6s2u0A6M7$3E0Q4x3X3c8G2k6W2)9J5k6r3#2S2K9X3!0J5i4K6u0V1j5h3&6V1M7X3!0A6k6q4)9J5k6s2k6#2L8r3&6W2M7X3q4T1K9h3I4A6N6s2W2Q4x3V1j5`.)），很多人反馈说它会经常说你的设备有漏洞，但其实是没有的。它的问题是，不应该缺省认为有漏洞，而应该缺省没有（原文：that said, false negatives are the real problem here, not false positives）。

还有一种选择是`[SRT AppScanner](https://bbs.kanxue.com/elink@68bK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6H3L8r3q4&6i4K6u0W2k6$3!0G2k6$3I4W2i4K6u0W2j5$3!0E0i4K6u0r3M7%4c8G2M7X3g2Q4x3V1k6S2M7s2m8K6i4K6u0r3k6r3g2@1j5h3W2D9M7#2)9K6c8X3W2V1i4K6y4p5k6r3g2Q4x3X3g2T1j5h3y4C8k6i4y4K6M7Y4c8Q4x3X3g2S2M7s2m8A6L8Y4c8W2k6%4u0A6N6s2V1`.)`，可以在`Play Store`上找到（这个对我也不起作用）。可能`[ReKey](https://bbs.kanxue.com/elink@c6aK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6i4u0W2K9$3g2&6i4K6u0W2K9h3!0Q4x3V1j5`.)`可以检测出来（与仅仅修复不同，不是很清楚）。终于，我找到一个程序——`[Tool to detect Bluebox exploits](https://bbs.kanxue.com/elink@4dbK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0L8$3c8W2i4K6u0W2k6$3!0G2k6$3I4W2i4K6u0W2j5$3!0E0i4K6u0r3M7q4)9J5c8X3u0D9N6h3g2T1L8%4S2Q4x3X3b7K6P5s2l9I4x3r3W2@1i4K6u0V1M7$3y4S2L8X3&6W2M7W2)9J5c8R3`.`.)`（可以检查`apk`）。

不幸的是，这些工具有时候不起作用。一个可能的原因是，根据`[X-Ray](https://bbs.kanxue.com/elink@013K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6i4S2J5j5i4W2Q4x3X3g2A6L8#2)9J5c8R3`.`.)`（另外一个漏洞扫描工具，但不能检查`Master Key`这个漏洞）网站上说的，扫描`Android`设备漏洞的应用是违反`Play Store`的服务条款的。

我们可以理解用户更喜欢从`Play Store`上安装`app`，特别是这些`app`是安全相关的。不幸的，`Google`告诉我们`Play Store`的服务条款不允许像`X-Ray`这样的检查`Android`漏洞的应用。

我主要想说的是，如果你在使用这些软件时遇到问题，它说你是安全的，或者你不相信它们，你可以尝试利用这些漏洞——你可以让`Cydia Impactor`做一些无意义的事（比如说简单地让它执行`echo`），来看看是否会出错。

## Substrate扩展

要修复这个漏洞，看一下`[CyanogenMod的补丁](https://bbs.kanxue.com/elink@8e4K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4u0W2N6X3W2W2N6#2)9J5k6h3y4&6j5h3&6G2k6$3g2F1L8h3!0V1i4K6u0W2L8%4u0Y4i4K6u0r3i4K6t1K6i4K6u0r3j5#2)9J5c8U0b7#2x3U0f1I4i4K6u0r3x3g2)9J5c8X3I4#2L8X3W2Q4x3V1k6K6M7X3y4Q4x3V1k6E0j5h3W2F1i4K6u0r3K9X3q4$3j5g2)9J5c8X3A6S2N6X3q4Q4x3V1k6#2N6r3W2D9i4K6u0r3P5X3W2H3i4K6u0r3h3X3W2H3c8X3W2D9k6g2)9J5k6h3A6S2N6X3p5`.)`是非常有用的。如果不出意外的话，就我的理解而言，这也会是`Google`的补丁所采用的做法。尽管这样做看起来有些局限性，但采用同样的实现是合理的。它只是简单地拒绝了`zip`文件中相同名字的入口。

```
String entryName = newEntry.getName();

if (mEntries.put(entryName, newEntry) != null)

    throw new ZipException(

        "Duplicate entry name: " + entryName);
```

要实现类似的效果，我们首先新建一个基本的`Substrate`扩展（它会初始化对`Java ZipFile`类的`classload`的方法钩子）。要了解关于使用`MS.hookClassLoad`的更多信息，我建议你阅读`[Substrate API文档](https://bbs.kanxue.com/elink@03bK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6h3y4&6k6r3W2S2M7%4g2T1M7%4c8J5j5i4c8W2i4K6u0W2j5$3!0E0i4K6u0r3j5i4m8A6i4K6u0r3K9X3q4$3j5g2)9J5c8V1#2e0i4K6u0W2K9r3!0G2K9@1y4D9j5i4y4K6e0r3!0S2k6q4)9J5c8R3`.`.)`.

```
public class Hook {

   public static void initialize() {

      MS.hookClassLoad("java.util.zip.ZipFile",

         new MS.ClassLoadHook() {

            public void classLoaded(Class<?> ZipFile$) {
```

当那个类加载时，我们需要找到`mEntries`字段。这个字段保存了一个`LinkedHashMap`。我们将修改这个字段，因此我们使用`setAccessible`（`Hendy`注：看起来就是反射的做法）。`Substrate`提供的方法，可以很简单地修改代码，但要解释的话就超出本文的范围了。要了解更多的信息，参看`[这篇文章](https://bbs.kanxue.com/elink@561K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6h3y4&6k6r3W2S2M7%4g2T1M7%4c8J5j5i4c8W2i4K6u0W2j5$3!0E0i4K6u0r3K9h3c8Q4x3V1k6U0x3e0N6U0y4e0f1@1k6W2)9J5k6r3t1$3x3o6y4Q4x3X3b7@1k6e0y4T1i4K6u0V1z5r3j5&6z5g2)9J5k6r3g2T1j5U0x3#2x3U0S2W2x3$3g2X3z5q4)9J5c8R3`.`.)`.

```
final Field ZipFile$mEntries =

   ZipFile$.getDeclaredField("mEntries");

ZipFile$mEntries.setAccessible(true);

final Method ZipFile$readCentralDir =

   ZipFile$.getDeclaredMethod("readCentralDir");
```

最后，我们使用`Substrate`提供的`[hookMethod方法](https://bbs.kanxue.com/elink@e2fK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6h3y4&6k6r3W2S2M7%4g2T1M7%4c8J5j5i4c8W2i4K6u0W2j5$3!0E0i4K6u0r3j5i4m8A6i4K6u0r3K9X3q4$3j5g2)9J5c8V1#2e0i4K6u0W2K9r3!0G2K9@1#2W2N6r3S2G2k6q4)9J5c8R3`.`.)`来修改`ZipFile.readCentralDir`的行为。与其重新实现`readCentralDir`（这会使得可能失去其它的一些安全补丁），我们找到问题的根本原因——`LinkedHashMap`支持重复的入口。我们通过子类化来修改它。

```
MS.hookMethod(ZipFile$, ZipFile$readCentralDir,

   new MS.MethodAlteration<ZipFile, Void>()

{

   public Void invoked(ZipFile thiz, Object... args)

      throws Throwable

   {

      ZipFile$mEntries.set(thiz,

         new LinkedHashMap<String, ZipEntry>() {

            public ZipEntry put(

               String key, ZipEntry value

            ) {

               if (super.put(key, value) != null)

                  throw new IllegalArgumentException(

                     "Duplicate entry name: " + key);

               return null;

            }

         }

      );

      return invoke(thiz, args);

   }

});
```
