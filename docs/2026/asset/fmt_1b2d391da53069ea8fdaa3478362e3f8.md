### 1、万用门实现逻辑指令

#### 理论知识

vmp里面只有1个逻辑运算指令`not_not_and`，设这条指令为`P`。

`P(a,b) = ~a & ~b`

这条指令的神奇之处就是能模拟`not`、`and`、`or`、`xor`4条常规的逻辑运算指令。

怕忘记了，直接给出公式，后面的数字指需要几次`P`运算：

- `not(a) = P(a,a)` 1
- `and(a,b) = P(P(a,a),P(b,b))` 3
- `or(a,b) = P(P(a,b),P(a,b))` 2
- `xor(a,b) = P(P(P(a,a),P(b,b)),P(a,b))` 5

#### 2.1 模拟减法指令

公式：`~(~a+b)`

假设：`eax = 0x77523C33`，`ebx = 0x7FFD3000`

模拟出正确：`eax - ebx = 0xF7550C33`

- 第0~2行模拟出`~a`，`a = 0x88ADC3CC`
- 第3行`(~A+B)`，`(~A+B) = 0x08AB03CC`，`Eflag1 = 0x207`
- 第4行保存`Eflag1`
- 第5~6行取出`(~A+B)`的结果
- 第7行`~(~a+b)`，`~(~a+b) = 0xF7550C33`，`Eflag2 = 0x286`
- 第8行保存`Eflag2`

剩下的`cmp`跟`sub`唯一区别：`sub`保留结果、`cmp`不保留结果。

![](https://bbs.kanxue.com/upload/attach/201909/585205_RGP26V3G2HQQGPS.png)

**总结：** 我们得到两个关键的数据分别是：`Eflag1 = (~a+b)`，值为`207`；`Eflag2 = ~(~a+b)`，值为`286`。

#### 2.2 模拟Eflag标志位

公式：

```
int Eflag1 = (~a+b)
int Eflag2 = ~(~a+b)
int Eflag = (Eflag1 and 0x815) + (Eflag2 and ~0x815)
```

第一个`ElfagAndConstant`模拟出`Eflag1 and 0x815 = 0x5`。第二个`ElfagAndConstant`模拟出`Eflag2 and ~0x815 = 0x282`。然后就`VM_ADDF = 0x282 + 0x5 = 0x287`。最后`VM_POP_CONTEXT`保存`0x287`标志位。

![](https://bbs.kanxue.com/upload/attach/201909/585205_ZAF7Z8T3Z9BXHN4.png)

细看第一个`ElfagAndConstant`函数（就是模拟`and`指令），第二个同理。

```
VM_PUSH_CONTEXT 取 Eflag1 = 0X207
VM_PUSH_CONTEXT 取 Eflag1 = 0X207
VM_NOR ~Eflag1 = 0XFFFFFFFFFFFFFDF8
VM_PUSH_IMM ~815 = 0X7EA
VM_NOR ~Eflag1 and ~0X7EA = 207 and 815
```

转了一圈发现是模拟`and(a,b) = P(P(a,a),P(b,b))`，需要3次`P`运算。

那么第一个`(Eflag1 and 0x815) = 0x207 and 0x815 = 0x7`。

![](https://bbs.kanxue.com/upload/attach/201909/585205_EH9PE3E84M45SNT.png)

#### 2.3 题外话

感谢群里小零大佬提供`0x811`与`0x815`等价。

`811`其实就是`OF`、`AF`、`CF`。

而`PF`、`ZF`、`SF`不管是`add`还是`sub`、`or`、`and`，计算出来都是一样的。

通过`nor`计算出`PF`、`ZF`、`SF`，和`add`出来的标志位合并一下就好了。

### 3、模拟JXX指令

#### 理论知识

![](https://bbs.kanxue.com/upload/attach/201909/585205_GNRFUARU293WXH7.png)

**`EFLAGS`中的状态标志**

`EFLAGS`的状态标志代表什么意思呢？它们代表的是算数指令（arithmetic instruction）的结果状态，算数指令就是大家熟悉的的加减乘除，`ADD`、`SUB`、`MUL`和`DIV`，当然还有很多其他指令暗含有这些基本的算数指令，比如`cmp`指令就暗含有`sub`操作，因此`cmp`也会影响状态标志。

```
typedef struct _EFLAGS
{
    unsigned CF : 1; // 进位或错位
    unsigned Reservel1 : 1; // 对Dr0保存的地址启用 全局断点
    unsigned PF : 1; // 计算结果低位包含偶数个数1时 此标志位1
    unsigned Reservel2 : 1; // 对Dr0保存的地址启用 全局断点
    unsigned AF : 1; // 辅助进位标志 当位3处 有进位或结尾时 该标志为1
    unsigned Reservel3 : 1; // 保留
    unsigned ZF : 1; // 计算结果为0时 此标志位1
    unsigned SF : 1; // 符号标志 计算结果为负时 该标志位1
    unsigned TF : 1; // 陷阱标志 此标志为1时 CPU每次仅会执行一条指令
    unsigned IF : 1; // 中断标志 为0时禁止响应（屏蔽中断） 为1回复
    unsigned DF : 1; // 方向标志
    unsigned OF : 1; // 溢出标志 计算结果超过表达范围为1 否则为0
    unsigned IOPL : 2; //用于标明当前任务的I/0特权级
    unsigned NT : 1; // 任务嵌套标志
    unsigned Reservel4 : 1; // 对Dr0保存的地址启用 全局断点
    unsigned RF : 1; // 调试异常相应标志位 为1禁止相应指令断点异常
    unsigned VM : 1; // 为1时启用虚拟8086模式
    unsigned AC : 1; // 内存对齐检查标志
    unsigned VIF : 1; // 虚拟中断标志
    unsigned VIP : 1; // 虚拟中断标志
    unsigned ID : 1; // cpuID检查标志
    unsigned Reservel5 : 1; // 保留
} EFLAGS, *PEFLAGS;
```

#### 3.1 实践（ZF）

**1.** 关于`jxx`处理的函数地址，只关注`0x32`的`jxx`系列。

![](https://bbs.kanxue.com/upload/attach/201909/585205_665UDT4H64PNTVR.png)

**2.** 首先`Push`两个加密跳转地址，后面根据运算结果来判断使用哪个地址。具体跳转地址`A`还是地址`B`取决于前面一句`cmp ebx, ebx`。

![](https://bbs.kanxue.com/upload/attach/201909/585205_836VWQJRHSNT9EE.png)

**3.** 计算出`Eflags`右移`X`位 > `Size`，我们的例子`flags`是`0x40`，`Size_1=4`，那么`v8`就是4次了。

![](https://bbs.kanxue.com/upload/attach/201909/585205_D56WH2HDJFXDMDF.png)

**4.** 首先取`Eflags`标志位，再压入`~0x40`入栈，最后再进行`NOR(~0x40, Eflags)`操作。可以简化成`0x40 and ~Eflags`。

![](https://bbs.kanxue.com/upload/attach/201909/585205_FZS6WFTGDKFSKMV.png)

**5.** 根据`VM_NOR`结果取决使用哪个地址：`+0`地址1，`+4`地址2。

![](https://bbs.kanxue.com/upload/attach/201909/585205_WY82D7QFN4RYA6P.png)
![](https://bbs.kanxue.com/upload/attach/201909/585205_GH4KE24QW5MQBHX.png)

**6.** 总结下前面流程：

整理下流程（数据参考demo）可以分为三步骤：

1. 保存跳转地址`A`和`B`。
2. 计算`eflags` `zf`的数值，返回对应的结果。公式：`ZF = 0x40 and ~ELFGS`
3. 根据结果`ADD`进行跳转地址`A`或`B`。
