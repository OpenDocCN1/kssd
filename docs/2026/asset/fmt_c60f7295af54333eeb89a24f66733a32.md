### SafeSEH 绕过方法

利用 SafeSEH 保护模块之外的地址。

对于目前的大部分 Windows 操作系统，其系统模块都受 SafeSEH 保护，可以选用未开启 SafeSEH 保护的模块来利用，比如漏洞软件本身自带的 DLL 文件，这个可以借助 OD 插件 SafeSEH 来查看进程中各模块是否开启 SafeSEH 保护。除此之外，也可通过直接覆盖返回地址（`jmp/call esp`）来利用。另一种方法，如果 `esp + 8` 指向 `EXCEPTION_REGISTRATION` 结构，那么你仍然可以寻找一个 `pop/pop/ret` 指令组合（在加载模块的地址范围之外的空间），也可以正常工作。但如果你在程序的加载模块中找不到 `pop/pop/ret` 指令，你可以观察下 `esp/ebp`，查看下这些寄存器距离 `nseh` 的偏移，接下来就是查找这样的指令：

- `call dword ptr [esp+nn]` / `jmp dword ptr [esp+nn]`
- `call dword ptr [ebp+nn]` / `jmp dword ptr [ebp+nn]`
- `call dword ptr [ebp-nn]` / `jmp dword ptr [ebp-nn]`

（其中的 `nn` 就是寄存器的值到 `nseh` 的偏移，偏移 `nn` 可能是：`esp+8`、`esp+14`、`esp+1c`、`esp+2c`、`esp+44`、`esp+50`、`ebp+0c`、`ebp+24`、`ebp+30`、`ebp-04`、`ebp-0c`、`ebp-18`）

很幸运地可以发现软件本身自带的 DLL 没有 SafeSEH 保护，找了一条 `pop pop retn = 0x6D7C4637`。

**典型 SafeSEH 保护攻击模型**

- 在 `nseh` 上放置向后的跳转指令（跳转 7 字节：`jmp 0xfffffff9`）
- 向后跳转足够长的地址以存放 `shellcode`，并借此执行至 `shellcode`
- 把 `shellcode` 放在用于覆盖异常处理结构的指令地址之前

```text
["\x90" * 5115] + [nseh] + [seh] + "\x90\x90\x90\xcc"

seh = 0x6D7C4637
```

（PS：附件 PoC 可以关闭 DEP，绕过 SafeSEH，进行漏洞利用。）

可是本题的要求是开启 DEP 保护，利用 SEH 进行漏洞利用。我这种小菜还是第一次遇到这种情况，到此遇到屏障。

想了许久：怎么同时绕过 SafeSEH、DEP 保护？怎么让数据可控，指向 shellcode？

## 第三步：利用非 SafeSEH 模块内的 `add esp, num; retn`（`num > 0x909`）绕过 SafeSEH

覆盖超长字符找到 `seh` 地址，将其修改为加载模块之外地址，并下断点 `Shift+F9`，查看异常处理时寄存器与堆栈情况。

![](https://bbs.kanxue.com/upload/attach/201403/457816_9dqrhkapi4sg5be.jpg)
![](https://bbs.kanxue.com/upload/attach/201403/457816_hq98tbhgb3j9fj4.jpg)

`esp = 0x22E2DC`

`ebp = 0x22E2FC`

看下我们输入的数据离此时 `esp` 多远。

![](https://bbs.kanxue.com/upload/attach/201403/457816_12c97y1j0a15gq0.png)

`ForEsp: 0x22EBE5 - 0x22E2DC = 0x909`

`ForEbp: 0x22EBE5 - 0x22E2FC = 0x8E9`

计算可了解到此时 `esp` 到我们准备数据至少为 `0x909`，那么可以寻找指令 `add esp, num`（`num >= 0x909`）`retn`，这样程序就又可控了。

`ADD ESP, xxxxxxxx` 的机器码：`81 C4 xx xx xx xx`

利用 `windbg` 搜索 `81 C4` 指令：

```text
s a 0x00000000 L?7fffffff 伳   (搜索 add esp XX XX XX XX)
```

![](https://bbs.kanxue.com/upload/attach/201403/457816_lzg60lv69tx80fz.png)

这么一搜索发现一大批的 `add esp, num; retn`，选择 `0x64998c87`（`add esp, 0x96c`），修改 `seh` 为 `0x64998c87`，再次进行调试观察堆栈情况。

![](https://bbs.kanxue.com/upload/attach/201403/457816_kpko7g1imczb6vd.png)

覆盖 `seh` 之后，执行到 `0x64998C87` 观察堆栈情况，成功进入堆栈。

`ESP` 已经指向我们的缓冲区了，下面看看 `ESP` 指向的地址相对 `RETN` 的偏移量，如图所示：

![](https://bbs.kanxue.com/upload/attach/201403/457816_f9l1mwrl2j80llr.png)

我们的缓冲区起始于 `0x22EBE5`，而现在 `esp` 指向 `0x22EC5C`，这里进行简单的计算：

`0x22EC5C - 0x22EBE5 = 0x77`（119），大概是这么多吧。这里可以直接在直接窗口里修改，然后二进制拷贝到 `WinHex`。

呵呵，算是甩开 SafeSEH 了，进入我们准备的数据区，只要关闭 DEP 跳入 shellcode 就算是胜利。

现在构造的数据模型应该是：

```text
my buffer = "\x90" * 119 + "Close_dep" + "\x90" * (5115 - 119) + "\x2C\x0E\x0A\x6D" + "\x90" * nums;
```

## 第四步：关闭 DEP，指向 shellcode

DEP：数据执行保护，算是目前 Windows 上最强保护了。

绕过方法：

**1. ret2lib**

其思路为：将返回地址指向 lib 库中的代码，而不直接跳转到 `shellcode` 去执行，进而实现恶意代码的运行。可以在库中找到一段执行系统命令的代码，比如 `system()` 函数，用它的地址覆盖返回地址，此时即使 NX/XD 禁止在堆栈上执行代码，但库中的代码依然是可以执行的。函数 `system()` 可通过运行环境来执行其它程序，例如启动 Shell 等等。另外，还可以通过 `VirtualProtect()` 函数来修改恶意代码所在内存页面的执行权限，然后再将控制转移到恶意代码，其堆栈布局如下所示：

本次利用使用关闭 DEP 方法：

此方法的主要**原理就是利用 `NtSetInformationProcess()` 函数来设置 `KPROCESS` 结构中的相关标志位，进而关闭 DEP**。

具体实现思路：

1. 将 `al` 设置为 1，比如指令 `mov al, 1 / ret`，然后用该指令地址覆盖返回地址。

   利用 `OllyFindAddr` 插件可以找到绕过 DEP 的指令地址。

   `mov al, 0x1 / ret` 地址：`0x7c80c190`

   ![](https://bbs.kanxue.com/upload/attach/201403/457816_svcwsujdngr1e54.png)

   执行到上条指令后，观察寄存器情况和堆栈情况，见下图。

   ![](https://bbs.kanxue.com/upload/attach/201403/457816_dnziqu8g0n74ecb.png)
   ![](https://bbs.kanxue.com/upload/attach/201403/457816_jee9wo3alplk6ve.jpg)

   发现 `ebp` 被修改为 `0x90909090`。

2. 接下来的工作就是修正 `ebp` 可写，与增大 `esp`（具体为什么《0day》讲得很清楚），注意堆栈的情况。利用 `OllyFindAddr` 插件找到：

   `push esp; pop ebp; retn 4` 地址：`0x77ECE353`

   `retn 0x24` 地址：`0x7D759FFD`

   ![](https://bbs.kanxue.com/upload/attach/201403/457816_qtza4khzc1sjn6o.png)

   此时 `esp = 0x0022EC68`。

   好了，此时我们就可以去关闭 DEP 了。

3. 修改 `0x22EC68` 处值为 `0x7C93CD24`。

   ![](https://bbs.kanxue.com/upload/attach/201403/457816_c3zv6cx5jtx22sz.png)

   `je` 比较成功，之后调用 `ZwSetInformationProcess()` 关闭 DEP，这一步好似干掉了元老吸血鬼。接下来再布置下堆栈就可以上 shellcode 了。在 `0x7C93CD6f` 处下断，显示此时 `esp = 0x22EC64`，后面的数据有部分已经被破坏，还好从 `0x22ECD0` 后面有一大片数据没有被破坏。执行完 `0x7C93CD6f` 的 `retn 4` 后，`esp = 0x22EC6C`，`0x22EC6C` 对应数据处写入反汇编指令 `jmp 0x22ECD0`，这样就会跳入 shellcode。

   构造的数据模型：

   ```text
   junks + mov_eax + rev_ebp + add_sep + jmp_esp + close_dep + jmp_shellcode + nops + shellcode + nopsh + seh_add_esp
   ```

   （可能地址会有不同，在实际调试时修改）

   ![](https://bbs.kanxue.com/upload/attach/201403/457816_x6sysn3aebfnt9s.jpg)
   ![](https://bbs.kanxue.com/upload/attach/201403/457816_v9bit64iy2o1xhz.jpg)
