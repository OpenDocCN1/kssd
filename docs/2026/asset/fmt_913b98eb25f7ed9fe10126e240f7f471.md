
至此，BK 所有 16 位代码使命结束，函数返回后，操作系统正式进入换页保护工作模式。

## （四）Int1Handler

![](https://bbs.kanxue.com/upload/attach/201312/118994_8cfmgu64zemaaim.png)

BK 的 HOOK 函数开始都是 `PUSH`/`MOV ESI, 12345678h`，其中 `12345678h` 会在 HOOK 创建时写入，使得 `ESI` 始终指向 BK 代码运行时线性基地址。

首先清掉上次下的硬件断点

![](https://bbs.kanxue.com/upload/attach/201312/118994_wyrl6kqoddvcrbe.png)

重新设置 `ebp` 指向 `CORE` 函数，以便执行 `CALL EBP` 函数调用，汇编代码中夹了一个 `REXW`，这是干啥的呢？

![](https://bbs.kanxue.com/upload/attach/201312/118994_zb6yj5awduamcx8.png)

原来 BK 为了兼容 X86、X64，使用了 CPU `REX` 前缀，也就是说 64 位的话就相当于扩展了寄存器而已，但是 32 位也能运行，只不过 `REXW` 相当于一个 `DEC EAX` 指令，这样就用不搞两套 BIN 了，而且代码也可以通过这种方式，判断自身运行是 32 位还是 64 位环境，如下。

![](https://bbs.kanxue.com/upload/attach/201312/118994_ygu4f9ecwxw9pro.png)

这里可能会有同学疑问，64 位就直接返回了，难道 BK 不支持 64 位？实际上不是的，应该是进入 64 位模式前，代码首先运行在 32 位保护模式，当然这只是我的猜想，也没有实际验证了【切换 64 位是通过读写 `MSR` 寄存器完成的】。

执行 OS 入口点 HOOK：

![](https://bbs.kanxue.com/upload/attach/201312/118994_auixqiliqkgju26.png)

`Winload` 函数负责 OS 入口点的 HOOK，`NT5 X86` 根据特征码 `68 4B 23 00 00 PUSH 234B`，搜索 `OsLoader` 中跳转到 OS 的入口点指令，`Call [ebp+XXX]`，并调用 `PatchCall` 函数将该 `Call` 替换为 `E8 Call Near` 到 `Hook` 函数，`NT5 OsLoader Call KernelEntryPoint` 对应的反汇编如下：

![](https://bbs.kanxue.com/upload/attach/201312/118994_qiabek3xodc1k31.png)

这里 BK 会针对不同版本 Windows 进行的处理，可见这个 BK 兼容性应该还是不错的。

接下来，BK 最想干的事莫过于赶紧申请一块内存，毕竟第一次进入新环境，否则指不定啥时就没了，`OsLoader` 通过 `BlAllocateAlignedDescriptor` 函数从内存子系统中申请内存。

![](https://bbs.kanxue.com/upload/attach/201312/118994_32ph2mys8cyci4m.png)

我们看看 `HookAlloc5` 是怎么 Hook 内存分配的，还是特征码搜索 `6a 00 6a 19 e8`（`PUSH 0`；`PUSH 19`；`CALL xxx`），具体代码如下：

![](https://bbs.kanxue.com/upload/attach/201312/118994_krrgicuiorz8061.png)

`IDA` 定位特征码如下：

![](https://bbs.kanxue.com/upload/attach/201312/118994_k1xnx7dcv0hbana.png)

由此可以获取 `BlAllocateAlignedDescriptor` 函数的地址，然后执行 `Inline Hook`

![](https://bbs.kanxue.com/upload/attach/201312/118994_quteb5mlvr16vhi.png)

注意这里的 `add esi, 8` 指令，因为我们同时 `PatchCall` 了两个函数，一个是 `WinLoad` 函数对 `Os` 入口点调用了一次 `PatchCall`，然后是这次 `PatchCall`，BK 将原始函数的 Patched 字节保存到 BK 的内存尾部，这里需要通过 `esi` 设定一个偏移量，否则会把上次保存的函数 Patched 字节冲掉了。

现在 BK 完成了 `BlAllocateAlignedDescriptor` 函数的 HOOK -> `LoadFile5`
`OsLoader Call OsEntryPoint` 的 HOOK -> `TransferHook5`。

## （五）LoadFile5

![](https://bbs.kanxue.com/upload/attach/201312/118994_km8d7ntkki54rlw.png)

该函数负责申请内存，将 `payload` 复制过去，然后在内存里面处理 PE 重定位。

然后从原始调用堆栈中复制一份到堆栈（`COPY` 代码大亮），执行原始函数调用。

![](https://bbs.kanxue.com/upload/attach/201312/118994_ct4rwlzmazojvui.png)

然后测试调用是否成功，成功的话就说明内存子系统没问题了，可以搞点私活了，如下：

![](https://bbs.kanxue.com/upload/attach/201312/118994_jfai9rwbyfphine.png)

![](https://bbs.kanxue.com/upload/attach/201312/118994_nn55q126uzbfo2c.png)

![](https://bbs.kanxue.com/upload/attach/201312/118994_dru7gk0v004r6sc.png)
