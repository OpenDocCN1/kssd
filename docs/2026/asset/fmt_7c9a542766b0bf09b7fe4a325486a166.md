## 6.5.3 分析通信协议

对于 `EchoSystemInfo`, `RunProcess` 和 `UploadFile` 的详细分析，这里笔者就不写出来了。原因之一是如果读者看到这里，相信已经具备一定的调试分析汇编的能力。另一个重要的原因是，现在笔者已经很疲惫了，迫切希望结束此篇文档„„下边直接给出分析结论。 收 `UDP` 包，绑定本机 `IP`，端口号为 `30167` 对于收到的包有三种情况：

1、 首字节为字符 `'e'`，`UDP` 包的长度必须为 `1`

此种包用来请求回传操作系统版本信息。

2、 首字节为字符 `'y'`, 包长度不限制，包格式如下：

`udp_packet_buffer`: `+0x00:db 'y'` `+0x01:dd show_window` `+0x05:command_line size XXXX` //此参数用来调用 `CreateProcess` 此种包用来执行客户端指定的命令。同时，会将执行结果回传给提出请求的客户端，客户端的端口必须是 `30168`

3、 首字节为字符 `'z'`, 包长不限制，包格式如下：

`udp_packet_buffer`: `+0x00:db 'z'` `+0x01:db filename size XXXX` //将要上传到系统目录里的文件名称 此种包用来向服务端上传文件。收到该包后，服务端会和客户端的 `30169` 端口建立 `TCP` 连接，并将从客户端收到的网络数据存至系统目录下规定的文件里。笔者在调试这个函数的时候费了些功夫，原因是不理解文件句柄可以和 `xocket` 直接进行转换。

发 `UDP` 包，客户端 `IP` 为提出请求的 `IP`，客户端端口号为 `30168` 对于收到的三种类型请求，发送的包的格式如下所述：

1、 请求服务端操作系统版本信息

`udp_packet`: 内容和大小和 `GetVersionA` 返回的结构完全相同。

2、 请求服务端执行命令：

`udp_packet`: `+0x00:db string size XX` //执行成功，回传字符串 `“Done”`, 失败回传 `“Error：XX”` 的字符串，其中 `XX` 代码出错码

3、 请求上传文件：

`TCP` 连接客户端 `30169` 端口。该连接由客户端主动关闭。
