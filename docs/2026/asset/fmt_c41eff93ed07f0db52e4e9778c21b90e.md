# 安装编译依赖

```
pacman -S mingw-w64-x86_64-gcc mingw-w64-x86_64-ninja mingw-w64-x86_64-python3 mingw-w64-x86_64-cmake autoconf libtool
```

这里安装了 `gcc`、`ninja` 构建工具，MinGW-w64 版的 `python3`，MinGW-w64 下的 `cmake`，以及一些编译用到的工具。

## git

可自己从 `git` [官网](<https://bbs.kanxue.com/elink@369K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Q4x3X3c8K6j5$3#2Q4x3X3g2U0L8$3#2Q4x3V1k6V1L8%4N6F1L8r3!0S2k6q4)9J5c8Y4N6A6L8R3`.`.)>)下载，也可以在 msys2 安装，看个人喜好。

我偏向于使用官网下载的 `git`，其他 IDE 也能用上。

![6c19e71ffdf046f8edbb54fdc23412e0.png](https://bbs.kanxue.com/upload/attach/202209/956011_TT935NMG98P8P3Q.png)

下载 64 位 Standalone Installer 即可，安装过程可以按照个人喜好配置，如果只是为了本次编译就直接无脑下一步即可。

## cmake

可从 [官网](<https://bbs.kanxue.com/elink@30cK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0L8h3q4C8k6g2)9J5k6h3!0J5k6#2)9J5c8X3c8G2N6$3&6D9L8$3q4V1i4K6u0r3)>)下载 Windows 安装包，也可以在 MSYS2 中安装 `mingw-w64-x86_64-cmake`，但千万不能使用 MSYS2 提供的 `cmake` 包。

即使用 `pacman -S mingw-w64-x86_64-cmake` 安装 cmake，本文使用 MSYS2 中的 `mingw-w64-x86_64-cmake`。

若使用官网安装的 cmake，需要在 MSYS2 mingw 中手动指定 `cmake.exe` 位置，即 `/c/Program\ Files/CMake/bin/cmake -G "Unix Makefiles"`。

## 对应 rust 版本的 LLVM

这里注意不要去 `llvm-org` 直接下载源码，以免出现不兼容等 bug。

在 rust 源码里有 `.gitmodules` 这个文件，打开看对应 LLVM 的分支，并克隆。例如 rust `1.63.0` 对应的 LLVM 版本是 `rustc/14.0-2022-03-22`：

# 编译 LLVM

## 给 LLVM 添加混淆插件

### 1. 添加 LLVM obfuscator

这里用的是 [heroims](<https://bbs.kanxue.com/elink@02eK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Z5k6i4u0G2K9h3#2K6i4K6u0W2k6$3W2@1K9s2g2T1i4K6u0W2K9h3!0Q4x3V1j5>) 的 patch，具体项目地址在 [这里](<https://bbs.kanxue.com/elink@4f5K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6Z5k6i4u0G2K9h3#2K6i4K6u0r3L8$3u0X3N6i4y4U0j5i4c8G2M7W2)9J5c8Y4c8J5k6h3g2Q4x3V1k6H3j5i4c8U0K9r3g2K6>)。

由于 LLVM 14 有两种 pass 方式，一种 legacy pass 一种 new pass，LLVM 官方正在逐渐用 new pass 淘汰 legacy pass，所以这里使用 new pass 作为补丁：

```
wget https://heroims.github.io/obfuscator/NewPass/ollvm14.patch
cd llvm-project
git apply --reject --ignore-whitespace ../ollvm14.patch
```

这里要注意，正常情况下是直接 patch 完毕的，如果应用 patch 错误有 `.rej` 文件出现，需要手动处理冲突。

成功应用 patch 截图：

![95c0b1440fff2a6929e7f4c57d4a270e.png](https://bbs.kanxue.com/upload/attach/202209/956011_D8BWHWN6V4WY53Y.png)

### 2. 修复 LLVM 14 的 Link 错误

无冲突应用完 patch 之后，需要去 `llvm-project/llvm/lib/Transforms/Obfuscation` 目录，修改 `CMakeLists.txt`。

在 `intrinsics_gen` 之后添加以下内容：

```
COMPONENT_NAME
Obfuscation

LINK_COMPONENTS
Analysis
Core
Support
TransformUtils
```

## 编译 LLVM 本体

### 1. 生成 cmake 构建项目

在刚刚克隆的 LLVM 源码同级目录输入以下命令：

```
cmake -G "Ninja" -S ./llvm-project/llvm -B ./build_dyn_x64 -DCMAKE_INSTALL_PREFIX=./llvm_x64 -DCMAKE_CXX_STANDARD=17 -DCMAKE_BUILD_TYPE=Release -DLLVM_ENABLE_PROJECTS="clang;lld;" -DLLVM_TARGETS_TO_BUILD="X86" -DBUILD_SHARED_LIBS=ON -DLLVM_INSTALL_UTILS=ON -DLLVM_INCLUDE_TESTS=OFF -DLLVM_BUILD_TESTS=OFF -DLLVM_INCLUDE_BENCHMARKS=OFF -DLLVM_BUILD_BENCHMARKS=OFF
```

命令解析：

- `-G "Ninja"`：让 cmake 生成 ninja 的编译项目。
- `-S ./llvm-project/llvm`：指定源码目录。
- `-B ./build_dyn_x64`：指定编译输出目录。
- `-DCMAKE_INSTALL_PREFIX=./llvm_x64`：指定 LLVM 安装目录为当前目录下的 `llvm_x64`。
- `-DCMAKE_CXX_STANDARD=17`：指定 C++17 标准，LLVM 需要至少 C++17 以上。
- `-DCMAKE_BUILD_TYPE=Release`：指定构建类型为 Release。
- `-DLLVM_ENABLE_PROJECTS="clang;lld;"`：指定 LLVM 启用项目。
- `-DLLVM_TARGETS_TO_BUILD="X86"`：指定编译 LLVM 的目标，这里只启用了 x86。
- `-DBUILD_SHARED_LIBS=ON`：构建 LLVM 动态库。
- `-DLLVM_INSTALL_UTILS=ON`：安装 LLVM 的其他工具，这是 rust 编译时需要的 `FileCheck` 等工具。
- `-DLLVM_INCLUDE_TESTS=OFF`、`-DLLVM_BUILD_TESTS=OFF`：不编译测试。
- `-DLLVM_INCLUDE_BENCHMARKS=OFF`、`-DLLVM_BUILD_BENCHMARKS=OFF`：不编译基准测试。

具体参数可以查看 LLVM 的 [官方文档](<https://bbs.kanxue.com/elink@18fK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6D9L8s2k6E0i4K6u0W2L8%4u0Y4i4K6u0r3k6r3!0U0M7#2)9J5c8V1y4y4j5h3E0W2i4K6u0W2K9s2c8E0L8l9`.`.)>).

![4a3c947a94903b6977141f104f5660cd.png](https://bbs.kanxue.com/upload/attach/202209/956011_CCSUVJNY34N9WKE.png)

### 2. 开始编译

```
cmake --build ./build_dyn_x64 -j 22
```

命令解析：

- `--build ./build_dyn_x64`：告诉 cmake 从哪里开始编译。
- `-j 22`：指定多少线程同时编译。

然后就是等待，这个时间可以刷会视频看看小说，大概 20-40 分钟，具体时长取决于机器配置。

![2dc7f7b403481626678ec5ced4732c88.png](https://bbs.kanxue.com/upload/attach/202209/956011_MRD95KFATS7NGMJ.png)

### 3. 安装（生成）LLVM

```
cmake --install ./build_dyn_x64
```

安装编译好的 LLVM 到 `llvm_x64` 目录。

这里如果不需要对 LLVM 进行其他修改，可以删除 `build_dyn_x64` 目录，节省硬盘空间。

### 4. 添加运行 LLVM 的依赖

由于是使用 MinGW-w64 的环境，编译出来的 LLVM 无法直接使用，需要去 MSYS2 的 `mingw64/bin` 目录复制下列 DLL 到 LLVM 的 `bin` 目录。

需要复制的 DLL 列表：

```
libgcc_s_seh-1.dll
libstdc++-6.dll
libwinpthread-1.dll
zlib1.dll
```

# 编译 rustc

## 配置 rust 编译选项

### 1. 进入 rust 源码目录

进入 rust 源码目录，复制一份 `config.toml.example` 到 `config.toml`。

如图所示：

![087d7bdded65c2f33f31828c9a9df680.png](https://bbs.kanxue.com/upload/attach/202209/956011_QUJ3C6YX8MVME3K.png)

### 2. 修改 `config.toml`

- 在 `[rust]` 子项，设置 `debug = false`。

  这里把 `debug` 关闭，提升速度。

  ![ff90f42f9abe240d0f23f640ca3543f7.png](https://bbs.kanxue.com/upload/attach/202209/956011_GQ9JV6M6SXKVPMB.png)

- 在 `[rust]` 子项，将 `channel` 设置成 `nightly`。

  使用 `nightly` channel 才能设置 LLVM pass 的参数。

  ![1d253194ab2b03202290747b993bdb5a.png](https://bbs.kanxue.com/upload/attach/202209/956011_F3RFVHVQJDCJDTW.png)

- 在 `[target.x86_64-unknown-linux-gnu]` 子项，将 `llvm-config` 设置到刚刚我们编译的 LLVM 目录下的 `llvm-config`，并修改 `x86_64-unknown-linux-gnu` 为 `x86_64-pc-windows-gnu`。

  这里设置 `llvm-config` 选项后，就能跳过 rustc 编译的过程中编译非动态版本的 LLVM。

  ![836d0d5c5dc5d4438809118754c7549f.png](https://bbs.kanxue.com/upload/attach/202209/956011_NZ3KQ35CBBDPRW9.png)

## 修改 rust 的源码

因为 `rustc`（rust 的编译器）有几个不同的编译阶段：

- 阶段 0：启动，下载当前 beta 版本的 `rustc` 等工具来编译 `src/bootstrap`、`std`、`rustc`。
- 阶段 1：由阶段 0 编译出当前源码的编译器（`rustc`），使用阶段 0 的 ABI。
- 阶段 2：由阶段 1 编译出当前源码的编译器，使用阶段 1 的 ABI。

这里我只是大概了解了一下，可能会有些偏差，具体详情可以看 [官方文档](<https://bbs.kanxue.com/elink@65dK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6J5N6i4y4@1j5#2)9J5k6r3c8W2N6W2)9J5k6r3N6#2K9h3c8W2i4K6u0W2M7Y4g2K6N6q4)9J5k6r3I4S2L8X3N6Q4x3X3g2G2M7X3N6Q4x3V1k6T1N6h3W2D9k6r3W2F1k6#2)9J5c8X3u0G2L8%4c8K6N6s2u0S2M7s2m8A6L8X3N6Q4x3X3g2Z5N6r3#2D9)>)以及 [源码的说明](<https://bbs.kanxue.com/elink@a58K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6J5N6i4y4@1i4K6u0V1L8r3q4F1k6#2)9J5c8Y4u0#2M7%4c8Q4x3V1k6@1M7X3g2W2i4K6u0r3L8h3q4K6N6r3g2J5i4K6u0r3M7%4u0U0i4K6u0r3j5X3!0G2N6s2y4@1M7X3q4H3)>)。

其中，我们真正使用的是阶段 2 的文件作为我们自己的 toolchain。由于我们的 LLVM 是动态编译的，所以在阶段 1 -> 阶段 2 的时候编译出的 `rustc` 无法执行，需要跟 LLVM 一样手动补充依赖文件。

修改的文件：`src/bootstrap/compile.rs`
