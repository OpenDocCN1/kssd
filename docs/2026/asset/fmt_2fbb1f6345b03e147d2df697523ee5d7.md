## 12. 从代码托管服务网站上查找，像 Github、gitlab、bitbucket 等网站。

可以在这些网站上找到各种有用的东西，[包括 web 漏洞、web 应用的 0day、配置问题、AWS 和其它的密钥](https://bbs.kanxue.com/elink@f99K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8X3#2A6j5$3S2W2L8Y4u0A6K9%4y4W2L8W2)9J5k6h3y4G2L8g2)9J5c8X3u0D9L8$3N6Q4x3V1k6Y4K9i4c8J5L8$3u0Q4x3X3c8H3N6i4c8@1K9h3&6Y4i4K6u0V1N6r3S2W2i4K6u0V1L8%4m8W2L8W2)9J5k6s2y4G2N6i4u0U0k6g2)9J5k6r3W2F1i4K6u0V1L8%4y4A6L8Y4c8Q4x3V1j5`.）。 

开发人员经常将产品密码和 API 访问密钥将代码一起提交，发现问题后才删除敏感信息然后进行新的提交。然而，根据代码提交的日志以及对特定提交评论的检查可以找到敏感的信息，然后用来对目标进行全面攻击。

像 [Gitrob](https://bbs.kanxue.com/elink@458K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6E0K9h3y4Z5k6h3&6J5K9h3E0K6k6h3&6Q4x3V1k6Y4K9i4c8J5L8$3t1`.）这样的工具可以用来搜索 Github 的内容，以寻找特定组织的敏感文件。

## 13. 浏览 HTML 代码来确定客户端是否将一些静态内容托管到了云上。

一些内容像图片、`js` 和 `css` 文件可能在 `s3` `bucket` 上托管。在一般的信息侦测过程中，可能会发现目标用户使用了云来存放动态或静态资源。在这种情况下，寻找用户使用的 `bucket`，如果客户给 `buckets` 配置了错误的权限，那么你就能收获很多。在公开的 `bucket` 中可以发现很多有趣的信息。

像 [DigiNinja’s Bucket Finder](https://bbs.kanxue.com/elink@bc9K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1K9h3N6A6i4K6u0W2L8X3W2F1K9X3q4Q4x3V1k6H3M7X3!0B7k6h3y4@1M7#2)9J5c8X3u0#2j5$3E0W2N6q4)9#2k6X3k6A6L8X3c8W2M7W2)9J5k6i4m8Z5M7l9`.`.) 这样的工具可以通过暴力破解 `bucket` 的名字来用来自动搜索。这个工具需要一组整理好的 `bucket` 名字和可能的完整 URL。

![](https://bbs.kanxue.com/upload/attach/201705/735073_sgwk5pw1i48kt8a.png)

一个私有的 `bucket` 不会泄漏文件和资源。

![](https://bbs.kanxue.com/upload/attach/201705/735073_nkglbb8qh2sgb2b.png)

一个公开的 `bucket` 显示了资源和文件的名字。可以通过完整 URL 来下载这些资源。

`OSINT` (Open source intelligence) 是一个不断增长和需要持续研究的领域。使用上面我列出来的和其他技术，不需要对目标发送一个数据包就可以对目标建立大概的了解或者找到一些弱点。
