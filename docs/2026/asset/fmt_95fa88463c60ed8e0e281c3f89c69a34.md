`EXCEPTION_SINGLE_STEP`的消息产生:

单步异常需要设置标志寄存器`eflags`里`TF`位,只对一条指令有效,并且单步异常是没有第二次异常的,因为当发生单步异常时,处理器已经执行了单步前指令,而上条指令所发生的影响无法还原回去,另外硬件断点也是产生的单步异常,硬件读写内存断点总是断在读写指令的下一条

其他几个异常消息还有另外几个调试事件都可下`nt!DbgkpQueueMessage`断点,重现调试事件,查看堆栈即可知道大致流程,与上面分析都一样

前面提到`DbgkpQueueMessage`向调试对象的事件列表插入调试事件后,通知调试器内核函数`nt!NtWaitForDebugEvent`的等待事件, `nt!NtWaitForDebugEvent`把要处理的调试事件转换为`DBGUI_WAIT_STATE_CHANGE`结构体后返回到用户态的`WaitForDebugEvent`函数, `WaitForDebugEvent`根据返回的`DBGUI_WAIT_STATE_CHANGE`的`NewState`字段,判断调试事件,封转成用户态的`DEBUG_EVENT`,等待调试器处理完后,调用`ContinueDebugEvent`把调试器处理的结果(处理或不处理)通知正在等待的被调试程序

``` 
BOOL ContinueDebugEvent(

DWORD dwProcessId,

DWORD dwThreadId,

DWORD dwContinueStatus );
```

其中第一个参数是被调试程序的进程ID, 第二个参数是被调试程序通知调试器的那个线程的ID ,也就是`DbgkpQueueMessage`中通知并等待调试器回应的线程的ID, 第三个参数是调试器处理的结果

调用`DbgUiContinue`通过`DbgUiContinue`获取调试对象句柄然后进入内核函数`NtDebugContinue`

`DbgUiContinue`有两个参数 第一个是指向`CLIENT_ID`指针 第二个是`dwContinueStatus`
