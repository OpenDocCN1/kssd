## CoMarshalInterface - CoUnmarshalInterface

&emsp;&emsp;还有两个关于COM API基本处理，`CoMarshalInterface`和`CoUnmarshalInterface`，msdn对两个函数介绍，通俗来讲是序列化和反序列化。

```
CoMarshalInterface: 将在某些客户端进程中初始化代理对象所需的数据写入流。
CoUnmarshalInterface: 使用先前调用 CoMarshalInterface 函数写入流的数据初始化新创建的代理，并返回指向该代理的接口指针。
```

&emsp;&emsp;接口封送：`Com_CoMarshalInterface`将COM接口指针序列化时，若目标上下文为跨沙箱，则生成指向沙箱代理的`OBJREF`，确保反序列化时在沙箱内重建，另外对`ISearchNotifyInlineSite`对象做了特殊处理。

```
static const GUID IID\_ISearchNotifyInlineSite =
{ 0xB5702E61, 0xE75C, 0x4B64,
{ 0x82, 0xA1, 0x6C, 0xB4, 0xF8, 0x32, 0xFC, 0xCF } };
HRESULT hr;
//
// special handling for ISearchNotifyInlineSite objects,
// normal handling otherwise
//
if (dwDestContext == MSHCTX\_INPROC ||
memcmp(riid, &IID\_ISearchNotifyInlineSite, sizeof(GUID)) != 0) {
hr = \_\_sys\_CoMarshalInterface(
pStream, riid, pUnknown,
dwDestContext, pvDestContext, mshlflags);
}
```

&emsp;&emsp;比如类型`dwDestContext`等于`MSHCTX_DIFFERENTMACHINE`，这是由宿主环境的`epmapper`生成，代理`OBJERF`数据构建，通过`SbieDll_CallServer`封送。
