
# PESpin 脱壳教程

## 导入段结构

2) `IMAGE_IMPORT_DESCRIPTOR` - 这是5x4字节的组。每个dll都有一个描述符。每4个字节的描述符包含特定信息：

1. 前4个字节表示hint数组的RVA。
2. 第二个4字节表示dll的`TimeDateStamp`。这并不重要，可以用零填充。
3. 第三个4字节表示一些不重要的`ForwarderChain`，它也可以用零填充。这个`ForwarderChain`已经过时了。
4. 第4个字节是指向导入段中dll ASCII名称的RVA的地址。
5. 最后4个字节指向RVA的thunks。

3) 然后我们还有一个`IMUR_IMPORT_DESCRIPTOR`填充零（以null终止）。

4) `Hint arrays` - 这些数组保留了RVA的hints。这实际上与thunk相同，但它们不会像thunks那样（在PE程序加载时）填充导入地址。

5) `Hint` - 它是一个两字节的值，它是Windows加载器的提示，它应首先查找API。如果提示不起作用（因为更新/不同版本的dll）加载器将执行ASCII API名称的二进制搜索。hint不是必需的，我们可以用零填充它，就像一些编译器那样。

6) `API name` - 它是API函数的ASCII名称。它的目的是Windows加载器可以执行API的二进制搜索。它的长度未确定，但最后一个字节必须为0（空终止符）。

7) `DLL name` - 与API名称相同，但对于DLL，它必须以两个零字节结束。

## 手动构建导入段

这是基本的导入段。我们将在`.newIID`段（`.idata2`段）中创建导入段，该部分由`OllyDump`添加。我们有三个需要加载的DLL，所以我们将有三个thunk，三个descriptors +一个零填充，三个hint数组和三个hint-api-dll名称。使用`LordPE`的PE编辑器打开我们的转储文件，然后单击段。您将看到`.newIID`段（`.idata2`段）的`RawOffset`为10000。关闭`LordPE`并在十六进制编辑器中打开转储文件。我们需要组织IAT的地方。下图显示了我如何保留地点以及用于什么。请注意，所有值和字符只是象征性的，可以让您（和我）更好地查看段应该如何显示：

![](https://bbs.kanxue.com/upload/attach/202001/93_C6GXHD6A86SV2YW.jpg)

`thnk1...` 是thunk，然后是数字1,2,3,0我填充1. 2. 3.并且空一个`IMAGE_IMPORT_DESCRIPTOR`。hint数组是`arr1...hint`，API和DLL位置无法保留，因为我在搜索之前不知道API和DLL名称的长度。这是我将用数据填充的第一个区域。我们很遗憾我们需要`kernel32.dll`，`user32.dll`和`gdi32.dll`，以及每个dll一个API。我会选择第一个我知道名字的API。填写该区域后，我有这个画面：

现在我们需要填写所有其他数据; thunks，descryptors和数组。所有这些数据都需要用RVA填充，因此在Olly中打开此文件并查看转储`.newIID`段（`.idata2`段）。从那以后，您可以轻松阅读所有RVA，甚至可以在Olly中进行更改。下图显示了如何为第一个dll填充数组, KERNEL32.DLL:

就是这样，导入段已经完成，但是如果你在Olly中完成了所有这些操作，你就将这些更改保存到我们的文件中。但是这里没有保存到文件的选项，所以与我们想做的不同。进入CPU窗口到`410000`地址：

```
00410000   8000 01          ADD BYTE PTR DS:[EAX],1
00410003   0000             ADD BYTE PTR DS:[EAX],AL
00410005   0000             ADD BYTE PTR DS:[EAX],AL
...
004100CF   0000             ADD BYTE PTR DS:[EAX],AL
004100D1   0000             ADD BYTE PTR DS:[EAX],AL
004100D3   0000             ADD BYTE PTR DS:[EAX],AL
```

选择所有“操作码”（这些不是操作码，只是我们的导入段）从`410000`到`4100CF`，右键单击，复制到可执行文件 - >选择，然后在新窗口中选择保存文件。将其另存为`dump.exe`。

现在我们只需告诉windows我们的IAT在哪里以及它有多大。什么是IAT？IAT不是整个导入段，而只是`IMAGE_IMPORT_DESCRIPTORS`。第一个描述符从RVA 410018 ==> RawA 10018开始。它的大小是三个descriptors+最后一个零填充= 5 * 4 * 4 = 50h。在`LeordPE`的PE编辑器中打开`dump.exe`，单击目录，然后将ImportTable RVA和Size更改为10018和50。保存更改并运行`dump.exe`。它有效吗？除非你没有犯错，否则我的工作得很好，所以你也一样。

这就是PESpin的这个版本。手动修复IAT很难，因为如果你有很多dll，这样你就有大活要做，你可能在任何步骤上犯错误。有些工具声称他们可以构建导入段，但是没有一个工具在我这儿起作用。

## 4. 教程 3 - PESpin v1.3

## 小结

### 一、`packed1.0.exe`快捷脱壳

1. `API`处理：`OD`载入`packed1.0.exe`后，忽略所有异常，`HE 0040905F`下断并`F9`运行，断下，`NOP`掉`0040905F`和`0040909C`之间的所有字节，删除断点。
2. `Timer`处理：`HE 0040910A`下断并`F9`运行，断下后删断点，处理防止调用计时器函数。(多余)
3. 暗桩处理：`HE 00409195`下断并`F9`运行，改此处跳转为`jmp 4091BF`(`RETN`后地址)，删断点。
4. 找回代码：`HE 00409279`下断并`F9`运行，断下后找到被盗代码（无），删除断点。

   这里

   ```
   004092C1   - E9 3A7DFFFF              jmp packed1_.00401000
   ```

5. 重定向处理：跳转到`OEP=00401000`后，运行脚本`PESpin 1.x - Code Fixer.txt`。
6. `Dump`修复：用`LordPE`来`Dump`，`OEP`填入`1000`，`ImportREC`高级方式获取`API`，剪掉多余项，转存就OK了。
