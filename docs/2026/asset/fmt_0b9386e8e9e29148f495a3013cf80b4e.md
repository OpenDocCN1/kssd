
- `TTF_SUBCLASS`：如果你使用这个标志，它意味着你告诉工具提示控件子类化工具所在的窗口，以便让工具提示控件能够窃听发送给窗口的鼠标消息。这个标志非常方便。如果你不使用这个标志，你必须做更多的工作来将鼠标消息转发给工具提示控件。

- `hWnd`：Handle to the window that contains the tool. If you specify the `TTF_IDISHWND` flag, this field is ignored since Windows will use the value in the `uId` member as the window handle. You need to fill this field if:（包含工具的窗口句柄。如果你指定`TTF_IDISHWND`标志，这个字段可以忽略，因为Windows将使用`uId`成员中的值作为窗口句柄。你需要填充这个字段，如果：）
  - You don't use the `TTF_IDISHWND` flag (in other words, you use a rectangular tool).（你没有使用`TTF_IDISHWND`标志，换句话说，你使用一个矩形工具。）
  - You specify the value `LPSTR_TEXTCALLBACK` in the `lpszText` member. This value tells the tooltip control that, when it needs to display the tooltip window, it must ask the window that contains the tool for the text to be displayed. This is a kind of dynamic realtime tooltip text update. If you want to change your tooltip text dynamically, you should specify the `LPSTR_TEXTCALLBACK` value in the `lpszText` member. The tooltip control will send the `TTN_NEEDTEXT` notification message to the window identified by the handle in the `hWnd` field.（你在`lpszText`成员中指定了`LPSTR_TEXTCALLBACK`值。这个值告诉工具提示控件，当需要显示提示窗口时，必须向包含工具的窗口查询应该显示什么。这是一种动态、实时的工具提示文本更新方式。如果你想动态地改变提示文本，你应该在`lpszText`成员中指定`LPSTR_TEXTCALLBACK`值。控件将会向由`hWnd`字段中的句柄所标识的窗口发送`TTN_NEEDTEXT`通知消息。）

- `uId`：The value in this field can have two meanings, depending on whether the `uFlags` member contains the flag `TTF_IDISHWND`.（这个字段中的值可以有两种含义，取决于`uFlags`成员是否包含`TTF_IDISHWND`标志。）
  - Application-defined tool ID if the `TTF_IDISHWND` flag is not specified. Since this means you use a tool which covers only a part of the client area, it's logical that you can have many such tools on the same client area (without overlap). The tooltip control needs a way to differentiate between them. In this case, the window handle in the `hWnd` member is not enough since all tools are on the same window. The application-defined IDs are thus necessary. The IDs can be any value so long as they are unique among themselves.（如果`TTF_IDISHWND`标志没有被指定，就代表应用程序定义的工具ID值。因为这意味着你使用的是仅覆盖客户区一部分的工具，逻辑上来说，在同一个客户区中这种工具可以有很多个（但不存在交迭）。工具提示控件需要一种方式来区分它们。既然这样，在`hWnd`成员中的一个窗口句柄是不足够的，因为所有的工具都在同一个窗口中。因此，应用程序必须定义ID值来区分它们，这些ID可以是任何值，但要保证它们之间的唯一性。）
  - The handle to the window whose whole client area is used as the tool if the `TTF_IDISHWND` flag is specified. You may wonder why this field is used to store the window handle instead of the `hWnd` field above. The answer is: the `hWnd` member may already be filled if the value `LPSTR_TEXTCALLBACK` is specified in the `lpszText` member, and the window that is responsible for supplying the tooltip text and the window that contains the tool may NOT be the same. You can design your program so that a single window can serve both roles, but this is too restrictive. In this case, Microsoft gives you more freedom. Cheers!（如果`TTF_IDISHWND`标志被指定，就表示整个客户区都作为焦点域的窗口句柄。你可能会奇怪为什么要用这个字段来代替上面`hWnd`字段来存储窗口句柄。答案是：如果在`lpszText`成员中指定了`LPSTR_TEXTCALLBACK`值，那么这个`hWnd`成员可能已经被填充，而且负责提供工具提示文本的窗口和包含工具的窗口可能不是同一个。你可以设计一个能充当两种角色的窗口程序，但这太受限制。在这种情况下，微软给了你更多的自由。举杯欢呼吧！）

- `rect`：A `RECT` structure that specifies the dimension of the tool. This structure defines a rectangle relative to the upper left corner of the client area of the window specified by the `hWnd` member. In short, you must fill this structure if you want to specify a tool that covers only a part of the client area. The tooltip control will ignore this field if you specify the `TTF_IDISHWND` flag (you choose to use a tool that covers the whole client area).（`RECT`结构指定工具的尺寸大小。这个结构定义了一个相对于由`hWnd`成员指定的窗口客户区左上角坐标的矩形。简而言之，如果你想指定一个仅覆盖客户区一部分的工具，你必须填充这个结构。如果你指定`TTF_IDISHWND`标志，工具提示控件将忽略这个字段中的值（即你选择使用覆盖整个客户区的工具）。）

- `hInst`：The handle of the instance that contains the string resource that will be used as the tooltip text if the value in the `lpszText` member specifies the string resource identifier. This may sound confusing. Read the explanation of the `lpszText` member first and you will understand what this field is used for. The tooltip control ignores this field if the `lpszText` field doesn't contain a string resource identifier.（包含字符串资源的实例句柄，如果在`lpszText`成员中指定了字符串资源标识符，那么这个字符串资源将被用作工具提示文本。听起来可能有点费劲。先阅读一下`lpszText`成员的说明，你就会明白这个字段是干什么用的了。如果`lpszText`字段不包含字符串资源标识符，工具提示控件会忽略这个字段。）

- `lpszText`：This field can have several values:（这个字段可以有以下几个值：）
  - If you specify the value `LPSTR_TEXTCALLBACK` in this field, the tooltip control will send the `TTN_NEEDTEXT` notification message to the window identified by the handle in the `hWnd` field for the text string to be displayed in the tooltip window. This is the most dynamic method of tooltip text update: you can change the tooltip text each time the tooltip window is displayed.（如果在这个字段中指定`LPSTR_TEXTCALLBACK`，工具提示控件将向由`hWnd`字段中的句柄标识的窗口发送`TTN_NEEDTEXT`通知消息，以获取要在工具提示窗口中显示的文本字符串。这是最动态的工具提示文本更新方法：你可以在每次显示工具提示窗口时更改工具提示文本。）
  - If you specify a string resource identifier in this field, when the tooltip control needs to display the tooltip text in the tooltip window, it searches for the string in the string table of the instance specified by the `hInst` member. The tooltip control identifies a string resource identifier by checking the high word of this field. Since a string resource identifier is a 16-bit value, the high word of this field will always be zero. This method is useful if you plan to port your program to other languages. Since the string resource is defined in a resource script, you don't need to modify the source code. You only have to modify the string table and the tooltip texts will change without the risk of introducing bugs into your program.（如果你在这个字段中指定了一个字符串资源标识符，当工具提示控件需要在工具提示窗口中显示工具提示文本时，它会在由`hInst`成员指定的实例的字符串表中搜索该字符串。工具提示控件通过检查此字段的高字节来识别字符串资源标识符。由于字符串资源标识符是16位值，此字段的高字节将始终为零。如果你打算将程序移植到其他语言，此方法非常有用。由于字符串资源在资源脚本中定义，你无需修改源代码。只需修改字符串表，工具提示文本就会改变，而不会有在程序中引入BUG的风险。）
  - If the value in this field is not `LPSTR_TEXTCALLBACK` and the high word is not zero, the tooltip control interprets the value as the pointer to a text string that will be used as the tooltip text. This method is the easiest to use but the least flexible.（如果此字段中的值不是`LPSTR_TEXTCALLBACK`且高字节不为零，则工具提示控件将该值解释为指向文本字符串的指针，该字符串将用作工具提示文本。此方法最易于使用，但灵活性最低。）

To recapitulate, you need to fill the `TOOLINFO` structure prior to submitting it to the tooltip control. This structure describes the characteristics of the tool you desire.（总之，在将`TOOLINFO`结构提交给工具提示控件之前，你需要填充它。此结构描述了你期望的工具的特征。）

### Register the tool with the tooltip control（注册工具到工具提示控件）

After you fill the `TOOLINFO` structure, you must submit it to the tooltip control. A tooltip control can service many tools, so it is usually unnecessary to create more than one tooltip control for a window. To register a tool with a tooltip control, you send the `TTM_ADDTOOL` message to the tooltip control. The `wParam` is not used and the `lParam` must contain the address of the `TOOLINFO` structure you want to register.（在填充好`TOOLINFO`结构之后，你必须将它提交给工具提示控件。一个工具提示控件能服务于多个工具，因此通常无需为一个窗口创建多个工具提示控件。要向工具提示控件注册工具，请向工具提示控件发送`TTM_ADDTOOL`消息。`wParam`参数不被使用，`lParam`必须包含要注册的`TOOLINFO`结构的地址。）

```
.data?

ti TOOLINFO <>

.......

.code

.......

<fill the TOOLINFO structure>

.......

invoke SendMessage, hwndTooltip, TTM_ADDTOOL, NULL, addr ti
```

`SendMessage` will return `TRUE` if the tool is successfully registered with the tooltip control, `FALSE` otherwise.（如果工具在工具提示控件中成功注册，`SendMessage`将返回`TRUE`，否则返回`FALSE`。）

You can unregister the tool by sending the `TTM_DELTOOL` message to the tooltip control.（你可以通过向工具提示控件发送`TTM_DELTOOL`消息来注销该工具。）
