## 利用步骤

### 0. 清空对应的工作目录

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_7Q5FPDVZBFF2FWN.png)

### 1. 判断系统版本及偏移

通过 `HKEY_LOCAL_MACHINE\Software\Microsoft\Windows NT\CurrentVersion` 获得系统版本，根据系统版本判断是否支持利用，并确定 `Token` 和 `PreviousMode` 偏移。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_RJV7WGH8BVSCKWR.png)

### 2. 获取基础信息

#### 获取系统版本

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_3XFBDTA6JN42WFT.png)

之后获取对应系统及当前进程的内核偏移，并初始化一系列内存。

通过动态地址获取的方式，分别从 `clfs.sys`/`ntoskrnl.exe` 中获取函数 `ClfsEarlierLsn`、`ClfsMgmtDeregisterManagedClient`、`RtlClearBit`/`PoFxProcessorNotification`、`SeSetAccessStateGenericMapping`。

### 3. 检测访问令牌句柄

检测当前进程的访问令牌句柄是否存在于系统句柄列表中。

### 4. 创建文件并获取对象地址

创建 `C:\Users\Public\p\_%08d` 文件，并获得其 `_FILE_OBJECT` 的地址。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_XY3KYVBF9EZHG6J.png)

之后获取 `NtFsControlFile` 函数地址，并通过 `ZwQuerySystimeInformation` 获取 `PipeAttributer` 的内核对象地址，在 `0xFFFFFFFF` 上分配长度为 `4096` 的内存，并以此部署 system Process token。这个位置用于辅助 `ClfsEarlierLsn`/`SeSetAccessStateGenericMapping` 进行最终的内存写入。

通过 `CreateLogFile` 创建第一个 log file。

最后调用 `AddLogContainer` 增加一个 log container。需要注意，对应的 trigger clfs base block 内核地址 `para_clfsKerneladdress` 通过 `ZwQuerySystemInforation` 搜索的方式获取，其原理是通过搜索 `0x7a00` 大小标志位 `clfs` 的 pool。类似地，包括 `pipeAttribute` 的内核地址也是通过该方式获取。

### 6. 创建并修改 spray clfs

再次创建 10 个 log file，这里称之为 `spray clfs[i]`，并修改其日志文件中的数据。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_FUT29JKSUQHNE7F.png)

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_86XRCAV9UY5BNRK.png)

`Spray clfs[i]` 生成之后，在这里并没有调用 `AddLogContainer`。

### 7. 使用匿名管道进行内存布局

首先，trigger clfs 对应的内核 base block 地址 `+0x30` 的位置被循环赋值到一个数组中，然后两次调用函数 `fun_pipeSpray`，对应的参数分别为 `0x5000` 及 `0x4000`。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_X4UHKFWZQF4C76S.png)

`pipeSpray` 为一个 pipe spray，其根据参数传入的数量生成指定数量对数的 pipe（read/write）。第一次 `pipeSpray` 调用传入 `0x5000`，因此生成了 `0x5000` 对 pipe（read/write）；这里统一将这 `0x5000` 对 pipe 称之为 `pipeA`，第二次的 `0x4000` 对称之为 `pipeB`。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_ZPGVSDUKDVVNC7H.png)

遍历 `0x5000` 对 `pipeA`，并调用其 `writepipe` 写入包含 trigger clfs base block + `0x30` 的数组。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_S9M57ARSHJ5VP4F.png)

遍历结束后，从 `pipeA`（`0x2000` 偏移）的第 174 对 pipe 开始释放，一共释放 `0x667` 对 pipe。

![图片描述](https://bbs.kanxue.com/upload/tmp/865065_KNZ62QEFREDT3XE.png)

释放结束后，紧接着通过前面的 `spray[i] clfs` 循环调用 `CreateLogFiles`，用 `CreateLogFiles` 调用中某一处内存对象占据前面 `pipeA` 中释放的 pipe 对。

`CreateLogFiles` 循环占位结束后，遍历 `0x4000` 对 `pipeB`，并调用其 `writepipe` 写入前面的数组。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_UR8A9SQ9JXPKFXY.png)

### 8. 触发漏洞并篡改日志数据

为 `LOG:C:\Users\Public\MyLog%d%08d` 添加容器，触发漏洞，篡改 `LOG:C:\Users\Public\MyLog\_%08d` 日志的 `rgContainers[0]`。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_ZKS9G3ACK8MWDDT.png)

### 9. 对指定地址进行内存布局

对 `0x5000000` 进行内存布局。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_YKU7T4MZ9YSQ6HZ.png)

### 10. 替换 Token

对 clfs 对象 trigger clfs 调用 `CreateLogFile`，通过 `NtFsControlFile` 读取 system process 的 token，执行了内存 `0x50000000` 中的内容，完成了对 `PipeAttribute` 内核对象的修改，从而使得 `NtFsControlFile` 能实现任意地址读取。

![图片描述](https://bbs.kanxue.com/upload/tmp/865065_8HQ56PU4K4G6EB5.png)

之后重复调用 `CreateLogFile` 触发漏洞，完成进程 token 的替换。

![图片描述](https://bbs.kanxue.com/upload/tmp/865065_KHZSRH3TVNECPDJ.png)

### 11. 修改 `PreviousMode`

此外，样本中同样也支持修改 `priviousMod`，实现任意地址读写来提权的方式。

在 `CClfsBaseFilePersisted::CheckSecureAccess` 中使用了 fake `pContainer`（`0x5000000`），并最终调用 `RtlClearBit` 将当前线程的 `PreviousMode` 置 `0`。

将当前线程的 `PreviousMode` 置 `0` 后，便可使用 `NtWriteVirtualMemory` 进行内核地址的任意读写。

![图片描述](https://bbs.kanxue.com/upload/attach/202311/865065_G9CABX2ZUC292QT.png)
