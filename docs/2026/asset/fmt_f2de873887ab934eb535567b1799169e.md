
## 0环中对错误的处理

在我们系列的第二篇文章（<http://bbs.pediy.com/showthread.php?p=1414691#post1414691>）中提到过，`CreateProcess`在0环下，最终“若一切顺利，会调用`PspUpdateCreateInfo`将进程创建信息保存到传出参数`CreateInfo`中”而“若不顺利，会调用`PspDoHandleSweepSingle`或者`PsTerminateProcess`结束新进程”。

我们在此就介绍下`PspDoHandleSweepSingle`的内部实现。

其函数原型如下：

```c
void PspDoHandleSweepSingle(

//指向进程对象结构的指针

IN EPROCESS* pEprocess);
```

功能是清除目标进程所有句柄并删除句柄表。

其内部流程图如下：

![](https://bbs.kanxue.com/upload/attach/201605/406681_6rqm2zrpbn5e2ov.png)

详细过程为：

1. 获取目标进程推锁`ProcessLock`，检查是否有活动现场，有则设置进程`Flags`和`Flags2`标志位：

   ![](https://bbs.kanxue.com/upload/attach/201605/406681_sk98ngmyvqs8kpo.png)

2. 释放锁：

   ![](https://bbs.kanxue.com/upload/attach/201605/406681_ece9er2wgyyb83p.png)

3. 调用`KiCheckForKernelApcDelivery`检查并交付APC：

   ![](https://bbs.kanxue.com/upload/attach/201605/406681_gbfwbnfayg2bawu.png)

4. 检查目标进程对象句柄表是否为空：

   ![](https://bbs.kanxue.com/upload/attach/201605/406681_x26ltry40pmjfu8.png)

5. 如果句柄表为空则调用`KeStackAttachProcess`将当前线程附加到目标进程，调用`ObKillProcess`清理进程所有句柄，调用`KeUnstackDetachProcess`解除附加：

   ![](https://bbs.kanxue.com/upload/attach/201605/406681_tp8qfgfldvzrtbu.png)

6. 如果句柄表为不空则调用`ObClearProcessHandleTable`清除目标进程所有句柄并删除句柄表：

   ![](https://bbs.kanxue.com/upload/attach/201605/406681_e6clvmzlcy4jcps.png)

## 新进程句柄的创建

`PspCreateObjectHandle`用于创建新进程的句柄，它的函数原型如下：

```c
NTSTATUS PspCreateObjectHandle(

//指向某对象结构的指针(EPROCESS  ETHREAD)

IN EPROCESS* pEprocess,

//32位系统中访问状态结构_ACCESS_STATE的扩展

IN_OUT ALL_ACCESS_STATE* pAccessState,

//对象类型

IN POBJECT_TYPE ObjectType);
```

以下是它的流程图：

![](https://bbs.kanxue.com/upload/attach/201605/406681_1tsh9krwz1x8314.png)

从流程图中可知，其所做工作主要为：

1. 调用`ObOpenObjectByPointerWithTag`。具体步骤如下：
   1) 调用`ObReferenceObjectByPointerWithTag`添加引用计数。
   2) 判断访问状态对象`PassedAccessState`是否为空，是则调用`SeCreateAccessStateEx`初始化`PassedAccessState`。
   3) 调用`ObpCreateHandle`根据对象创建句柄。
   4) 若第二步创建访问状态对象，则调用`SeDeleteAccessState`删除对象。
2. 检查`ObOpenObjectByPointerWithTag`返回值，成功则继续调用`SePrivilegeObjectAuditAlam`生成审计信息安全事件日志，否则返回。

其中又属`ObOpenObjectByPointerWithTag`中的工作最为主要，因此我们单独提出分析：

### ObOpenObjectByPointerWithTag函数

![](https://bbs.kanxue.com/upload/attach/201605/406681_5jxr577jl1c9wa6.png)

`ObOpenObjectByPointerWithTag`调用：`ObOpenObjectByPointerWithTag`函数和32位下的`ObOpenObjectByPointer`函数相比增加了一个用于对象引用跟踪的参数`tlfD`，关于对象引用跟踪，可参考看雪论坛相关文章<http://bbs.pediy.com/showthread.php?t=120296>。

`ObOpenObjectByPointerWithTag`函数首先调用`ObReferenceObjectByPointerWithTag`增加对象引用计数，然后判断参数`PassedAccessState`(访问状态对象)是否为空，若为空则调用`SeCreateAccessStateEx`对该对象进行初始化，接着调用`ObpCreateHandle`根据参数`pObject`创建句柄，若不为空则直接掉用`ObpCreateHandle`，最后根据是否调用`SeCreateAccessStateEx`决定是否调用`SeDeleteAccessState`删除访问权限对象。

1) 调用`ObReferenceObjectByPointerWithTag`增加对象引用计数：

![](https://bbs.kanxue.com/upload/attach/201605/406681_1br4n7e7woafha3.png)

2) 调用`SeCreateAccessStateEx`初始化访问权限对象：

![](https://bbs.kanxue.com/upload/attach/201605/406681_9cx0km55d7ec78q.png)

3) 调用`ObpCreateHandle`根据对象创建句柄：

![](https://bbs.kanxue.com/upload/attach/201605/406681_kvw37r6j0nkvyfo.png)

4) 调用`SeDeleteAccessState`删除访问权限对象：

![](https://bbs.kanxue.com/upload/attach/201605/406681_iei5tzbatklkigp.png)

而其中的`ObReferenceObjectByPointerWithTag`也很重要，我们同样进行了剖析：

### ObReferenceObjectByPointerWithTag函数

![](https://bbs.kanxue.com/upload/attach/201605/406681_492ifxeal9eqeq5.png)

`bReferenceObjectByPointerWithTag`函数首先根据对象头中的类型索引检查对象与全局的对象类型表`ObTypeIndexTable`中相应项是否一致，然后检查对象跟踪标志是否为真，若为真则调用`ObpPushStackInfo`进行跟踪记录，最后将对象引用计数成员`PointerCount`加1。

1) 检查对象与全局的对象类型表`ObTypeIndexTable`中相应项是否一致：

![](https://bbs.kanxue.com/upload/attach/201605/406681_wv0jadq8l8qk7v4.png)

2) 判断对象跟踪标志若为真则调用`ObpPushStackInfo`进行跟踪记录：

![](https://bbs.kanxue.com/upload/attach/201605/406681_0mgib71hafin7pl.png)

3) 将对象引用计数成员`PointerCount`加1：

![](https://bbs.kanxue.com/upload/attach/201605/406681_i83ych0wpf9gxu9.png)

## 资源的释放

如本系列的第二篇（<http://bbs.pediy.com/showthread.php?p=1414691#post1414691>）所述，资源释放涉及到`PspDeleteCreateProcessContext`与`SeDeleteAccessState`两个函数。以下是针对它们的分析。

### SeDeleteAccessState函数

它的函数原型如下，其功能为删除访问状态对象。

```c
NTSTATUS SeDeleteAccessState(

// ALL_ACCESS_STATE结构体指针

IN ALL_ACCESS_STATE* pAccessState);
```

![](https://bbs.kanxue.com/upload/attach/201605/406681_qamn4b44u2hrm5z.png)

其内部详细流程为：

1. 调用`ExFreePoolWithTag`释放扩展数据、对象名字符串、对象类型字符串的内存空间。

![](https://bbs.kanxue.com/upload/attach/201605/406681_249ptkqbrqv3hp9.png)

2. 调用`SeDeassignSecurity`释放与安全描述符被分配使用`seassignsecurity`相关的内存。

![](https://bbs.kanxue.com/upload/attach/201605/406681_4677fsg056llyp5.png)

3. 解除对进程快速访问令牌的引用，将访问对象主令牌`PrimaryToken`置为`NULL`。

![](https://bbs.kanxue.com/upload/attach/201605/406681_u9ayf7g634amxny.png)

4. 检查访问对象客户令牌`ClientToken`是否为`NULL`，不为`NULL`则调用`ObfDereferenceObject`解除引用。并将`Ethread`成员`QuantumTarget`置为`NULL`。

![](https://bbs.kanxue.com/upload/attach/201605/406681_86grkwz3alxjdpj.png)

### PspDeleteCreateProcessContext函数

它的函数原型如下：

```c
void PspDeleteCreateProcessContext(

//指向进程创建信息对象结构的指针

IN CREATEPROCESSTEXT* pCreateProcessContext);
```

内部流程图为：

![](https://bbs.kanxue.com/upload/attach/201605/406681_gufwjur13sjb90r.png)

内部详细流程为：

1. 检查文件句柄`FileHandle`是否为空，不为空则调用`ObCloseHandle`关闭句柄。

![](https://bbs.kanxue.com/upload/attach/201605/406681_gkh05ho7c3zd3tf.png)

![](https://bbs.kanxue.com/upload/attach/201605/406681_me8tbgtbrl9ul7u.png)

2. 检查文件对象`FileObject`是否为空，不为空则调用`ObfDereferenceObject`解除引用。

![](https://bbs.kanxue.com/upload/attach/201605/406681_zhklmc7iio4ab82.png)

![](https://bbs.kanxue.com/upload/attach/201605/406681_tukdadfgpadrcc8.png)

3. 检查进程`pEprocess`是否为空，不为空则调用`ObfDereferenceObject`解除引用。

![](https://bbs.kanxue.com/upload/attach/201605/406681_5z0bwoshvlkgfda.png)

![](https://bbs.kanxue.com/upload/attach/201605/406681_4jqcre8dlmbg5vv.png)

4. 检查文件映像句柄`SectionHandle`是否为空，不为空则调用`ObCloseHandle`关闭句柄。

![](https://bbs.kanxue.com/upload/attach/201605/406681_bh68ao2h0jmarm6.png)

![](https://bbs.kanxue.com/upload/attach/201605/406681_nyni1ypbepsi0nq.png)

5. 检查结构体`CreateProcessContext`偏移0x100处成员是否为`NULL`，不为`NULL`则调用`ExFreePoolWithTag`释放结构体`CreateProcessContext`偏移0xF0处成员指向的内存。

![](https://bbs.kanxue.com/upload/attach/201605/406681_7hfjfhvs53aaz0s.png)

![](https://bbs.kanxue.com/upload/attach/201605/406681_mkpjugkvq0avld0.png)

![](https://bbs.kanxue.com/upload/attach/201605/406681_sg5vvczge5htsz9.png)

6. 检查结构体`CreateProcessContext`偏移0x110处成员是否为`NULL`，不为`NULL`则调用`ExFreePoolWithTag`释放其指向的内存。

![](https://bbs.kanxue.com/upload/attach/201605/406681_c8q6evpnbbshc66.png)

![](https://bbs.kanxue.com/upload/attach/201605/406681_ifxstrrj11a2sdx.png)

7. 检查`FileName.Buffer`指针是否为空，不为空则调用`RtlFreeStringRoutine`释放内存，并设置`FileName.Length`为0，设置`FileName.Buffer`为`NULL`。

![](https://bbs.kanxue.com/upload/attach/201605/406681_ujlz184gwkea0gg.png)
