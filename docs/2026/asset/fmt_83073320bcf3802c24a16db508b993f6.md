
Chrome中用于进程间通讯的默认机制叫作`Mojo`。它支持信息/数据管道和共享内存, 但是你通常会使用其中`C++`, `Java`和`JavaScript`实现的高级语言绑定。 也就是说, 你以一个自定义的接口定义语言(`IDL`)创建带有方法的接口, `Mojo`会生成你选择的语言的桩, 你只需实现其中的功能。 要想看看实际的情况, 你可以浏览[.mojom IDL](https://bbs.kanxue.com/elink@0e2K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0M7#2)9J5k6h3y4Z5M7X3!0E0K9i4g2E0i4K6u0W2L8%4u0Y4i4K6u0r3j5$3S2J5L8$3#2A6N6h3#2Q4x3V1k6K6M7X3y4Q4x3V1k6K6k6i4u0$3K9h3y4W2M7#2)9J5c8X3&6W2N6s2N6G2M7X3E0Q4x3V1k6H3N6h3u0D9K9h3y4Q4x3V1k6E0L8$3A6G2L8g2)9J5c8Y4g2J5L8q4)9#2k6X3I4G2j5h3c8W2M7W2)9#2k6X3k6S2j5%4c8G2M7Y4W2Q4x3X3g2E0L8$3A6G2L8g2)9K6c8X3I4Q4x3@1b7K6x3W2)9J5y4X3q4E0M7q4)9K6b7Y4u0U0L8q4)9K6c8o6R3#2j5K6c8V1z5o6R3J5k6o6x3H3j5U0V1K6k6U0j5I4y4e0l9I4x3h3t1H3x3K6j5I4y4K6k6U0k6o6m8U0k6e0g2T1y4K6V1I4k6r3j5`.)中的`URLLoaderFactory`, [C++ 实现](https://bbs.kanxue.com/elink@1c3K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0M7#2)9J5k6h3y4Z5M7X3!0E0K9i4g2E0i4K6u0W2L8%4u0Y4i4K6u0r3j5$3S2J5L8$3#2A6N6h3#2Q4x3V1k6K6M7X3y4Q4x3V1k6K6k6i4u0$3K9h3y4W2M7#2)9J5c8X3&6W2N6s2N6G2M7X3E0Q4x3V1k6#2M7X3I4Q4y4h3k6D9L8$3q4V1k6i4u0Q4y4h3k6X3j5h3y4@1L8%4u0&6i4K6u0W2K9q4)9K6c8X3I4Q4x3@1b7@1x3#2)9J5y4X3q4E0M7q4)9K6b7Y4u0U0L8q4)9K6c8o6g2X3j5e0R3H3x3o6f1^5x3e0x3#2y4o6x3H3k6o6f1J5y4e0y4V1y4r3j5J5z5e0p5J5j5e0y4T1j5U0p5I4j5K6k6W2j5$3u0X3j5e0V1`.)和[渲染器中的使用](https://bbs.kanxue.com/elink@1a6K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0M7#2)9J5k6h3y4Z5M7X3!0E0K9i4g2E0i4K6u0W2L8%4u0Y4i4K6u0r3j5$3S2J5L8$3#2A6N6h3#2Q4x3V1k6K6M7X3y4Q4x3V1k6K6k6i4u0$3K9h3y4W2M7#2)9J5c8X3&6W2N6s2N6G2M7X3E0Q4x3V1k6U0L8%4u0K6i4K6u0r3j5$3!0J5M7#2)9#2k6Y4g2J5L8q4)9#2k6X3I4G2j5h3c8W2M7W2)9J5k6h3y4U0i4K6y4r3L8q4)9K6c8o6f1I4x3#2)9J5y4X3q4E0M7q4)9K6b7Y4u0U0L8q4)9K6c8o6g2X3j5e0R3H3x3o6f1^5x3e0x3#2y4o6x3H3k6o6f1J5y4e0y4V1y4r3j5J5z5e0p5J5j5e0y4T1j5U0p5I4j5K6k6W2j5$3u0X3j5e0V1`.)。

一个值得注意的功能是, `Mojo`允许你通过现有通道转发`IPC`端点。该功能在`Chrome`里被广泛使用, 也就是你在`.mojom`文件里看到的`pending_receiver`或`pending_remote`参数。

![img](https://bbs.kanxue.com/upload/attach/202003/820961_VVTD567HSTZ27C9.png)

其内部机制是, `Mojo`在进程之间, 或者更具体地说是在`Mojo`的**节点**之间, 它使用的是平台特定的消息管道。两个节点之间能直接连接, 但这样没有必要, 因为`Mojo`支持消息路由。网络中的代理节点有一些额外的职责, 它们要设置节点频道和执行沙箱限制的一些操作.

`IPC`端点本身被称为**端口**。 在上面的`URLLoaderFactory`例子中, 客户端和实现方都是以端口作区分。在代码中, 端口是[这个](https://bbs.kanxue.com/elink@1c2K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0M7#2)9J5k6h3y4Z5M7X3!0E0K9i4g2E0i4K6u0W2L8%4u0Y4i4K6u0r3j5$3S2J5L8$3#2A6N6h3#2Q4x3V1k6K6M7X3y4Q4x3V1k6E0L8$3A6G2i4K6u0r3j5$3!0J5k6g2)9J5c8Y4m8G2M7Y4c8K6i4K6u0r3M7r3!0J5N6q4)9J5k6h3S2Q4x3@1k6D9i4K6y4p5y4U0c8Q4x3U0k6S2L8i4m8Q4x3@1u0J5j5$3I4Q4x3@1b7J5x3r3x3@1z5r3g2W2k6e0M7@1x3o6x3%4y4e0W2V1y4U0M7$3k6e0g2V1x3$3p5I4x3U0f1$3y4e0N6S2j5h3u0S2x3h3p5H3x3$3y4S2)样子:

```
class Port : public base::RefCountedThreadSafe<Port> {

 public:

  // [...]

  // The current State of the Port.

  State state;

  // The Node and Port address to which events should be routed FROM this Port.
  // Note that this is NOT necessarily the address of the Port currently sending
  // events TO this Port.

  NodeName peer_node_name;

  PortName peer_port_name;

  // The next available sequence number to use for outgoing user message events
  // originating from this port.

  uint64_t next_sequence_num_to_send;

  // [...]

}
```

上面的*peer_node_name*和*peer_port_name*都是用于寻址的随机128位整数。 如果你向某个端口发送消息, 它将首先将其转发到正确的节点, 然后接收节点会在本地端口的map中查找端口名, 之后再将消息放入正确的消息队列.

当然这意味着, 如果你在浏览器进程中有一个信息泄露漏洞, 你可以泄露端口名并利用它们来将消息插入特权`IPC`通道。而且实际上, 在`Mojo`核心文档中的[安全章节](https://bbs.kanxue.com/elink@af9K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0K9s2u0G2L8h3W2#2L8g2)9J5k6h3N6G2L8$3N6D9k6i4y4G2N6i4u0U0k6g2)9J5k6h3y4G2L8g2)9J5c8X3y4Z5M7X3!0E0K9i4g2E0i4K6u0r3M7%4u0U0i4K6u0r3i4K6u0n7i4K6u0r3L8h3q4K6N6r3g2J5i4K6u0r3L8h3!0B7L8#2)9J5c8X3y4G2M7X3g2Q4x3V1k6d9c8f1q4p5e0f1g2Q4x3X3g2E0k6q4)9J5x3%4y4W2j5%4g2J5K9i4c8&6) 中，这一点也被提及到:

> "[...]任意节点可以发送任意消息到任意其他节点的任意端口, 只要它知道端口和节点名. [...]因此, 重要的是不要将端口名泄露到不应被授予对应功能(Capability)的节点中."

这里有个不错的例子, 该缺陷能被轻松利用来泄露端口号, 由[@NedWilliamson](https://bbs.kanxue.com/elink@b39K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6@1N6$3W2@1N6r3g2J5i4K6u0W2j5$3!0E0i4K6u0r3e0X3g2V1g2$3W2D9L8r3W2S2L8i4y4G2L8R3`.`.)报告的[crbug.com/779314](https://bbs.kanxue.com/elink@a8bK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6U0M7X3u0#2k6#2)9J5k6h3y4G2L8g2)9J5c8U0M7%4z5e0x3I4y4l9`.`.)。它是一个在[blob](https://bbs.kanxue.com/elink@b60K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1k6i4k6W2L8r3!0H3k6i4u0Q4x3X3g2E0L8%4A6A6L8r3I4S2i4K6u0W2L8%4u0Y4i4K6u0r3k6h3&6Q4x3X3c8g2f1#2)9J5c8X3c8G2j5%4y4Q4x3V1k6i4k6h3u0Q4x3V1k6m8f1p5W2Q4x3V1k6n7L8r3!0T1)实现中的整数溢出, 能让你读取浏览器进程中`blob`前任意数量的堆内存。利用方式大概如下所示:

1. 破坏渲染器.

2. 利用`blob`缺陷来泄露堆内存.

3. 在内存中搜索端口(一个有效状态+16个高熵字节)

4. 利用泄露的端口将消息插入特权`IPC`连接.

接下来, 我们来解决两个问题. 如何用`CPU`缺陷替换掉上面的2和3呢? 以及我们可以通过特权`IPC`连接获得什么原语(primitives)?

## RIDL

为了使用硬件漏洞来利用这种行为, 我之前在寻找能让你泄露跨进程边界内存的缺陷。[MDS攻击](https://bbs.kanxue.com/elink@b76K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8X3#2V1M7$3q4@1N6r3q4U0K9%4y4Q4x3X3g2U0L8$3#2Q4x3V1j5`.)中的`RIDL`似乎是个完美的选择, 因为它能确切做到这点: 它能让你在受影响的`CPU`上泄露各种内部缓冲区的数据。 具体实现方法可以查看这篇[论文](https://bbs.kanxue.com/elink@ad9K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6E0k6s2y4S2N6s2c8S2j5$3E0K6i4K6u0W2j5$3!0E0i4K6u0r3k6X3W2D9k6i4y4Q4x3V1k6J5K9h3c8D9i4K6u0W2M7r3c8X3)或者[幻灯片](https://bbs.kanxue.com/elink@75aK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6E0k6s2y4S2N6s2c8S2j5$3E0K6i4K6u0W2j5$3!0E0i4K6u0r3M7$3I4A6k6r3g2K6i4K6u0r3M7$3I4A6k6r3g2K6i4K6u0W2K9s2c8E0L8l9`.`.), 它们解释得比我好多了。
