
# [原创]祥云杯2020 babydev（内核 PWN）详解

## 祥云杯2020 babydev（Kernel PWN）

### `start.sh`

```shell
#!/bin/sh
qemu-system-x86_64 \
-m 256M \
-kernel bzImage \
-initrd core.cpio \
-append "root=/dev/ram rw console=ttyS0 oops=panic panic=1 nokaslr" \
-cpu qemu64,+smep,+smap \
-nographic \
-monitor /dev/null \
-gdb tcp::1234
```

没有开启 KASLR，开启了 SMEP 和 SMAP，不能使用 `ret2usr`。

### `init`

```shell
#!/bin/sh
mount -t proc none /proc
mount -t sysfs none /sys
mount -t devtmpfs devtmpfs /dev
chown root:root flag
chmod 400 flag
exec 0</dev/console
exec 1>/dev/console
exec 2>/dev/console
insmod mychrdev.ko
chmod 777 /dev/mychrdev
echo -e "\nBoot took $(cut -d' ' -f1 /proc/uptime) seconds\n"
setsid cttyhack setuidgid 1000 sh
poweroff -d 0 -f
```

## `mychrdev.ko`

### `open`

![](upload/attach/202011/876323_NCSFZRH5ZDUYK7Z.jpg)

### `write`

`write` 每向 `llseek + *(mydata+0x10000) + mydata` 进行写操作，写入内容为用户空间传递的值。同时，`*(mydata + 0x10008)` 处的值增大。

![](upload/attach/202011/876323_EFMWC7GN8DNCCHQ.jpg)

![](upload/attach/202011/876323_TWFQ5RPRETVMPNR.jpg)

### `unlock_inctl`

可以将对应的 `struct file` 结构体中偏移 `0xc8` 位置的指针指向的内容（前 `0x28` 字节）拷贝到用户空间。

![](upload/attach/202011/876323_CDPNYN4FHQJY3DR.jpg)

### `mychrdev_read`

在满足条件的情况下，将内核空间 `llseek + have_use + mydata` 处的内容传递给用户空间。

![](upload/attach/202011/876323_VDFUGUMHKUD9T6D.jpg)

### `mychrdev_llseek`

`llseek` 用来通过设置 `file->f_ops`，设置 `write()` 和 `read()` 的读写位置。

![](upload/attach/202011/876323_3CVY2NWGASNSX4D.jpg)

## 漏洞分析与利用

1. 控制写入地址的位置主要依赖于 `file->f_pos`（以下简称 `llseek`）以及 `*(mydata+0x10000)` 处存储的值。
2. 通过多次调用 `write` 并配合 `lseek`，可以不断增大 `*(mydata+0x10008)`。配合 `lseek` 触发 `write` 函数中的溢出后，可以劫持 `*(mydata+0x10000)` 和 `*(mydata+0x10008)` 这两个关键位置。

   ![](upload/attach/202011/876323_R7VKVSFEJ8XKN3X.jpg)

3. 劫持 `*(mydata+0x10000)` 和 `*(mydata+0x10008)` 后，配合 `read` 函数进行任意地址读取，并爆破 `file` 结构体的地址。读取 `0x98` 字节后，最后 8 个字节即为 `file->f_cred`，它指向当前进程的 `cred` 结构体。
4. 通过计算偏移，重新设置 `lseek` 和 `*(mydata+0x10000)`，配合 `write` 函数进行任意地址写，目标地址为爆破得到的 `cred` 结构体地址。
5. 将当前进程的 `cred` 结构体前 `0x28` 字节写为全 0，以达到提权目的。
