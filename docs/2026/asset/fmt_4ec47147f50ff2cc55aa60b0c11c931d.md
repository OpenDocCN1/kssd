你会发现都是些乱七八糟的代码，基本上没法读。但是最终会发现这么一段代码会有一个趋向，就是会向堆栈里压数据，这就不得不让人想起了一个著名的引擎，就是KME32多态引擎，呵呵。玩病毒的没有人不会知道Zombie吧。大家多跟踪几次就会确定是KME32引擎了。经过对KME32引擎的研究，发现KME32确实很强大，随机生成解密代码，支持多重加密，Forgot这个壳的弱点就是没有使用多重加密，但要用多重加密代价也是很大的，重数越多，代码量越大，不过看起来Forgot的壳加上两层是没问题的。闲话少说，看看我们怎么来对付KME引擎。经过我的一些研究，发现KME32有个弱点，就是不管加多少层，总是在每一层的最后会跳到下一层，本壳只加了一层，当然就是跳向真正要运行的代码了。这里要说明的就是KME32引擎每次生成的解密代码都不一样，我这里得到的跳转点在程序再被加密一次的时候会完全不一样。

标 题:附KME32的测试程序，使用了固定地址调用，各位各根据自己的系统，修改调用地址

发信人:onlyu

时 间:2004-12-21,17:22

详细信息:

```
.586

.model flat,stdcall  ;32 bit memory model

option casemap:none  ;case sensitive

assume fs:flat

.data?

  tempbufptr  dd  ?

  outbuf    dd  ?

include asmtest.inc

MAXVIRSIZE              equ      1024000

.code

start:

        mov    ebp,ProgramStart

                        push    virmemory

                        push    40h     ; GMEM_FIXED+GMEM_ZEROINIT

                        call    GlobalAlloc

                        push    MAXVIRSIZE

                        push    40h

                        call    GlobalAlloc

                        mov     tempbufptr,eax

                        push    MAXVIRSIZE

                        push    40h

                        call    GlobalAlloc

                        mov    outbuf,eax

do_morph:

                        push    FLAG_NOJMPS+FLAG_X_CALLESP ; flags

                        push    CMD_ALL                 ; cmd mask

                        push    CMD2_ALL-CMD2_FPU       ; cmd2 mask

                        push    REG_ALL                 ; reg mask

                        push    0                       ; jmps if rnd(X)==0

                        push    0                       ; [output eip]

                        push    0                       ; [output size]

                        push    0                       ; output filler
```
