

# [原创]某游戏 LUA 分析

游戏引擎是`libcocos2dlua.so`。

![](https://bbs.kanxue.com/upload/attach/202208/540232_NKRNZYJQJ3BAKYN.jpg)

## 脱壳与修复

拖到 IDA 去看看，发现加固了。

![](https://bbs.kanxue.com/upload/attach/202208/540232_ETNQBD7PW753F2E.jpg)

我们去内存中 DUMP 出来，这里就不写 DUMP 过程了，DUMP 脚本很多。

DUMP 出来之后进行修复。修复工具下载地址：[872K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6r3z5p5I4q4c8W2c8Q4x3V1k6e0L8@1k6A6P5r3g2J5](https://bbs.kanxue.com/elink@0bbK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6r3z5p5I4q4c8W2c8Q4x3V1k6e0L8@1k6A6P5r3g2J5)。

DUMP 出来的文件头被魔改了，自己用原来的 SO 文件头复制粘贴进去，再进行修复就可以了。

## 定位 `luaLoadBuffer`

说到 LUA 的游戏，我们基本上都是通过`luaLoadBuffer`进行 HOOK DUMP 的。

我们打开修复好的 SO，竟然找不到`luaLoadBuffer`。

![](https://bbs.kanxue.com/upload/attach/202208/540232_KKCKT5BMCSCXKZF.jpg)

遇见这种情况，只能去看它的开源框架了。先看下它是多少版本的。

![](https://bbs.kanxue.com/upload/attach/202208/540232_TZ4FV4Z2F793XU6.jpg)

发现是`cocos2d-x-3.13.1`，我们去下载这个版本的源码。下载地址：[12aK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6U0L8$3y4G2M7K6u0V1i4K6u0r3j5$3!0U0L8%4x3J5k6q4)9J5k6s2R3`.](https://bbs.kanxue.com/elink@4eaK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6U0L8$3y4G2M7K6u0V1i4K6u0r3j5$3!0U0L8%4x3J5k6q4)9J5k6s2R3`.) 

下载好后解压。这里我为了图方便，直接用 Notepad++ 的搜索功能搜`luaLoadBuffer`。

![](https://bbs.kanxue.com/upload/attach/202208/540232_943EHMS9Y9AYQQS.jpg)

可以看到它是有`luaLoadBuffer`的，只是被它隐藏了。那我们该怎么定位到它呢？我们看到上面有个`?.lua`字符串，我们去 IDA 搜下看看。

![](https://bbs.kanxue.com/upload/attach/202208/540232_W6FZPFMHVJF548G.jpg)

可以看到也是有的。那么我们就鼠标点击过去，选中`alua_2`，按下键盘上的 X 键。

![](https://bbs.kanxue.com/upload/attach/202208/540232_A8AEA3CHU4G62XY.jpg)

点 OK 跳过去。

![](https://bbs.kanxue.com/upload/attach/202208/540232_6FPESN298M5HKRF.jpg)

我们可以看到这里和我们刚才看的源码基本上是一样的。那么我们按 F5 看伪代码。

![](https://bbs.kanxue.com/upload/attach/202208/540232_G2XVU8NNCBDGVZ8.jpg)

通过分析，`sub_18A080`就是`luaLoadBuffer`，我们点进去看看。

![](https://bbs.kanxue.com/upload/attach/202208/540232_NNT4TKRRHT56S5J.jpg)

伪代码太长了，我就不全部截图了。

通过 HOOK 打印`sub_18A080(v41, a1, v42, v43, v71);`

`V42` = 内容，`V43` = 长度，`V71` = 文件名。

进入`sub_18A080`内部，发现这个`sub_4595C0`正好对应`luaLoadBuffer`参数：

```cpp
sub_4595C0(a2, v21, v64, a5);
```

```cpp
luaLoadBuffer(l, (const char*)data.getBytes(), (int)data.getSize(), fullPathOfScript.c_str());
```

到这里就不需要多说什么了，直接 HOOK DUMP 脚本就好了。

## 修改 opcode

发现脚本 DUMP 出来竟然是 LUAq 的。

![](https://bbs.kanxue.com/upload/attach/202208/540232_6ZAPV7KXDY5NEA8.jpg)

直接用`unluac`反编译，发现报错了，那应该是修改了 opcode。

继续用 IDA 定位 opcode。

搜索字符串`'for' limit must be a number`。

![](https://bbs.kanxue.com/upload/attach/202208/540232_2BNPYHMVDRYYHBV.jpg)

和刚才一样，点击过去按 X 键，点 OK 跳过去。

![](https://bbs.kanxue.com/upload/attach/202208/540232_96FKT6WN9FNVXR8.jpg)

然后按 F5。

![](https://bbs.kanxue.com/upload/attach/202208/540232_GKEC9P5YXKKFW76.jpg)

`case`就是 opcode，把它拿出来修改下`unluac`的就可以解密了，这里就不写那么详细了。
