LRESULT WINAPI ButtonWndProcW(
    HWND hwnd,
    UINT message,
    WPARAM wParam,
    LPARAM lParam)
{
    PWND pwnd;

    if ((pwnd = ValidateHwnd(hwnd)) == NULL) {
        return (0L);
    }

    /*
     * If the control is not interested in this message,
     * pass it to DefWindowProc.
     */
    if (!FWINDOWMSG(message, FNID_BUTTON))
        return DefWindowProcWorker(pwnd, message, wParam, lParam, FALSE);

    return ButtonWndProcWorker(pwnd, message, wParam, lParam, FALSE);
}

另外，`user32`有两个辅助表用于继续分发消息，比较有意思：

- 一个是消息表：`MessageTable`。记得笨笨雄也以前提出来过这个东西。
- 一个是消息所对应跳转的事件表：`gapfnScSendMessage`。

两个表如下：

首先根据消息的 ID 在`MessageTable`表中取出消息 ID 所对应的`sig`，然后与`3F`相加，得出的结果是它所对应事件表`gapfnScSendMessage`的索引，然后跳转到它的事件地址中。

随便找个消息分发函数，比如：`DefWindowProc` → `RealDefWindowProc` → `RealDefWindowProcWorker`。

真正用到`MessageTable`索引是在`RealDefWindowProcWorker`这个函数中。`win2k`代码好像没有找到这个函数。

这个过程用`od`跟踪不错，`od`跟踪到这里：
