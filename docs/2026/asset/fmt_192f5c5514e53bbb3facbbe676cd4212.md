
# [原创] 实现将AJM脱UPX壳修复so文件

工具使用:IDA6.8, 010 Editor

## 开始前描述现象

将原APP解压出来的`libexec.so`放到IDA中加载发现打开的函数不能进行F5转为C代码

![](https://bbs.kanxue.com/upload/attach/202004/732177_QWN5Q4EJ88GRU9Q.png)

在该函数中按F5会弹出该提示,使我们无法转为C代码进行进一步的分析

![](https://bbs.kanxue.com/upload/attach/202004/732177_EUKE9VSXEJ7T683.png)

![](https://bbs.kanxue.com/upload/attach/202004/732177_3ZJ5EQ8QBKUPDJP.png)

## 3.dump so操作

## 4.根据UPX数据结构分析得出真实的数据大小

使用010 Editoe工具先加载app的原`libexec.so`

![](https://bbs.kanxue.com/upload/attach/202004/732177_C643RMJG5776VV2.png)

接着搜索关键字”AJM!”,选择第一个

![](https://bbs.kanxue.com/upload/attach/202004/732177_6TPCCJBGWQZCHYB.png)

接着使用IDA打开app里面的原`libexec.so`,待加载完毕后在导出表中搜索`.init_proc`并进入

![](https://bbs.kanxue.com/upload/attach/202004/732177_SQZDXGVJWSDVVE2.png)

此位置就是so的开始位置

![](https://bbs.kanxue.com/upload/attach/202004/732177_57VNXBANJNTM3PW.png)

那么接着在010 Editor中可以看到刚才搜索的位置就在`0x11A20`开始

![](https://bbs.kanxue.com/upload/attach/202004/732177_FG97EMKRD4FE3K3.png)

其中结构体我这边是参考 一只流浪狗 大神写的 upx分析原理 进行分析的

![](https://bbs.kanxue.com/upload/attach/202004/732177_EWZRSDKV7M5WMBS.png)

里面共有3个结构体共36个字节,其实大家关注的地位就在第三个结构体中的`sz_cpr`字段的数据.

其数据为第二行后4字节.即`0x91`

那么计算压缩前数据的初始位置,从魔数位置开始算起,也就是UPX结构体的后面开始计算得出记录原始数据数据段大小的位置:`0x11A44 + 0x91 = 0x11AD5`

现在跟进`0x11AD5`的位置所在的12个字节数据就是对应压缩前,压缩后的数据大小,分别为`0x46A50`和`0x28B55`

![](https://bbs.kanxue.com/upload/attach/202004/732177_2Z5RYFKBFH978KE.png)

## 5.修复libexec.so

现在知道了压缩前的数据大小了,那么接着开始修复.首先将之前在内存中dump出来的`libexec.so`拖到010 Editor里面使用elf结构解析脚本进行解析.

![](https://bbs.kanxue.com/upload/attach/202004/732177_MRRQ4MZZUEG2DD3.png)

修复的话只需修复01~03段即可.

01段 只需要将之前得出的`0x46A50`转换为十进制进行将01段的数值替换即可
