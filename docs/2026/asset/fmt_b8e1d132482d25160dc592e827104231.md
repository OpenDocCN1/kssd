# 0x02 分析

直接加载sys后发现往`afd.sys`挂了一个注册表回调，回调入口是跳板

![](https://bbs.kanxue.com/upload/attach/201902/619065_N69BQ2H9Y8TNRX2.png)

由于驱动直接加载会返回`C0000001`导致立刻被卸载，无法直接dump

于是改用模拟器加载并在真实`DriverEntry`处dump整个sys内存：

经过调试发现Safengine保护的驱动会使用`DriverObject->DriverSection`进行`PsLoadedModuleList`的遍历并修复导入表

如果在模拟器中给上假的

`DriverSection`会导致SE访问到非法内存

![](https://bbs.kanxue.com/upload/attach/201902/619065_KUBJBG5WJHX3DTS.png)

![](https://bbs.kanxue.com/upload/attach/201902/619065_PNCQD975H9W4S2M.jpg)

于是我们给模拟器补上自己伪造的

`PsLoadedModuleList`和

`DriverSection`

：

![](https://bbs.kanxue.com/upload/attach/201902/619065_ME25C5FBKDWM2AP.jpg)

```
DriverObject.DriverSection = (PVOID)m_DriverLdrEntry;
```

补完后可以正常执行到真实入口点，可以看到这个sys执行的第一次API是`RtlInitUnicodeString`

![](https://bbs.kanxue.com/upload/attach/201902/619065_3ABCB8YKK9DVGHM.png)

# 0x03 总结

用Safengine加壳驱动并且不vm不混淆任何函数是非常不安全的行为，在模拟器的安排下几乎等同于裸奔。（此时有效的保护只有代码重组，只能干扰一下IDA的F5，如果单看汇编就是裸奔）

用VMProtect 3.X加壳并保护导入表会稍微好一点，不过稍微修改一下本文中的导入表重建算法，像https://bbs.pediy.com/thread-248812.htm一样

识别出VMP的API call，也可以无压力完美脱壳。
