# 逻辑构思

在进行硬编码解析的时候,我们需要先明白这样一个道理:`一段硬编码解析开始位置的不同,将会导致整段汇编代码发生巨大的变化`
为什么这样说呢,举个简单的例子
我们都知道 `0x74` 对应的指令为`JZ`,后面跟着一个字节的数据用来确定跳转距离,这是个`两字节的定长指令`,而我们知道 `0x50`对应的指令为`PUSH EAX`,这是个`一字节的定长指令`
那么假如有这样一段数据 `XX XX XX 74 50 XX XX`,那么当引擎想要解析这段硬编码时,必须确定从何处开始,如果从74处开始解析,指令会变成`JZ XX`,后面的50将会被吞入JZ指令中
若从50处开始解析,那么会变成`PUSH EAX`,前面的74可能会成为上一句指令的一部分
所以不同的开始位置将会改变指令的含义,由此推出解析逻辑:
`首先确定解析开始位置,位置确定后,根据首字节数据进行解析,当解析完改条指令后,索引向后移动刚刚解析完的指令的长度,这样就可以保证解析的完整性,不会丢字节,多吞字节`
