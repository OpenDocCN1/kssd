## 重要结构体

### 可执行文件

Linux中所有支持的可执行文件类型在内核中都有一个对应的`linux_binfmt`类型的对象。

所有的`linux_binfmt`对象都保存在一个双向链表中，此链表第一个元素的地址保存在`formats`内核全局变量中。

```C
/*
 * This structure defines the functions that are used to load the binary formats that
 * linux accepts.
 */
struct linux_binfmt {
    struct list_head lh;
    struct module *module;
    int (*load_binary)(struct linux_binprm *);
    int (*load_shlib)(struct file *);
    #ifdef CONFIG_COREDUMP
    int (*core_dump)(struct coredump_params *cprm);
    unsigned long min_coredump; /* minimal dump size */
    #endif
} __randomize_layout;
```

- `load_binary` 装入并执行新的程序
- `load_shlib` 装入共享库
- `core_dump` 崩溃时进行内存转存

```C
static struct linux_binfmt elf_format = {
    .module         = THIS_MODULE,
    .load_binary    = load_elf_binary,
    .load_shlib     = load_elf_library,
    #ifdef CONFIG_COREDUMP
    .core_dump      = elf_core_dump,
    .min_coredump   = ELF_EXEC_PAGESIZE,
    #endif
};
```

所以我们可以知道，`load_elf_binary`负责加载新的程序，`load_elf_library`负责加载共享库。

#### ELF 的类型

- `ET_NONE`：未知类型。
- `ET_REL`：重定位文件。通常是还未被链接到可执行程序中的一段位置独立的代码，例如 Linux 中的 `.o` 格式的文件。
- `ET_EXEC`：可执行文件。
- `ET_DYN`：共享目标文件。ELF 类型为 `dynamic`，意味着该文件被标记为了一个动态的可连接的目标文件，也称为共享库，这类共享库会在程序运行时被装载并链接到程序的进程镜像中。
- `ET_CORE`：核心文件，在程序崩溃或进程传递了一个 `SIGSEGV` 信号（分段违规）时，会在核心文件中记录整个进程的镜像信息。

## 启动流程

> 一般程序启动的流程就是调用 `fork` 复制一个当前进程的副本为新的进程，子进程 `fork()` 返回后会继续调用 `exec()` 进入到内核中。

### 调用链

> Linux 6.12.32 版本下

```C
do_execve() [入口]
do_execveat_common() [准备环境]
bprm_execve()
exec_binprm()
search_binary_handler()
load_libary() [加载 ELF 的核心逻辑]
```

### `do_execve`

总的来说 `exec()` 作用就是清空新创建的进程的 `.text`、`.data`、`.bss` 段等，然后装载新进程并运行。
