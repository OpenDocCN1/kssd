
# 修改指针泄露 libc 总结

```
add(0x98) #0
add(0x90) #1
payload=p64(0)+p64(0x91)+p64(ptr-0x18)+p64(ptr-0x10)+p64(0)*14+p64(0x90)+p64(0xa0)
```

这个蛮灵活的，像 `axb_2019_heap` 这个给了格式化就可以直接泄露比较方便，也是因为开了 PIE 保护的原因。

## 1. 无 PIE 无 show

这里还要考虑有没有开 PIE、有没有 `show` 功能。如果题目开了 PIE 但没给 `show`，我们可以先 `unlink`，然后再往存放 `chunk` 的数组里面去构造 `got` 表更改，比如写入 `free` 的 `got` 改为 `puts` 的 `got`，然后再拿个正常的 `chunk`，编号在他前面的正常 `chunk` 往里面写入 `puts` 的 `plt` 地址，就像我前面提到的，函数 `chunk` 和参数 `chunk` 的道理。此时我们去释放写入 `got` 的参数 `chunk`，就会触发函数 `chunk` 的内容，由此就可以得到 `puts` 的真实地址。

## 2. 无 PIE 有 show

`unlink` 后直接写入要泄露的 `got` 地址然后 `show` 出来就行了。

## 3. 我们 unlink 后修改到的地方

在构造 fake chunk 时我们修改了 `fd`、`bk` 指针。

当我们 `unlink` 后，我们的指针指向的是 `ptr-0x18` 的地方。

我们再对新的 `chunk` 或者当前用于构造 fake chunk 的 `chunk` 去写入的时候，是往 `ptr-0x18` 的地方去写入。

我们在写入数据的时候要找好偏移，所以要去摸清楚数组存放了什么，哪些是指针，加多少 `p64(0)` 才能到达。

可以利用区块的指针然后去修改他。

### 思路概述

我们先要明白我们的条件有什么：1. 堆溢出 2. 泄露地址

## 2. `wdb2018_guess`

生草的多线程哈哈，还好不是爆破 canary，不然我真觉得没意思。

`main` 函数打开了 flag，存在在栈上变量 `buf` 上，然后这个题开了 canary，开了多线程。

我们知道的多线程 canary 不变的，同时有 canary 的时候是不会改变的。

同时没有填充 canary 的栈溢出是会有错误提示的，如下：

同时这题有 `gets`，那么我们可以这么想，这种报错提示也是一种输出，那么我们把输出内容换成 `got` 表，是不是就有了 real addr。

我们打开 IDA 来看在 `jnzf` 打断点。

`rsi` 距离 `0x7fffffffdec8` —▸ `0x7fffffffe267` ◂— '/home/q/Desktop/GUESS1' 为 `0x128`。

我们报错输出的就是后面那的东西，我们将其覆盖为 `got` 表得到 `libc`，再得到 `__environ` 函数的真实地址。

再去覆盖到那就可以得到栈地址，有了栈地址就可以知道他和 flag 的 `offset`，到时候再传入这个偏移，下次报错就吐 flag 了。
