
## 三、SMB Message 结构

SMB Message 包括一个固定长度的 Header（32 字节）、一个可变长度的 Parameter Block（最大为 64 KB）以及一个可变长度的 Data Block。

### SMB Message Header

长度为 32 字节的固定结构：

```c
SMB_Header
{
  UCHAR  Protocol[4];
  UCHAR  Command;
  SMB_ERROR Status;
  UCHAR  Flags;
  USHORT Flags2;
  USHORT PIDHigh;
  UCHAR  SecurityFeatures[8];
  USHORT Reserved;
  USHORT TID;
  USHORT PIDLow;
  USHORT UID;
  USHORT MID;
}
```

简单介绍一下比较重要的部分：

1. **Protocol**（4 字节）：需要包含 `"\xff"、"S"、"M"、"B"`。
2. **Flags2**：保留位必须设置为 0，且需要重点关注 `SMB_FLAGS2_DFS` 字段。如果该位被设置为 1，则任何文件路径名都应该在 DFS 中进行处理。这也是很多漏洞的触发点，因为文件路径规范化处理函数可能存在漏洞。
3. **SecuritySignature**（8 字节）：如果已协商 SMB 签名，则此字段必须包含一个 8 字节的加密消息签名，可用于检测消息是否在传输过程中被修改。消息签名的使用与无连接传输是互斥的。

### Parameter Block

在 CIFS 方言中，`SMB_Parameters.Words` 数组可以包含任意结构。`SMB_Parameters.Words` 结构的格式针对每个命令消息单独定义。`Words` 数组的大小仍然被测量为字节对的计数，其结构如下所示：

```c
SMB_Parameters
{
  UCHAR  WordCount;
  USHORT Words[WordCount] (variable);
}
```

1. **Words**（variable）：消息特定的参数结构。此字段的大小必须为 `2 x WordCount` 字节。如果 `WordCount` 为 `0x00`，则不包含此字段。

### Data Block

结构与 Parameter Block 相似：

```c
SMB_Data
{
  USHORT ByteCount;
  UCHAR  Bytes[ByteCount] (variable);
}
```

### Batched Message（AndX Messages）

主要用于在一个 Message 中发送多个 Request 或 Response Command，而只需要一个 SMB Header 即可。

在 AndX Messages 中，只发送一个 SMB Header（Section 2.2.3.1）。Header 后面跟随零个或多个 Parameter Block 和 Data Block 对，每一对分别对应一个额外的命令请求或响应。具体消息中对 Block Pair 的数量没有限制，限制仅来自消息的总大小。Batched Message 的总大小不得超过协商得到的 `MaxBufferSize`。

AndX Messages 包含一个概念上类似于链表的结构，用于连接批量传输的 Block Pair。由此形成的列表称为 AndX Chain。

其结构如下：

```c
AndX
{
  UCHAR  AndXCommand;
  UCHAR  AndXReserved;
  USHORT AndXOffset;
}
```

1. **AndXOffset**（2 字节）：下一个 Parameter Block 在 AndX Message 中的偏移量。该偏移量以 SMB Header 的起始位置为相对基准，并且独立于命令中的其他大小参数或偏移量。此偏移量可以指向当前 Block Pair 末尾之后的位置。

AndX 结构位于 AndX 命令请求或响应的 Parameter Block 起始位置。

## 五、SMB Examples

### 1. Negotiate and Tree Connect Example

![](https://bbs.kanxue.com/upload/attach/201904/779730_XZQXNZF5S5D2BYC.png)

这是 SMB 协议的第一步，首先进行的是 Negotiate and Tree Connect。在该过程中，使用的 SMB 命令为 `SMB_COM_NEGOTIATE(0x72)`，此命令用于启动客户端和服务器之间的 SMB 连接。

在将任何其他 SMB 消息发送到服务器之前，必须完成 `SMB_COM_NEGOTIATE` 交换。需要注意的是，每个 SMB 连接只能有一个 `SMB_COM_NEGOTIATE` 交换。必须拒绝服务器收到的后续 `SMB_COM_NEGOTIATE` 请求以及错误响应。服务器不得采取任何其他行动。

从图中可以看出，在完成 `SMB_COM_NEGOTIATE` 交换之后，再进行 Session 的建立和 Tree 的连接。完成这三个步骤之后，一个 SMB 连接的基本配置完成。

### 2. Disconnect Example

在 SMB 连接和会话已经完成时，客户端会按照此示例从共享服务端断开连接。

![](https://bbs.kanxue.com/upload/attach/201904/779730_J3AMGQ45RGJ7AHJ.png)

该过程中基本只涉及一个 `SMB_COM_TREE_DISCONNECT(0x71)` 命令，相对来说比较简单。客户端收到 Response 后，SMB 连接正式中断。

### 3. Get File Attributes Example

最后介绍一个稍微复杂一点的例子：获取共享文件相关属性的过程。

![](https://bbs.kanxue.com/upload/attach/201904/779730_2NM2WYCCDJPUA3A.png)

在连接建立后，客户端向共享服务端发起文件访问请求。在该过程中，双方要确认所访问文件的相关属性，以确定客户端是否有权访问，或者具体访问哪个文件。

从图中可以看出，该过程分多次完成。客户端发起 `SMB_FIND_FIRST(0X32)` 请求，告诉共享服务端要执行的操作；然后客户端传输一个 `SMB_COM_QUERY_INFORMATION(0x08)`，共享服务端返回相应的文件数据，这样就完成了一次文件属性的获取。

然后，客户端和共享服务端将通过多次请求，确定所有待访问文件属性。最后，客户端在获取到自己需要的所有信息后，发起 `SMB_COM_FIND_CLOSE(0x34)`，终止该过程。

上面只是简单地举了几个例子，以加深对 SMB 的理解。其实只要懂网络协议，想弄清楚 SMB 还是相对来说比较简单的。困难的地方在于传输过程中可能出现的错误或者数据包的不正确性等问题，SMB 的所有漏洞也基本出在这两个点上。

虽然现在 SMB 已经很完善，对于数据包校验和检查以及容易出现漏洞的地方都进行了优化，但是只要熟悉它的细节，还是很有可能从其他地方找到漏洞的。也就是说，如果再想挖 SMB 的漏洞，现在需要换思路、调整方向，不能走以前的老路子了。
