
# [原创]X浪的缓冲区溢出漏洞

## 缓冲区溢出

X浪在处理本地图片时存在缓冲区溢出的漏洞，问题出现在`Java_com_sina_filter_JpegExifExtractor_nativeExifExtrator`函数，具体功能是解析JPEG格式的EXIF的信息。

![](upload/attach/202510/920134_KH4Z823A98C9BK4.webp)

## 漏洞代码

继续分析发现了真正出现漏洞的地方是如下的代码：

```
printf_(s, "CameraModel make: %s, model: %s", v64, v65);
```

将`Make (271)` 和 `Model (272)` 的字段值进行了合并，正常的逻辑是`EXIF`内容的所有值加起来的最大长度是`0xFFFF`，似乎`make`加`model`的最大长度也不会超过`0xFFFF`。

![](upload/attach/202510/920134_5RAVYP2KBUUT72Y.webp)

`Make`的值可以设置为`64995(0xFDE3)`，这时`Model`值的正常长度是`13(0xD)`，合并后的长度是`65008(0xFDF0)`，显然是在`0xFFFF`的长度范围内。

如果将`Model`的偏移地址和长度设置为与`Make`的偏移地址和长度一致，就可以突破`0xFFFF`的限制，长度可达`129990(0x1FBC6)`，同时可以控制`Model`的长度，来设置溢出的范围。

同时`s`的地址是`0x0005C05C`,程序的最大地址是`0x00072268`,差值是`0x1620C`,可以向程序外溢出`0x99BA`。

## 漏洞利用

查看程序的`segment`表，可以向下溢出到`bss`段。

![](upload/attach/202510/920134_FV622ZE8PS7FF65.webp)

查看程序的防护，防护全开。

```

```

首先覆盖的是位于其下方的`DATA`段的导出函数：`EXPORT __ZN10__cxxabiv119__terminate_handlerE`

![](upload/attach/202510/920134_R5UCTQ34FC8UZEX.webp)

与`s`值的结束地址相差`0x8D`，对内存破坏的影响最小，但是这是一个被动调用的函数，只有程序出现异常才有可能触发，另外即使触发也需要处理传递参数的问题。

继续向下溢出到`bss`段，`JNI`调用出现了异常。

出现异常的是以下的代码：

```
int __fastcall NewObject(int jnienv)
{
return (*(int (__fastcall **)(int, int, int))(*(_DWORD *)jnienv + 112))(jnienv, dword_6C184, dword_6C188);
}
```

`dword_6C184`和`dword_6C188`对应的参数是`jclass`和`jmethodID`:

```
jobject (*NewObject)(JNIEnv*, jclass, jmethodID, ...);
```

调用代码是：

```
v14 = NewObject((int)jnienv);
```

原始的逻辑是调用`ExifInfo`的构造函数创建`Object`对象，理论上可以替换`jclass`和`jmethodID`来构造指定的对象。

```
JNIEnv->NewObject(class com/sina/filter/ExifInfo, <init>()
```

然后是三个`CallVoidMethod`进行了对象函数的调用:
