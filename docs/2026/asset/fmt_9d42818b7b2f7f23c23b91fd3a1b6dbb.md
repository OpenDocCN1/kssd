如果使用机器码的话一定要注意不能被轻易拦截或替换，最好用比较底层的操作，少调用系统函数，用不同方法多取一些特征。验证用的机器码不要和显示的相同，最好是取到机器特征并计算后再用不同的算法生成显示和验证用的内容，生成机器码的部分要重点保护，否则很容易被替换。

用虚拟机加密的代码中尽量减少退出虚拟机的次数，比如函数调用，从调用参数和堆栈、寄存器等内容中可以得到一些重要信息。长整型和浮点数计算编译器可能会自动加入一些函数调用。如果要调用函数，最好把被调用函数也虚拟，通常情况下VMP会直接`JMP`进这些函数而不是退出虚拟机。

转移目标在`vR10`中，可以插入指令

清除堆栈数据，插件认为被弹出堆栈的数据无效，插入以下代码可以清除堆栈中的已知数据

```
add esp,0x1000
sub esp,0x1000
```

先把`esp`加`0x1000`，这样插件分析时会认为当前`esp+0x1000`内的数据都被弹出了，从已知数据中清除。可以先定义一下，这样使用方便

```
#define QINGCHUDUIZHAN {\
        __asm pushfd\
        __asm add esp,0x1000\
        __asm sub esp,0x1000\
        __asm popfd\
}
```

生成长表达式，由于化简过程中会将每个指令块中相关的操作组合成一个表达式，然后再拆分成变量，中间结果使用表达式树保存，可以用重复操作生成很长的表达式，使分析失败。

```
#define CHANGBIAODASHI {\
        __asm push eax\
        __asm pushfd\
        __asm pushfd\
        __asm pop eax\
        __asm add eax,eax\
        ...//32个
        __asm popfd\
        __asm pop eax\
}
```

先把`EFL`赋值给`EAX`，确保计算结果为变量，以免计算结果为常量而被合并。然后32个加法，会产生含有2^32个`EFL`的表达式，没有人内存能装下这么多内容吧，光是创建就慢死他。减法或异或等可能产生更长的表达式，但是化简规则中有异或自己和减自己等于0，会清除这种操作。插件选项中有一项最大表达式长度，如果设了这个选项可能就没用了，只生成一个`longExp`变量。上面只简单介绍了几种方法，其他的还有很多，只要知道分析原理很容易想出其他的。
