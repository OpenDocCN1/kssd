# 以直接调用方式绕过资源加密

开始我尝试了用 unicorn-engine 模拟运行。但是后来发现函数里调用了 malloc 等标准库函数，处理起来很麻烦。IDA 调试的选项也被我 pass 掉了，结合 cocos2dx 在 `CCImage.cpp` 中对图片的处理过程可知，内存里面存的是原始的 RGBA 数据，即使做出来内存 dump 也卵用无。折腾两天后决定利用 NDK 自己写一个 wrapper，利用这个函数已导出的特性，从 so 里面获取这个函数并调用它来为我们解密。

我们先从已有代码入手判断一下 `Image` 类的结构。结合一下 [CCImage.h](https://bbs.kanxue.com/elink@80fK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6#2x3s2f1H3i4K6u0r3f1i4g2A6j5$3E0Q4x3X3c8o6L8$3y4G2M7K6u0V1P5q4)9J5k6p5y4G2L8h3#2#2L8X3W2@1P5g2)9J5c8X3u0D9L8$3u0Q4x3V1j5$3x3h3x3@1k6U0k6W2x3r3x3&6j5U0M7^5k6h3x3J5j5$3b7$3y4o6V1I4j5e0k6X3x3r3q4W2k6e0u0U0y4U0M7#2k6e0x3H3y4o6q4T1i4K6u0r3j5$3!0U0L8%4y4Q4x3V1k6H3L8r3q4@1k6X3!0J5L8g2)9J5c8V1y4o6d9h3#2S2k6$3g2Q4x3X3g2Z5i4K6t1K6e0o6p5%4y4R3`.`.) 与 [CCImage.cpp](https://bbs.kanxue.com/elink@a90K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6#2x3s2f1H3i4K6u0r3f1i4g2A6j5$3E0Q4x3X3c8o6L8$3y4G2M7K6u0V1P5q4)9J5k6p5y4G2L8h3#2#2L8X3W2@1P5g2)9J5c8X3u0D9L8$3u0Q4x3V1j5$3x3h3x3@1k6U0k6W2x3r3x3&6j5U0M7^5k6h3x3J5j5$3b7$3y4o6V1I4j5e0k6X3x3r3q4W2k6e0u0U0y4U0M7#2k6e0x3H3y4o6q4T1i4K6u0r3j5$3!0U0L8%4y4Q4x3V1k6H3L8r3q4@1k6X3!0J5L8g2)9J5c8V1y4o6d9h3#2S2k6$3g2Q4x3X3g2U0M7s2m8Q4x3U0y4x3z5o6V1@1) 中`cocos2d::Image::initWithPngData`与其在 IDA 中反汇编的对应关系整理如下。

然后就是编写程序了。C++ 类成员函数在编译时被 mangle 成一个乱乱的字符串，在 IDA 里或 objdump 都可以获得，原样拿来并用`dlsym`寻找函数指针，用我们伪造的 `Image` 类作为第一个参数的 this 指针调用即可。至于如何将 `Image` 对象的内容保存为 png，这个就留给大家作为思考题，方法是一样的。

注意，这里没有写但是我已经*提前分析*过我们要调用的函数对 `Image` 类的读写状况，对成员变量的所有操作都是先写入再读取，不存在未初始化的情况。如果大家要用类似方法调用其他函数，也要注意传入的数据成员的值。
