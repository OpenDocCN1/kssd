
### 方法一（重启失效）

已 root 的手机修改手机系统的全局 `debuggable` 标志值为 `true`（即将 `/default.prop` 中的 `ro.debuggable` 的默认字段值 `0` 修改为 `1`），这样此手机上各种 AP 都可以调试了，**若手机重启后需要再次进行修改操作**。修改 `ro.debuggable` 的步骤：

| 步骤 | 操作 |
| --- | --- |
| 1 | 连接 Google Nexus 真机：`adb devices` |
| 2 | 检查 Google Nexus 架构：`adb shell getprop ro.product.cpu.abi` |
| 3 | 下载架构相同的 `mprop`：`https://github.com/wpvsyou/mprop` |
| 4 | 将文件 push 进手机的指定目录下：`adb push mprop /data/local/tmp` |
| 5 | 进入手机端命令：`adb shell` |
| 6 | 切换获取手机的 root 权限：`su` |
| 7 | 查找 push 的文件是否在手机中：`cd /data/local/tmp/` |
| 8 | 查看路径下的文件以及权限：`ls -l` |
| 9 | 拥有 root 权限更改文件的权限为 777：`chmod 777 mprop` |
| 10 | 修改 `ro.debuggable` 的值为 `1`：`./mprop ro.debuggable 1` |
| 11 | 获取 `ro.debuggable` 值：`getprop ro.debuggable` |

### 检测是否被调试

利用 Linux 系统 `ptrace` 来实现，当应用被调试时应用内存里的 `TracerPid` 字段就不为 `0`，只要是不为 `0` 的时候，就会直接地退出程序达到反调试的目的。

接下来进入设备查看一下 `ptrace` 字段：

| 步骤 | 操作 |
| --- | --- |
| 1 | 进入设备：`adb shell` |
| 2 | 获取 Root 权限：`su` |
| 3 | 获得 APP 的进程 ID：`ps \| grep 软件的包名` |
| 4 | 查看进程的信息及 `TracerPid` 值：`cat /proc/进程ID/status \| grep TracerPid` |

![图片描述](https://bbs.kanxue.com/upload/attach/202306/909733_UR333Y34X5WSNTC.png)

## 反反调试

**如何反反调试**：程序的 `so` 文件在加载阶段会先执行 `JNI_OnLoad`，之后就不再执行，在程序的 `so` 文件加载阶段才能给 `JNI_OnLoad` 打断点调试即可！

| 步骤 | 操作 |
| --- | --- |
| 1 | `//`调试 APP 挂在加载界面 |
| 2 | `adb shell am start -D -n 包名/.类名` |
| 3 | `adb shell am start -D -n com.yaotong.crackme/.MainActivity` |
