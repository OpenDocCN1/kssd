
我们再来看看 SMB 上 RPC 的另一个简单示例：使用<a href="elink@1f3K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6K6N6i4m8H3L8%4u0@1i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3S2W2L8s2m8Q4x3V1j5K6x3e0x3#2y4U0g2Q4x3V1k6Z5L8%4N6Q4x3X3c8@1L8#2)9J5k6s2g2K6k6g2)9J5k6s2c8Z5k6g2)9J5k6r3q4@1i4K6u0V1j5$3!0E0L8h3q4F1k6q4)9J5k6s2c8G2i4K6u0V1M7$3y4Z5k6h3c8#2L8r3g2Q4x3X3c8@1j5i4y4C8M7H3`.`.">at 命令</a>在远程计算机上安排任务。我们将只看到 PCAP 的一部分，从会话建立之后开始，而我们已经连接到 IPC$ 共享。

![](upload/attach/202002/505507\_HCJA3JH7BXVSXGV.jpg)

从高层次来看，<a href="elink@794K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1j5@1x3o6q4@1M7X3N6Q4x3V1k6V1k6i4c8W2j5%4c8A6L8$3&6K6i4K6u0r3M7X3q4%4i4K6u0r3L8h3q4K6N6r3g2J5i4K6u0r3M7r3y4S2M7s2y4Q4x3V1j5J5x3o6p5%4x3e0t1J5x3q4)9#2k6Y4y4E0j5W2)9#2k6X3q4@1i4K6g2X3M7$3y4Z5k6h3c8#2L8r3g2Q4x3X3g2H3j5$3q4H3">这个 PCAP</a>看起来与上面的 SAMR 调用类似。我们使用服务名（标记 1）（`atsvc`，我们可以从 SMB Create Request File 命令中看到）创建一个请求文件，调用一个 RPC 绑定（2），然后发送一个 JobAdd 请求到 at 服务（标记 3）。

有几点需要注意：

1. 由于在这种情况下，RPC 在 SMB 上运行，所以每个 RPC 命令都必须有一个与其关联的 SMB 命令。在这种情况下，RPC bind 位于 SMB write 之上，而与服务的通信发生在 ioctl/fsctl 命令上（<a href="elink@b57K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6E0M7$3c8F1i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3I4A6j5Y4u0S2M7Y4W2Q4x3V1k6U0j5K6t1@1y4U0f1@1y4g2)9J5k6h3q4K6M7s2R3`.">详见</a>）。
2. 这可能有点混乱，所以有时候最好把它看作三个独立的层：SMB、RPC 和服务（在这个例子中是 ATSVC）。许多 RPC 命令都会在 SMB ioctl 命令之上，如下所示。
3. 假设你不是逐字节地撕开数据包，那么 SMB 命令并不是特别重要：相反，把重点放在 RPC 调用上，或者（如果 Wireshark 能解析它）在 RPC 上运行的服务。

这是一个重大的简化。SMB 命令最终确实很重要，并且对数据如何传递给 RPC 调用和低层服务有影响。充分讨论这个超出了本指南的范围，但我建议每个读者仔细检查每个 PCAP 中的 RPC 调用，看看 SMB、RPC 和服务命令是如何关联的。

![](upload/attach/202002/505507\_T4G723UAS35WG8A.jpg)

Wireshark 为我们解析了 at 编排器服务命令，我们可以看到用户正在尝试安排 `mimikatz` 运行。

# PSExec

PsExec 是一个 Windows 远程管理工具，长期以来一直是 Active Directory 环境中攻击者横向移动的最爱。PsExec 自己的网站将自己描述为：“一个轻量级的 telnet 替代品，可让您在其他系统上执行进程，并且具有控制台应用程序完全交互性，而无需手动安装客户端软件。PsExec 最强大的用途包括在远程系统上启动交互式命令提示符，以及像 IpConfig 这样的远程启用工具，否则无法使用这些工具显示有关远程系统的信息。”（<a href="elink@111K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4y4&6M7$3W2F1N6r3g2J5L8X3q4D9M7#2)9J5c8X3c8G2N6$3&6D9L8$3q4V1M7#2)9J5c8Y4m8K6k6i4S2W2j5H3`.`.">详见 PsExec</a>）。

虽然它仍然常用于合法管理任务，其广泛的功能对攻击者来说很有用。如果完全部署的话，请务必密切关注它在网络中的所有使用。

PsExec 在网络分析上可能会相当复杂，所以我们首先看一下两个简单的例子。

## 示例一：提取文件

第一个显示 PsExec 被用来从目标机器提取文件。正在执行的命令是：

```text
psexec.exe \\admin-pc -accepteula cmd /c (cd c:\temp ^&mimikatz.exe “privilege::debug” “sekurlsa::tickets /export” “exit”）
```

（见上面的 ATA 手册。）

![](upload/attach/202002/505507\_PUAJJBWZQ9VZPJ2.jpg)

我们首先连接到 ADMIN$ 共享（标记 1）（指向 `C:\Windows`），然后复制 `PSEXESVC.exe` 文件（标记 2）。这是一个最终将作为临时服务在目标机器上运行的可执行文件。

然后，我们连接到 IPC$ 共享（标记 3）（注意，我们不需要为此产生另一个会话设置）。由于 Wireshark 在本文编写时还无法解析 PSEXESVC（跟 ATSVC 和 SAMR 一样不过是另一个服务），我们看到原始的 ioctl 请求 `FSCTL_PIPE_TRANSCEIVE`（标记 4），而不是被解码成特定于服务的命令。

然后，我们打开（或更准确地说，<a href="elink@f86K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6E0M7$3c8F1i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3I4A6j5Y4u0S2M7Y4W2Q4x3V1k6U0j5K6t1K6x3U0p5J5y4W2)9J5k6h3q4K6M7s2R3`.">`FSCTL_PIPE_WAIT` 请求</a>）服务的 stdin（标记 5）、stdout（标记 6）和 stderr（标记 7），然后从 stdout（标记 8）开始读取实际的文件。

从版本 2.1 开始，PsExec 会加密本地和远程机器之间的所有通信，所以我们无法从这个 PCAP 中获得更多的信息。

# 横向移动技术

到目前为止，我们已经看到了一些运行在 SMB 上的潜在恶意行为的个别例子，但是我们还没有任何关于攻击者如何跨越网络的大局观。

当然，关于这个存在一些潜在策略，但是我想关注的一个相对常见的技术，既易于执行又相对难于检测。由于 Windows 为登录的用户在内存中存储了一些凭据（Kerberos 票据或 NTLM 哈希），攻击者有时可以通过获取本地管理员的身份，从存储器中转储 Kerberos 票据或 NTLM 哈希来获取更有价值的凭据，然后模拟用户移动到他们有权访问的另一台机器。然后这个过程可以在另一台机器上不断重复执行。

这只需要 `mimikatz` 和合法的 Windows 工具，所以防护者必须知道正确的机器/用户对和正确的访问控制。SMB 分析可从多个方面起到帮助。

首先，检查 SMB 的异常认证可以在不好的事情发生时给我们一个提示。如果我们的网络使用 Kerberos，但是我们在两台机器之间看到一个 NTLM 认证，那么肯定有谁在搞事情！

其次，像上面这样的技术经常需要大量的侦察，因为攻击者必须知道哪些用户具有什么权限以及谁登录了什么机器。攻击者有时可能会在尝试了解这些信息时制造噪声（尽管枚举工具的确有一些合法的用途），并且看到与用户权限、组成员身份或活动会话相关的异常 RPC 调用有时表示目标已被攻陷。（<a href="elink@c27K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6%4N6%4N6Q4x3X3g2K6K9i4S2V1N6h3u0Q4x3X3g2F1k6i4c8Q4x3V1k6Q4x3@1k6H3i4K6y4p5y4e0V1I4">这里</a>是关于横向移动技术的优秀讨论。）

一个好的攻击者几乎可以静悄悄地在你的网络上移动，甚至当你以 SMB 知识武装自己后，他们有时也能逃避检测。

Windows Management Instrumentation（WMI）和 PowerShell 远程处理是两种可以避免使用 SMB 的技术，且可以执行我们之前讨论过的一些相同的功能。（WMI 可以使用基于 TCP 的 RPC，并且可以通过基于 HTTP 的 Windows 远程管理（WinRM）运行 PowerShell 远程处理。有关 PowerShell 远程处理的更多详细信息，请参阅<a href="elink@5b8K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6@1k6h3y4Z5L8X3g2@1i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3I4A6j5Y4u0S2M7Y4W2Q4x3V1k6X3k6U0M7H3x3o6t1J5y4#2)9J5k6h3q4K6M7s2R3`.">这里</a>。）

我们在这篇文章中没有看到任何一个指标表明恶意行为本身，但是与任何协议一样，对于正常的 SMB 流量在您的网络中看起来是什么样的较好理解，对于发现可能与攻击者有关的异常行为是至关重要的。

我希望这个指南会成为一个有用的介绍，然后你可以使用你在这里学到的一些工具来在你的网络中开始发动追捕。（<a href="elink@2f8K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6h3S2S2M7X3#2B7x3s2W2Q4x3X3g2F1k6i4c8Q4x3V1k6T1L8r3!0Y4i4K6u0r3"><mark class="encrypted">9abK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6h3S2S2M7X3#2B7x3s2W2Q4x3X3g2F1k6i4c8Q4x3V1k6T1L8r3!0Y4i4K6u0r3</mark></a>是开始扩展 Active Directory 攻击技术知识的绝佳资源，<a href="elink@89bK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8X3q4V1M7$3g2U0N6i4u0A6N6s2W2Q4x3X3g2G2M7X3N6Q4x3V1j5`."><mark class="encrypted">2c4K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8X3q4V1M7$3g2U0N6i4u0A6N6s2W2Q4x3X3g2G2M7X3N6Q4x3V1j5`.</mark></a>是另一个很好的来源。）
