
### MSGetInstructionWithThumb

调用`used += MSGetInstructionWithThumb(reinterpret_cast<uint8_t *>(area) + used);`

`MSGetInstructionWithThumb`的参数为`uint16_t*`。

返回结果：这条指令占用多少字节（`4`或`2`）。

`T$32bit$i`的作用：

`(指令(ic) & 1110 0000 0000 0000) && (ic & 0001 1000 0000 0000 != 0x0000)`

第一个判断用于确定高位的3个bit（即`bit[15]`、`bit[14]`、`bit[13]`）为1。第二个判断用于确保`bit[12]`、`bit[11]`有值（即至少这两位中有1位为1）。

其实就是判断该`thumb`指令是否为`thumb32`指令。

`thumb32`指令的判断依据是`b[15:11]`为`0b11101`、`0b11110`或`0b11111`。

`MSGetInstructionWithThumb`：

```cpp
static size_t MSGetInstructionWidthThumb(void *start) {
    uint16_t *thumb(reinterpret_cast<uint16_t *>(start));   //

    return T$32bit$i(thumb[0]) ? 4 : 2;
}
```

`T$32bit$i`：

```cpp
static inline bool T$32bit$i(uint16_t ic) {
    return ((ic & 0xe000) == 0xe000 && (ic & 0x1800) != 0x0000);
}
```

### 分析`MemHelper`类

有4个方法：

1. `static bool isFunctionAddr(void* addr);`
2. `static bool unProtectMemory(void* addr, uint32_t size);`：移除写保护。
3. `static bool protectMemory(void* addr, uint32_t size);`：添加写保护。
4. `static void* createExecMemory(uint32_t size);`：创建一块可执行内存。

有4个field：

1. `std::vector<void*> all_memory_page;`
2. `void* current_page = nullptr;`
3. `uint32_t page_ptr = 0;`
4. `static uint32_t page_size;`：构造函数中执行`page_size = sysconf(_SC_PAGESIZE);`。

我们现在分析一下`createExecMemory(uint32_t size)`：

1. 可以看到，分配内存的操作是通过`mmap`实现的。
2. `all_memory_page`是一个`vector`，每个单位保存一个指针，指向`mmap`分配的内存。

`createExecMemory`：

```cpp
void *FAHook::MemHelper::createExecMemory(uint32_t size) {
    if(size & 1) {
        size++;
    }

    if(size > page_size) {
        return nullptr;
    }

    if(gMemHelper.current_page != nullptr && page_size - gMemHelper.page_ptr_ >= size) {
        auto funPtr = (void*)((size_t)gMemHelper.current_page + gMemHelper.page_ptr_);

        gMemHelper.page_ptr_ += size;

        // Align 4
        while(gMemHelper.page_ptr_ & 0x3) {
            gMemHelper.page_ptr_++;
        }

        return funPtr;
    }

    // scroll to next page
    auto newPage = mmap(nullptr, page_size, PROT_READ | PROT_WRITE | PROT_EXEC, MAP_ANONYMOUS | MAP_PRIVATE, 0, 0);

    if(newPage != MAP_FAILED) {
        gMemHelper.alloc_memory_page_.push_back(newPage);

        gMemHelper.current_page = newPage;
        gMemHelper.page_ptr_ = 0;

        return createExecMemory(size);
    }

    return nullptr;
}
```

分析`enableJumpStub(info)`：

```cpp
bool FAHook::Instruction::enableJumpStub(FAHook::HookInfo *info) {
    auto origAddr = getOriginalAddr(info);
    auto len = info->getJumpStubLen();
    auto stubAddr = info->getJumpStubBack();

    return patchMemory(origAddr, stubAddr, len);
}
```

可以看到，在得到`origAddr`、`stubAddr`和`len`之后，我们会进入`patchMemory`函数。根据前面的分析，它会修改原函数入口指令的前（`8`或`10`？）个字节。

`patchMemory`：

```cpp
bool FAHook::Instruction::patchMemory(void *dest, void *src, uint32_t len) {
    if(dest == nullptr || src == nullptr || len == 0) {
        return false;
    }

    if(!MemHelper::unProtectMemory(dest, len)) {
        return false;
    }

    memcpy(dest, src, len);
    MemHelper::protectMemory(dest, len);

#ifdef __arm__
    cacheflush((Elf_Addr)dest, (Elf_Addr)dest + len, 0);
#endif

    return true;
}
```

首先会调用`unProtectMemory`函数，将对应内存修改为`rwx`；然后调用`memcpy`来修改内存；最后调用`protectMemory`，将对应内存修改为`r-x`。

## 总结

现在我们就基本对该项目进行了简单的分析，下面总结一下：

1. `registerHook`

   主要操作其实就是：

   - `createStub`：创建代理。这个代理用于跳转到我们的`newFuncAddr`函数。
   - `createCallOriginalStub`：创建`callback`代理。这个代理用于执行回调，回调我们的`originalFunAddr`。该过程主要涉及处理与`pc`相关的指令，原因在文中已经有介绍。

2. `doInHook`

   - 主要就是`patchMemory`：将`originalFunAddr`函数起始处的几个指令修改为`stubInstruction`。之后会涉及与`pc`相关指令的修复，以便继续执行原函数。

3. `unHook`

   - 同样是`patchMemory`，用于将原函数的原始指令复原。
