
# [原创]页表项（PTE）地址计算公式的解释

在[《JIURL玩玩Win2k内存篇 分页机制（三）》](https://bbs.kanxue.com/elink@e6bK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6h3c8J5K9i4k6W2M7X3c8W2N6X3g2D9L8%4m8Q4x3X3g2U0L8$3#2Q4x3V1k6S2M7Y4c8A6j5$3I4W2i4K6u0r3K9X3W2#2M7X3I4Q4y4h3k6y4L8g2m8S2k6$3W2F1k6K6y4Q4x3X3g2Z5N6r3@1`.)中提到计算虚拟地址对应 PTE 地址的公式，如下：

```text
PTE_Addr = (VirtualAddr >> 12) * 4 + 0xC0000000
```

从虚拟地址转换到物理地址的过程来看，计算 PTE 需要虚拟地址的高 10 位做页目录索引，还需要第 12～21 位做页表索引。上面的公式乍看貌似是错的，但是偏偏它又是对的，为什么呢？

其实很简单，因为 1024 个页表被映射在 `0xC0000000`～`0xC03FFFFF` 地址中。暂且不理会页目录被映射到哪里，只要知道页目录里的 1024 个页目录项分别指向 `0xC0000000`～`0xC03FFFFF` 地址中的 1024 个页表就行了（其实这是因为页目录和一个页表完全重合的原因，见[《JIURL玩玩Win2k内存篇 分页机制（四）》](https://bbs.kanxue.com/elink@6cdK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6h3c8J5K9i4k6W2M7X3c8W2N6X3g2D9L8%4m8Q4x3X3g2U0L8$3#2Q4x3V1k6S2M7Y4c8A6j5$3I4W2i4K6u0r3K9X3W2#2M7X3I4Q4y4h3k6y4L8g2m8S2k6$3W2F1k6K6y4Q4x3X3g2Z5N6r3@1`.)）。这样就可以得到一个关系：页目录索引 `n` 指向的页表就等于 `0xC0000000 + n * 页表大小`。一个页表的大小是 `1024 * 4 = 4096 = 2` 的 12 次方。得到了页表，再加上页表索引就可以得到页表项（PTE）的地址了。用公式表示就是如下：

```text
// 为了缩短表达式，用 VA 表示虚拟地址

//           页目录索引                  页表索引

PTE_Addr = ((VA & 0xffc00000) >> 22) * 4096
         + ((VA & 0x3ff000) >> 12) * 4
         + 0xc0000000

         = (((VA & 0xffc00000) >> 22) << 12)
         + (((VA & 0x3ff000) >> 12) << 2)
         + 0xc0000000

         = ((VA & 0xffc00000) >> 10)
         + ((VA & 0x3ff000) >> 10)
         + 0xc0000000

         = ((VA & 0xffc00000) + (VA & 0x3ff000) >> 10)
         + 0xc0000000

         = ((VA & (0xffc00000 | 0x3ff000)) >> 10)
         + 0xc0000000

         = ((VA & 0xfffff000) >> 10)
         + 0xc0000000

         = (((VA & 0xfffff000) >> 12) << 2)
         + 0xc0000000

         = ((VA & 0xfffff000) >> 12) * 4
         + 0xc0000000
```

由于 `VA` 的低位被清零，所以上面的移位操作化简是成立的。最后一个表达式已经很明显了，`VA & 0xfffff000` 完全是多余的，因为始终要 `>> 12`，所以最终公式就是：

```text
PTE_Addr = (VirtualAddr >> 12) * 4 + 0xC0000000
```

`combojiang` 兄在[《透过MmIsAddressValid看Windows分页机制》](http://bbs.pediy.com/showthread.php?t=61327)中也提到 PTE 的计算公式，如下：

```text
PTE = ((VA >> 12) << 2) & 0x3FFFC + 0xc0000000；
```

估计 `combojiang` 兄深夜发帖，意识模糊 :-)，少写了个 `F`，误导了不少群众，还没人指出。正确的应该是：

```text
PTE = ((VA >> 12) << 2) & 0x3FFFFC + 0xc0000000；
```

这里的 `& 0x3FFFFC` 也是不必要的。`& 0x3FFFFC` 只是将低 2 位清零，而 `<< 2` 后低 2 位本来就是 0，所以等价于：

```text
PTE = (VA >> 12) * 4 + 0xc0000000；
```

上面说的都是在 32 位 x86 非 PAE 的情况下，PAE 情况下略有不同，有时间再整理。
