# [原创] 某Android模拟器的广告植入分析

这是一个做的还不错的模拟器，不过它的广告让人很烦，考虑先分析看看。
# 初步分析dnplayer.exe
## 1， 反调试：
它是带反调试的，使用x64dbg启动，会直接带调试器一起退出，添加了两项后，可以继续：
1. SharpOD : anti\_anti\_debug
2. x64dbg : 获取调试权限
## 2，静态分：
在启动的时候，会出现异常：

![图片描述](upload/attach/202004/587311\_ZEZY76F2NCVRHE9.png)
定位到上面的代码，并且发现它在加载文件launchConfig.data，打开看看内容：
![图片描述](upload/attach/202004/587311\_B3CRZTQGYADY6VH.png)
看上去是去远端获取游戏资源的配置项（连接可以加载打开看）。
先把这部分bypass后再看看功能，发现启动还是有广告。
```

+--->show\_root\_window\_sub\_4D1930(\_\_m128i \*this) ## 初始化函数，不能去掉
+--->sub\_448D30()
+---> sub\_449010()
```
查看网络数据信息：
![图片描述](upload/attach/202004/587311\_JYE2JMVZAEWR3QV.png)

![图片描述](upload/attach/202004/587311\_TAWUZFBTSMHRA97.png)
HTTP相关的调用操作：
```

```
因为测试show\_root\_window\_sub\_4D1930函数不能被bypass，但是它是主要的加载位置，而且广告也是在它内部加载的，所以考虑从它内部进行分析.

从请求数据可以发现它进行了很多远端操作，包括统计信息发送，版本检测等等，需要把这些全干掉；从API监控分析：
