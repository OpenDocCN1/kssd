# 初次发帖，实例示范脱壳常用工具使用

注册也有一段时间了，一直临时会员着，不久前通过分析论坛一个坛友写写的挂机客户端这才又涨了十几KX，凑够了50。这里先感谢一下这位坛友，下面的实例示范其实就是这位坛友的工具，希望这位坛友不要生气，因此示例程序就不发了，可在临时版块自行寻找到。
那么废话少说，进入正题。
首先用pEid查一下，发现是ACP1.0x（图1）
 ![](https://bbs.kanxue.com/upload/attach/201306/546812_vey5wu6w3pnnu4o.jpg)

这个壳不会修改原始的节段，只是增加一个壳段，这里的”终极保镖”
Lord\_PE查看区段（图2）:
![](https://bbs.kanxue.com/upload/attach/201306/546812_a13imw6ntvfw66h.jpg)

就是添加的段了。
OD载入后看一下Memory map（图3）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_able2chpl09itih.jpg)
 在观察一下数据窗口（图4）：

结合上面图3和图4，我们有理由猜测这里就是IAT，直接F9跑跑看（图5）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_99y4ofibxqnsgy4.jpg)
确实是的。
那么重新载入OD，利用两次断点走到OEP，DUMP重建看是否可以了。
首先在rdata段下断点（图6）：
 ![](https://bbs.kanxue.com/upload/attach/201306/546812_mngodaykk9o4ecv.jpg)

![](https://bbs.kanxue.com/upload/attach/201306/546812_jq9b45faqkslkts.jpg)

![](https://bbs.kanxue.com/upload/attach/201306/546812_4rzcf5oj1vxnfaj.jpg)

看起来很标准的VC程序头部，
此时DUMP然后用import REC重建（图9）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_wd3a7sorukqq0cs.jpg)

发现一个问号，展开之后发现有一处未填充（图10）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_7ka8a95mpzwitc2.jpg)

偏移773e4处指向的这个地址是壳段，看来是对某个函数做了特殊处理，
那我们跟一下它是如何填充这个壳段地址的，重载然后在004773e0下
内存访问断点（就是处理偏移773e4的上一处），F9断下（图11）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_nhthbkamg6n4fxu.jpg)

这里应该就是填充IAT的代码了，那就F8单步看一下吧，因为马上要处理的就是
偏移773e4处这个特殊的函数了，跟了几步便有了如下发现（图12）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_clwpjfjh021swjj.jpg)

每次取得函数地址后，会做一次比较：
004D37C7   CMP EAX,DWORD PTR SS:[EBP+406E98]        ;USER32.MessageBoxA
看是不是USER32.MessageBoxA，如果是则跳到
004D37D3   LEA EAX,DWORD PTR SS:[EBP+402123];正是之前import REC得到的值，
这样得知是MessageBoxA这个函数我们便自己处理一下（直接import REC手动修改）
然后用LordPE DUMP内存映像（当然直接OD也可以DUMP也可以）（图13）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_0b6xgngm53ccq3n.jpg)

用import REC导入IAT，这个时候就可以了，用PEID看一下，已经
能识别了，也能正常运行（图14）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_clkv4vrdw6qulkx.jpg)
用LordPE看一下（图15）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_04i70fqjbbs6lol.jpg)

通过分析发现它可能存在着完整的IID，于是想到我们可以不借助import REC便完成脱壳，
重新载入OD，我们需要断在它访问第一个IID的地方，这个例子方法很多，这里我们直接在rdata下断点，断下的地方其实就是了（图16）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_ly53huq4o3xyj7h.jpg)
004D36F7    8B46 0C         MOV EAX,DWORD PTR DS:[ESI+C]
此处ESI便是第一个IID的VA，去看看（图17）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_ohiq3cdkp164yz6.jpg)
好了，就是这里F8跟一下发现：
004D3702    C746 0C 0000000>MOV DWORD PTR DS:[ESI+C],0
此处会将模块名称RVA填0，为了保持IID的完整，需要NOP掉它。
重新断到OEP然后DUMP，之后用LordPE打开修改入口点和IID（图18）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_4wn68x63vmlyah6.jpg)
这样就可以了，可此时壳段还在。
直接去掉壳段是否可行，要看是否还有依赖壳段的地方。这个壳有一些资源在壳段
，那么要去掉壳段必须重建资源（图19）。
![](https://bbs.kanxue.com/upload/attach/201306/546812_no2pmt4bpg6gpt4.jpg)
下面用DT FixResource提取资源段（图20）：
 ![](https://bbs.kanxue.com/upload/attach/201306/546812_o8k2mc5b3jg894y.jpg)
用PE Tools将壳段和资源段填0（直接清空可能导致错误）（图21）：
 ![](https://bbs.kanxue.com/upload/attach/201306/546812_rtpqvchtigqva19.jpg)



最后用LordPE清除壳段和资源段并载入之前提取的资源段并重建使PE有效（图22）：
![](https://bbs.kanxue.com/upload/attach/201306/546812_8t3mdfrdmegbrle.jpg)

这样 便去掉壳段了。这个壳几乎没什么强度可言，这里主要演示了几种常用工具的使用。
