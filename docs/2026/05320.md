# [原创]DXF公告Call分析

既然要分析公告Call，肯定是要找到某个插入点的。
![](upload/attach/202009/587180\_6UPP5TBK6KUQTT8.jpg)
公告嘛那肯定是从公告的内容入手的，但是存着内容的地址，发完它就释放了，所以嘛我就找到了技能冷却的提示公告。那玩会儿固定一个模板“技能冷却时间还剩xxxx”。我感觉就是sprintf(str,"技能冷却时间还剩%.\*f秒",time);不对别喷我。
那就用ce搜
![](upload/attach/202009/587180\_FSANV55VN8ADVB6.png)
它这不就出来了，记住地址，打开x64dbg，给它整个访问断点
![图片描述](upload/attach/202009/587180\_TX49CD8XH8WHCEY.png)
断下了猜一猜就完事了，别整那些没用的分析。这里访问了模板,然后再取冷却时间,然后步过某个call肯定就合一块了。F8就完事.
经过了一堆循环(八成再算冷却时间)，来到了这里
![图片描述](upload/attach/202009/587180\_XUP3TNGCWXD72T9.png)
再往下走就返回了，上面刚循环完，走了这个call，然后把值给ebx。看看ebx
![图片描述](upload/attach/202009/587180\_DM8J8WG2D9MRHTB.png)
没茅台。然后就取到了公告call的公告内容，给它整个访问断点
![图片描述](upload/attach/202009/587180\_P75AGSY5XM498VN.png)
oj8k。这里就是公告call了。
![](upload/attach/202009/587180\_6UPP5TBK6KUQTT8.jpg)
众所周知，公告call前面能带个图标，而我就喜欢花里胡哨，所以安排
![图片描述](upload/attach/202009/587180\_T6GTQBSDFAYS2KJ.png)
就从这个公会公告入手。call头部下个断返回上一层。
![图片描述](upload/attach/202009/587180\_W2W62KS2G7Z74QN.png)
众所周知fastcall 传参顺序是 rcx rdx r8 r9。那咱重点看这几个寄存器就完事了
rcx来源rax,rax来源于上面call里的[rcx+a0],而rcx来源于全局变量的值
![图片描述](upload/attach/202009/587180\_W9NY5PJCSA36E7M.png)
所以rcx = [[基址]+A0]
再看rdx,rdx来源 ebp的值
往上嫖了一眼，发现上面还有句lea rcx,[ebp],然后再执行了个call
进去看看
![图片描述](upload/attach/202009/587180\_B8HUR36GDYWDCX9.png)
那就懂了。下面留给你们自个儿分析奥
