
# [翻译] 加固微软 Edge 沙盒

在一个近期的帖子中，我们简要地描述了微软 Edge 安全小组使用的一个分层策略，用来保护你的可能使你的设备或者个人数据陷入危险的弱点。特别是我们展示了微软 Edge 如何利用像代码完整性保护（CIG）和任意代码保护（ACG）来打败利用漏洞来获得远程代码执行时黑客所依赖的一些技术。这就是攻击者在浏览器中寻找从 web 代码中逃走的地方（JS 和 HTML），来执行攻击者选择的原生 CPU 指令。这使攻击者破坏所有浏览器对于 web 所设的规则，例如同源策略，所以尽最大努力来阻止 RCE 攻击对于 web 使用者来说非常重要。

然而，尽管我们做好了最好的努力，有些时候攻击者还是执行了 RCE，在这个帖子中，我们将研究一些我们在 Windows 10 Creators Update 中的重大改进来加固我们下一道防线：微软 Edge 沙盒。

## 微软 Edge 沙盒的历史

因为 RCE 能够发生，在过去也经常发生，浏览器制造商们寻求将浏览器置入沙盒中来保护其余用户的个人电脑免受攻击。在 2007 年，IE7 引入了 [Protected Mode](https://bbs.kanxue.com/elink@600K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6E0M7$3c8F1i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3I4A6j5Y4u0S2M7Y4W2Q4x3V1k6T1j5U0t1#2x3o6b7$3x3W2)9J5z5s2k6Q4x3@1c8$3M7#2)9J5k6e0R3#2i4K6t1&6i4K6u0W2j5i4y4H3P5l9`.`.)，每一个 web 浏览器沙盒。Windows 8 向操作系统中加入了 [app container](https://bbs.kanxue.com/elink@68fK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6E0M7$3c8F1i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3I4A6j5Y4u0S2M7Y4W2Q4x3V1k6%4K9h3&6V1L8%4N6K6i4K6u0r3k6r3g2K6K9%4c8G2M7q4)9J5c8X3#2@1y4e0V1#2z5o6V1^5i4K6t1^5N6W2)9K6c8s2k6K6i4K6u0W2z5o6g2Q4x3U0W2Q4x3X3g2S2M7%4m8^5) ，主要用来支持新的 Windows 商店应用程序模型和支持 [confidence promise](https://bbs.kanxue.com/elink@a0cK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6T1L8r3!0Y4M7#2)9J5k6h3#2K6k6r3&6Q4x3X3g2E0K9h3y4J5L8%4y4G2k6Y4c8Q4x3X3g2U0L8$3#2Q4x3V1k6T1z5q4)9J5c8U0t1H3x3e0u0Q4x3V1j5H3y4g2)9J5c8U0p5%4i4K6u0r3k6r3g2D9K9i4k6W2M7X3W2F1k6#2)9J5k6s2u0W2L8r3W2S2j5X3I4W2i4K6u0V1j5h3&6V1i4K6u0V1N6s2u0#2M7%4c8%4L8%4u0@1K9s2W2Q4x3X3c8E0k6i4c8J5L8#2)9J5k6s2y4@1P5h3I4W2i4K6u0V1j5i4m8H3M7#2)9J5c8R3`.`.) 使应用程序可以被安全使用。IE10 和 IE11 使用了 app container 来创建 [EPM（加强的受保护模式）](https://bbs.kanxue.com/elink@c00K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6T1L8r3!0Y4M7#2)9J5k6h3#2K6k6r3&6Q4x3X3g2E0K9h3y4J5L8%4y4G2k6Y4c8Q4x3X3g2U0L8$3#2Q4x3V1k6A6k6h3W2F1N6r3g2J5L8X3q4D9M7#2)9J5c8U0t1H3x3e0u0Q4x3V1j5H3x3#2)9J5c8U0t1K6i4K6u0r3N6h3&6V1k6i4u0K6N6r3q4F1k6r3W2F1k6#2)9J5k6r3g2F1K9r3q4F1j5$3g2V1i4K6u0V1M7s2u0G2N6r3g2U0N6r3g2V1i4K6u0V1L8h3!0V1k6g2)9J5c8R3`.`.)，一个更强壮的浏览器沙盒。然而，EPM 沙盒限制与在 app container 之前的较老的 ActiveX 控件不兼容，所以 EPM 是作为一个安全加强选项来提供给用户的。

微软 Edge 不支持 ActiveX，所以它不能够在所有的时间里在 app container 沙盒中一直保持完整的运行。因为开始的时候，微软 Edge 使用了一些 app containers。最开始有一个对于 Manager 来说有一个 parent app container，它创建了一小部分额外的 app containers 来容纳来自从 intranet 内容中分离出来的 internet 的内容。[Windows 10 Anniversary Update](https://bbs.kanxue.com/elink@e1cK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6%4N6%4N6Q4x3X3g2E0K9h3y4J5L8%4y4G2k6Y4c8Q4x3X3g2U0L8$3#2Q4x3V1k6W2L8W2)9J5k6q4g2e0i4K6u0r3N6$3W2F1k6r3!0%4M7#2)9J5c8X3k6W2j5i4c8#2M7X3g2K6) 将 Flash 加入到它自身当中单分出来一个 app container。如今的微软 Edge app container 模型看起来是这样的：

![](https://bbs.kanxue.com/upload/attach/201705/1294_31g9cmk81w2clx7.png)

Manager 提供了浏览器特性——如 URL 条，返回按钮，标签，和你的收藏列表。其余的 app container 是：

- **Internet AC**：容纳来自 Internet 的内容。
- **Intranet AC**：容纳来自 Intranet 的内容。对于企业用户来说，那是企业网。对于消费者来说，那是“网站”，即你家庭网络中设备的控制接口，比如说你的 Wi-Fi 路由器，或者 IoT 设备。将这个 AC 与 Internet 分离，比如将你的家庭 WiFi 路由器与 Internet 上的攻击者分离开。
- **Extensions AC**：为微软 Edge 新的扩展。
- **Flash AC**：容纳 Adobe Flash player，将它与主要的内容进程分离。
- **Service UI AC**：容纳特殊的网页，比如 `about:` 标记和默认主页。

Internet AC 是行动的场所。它的工作是容纳来自任何地方的网页，包含网页提供的 JS 代码、图像和多媒体。容纳网页是相当复杂的，因为当今网页的丰富性。这是 Internet 的平台，开发者要能够创建任何程序并在这个环境中运行它。因为它很复杂，并要容纳来自任何地方的网页，所以这是网络安全攻击开始的地方。一个恶意网站展示内容，企图利用内容容纳系统中的漏洞，接管内容处理控制权。

如果一个攻击者攻破了一个 Internet AC 的进程，他们需要找到一些方法来实现他们的目的。如果他们的目标涉及到危害用户的设备或是储存设备上的个人数据，然后他们将会首先想要逃出沙盒。

## 减少微软 Edge 沙盒的攻击表面

在复杂的程序中，消除漏洞最有效的方法之一是减少一个攻击者能够在其中尝试寻找漏洞的代码量。这常被指为减少攻击表面，并且它是我们整个安全策略中的一个关键策略。在这一点上，微软 Edge 在 Windows 10 的 Creators Update 中已经通过配置 app container 进一步降低它的特权来大幅减少沙盒的攻击表面。

为了调整微软 Edge AC，我们首先需要知道 app container 本身是如何工作的。一个 app container 进程对于任意受保护的安全对象是默认拒绝访问的，除非对象的安全描述符有一个允许访问控制入口 (ACE)，该入口将会允许 app container 具有访问权限。共有 3 种 SIDs 可以在这样的 ACEs 中使用：

- **Capabilities**：如果一个 Capability SID 基于 allow ACE 在安全描述符中，并且请求 AC 在它的 token 中具有那个 Capability SID，那么它获得了访问权限。比如：Web-Cam 相关的设备对于具有 WEBCAM Capability SID 的进程来说是可以访问的，比如说微软 Edge。
- **AppID SIDs**：如果一个具体的 AppID SID 基于 allow ACE 在安全描述符中，并且请求 AC 是那个具体的 AppID，然后它就获得了访问权。其主要用途是每个 app 的存储：在安全描述符中使用该 app 的 AppID，确保它的存储对于那个 app 是私有的。
- **“ALL APPLICATION PACKAGES” (“AC” SID)**：这是 AC 外卡，允许所有的 app containers 访问资源。“AC” SID 存在，所以 Windows 能够提供一个对于开发者很有用的 app 平台，允许丰富的 UWPs 在 Windows 商店里。比如，大部分的 [WinRT API surface](https://bbs.kanxue.com/elink@ba2K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4g2%4M7q4)9J5c8X3q4H3K9g2)9J5c8R3`.`.) 对 “AC” SID 是开放的，所以所有的 UWP app 都能访问 WinRT APIs。

微软 Edge AC 只在一种方式中变得不同了：the “AC” SID 不足以使一个请求进程访问一个资源，为了获得访问权限，AC 必须要么拥有一个对应的 Capability SID，要么就是安全描述符中的一个已命名的 AppIDs。

这样 AC 失去了访问整个 WinRT API 组的访问权限和 app containers 正常能够访问的其它每一个资源。这对于安全来说是极好的，但是，它将打破关于浏览器的一切东西，把浏览器变成了一个高度安全的砖块。

“Normal” app container ![](https://winblogs.azureedge.net/win/2017/03/normal-AC-204x300.png)  Microsoft Edge “Tuned” AC ![](https://winblogs.azureedge.net/win/2017/03/tuned-AC-205x300.png)

所以为了使微软 Edge 再次工作，我们使用 Capabilities 来点亮具体的功能区域。比如，我们创建一个 Capability 能够使 COM 正常工作。我们同样增加了其它的 capabilities，对访问具体的资源进行授权，直到微软 Edge 再次工作为止。然后我们增加了一些对于内容处理检测访问控制失败的遥测手段，并将它共享给 Windows Insider Program (WIP) 来确保我们给所有场景所需的资源均进行了授权。

我们刚刚做的是为微软 Edge 创建一个调谐的沙盒，这个沙盒与一个正常的应用程序容器所提供的功能相比更加符合软件的功能需要。这是很大量的工作，也这是为什么这不是 UWP 平台如何工作的原因。但是因为 web 浏览器是最受威胁的软件之一，在这种情况下所有的工作都是值得的。

我们为 Flash AC 重复这一手动调谐的工作，因为它也是一系列攻击的目标，把 Flash 放进一个牢固的沙盒中补充了本次放出的工作，使 Flash 即点即得。

## 对攻击者的影响

使微软 Edge 内容处理运行在这个牢固的沙盒中减少了沙盒的攻击表面，但是减少了多少？结果是减少了很多。

- 100% 减少了 MUTEXes 访问：允许一个程序锁定一个资源，产生挂起。
- 90% 减少了对 WinRT 和 DCOM API 的访问：这是一个很大的胜利，极大的减少了微软 Edge 的针对于 WinRT API 组的攻击表面。
- 70% 减少了访问事件和 symlinks 的访问：symlinks 很有趣，因为它们经常被用在创建诱饵和切换攻击来逃出沙盒。
- 40% 减少了对设备的访问：Windows 支持很多设备驱动，它们的质量有时超出了微软的控制。调谐过的沙盒切断了访问任何沙盒明确不需要使用的设备的道路，阻止攻击者使用设备驱动的漏洞来逃逸或滥用设备。

但是攻击表面减少并不保证攻击都不能逃出沙盒。它只是很大程度上减少了攻击发生的可能性。就像减少了堡垒的门和窗。另外，额外对于微软 Edge 正常能够访问的代理的挖掘缓和的使能同样增加了利用残余漏洞的难度。

## 结论

安全是一个过程，不是目的，所以我们继续为微软 Edge 在 RCE 和沙盒缓和上进行投入。这些利用缓和联合加固的沙盒将会使 Microsoft Edge 的攻击者付出更多的努力来利用，在第一步就对攻击都产生阻碍。
