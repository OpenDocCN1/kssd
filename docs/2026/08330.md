
# [原创]对目前开源OLLVM的跳转加密混淆学习笔记

## Hikari的indirectBr

为每个`condition BR`生成一个`[2 x i8*]`的`BrTable`存放2个`BasicBlock`的`Label`符号。

将`condition BR`替换成通过`gep`用`cmp`的结果来取`BrTable`的跳转目标`Label`符号。

然后调用`indirectbr`指令进行跳转。

如果是非`condition BR`，则生成`GlobalTable`存放所有的`BR`目标`Label`符号。

将`BR`指令替换成通过`gep`用`index`取`GlobalTable`存放的目标`Label`符号。

然后调用`indirectbr`指令进行跳转。

测试：

对于非`condition BR`，最终指令为连续的 `mov eax, [TableN] + jmp eax`。

对于`condition BR`，最终指令为连续的 `mov eax, [TableX + ecx * 8] + jmp eax`。

因为`BR`的两个分支`Label`分别以明文存储在`BrTable`中，这样保护强度很有限。

---

## Goron的indirectBr

基本与`Hikari`一致，主要区别是生成的`BrTable`中存放的是`gep Label`符号 + 随机数索引。

这样最终编译出来的`BrTable`中不是明文的`Label`地址，使用的时候读出来再用`Key`解密得到`Label`，对于加密强度有很大提升。而且对于解密的`Key`，分成了两个数，其中一个数通过`store`指令存储在函数的局部变量中，另一个通过`sub`指令进行运算。这样最终编译出来之后的指令为：

```
mov [esp+n], key1
mov ebx, [esp+n]
...FunctionCode
mov eax, [TableX+ecx*8]
mov edx, key2
sub edx, ebx
add eax, edx
jmp eax
```
