## 硬件断点

下图的红框位置就是调试寄存器组`Dr0~Dr7`，`Dr0`,`Dr1`,`Dr2`,`Dr3`是用于设置硬件断点的,由于只有4个硬件断点寄存器,所以同时最多只能设置4个硬件断点。它产生的异常是单步异常。

这里不对原理做过多介绍，详细知识请参考《加密与解密》第二章2.1.4节

![图片描述](upload/attach/202006/803227_D4ZKP75YYBK335R.png)

## 通讯协议

这方面的知识可以看我以前的帖子，这里给上链接https://bbs.pediy.com/thread-252468.htm。

一般客户端的通讯协议常用的是`tcp`或者`udp`，他们对应的API：

协议 函数

`tcp` `send`

`udp` `sendto`

## 分析

版本信息

![图片描述](upload/attach/202006/803227_SWNNTRKWZPYZMFF.png)

1.寻找给`send`函数下断点，根据我以前的帖子可以知道`send`函数是在`ws2_32.dll`这个模块。

![图片描述](upload/attach/202006/803227_DTRPW8XSHQHZBC4.png)

所以我们在符号——>选中`ws2_32.dll`模块——>搜索`send`——>下断点。

![图片描述](upload/attach/202006/803227_YE2HFG2UZTBMGY2.png)

打开微信随意给一个人发信息，这个时候程序断下，由于这个属于系统模块，我们不做分析，直接`Ctrl+F9`运行到程序模块。

![图片描述](upload/attach/202006/803227_4J45URR5MMJJ63M.png)

接下来我们看下`send`函数，对我们有用的是第二个，所以这个参数我们需要着重关注。

```
int send(
SOCKET s,
const char FAR* buf,
int len,
int flags
);
```

通过分析后发现`buf`中是一个数值，这个数值是随着消息的不同而改变的。这里给该地址处下一个硬件写入断点。

![图片描述](upload/attach/202006/803227_9TKN27U8RZJPR6D.png)

运行程序后会在下图的位置断下。这个时候分析了好久的汇编，感觉收获不大，所以这个时候试着在堆栈中寻找信息。

![图片描述](upload/attach/202006/803227_GCC3PWQMEK8M2UG.png)

在堆栈中得到一个可疑信息，但是并没有发现发送的文本信息，所以我们试着分析该字符出现的函数处。

![图片描述](upload/attach/202006/803227_65KUC32A6M6CQDF.png)

我们在`wechatwin.dll`中进行字符串搜索寻找”`newsendmsg`“字符串，运气不错，这里只发现了一处代码。

![图片描述](upload/attach/202006/803227_KQ6XXWSJXF6R3DT.png)

在断点标签栏处，取消其他断点，然后重新发送信息，程序在下图处断下，通过分析后发现收益不大，继续通过观察堆栈查找信息。

![图片描述](upload/attach/202006/803227_2X9HTNUYBSR8T68.png)

在堆栈中发现了下图的关键信息。”`1234`“这个就是我们发送的信息。在该地址处下一个硬件写入断点。

![图片描述](upload/attach/202006/803227_VKSMQAFK5MH2BUQ.png)

重新发送信息后，程序在下图位置断下。这里的函数看着很难受，直接运行到返回处查看上一层代码。

![图片描述](upload/attach/202006/803227_HXTV8DZMREHYFB7.png)

下图就是上一层代码的调用处，这个函数也就是发送消息的函数了。

![图片描述](upload/attach/202006/803227_R4Q9JHFDXH9259H.png)

进去查看函数代码，这里我们发现代码似乎是加了混淆。

![图片描述](upload/attach/202006/803227_JTX8WY4X5239MJK.png)

查看区段果然有一个区段加了`VMP`。

![图片描述](upload/attach/202006/803227_WK86KS327CRXSUW.png)
