
# [原创]phobos勒索病毒样本分析

# 介绍

Phobos勒索家族于2019年初被发现，并不断更新病毒变种，通过RDP暴力破解+人工投放和钓鱼邮件等方式扩散到企业与个人用户中，感染数量持续增长。据说此勒索软件变种使用“RSA+AES”算法加密文件，暂时没有解密工具。

值得关注的是，该勒索病毒在运行过程中会进行自复制，并在注册表添加自启动项，如果没有清除系统中残留的病毒体，很可能会遭遇二次加密。

文件名：`Ransom.Win32.Phobos.exe`

MD5：f785b1a9a657aca7e70d16ac5effaabd

# 分析

## 自启动

先将敏感字符串解密出来。

使用`CopyFileW`将自身拷贝到`C:\User\administrator\Local\`目录下

成功后使用`RegOpenKeyEx`打开注册表中的`Software\Microsoft\Windows\CurrentVersion\Run`键值

将自身路径写入开机自启动项

![](upload/attach/202303/915331\_6NAVC79HJVV4U4E.png)

之后循环拷贝，将自身拷贝到各种系统关键目录下

![](upload/attach/202303/915331\_8AM5MF4TQ45HZ93.png)

## 关闭防火墙

先将关闭防火墙的命令解密出来。

![C:\Users\l0v3m1ng\AppData\Roaming\Typora\typora-user-images\image-20230306095934224.png](upload/attach/202303/915331\_W4ZVN4XYQAHTS63.png)

先创建新的线程，将之前解密的指令传入线程回调函数。

但是很奇怪的是，传入的时候`v2`还是之前的防火墙操作。

![](upload/attach/202303/915331\_SJ2FUJFQZ4H683F.png)

经过调试可以发现，这个回调函数在解密函数前也被调用，执行了以下命令。

![](upload/attach/202303/915331\_UW9D6N4PSFW3HXZ.png)

命令执行的流程是先创建通信管道，之后使用`CreateProcessW`打开了`cmd`进程，通过管道通信将命令写入`cmd`。

这样做估计是因为直接在`CreateProcessW`传入参数会被EDR记录，这样应该也是一种免杀手段。

![](upload/attach/202303/915331\_J83CTPW4UDWVAB6.png)

## 关闭指定进程

先将目标程序名解密出来

![](upload/attach/202303/915331\_P43CTXCJ7XJHX5R.png)

拍摄自身进程以及这些进程使用的堆、模块和线程的快照。

在快照中遍历进程，比较进程名与目标程序名。

比较成功则使用`OpenProcess`获得进程句柄，之后进行关闭操作。

![](upload/attach/202303/915331\_Q58K7GNGSFV9JF4.png)

## 文件加密

病毒先尝试打开磁盘，获取系统磁盘的序列号xxxxxxxx，为待加密文件生成特定后缀名。

之后搜索磁盘中的资源，文件名通过比较后进入加密函数。

![](upload/attach/202303/915331\_865TD34ZNGEE3EZ.png)

使用`CryptGenRandom`获得aes随机密钥用于加密。

使用`CreateFileW`打开目标文件，获取文件大小。

使用`SetFileAttributesW`去除文件只读属性。

对文件大小进行判断，对比较小的文件进行全加密，对大文件进行部分加密。

![](upload/attach/202303/915331\_Y9DVGZFTZFYF44D.png)

### 全加密

创建一个新文件，由目标文件名和加密后缀拼接。

![](upload/attach/202303/915331\_9XHR5AET79JDJBF.png)

使用`ReadFile`循环读取原文件内容，使用aes随机密钥进行cbc加密。

在完成加密后，还会拼接一段数据，可以看到其中有原文件名，aes密钥等信息，猜测为用于还原的信息。

之后对这段信息使用相同的密钥进行aes加密，写入新文件尾部。

最后删除原文件。

![](upload/attach/202303/915331\_RZ5YPC53SGA74CT.png)

### 部分加密

从原文件中截取三段内容，大小为0x40000字节，将三段内容和一些数据进行拼接，之后使用aes随机密钥进行加密，加密方式与全加密相同。

![](upload/attach/202303/915331\_DYAWAEV79VA5X2P.png)

# 分析中的问题

样本中有很大的代码都是关于互斥量和多线程的，因为没有什么这方面的经验，调试起来很费事。

在单步到`sleep`函数时，出现了用户账户控制（UAC）对话框，应该是触发了其他线程中的提权代码。

因为win32代码水平有限，可能在分析的过程中会漏掉了一些功能，之后会将其补上。
