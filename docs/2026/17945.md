
# [分享] CVE-2012-0158 两种 PoC 分析

## CVE-2012-0158

### 目录

1. 漏洞原理简介
2. 分别对两个 PoC 进行调试分析
3. 分析总结

**环境：** Windows XP SP3 Pro

**工具：** WinDbg（Dbg x86 6.11.1.404）、IDA、Office 2003（Standard）

**样本来源：**《漏洞战争》、看雪论坛

### 漏洞原理简介

> The (1) ListView, (2) ListView2, (3) TreeView, and (4) TreeView2 ActiveX controls in MSCOMCTL.OCX in the Common Controls in Microsoft Office 2003 SP3, 2007 SP2 and SP3, and 2010 Gold and SP1; Office 2003 Web Components SP3; SQL Server 2000 SP4, 2005 SP4, and 2008 SP2, SP3, and R2; BizTalk Server 2002 SP1; Commerce Server 2002 SP4, 2007 SP2, and 2009 Gold and R2; Visual FoxPro 8.0 SP1 and 9.0 SP2; and Visual Basic 6.0 Runtime allow remote attackers to execute arbitrary code via a crafted (a) web site, (b) Office document, or (c) .rtf file that triggers "system state" corruption, as exploited in the wild in April 2012, aka "MSCOMCTL.OCX RCE Vulnerability."

《NVD》：非常经典的栈溢出漏洞。

## PoC 分析一

此 PoC 来自《漏洞战争》。分析流程如下：

1. 分析 PoC 的行为。
2. 综合利用 WinDbg 和 IDA 进行动态和静态分析。

首先直接打开 WinDbg 和 `word.exe`，然后在 WinDbg 中使用快捷键 `F6` 附加 `word.exe`，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/72AYS3CHZMZUJPW.jpg)

如下图，当载入 `poc.doc` 时：

![](https://bbs.kanxue.com/upload/attach/201705/8SGZ4C2CZ4KGXAG.jpg)

在上图中，关键信息已经标注出来。当载入 `poc.exe` 时，最终在 `EIP = 41414141` 处断下。当利用 `kb` 命令查看堆栈时，发现堆栈已经被破坏。利用 `dps` 查看详细的栈信息。

![](https://bbs.kanxue.com/upload/attach/201705/R3FC5EAMJZJMKJB.jpg)

根据上图的栈信息，`0x127b30 = 41414141`，而 `0x127afc = 275c8a0a`。直接查看 `0x275c8a0a` 地址处的反汇编代码，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/VKJ4U5URAQVX8XS.jpg)

从上图中可以获取到，`0x275c8a0a` 是函数的返回地址。地址 `0x275c8a05` 处的函数调用极可能就是溢出函数。根据函数信息可知：

`MSCOMCTL!DLLGetClassObject+0x41a29`。

此函数调用发生在 `mscomctl.ocx` 中。此组件是打开 DOC 文件时动态加载的，所以只在此处下断点是断不下来的。

接下来在上图的基础上持续向上查找，查找到 `0x275c8a0a` 函数调用的起始处，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/FNWYCB7BH8HZ3SF.jpg)

### 调试此处函数的方法

利用 `sxe ld mscomctl.ocx`，在动态加载时断下。断下来之后，直接在地址 `0x275c89c7` 处下 `int3` 断点即可。

重新加载 PoC 文件，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/DR3TQ6M7ZQ9QNWZ.jpg)

此时程序已经来到溢出函数的被调函数处。同时，此时用 IDA 打开 `mscomctl.ocx` 文件（此文件在 `system32` 文件目录下），直接在函数窗口中打开 `sub 0x275c89c7` 函数地址，如图所示：

![](https://bbs.kanxue.com/upload/attach/201705/HPMDH3VEA2P49SJ.jpg)

从上图中我们可以直接获取到函数参数，以及函数的调用信息。这里我们先主要依靠 WinDbg 进行分析。

接下来直接利用 `u 0x275c89c7 L64` 命令查看 100 条反汇编指令，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/H9F2642JP575HWF.jpg)

如图所示，重点部分已经标注。接下来直接使用命令 `uf MSCOMCTL!DllGetClassObject+0x41a29` 查看函数完整的反汇编指令。

仔细观察会发现，在溢出的被调用函数中，总共发生过两次相同的函数调用，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/8U67RQCTKTXUU8D.jpg)

### 下面对溢出函数进行分析

单步运行到 `0x275c8a05`，然后使用 `dd esp` 查看函数参数值，如图：

![](https://bbs.kanxue.com/upload/attach/201705/DA8PDF8KAGZQ8F2.jpg)

如上图，函数三个参数分别是 `0x127b24`、`0xbfe06b0`、`0x8282`。进入溢出函数前的 `ebp = 0x127b2c`，进入函数后 `ebp = 127af8`。

接下来继续单步运行程序，直接来到地址 `0x275c87cb` 处，如图所示：

![](https://bbs.kanxue.com/upload/attach/201705/UK2RK46XRMS3H85.jpg)

如图所示，当执行到地址 `0x275c87cb` 处时，可以观察到 `esi` 内存中包含 `41414141`，而 `ecx = 0x20a0`。因此，当执行此指令时，即可表明程序的执行已经被用户控制。

### 溯源

接下来分别对地址 `0x275c87cb` 处相关的寄存器（`ecx`、`esi`、`edi`）进行值溯源，详细分析程序。

当程序执行到地址 `0x275c87cb` 处时，从上图中可以观察到：`ecx = 0x20a0`、`edi = 0x127b24`、`esi = 0x5602008`。

从此地址向上翻看，也就是向低地址寻找时，发现 `shr ecx, 2` 右移位指令，相当于将 `ecx /= 4 == 0x20a0`。`0x20a0 * 4 = 0x8280`，此处暂且记住。

接下来重新载入 PoC 样本，分别在地址 `0x275c89c7` 第一次调用溢出函数时的 `0x275c876e` 处下断点。

当程序断在地址 `0x275c89c7` 时，可以查看到：

![](https://bbs.kanxue.com/upload/attach/201705/VC2XWNANZ2AN9TH.jpg)

此时上层函数的返回地址是 `0x275e701a`，此层函数的 `ebp = 0x127b2c`（执行完 `mov ebp, esp` 后的 `ebp` 值）。

接下来单步运行程序，来到地址 `0x275c89da` 处，查看栈空间。在此处特别要谨记函数调用中的三个参数，分别是：`0x127b18`、`0x0c4e06b0`、`0xc`。

![](https://bbs.kanxue.com/upload/attach/201705/XX5YMM9DMFSVNY9.jpg)

结合汇编指令，很容易理解上图中的内容。接下来进入此函数。

![](https://bbs.kanxue.com/upload/attach/201705/Z2ZZJH2BH32CSU2.jpg)

如上图所示，地址 `0x27589df` 是此函数的返回地址，`0x127b2c` 是上层函数 `ebp` 的值，此层函数 `ebp = 0x127af8`。继续单步运行。

当执行完地址 `0x275c8783` 处的指令后，观察前后栈区数值的变化，如下图所示。此函数的作用是从源地址 `0xbd706b0` 处向 `0x127af4` 处读取四个字节内容：

![](https://bbs.kanxue.com/upload/attach/201705/6F246R9TZVESV44.jpg)

此处的变化仅仅是地址 `0x0127af4` 处的值由原来的 `0x275b2480` 变为 `0x0000000c`。程序运行到地址 `0x275c878d` 处时，此函数的第三个参数与地址 `0x127af4` 处的值进行比较，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/JGBHG8MBQ93T59Z.jpg)

接下来继续单步运行，来到堆内存申请函数处，可以观察出申请的内存大小是 `0xc` 字节，并且函数的返回句柄保存在 `eax` 中（此处需要谨记）。

![](https://bbs.kanxue.com/upload/attach/201705/XK5AJEXXVHJX4GU.jpg)

接下来继续单步执行到地址 `0x275c87b5` 处。此函数作用仍然是从 PoC 的文件内容中读取 `0xc` 字节的数据到申请的堆区内存中。当执行完以后，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/6VZSCF9PK86FE8D.jpg)

接下来继续单步运行，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/U8AXUA2J78HGE9F.jpg)

接下来直接执行到地址 `0x275c87cb` 处。此时观察 `edi`、`esi`、`ecx` 的值，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/WT5DR9AW4YY6ZVE.jpg)

从上图中观察出，`edi = 0x00127b8`（即函数的第一个参数），`esi` 的值就是申请堆内存时返回的句柄，`ecx = 3`，是 `shr ecx, 2` 后的值。通过向上翻看指令可知，`ecx` 值来自 `edi`，而 `edi` 来自函数调用中第三个参数的值。

> 至此可以得到的是：在溢出函数的被调函数中（也就是从地址 `0x275c89c7` 开始的函数中），当在栈中申请 `0x14` 字节内存后（内存地址是 `0x127b18-0x127b2c`），当在地址 `0x275c89da` 处第一次执行函数时，在栈区申请的 `0x14` 字节内存已经用掉了 `0xc` 字节，并且进行了复制，如下图所示：
>
> ![](https://bbs.kanxue.com/upload/attach/201705/ZHTK6ZTC9UUVNCU.jpg)
>
> 地址 `0x275c89da` 处函数的作用是：间接利用堆内存，从 PoC 文件中复制内容到栈区中。**复制内容的多少由函数的第三个参数决定。（这个是重点）**

接着从地址 `0x275c89df` 开始继续进行分析，单步运行程序：

![](https://bbs.kanxue.com/upload/attach/201705/U88WB5KR2DA3CFZ.jpg)

从地址 `0x275c89df` 到地址 `0x275c89f7` 处，其中两条 `cmp` 比较指令尤为重要，决定了是否执行 `esp`。并且第二条 `cmp` 指令的值决定了在 `0x275c8a05` 处第三个参数的大小。

以上分析可知，`0x127b18 - 0x127b2c` 中间内存的值是从 PoC 样本中复制出来的。因此只需构造一下即可满足这两个条件。

接下来进入 `0x275c8a05` 地址处进行分析。（其实和地址 `0x275c89da` 处的分析一样，只不过是数据发生了变化。）进入函数后，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/F85W7C827XDTR7G.jpg)

如上图所示，在函数返回地址后面紧跟的三个数值即为函数参数。

当执行到地址 `0x275c8786` 处时，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/N8P6F6NMY4C4D2B.jpg)

如上图所示，在地址 `0x275c8783` 处的函数调用中，成功读取到了四个字节的值（`0x127af4 = 0x00008282`）。

当执行完 `0x275c879e` 处指令后，记下返回值 `eax = 0x04ed9008`，接着继续执行到地址 `0x275c87b8` 处，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/485NWATYTBADE8C.jpg)

地址 `0x275c87b5` 处的指令作用是向堆区复制 `0x8282` 字节的内容，源文件来自 PoC 样本，地址是 `0xbd706b0`。

接下来直接执行到地址 `0x275c87cb` 处，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/PNRDTP5763HKZWZ.jpg)

如上图所示，一目了然：`ecx = ecx >> 2 == 0x20a0`，`edi` 仍然是参数，`esi` 仍然是堆区首地址。此时查看堆区内容，如下图：

![](https://bbs.kanxue.com/upload/attach/201705/7A3YTKRXXFV7RN5.jpg)

此时应该很清晰了。当执行 `0x275c87cb` 地址处的指令时，`EIP` 肯定会被 PoC 样本控制。

## 另外一种 PoC

样本来源：[样本来源](http://bbs.pediy.com/thread-207638.htm)。

此处 PoC 的利用效果是：打开 PoC 时弹出计算器。（但是使用过一次样本后需要重新载入一个新的样本，因此使用时请先进行备份。）

同样，直接在 `mscomctl.ocx` 地址处下断点。当程序执行到地址 `0x275c89df` 处时，可以看到如下图所示：

![](https://bbs.kanxue.com/upload/attach/201705/6AV6ZU8QF8T5MGU.jpg)

如上图所示，`[ebp-0xc]` 的值是 `0x8282`，同样大于 `0x8`。接着执行程序，来到地址 `0x275c87cb` 处，如下图：

![](https://bbs.kanxue.com/upload/attach/201705/6JVCDVP645WFM5C.jpg)

如上图所示，很明显的 `0x7ffa4512`（`jmp esp`）指令跳转到 Shellcode。
