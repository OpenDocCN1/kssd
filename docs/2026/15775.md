
# [原创]Art 模式实现XposedNativeHook兼容Android10

## 前言

现在市面上的 Hook 框架有很多，Xposed、Frida、YAHAK 等。Frida 是目前最火的跨平台注入框架，支持 Java 和 Native 层。安卓目前沙盒注入方式应该就两种：`Ptrace` 和 `Zygote`。各有各的优点和短板，曾经 Hook 之王 Xposed 在 Native 层显得比较无力，也就导致市场上很多模块都不能进行 Native 层的 Hook。我一直在想着能不能试着完善一下。

[如何利用xposed Hook Native层 函数 - 简书](<https://bbs.kanxue.com/elink@edaK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6%4N6%4N6Q4x3X3g2B7K9h3q4F1M7$3S2#2i4K6u0W2j5$3!0E0i4K6u0r3M7q4)9J5c8U0R3I4x3r3j5$3j5h3x3H3y4h3x3K6y4H3.>)

## 实现原理与限制

在之前这篇帖子里，简单实现了 Xposed 在 4.4 版本的 Native Hook。主要原理就是：在加载被 Hook 的 So 的时候，利用 Xposed 拦截；在 Java 层调用 `System.load` 函数，把 Xposed 模块里面的 so 进行加载注入；在 so 里面直接调用 `dlopen` 拿到被 Hook So 地址即可。

在高版本里面是不允许直接 `System.load` 的，认为是不安全的。

![](https://bbs.kanxue.com/upload/attach/201905/819934_9PYGRZMBJE6E4HF.jpg)

大概意思就是说直接 `System.load` 容易被篡改，在高版本会失效，应该使用 `System.loadLib`。这个函数是加载 app 内部 lib 下 so 的函数，但最终都会调用 `doLoad` 函数（具体可以参考对应源码）。我们就从这个函数入手。Xposed 先挂钩，以 So 名字作为条件过滤依据。

![](https://bbs.kanxue.com/upload/attach/201905/819934_WQHVE9BMHVSRDMH.jpg)

## 注入 So 的两种方案

这块有个问题，就是怎么把 Xposed 模块里面的 So 注入到目标进程中。在 4.4 版本的时候，可以直接 `System.load` 打开即可，然后进行装载和链接。这个问题我想了很长时间，有两种可行方案。

### 方案一：拷贝 So 到目标 lib 目录

可以把模块里的 so 利用 shell 权限进行 copy，直接拷贝到被 Hook 的 lib 下面，然后 `System.loadLib` 去加载即可。因为 shell 需要 root，会导致被 Hook 进程申请 Root 权限才可以（比如 Hook A app，因为 Xposed 走的是 A 所在的进程，所以如果在代码里申请 Root，最终会提示 A app 申请 Root）。进行操作不方便，也不实用。

### 方案二：反射调用 doLoad

直接利用反射调用 `doLoad` 函数进行 So 的加载，如图。

![](https://bbs.kanxue.com/upload/attach/201905/819934_49NS233W9AZ4J6C.jpg)

第一个参数是 So 的路径，第二个参数是 `ClassLoader`，其实它是一个 `PathClassLoader`。如果发现加载的 So 是被 Hook 的 So，便进行注入，把第二个参数传入进去，反射备用。

![](https://bbs.kanxue.com/upload/attach/201905/819934_SMB29HQJ77GM9SB.png)

这块的 `Path` 是绝对路径，有人会问为什么要这么写。我在 Hook 这个函数的时候，把参数 1 打印了一下，可以看到加载的是 So 的绝对路径。（这块楼主也有一件事不太懂，为什么路径要加个 `-1`，很奇怪，算了，照葫芦画瓢，先这么写。）

![](https://bbs.kanxue.com/upload/attach/201905/819934_PWSEDYE96573B6X.png)

这里科普一下：`/data/data/` 下面都是 App 的数据，而 `/data/App/` 下面放的是 App 包。然后把路径改成自己 Xposed 模块里的 So，进行注入，成功！

这块有个调用时机问题，一定要在目标 So 加载完毕以后再注入，因为后期需要实现突破 7.0 `dlopen` 限制，需要遍历内存对应的 Map 文件。

## 挂钩目标函数与突破 dlopen 限制

接下来，在 Xposed 模块的 so 的 `JNI_OnLoad` 中进行挂钩，楼主用的是 `InlineHook`。

![](https://bbs.kanxue.com/upload/attach/201905/819934_2HM9DW8KH3NC4QF.png)

在 4.4 版本以前，可以直接 `dlopen` 打开任意目录的 So 进行装载和链接；在 4.4 的时候，直接打开被 Hook 的 so 即可；在高版本，因为权限问题不能直接打开。

![](https://bbs.kanxue.com/upload/attach/201905/819934_KY57J9A5Q54EZP5.png)

## 2020-09-21 更新：兼容 Android 10

2020年9月21日18:36:08

在之前版本里面，是通过调用 `doLoad` 函数进行反射加载模块 So 文件，8.0 还可以，但是在 9.0、10.0 发现不可行。去源码里面搜索，在 `Runtime.java` 里面已经没有这个方法。找到了一个替换方法 `nativeLoad`，参数类型也一样。

![](https://bbs.kanxue.com/upload/attach/202009/819934_57SZ32MHC2M92QS.jpg)

兼容了一下，在 Android 10 里面也可以支持这种方式。

在获取模块 So 文件路径的时候，在高版本里面 `/data/app` 下面会有一个随机字符串，每次安装都会变，所以写死路径不可以：

```
//data/app/com.lyh.nkddemo-YuNFiNvInJyE3ahHYBXAQw==/base.apk
```

大概长这样。

![](https://bbs.kanxue.com/upload/attach/202009/819934_ZTK7PTFRT8SCKZ5.jpg)

我在模块里面获取安装的 app 路径，然后将后面的 `base.apk` 换成 `/lib/arm/模块so`，即可解决。

增加了开源库 `dlfc` 寻找 So 指定格式，只需要传入一个需要的 `包名|So名字`。

![](https://bbs.kanxue.com/upload/attach/202009/819934_HKKDHVB935KT8KJ.jpg)

在安卓 10 的 `/data/app` 下面，包名都是这种加密的。想要定位很难，在遍历 Map 文件的时候做字符串分割，两个都满足就认为是匹配项。

![](https://bbs.kanxue.com/upload/attach/202009/819934_7Q678HRS3W4QRMQ.jpg)

代码也很简单，在兼容原来逻辑上加个判断。

这块有个很坑的地方，就是 `fgets` 函数读取文件每一行的时候会加个回车，直接打开是打不开的。当时对比发现都一样，卡了很久，直到打印字符串长度的时候才发现多一位字符串。
