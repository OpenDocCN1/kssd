# CVE-2019-0803

## 背景

日前对某APT组织的C2测试下，成功拿下shell

在提权过程中发现，该服务器系统为windos 2012 R2 x64

![](upload/attach/202006/830989_Y6C2KF9XZ9MMGR8.png)

在Github找exp时发现，win7 和 2008的居多，针对2012的漏洞除了一些com组件产生的逻辑漏洞之外，内核相关的提权漏洞源码比较少

本着积累武器库的原则，选用了`CVE-2019-0803`漏洞进行分析，目标移植到windows 2012 R2

## 漏洞原理及利用方式

该漏洞属于`UAF`(Use After Free)类型的漏洞

漏洞存在于`DDE`通信中，在`DDE`通信时，Server返回数据时，会调用应用层的函数`clientCopyDDEIn1`，该函数会将一些数据填充到`tagINTDDEINFO`结构，后续会调用内核态`hmgSetOwner`函数，该函数会将`tagINTDDEINFO`中的成员`hIndirect`返还给Client。

因此可以通过对`clientCopyDDEIn1`函数进行`InlineHook`，在填充的数据改为gdi对象，这样当Server端退出的时候，gdi对象将会被释放，此时利用堆风水，可以成功占位，从而实现任意地址读写

### gSharedInfo泄露内核地址验证

`rax`为内核地址 `fffff900c3185970`

![](upload/attach/202006/830989_JY4BMVB5VCU8PNH.png)

找到`gSharedInfo`结构体

```
dq user32!gSharedInfo
dt win32k!tagSharedInfo
```

![](upload/attach/202006/830989_6NA4HDTYU7AGZHE.png)

user object可以在`user32.dll`的导出函数`gSharedInfo`中找到泄露内核地址,具体计算公式为

注意：`AcceleratorTabl`句柄为`CreateAcceleratorTableW`的返回值，而非传入的参数

```
(SHAREDINFO->aheList+sizeOf(HANDLEENTRY)*(AcceleratorTabl句柄&0xffff))
```

返回的句柄为`0xd00d5`

![](upload/attach/202006/830989_U6XET4SV8H9GQMN.png)

```
dq 0x450000+0x18*(0xd00d5&0xffff)
```

可以看到与内核态对应

![](upload/attach/202006/830989_JKW833GKDHPYYUJ.png)
