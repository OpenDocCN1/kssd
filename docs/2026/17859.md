
# [原创]CVE-2012-1875简单分析

在IE漏洞中，UAF是广为存在的，所以这一次想调试学习一下这类型的漏洞，也熟悉了解一些IE的机制。如有错误或意见，还请斧正和提出，感激不尽。

## 调试环境

- Windows 7 SP1 x86
- IE 8.0.7601.17514

## 修改过后的简易 POC

```html
<html>
<body>
<title></title>
<DIV id=testfaild>
    <img id="test">
    <div id="test"></div>
    <input id="what" onMouseOver="crash();"></input>
</DIV>

<script language="JavaScript">
function crash() {
    test.src = "";
}

function trigger() {
    Math.tan(0);
    var x = document.getElementsByTagName("input");
    Math.tan(0);
    x[0].fireEvent("onMouseOver");
    Math.sin(0);
    testfaild.innerHTML = testfaild.innerHTML;
    Math.cos(0);
    x[0].fireEvent("onMouseOver");
}
trigger();
</script>
</body>
</html>
```

打开PoC后，崩溃信息如下：

![](https://bbs.kanxue.com/upload/attach/201805/744498_EG7EQER2HCDA8A4.png)

看来是某个`Element`释放后重用所导致的。IE在解析DOM树的过程中会使用`CCollectionCache`结构将所创建的元素缓存以加速查询。在第一次执行`crash`函数时，`CCollectionCache::GetDisp`会调用`CCollectionCache::BuildNamedArray`、`CMarkup::AddToCollections`来遍历HTML页面中所有具有`id`属性的标签在内存中的对象，创建一个由具有`"test"` `id`属性的对象组成的数组，通过`CImplPtrAry::Copy`将上述数组保存至新创建的`CElementAryCacheItem`对象中。

![](https://bbs.kanxue.com/upload/attach/201805/744498_2DUM76YSM42KC6U.png)

打开Windbg附加进程，设置如下断点：

![](https://bbs.kanxue.com/upload/attach/201805/744498_7KBMJV396YYPFS3.png)

运行后断在断点0处，在IDA加载符号表后找到`mshtml.dll`中的`CCollectionCache::CCollectionCache`。

![](https://bbs.kanxue.com/upload/attach/201805/744498_GS89GCASP7HD6W9.png)

在Windbg单步执行完该函数，查看`CCollectionCache`对象。

![](https://bbs.kanxue.com/upload/attach/201805/744498_3V92AYVJSX38T8Y.png)

第一次断在`Math.tan(0)`语句时，查看`CCollectionCache`对象（`05b7dfd0`即为上文中`esi`的值）。

![](https://bbs.kanxue.com/upload/attach/201805/744498_YK6HGUAYH2364F9.png)

可以看到其保留的数组大小为`0x0d`，先来查看`Index 0`。

![](https://bbs.kanxue.com/upload/attach/201805/744498_922S8AWFNHDPYER.png)

接着需要重点关注`Index 8`中对应元素`CElementAryCacheItem`中的内容：

![](https://bbs.kanxue.com/upload/attach/201805/744498_W9UXA5SQA5WZHGE.png)

可以看到其`ArraySize`为4，

![](https://bbs.kanxue.com/upload/attach/201805/744498_S97NDMECA8ZPWYC.png)

对应着我们在PoC中定义的对象。

接着我们在开始提到的，在第一次执行`crash`函数时，会创建一个具有`"test"` `id`属性的对象所组成的数组，数组会保存在`Index e`处。在执行之前，我们先来看看那里现在的情况。（在两个`Math.tan(0)`语句中间获取`input`对象时，`CCollectionCache`结构体中`Item`数组大小及首地址均变化，因重复打开后地址随机化，故此处`0720dfd`对应着之前`CCollectionCache`对象的地址）

![](https://bbs.kanxue.com/upload/attach/201805/744498_PA5AHK8THY43BJU.png)

（当执行`getElementsByTagName`语句且在`CImplPtrAry::Copy`断下时，可以自己试试找找准备拷贝的`id`为`input`的对象数组，此处略）

![](https://bbs.kanxue.com/upload/attach/201805/744498_865GTD928VANHY2.png)

在执行`Math.tan(0)`与`Math.sin(0)`之间的`crash`函数时，代码在`BuildNamedArray`函数之后断在`CImplPtrAry::Copy`处，在`Index e`处新建了一个`CElementAryCacheItem`待赋值。

![](https://bbs.kanxue.com/upload/attach/201805/744498_2VG4GKGXPU833UR.png)

可以发现此时`ecx`中保存着新`CElementAryCacheItem`对象地址，`DWORD PTR[EAX+C]`中保存着被拷贝的`id`为`"test"`的对象数组：

![](https://bbs.kanxue.com/upload/attach/201805/744498_46B2KQG3Q9E6DYX.png)

单步执行至`CImplPtrAry::Copy`函数结束后，新`CElementAryCacheItem`完成赋值。

在`Math.sin(0)`与`Math.cos(0)`之间，语句`testfaild.innerHTML = testfaild.innerHTML`会使得当前页面中所有标签在内存中的对象被销毁，并依次重新创建相关类型的对象。所以当执行过该语句后，`CCollectionCache`的`Item`数组`Index E`位置上的`NewCacheItem`中保存的已经是被释放了的对象的内存地址。

![](https://bbs.kanxue.com/upload/attach/201805/744498_46B2KQG3Q9E6DYX.png)

当PoC中第二次调用`crash`函数时，会使用`GetDispID`查询对应的元素是否需要重建。在IDA中可以得到`GetDispID`的堆栈调用：

```text
CCollectionCache::GetDispID
    CCollectionCache::EnsureAry
    CCollectionCache::GetIntoAry
        CCollectionCache::GetAtomFromName
```
