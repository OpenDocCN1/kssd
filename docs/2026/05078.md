
# [原创]闪讯客户端内存泄漏的简单分析

小菜第一次发文章，没啥技术含量，大家见谅。![](https://bbs.kanxue.com/view/img/face/12.gif)

杭州大部分地区的高校应该都用着闪讯客户端，现在是2.5.0081版本。上学也有个几年了，闪讯作为一个拨号软件搞得这么的复杂确实会让人不爽，但不管怎么说，作为一个每天必点的软件，对它多多少少有了些感情。以前写过个解除wifi限制的软件，自从有了猎豹之后也没啥用了。最近又注意到一个问题，很奇怪闪讯的内存占用一直再涨，一开始也没怎么注意，后来发现如果挂着闪讯的时间略长后，内存占有竟然会变成原来的几十倍。

刚开始连上网时的内存占有：

![](https://bbs.kanxue.com/upload/attach/201406/578829_1jktjdsz03rvwow.jpg)

一段时间后（10几个小时）

![](https://bbs.kanxue.com/upload/attach/201406/578829_iwyyq4kyoaufueg.png)

内存从10几MB升到400MB,这种情况我想基本就是哪里有内存泄露了。于是就觉得一看究竟。

用OD附加上，在`ZwAllocateVirtualMemory`处下断来线索，因为调用`ZwAllocateVirtualMemory`的地方较多，我就又下断`ZwFreeVirtualMemory`来排除有借有还的内存申请部分，最后终于锁定申请内存没释放的地方。

它这里有调用一个 API `iphlpapi.GetIfTable`，百度了下这个 api 的功能。

```
int GetIfTable(PMIB_IFTABLE pIfTable,int pdwSize,bool bOrder )



pIfTable [out]

指向一个MIB_IFTABLE结构，用于获取本机各个接口的信息



pdwSize [in, out]

若pIfTable指向的buffer大于实际可以获取的table大小，则作为输入参数。

若小于则作为输出，输出table的大小



bOrder [in]

table是否排序
```

所以使用 `GetIfTable`，就需要先将 `pIfTable` 空 buffer 传入，获取 table 的大小，根据大小申请内存，然后再调用 `GetIfTable` 一次获取 table 数据。

看上面的代码其实就是这样处理的，5F7116E8 处其实相当于 `malloc`。很显然最后的代码就没有调用 `free`。

经过进一步分析，传入 `IsConnectNet` 的参数为一个字符串，其实就是网卡的名称：

```
040DFE88   5F711109  返回到 NetScan.5F711109 来自 NetScan.CNetScan::IsConnectNet

040DFE8C   03B999A0  ASCII "Realtek PCIe GBE Family Controller"

040DFE90   0018ADC8

040DFE94   0000027C

040DFE98   03B913C0
```

"Realtek PCIe GBE Family Controller" 就是我电脑上的网卡名称，`GetIfTable` 获取的是本机上接口的 table，跟踪观察了下，后面的代码其实就是取 table 中接口的名称与当前联网适配器的名称比较，判断是否连接着网线(接口中有没网卡的名称)。

其实原理很简单，内存泄露的原因也仅仅是因为申请的 table 数据没有释放。

最后看一下他每次检查连接状态时需要申请的内存大小：

```
040DFC84   77C5B8C1  返回到 ntdll.77C5B8C1 来自 ntdll.ZwAllocateVirtualMemory

040DFC88   FFFFFFFF  //ProcessHandle（-1 当前进程）

040DFC8C   040DFCBC  //BaseAddress

040DFC90   00000000  //ZeroBits

040DFC94   040DFCD0  //RegionSize

040DFC98   00001000  //AllocationType

040DFC9C   00000004  //Protect

```

最后得出 是每5秒泄露 0xC000 Byte(48KB) 的内存，和我观察到的情况基本相符。
