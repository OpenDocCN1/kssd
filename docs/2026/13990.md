
# 从钓鱼邮件到窃密木马的完整分析

## 0x00 前言

在做样本分析的时候，通常都是针对恶意软件进行分析。这种属于样本分析，是安全分析中的一部分，但也是比较关键的一部分。样本分析是安全分析人员与恶意软件开发/投放人员沟通最直接的桥梁。

但是很明显，攻击并不是直接就是从恶意软件开始的。

我们拿到的恶意软件，可能是鱼叉类钓鱼邮件攻击精准投放，也有可能是水坑类攻击下发。

作为分析人员，除了分析看到的这个恶意样本，也应该关注整个攻击事件和攻击背景的分析。

## 0x03 第一阶段 payload

原始样本是带了一定混淆的，但这里的混淆很好解，就直接 `de4dot` 去混淆即可。

![image.png](https://bbs.kanxue.com/upload/attach/202009/757351_Z67D8BFMRRU6A5T.jpg "image.png")

去混淆之后，样本名还是乱序韩文，但类名和方法名已经显示正常了：

![image.png](https://bbs.kanxue.com/upload/attach/202009/757351_EU4C9Y9WW64DYB3.jpg "image.png")

这里需要注意，样本执行的时候，首先执行的不是 `Main()` 函数的内容，而是 95 行的：

```
public static byte[] Bytes = Class0.smethod_0();
```

原因很简单，静态变量的初始化会在正式的代码执行之前完成。

所以当程序运行的时候，会首先将各个静态变量赋值，这里 95 行处，程序就会通过 `Class0` 类的 `Smethod_0()` 方法给 `Bytes` 变量赋值。

`Smethod_0()` 方法是直接返回了一个大的数组。

![image.png](https://bbs.kanxue.com/upload/attach/202009/757351_Y8WVD8YVMXBYXW8.jpg)

分别在 95 行这里和 `Main()` 函数里面 `new GClass0().method_0();` 进来的地方设置断点

## 0x04 第二阶段 dll

通过调试，这里可以知道，程序调用 dll 的时候，会调用 `awrfsdg` 类下面的 `aj()` 方法。

![image.png](https://bbs.kanxue.com/upload/attach/202009/757351_QDNH5GJWPGV8VQ7.jpg "image.png")

加载 dll 后如下：

![image.png](https://bbs.kanxue.com/upload/attach/202009/757351_8CMM2MSY4UKH8HS.jpg "image.png")

`aj()` 函数的调用逻辑是这样的。

1. 通过 `Abs(-3)` 给 switch case 的初始值设置为 3，执行 `case 3` 分支

2. 将 `num` 赋值为 2，跳转到 `IL_02` 重新执行 switch，执行 `case 0` 分支。

3. 跳转到 `IL_4A` 执行 `b.a()`

4. 如果 `b.a()` 执行失败，则跳转到最后执行 `f.a()`

5. 如果 `b.a()` 执行成，这 `num` 赋值为 2，退出程序。

![image.png](https://bbs.kanxue.com/upload/attach/202009/757351_7FW7EMVJDUNNZHE.jpg "image.png")

所以这里就是两个关键函数，一个是 `b.a()`，一个是 `f.a()`。

程序过来之后，首先会在实例函数这里解密一个字符串，然后等待 25s。
