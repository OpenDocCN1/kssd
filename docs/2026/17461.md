
# [原创]X64 Kernel Shellcode获取Ntos Base

之前网上的思路是`GetPcr()->IdtBase`拿到`isr`地址对齐后往上爆搜`'MZ' 0x5A4D`，来拿到`ntos base`。

![](https://bbs.kanxue.com/upload/attach/202103/99882_RF8Q262V8QRTWS6.jpg)

在win10 2004以下版本中没什么问题。

`isr`本身位于`.text`中，往上很快就能得到`pe`头。

![](https://bbs.kanxue.com/upload/attach/202103/99882_KZJDGN69C3RRAJY.jpg)

但是在win10 2004下，`ntos`的区段结构变了，`.text`不再是第一个区段。几个data区段跑到了上面，还有3个区段不能访问。

![](https://bbs.kanxue.com/upload/attach/202103/99882_WHH7CSXNQ52TY6T.jpg)

如果继续往上爆搜，则会直接裂开。

![](https://bbs.kanxue.com/upload/attach/202103/99882_KR2HDKT3FK3E6JG.jpg)

那么换个思路，可以看到在`ntos`的`.text`中还是有很多地方引用了`image base`了的。

![](https://bbs.kanxue.com/upload/attach/202103/99882_74Y9TU5PEEP3JQ2.jpg)

直接往上爆搜`48 8D 1D ?? ?? ?? FF`，(`lea xxx, -aaaaaaa`)，最后一个`0xff`确保方向朝上，然后判断`aaaa`是否`PAGE_SIZE`对齐(`& 0xFFF == 0`)。

代码如下

```asm
.CODE

PUBLIC GetKernelBase

GetKernelBase PROC

mov     rax, qword ptr gs:[18h]

mov     rcx, [rax+38h]

mov     rax, 0FFFFFFFFFFFFF000h

and     rax, [rcx+4h]

jmp      while_start

search_mem_start:

add     rax, 0FFFFFFFFFFFFF000h

while_start: 

xor     ecx, ecx

jmp      search_mem_check

search_mem_next: 

add     rcx, 1

cmp     rcx, 0FF9h

jz       search_mem_start

search_mem_check:  

cmp     byte ptr[rax+rcx], 48h

jnz     search_mem_next

cmp     byte ptr[rax+rcx+1], 8Dh

jnz     search_mem_next

cmp     byte ptr[rax+rcx+2], 1Dh

jnz     search_mem_next

cmp     byte ptr[rax+rcx+6], 0FFh

jnz     search_mem_next

mov     r8d,[rax+rcx+3]

lea     edx,[rcx+r8]

add     edx, eax

add     edx, 7

test    edx, 0FFFh

jnz      search_mem_next

mov     rdx, 0FFFFFFFF00000000h

and     rdx, rax

add     r8d, eax

lea     eax,[rcx+r8]

add     eax, 7

or      rax, rdx

ret     

GetKernelBase ENDP

END
```
