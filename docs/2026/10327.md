# [原创]加载内存当中的DLL（文件），支持64位和32位。直接加载内存或资源当中的dll，不落地

由于某些目的，自己做了一个加载内存当中DLL文件的东西，原本网上的各种教程都挺多的，但是就是没有针对32、64位适配。

先说说功能和特性（BUG[S]）吧：

1、支持直接加载内存当中的DLL映像，无磁盘占用

2、自动适应32/64位

3、支持寻找函数地址

4、支持卸载DLL， 重复利用实例

6、支持静态或者非静态编译

用VS2017编译通过，能正常加载内存当中的DLL文件。

![](https://bbs.kanxue.com/upload/attach/201807/402738_U323B9J4QSFMYZH.jpg)

自己的dll只是弹框，也测试过寻找地址，都是没问题的。

程序是x64的，也有x86版本，为什么要x64版本，是因为某些程序用32位不方便（某些新的游戏，你懂的）。

使用方法：

包含dllloader.h头文件

#include "dllloader.h"

引入库文件

#pragma comment(lib,"MemLoadLibLib.lib")

32位和64位的静态链接、非静态链接版本都提供了。

在全局创建一个容器，里面为MEM\_LoadDllAPI的指针。喜欢可以用智能指针。使用完以后释放掉即可。

简单的例子：

// 实例化

MEM\_LoadDllAPI\* hDll = GetMemLoadDllApp();

// 装载内存的DLL

hDLL->MemLoadLibrary(&\*buffer, lSize); //&\*buffer是一个指向读入内存的dll，是一段内存。lSize是大小

// 获取函数地址

typedef void (\*MyFunc)();

MyFunc Func1 = (MyFunc)hDll->MemGetProcAddress("Func1");

    MyFunc Func2 = (MyFunc)hDll->MemGetProcAddress("Func2");

Func1(); Func2();

// 脱钩并释放内存，实例可重复使用
    hDLL->MemFreeLibrary();

// 释放内存（需要手动释放，每个实例都会消耗内存。）

delete hDLL;

目前已知的一些问题：

由于使用C++实例，因此需要在全局用一个容器缓存实例指针（暂时是这个办法解决的）。貌似可以用std::map之类的缓存实例指针。实例销毁以后会自动脱钩并释放内存，防止内存泄漏。

静态编译的dll有时候会无法加载，原因不明，vmp加壳的dll加载没出问题。

MSVC14.x貌似有点问题，编译出来的程序在某些操作系统和硬件环境会出现随机崩溃，原因不明。
