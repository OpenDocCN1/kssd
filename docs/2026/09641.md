# [原创]某个 python IDE 注册过程分析

首先，感谢xee发表的爆破教程，http://bbs.pediy.com/showthread.php?t=138599，省去了许多前期工作。
友情提示，本文需要一点python基础。

【准备】
xee同学已经说过，用unpyclib能得到.pyc .pyo的op code，而一个op code的文本基本上有几百K，

怎么查看、分析这些op code呢?

正所谓，工欲善其事，必先利其器。要浏览如烟似海的代码，一个能高亮代码的编辑器是必不可少的。
我用了notepad++，利用自定义语言功能，简单定义了python opcode的高亮语法。
相信我，花半个小时做这点事，是绝对值得的。

光看静态的代码很吃力，要让代码跑起来，才能更好的理解和分析。
注册模块运行的是python 2.5，所以得先安装一个python 2.5。
然后，将目标程序安装目录下 bin\2.5的src.zip解压到c:\ide 下面，把所有的.pyo文件改名成.pyc。
编辑一个test.py，里面只用写一句

```
 
from process import abstract
```


运行后会出现各种错误，包括找不到某模块，找不到某dll等。
到安装目录下找这些模块和dll，统统copy过来，实在找不到的模块，就编辑一个同名的空文件（.py后缀）糊弄过去。
同时，根据错误提示，还需要设置一些环境变量。
最终的代码如下：

```

import sys
sys.path += ("c:/ide", "c:/ide/pygtk")
import tempfile
tempfile.tempdir = "c:/windows/temp"
import os
os.environ["WINGHOME"] = "c:/ide"
from process import abstract
```


此时，运行test.py已不跳出任何错误，abstract模块乖乖的准备好了，我们已经能调用、查看它内部的任一全局变量、函数和类。

【继续】
有了License还没完，输入进去后，程序又跳出一个Activate License的窗口，并给出了一个request code，要求我们激活。

输入任意的字符，提示说长度错误，要求20个字符，并且前缀必须是AXX（这个注册系统也太友好了吧）。

输入AXX123456789A1234567，提示“Invalid license activation”。
用此关键句，直接定位到\_ValidateLicenseDict(self, lic, filename)。
参数中有self，说明这是一个类（class）中的函数。
继续找\_ValidateLicenseDict，可以发现它是CLicenseManager中的一个成员函数。
运行

```

c = abstract.CLicenseManager()
lic = abstract.CreateLicenseDict("CN123456789A12345678")
lic["activation"] = "AXX123456789A1234567"
```

简单说明一下这段代码
1. CreateActivationRequest(lic) 创建一个request code，存入lichash，正版用户凭这个code去拿激活码
2. 去掉 lic.activation 中的"-"，存入act30
3. textutils.BaseConvert(act30, textutils.BASE30, textutils.BASE16)，转成16进制的字符串，存入hexact
4. config.\_locale\_valid置0
5. 重点来了
   control.validate(lichash, lic.os, lic.version[:lic.version.find('.')], hexact)，把结果存入config.\_locale\_valid，非真的话出报错信息。
   第一个参数是 request code，软件会显示出来
   第二个参数，操作系统，这里是"windows"
   第三个参数，版本号，这里是"4"
   第三个参数，是变形后的激活码
   返回结果为真，则注册成功，反之则失败。

```

import ctlutil as control
```



【曙光】
在process目录下有ctlutil.pyd，这是用c编译的python模块，本质上就是一个dll。
可能作者觉得编译成native code比较安全吧，真的是这样吗？

先在test.py中输入代码：

```

while True:
    abstract.control.validate("RW42X-XXXXX-XXXXX-XXXXX", "windows", "4", "11111111")
```


终于，老朋友ollydbg要登场了，让test.py跑起来，然后“附加”python.exe进程，ctrl^M，在ctlutil的.text段下断点。

能看到i386的汇编代码真是让人泪流满面啊。

关键算法在10001020，整个执行逻辑清晰易懂，不愧是做python开发的啊。

我相信有crack经验的同学，10分钟内就能理解是怎么运作的。

为了保护原作者，毕竟开发这么好的软件也很不容易，这里对具体的注册算法就不啰述了。
