# [原创]使用NMI中断检测无模块驱动

各大论坛、博客讲利用NMI插中断检查堆栈的时候普遍有一个错误：在NMI回调中直接调用了`RtlWalkFrameChain`或者`RtlCaptureStackBackTrace`。比如R0g大佬这里百密一疏：[[原创]2024鹅厂游戏安全技术竞赛决赛题解-PC客户端-CTF对抗-看雪论坛-安全社区|非营利性质技术交流社区](https://bbs.kanxue.com/thread-281459.htm)

![](https://bbs.kanxue.com/upload/attach/202509/1025431_VF9BRHWHPPC9E9Q.webp)![image-20250922213245093](https://bbs.kanxue.com/upload/attach/202509/8ZNX9AFNSXSQD7H.jpg)

64位下，这两个函数会扫描PE文件的`UNWIND_INFO`来解析栈帧信息，此时如果触发`Page Fault`那就蓝屏GG

正确的思路是在`KPCR`里找到NMI的异常栈地址，解析`MACHINE_FRAME`去拿`RIP`和`RSP`，再来判断是否rootkit

`IST Index`是记录在IDT表项中，触发中断/异常时的异常栈指针索引号

![](https://bbs.kanxue.com/upload/attach/202509/1025431_5JXPUQQEZT852RY.webp)![image-20250922204640032](https://bbs.kanxue.com/upload/attach/202509/8ZNX9AFNSXSQD7H.jpg)

NMI中断在机器上映射的中断向量号总是2：

![image-20250922204503469](https://bbs.kanxue.com/upload/attach/202509/8ZNX9AFNSXSQD7H.jpg)![](https://bbs.kanxue.com/upload/attach/202509/1025431_AHFWHMEMP7TP6SF.webp)

找到对应的IDT表项，这里的03就是`IST Index`，说明NMI触发时使用了Ist3这个栈指针
