# [原创]TsFltMgr的简单逆向

闲着无聊也对QQ管家的TsFltMgr.sys进行了简单的逆向
详细的大家就去看看附件IDB吧,这里只简单说下TsFltMgr寻找KiSystemService中目标hook位置的过程

大家都知道360中是使用了栈回溯的方法进行hook位置定位的,TsFltMgr中使用的是读取中断描述符表的方法.
对应IDB中的位置是: DriverEntry -> BeginInitDriver -> InitDriver -> GetDestHookAddr -> GetInt2EProcedure
![](https://bbs.kanxue.com/upload/attach/201203/440388_ciug52533o8q247.jpg)
sidt指令将IDT描述信息存储到目标操作数起始的6字节位置中<其实是两个寄存器的值>
其中低两个字节为IDT全长,高四字节表示IDT基址


```

sidt    fword ptr [esp+0Ch+var_8]
```


即是将这6字节存储在var\_8起始的6字节中,包括var\_8的4字节和var\_4的2字节


```

mov     eax, [esp+0Ch+var_8+2]
```


将IDT基址装入eax

因为要找的是Int 2E的中断处理,所以检测了一下 0x2E\*8 = 0x170 位置的内存区域有效性<每一项都是8字节>
之后就进行了一下运算得到真正的地址.

在这里我有点疑问,网上也没找到什么资料,就是每一项中断描述符都是8字节长,为什么分为两部分,
真正的地址需要第二个双字的高字和第一个双字的低字进行组合呢?希望知道答案的朋友能不吝赐教啊

上面的步骤我们可以利用livekd重现一下:
输入 !r 列出寄存器值:
![](https://bbs.kanxue.com/upload/attach/201203/440388_vz1m4yvzwp5wt78.jpg)

idtr中存放的就是IDT基址了,看一下:
![](https://bbs.kanxue.com/upload/attach/201203/440388_rlxgguujfphzy73.jpg)

我们要找的是 Int 2E 的中断处理例程,所以输入 dd 80b95400+2e\*8 :
![](https://bbs.kanxue.com/upload/attach/201203/440388_hfcpkczgwmm47wv.jpg)

这里前两个双字就是了,组合一下得到地址 0x8408cfee ,反汇编一下:
![](https://bbs.kanxue.com/upload/attach/201203/440388_z9g0k1x68fmd278.jpg)
正是中断处理的入口点了.

得到入口点之后TsFltMgr对其进行了判断<是否在内核地址空间>,然后通过搜索特征码来找到具体的hook点
![](https://bbs.kanxue.com/upload/attach/201203/440388_xg5adat6ftxz6dl.jpg)

unk\_18FE0中保存了一段数据,对应于KiSystemService的这里:
![](https://bbs.kanxue.com/upload/attach/201203/440388_3fe9fhlas3r7k4q.jpg)

其中MmUserProbeAddress的具体数据之前通过MmGetSystemRoutineAddress已经获取
之后剩下的就是hook了,Fypher兄在这篇帖子中有介绍:
<http://bbs.pediy.com/showthread.php?t=146156>

另外驱动中保存SSDT相关信息用到了几个结构,不过能力和精力有限只逆出了很少一部分:


```

//一共46个
struct SSDTINFO{
	ULONG			flag;				// 不能为2 为0查询,为1略过
	PWCHAR			ssdtName;			// SSDT名称
	PVOID			proxyAddress;		// 代理函数地址
	ULONG			index;				// SSDT索引
	..
	ULONG			Number;				// 次序
}size = 52 = 0x34
```



每个SSDT都有一个结构保存信息,这些结构是保存在驱动文件中的,而且还为每个SSDT分配了一个0x4f8大小的结构:

```

针对每一个SSDT分配了一块内存大小为 0x4f8
struct SSDTBUFFER{
	ULONG			flag;			//+0x000
	ULONG			index;			//+0x004	SSDT 索引号
	PWCHAR			ssdtName;		//+0x008	名
	ULONG			ssdtNumber;		//+0x00C	次序
	BOOL			valid;			//+0x010	分配了内存并且flag为0或1时有效
	ULONG			BusyNow;		//+0x014
	..
	PVOID			prevAddress;	//+0x020	HOOK之前的值
	PVOID			proxyAddress;	//+0x024	代理函数
	..
	ULONG							//+0x040	1
	..
	ULONG							//+0x048	0
	EVENT			event;			//+0x04C
	..
	ULONG							//+0x0F0	在设备扩展函数中被设置
	..
}size = 0x4f8
```


上面这个结构还用来描述驱动注册的三种监控回调,也就是进程回调,线程回调,模块回调
