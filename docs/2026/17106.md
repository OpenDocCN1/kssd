# [原创]Burp使用手册_在续情缘之Upstream Proxy Servers(上游代理服务器)

之前叙述了Burp的常规用法，这次来点不一样的，也是自身心路的记录
[toc]
# 前因
## 文字描述
因一些需求，需要使用代理进行测试。
举例：测试站需某个代理才可访问，测试的时候就需通过这个代理进行发送数据了，但Burp简单的设置后与代理会形成干扰导致Burp自带的浏览器无网络，或抓包测试的时候请求IP是原IP，所需的代理未起作用，导致测试失败，故需解决这一问题。
## 图示描述
为方便理解，根据所想画了一张图 ：
![](upload/attach/202011/767964\_74XWY54EQSR6469.png)
# 解决
经多方询问后，了解到Burp有个上流代理功能(Upstream Proxy Servers)可满足此需求
## 文字描述
\* Burp：127.0.0.1:8080
\* v2ray：127.0.0.1:1081
Burp设置v2ray为上流代理这样就解决了此问题
![](upload/attach/202011/767964\_DHDV6U9CC4MNBM2.png)
这样数据的传输路径即为：
浏览器-请求数据-Burp-v2ray-测试目标，测试目标-响应数据-v2ray-Burp-浏览器
## 图示描述
![](upload/attach/202011/767964\_XH7XPE86ZCKJUAW.png)
# 扩展
有老哥说可以根据这一特性进行联动其它工具，进行工作，列如：xray
## 联动xray
\* 原理Burp 与 xray 建立起一个多层代理关系，使测试流量从可从Burp 转发到 xray 中。
\* 先启动xray,使其可正常工作
(因工具还在下载故这里暂时使用网络图片)
![](upload/attach/202011/767964\_D9YC945M5X6BY5U.jpg)
\* Burp-Upstream Proxy Servers
根据之前的原理设置xray为Burp的上流代理
这样数据
数据-Burp-xray
![](upload/attach/202011/767964\_V8RE7V4T9THG3JZ.png)
\* 之后使用Burp进行测试
可使用自带浏览器或结合其它浏览器（此浏览器需使用Burp开通的代理服务）
并除了安装Burp的证书还需需安装xray证书
否则会出现下图，让安装证书
![](upload/attach/202011/767964\_HPUAYVBNNHEX6RU.png)
![](upload/attach/202011/767964\_JKUXFKXEZGYBJJ7.jpg)
\* https测试准备
xray生成证书
```
xray.exe geca
```
![](upload/attach/202011/767964\_SHB8FP4GB59GEC6.png)
导入生成的证书
![](upload/attach/202011/767964\_FVJQX7W4CNKNFJ7.png)
\* 效果
Burp正常捕获到数据，并xray可进行被动扫描
![](upload/attach/202011/767964\_VCWDHVHPMN6UYPU.png)
![](upload/attach/202011/767964\_B2NZDN4ZJYZ6HFN.png)
