## 介绍-欢迎来到E5573

华为e5573设备是一个4G调制解调器，Optus在澳大利亚有转售，在世界各地都有途径拿到。这个设备有一个白色的小塑料盒，当它打开时，看起来像这样：

![](https://bbs.kanxue.com/upload/attach/201707/746111_z3cxatt6l6mu6lg.png)

可识别调试引脚如下所示：

- 上面的红色盒子里的插脚是UART。上一行的第二个和第三个引脚分别接收（数据输入）和传输（数据输出）。
- 左边的三个引脚，外观黄色，是另一组调试的bottomost引脚：引脚“boot pin”–如果该引脚接地，当设备上电后，它会引导到一个“USB DLOAD”模式，它可以用来覆盖设备的引导程序（也就是，固件）。这是一般用于给设备越狱和防止变砖的方法。
- 右边的引脚可能是JTAG -这种配置在华为的设备上很常见（如在这里提到的），虽然我在逻辑分析仪上的任何一个引脚上看不到任何东西。

## 观察引导

我的第一步是观察通过UART引导的设备：

![](https://bbs.kanxue.com/upload/attach/201707/746111_1omypcnw1tj3u5y.png)

然后该设备引导Linux，并运行自定义密码提示符。使用暴力破解显示密码长度必须为8个字符，但没有提供其他信息。

更详细地检查引导过程，我们发现了奇怪的一行：

```
[0000028ms]Heap:0x57d3bbe0 -- 0x57d3c180, 1440Here, I

[0000029ms]Please distribute uart with command L/V/M...

[0000029ms] heap:0x57d3bbe0 -- 0x57d3c180, 1440
```

我们从4pda.ru获得一个线索，来自forth32这个用户。

![](https://bbs.kanxue.com/upload/attach/201707/746111_5129zi9wamf1h3h.png)

拖着这为谷歌翻译，我们得知一个可以发送“M”、“V”或“L”通过UART连接引导到不同的模式，分别是：“M3控制台”，VxWorks或Linux内核。至少有一个可用的模式（“K”），通过公开可用固件的逆向工程可以看到。

选择“L”选项允许定时开机，而选择V给非交互式的VxWorks控制台（在e3372，这是交互的–我不知道为什么这里是关闭状态，关于这个设备也没办法重启它）。

## 进入未知的世界

在文件中的字符串显示，我们可以看一些任意进程的内存，甚至是，这个Balong单片机控制台本身：

![](https://bbs.kanxue.com/upload/attach/201707/746111_l7hfkimrtlrqv0r.png)

不幸的是，内存转储没有正常的可执行格式。加载到IDA不显示任何类型的头文件。我们从引导日志中知道，处理器是ARM，所以我们可以简单地将其加载到IDA中，并开始强制转换为ARM代码，看看我们得到了什么：

最初的指令看起来不象有效的ARM，但是如果我们往下看，我们可以看到有意义的ARM函数（用正常的push/pop指令），而且数据开始成形：

![](https://bbs.kanxue.com/upload/attach/201707/746111_uz0cwsk0b6it0qc.png)

奇怪的是，我们看到在0x10000000内存区域有一些引用。凭直觉，我决定在0x1000000重建可执行文件，然后再试一次。这个时候，代码容易分散，IDA Pro的交叉引用的功能大放异彩：这些神秘的字大多是函数指针，指向代码中的其他地方。

![](https://bbs.kanxue.com/upload/attach/201707/746111_yke31qhf8q8desv.png)

回到内存转储开始时，我们还可以看到类似的模式–这段代码在0处不是代码，实际上是DWORD数组。

浪费了半个小时后，我们终于嗅到了成功的气息——IDA成功地将函数引用到内存转储中的字符串引用中，表明这确实是MCU控制台本身：

![](https://bbs.kanxue.com/upload/attach/201707/746111_7zydip2agevcepn.png)

这似乎是一个关于参数数量的检查，足够我们开始证明我们可以执行任意代码，而不用通过单独的MCU控制台启动引脚。

## 修改代码流

为了证明我们可以执行任意代码，证明我们可以控制代码流就足够了。上面的检查是一个很好的开始的地方：我们可以触发这个代码流，结果是合乎逻辑的-如果有超过5个参数，就会显示一个关于太多参数的消息，并且命令不会执行。如果我们能降低这个限制，我们就可以控制执行的代码。

一个小的尝试，我们会发现`m`命令允许我们修改内存，但在同一时间只有一个DWORD值，如下（你必须提供一个完整的DWORD值，否则它会假定这些丢失的字节是0,并重写你的目标地址）：

```
m 0x1000F000 0xAABBCCDD
```

我们可以在0x1000075c用这个修改这个检查，如下所示，保持字节顺序：

```
m 0x1000075C 0x0F02F1BB
```

这就意味着，我们可以为命令提供至少两个参数，在这里，我们最多可以提供5个参数。首先，我们测试的五个参数的`d`行为符合预期（这个测试用例使用自动化的小型计算机脚本，因此缺少一些输出–但也足够接近）。

![](https://bbs.kanxue.com/upload/attach/201707/746111_65tz7lmffeocr1g.png)

现在，我们将`m`命令添加到脚本中，然后尝试：

## 最后的想法 + 接下来的工作

在这一点上，我们已经：

- 识别出未知的二进制文件，并将其恢复到某种合理的格式以供进一步分析。
- 证明我们能够同时编辑二进制文件中的资源，以及任意执行的代码。
- 证明特权代码执行没有“boot pin”后门/有一个新鲜的bootloader（而不是使用一个routerunlock.com越狱您的设备）。

这应该足以加载任意特权代码，尽管通过UART非常缓慢。

因为本设备存在公开的越狱（而且快得多），这项工作作为e5573设备和其他可能已经不存在越狱的设备逆向工程的基本“乐高积木”。
