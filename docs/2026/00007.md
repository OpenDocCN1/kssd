谈谈IA-32的指令格式

废话不多说，作为CISC的代表，x86指令集的解码工作较为复杂。这种工作主要是为了照顾兼容性，实际上现在把一堆东西挤在几个比特里面完全没有必要，看看MIPS的汇编器，除了伪指令外，其他就是一一对应好嘛。

这部分的参考资料主要是`intel手册2`的第2章和第三章的3.1，当然还有手册2的附录。`intel手册`分为三册，手册1是给汇编程序员用的，主要指导你怎么写汇编程序；手册2是给编译器设计者用的，主要指导你怎么给你的编译器写一个x86后端--这也是我从事工作的一部分；手册3是给系统程序员用的，主要是指导操作系统编写者如何利用CPU。

## 一、前缀：（prefix）

前缀是可选字段，也就是说它可以不出现。它分为四类（组），`intel`的术语叫四个`group`。在一條指令裡，每一類前缀最多只能出現一次。這四類是：

### 1.锁总线和重复前缀

`F0H`: `LOCK` 锁总线前缀

`F2H`: `REPNE`/`REPNZ`

`F3H`: `REP` `REPE`/`REPZ`

注意這三小類占用的是一個`group`，也就是說，前綴中出現了`LOCK`就不能再出現`REP`之類的重複前綴。

其實應該發現一個奇怪的問題，`F1H`不見了，它是否是一種前綴呢？事實上，`inte`和`amd`手冊在這裡存在著差異。在`intel`手冊中，`F1H`的指令槽是空出來的，但是`AMD`手冊裏面把`F1H`給了`INT1`。這實際上是一個`undocumented opcode`。

### 2.段超越和分支提示前缀

`CS`/`SS`/`DS`/`ES`/`FS`/`GS` 六個段超越前綴 對應的編碼是

`2E`/`36`/`3E`/`26`/`64`/`65`

分支不被接受：`2E`

分支被接受：`3E`

注意到，`2E`和`3E`是被複用的。如果我們寫一個反彙編引擎的時候，僅僅得到`2E`和`3E`是不清楚到底是`CS`/`DS`的超越前綴還是分支預測。需要往後看`opcode`，這是解析前綴指令需要注意的一點。請注意段超越前綴不能用於分支跳轉類指令，而分支預測前綴只能用於`Jcc`（條件跳轉指令），它們是不存在交集的。

### 3.操作数超越前缀

實話說，此處“超越”翻譯的不咋樣。實際上，是可以改變操作數的寬度。

`66H`

### 4.地址超越前缀

`67H`

這些前綴有些需要說明：

1）不少前綴需要等待`opcode`才能確定。所以編程時候需要往後看`opcode`才能決定`prefix`解釋成什麼。

2）第一類的`REP`和`REPE`有什麼區別？`REPE`和`REPZ`有什麼區別？

`REP`和`REPE`的區別是`opcode`不同。`opcode`如果修改標誌位，則`F3H`是`REPE`，否則就是`REP`。這也是需要看標誌位的`prefix`之一，實際上是兩類指令前綴復用了這個指令槽。

`REPE`和`REPZ`沒什麼區別，助記符的兩種寫法。

3）什麼叫地址超越？什麼叫操作數超越？

超越是對英文`override`的翻譯，這個翻譯很奇特，也不符合`override`的真實意義。但是國內大部分介紹8086的書籍都採用這種翻譯。實際上`override`在此處意思是“重寫”。

重寫了什麼呢？操作數默認的`size`（寬度）可能是16位或者32位。而操作數超越前綴就是允許此指令使用非默認的寬度。

同樣地址超越作用類似，允許指令使用非默認的地址寬度（16位或者32位）。

那麼默認的操作數寬度、默認的地址寬度在哪兒呢？代碼段選擇子有一個位（第22位 `CS.D`）指明了默認值。被置位，上面兩個默認寬度都是32位；被清零，上面兩個默認寬度都是16位。

請注意，給指令施加這兩類超越前綴不會改變默認寬度，僅僅是改變該指令的執行使用的寬度。

## 二、opcode

實際上`opcode`分為兩個部分，一部分就是`opcode`本身，另一部分是個別指令會占用`modr/m`的`reg/opcode`位域。

學`MIPS`或者其他`RISC`指令集的見到`intel`的`opcode`編碼可能會嚇一跳。相比較`MIPS`那種`I` `J` `R`三類指令，`x86`的指令`opcode`編碼實在是太複雜了。`x86`的`opcode`最短是1個字節，最長是3個字節。這是其一。

和`MIPS`解決方案不同，`x86`對於源操作數和目的操作數是暗含在`opcode`裏面的。對於念`MIPS`教科書過來的朋友，幾乎難以理解。這話意思是：

比如說`mov`指令：

![](https://bbs.kanxue.com/upload/attach/201406/301429_tmdy6heu8y5vfnn.png)

我框出來的這兩條指令没有任何的本质区别，就是源操作数和目的操作数反过来了。也就是说谁是源操作数谁是目的操作数就隐藏在`opcode`中。这和`MIPS`的想法不同。

比如說：

`88 D9`

對應 `MOV CL,BL`

而 `8A D9`

對應 `MOV BL,CL`

`D9`還是那個`D9`，但是誰是源誰是目的不一樣了（也就是說由於`opcode`不同，對於`D9`的解釋不一樣）。這一點對於`modr/m`字節理解有幫助。

單字節`opcode`比較好理解。

二字節和三字節`opcode`比較特殊：

二字節通用`opcode`是`0fh`+一字節的編碼；但是二字節的`SIMD opcode`是一個強制前綴+`0fh`+一字節的操作碼。

不知道大家看懂了沒。`intel`的二字節的`SIMD opcode`實際上是三個字節，有一個字節（“強制前綴”）被計入了前綴部分。對於二字節的`SIMD opcode`，這個前綴不是可選部分。

同樣的，三字節的通用`opcode`，是`0fh`+二字節的編碼。`SIMD opcode`格式是強制前綴+`0FH`+二字節編碼。

問：

1）此處強制前綴，是否計入“前綴”的四個字節限制？

不計入。此處強制前綴，是為了引導出來此處是`SIMD`指令，類似某種轉義碼。實際上，此處強制前綴，應該納入`opcode`的範疇，所以此處`SIMD`所謂二字節、三字節名不副實，應該是三字節、四字節。

個別的`SIMD`指令不需要強制前綴來引導，比如`addps(0FH+58H)`

2）`0FH`是什麼?

`x86`常用的轉義碼。此處用來提示是多字節`opcode`。

3）強制前綴有哪些？

和前面的`prefix`編碼有重疊。是`66h` `f3h` `F2h`。

4 ) 二字節和三字節都用`0FH`作為轉義碼，那麼解碼時候如何知道是二字節還是三字節呢？

問的好！事實上三字節指令的第二個字節（它和`0FH`一起構成三字節的轉義碼）是在二字節指令槽裏面的。就像`0FH`在一字節指令槽裏面一樣。

## 三、modr/m字节

`modr/m`是一個字節。被切分成三個位域（2![](https://bbs.kanxue.com/view/img/face/1.gif)3），它用來確定尋址方式，並可能對`opcode`做一定補充。

![](https://bbs.kanxue.com/upload/attach/201406/301429_qqzqj6dywdjrg4l.png)

`mod`:提供尋址模式，`11`=寄存器尋址 其餘都是內存尋址

`reg/opcode`：

兩種作用，第一種是提供寄存器尋址；另一種為某些`opcode`提供補充說明。

`R/M`：

結合`MOD`位域，提供內存/寄存器尋址。

1.這裡先研究`reg/opcode`位域：

1）請問此處提供的是源操作數還是目的操作數的寄存器尋址？換而言之，比如我要編碼`mov eax，ebx`，此處`reg/opcode`負責編碼`eax`還是`ebx`？

都可以。取決於你使用什麼`opcode`。這個問題我們在`opcode`那裡已經解釋了一部分，這裡著重解釋一下。

![](https://bbs.kanxue.com/upload/attach/201406/301429_n4cnq1tqu3ddneo.png)

請注意畫紅框的兩條`opcode`，都可以用来编码`mov eax，ebx`。如果采用`89`編碼，則`eax`為`r/m`位域，編碼是：

```
89H       11         011   000
opcode   reg尋址    ebx   eax
```

請注意`89`編碼時候，目的地址是在`r/m`字段，也就是說，此處的`eax`是目的地址。這樣編碼就是`89 D8`。

而採用`8B`編碼，則`eax`為`reg/opcode`位域：

```
8BH       11        000    011
opcode   reg尋址    eax     ebx
```

最終編碼是`8B C3`。

這也就是我上面說的，`x86`把源和目的操作數隱藏在`opcode`裏面了。

2）什麼類型的`opcode`需要這個位域來補充？為何不乾脆再用一個字節編碼`opcode`，要占用這個位域？

這個問題你得問設計這些指令槽的設計師。實際上再設計一個字節編碼也毫無問題。這部分編碼類似元素週期表中鑭系元素和錒系元素。

3）這會給反彙編引擎帶來什麼問題？

導致有些指令（被稱為組編碼指令--在原始的`opcode`表裏面一組占用一個格子，用陰影區分）需要讀到`ModR/m`才能確定其作用。

2.下面談`mod` 位域和`R/M`位域

這個位域配合`r/m`一起來確定尋址方式，`mod`有4種，每一種對應一種尋址方式。請注意，16位下的`mod r/m`編碼對應尋址方式和32位下的完全不同--也就是說，它們没有任何可比性。

16位下面是没有`SIB`字節的，那麼16位怎麼實現基址變址尋址呢？只好通過`modr/m`來實現。為此，16位犧牲了通用的寄存器間接尋址（只提供`BP BX SI DI`作為間接尋址的寄存器，並且`BP`實現稍微特殊）。也就是说16位下面没有`mov [al],bl`这种东西。

![](https://bbs.kanxue.com/upload/attach/201406/301429_my8vuvnrwpfwxzs.png)

我們稍微來研究一下這張32位的`modr/m`編碼表。`mod=11`時候，是寄存器尋址，這很簡單。請注意紅杠標註的那些個行。我們注意到：

1）`[ESP]`這種尋址方式在`modR/M`裏面沒有。它被用來引導`SIB`（可以理解`R/M=100`作為`SIB`的轉義碼）。表示`[ESP]`的編碼方法要在`SIB`裏面。

2）`[EBP]`這種尋址方式類似16位裏面`[BP]`的編碼方式。在`mod=00`時候，反倒没有`[EBP]`。`[EBP]`是採用`[EBP]+disp8`或者`[EBP]+disp32`來編碼的。

稍後我們會看到，在`SIB`裏面，也有類似的特殊設置。

## 四、SIB字节

![](https://bbs.kanxue.com/upload/attach/201406/301429_gyfvf2ozl6gv84z.png)

同`modr/m`類似，`SIB`字節也是採用2![](https://bbs.kanxue.com/view/img/face/1.gif)3切分成三個位域，名字分別叫`Scale`、`Index`、`Base`。`SIB`的名字也來自這三個位域名字的首字母縮寫。

`SIB`字節由`R/M=100 MOD≠11`引導出來。

`SIB`確定的尋址方式是`[base+Index\* Scale +disp]`

`disp`意思是後面尾隨的若干個`displacement`字節。

![](https://bbs.kanxue.com/upload/attach/201406/301429_yyynzf5msxnd3ge.png)

這個圖，可以補充幾點：

1）`base`中的`ebp`哪去了？

`SIB.base=ebp`的時候，要看`mod`決定是何種尋址方式。上圖的附注裏面已經說明了。這是解析`SIB`字節，需要反過來查`modr/m`的情況。

2）`index`裏面的`esp`哪去了？

`esp`作為`index`時候，`index`自動被忽略--此時`scale`因子視為0.（請注意`scale`編碼為`00`時候，因子視為1）上表裏面`none`真是混淆是非的典範。也就是说`esp`作為`index`，計算方法是`[base+disp]`，不管你的`scale`是多少。

這種表示有一個重要的作用，就是我們可以表示`[ESP]`這種尋址方式。如果你還記得`modr/m`那邊把本該屬於`[esp]`的編碼當做轉義碼來引導`SIB`字節了，導致`modr/m`無法表示`[ESP]`。只好用`sib`來表示。

前面說過`sib`表示的是`[base+ Index\*Scale+disp]`，要想表示`[esp]`，只好把`base`設置成`esp`，`scale`因子設置成0，`disp`設置成0.但是我們發現，`scale`沒有0這個編碼（`00`、`01`、`10`、`11`分別代表1 2 4 8 沒有0）。只好用替代的方法，如果`index`是`100`（`esp`），則`scale\*index=0`。

當然這個規則是一致的，就算你的`base`不是`esp`，而是`eax`等寄存器，只要把`index`設置成`100`，`scale\*index`一樣視為0。

## 五、displacement和immediate

問：

1）這兩者有什麼區別？

要說核心區別，那就是`displacement`大部分用在尋址上，而`immediate`用於操作數的編碼上。

舉個例子：

`mov ecx，1`

可以編碼成

```
OPCODE IMME
B9      01 00 00 00H
```

請注意目的操作的地址`ecx`（一個寄存器）已經蘊含在操作碼`B9`裏面了

而`mov ecx，[0x1]`

編碼成：

```
opcode   mod   reg   r/m  displacement
8B       00    001   101  01 00 00 00H
                 ecx
```

即

`8B 0D 01 00 00 00H`

其中`mod`和`r/m`在一起，表示`disp32`的尋址方式。

當然了，你也可以額外使用一個`SIB`字節來編碼`mov ecx，[0x1]`

```
opcode   mod   reg   r/m  scale    index  base   displacement
8B       00   001  100    01     100    101  01 00 00 00H
                     引導   scale随便写
```

即：`8B 0C 65 01 00 00 00`

其中`scale`是可以随便寫的，`00 01 10 11`都行，因為`index=100`，不管你寫什麼，都視為`index\*scale=0`.

2）嵌入到指令編碼裏面所有的立即數不是`disp`就是`imme`嗎？

個別指令提供了`moffs*`的立即數尋址，比如`mov`指令：

![](https://bbs.kanxue.com/upload/attach/201406/301429_5qgoseyxb3dqrkw.png)

此處`moffs32`等就是`moffs*`的立即數，可以直接編碼在`opcode`後面，你可以把他們歸為一類`disp`，但是這類`disp`不需要`modr/m`字節來引導出來。

比如`mov eax，[0x1]`就可以編碼為以下形式：

a）採用`moffs32`編碼

```
opcode moffs32
A1    01 00 00 00
```

`A1 01 00 00 00H`

b）採用`MODR/M`引導的`disp`

```
opcode   mod   reg   r/m  displacement
8B       00    000   101  01 00 00 00H
```

`8B 05 01 00 00 00H`

c）採用`SIB`引導的`disp`

```
opcode   mod   reg   r/m  scale    index  base   displacement
8B       00   000  100    01     100    101  01 00 00 00H
                     引導   scale随便写
```

`8B 04 65 01 00 00 00H`
