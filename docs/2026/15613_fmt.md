
# [原创]逆向某4399分析过程

## 1. 抓包报文分析

### 1.1. charles抓包分析报文

登录和注册 发送验证码 都带有⼀个`sign`字段

![](https://bbs.kanxue.com/upload/attach/202202/884888_NRCZ72B6VET7T7T.jpg)

其他参数都为固定参数 比如请求头中的

![](https://bbs.kanxue.com/upload/attach/202202/884888_2NJ4ERJ5K6QVP47.jpg)

只有这个`sign`每次都是变化的,那我们就开始分析这个`sign`

## 2. 老规矩

1. 先查`apk`是否加固 查询发现没加固
2. 直接上`jadx`打开`apk`,能正常反编译
3. 发现网络框架使用的是`okhttp`

## 3. 代码分析

1. 因为使用的`okhttp`框架 那么自然直接搜索`OKhttpClient` 在哪被初始化 `jadx`直接搜索到

![](https://bbs.kanxue.com/upload/attach/202202/884888_6Q23RT9NAXKCSAR.jpg)

看名字猜测应该是网络核心父类,接着按`x`找到相关引用类 找到

![](https://bbs.kanxue.com/upload/attach/202202/884888_4YZNTA5XMXYTRYH.jpg)

看名字就猜到了`http`相关的工具类,接着继续找关键字`sign`,因为网络相关的类都在`framework`包下的 `helper`子目录中所有随便翻翻找到一个

![](https://bbs.kanxue.com/upload/attach/202202/884888_PK5C47RUVGCYG89.jpg)

打开一看找到`app`相关的`native`方法都在这类中定义 按`x`找到相关引用的类中 有一个

![](https://bbs.kanxue.com/upload/attach/202202/884888_QN8DH9MW9ESNE3W.jpg)

看方法名就猜到了应该是计算`sign`的方法，打开看果然是

![](https://bbs.kanxue.com/upload/attach/202202/884888_NNYS69U2D3QJPV9.jpg)

计算方法为:

1. 调用`buildSignRequestParams(str,map)`方法将请求参数赋值给`hashMap`,并将`hashMap`中的值按照 `key`进行排序,重新赋值给`map`
2. 遍历排序后的`hashmap`的取出`value`进行拼接传递给`buildSignValue()`方法，调用`native`方法 用`frida` Hook这两个方法调用也证明了这两点:

![](https://bbs.kanxue.com/upload/attach/202202/884888_Z8C2AE7M4NNAR4J.jpg)

3. 接下来开始分析`native`方法 `getServerApi()` 找到使用的`so` 包为`libNativeHelper.so`

![](https://bbs.kanxue.com/upload/attach/202202/884888_BZW65S98C3ZKZPR.jpg)

扔到`ida`看导出函数发现是`jni`动态注册没找到`getServerApi()`这个方法,接下来使用`unidbg`进行分析 `call_jni_onload` 后找到 偏移地址`0x12795`

![](https://bbs.kanxue.com/upload/attach/202202/884888_VBJS8BMNBCDEN5N.jpg)

在`ida`中`G` 跳转到偏移地址

![](https://bbs.kanxue.com/upload/attach/202202/884888_4SN45D4QKXC8TA8.jpg)

![](https://bbs.kanxue.com/upload/attach/202202/884888_SXQ5TG86HHWZ8XV.jpg)

查看`sub_4DF0`函数`F5`生成伪代码

![](https://bbs.kanxue.com/upload/attach/202202/884888_759F25XDEGUFU4R.jpg)

阅读代码修改原有的字段名称。祭出大杀器`unidbg` `Hook`

![](https://bbs.kanxue.com/upload/attach/202202/884888_2D6W6VBHT48JX8K.jpg)

多次调用方法发现入参为一串固定字符串值,先暂定它为加密因子吧！ `hook`伪代码中的

`strcat(参数1,参数2);`

参数1为之前调用`java` 层 `native`方法中请求参数排序后的`value` 字符串,参数2位固定的加密因子 将两个字符串拼接后生成新的待加密串。

接着分析 `sub_4538(&v20)`函数

![](https://bbs.kanxue.com/upload/attach/202202/884888_9578TSH5JU6ZX8N.jpg)

这个4个常量 在结合`sign`的长度为32 很明显的可以猜到使用的`MD5`加密,具体在往下看。 分析`sub_4564()`函数;

![](https://bbs.kanxue.com/upload/attach/202202/884888_UG86JVR63KVJ6P5.jpg)

`hook`函数`sub45F4`函数 得到的入参 为 `md5`标识和待加密串 接着点进去查看这个函数具体实现

![](https://bbs.kanxue.com/upload/attach/202202/884888_QQXCEWJXG972MPB.jpg)

![](https://bbs.kanxue.com/upload/attach/202202/884888_2MBCHA8RAVCBTNY.jpg)

最终`hook`这两个函数都没发现生成具体的`sign`值 加密串也没有最终被修改 于是随手拿之前得到的加密串去做个`MD5`发现直接就跟`sign`一样 所以大概得出这个`sign`算法就是标准的 `MD5`

![](https://bbs.kanxue.com/upload/attach/202202/884888_ST7DM6THC723AG3.jpg)
