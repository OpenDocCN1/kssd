# [原创]调试外挂经验记录[更新]

我目前遇到的外挂绕过保护有两种：
1. 将外挂代码写到系统进程中。
2. 将外挂dll注入到游戏进程中。

游戏是有保护的，调试外挂，想知道外挂功能执行，打开游戏进行调试是不现实的，因为你想用OD之类的，你首先要绕过游戏的保护![](https://bbs.kanxue.com/view/img/face/33.gif)。

有一个办法可以解决这个问题，那就是你写一个exe，伪装成游戏进程。伪装很简单，把自己写的exe的名字改成与游戏进程名一样就OK了。有些外挂即使你进程名和游戏进程名是一样的，还是会提示“请打开XXX游戏”，经过实际调试，原因是外挂使用FindWindow()函数，所以你要把你的程序的窗口名和窗口句柄改成和游戏一样的。这样就完全OK了。
伪装游戏的程序用易语言写最简单，直接生成一个窗口程序，在属性里面将窗口标题和窗口类名改了，然后静态编译，熟悉的话1分钟搞定，不熟悉的人10分钟也能搞定。
伪装进程还有一个好处，那就是游戏中存在的地址你的这个假进程不一定有，因为游戏是很大的，现在的游戏动辄1G+，而你的伪装程序可能就1M左右。所以当执行部分功能的时候会出现下图的消息框：
![](https://bbs.kanxue.com/upload/attach/201304/552616_10zfdtgrwo6z815.jpg)
主要的是这句话："XXXX1"指令引用的"XXXX2"内存。该内存不能为"written"。
XXXX2这个内存地址就是外挂写入游戏的内存地址，如果打开OD，将所有的异常忽略全部取消，OD就可以在这个错误发生的地方断下来，再根据调用堆栈，就可以定位这个功能执行的地方。

我所分析的外挂都是用易语言写的，发现了一个情况，易语言的组合框(就是下拉列表)中的功能可以用OD搜索到字符串，而复选框却不可以。经过分析，我认为组合框是要临时判断所选择的功能的，所以在执行功能的时候会用到组合框中的文字，所以OD搜索到相应的文字以后可以很快的定位功能实现地点，而复选框不用，所以无法根据复选框旁边的文字来定位功能实现的地点。

想要知道外挂进程向游戏进程写入数据的细节，可以自己写一个驱动级的监控软件。

因为有[local.1]、jl short 易语言试.0041A52D之类的OD翻译的汇编语句，所以不能直接用来查找命令序列，而且OD的命令序列只能查找8条指令，还有易语言所编译出来的汇编和OD所翻译的汇编有时会不一样，所以使用ctrl+s查找命令序列的方法是很不精确甚至查不到的。
那么最好是使用二进制来定位，虽然提取二进制很麻烦，但是只要易语言不做大的更新，这个二进制特征码可以用很长很长时间了。
将前面的汇编的二进制提取出来

```
8B4DEC83E901894DEC837DEC007C128B55EC8B45088B4C9010894DF0FF75F0EBDFFF55FC
```


那么如何进入外挂作者的事件当中哪？在上面的

```
0041A52D  |>  FF55 FC       call [local.1]
```


这个call中，按F7进入，就直接到了事件处理函数中。
当定位到这段汇编以后，要在

```
0041A52D  |>  FF55 FC       call [local.1]
```


这个语句下断点，因为只要定位的位置正确，这个call是必然会被调用的，而别的地方不一定。
如果外挂中使用了线程，那么就会频繁的进入这段代码，因为这段代码就是用来调用外挂作者自己的函数的(这个描述可能不太准确，因为在外挂作者自己的函数中调用了外挂作者自己写的函数，可能不会执行到这段汇编)。所以需要使用条件断点。
如果外挂注入的是伪造进程，而伪造进程是用易语言写的，那么就会有两段这样的代码，需要在内存窗口中去查看，定位到的内存地址是在哪个模块中。
