## 二、详细内容

### （一）Fortinet漏洞

#### 1. CVE-2024-55591身份验证漏洞

该漏洞影响：Fortinet FortiOS（版本7.0.0–7.0.16）和FortiProxy版本7.0.0–7.0.19、7.2.0–7.2.12）。

CISA将CVE-2024-55591列入已知被利用漏洞目录，此举意味着：该漏洞目前正在被攻击者实际利用（exploited in the wild），表明它已被用于针对真实环境的攻击中，且该漏洞具有较高的现实威胁性。

**修复方案：**

1. FortiOS：更新到版本7.0.17或更高版本。  
   注意：生产环境建议在更新前先做兼容测试，无问题再更新。
2. FortiProxy：更新到版本7.2.13或更高版本，或者7.0.20或更高版本。

**临时解决方法：** 收敛管理界面的公开暴露面（如禁用HTTP/HTTPS管理界面）或限制受信任的内部用户访问（如限制可通过本地进入策略到达管理界面的IP地址）。

```
#限制可通过本地进入策略到达管理界面的IP地址的操作参考示例：

config firewall address

edit "my_allowed_addresses"

set subnet

end

##然后创建地址组：

config firewall addrgrp

edit "MGMT_IPs"

set member "my_allowed_addresses"

end

##创建本地策略，以限制对管理接口（此处为端口1）上预定义组的访问：

config firewall local-in-policy

edit 1

set intf port1

set srcaddr "MGMT_IPs"

set dstaddr 'all'

set action accept

set service HTTPS HTTP

set schedule "always"

set status enable

next

edit 2

set intf "all"

set srcaddr "all"

set dstaddr 'all'

set action deny

set service HTTPS HTTP

set schedule "always"

set status enable

end

##如果使用非默认端口，请为GUI管理访问创建适当的服务对象：

config firewall service custom

edit GUI_HTTPS

set tcp-portrange 443

next

edit GUI_HTTP

set tcp-portrange 80

end

在下面的本地登录策略1和2中使用这些对象代替"HTTPS HTTP"。

只有当所有GUI用户都配置了trusthost功能时，该功能才能实现与上述本地登录策略相同的效果。因此，上述本地登录策略是首选的变通方法。
```

#### 2. CVE-2025-24772身份验证绕过的漏洞

漏洞介绍：在FortiOS 7.0.0至7.0.16以及FortiProxy 7.2.0至7.2.12、7.0.0至7.0.19中存在一个利用替代路径或通道进行身份验证绕过的漏洞[CWE-288]，该漏洞可能允许远程攻击者通过构造特定的CSF代理请求来获取超级管理员权限。

CISA将CVE-2025-24772列入已知被利用漏洞目录，此举意味着：该漏洞目前正在被攻击者实际利用（exploited in the wild），表明它已被用于针对真实环境的攻击中，且该漏洞具有较高的现实威胁性。

### （二）利用该漏洞的攻击者Mora_001

#### 1. 主要特征

以下是新发现的利用影响Fortinet设备的CVE-2024-55591和CVE-2025-24472的Mora_001攻击者的主要特征：

![](https://bbs.kanxue.com/upload/attach/202505/767964_QBXCR78ZR4U42U9.webp)

Forescout Research正在将Mora_001视为一个独立的攻击者进行追踪，同时基于以下因素，也认识到它与已有的勒索软件组织存在关联：

1. **在调查中发现，Mora_001展现出与其他已知勒索软件组织一致的入侵后行为模式，具体包括以下方面：**
   - 在多个受害网络中创建相同的用户名；
   - 初始访问、入侵后活动以及命令与控制（C2）操作中存在重叠的IP地址；
   - 在受侵害环境中表现出相似的配置备份行为；
   - 在条件允许的情况下，48小时内迅速部署勒索软件；而在安全控制措施较强的环境中，则会进行更长时间的侦察。

2. **勒索软件的定制化**：该组织利用了泄露的LockBit构建工具（builder），并对勒索信结构进行了修改，去除了LockBit的品牌标识，并使用了自己开发的数据窃取工具。

3. **与LockBit的关系**：其勒索信中包含了与LockBit相同的TOX ID，表明该组织与臭名昭著的LockBit勒索软件团伙可能存在关联。这一联系表明，Mora_001要么是LockBit当前的一个合作成员（affiliate），具备独特的操作手法；要么是一个关联组织，共享部分通信渠道。

Forescout Research观察到的入侵后行为模式使其能够定义出一套独特的操作特征，从而将Mora_001与其他勒索软件组织（包括LockBit的关联团伙）区分开来。这种一致的作战框架表明，Mora_001是一个具有明确战术流程的独立威胁实体，而非多个攻击者在遵循通用的LockBit方法论。

通过对入侵时间线、重叠威胁指标和操作模式的分析，Forescout Research将未来的入侵活动归因于这一特定实体——无论其与LockBit之间的确切关系如何。

#### 1. 从Fortinet防火墙漏洞到勒索软件部署

Forescout Research的调查发现了跨越多个环境的入侵，并追溯到对Fortinet防火墙漏洞的利用。下面，展示了近乎完整的防火墙日志，这些日志有助于重建这些攻击序列。为了保护仍在进行修复的受影响组织，编辑了日期、时间戳和其他敏感细节。

#### 2. 初始访问和持久性

CVE-2024-55591和CVE-2025-24472允许未经认证的攻击者在具有暴露管理界面的易受攻击FortiOS设备（<7.0.16）上获得super_admin权限。

1月27日，公开发布了一个概念验证（PoC）漏洞利用程序，在96小时内，Forescout Research观察到有人使用两种不同的方法在实际场景中积极利用漏洞：

- **jsconsole：** 通过jsconsole界面直接利用WebSocket漏洞。在日志中，该活动显示为jsconsole(IP)，IP地址通常被伪装成127.0.0.1、13.73.13.73、8.8.8.8、1.1.1.1或其他可识别地址。
- **HTTPS：** 使用直接HTTPS请求的另一种利用方法。虽然这种方法在日志中的显示方式不同，但它针对的是相同的潜在漏洞。

Forescout Research观察到攻击者利用默认PoC漏洞利用程序以及稍作修改的变种的情况，这些变种只做了细微改动，如更改用户名和IP地址。

### 4、横向移动和勒索软件部署

攻击者利用防火墙配置、仪表板洞察信息以及已建立的网络访问权限（通过VPN或直接身份验证），在网络中进行横向移动，优先针对高价值目标，包括文件服务器、认证服务器和域控制器、数据库服务器以及其他网络基础设施设备。

攻击者主要依赖Windows管理工具（`WMIC`）进行远程系统的发现和执行操作，并通过SSH协议访问其他系统，尤其是服务器和网络设备。

在其中一个确认案例中，攻击者重点识别并入侵了文件服务器，这些服务器随后成为数据窃取和勒索软件部署的主要目标。攻击者并未对整个网络进行加密，而是有针对性地加密了那些存储敏感数据的文件服务器。

这种加密行为是在完成数据窃取之后进行的，这与近期勒索软件攻击者更倾向于优先窃取数据而非单纯造成系统瘫痪的趋势相一致。

### 5、勒索软件与基础设施分析

在这些事件中观察到的勒索软件变种与 LockBit 3.0（LockBit Black） 高度相似。主要区别在于加密后留下的赎金通知（ransom note）以及一个自定义的数据窃取可执行文件。由于这些修改，Forescout Research将该变种命名为 “SuperBlack” 。

### 7、可观测的网络枢纽

攻击者利用被入侵防火墙配置文件和仪表板中的信息，深入内部网络。为了最大限度地扩大范围，他们试图登录多个防火墙和账户。Forescout Research观察到 IP 地址 `185.147.124[.]34` 执行了其中一些操作。

该 IP 之前与多个边缘设备的恶意网络请求有关。它有 SSHfingerprint `fa3f3f12cee3c18aa50ea8b8e38708cad06875e617164baca8f8ee7156459249`.

发现该 IP 上的 `7000` 端口打开，显示出一个名为 “VPN Brute v1.0.2” 的工具，其中包含俄语内容。

![](https://bbs.kanxue.com/upload/attach/202505/767964_EQ8YAFH56QTWWQT.jpg)

VPN Brute 工具可对多个边缘设备进行暴力破解，包括

- RDWeb (Remote Desktop Web Access)
- PulseSecure (referred to as “Dana” in some sections)
- OWA (Outlook Web Access)
- GlobalProtect (Palo Alto Networks)
- Fortinet
- Cisco
- BIG-IP (F5 Networks)
- Citrix

此外，VPN Brute 还能为每个请求或每组请求轮流使用多个代理服务器（SOCKS 和 HTTPS）。这样就能用新的代理服务器动态替换被阻止或失效的代理服务器。它还允许操作员通过设置每个线程的凭证字符串数量，以及定义每个客户端请求的最大或最小凭证来控制凭证处理。

发现还有 15 个 IP 地址在运行 VPN Brute v1.0.2 和 v1.1.0（列在 “出错指标（IoC）”部分）。较新版本引入了基于复选框的选项以增加功能，包括

- “Продолжить поиск после успешного гуда” (“Continue searching after successful discovery”) – 这表明，即使找到了有效凭证，该工具也能继续进行暴力破解。
- “Включить комбинационный режим” (“Enable combination mode”) – 允许自定义用户名和密码组合。
- “Сканировать ханипоты” (“Scan honeypots”) – 帮助侦测蜜罐，以避免被侦测到。

# 三、建议采取的缓解措施

Forescout Research调查的入侵事件凸显了利用外围安全设备进行初始访问的趋势日益明显。从漏洞披露到主动利用的快速转变大大缩短了企业应用关键更新的时间。

为了减轻这些威胁，企业必须采取纵深防御的方法，对网络进行适当分段，并实施分层安全控制，以限制攻击者实现其目标的能力。

截至本文撰写之时，美国（7677 台）、印度（5536 台）和巴西（3201 台）暴露的 FortiGate 防火墙数量最多。Forescout Research建议 FortiGate 用户采取以下措施：

- 修补易受攻击的系统： 立即应用 FortiOS 更新解决 `CVE-2024-55591` 和 `CVE-2025-24472`。
- 限制管理访问： 尽可能禁止防火墙的外部管理访问。
- 审计管理员账户： 定期检查所有管理员账户，删除任何未经授权或意外的用户。
- 检查自动化设置： 检查是否有未经授权的自动化任务，特别是那些设置为每天或非工作时间运行的任务。
- 审查 VPN 用户： 审核所有 VPN 用户和组，检查合法用户名是否有细微变化，或最近创建的账户是否没有明确的业务理由。
- 启用全面日志记录： 调查中常见的漏洞是缺乏全面的日志记录。确保启用以下功能： FortiGate 上的 CLI 审计日志、进出防火墙的 HTTP/S 流量日志、网络策略服务器 (NPS) 对身份验证事件的审计、设置为同时记录成功和失败（而不仅仅是失败）的身份验证系统审计。全面的日志记录增强了检测、调查和主动威胁捕猎的能力。
