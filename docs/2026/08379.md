
# [原创]在Windows平台使用VS2022的MSVC编译LLVM16，让LLVM再再次优雅起来

## 前言

> 联动一下隔壁帖子，本文章仅作为一个补充：
>
> [如何优雅的在 Windows 上使用 LLVM Pass 插件进行代码混淆](https://bbs.kanxue.com/thread-272346.htm)
>
> [[原创]让LLVM16在windows上再次优雅起来](https://bbs.kanxue.com/thread-279723.htm)

本文的编译方法不需要对LLVM源码进行任何改动，除了VS2022以外不需要安装任何额外的软件或者依赖

## 正文

首先，保证你的Windows上安装了VS2022

![图片描述](upload/attach/202312/684293_Y6G4JEJEC6VG22W.webp)

其次，保证你的VS2022安装了MSVC，一般勾选了使用C++的桌面开发就应该满足条件了

![图片描述](upload/attach/202312/684293_K82MJCK7WYJR89P.webp)

别忘了把这两个给勾上，虽然编译LLVM的时候用不上它们，但是编译完了我们可以把编译后的与自带的进行替换，然后就能使用MSBuild工具链调用我们自己的LLVM进行编译了（具体方法参考隔壁，这里不赘述了）

![图片描述](upload/attach/202312/684293_KAXRSSCV8VEEVSD.webp)

然后是重点，一定要从设置里把当前系统区域设置给改为英语(美国)并重启系统

![图片描述](upload/attach/202312/684293_P7ADESBD6JC3JD7.webp)

准备好编译环境后，从GitHub上把LLVM的源码clone下来，选择LLVM16的branch，最后一个版本应该为16.0.6（VS2022自带的是16.0.5，不过基本没啥影响）

`git clone <mark class="encrypted">318K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6D9L8s2k6E0i4K6u0r3L8r3I4$3L8g2)9J5k6s2m8J5L8$3A6W2j5%4c8Q4x3X3g2Y4K9i4b7`.</mark> -b release/16.x`

![图片描述](upload/attach/202312/684293_ZQ4QYYSDAFEHFPY.webp)

我们直接对着llvm-project右键=>使用 Visual Studio 打开

这时VS2022可能会弹窗，我们选择不启用

![图片描述](upload/attach/202312/684293_P33TAWGRVM2ZBKK.webp)

点击视图=>终端，打开VS2022的开发者命令行（一定要用这个，不能用别的）

![图片描述](upload/attach/202312/684293_D847UUFQB25BPUM.webp)

使用VS2022自带的cmake进行构建，等待项目构建完毕

`cmake -S llvm -B build -DLLVM_ENABLE_PROJECTS=clang -DLLVM_TARGETS_TO_BUILD=X86`

这里指定的`LLVM_TARGETS_TO_BUILD=X86`表示我们编译出来的LLVM只能编译为X86指令集（32位和64位），如果想支持更多的指令集可以去掉这个参数，但是会增大项目体积、增加编译时间

![图片描述](upload/attach/202312/684293_P8KPE6GMFRPBQHF.webp)

然后关闭当前的VS2022，找到生成的.sln文件并双击打开

![图片描述](upload/attach/202312/684293_7AS4J8UZDDNMZG9.webp)

可以看到解决方案已经被成功的构建了

![图片描述](upload/attach/202312/684293_YCEFZXARDFPFP42.webp)

下一步是可选的，将默认选中的Debug改为MinSizeRel，可以提高编译LLVM时的速度、减少编译产物的体积、提高LLVM的运行速度，但是如果后续是要进行LLVM本体魔改或者Pass开发的话，建议保持Debug不变

![图片描述](upload/attach/202312/684293_Z7WMQ63PKNDJ5TZ.webp)

然后点击生成=>生成解决方案，开始漫长的等待，以这台i5-12500的机子为例，编译MinSizeRel耗时大概半小时

![图片描述](upload/attach/202312/684293_AANHFC42GJDZ3PE.webp)

在对应目录下可以找到生成的可执行文件，我们将该目录添加到环境变量中

![图片描述](upload/attach/202312/684293_NRQPJCRACYHWT3A.webp)

在VSCode的命令行中测试一下版本，确定是16.0.6

![图片描述](upload/attach/202312/684293_E7RNYHSKDXCB6ZG.webp)

编写一个C++测试程序

![图片描述](upload/attach/202312/684293_UQT2NJ3KAU5DSTT.webp)

使用`clang++`编译后运行，可以看到正确的输出

![图片描述](upload/attach/202312/684293_Z77M9ZZD9ZWYSYG.webp)

## 结语

到此为止，我们已经成功的编译了LLVM

当然我们的目的肯定不是仅仅编译一下而已（不然为啥不用VS2022自带的），更多的是对LLVM的前端、中端和后端进行魔改，或者编写自己的Pass，最后将其整合到MSBuild工具链中

得益于VS2022强大的解决方案，我们可以很轻松、很方便的对整个LLVM项目进行修改和增量编译
