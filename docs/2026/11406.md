其中关键的代码，也就是写入 jmp的代码如图：

![](https://bbs.kanxue.com/upload/attach/201207/236210_rwlbdxlfe7kbn3u.jpg)
原理是声明2个 \_JMPCODE的结构，\_JMPCODE如下：

```
typedef struct _JMPCODE
{
	BYTE E9;
	ULONG JMPADDR;//88881234=B
}JMPCODE,*PJMPCODE;
```


一个是指针pcur，一个是JmpCode，然后将要写入的地址填入pcur中，要写入的跳转代码写入JmpCode中，然后用JmpCode的值写入pcur指向的地址中

可能是我水平有限，说得很绕，不知大家是什么感觉，我当是看完后感觉很绕，可能是我的C++学得太差。如果这段代码用汇编来实现，将是异常的简单明了，也不用去声明什么\_JMPCODE的结构，当然这里不是说郁金香老师写的不好，只是说用C和C++来操作内存总存在一些不足。

```
NTSTATUS VK_WriteSSDT(ULONG WriteAddr, ULONG  JmpAddr)
{
	ULONG JmpCode= JmpAddr - WriteAddr -5;				//得到要写入的跳转地址码
	DbgPrint("要写入的地址为：%x\n", JmpCode);
	_asm
	{
		pushad
			cli
			mov	eax, cr0
			and	eax, 0FFFEFFFFh
			mov  cr0, eax

			mov	eax, JmpCode
			mov	ebx, WriteAddr
			mov	[ebx], 0E9h
			inc	ebx
			mov	[ebx], eax

			mov eax, cr0
			or	eax, 10000h
			mov	cr0, eax
			sti

		popad
	}
	return STATUS_SUCCESS;
}
```


WriteAddr是我们要写入的地址，这里我们就是SSDT中被Hook了的地址，JmpAddr是我们要跳转的地址，这里就是我们源 NTOpenProcess 的地址。
JmpCode= JmpAddr - WriteAddr -5
通过这样一个简单的计算我们就得到了要写入的跳转地址的机器码

```
mov	eax, JmpCode
mov	ebx, WriteAddr          ;将要写入的地址放入ebx
mov	[ebx], 0E9h             ;写入 'jmp' 的机器码
inc	ebx                     ;将ebx+1，指向下一字节
mov	[ebx], eax              ;写入跳转地址的机器码
```



是不是很简单，几行代码就替代了原C++要写的绕来绕去的代码

这里我将郁金香老师的代码优化了下，将写入JMP代码的函数（VK\_WriteSSDT）、绕开Hook的函数（VK\_UnHookSSDT）、以及得到当前SSDT函数地址的函数（VK\_GetCurrentProcAddr）都分开写了，这样的目的是为了这套代码可以对任何被Hook的内核函数都通用，我们只要改写我们要绕过的内核函数的名称和索引号部分。

```
	SSDT_NTOpenProcess_Index=122;
	RtlInitUnicodeString(&NTOpenProcess_Name, L"NtOpenProcess");
	VK_UnHookSSDT(&NTOpenProcess_Name, SSDT_NTOpenProcess_Index);
```



下面是测试，我们要用到上一篇“[汇编与驱动-采用SSDT Hook NtOpenProcess保护进程](http://bbs.pediy.com/showthread.php?t=153176)”帖子的两个程序
1、将SSDTHook\_NtOpenProcess.sys和SSDTHook\_NtOpenProcess.exe放入虚拟机中，用monitor加载SSDTHook\_NtOpenProcess.sys驱动并运行

2、运行SSDTHook\_NtOpenProcess.exe，输入一个你想Hook的进程的PID，然后点击“Hook”按钮，这样就将NTOpenProcess Hook掉了
![](https://bbs.kanxue.com/upload/attach/201207/236210_ax8wlou4dgq2jx2.jpg)
3、我们打开Kernel Detective 点击SSDT验证一下，可以看到我们的NtOpenProcess已经被Hook掉了，用CE，OD都附加不了我们保护的进程
![](https://bbs.kanxue.com/upload/attach/201207/236210_f5mogx17r1jfddy.jpg)
4、这时我们不要点击“UnHook”按钮，用monitor加载ReadSSDT.sys，运行，monitor提示"NTOpenProcess已被绕过，可以正常使用"，这时monitor你一堆的"进入MyNtOpenProcess"立即停止了，说明我们已经反Hook成功
![](https://bbs.kanxue.com/upload/attach/201207/236210_t1xrhtzv417sarw.jpg)
5、这时我们再用Kernel Detective打开 SSDT验证一下，发现NTOpenProcess仍是被Hook的，我们点击NTOpenProcess当前被Hook的地址反汇编一下，就会看到我们的 "jmp NtOpenProcess"代码，说明我们写入是成功的
![](https://bbs.kanxue.com/upload/attach/201207/236210_du93rnr8hrn4jw2.jpg)
