运行时改变代码，好，那就OD看下

跟进call，
![](https://bbs.kanxue.com/upload/attach/202002/742286_4eo1rxvil59x5oc.png)
这里看到了sub\_404689，功能很简单，把input+=1，这个函数在dialogfunc那里也有调用
F7走起，
![](https://bbs.kanxue.com/upload/attach/202002/742286_86eje9qpubvwv5s.png)
再F7，
![](https://bbs.kanxue.com/upload/attach/202002/742286_oqikiiqlc33tcb8.png)

![](https://bbs.kanxue.com/upload/attach/202002/742286_6ws56g3y9es8efa.png)

到了这个地方，就是把input增加0x601605c7，可能会溢出，但是无所谓，取余一下就好
下面一点指令貌似没什么用，因为没对input有什么影响，走到下面的call，又会inc input两次，最后retn会返回到dialogproc
![](https://bbs.kanxue.com/upload/attach/202002/742286_ialxrvejogmza76.png)
所以这个函数在被后面的指令修改之前，干了一件事，把input +2 +
0x601605c7 +2
确认一下，我输入的是20192019，所以
>>> hex(20192019+2+2+0x601605c7)
'0x614a20de'
如数据窗口所示，数是反过来的是因为little endian
![](https://bbs.kanxue.com/upload/attach/202002/742286_m07hs99gp08eq54.png)
返回那个函数(change\_f)之后(在xor eax,eax那里)，被修改过的input被mov到了eax中，然后又调用一次inc\_input，然后修改change\_f函数的函数头，在call change\_f那里F7进去，发现汇编被修改成了
![](https://bbs.kanxue.com/upload/attach/202002/742286_knassaconoxbfux.png)
[eax]=0x90，注意此时eax的值，其实就是
input +2 +
0x601605c7 +2
，所以随便输一个数会崩溃，因为访问了无效的内存地址
返回后inc eax，然后再调用一次被修改后的change\_f
0x90，是不是很熟悉？没错，就是nop，再看看IDA的代码，有一个疑似成功的代码段

但是没有任何jmp之类的跳转到这里，空格看看，上面有个jmp short(刚好两个字节)，
![](https://bbs.kanxue.com/upload/attach/202002/742286_yydardcfdaiaoty.png)
很明显了，这道题就是要通过这个mov byte ds:[eax], 0x90来nop掉那个jmp short，所以
input + 2 +
0x601605c7 + 2 = 那个jmp short的地址。
考虑到整数溢出，所以用C，
//input + 2 + 0x601605c7 + 2 == 0x00401071

unsigned int getinput()
{
    return 0x00401071/\*jmp short 地址\*/ - 4 - 0x601605c7;
}

int main()
{
    printf("%u\n", getinput());
    system("pause");
}//\*/
