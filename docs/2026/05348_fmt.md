
# [原创]某道游戏任务二叉树组分析

## 一：先把分析好的任务结构图放出来

![](https://bbs.kanxue.com/upload/attach/201507/581282_ev4kfwbtpdkla2h.jpg)

其中有两点要说：

1. 任务的对象组成了一个数组，比如里面的任务一、任务二
2. 任务一、任务二各自指向了一颗树
3. 对于这两颗树
    - a) 右子树里面放了任务的属性名字，比如任务类型、提示等等，太多图中没有画完
    - b) 左子树，就是对应属性的数据，比如任务类型的具体数据、提示的具体数据

## 二：从什么地方入手

1. 假设我们需要写一个游戏，一个游戏任务包含哪些部分了，大致如下：

    - a. 任务ID，主要发给服务端进行交接做任务的
    - b. 任务类型，一个任务是杀怪任务还是传对话任务（跑环，让你到某个NPC旁边）
    - c. 任务描述，这个没什么好介绍了
    - d. 任务数量
    - e. 任务提示
    - f. 杀怪或者打怪任务计数器

2. 这里我们从任务描述入手（需找王老板）

![](https://bbs.kanxue.com/upload/attach/201507/581282_6jfbgofwj865u8x.png)

3. 重新打开游戏，会发现，其中`0e1c4b60`这个文本又变回来了

![](https://bbs.kanxue.com/upload/attach/201507/581282_0x376uns8avrgor.png)

4. 这个地址`0e1c4b60`，就是我们重点研究的对象了

## 三：开始分析

1. 对地址`0e1c4b60`，下硬件写入断点

![](https://bbs.kanxue.com/upload/attach/201507/581282_1iqhyrsnaemeklx.png)

2. 这里被断下，但是在系统，但是在`msvcr80`中

![](https://bbs.kanxue.com/upload/attach/201507/581282_8y9kq3hlmik3vmy.png)

其中`EDI`的信息，就是我们在`CE`中搜索到的

![](https://bbs.kanxue.com/upload/attach/201507/581282_xzl9p3b920fghsi.png)

3. Alt+F9到游戏领空，其中`ECX`和上面系统领空地址一样，`E1C4B58`

![](https://bbs.kanxue.com/upload/attach/201507/581282_v72dy034q1js27y.png)

4. 继续往上一层，Alt+F9，就在函数`00666e30`中，中间单步一遍，发现，上面`eax`的来源一个call

![](https://bbs.kanxue.com/upload/attach/201507/581282_jesmrdcpszub6z3.png)

单步一遍发现，中间`call 006D8920`，中返回了步骤3中的`eax`和`ecx`的值

![](https://bbs.kanxue.com/upload/attach/201507/581282_q61t85dop575a5g.png)

5. 现在要重点分析`006D8920`，这个是thiscall，通过`eax`返回

![](https://bbs.kanxue.com/upload/attach/201507/581282_ji5sc4h2yimy1lk.png)

`esi`来源，是函数`006d8920`这个函数局部变量赋值：

![](https://bbs.kanxue.com/upload/attach/201507/581282_clrrrtq1794gn8r.png)

我们要找到类似`lea xxx, dword ptr [esp + 18]`

![](https://bbs.kanxue.com/upload/attach/201507/581282_nu3g0pvaiva89j9.png)

6. 现在需要分析`call 005107f0`，中怎么对`ecx`进行操作的

第5步中的`esp + 18`对应的地址在`call 005107f0`中的操作是，`mov [eax + 4], ecx`

![](https://bbs.kanxue.com/upload/attach/201507/581282_762nj156hnnivhe.png)

所以需要取`ecx`的来源，根据分析`ecx = [esp + 18]`, `[esp + 18] = eax`

![](https://bbs.kanxue.com/upload/attach/201507/581282_24sjym9fqudf1i6.png)

所以需要取`eax`的来源，`eax`来着`call 004d7ae0`

![](https://bbs.kanxue.com/upload/attach/201507/581282_y8q7jugkw9l3xyh.png)

7. 现在需要分析`call 004d7ae0`，这个也是这个游戏中一个通用的二叉树，这个函数也对应我在上面贴出的第一图中的树

我们需要关注`eax`的来源，所以进入`call 004d7ae0`中查看，来源于`edi`：

![](https://bbs.kanxue.com/upload/attach/201507/581282_s30dxytn7qy7gbf.png)

其中`EDI`来自循环中活动，上图中`004d7b1B` ~ `004d7b00`就是这个循环代码，是个`Do-While`循环，用c语言描述如下：

![](https://bbs.kanxue.com/upload/attach/201507/581282_wus11g0fvzo2f35.png)

这个循环参与运算所有的数据来源于`esi`，需要取`esi`的数据，所有数据来源于`ecx`

![](https://bbs.kanxue.com/upload/attach/201507/581282_y6wskijv68oha7n.png)

这个`ecx`来自上层的的`ecx`，向上一层：

需要继续往上，查找`ecx`的来源

![](https://bbs.kanxue.com/upload/attach/201507/581282_8glcgp44myroim7.png)

需要继续查找，`ecx`的来源，来源`edi`

![](https://bbs.kanxue.com/upload/attach/201507/581282_5j1a3vfgnse1oi2.png)

## 三：总结下

1. 分析上面的数据是个苦逼的过程，只所以写下是为了再次整理一遍，下次遇到类似问题时候能够快速解决

2. 分析数据时候，需要从程序的设计角度去看问题，一定要明白自己在干什么

3. 从逆向的角度来看一个游戏，一般分为三层，数据层、显示层、交换层

    - i. 数据层，客户端从服务端请求来的数据或者自有数据
    - ii. 显示层，比如场景、角色面板之类的
    - iii. 一块逻辑代码，取数据层的代码，然后经过一系列操作放到显示层上去，玩家可以看到
    - iv. 一般逆向，都希望拿到数据层的数据，这块东西是最靠谱的

4. 逆向时候一般比较惬意的分析过程是这样的：显示层 -> 交换层 -> 数据层

    - i. 如果在交换层VM，数据层都是加密数据，就可以加大逆向的分析的难度
