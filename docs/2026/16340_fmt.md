## 2.2 常用命令行工具

### 2.2.1 `adb`

Android 调试桥（`adb`）全称为 Android Debug Bridge，是一种功能多样的命令行工具，可让使用者与目标设备进行通信。`adb` 命令还可进行各种设备操作（例如安装和调试应用），并提供对 Unix shell（可用来在设备上运行各种命令）的访问权限。

`adb` 命令语法格式如下：

```
adb [ -d | -e | -s <deviceId>] <command>
```

参数具体含义如下：

![图片描述](upload/attach/202306/452101_ETKYBHG8USTUMHE.png)

当仅有一个设备连接时，命令中可以不指定 `[-d|-e|-s <serial-number>]` 参数，直接使用 `adb <command>` 的方式进行操作。连接多个设备时，常见的方法是通过 `-s <deviceId>` 参数指定待连接的设备。

如果和目标设备在同一局域网，可以通过 IP 加端口的方式连接到目标设备。

```
adb connect host_ip[:port]
```

可以通过 `adb devices` 命令查看当前已经连接的设备：

```
$ adb devices
List of devices attached
rsnvs87d5dgewt device
a38b2e8 device
emulator-5554 device
```

这种场景下如果想指定 `a38b2e8` 设备来运行 `adb` 命令，可以采用 `-s <deviceId>` 的方式：

```
adb -s a38b2e8 install demo.apk
```

通过 `adb` 查看目标设备应用列表的基本命令格式是：

```
adb shell pm list packages [-f|-d|-e|-s|-3|-i|-u] [--user USER_ID] [FILTER]
```

![图片描述](upload/attach/202306/452101_JADUZQ96727795E.png)

查看目标设备上安装的所有应用：

```
adb shell pm list packages
```

查看目标设备上安装的系统应用：

```
adb shell pm list packages -s
```

查看目标设备上用户自己安装的应用：

```
adb shell pm list packages -3
```

查看目标设备上包名中含有指定字符的应用：

```
adb shell pm list packages 'test'
```

`adb` 配合 `am <command>` 命令可以实现与目标应用的交互，常用命令如下图所示：

![图片描述](upload/attach/202306/452101_NM5KNVCBMYNTWCX.png)

启动一个应用，命令格式如下所示：

```
adb shell am start -n com.test.demo/com.test.demo.activity
```

注意：可以用 debug 方式启动应用（`am start -D -n`）。特别在反编译调试应用的时候，可能需要用 debug 方式启动应用。

启动指定的 Service 服务，具体命令如下所示：

```
adb shell am startservice -n com.test.demo/com.test.demo.service
```

发送一个指定的广播，具体命令如下所示：

```
adb shell am broadcast -a android.NET.conn.CONNECTIVITY_CHANGE
```

强制停止指定报名的应用，具体命令如下所示：

```
adb shell am force-stop com.test.demo
```

`adb` 除了可以和应用交互外，还可以配合 `input` 命令模拟更多的用户行为，例如按键行为和输入行为。模拟按键行为的命令如下：

```
adb shell input keyevent <keycode>
```

经常使用的 `keycode` 如下表所示：

![图片描述](upload/attach/202306/452101_8HSDVV946ZEWNM6.png)

模拟用户滑动行为，具体命令如下图所示：

```
adb shell input swipe 500 300 100 300
```

代码含义模拟用户向左滑动屏幕。参数 `500 300 100 300`，分别表示起始点 x 坐标、起始点 y 坐标、结束点 x 坐标和结束点 y 坐标。

模拟用户点击屏幕的行为，具体命令如下图所示：

```
adb shell input tap 100 300
```

代码含义模拟用户向单击屏幕。参数 `100 300` 分别表示点击位置的 x 坐标和 y 坐标。

#### 其他常用命令

查看当前应用的 Activity 组件信息：

```
adb shell dumpsys activity top
```

查看指定包名应用的详细信息：

```
adb shell dumpsys [packagename]
```

查看指定进程名或者进程 ID 的内存信息：

```
adb shell dumpsys meminfo [packagename/pid]
```

可以查看指定包名应用的数据库存储信息：

```
adb shell dumpsys dbinfo [packagename]
```

重启进入到 bootloader，即刷机模式：

```
adb reboot bootloader
```

重启进入 recovery，即恢复模式：

```
adb reboot recovery
```

### 2.2.4 `Clutch`

iOS 正常只能通过 App Store 下载安装应用，要想对应用进行分析，只能从目标设备上导出目标应用的 IPA 包。苹果为了保护开发者的权益，使用了数字版权加密技术对 IPA 包进行了保护，直接导出的 IPA 包内容无法直接进行分析。如果要想对 IPA 文件进行分析，就需要对其进行解密，也就是人们通常说的砸壳。

`Clutch` 是一款便捷的工具解密工具，支持 iPhone、iPod Touch 和 iPad，以及所有 iOS 版本、架构类型和大多数二进制文件。不管应用如何加密，运行的时候总要解密，`Clutch` 就是在应用运行时将内存数据按照一定格式导出。

`Clutch` 的源码是在 GitHub 开源的，可以自己下载编译。下载源码后可以将项目导入到 Xcode 中编译，也可以通过命令行的方式进行编译。在这里将展示通过命令行的方式编译 `Clutch`。首先安装编译所需环境和下载工具源码，具体如下图所示：

```
xcode-select --install // 安装编译所需的 command line tools
git clone https://github.com/KJCracks/Clutch.git // 下载工具源码
```

开始正式编译，具体命令如下图所示：

```
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=../cmake/iphoneos.toolchain.cmake ..
make
```

通过 `scp` 命令将编译好的 `Clutch` 安装到目标设备，具体命令如下：

```
scp ./build/Clutch root@<your.device.ip>:/usr/bin/Clutch
```

通过 `ssh` 的方式连接目标设备，在命令行中输入 `Clutch` 即可查看该工具的所有功能，如下图所示。

![图片描述](upload/attach/202306/452101_Q997WNGWJAVCHRH.png)

查看目标设备上安装的应用清单，具体命令如下图所示：

```
iPhone:~ root# Clutch -i
Installed apps:
1: TextDemo <com.test.dump>
2: TextDemo2 <com.test2.dump>
3: TextDemo3 <com.test3.dump>
```

对选中的目标应用进行砸壳操作，具体命令如下图所示：

```
iPhone:~ root# Clutch -d 2 // 数字 2 即上一步中应用对应的序号
```

至此已经完成砸壳操作，砸壳后的应用通常会存在此目录下 `/private/var/mobile/Documents/Dumped`。

### 2.2.4 `Clutch`

`iOS`正常只能通过App Store下载安装应用，要想对应用进行分析只能从目标设备上导出目标应用的`IPA`包。苹果为了保护开发者的权益使用了数字版权加密技术对`IPA`包进行了保护，直接导出的`IPA`包内容是无法直接进行分析。如果要想对`IPA`文件进行分析就需要对其进行解密，也就是人们通常说的砸壳。

`Clutch`是一款便捷的解密工具，支持 iPhone、iPod Touch和iPad以及所有iOS版本、架构类型和大多数二进制文件。不管应用如何加密，运行的时候总要解密，`Clutch`就是在应用运行时，将内存数据按照一定格式导出。




Clutch 的源码在 GitHub 上开源，可以自行下载编译。下载源码后，可以将项目导入到 Xcode 中编译，也可以通过命令行的方式进行编译。下面将展示通过命令行的方式编译 Clutch。首先安装编译所需环境和下载工具源码，具体如下：

```bash
# 安装编译所需的 command line tools
xcode-select --install

# 下载工具源码
git clone https://github.com/KJCracks/Clutch.git
```

开始正式编译，具体命令如下：

```bash
mkdir build && cd build
cmake -DCMAKE_BUILD_TYPE=Release -DCMAKE_TOOLCHAIN_FILE=../cmake/iphoneos.toolchain.cmake ..
make
```

通过 `scp` 命令将编译好的 Clutch 安装到目标设备，具体命令如下：

```bash
scp ./build/Clutch root@<your.device.ip>:/usr/bin/Clutch
```

通过 `ssh` 的方式连接目标设备，在命令行中输入 `Clutch` 即可查看该工具的所有功能，如下图所示。

![图片描述](https://bbs.kanxue.com/upload/attach/202306/452101_Q997WNGWJAVCHRH.png)

查看目标设备上安装的应用清单，具体命令如下：

```text
iPhone:~ root# Clutch -i
Installed apps:
1:   TextDemo <com.test.dump>
2:   TextDemo2 <com.test2.dump>
3:   TextDemo3 <com.test3.dump>
```

对选中的目标应用进行砸壳操作，具体命令如下：

```bash
iPhone:~ root# Clutch -d 2
```

其中，数字 `2` 即上一步中应用对应的序号。

至此已经完成砸壳操作，砸壳后的应用通常会存在此目录下：

`/private/var/mobile/Documents/Dumped`

### 2.2.5 Class-dump

`Class-dump` 可以将砸壳后的 IPA 文件中的头文件导出。逆向分析 iOS 应用时，根据头文件中声明的函数名或者变量名，可极大地提高分析速度。

`Class-dump` 的官方版本因太久未维护，对 Objective-C 2.0 和 Swift 开发的应用支持得不够友好。一些开发者基于官方版本进行了修改，可以很好地支持 Objective-C 2.0 和 Swift 开发的应用。虽然 `Class-dump` 出现了许多修改版，但是使用方法、功能与官方版本依然保持一致。本章节将使用官方版本进行讲解。

在官网 `https://bbs.kanxue.com` 下载 `class-dump-3.5.dmg` 文件，双击打开后，将里面的 `class-dump` 文件复制到 `/usr/local/bin/` 目录下。这样就可以直接在终端的命令行中使用 `class-dump` 命令。

![图片描述](https://bbs.kanxue.com/upload/attach/202306/452101_ENSUCKT85XTTP9D.png)

通过 `class-dump` 工具将应用的 Header 信息输出在终端，具体命令如下：

```bash
class-dump TestDemo.app
```

输出结果如下图所示：

![图片描述](https://bbs.kanxue.com/upload/attach/202306/452101_EP7DASXR3Z7URW2.png)

正常情况下，目标应用中会存在大量的函数，如果将结果输出在终端，不方便查看。`Class-dump` 提供了将结果输出到指定目录的功能，具体命令如下：

```bash
class-dump -H TestDemo.app -o Headers
```
