
# [原创]DXF公告Call分析

既然要分析公告Call，肯定是要找到某个插入点的。

![](upload/attach/202009/587180_6UPP5TBK6KUQTT8.jpg)

公告嘛那肯定是从公告的内容入手的，但是存着内容的地址，发完它就释放了，所以嘛我就找到了技能冷却的提示公告。那玩会儿固定一个模板“技能冷却时间还剩xxxx”。我感觉就是`sprintf(str,"技能冷却时间还剩%.*f秒",time)`;不对别喷我。

那就用`ce`搜

![](upload/attach/202009/587180_FSANV55VN8ADVB6.png)

它这不就出来了，记住地址，打开`x64dbg`，给它整个访问断点

![图片描述](upload/attach/202009/587180_TX49CD8XH8WHCEY.png)

断下了猜一猜就完事了，别整那些没用的分析。这里访问了模板,然后再取冷却时间,然后步过某个`call`肯定就合一块了。`F8`就完事.

经过了一堆循环(八成再算冷却时间)，来到了这里

![图片描述](upload/attach/202009/587180_XUP3TNGCWXD72T9.png)

再往下走就返回了，上面刚循环完，走了这个`call`，然后把值给`ebx`。看看`ebx`

![图片描述](upload/attach/202009/587180_DM8J8WG2D9MRHTB.png)

没茅台。然后就取到了公告`call`的公告内容，给它整个访问断点

![图片描述](upload/attach/202009/587180_P75AGSY5XM498VN.png)

`oj8k`。这里就是公告`call`了。

![](upload/attach/202009/587180_6UPP5TBK6KUQTT8.jpg)

众所周知，公告`call`前面能带个图标，而我就喜欢花里胡哨，所以安排

![图片描述](upload/attach/202009/587180_T6GTQBSDFAYS2KJ.png)

就从这个公会公告入手。`call`头部下个断返回上一层。

![图片描述](upload/attach/202009/587180_W2W62KS2G7Z74QN.png)

众所周知`fastcall`传参顺序是`rcx` `rdx` `r8` `r9`。那咱重点看这几个寄存器就完事了

`rcx`来源`rax`,`rax`来源于上面`call`里的[`rcx+a0`],而`rcx`来源于全局变量的值

![图片描述](upload/attach/202009/587180_W9NY5PJCSA36E7M.png)

所以`rcx = [[基址]+A0]`

再看`rdx`,`rdx`来源`ebp`的值

往上嫖了一眼，发现上面还有句`lea rcx,[ebp]`,然后再执行了个`call`

进去看看

![图片描述](upload/attach/202009/587180_B8HUR36GDYWDCX9.png)
