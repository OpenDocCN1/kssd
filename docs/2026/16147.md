## sign算法
先通过JEB定位sign算法的地方，发现这个函数最终还是调用了so里面的函数：
![](upload/attach/202102/651413\_2PFUNWF9TDAMPP4.png)
先用frida hook该函数，打印下日志，看看传参是啥，脚本如下：
```
Java.perform(function () {
var Encryption = Java.use('com.qimao.qmsdk.tools.encryption.Encryption');
Encryption.sign.implementation = function () {
var s = arguments[0];
var r = this.sign(s)
send('sign: '+s+' result: '+r);
return r;
}
});
```
很明显，传入的是HTTP的get或者post参数，参数key按升序排列。
![](upload/attach/202102/651413\_SJM7NVNVVPA2S7K.png)
为了分析sign算法，定位到了so里面的处理逻辑，把key append到字符串结尾，再求md5
![](upload/attach/202102/651413\_9DZR6BTZ9JSB99Q.png)
这里我直接在memcpy打个断点，用IDA连上去查看key，当然也可以继续用frida hook。
![](upload/attach/202102/651413\_96FME5DWS4TKZ5U.png)
好的，现在已经成功获取到sign的key，直接写出相关sign算法如下：
```
def getsign(param\_dict):
sign\_key='d3dGiJ\*\*\*\*\*\*\*\*\*\*'
before\_sign = '';
for key in sorted(param\_dict):
before\_sign += f'{key}={str(param\_dict[key])}'
before\_sign+=sign\_key
sign=MD5.new(before\_sign.encode('utf8')).hexdigest()
return sign
```
## 小说数据解密
搞定了sign算法之后，开始分析小说数据的解密算法。
解密算法也在so里面，但是回调了java层里面的AES解密算法
![](upload/attach/202102/651413\_S3R8YTAQNU8GXRA.png)
java算法如下，把数据base64解密后，取前16个字节作为IV，传入的key直接作为AES-CBC的解密密钥进行解密：
![](upload/attach/202102/651413\_XWBDZWR5NR93URT.png)
这里继续用frida hook：
```
Java.perform(function () {
var AESManager = Java.use('com.km.encryption.aes.AESManager');
AESManager.decrypt.overload('java.lang.String', 'java.lang.String').implementation = function () {
var s = arguments[0];
var k = arguments[1];
var r = this.decrypt(s,k)
send('decrpt book: '+s+' key: '+k);
return r;
}
});
```
通过日志直接获取aes解密密钥，经过测试，不同的小说解密密钥都是一样的：
![](upload/attach/202102/651413\_JBVQ3CH5FDE5KR3.png)
解密算法如下：
```
def decrypt\_chapter(s):
aes\_key=b'242ccb\*\*\*\*\*\*\*\*\*\*'
iv\_enc\_data=base64.b64decode(s)
aes\_iv=iv\_enc\_data[0:16]
enc\_data=iv\_enc\_data[16:]
unpad = lambda s: s[:-ord(s[len(s) - 1:])]
aes=AES.new(aes\_key,AES.MODE\_CBC,aes\_iv)
return unpad(aes.decrypt(enc\_data))
```
