
# 加密哈希函数的生命周期

关于使用加密哈希函数来创建基于内容的哈希地址（比较哈希），我写了一些警告性的文章。这个页面汇集了我写的所有内容，并维持了一个实时更新的流行加密散列函数表。

我对比较哈希的建议：如果你正在使用比较哈希来为数据生成哈希地址，而这些数据由可以由恶意用户提供的话，那么你就应该有个计划，每隔几年就要迁移到一个新的哈希。比如说：BitTorrent就需要，而rsync就不用。一定要记住，新的、更安全的哈希可能会有更大的输出（比如SHA-2有256bit，SHA-1有160bit），而且会耗费更多的计算机资源。

发表在[Hot Topics in Operating Systems 2003](https://bbs.kanxue.com/elink@1eeK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6i4g2K6k6h3&6A6P5q4)9J5k6h3!0J5k6#2)9J5c8X3g2$3k6h3&6@1M7#2)9J5c8X3S2G2N6r3!0K6x3o6y4Q4x3V1j5`.)的一篇论文关于比较哈希的分析（[An Analysis of Compare-by-hash](https://bbs.kanxue.com/elink@026K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4k6S2L8r3g2J5K9h3g2S2N6i4u0G2M7X3q4Q4x3X3g2G2M7X3N6Q4x3V1k6J5k6i4k6A6k6i4N6Q4x3V1k6Z5j5i4y4Z5i4K6u0W2K9s2c8E0L8l9`.`.) ）就对用比较哈希来一切问题提出了质疑。

发表在LinuxWorld的文章：程序员加密哈希函数指南（[The code monkey's guide to cryptographic hash functions](https://bbs.kanxue.com/elink@5b2K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4k6S2L8r3g2J5K9h3g2S2N6i4u0G2M7X3q4Q4x3X3g2G2M7X3N6Q4x3V1k6E0L8$3&6C8k6i4W2Q4x3X3g2Z5N6r3#2D9) ）为程序员提供了实用的建议，还附加了流行哈希函数生命周期的表格（下面转载了过来）。
