#### Address Translation

##### Now that you’ve seen how Windows structures the virtual address space, let’s look at how it maps these address spaces to real physical pages. User applications and system code reference virtual addresses. This section starts with a detailed description of 32-bit x86 address translation (in both non-PAE and PAE modes) and continues with a brief description of the differences on the 64-bit IA64 and x64  platforms. In the next section, we'll describe what happens when such a translation doesn't resolve to a physical memory address (paging)  and explain how Windows manages physical memory via working sets and the page frame database.

#### 地址翻译

##### 现在你已看过 Windows 如何组织虚拟地址空间，我们再来看看它如何将这些地址空间映射到真实的物理页面。用户程序和系统代码都引用虚拟地址。本节首先详细讨论 32 位的 x86 地址转换（包括非 PAE 和 PAE 模式——译注：PAE 即“物理地址扩展”），然后简要描述在 64 位的 IA64和 x64 平台上，地址转换有何不同。而在下一节，我们将探讨，当这种转换无法解析到一个物理内存地址（分页）的时候，会出现什么情况，并解释 Windows 如何通过工作集和页框数据库来管理物理内存。

#### x86 Virtual Address Translation

##### Using data structures the memory manager creates and maintains called page tables, the CPU translates virtual addresses into physical addresses. Each page of virtual address space is associated with a system-space structure called a page table entry (PTE), which contains the physical address to which the virtual one is mapped. For example, Figure 10-15 shows how three consecutive virtual pages might be mapped to three physically discontiguous pages on an x86 system.  There may not even be any PTEs for regions that have been marked as reserved or committed but never accessed,  because the page table itself might be allocated only when the first page fault occurs.

#### x86 虚拟地址翻译

##### 使用内存管理器创建和维护的数据结构称为页表，而 CPU 则把虚拟地址转换成物理地址。虚拟地址空间的每个页（虚拟页）都有一系统空间中的结构与其关联，叫做页表条目（PTE，有些文献译作“页表项”），其中包含虚拟地址映射到的物理地址。 举例来讲，图 10-15 描绘出，对于 x86 系统，三个连贯的虚拟页是如何被映射到三个物理上不连续的页面。 甚至对于标记为“保留/预定”，或者“已提交”，但尚未访问过的内存区域，可能也没有任何对应的 PTE 来描述，因为只有在发首次缺页异常（“page fault”直译为“页错误”，它的本质是“缺页”）的时候，才会分配页表自身，以存储这些 PTE。

##### The dashed line connecting the virtual pages to the PTEs in Figure 10-15 represents the indirect relationship between virtual pages and physical memory.

##### 图 10-15 中，连接虚拟页到 PTE 的虚线，表示虚拟页与物理内存的间接关系。

##### Note Even kernel-mode code (such as device drivers) cannot reference physical memory addresses directly, but it may do so indirectly by first creating virtual addresses mapped to them. For more information, see the memory descriptor list (MDL) support routines described in the WDK documentation.

##### 注意 甚至内核模式代码（譬如设备驱动程序），也不能直接引用物理内存地址，但它们可以通过首先创建映射到这些物理地址的虚拟地址，而后间接引用物理内存。更多信息请参考 WDK 文档中描述的“内存描述符列表（MDL）”支持例程。 （译注：我已经对关键 MDL 例程的 MSDN WDK 文档作了翻译，必要时会列出说明，以增进对原文相关内容的理解 ）

##### As mentioned previously, Windows on x86 can use either of two schemes for address translation:  non-PAE and PAE. We’ll discuss the non-PAE mode first and cover PAE in the next section. The PAE material does depend on the non-PAE material, so even if you are primarily interested in PAE, yo should study this section first. The description of x64 address translation similarly builds on the PAE information.

##### 如前所述，x86 上的 Windows 可以在两种地址转译方案：非 PAE 和 PAE 之间，任选其一来使用。我们将首先讨论非 PAE 模式，然后在下一节涵盖 PAE 模式。而 PAE 方案确实依赖于非 PAE 方案，即便你主要对 PAE 感兴趣， 也应该先学习完本节。 类似地，我们对 x64 地址翻译的描述也建立在 PAE 相关讨论的基础上。

##### Non-PAE x86 systems use a two-level page table structure to translate virtual to physical addresses. A 32-bit virtual address mapped by a normal 4-KB page is interpreted as two fields: the virtual page number and the byte within the page, called the byte offset. The virtual page number is further divided into two subfields, called the page directory index and the page table index, as illustrated in Figure 10-16. These two fields are used to locate entries in the page directory and in a pag table.

##### 非 PAE 的 x86 系统使用一个 2 级页表结构把虚拟地址转换成物理地址。一个 32 位的虚拟地址通过正常情况下，大小为 4KB 的页来映射（译注：前面部分译文讲过使用 64KB 大页面的场景，请复习一遍），该地址被解释为两个字段：所属的虚拟页号，以及在该页中的字节偏移。“虚拟页号”被进一步划分为两个子域，叫做“页目录索引”和“页表索引”，如图 10-16 所示。 这两个字段用于定位页目录和页表中的条目。
