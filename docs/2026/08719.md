
# [原创]win10 32位 过TP双机保护

之前通过看雪相关的过tp双机检测贴子未成功，特意看了下软件调试得出了以下结论：

```
调试器中断挂起分为2种情况，1是主动触发异常挂起 2是通过windbg发生数据包让操作系统自己中断挂起

其中第二种情况是否成功与多个全局变量相关，而第一种情况在win10 32位下只与KdpDebugRoutineSelect有关

以下是在软件调试::内核调试器中得到的相关消息

PsActiveProcessHead 指向进程链表

KdinitSystem->KdDebuggerInitialize1 初始化内核调试通信扩展DLL（KDCOMD.DLL等等）第二次调用

KdinitSystem会被执行两次
    第一次由ntosklnel.exe入口KiSystemStarup函数调用
    第二次由KiSystemStarup函数调用返回的新线程进入Phase1Initaliztion后内部调用

KdinitSystem第一次:只有0号cpu才会调用
    1、初始化调试器数据链表,使用变量kdpDebugerDataListHead指向这个链表
    2、初始化KdDebuggerDataBlock数据结构,该结构体包含了内核基地址，模块链表指针，调试器数据链表指针等相关数据,调试器通过该结构了解目标操作系统
    3、根据参数LOADER_PARAMETER_BLOCK结构寻找有关的选项,然后保存到变量中
    XP后系统:调用KdDebuggerInitalize0对通信模块进行第0阶段初始化,如果使用的是串行通信,那么KDCOM中的KdDebuggerInitalize0函数会调用模块内的KdCompInitialize函数初始化串口,初始成功后会设置HAL模块中所定义的KdComPortInUse全局变量,记录已被内核使用的COM端口
    4、KdPitchDebugger:BOOL 设TRUE,该变量用于表示是否抑制内核调试(当启用/NODEBUG选项时即设置为TRUE)
    5、KdDebuggerEnabled:BOOL 用于表示内核调试器是否已经被启用(当启动选项中包含/DEBUG或/DEBUGGPORT而且不包含NODEBUG会设TRUE)
    6、KiDebugRoutinr:函数指针 用于记录内核调试引起的异常处理回调函数,当内核调试器活动时,它指向KdpTrap函数,否则指向KdpSub函数
    7、KdpBreakpointTable: BREAKPOINT_ENTRY[]数组 用来记录代码断点
    8、KdpNextPacketIdtoSend(xp后:KdCompNextPacketIdToSend):ULONG 用于标识下一个发生数据包ID,KdinitSystem将这个变量设置为0x80800000|0x800 即INTTLAL_PACKET_ID(初始包) 或 SYNC_PACKET_ID(同步包)
    9、KdpPacketIdExpexced(xp后:KdcompPacketIdExpected) ULONG 用于表示期待收到的下一个数据包ID,初始化为0x80800000 即INTTLAL_PACKET_ID
    10、KdAutoEnableOnEvent(Vista后):BOOL 调试设置中启用AUTOENABLE设TRUE
    11、KdIgnoreUmExceptions(Vista后):BOOL 代表了用户态异常处理的方式 如果调试设置中启用了/NOUMEX 即设TRUE(忽略用户态异常)

KdinitSystem第二次:
    调用KeQueryRerformanceCounter对变量KdPerformanceCounterRate(性能计数器)初始化KdDebuggerDataBlock数据结构

中断到调试器:
    在调试引擎发生数据包前会调用KdEnterDebugger函数冻结内核,到收到调试器恢复指令后调用KdExitDebugger恢复内核运行

    KdEnterDebugger函数：
        call KerFreezeExecution,KeFreezeExecution,KeDisableInterrupts 提升IRQL 冻结其他所有CPU
        锁定调试通信端口通过KdpDebuggerLock全局变量获取
        将全局变量KdEnteredDebugger设置为TRUE

    KdExitDebugger函数:
        调用JdRestore恢复通信模块
        释放调试通信端口 KdpDebuggerLock全局变量获取
        调用KeThawExecution恢复正常运行状态
        KdEnteredDebugger = FALSE

    KeUpdateSystemTime函数会在每次更新系统时间时检测全局变量KdDebuggerEnabled 如果为TRUE则调用KdpollBreakIn函数来查看调试器是否发送了中断命令
    如果是,就调用DbgBerakPointWithStatus触发断点异常,以中断到调试器

    KdpTrap内核调试器回调试函数:会对断点指令异常,调试异常,和所有的二次异常会调用KdpReport向调试器报告异常,主要执行以下步骤
        1、调用KdEnterDebugger函数冻结内核其他部分
        2、调用KiSaveProcessorControlState保存处理的控制状态
        3、调用KdpRePortExceptionStateChange向调试器报告异常状态变化,这个函数后会等待和接受调试器指令,直到接受到恢复指令才继续执行下面步骤
        4、调用KiRestoreProcessorControlState恢复CPU状态
        5、调用KdExitDebugger恢复内核运行
```

## 处理的位置

- `KdPitchDebugger`：如未启用调试该值为1，启用调试该值为0，须将该值设1。只要该值设1，调试器就无法主动中断，与`KdDebuggerEnabled`一样原因，该值优先级大于`KdDebuggerEnabled`。
- `KdDebuggerEnabled`：表示内核调试器是否已经被启用（当启动选项中包含`/DEBUG`或`/DEBUGGPORT`而且不包含`/NODEBUG`会设`TRUE`）。移位处理，并设0，该值设0调试器无法主动中断，因为`KeUpdateSystemTime`函数会主动检测是否为1。
- `KiDebugRoutinr`：指向调试器回调（Win10下没有，Win7下存在）。存在调试器时它指向`KdpTrap`函数，否则指向`KdpSub`函数。指向`KdpSub`函数，Hook中断在进入异常流程前恢复指向。
- `KdpBreakpointTable`数组：记录异常断点。移位并清零，tp未检测。
- `KdEnteredDebugger`：中断到调试器标志，中断前会设1，恢复后会设0。
- `KdpDebugRoutineSelect`（Win10）：如果该值为1，异常处理时调用`KdpTrap`函数，否则调用`KdpSub`函数。必须设0，启动游戏前会检测，之后应将其设1，主动中断无法进入`KdpTrap`函数从而导致虚拟卡死。
- `KdpBreakpointTable`：用于记录断点，未检测。
- 断链`KDCOMD.DLL`。
