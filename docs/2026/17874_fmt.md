
# [原创]CVE-2012-1876漏洞分析

## 1. 分析环境

![](https://bbs.kanxue.com/upload/attach/201902/93_QB8UX8FF5WNP9FV.jpg)

## 2. 简述

`table`标签中`col`元素的`span`值被重新设置时未正确检查需要分配的缓冲区大小，并向堆中进行写入操作，若用户访问攻击者精心构造的页面，可能导致任意代码执行。

## 3. 分析过程

先用`gflag`给IE加上`hpa`，然后运行IE，用`Windbg`附加，开启子进程调试（`.childdbg 1`），打开POC，`+42F167`处崩溃，如下图所示：

![](https://bbs.kanxue.com/upload/attach/201902/93_U93QQWCFSA5DTGR.jpg)

可看到`edi`被污染，反汇编看下该函数，`edi`由`esi`赋值，而`esi`又由上层函数`CalculateMinMax`传递过来。

![](https://bbs.kanxue.com/upload/attach/201902/93_FQSMK8KXNRP2XAA.jpg)

重新附加IE，通过`sxe ld:mshtml`命令让子进程在加载`mshtml`模块时断下，然后再通过命令`bp mshtml!CTableLayout::CalculateMinMax`对漏洞函数下断。

![](https://bbs.kanxue.com/upload/attach/201902/93_3RBTGRBGZQEMDQV.jpg)

断下来后进行跟踪分析，可看到该函数的第一个参数为`CTableLayout`对象。

![](https://bbs.kanxue.com/upload/attach/201902/93_UDPW6G2D2NEK7SK.jpg)

继续跟踪，代码取出了`col`元素中的`span`值，我们这里称之为`spannum`，在后面的指令经常会用到。

![](https://bbs.kanxue.com/upload/attach/201902/93_VSX7AMFREQ6EZT6.jpg)

后面的指令非常多，单步跟踪太耗时，这里结合`IDA`进行分析，导入`windbg`下载的`pdb`文件后，找到`CalculateMinMax`函数。跳过部分指令，找到负责分配内存的函数，在分配前会取出一个值（为0）用于和`spannum`比较，我们称之为`spancmp`。

![](https://bbs.kanxue.com/upload/attach/201902/93_W6XVADF83P5DNA4.jpg)

跟进该函数，计算分配内存大小时为`spannum \* 0x1C`，至少为`4 \* 0x1C`，分配后的内存地址位于`CTableLayout+0x9C`（`ebx+0x9C`）。

![](https://bbs.kanxue.com/upload/attach/201902/93_8YG2W3TEEGMR9K4.jpg)

分配完内存后，运行，允许加载控件，再次在`CalculateMinMax`断下，再运行，断下来后才执行`poc`中的`over_trigger`函数，而《漏洞战争》一书中第二次运行就执行`over_trigger`函数，猜测是本地允许加载控件后重新解析`poc`的原因。

第二次断在`CalculateMinMax`后，`spannum`不变，`spancmp`为4，所以不再分配内存。

![](https://bbs.kanxue.com/upload/attach/201902/93_5TTFQMMYAPYFXN4.jpg)

在`mshtml!CTableCol::GetAAspan`下断点，使其在第二次获取`span`值时断下，然后用`gu`命令执行到返回后断下，获取的值为`0x3e8`（1000）。

![](https://bbs.kanxue.com/upload/attach/201902/93_DFZ6Z9GAC6CS24V.jpg)

继续执行，会计算`width \* 100`的结果`0x414114`作为循环复制的内容。

![](https://bbs.kanxue.com/upload/attach/201902/93_FHM5VV3K6UD685C.jpg)

然后将取出的`span`值`0x3e8`作为复制操作的计数器，书上写的计数器则为`0x3e8 \* 1C`，通过调试分析，`0x3e8 \* 1C`为拷贝的最大偏移地址，一开始还没拷贝时偏移为`0 \* 1C`，每次拷贝后偏移地址加`0x1C`，所以计数器为`0x3e8`，复制大小为`0x3e8 \* 0x1C`。

![](https://bbs.kanxue.com/upload/attach/201902/93_JVS3FVRVBEZKER6.jpg)

继续跟踪分析，可看到每次复制后会将已复制次数`[ebp-14h]`加1，然后跟最大复制次数`0x3e8`比较，而目标堆大小只有`0x70 < 0x3e8 \* 1C`，所以会触发异常。

![](https://bbs.kanxue.com/upload/attach/201902/93_WS4T4E5HXDMEDAG.jpg)

## 4. 漏洞利用

### 4.1 堆占位

通过申请大量的堆并释放，可让程序在申请可溢出堆时分配到前面释放的堆块，该堆块后面为`Button`的虚表指针。

![](https://bbs.kanxue.com/upload/attach/201902/93_GVYHHE7NP9CW6W3.jpg)

### 4.2 溢出得到虚表指针

将`span`值改为19以造成溢出，改写内容全为`B`字符的堆块的头部的长度字段，然后将虚拟地址读取出来并减去偏移得到基地址。

![](https://bbs.kanxue.com/upload/attach/201902/93_BS5KCH4JVGGZGDH.jpg)

![](https://bbs.kanxue.com/upload/attach/201902/93_WUZ6U9VRM53TDNG.jpg)

定位溢出块得先在`CollectGarbage`处下断点，断下来后在申请和释放的指令处进行记录并保存，指令如下：

```
.childdbg 1
sxe ld:jscript
bp jscript!JsCollectGarbage
bu ntdll!RtlFreeHeap ".echo free heap;db poi(esp+c) l10;g"
bu mshtml!ctablelayout::calculateminmax+0x16d ".echo vulheap;dd poi(ebx+9c) l4;g"
.logopen D:\log.txt
g
.logclose
```

可在修改`span`值前`alert()`一下，然后在后面输出的`vulheap`即为溢出块，日志如下，第一张图为申请的可溢出堆的地址，第二张图显示该地址刚被释放。

![](https://bbs.kanxue.com/upload/attach/201902/93_GVMJYFV6VQSHM8Q.jpg)

![](https://bbs.kanxue.com/upload/attach/201902/93_57CMNZYRKAMM3HU.jpg)

## 5. 再次溢出然后控制EIP

修改`width`为`1178993`，增加`span`值到44，再次溢出，覆盖虚表指针，变为`0x07070024`，后面会`call [eax+8]`，这样就能劫持`EIP`了。

![](https://bbs.kanxue.com/upload/attach/201902/93_P7MHD7MNWPBHVFM.jpg)

想要执行任意代码的话，需要构造`ROP`链，并结合堆喷技术将`ROP` + `shellcode`布置到劫持的`EIP`范围。
