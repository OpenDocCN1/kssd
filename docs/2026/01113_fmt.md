首先进行定义：`ExprId("c" + str(i), 8)`。

该定义类似于 `z3` 中的 `BitVec("c" + str(i), 8)`。

`dse.update_state` 这个东西传进去的是一个 `dict`，如这种形式：`dse.update_state({ExprMem(xxxx): ExpId('c1', 8)})`。

或者这样定义：

```
reg_ecx = ExprId("reg_ecx", 32)
regs = dse.ir_arch.arch.regs
dse.update_state({regs.ECX: reg_ecx})
```

这样我们就大概知道 `update_state` 就如其名一样，修改符号执行器现在的状态（内存状态或者寄存器的），表达式都是 `Expr` 类型的。

现在我们要将内存区间 `[0xCA138, 0xCA138+0x10)` 的 16 字节进行符号运行。

那怎么运行呢？反复查看例子，大概可以这样写：

```
update = {}
X = [0 for i in range(16)]
for i in range(16):
    X[i] = ExprId("c" + str(i), 8)
    update[ExprMem(ExprInt(i + 0xCA138, 32), 8)] = X[i]

dse.update_state(update)
```

地址是 32 位的，所以这样写 `ExprInt(i + 0xCA138, 32)`。需要注意的是，运算都需要在 `Expr` 中，然后再将其转化，因为 `ExprMem` 需要读取一个 32 位的 `ExprInt` 型；至于读几位 `Mem` 就根据情况了，比如现在定义的 `char`，所以定义成 `ExprMem(ExprInt(i + 0xCA138, 32), 8)`。

有点类似于汇编中的 `byte ds:[0xCA138 + i] = xxxx`；至于为什么不能弄成 `ExprMem(i + 0xCA138, 8)`，估计是开发考虑到不同的架构吧。

下面是打印执行后的结果，该结果在内存区间 `[ebp - 0xb4, ebp - 0xb4 + 0x10)` 中，打印方法如下：

```
    result = dse.eval_expr(ExprMem(ExprInt(i + jitter.cpu.EBP - 0xb4, 32), 8))
    print result
```

`eval_expr` 感觉有点类似 PHP `eval`，应该就是将表达式运行起来然后转化吧。

然后就是加限制条件进行求解了，写法如下：

```
r=[0x42, 0x45, 0x31, 0x43, 0x36, 0x43, 0x42, 0x31, 0x46, 0x31,
  0x36, 0x31, 0x36, 0x30, 0x38, 0x33]

for i in range(16):
    #addr = dse.symb.expr_simp(ExprInt(i+0xCA138, 32))
    result = dse.eval_expr(ExprMem(ExprInt(i+jitter.cpu.EBP - 0xb4, 32), 8))
    print result
    eaff = ExprAff(result, ExprInt(r[i], 8))
    dse.cur_solver.add(dse.z3_trans.from_expr(eaff))
```

首先把限制条件转换为 `ExprInt` 型，然后表达式相等用 `ExprAff`。然后 `z3_trans.from_expr` 转化为 `z3` 的表达式吧。最后的 `check` 和打印就类似于 `z3` 了。
