
# [原创]pwnable.kr uaf

Pwnable.kr之uaf

UAF漏洞的利用：

1. 先制造一个迷途指针
2. 利用我们构造的数据去填充被释放的内存
3. 再次使用该指针

![](https://bbs.kanxue.com/upload/attach/201811/798964_EUA6A2KH3RB3687.jpg)

`Human`中有两个虚函数，然后`human`就会有一个虚表，虚表会记录类中所有虚函数的函数指针，可以看到`human`里面有一个`system("/bin/sh")`；这就是我们利用的最终目的，但现在我们还没办法利用，我们接着往下看

![](https://bbs.kanxue.com/upload/attach/201811/798964_643T5B7ZYN6PNYK.jpg)

接着我们看到`man`类，他会继承父类的`vtable`（虚表），同时子类的`introduce()`的函数的地址会替换父类在`introduce()`在虚表中的位置。

![](https://bbs.kanxue.com/upload/attach/201811/798964_S3S8AYRKCMY9F85.jpg)

分析同上一步

![](https://bbs.kanxue.com/upload/attach/201811/798964_SBCRMN7CF7NRNGG.jpg)

这是主函数，如果我们依次输入`3 1`，程序会首先释放了`m`、`w`，接着又会去引用我们已经释放的对象，就造成了`uaf`漏洞，怎么利用呢？

我们看到`case2`，哪里会接收参数，首先接收长度参数和文件参数，并写入内存，我们可以利用这个写内存的操作去占我们释放操作的位置的内存，就可以利用了。接下来我们具体分析。
