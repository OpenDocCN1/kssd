## 分析过程

原始 apk 是非虫书上的例子 `debugjniso.apk`，加固的版本是找到的五月份加固的样本（能找到归功于做科研培养的良好的样本收藏习惯![](https://bbs.kanxue.com/view/img/face/12.gif)）。

### 1. 利用 APKTool 反编译

发现是可以的。

![](https://bbs.kanxue.com/upload/attach/201507/468931_t7nqcjauej6wxr5.png)

### 2. 解压后比较下加固前后文件夹

![](https://bbs.kanxue.com/upload/attach/201507/468931_r968r5dommtl7dz.png)

首先 `lib` 目录下增加了四个 `so` 文件，源 apk 中的 `libdebugjniso.so` 没改变，显然没对 `so` 进行加壳。

另外 `AndroidManifest.xml` 和 `dex` 文件改变了，估计留在外面的 `dex` 是壳，后面再分析这两个文件。

### 3. Dex2jar 生成 jar 包，jd-jui 打开查看

![](https://bbs.kanxue.com/upload/attach/201507/468931_s3445vxdgohbiiv.png)

这里只看到根据 CPU 类型加载不同的 `so` 库，arm 下是 `libmobisec.so`，x86 下是 `libmobisecx.so`，另外声明了两个 JNI 函数，`attachBaseContext` 和 `onCreate()`。

查看反编译后的 smali 代码，也确实是这样，`dex2jar` 没受到影响。

### 4. 安装运行，单进程

之前受梆梆加固多进程反调试荼毒太深。

### 5. 尝试附加

用 IDA attach 下试试，what？这样就附加上了？一定有阴谋。看看先~

### 6. Dump dex

不明觉厉，不管了，先试着 dump dex。

![](https://bbs.kanxue.com/upload/attach/201507/468931_0n02rwy26l27bg7.png)

然后找到应用进程，查看 `maps` 并 dump dex。

![](https://bbs.kanxue.com/upload/attach/201507/468931_slbnn1rsoopcvx9.png)

打开查看，找到了 `dey` 和 `dex`，好高兴，准备从里面取出 dex。

![](https://bbs.kanxue.com/upload/attach/201507/468931_afirqhwylajf1lw.png)

等等，不对啊，内存 dump 的这个 dex 和外面的 dex 壳很像呀，比较下还真是一样。

那真正的 dex 在哪里？回头查看刚才忽略的 `so`，发现 `libmobisecy.so` 其实不是一个 `so`，如图。

![](https://bbs.kanxue.com/upload/attach/201507/468931_tuukvkj547vwfjk.png)

用 IDA 打开发现，`libmobisecy.so` 其实是个存储了 dex 的 zip。

![](https://bbs.kanxue.com/upload/attach/201507/468931_smx5896z69oyf6g.png)

### 7. 解压 `libmobisecy.so` 并反编译 dex

解压 `libmobisecy.so` 后得到一个 dex，Baksmali 反编译，得到如下：

![](https://bbs.kanxue.com/upload/attach/201507/468931_pzx72wzgjzfmsnh.png)

对比源 apk 的 dex 反编译目录：

![](https://bbs.kanxue.com/upload/attach/201507/468931_sn2ckawheha0j51.png)

现在一个一个文件夹分析。

#### `android` 目录

先比较 `android` 目录，和预想的一样，加固前后没变化。

#### `a` 目录

分析 `a` 目录，里面就一个 `an.smali`，查看代码，发现了一个 `testdex2jarcrash` 函数，后来发现 `pnf` 里的 `exit.smali` 与 `an.smali` 是一样的。

看名字好像是用来干扰 dex2jar 的，验证了下还真是：

（下图是 so 中获取的 dex 转成 jar 查看，有 `testdex2jarcrash`）

![](https://bbs.kanxue.com/upload/attach/201507/468931_x10izgrxmwljo9i.png)

因此去除 `a` 目录和 `pnf` 目录（实验中发现其实只去除 `a` 目录即可，`pnf` 其实没影响，不知道为什么），效果如下：

![](https://bbs.kanxue.com/upload/attach/201507/468931_z16m83txovosrxg.png)

#### `pnf` 目录

Pnf 目录提过了，就不说了，不过路径很幽默，就是下面这个 —。—！

`xxx\pnf\this\boject\does\not\Exist.smali`

#### `com` 目录

然后开始看 `com` 目录，发现许多方法中抛出 `RuntimeException` 异常，如图：

![](https://bbs.kanxue.com/upload/attach/201507/468931_pch1419ds9wgqcc.png)

另外在 `DebugjnisoActivityn` 中发现许多 native 函数的声明，如图：

![](https://bbs.kanxue.com/upload/attach/201507/468931_70q3zt0t4ma807a.jpg)

## 小结

今天的分析先到这，对基本确定的小结一下：

1. 加固后外面的是个壳 dex，真正的 dex 放到 `libmobisecy.so` 中了。
2. 解压缩后得到的 dex 不能直接 dex2jar，去掉其中的 `a` 目录和 `pnf` 目录然后回编译就能正常了。

准备明天分析下 `RuntimeException` 作用、native 函数的作用和 `libmobisec.so`。之前没接触过 `RuntimeException`，准备明天现学下，希望能得到指点。其他方面也希望大大们不吝赐教![](https://bbs.kanxue.com/view/img/face/12.gif)
