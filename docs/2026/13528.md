这个样本一年多了吧（刚知道这是机器狗病毒第三代，很多大牛分析过了），在复印店打印东西的时候中的毒，当时感觉病毒比较厉害，技术又烂的要死，`rin3`层的程序不会脱壳，丢在`OD`里面干瞪眼。。。从大三下开始接触驱动，到现在有点时间了。。。但是因为个人时间有限，看编程时间并不多，现在终于敢拿起`IDA`大致看一下这个病毒的驱动了。。。

程序一共两个驱动，文件名随机，一个`3,968`字节，一个`8,256`字节

技术实力有限，并没有完全逆完。。。距离编译通过有质的差距![](https://bbs.kanxue.com/view/img/face/1.gif)

## 驱动一

这个驱动先是打印一堆骂人的英文，在`UserDispatch`例程接收传来的进程`ID`（应该是），但是这个函数里面 `v7`没有初始化。。。。不太懂咋回事

```
if ( v7 )
{
     Object = TmpObj;
}
```

创建新的线程，通过`NtQuerySystemInformation`的`11`功能号得到内核模块基地址，并利用特征码搜索得到`PspTerminateProcess`函数地址，调用该函数结束进程

## 驱动二

这个驱动比较复杂。。。现在还是有点晕。。。

在这个驱动里还是学到了一点东西的

1、最主要的就是读取原始`atapi.sys`文件，定位到`DriverEntry`函数通过特征码搜索得到 `IRP_MJ_DEVICE_CONTROL`和`IRP_MJ_INTERNAL_DEVICE_CONTROL`的分发函数偏移，最终结合内核中的镜像地址得到原始的分发函数`IdePortDispatchDeviceControl`和`IdePortDispatch`的地址。。。虽然我不知道它们可以用来穿透还原卡。。。（后来搜索`atapi.sys`的时候发现的）。将这两个原始函数替换了`atapi.sys`的相应处理历程。。。

在`GeATAPIDispatchRoution`函数里面，已经测试通过了。。。

2、发现驱动自己创建了`IRP`后没有调用`IoCallDriver`，跟进了一下发现是自己实现了`IopfCallDriver`（结合了`WRK`源代码发现的）。。。

3、驱动禁用了调试器，发现`SOFEICE`和`SYSER`的驱动就制造蓝屏。。。

4、使用了简单的加密，将驱动名称等信息加密了，解密很简单。。。

5、得到内核地址的方法比较全面有效。。。

在驱动里打开`explorer.exe`并读取了`512`字节（不知道这是干嘛？），得到了文件句柄、文件对象、对应的设备对象和驱动对象
