
# [原创]从内核在WOW64进程中执行用户态shellcode

首先说说`KeUserCallbackCallback`。

之前做某个项目时，用到了`KeUserCallback`的方式执行用户态的shellcode。

当时遗留了一个问题，关于wow64下，`KeUserCallbackCallback`的分发没有搞清楚。

导致只能执行原生的shellcode。

普通的32位和64位模式下原生的`KeUserCallback`执行ring3代码大家都不陌生了。![](https://bbs.kanxue.com/view/img/face/27.gif)

详情可见俄国人的`ring0MsgBox`。

但是如果内核所在的进程空间是一个wow64的进程，就有点麻烦了。

在内核`nt!KeUserCallbackDispatcher` -> `nt!KiCallUserMode`。

进入Ring3之后，首先到达的分发函数是`ntdll64!KiUserCallbackDispatcher`。

虽然是WOW64进程，但是当前的CPU模式是x64！是没法直接执行我们的x86 shellcode的。

但是系统的自带的功能是可以正常切换到wow64模式的，比如`user32!_ClientLoadLibrary`。

简单IDA之后，发现系统是存在一个模式切换的过程。

以`ClientLoadLibrary`为例。

首先，到达`ntdll64!KiUserCallbackDispatcher`之后，`call qword ptr [r9+r8*8]`这里的地址是`wow64win!whcbClientLoadLibrary`这里都是x64的代码。

```

.text:0000000078BA92C9 45 8B C2                                mov     r8d, r10d                                        ;参数的地址
.text:0000000078BA92CC 41 8D 51 19                             lea     edx, [r9+19h]                                ; Wow64模式的ApiIndex
.text:0000000078BA92D0 48 8D 4C 24 30                          lea     rcx, [rsp+9F8h+pContext]        ;线程的上下文
.text:0000000078BA92D5 E8 2C 69 00 00                          call    Wow64KiUserCallbackDispatcher
```

`wow64win!whcbClientLoadLibrary`内部继续分发了`wow64!Wow64KiUserCallbackDispatcher`。

```
        void Wow64KiUserCallbackDispatcher(
OUT PCONTEXT Context,        //线程上下文,需要外部分配内存
IN LONG ApiIndex,                //wow64的KernelCallbackTable的ApiIndex
IN PVOID pParam,
IN ULONG ParamSize
);
```

OK.到这里，整个大概的分发流程已经清楚了，实现我们的需求就很简单了，模拟一次即可了。

要执行`wow64`模式的shellcode，也需要构造这些stub。一共是2个stub：

1. `PsGetProcessPeb` 返回的原生的`PEB`。添加`KeCallbackTable`的entry指向我们的`wow64` stub。
2. `PsGetProcessWow64Process`获取到`wow64`模式的`PEB`，然后定位到相应的`WOW64 KeCallbackTable`，添加entry指向需要执行的`x86` shellcode。

`wow64`模式的APC相对来说就好多了，只有一个简单的变换：
