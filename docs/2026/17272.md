# 基础1，栈溢出手工代码注入
本实验根据 0day 软件安全一书调试完成

## 环境
```
操作系统： Windows XP SP2
编译器： Visual C++ 6.0
编译选项： 默认编译选项
build版本：debug版本
```
## 步骤
### 实验源码
此次实验所用的源码如下
```
#include <string.h>
#include <stdio.h>
#include <stdlib.h>
#include <windows.h>
#define PASSWORD "1234567"
int verify\_password(char \*password)
{
int auth;
char buffer[44];
auth = strcmp(password,PASSWORD);
strcpy(buffer,password);//over flowed here
return auth;
}
void main()
{
int valid\_flag = 0;
char passwd[1024];
FILE \*fp;
LoadLibrary("user32.dll");
if(!(fp = fopen("passwd.txt","rw+")))
{
exit(0);
}
fscanf(fp,"%s",passwd);
valid\_flag = verify\_password(passwd);
if(valid\_flag)
{
printf("incorrect password !!!\n");
}
else
{
printf("Congratulation !!! you have passwd the verification !! \n");
}
fclose(fp);
}
```
这个程序很简单就是从当前目录，读取`passwd.txt`中的内容，并判断是否和程序中定义的`PASSWORD`相同。在`verify\_password`函数中用`strcpy`函数构造了一个栈溢出漏洞。
### 分析调试
首先使用VS++生成exe，然后在其目录下创建一个`passwd.txt`文件，如下图所示。
![图片描述](upload/attach/202304/879928\_GS47ZXCAXHZUD7W.png)
使用`Ollydbg`打开程序进行调试，打开`Ollydbg`往上即可看见程序函数`main`跳转地址，和调用`verfy\_password`函数地址，如下图：
![图片描述](upload/attach/202304/879928\_YVG4E3XXCYUB9JQ.png)
此处可以看见`main`函数和`verify\_password`函数跳转地址。进入主函数，可以看见打开、读取文件，并将读取的内容进行压栈，然后再调用`verify\_password`函数。如下所示
![图片描述](upload/attach/202304/879928\_D8EYWBPQ47YQMZR.png)
按 `F8` 调用函数。进入函数内部。
![图片描述](upload/attach/202304/879928\_4HN7K7BCMTVWQGC.png)
这里主要功能就是比较传进来的参数和`1234567`是否相同，然后使用`strcpy`将传进来的参数复制到`buffer`中。
这里查看栈区，可以看见函数执行完毕之后，EIP 会跳转到`004010E4`继续执行流程。这里栈空间存放函数返回地址的地址为：`0012FB24`
![图片描述](upload/attach/202304/879928\_Q427PCSBJ2F4U9T.png)
由于我们源码中的`buffer`定义为44个字节，我们如果在`passwd.txt`写入44个字节，那么第45个隐藏的截断符`'\0'`会将我们的`auth`低字节中的`1`覆盖，从而突破密码的限制。
我们在`passwd.txt`中使用11组1234，这种一共44个字符，此时查看栈中情况
![图片描述](upload/attach/202304/879928\_Q5N6TRUB2BNUN8N.png)
由栈中的情况分析可以看见
1. `buffer`数组的起始地址为 `0x0012FAF0`。
2. `passwd.txt` 文件中53~56个字符的 ASCII码将写入栈中，并覆盖函数返回地址。成为函数返回后执行的指令地址。
也就是说，我们将`passwd.txt`中第53~56个字节改为`0x0012FAF0`可以引导EIP跳入我们输入的字符串开始取执行指令。
### shellcode构造
这一节我们手工构造shellcode，下一节再教大家怎么生成通用shellcode。
使用VC自带工具`Dependency Walker`获取`user32.dll`中`MessageBoxA`的地址。如下所示：
![图片描述](upload/attach/202304/879928\_XBZZ94M4PQC7AC8.png)
此时`user32.dll`的基址为：`0x77D10000` , 而`MessageBoxA`的入口地址为：0x000407EA，那么`MessageBoxA`再内存中的地址为：`0x77D507EA`
使用OD生成调用MessageBoxA shellcode如下所示：
![图片描述](upload/attach/202304/879928\_2AWVZCU35JAKQY9.png)
弹窗shellcode为
```
33 DB 53 53 53 53 B8 EA 07 D5 77 FF D0
```
因此我们可以用 010editor 和滑板指令90 来填充我们的shellcode。如下所示：
![图片描述](upload/attach/202304/879928\_53PWR3KDEB4DVUP.png)
### 效果
此时运行我们的exe，成功弹出MessageBox弹窗如下所示:
![图片描述](upload/attach/202304/879928\_Y7KT9ZGW65T2C6Y.png)
