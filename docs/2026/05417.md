# [原创]分析某程序-------如何枚举套接字

由于做一个小项目需要，最近急需搞懂如何枚举特定进程的套接字。由于MSDN并没有提供相关的接口，没办法，先度娘一下，看有没有结果。结果找到了易语言写的程序，而且还有源码和视频的，有点小激动，看了视频才知道，易语言是中文的![](https://bbs.kanxue.com/view/img/face/50.gif)，而且枚举套接字功能是在添加的模块里面的，视频里面只提到怎么引用，并没有提到任何实现的细节。![](https://bbs.kanxue.com/view/img/face/16.gif)没办法只能通过OD来查一下了。
![](https://bbs.kanxue.com/upload/attach/201204/330889_0el620s4k0pnaib.jpg)
据说易语言有壳，于是在看雪上找了个通用脱壳的软件Load一下。
![](https://bbs.kanxue.com/upload/attach/201204/330889_nxkbqv3d1tih26w.jpg)
然后attach这个程序的进程，结果来到了非程序领空：
![](https://bbs.kanxue.com/upload/attach/201204/330889_lufur5v0freg0q3.jpg)
Alt + M，在代码断设一个内存访问断点，F9，等一下，就可以回到程序领空：
![](https://bbs.kanxue.com/upload/attach/201204/330889_sboiht8de9gx19d.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_6xlqjj76sq7eqkt.jpg)
用OD附加进程之前，通过SPY++看了一下程序消息，发现是通过发送LB\_ADDSTRING这个消息
![](https://bbs.kanxue.com/upload/attach/201204/330889_oi97403x4ihuj70.jpg)
来添加内容的。在进入到程序领空之后，通过Ctrl + F？查找指令（push 180）：
![](https://bbs.kanxue.com/upload/attach/201204/330889_wkcfrp1f5qgugim.jpg)
结果还真有，而且指令附近可以看到有SendMessage函数的地址，应该就是这里了，
![](https://bbs.kanxue.com/upload/attach/201204/330889_vbiiigzh249xvoh.jpg)
下了个断点，让程序继续运行，点一下枚举套接字按钮，程序就断下来了。执行到程序返回，就可以到调用程序的地方，
![](https://bbs.kanxue.com/upload/attach/201204/330889_r72p0r8sai8f2f1.jpg)
到目前为止，就是需要弄清楚保存进程套接字信息是如何传进来的，不管先，先按F8继续走。单步了一下就发现一个跳转指令，跳到了一个地方，INC ecx，这条指令![](https://bbs.kanxue.com/view/img/face/16.gif)，貌似这里是一个循环来的，在看看寄存器，发现一个缓冲区地址，不管在地址栏看看里面到底是什么东西：
![](https://bbs.kanxue.com/upload/attach/201204/330889_jr8q7xlhxygtv27.jpg)
【![](https://bbs.kanxue.com/view/img/face/1.gif)注意看内存的HEX数据】
那个0x00000001不懂是什么，但是那个0x00000004貌似是找到的套接字个数。接下来的4个像地址。都是猜的……![](https://bbs.kanxue.com/view/img/face/16.gif)，进去看看再说：
![](https://bbs.kanxue.com/upload/attach/201204/330889_xgajyqr1eb8u5p1.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_geb6ntj6lnv960a.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_pe0765xw8nrn390.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_q68oyxnko3o9mlk.jpg)
哎哟，这些缓冲区里面的内容就是枚举到的套接字的十六进制表示。（也许是巧合![](https://bbs.kanxue.com/view/img/face/12.gif)），惊喜暂时就这么多，跟了许多遍这个循环，只发现一些不痛不痒的东西。
![](https://bbs.kanxue.com/upload/attach/201204/330889_yz4tuxndmq64mzq.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_77clocn8jieqvsr.jpg)
暂时认为这个循环已经没有研究的价值了，于是把断点往前移。
选了一个比较看好的为止下了断点之后，F9一下，然程序跑起来，然后再触发断点。然后一边跟，顺便记下一些临时缓冲区地址，顺便db xxxxx看一下缓冲区里面有什么东西。
![](https://bbs.kanxue.com/upload/attach/201204/330889_m1wqz6ffxgu23k4.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_h59tjeked4yq21p.jpg)
这个Call EBX里面就是一个SendMessage，push 184【LB\_RESETCONTENT】清空ListBox控件。记得中文代码里面写的很清楚，再执行枚举套接字之前会清空一下控件的内容。【中文源码有时候还挺有用的啊 ![](https://bbs.kanxue.com/view/img/face/12.gif)】执行到返回，发现从清空控件，到刚才向ListBox发送内容的那个循环之间，就只用一个CALL。![](https://bbs.kanxue.com/view/img/face/27.gif)
赶紧跟进去。
![](https://bbs.kanxue.com/upload/attach/201204/330889_do851upuapqd0hy.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_5fdk3a9rofwfg4n.jpg)
刚开始都是一下申请缓冲区和清空缓冲区操作，茫然啊，也不懂这些缓冲区干嘛的，不管，先记录下来。![](https://bbs.kanxue.com/view/img/face/50.gif)
一直F8走过去，又到循环了，而且寄存器所指向的缓冲区里面的内容也是令人非常兴奋的，至于是什么，有注释，有码：
![](https://bbs.kanxue.com/upload/attach/201204/330889_bse9w1rn68j7h13.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_prj8cpmsqawiw6x.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_ywjug887ffpehke.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_1f1utt23xah9bud.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_48fkw5jflsb030i.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_ei8sy9rw3f0m4sf.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_7q6mfs9nm2d06yg.jpg)
这一大窜代码，大概的功能就是搜索已经获得Socket信息中拿一下是目标进程的Socket。得到符合条件的Socket后，进行一个检查，如果是TRUE，就保存。保存这些socket信息的缓冲区是一个个长度为0x18的小缓冲区，这些一个个小缓冲区的地址有存在一个大的缓冲区里面，这个大缓冲区里面顺序排列这这些小缓冲区的地址，代码里面的SHL EAX，2就是计算小缓冲区地址。
到这里，应该离目标不远了，只要搞懂这些缓冲区里面的内容是从哪里来的，这次逆向就达到目的了；还是老办法，在循环之前的附近设个断点，触发断点,F8继续搜索目标代码，……（过了很久）：
![](https://bbs.kanxue.com/upload/attach/201204/330889_she9wakjwz489gu.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_2dnrkhwh8alxdqf.jpg)

![](https://bbs.kanxue.com/upload/attach/201204/330889_j5w7k99ocffgedc.jpg)
执行完后，寄存器值：
![](https://bbs.kanxue.com/upload/attach/201204/330889_hqzzleu3lhon92o.jpg)
C0000004，这个值是否很熟悉呢![](https://bbs.kanxue.com/view/img/face/27.gif)，没错，这个就是STASTUS\_缓冲区不足的错误码的十六进制。![](https://bbs.kanxue.com/view/img/face/1.gif)
而且在write data to target buffer这里会再次调用到这个int 2E

对应的堆栈地址值：

执行完int 2E之后，对应缓冲区就会得到这张系统的Socket表了。所有进程的Socket都在里面。这个缓冲区头四个字节是包含的ITEM数量，接着就是大小为16个字节的Socket信息了。
接着就是一下缓冲区的转化了，
![](https://bbs.kanxue.com/upload/attach/201204/330889_54u13xvixz8aw4t.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_bltoukw7h28u4t2.jpg)
![](https://bbs.kanxue.com/upload/attach/201204/330889_uan9icpmbkl0ts7.jpg)
这就是Socket表转换的代码，主要的操作就是把16个字节的缓冲区信息装到20个字节的缓冲区中。转换方法：
dword   ----》 dword
byte      ----》 dowrd
byte      ----》 dowrd
word     ----》 dword【Socket】
dword   ----》 dword
