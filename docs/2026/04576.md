# [原创]偷出 Directory Opus 9 的授权证书 -- 另类提取被 Thinapp 打包的文件

听别人说 Directory Opus9 可以替代系统自身的 Exploer.exe 来管理文件，而且功能很强大。
于是上官网下载了一个 x86 版的回来，我下载的时候，版本是 9.5.5.0.3889.x86 可能现在版本号已经升级了。
试用了一下，感觉功能不错，不像 Explorer 一样经常假死。于是决定就使用它了。
可是这个软件是 30 天的评估版，必须导入证书才能变成无限制版本，用 google 搜索了半天，找到了不少带 Key 的
集成版，但是下载链接都失效了，估计是 GP Software 公司和网站交涉过，要找一个 key 真难呀，不过功夫不负有心人。
我终于还有在某个论坛里找到了一个可下载的 Directory Opus9 便携版，虽说是便携版，但却不像国内的绿色软件是一个压缩包，
而是经过了 Thinapp 打包成了一个 exe 文件。
![](https://bbs.kanxue.com/upload/attach/201009/48065_0gfar1r7z6h7z3g.jpg)
关于 Thinapp 解包的讨论，在论坛里也有相关的资料，但是我想不起来在哪了……
    后来经过摸索，我发现了一条规律，经过 Thinapp 打包的软件，在运行时，都会把文件释放到打包前的安装路径下，这个路径在资源
管理器里看不到也无法访问，只有被打包的程序拥有访问权限，对被打包的程序来说，这个路径是真实存在的，但是对于外部程序来说，
这个路径是不存在的。
    既然这样，那么方法就有了，我运行便携版的 Directory Opus ,然后用它来访问它本身的安装路径，不就可以找到 Keyfile 了么？
按照这个思路来操作，如图：
![](https://bbs.kanxue.com/upload/attach/201009/48065_zaps4pruz9cpl4l.jpg)

真的发现 Keyfile 了，赶紧复制一份。把它导入我的安装版 Diretory Opus ，里，在证书管理里显示如下：
![](https://bbs.kanxue.com/upload/attach/201009/48065_en58725hs2c5str.jpg)
![](https://bbs.kanxue.com/upload/attach/201009/48065_1sxc1prjs82jr4f.jpg)

是 5 个用户授权的证书，赚到了~~

便携版的会有一个文件完整性检测失败的问题。所以动手的时候一定要快。
要是等到出现这个画面，就太迟了。
