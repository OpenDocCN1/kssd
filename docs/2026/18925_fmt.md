
# D-Link DCS-935L 栈溢出漏洞复现

## 0x00 前言

- 本文是对 D-Link DCS-935L 网络摄像头已知栈溢出漏洞的复现与学习记录。漏洞作者为某不愿意透露姓名的师傅，在此感谢原作者的分享。
- 本文主要侧重于分析过程，如**逐步追踪调用链，通过逆向分析手动推导偏移量，调试验证 Poc 等环节**，以便于大家可以更直观地看到漏洞从发现到利用的全链路分析思路。
- **声明**：本文仅用于网络安全技术学习与研究，所有测试均在本地 QEMU 模拟环境中进行。设备已经停产，且该漏洞已有对应编号，以及补丁，请用户及时更新固件。

- 固件：`DCS-935L_A1_FW_1.10.01_20161128_r4156.bin`
- 分析工具：Binwalk、IDA Pro

## 0x03 找到pwn调用链

### 3.1 查找漏洞点

1. 搜索栈溢出漏洞常见的API，如`sprint`、`fstrcpy`、`sprintf+system`。

2. 对`strcpy`查看交叉引用，得到调用位置，一个个找看看有没有符合溢出条件的。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_22RTDF8JHRE39RK.webp)

3. 找到其中的一个`strcpy`：

   - `V12`来自于`HNAP_AUTH`。

     ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_8MR256ZFUTS2ZJK.webp)

   - 没检查长度。

     ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_CKJAYE7X883V45M.webp)

   - 目的地址`haystack`仅256字节，且是局部变量在栈上。

     ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_8T4MWT89WZ8FQHZ.webp)

   - 综上，可判断此处或存在栈溢出漏洞，将`V12`重命名为`input_HNAP_AUTH`。

### 3.2 追踪调用链

从溢出点开始向上逐步追踪。

1. 条件1：`COOKIE="uid="`——`if(V16)`，需要`v16=strstr(haystack,"uid=")`，所以需要包含`"uid="`。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_4GE4EKMEVXCGSBW.webp)

2. 条件2：此处不能返回，所以`HNAP_AUTH`和`COOKIE`都不能为空。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_C8K64VBZJFASAX5.webp)

3. 条件3：要给个XML文档。需要包含`<soap:Body>`标签，并且`<soap:Body>`标签内的第一个子标签不能是`GetMultipleHNAPs`、`PushDCHEvent`、`PushDCHEventList`、`Login`、`DoAction`。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_PXQCH22K2MDGXU4.webp)

4. 条件4：XML具体路径在调用方给了`/tmp/.hnap_in.xml`，并且会从`stdin`中读取。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_WRNTJR6D2HHMU6K.webp)

5. 条件5：`CONTENT_LENGTH < 0x20000 且 == sizeof(stdin)`，`SOAP_ACTION`需要有内容，`REQUEST_METHOD=="POST"`。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_WCNZRQG4HFR7H3S.webp)

6. 根据上述的追踪内容，可以确定调用链如下：

   1. `REQUEST_METHOD=="POST"`

   2. `SOAP_ACTION`需要有内容。

   3. `CONTENT_LENGTH < 0x20000`并且是XML的大小。

   4. XML文档需要使用`stdin`输入，即`http_body`。

   5. `HNAP_AUTH`为导致栈溢出的数据。

   6. `COOKIE=="uid=XXXXX"`。

      ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_9DX257ZGDDGPZYM.webp)

## 0x05 调利用漏洞验证

### 5.1 覆盖返回地址

1. 编写Python脚本（在本文最后），方便我们进行调试。调试时发现，覆盖缓冲区后，未执行到`return`就崩了。找一下崩溃原因，`V20`是空指针，因为`HNAP_AUTH`是很多A，没有空格，所以没法分割，所以给俩空格让`strtok`能分割。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_AUZDRW5JNSUBVYF.webp)

2. 确定返回地址在栈上的位置：由于产生栈溢出的函数是非叶子函数，所以`ra`寄存器会存到栈上位置为`2B28B70C`，而`haystack`地址是`2B28B2DC`（栈地址不是每次固定，这里只是为了算偏移量）。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_2V26HCE3E4MZVWA.webp)

3. 计算出两个地址在栈上的偏移量为十进制的1072，修改一下POC。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_7JG8999QVZQ4G6J.webp)

4. 再次运行，此次`ra`寄存器在栈上位置为`2B28B64C`，可以观察到返回地址被覆盖为了BBBB，且返回后PC指向了`42424242`，程序崩溃。接下来修改BBBB即可控制PC。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_8SK9JFS3JRCTC56.webp)

### 5.2 命令执行

1. 确定有没有开启NX，RWE，说明栈是可以执行的。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_4V24WXJAQM2W8XN.webp)

2. 但是由于栈地址随机，无法直接在栈里写入shellcode（地址未知），所以需要找跳板。而在这个程序中没有找到合适的跳板，但是程序本身调用了`system`（直接调用）和`memcpy`（固定shellcode），所以可以直接跳过去进行调用。

3. `00431248`：是存储`http_body`给的XML文档中`<soap:Body>`标签第一个子标签的全局变量，可以用于传递`system`的参数。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_8SEEGFYDA4TETPA.webp)

4. 观察调用`system`的地方，`s0`可以通过栈溢出控制，偏移量`1036`。所以让`RA=004033CC`，`S0=00431248`，`http_body`传入参数`ls`让`system`调用，即可实现RCE。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_EXUBK9Y6TMKNDCC.webp)

5. 修改POC运行，成功执行`ls`命令。

   ![图片描述](https://bbs.kanxue.com/upload/attach/202603/1051776_WAPC8ECFS6WAPP4.webp)
