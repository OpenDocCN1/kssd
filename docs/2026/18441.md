# [讨论]菜鸟对CVE-2008-0015的一点分析

这是一个很老的漏洞，机理也很简单，分析他主要是学习windbg，感觉在符号解析和复杂条件断点等方面windbg真是太强，除了ui比较丑以外几乎没什么缺点了![](https://bbs.kanxue.com/view/img/face/27.gif)

本机测试环境为win xp sp3+IE6，msvidctl版本为6.5.2600.5512，漏洞样本来自metasploit\msf3\modules\exploits\windows\browser\msvidctl\_mpeg2.rb，实际上这不是一个浏览器漏洞，而是DirectShow mpeg2组件漏洞，CVE编号CVE-2008-0015。其组件msvidctl在加载特制mpeg2文件时可能存在溢出，成功的利用将引发执行任意代码。

注释掉heapspray，将喷射内容换为无效指令，漏洞触发后，crash信息如下

这里要注意，这个异常是first chance，可以再g一下，不过g一下之后发现崩掉了，异常地址为堆喷地址0x0c0c0c0c，这说明线程自己在异常处理时eip被劫持，回到刚才的first chance，查看seh链


```
0:000> dt ntdll!_EXCEPTION_REGISTRATION_RECORD poi(fs:[0])
   +0x000 Next     	: 0xffffffff 	_EXCEPTION_REGISTRATION_RECORD
   +0x004 Handler   	: 0x0c0c0c0c   _EXCEPTION_DISPOSITION
```



如上，整条seh链已经被破坏，只剩一个record，此record的next域已被修改为-1，handler也已经被修改为堆喷地址，此时若继续执行，将跳转至0c0c0c0c，执行预先布置的shellcode

据此基本上可以判断是栈溢出所致，，对AtlIPersistStreamInit\_Load单步跟踪，发现seh链在函数ATL::CComVariant::ReadFromStream中被覆盖，解析文件部分反汇编如下

3，将var\_qword\_2低32位作为长度，从文件读取数据到参数1的地址，就这里的问题，先看文件

![](https://bbs.kanxue.com/upload/attach/201203/321334_n97g3mg8fgv65cq.png)

结合文件内容，此处将0x34作为长度向栈中拷贝数据，栈里其实是没有空间的，然后seh record被覆盖，好死不死一个后面要用的局部变量也被覆盖，还是个指针，促成了seh handler的执行
第三步比较诡异，因为参数传进来的就是一个指针，读取数据的时候怎么可能直接把指针的地址当作buffer呢，个人认为是一个&笔误，注意加红部分

为验证是否是此问题，对win7下的该组件部分进行对照分析，反汇编如下


3，然后按照2取得的长度申请缓冲区，按照长度读取文件内容到缓冲区，避免了旧版本的漏洞。

关于该漏洞的利用，因为简单所以没有什么亮点，因为溢出点和返回地址之间存在一个重要的指针变量，盲目的覆盖将导致指针无效而异常，因此攻击脚本选择覆盖seh来执行shellcode，其实覆盖返回地址也是可以的，只要将溢出数据加大到0x3c并用0c来填充变量区，因为堆喷的关系，所有变量都是可以访问的，这样也能绕过可能产生的异常风险，同时也规避了safe seh(其实没关系的)，文件内容如图
