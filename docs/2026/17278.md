
# 分享一个堆中链表的卸载过程图

最近在看《0day安全》，研究了好久，终于弄明白了链表的卸载过程，给大家分享下我的心得。由于是新手初学，若有错误，还请大家指正。![](https://bbs.kanxue.com/view/img/face/12.gif)

在空表中，当堆被重新分配时，链表会从索引中卸下，这里主要有两步操作（这里不考虑堆块的合并）：

1. `node -> blink -> flink = node -> flink`

   意思就是将`flink`中的值写入到`blink`所指的`flink`中去。

   （这里的第一个`flink`和`blink`是将要卸载链表里的）

2. `node -> flink -> blink = node -> blink`

   意思就是将`blink`中的值写入到`flink`所指的`blink`中去。

   （这里的第一个`blink`和`flink`是将要卸载链表里的）

感觉很绕，其实很简单，过程如下图：

![](https://bbs.kanxue.com/upload/attach/201404/603264_jrtkyvzyzee5p7j.jpg)

其中`Freelist`是空表索引，`h1`、`h2`、`h3`代表不相邻的堆块，`a1`-`a8`表示地址。

对照上边的两步，验证后没有问题。这是卸载最后一个堆块的过程，那么卸载中间的是否也是这样呢？如下图：

![](https://bbs.kanxue.com/upload/attach/201404/603264_5e5rtm2i4caw8gn.jpg)

依然正确，没有问题。

书中实验为将`flink`改为`0x44444444`，`blink`改为`0x00000000`，但是只提到将`0x44444444`写入到`0x00000000`，而没有说将`0x00000000`写入到`0x44444444 + 4`（这里加4是因为`blink`相对`flink`有4字节偏移）。虽然第一步不成功第二步当然不会执行，但是我觉得还是说一下好，以免在修改的地址合法的时候忽略了第二步。
