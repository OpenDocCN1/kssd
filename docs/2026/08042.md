
# [原创]获取VEH SEH VCH UEF异常的函数地址

我们知道不管是在逆向破解还是脱壳,绝大部分的反调试机制是基于异常机制的，如果我们能够知道异常处理函数的地址，那么我们也就知道了敌人的巢穴，剩下的就看我们的能力能不能够摧垮敌人的巢穴了。

我只是简单告诉你怎么找到异常函数的地址,并不会去分析异常的实现机制,因为这就会和主题不符合了.

在找地址之前我先贴出两个至关重要的结构体 `TEB` 和 `PEB`。

## SEH 异常函数地址

`fs:[0]` 指向 `TEB` 结构的开始，其中第一个字段是一个结构体 `NtTib`，`NtTib` 的结构为：

```
typedef struct \_NT\_TIB //sizeof 1ch
{
00h struct \_EXCEPTION\_REGISTRATION\_RECORD \*ExceptionList;
04h PVOID StackBase;
08h PVOID StackLimit;
0ch PVOID SubSystemTib;
10h union {
PVOID FiberData;
DWORD Version;
};
14h PVOID ArbitraryUserPointer;
18h struct \_NT\_TIB \*Self;
}NT\_TIB;
```

其中 `NtTib` 的第一个字段 `ExceptionList` 是一个指针指向记录 SEH 的信息的结构体 `_EXCEPTION_REGISTRATION_RECORD`，该结构体结构为：

```
typedef struct \_EXCEPTION\_REGISTRATION\_RECORD
{
struct \_EXCEPTION\_REGISTRATION\_RECORD \*Next；//指向下一个SEH异常处理函数
PEXCEPTION\_ROUTINE Handler;//SEH 异常处理函数
}
```

看来这个结构是一个单向链表，当 `Next = 0xFFFFFFFF` 时，表示链表结束。

总结一下找 SEH：

1. 从 `FS:[0]` 得到 `ExceptionList`
2. `ExceptionList->Handler` 获取一个 SEH 异常处理函数地址
3. `ExceptionList->Next` 如果不是 `0xFFFFFFFF` 获取下一个 `ExceptionList`，重复第 2 步

## 寻找VEH VCH异常的函数地址

我创建一个 demo：

```
#include "stdafx.h"
#include <windows.h>
DWORD d;
LONG WINAPI VCHCallBack(PEXCEPTION\_POINTERS ExceptionInfo)
{
ExceptionInfo->ContextRecord->Eax = (DWORD)&d;
return EXCEPTION\_CONTINUE\_EXECUTION;
}
LONG WINAPI VEHCallBack(PEXCEPTION\_POINTERS ExceptionInfo)
{
ExceptionInfo->ContextRecord->Eax = (DWORD)&d;
return EXCEPTION\_CONTINUE\_EXECUTION;
}
int main()
{
AddVectoredExceptionHandler(0, VEHCallBack);
AddVectoredContinueHandler(0, VCHCallBack);
\_\_asm
{
mov eax,0
mov [eax],0
}
getchar();
return 0;
}
```

可有看到`_LdrpVectorHandlerList`指向了存放VEH和VCH的地方.其中每一个 VEH和VCH会用一个`10h`大小的空间保存.

`_LdrpVectorHandlerList` 在ntdll时一个全局参数

- `_LdrpVectorHandlerList`：指向了VEH
- `_LdrpVectorHandlerList+C`：指向了VCH

经过分析`_LdrpVectorHandlerList`全局变量的结构类型为

```
typedef struct _LIST_ENTRY //这是一个环形链表
{

struct _LIST_ENTRY *Blink;//指向前一个
}LIST_ENTRY,*PLIST_ENTRY;
struct _LVHL //_LdrpVectorHandlerList
{

{

};
struct _VCH
{
DWORD VCH_LockCount;//这个参数不重要
LIST_ENTRY VCH_listTop;
};
//申请10h堆空间保存VEH和VCH的结构
struct SaveVector
{
LIST_ENTRY List;

```

还需要注意的时VEH和VCH的回调i函数指针是经过`RtlEncodePointer`加密的,所以要获取真实的函数指针地址需要经过`RtlDecodePointer`解密.

描述总是浅显的,看图

![链表](upload/attach/201804/793792_DZ2TUETS3KB5U5Q.png)

总结:

1. 在ntdll中找到`RtlpAddVectoredHandler`函数
2. 获取`_LdrpVectorHandlerList`(`add ebx, offset _LdrpVectorHandlerList`;这句汇编代码获取)
3. 根据链表关系寻找VEH和VCH的回调函数地址
4. 用`RtlDecodePointer`解密.

## 寻找UEF异常的函数地址

{

2. 找到`_BasepCurrentTopLevelFilte`这个全局变量的地址(可通过`mov _BasepCurrentTopLevelFilter, eax`这个汇编语句获取)
3. `_BasepCurrentTopLevelFilte`的内容就是当前UEF回调函数的地址,当然是加密的地址,需要经过`RtlDecodePointer`解密才是真正的函数地址.

## 总结

- SEH:保存在`FS:[0]`,这是一个链表
- VEH,VCH:保存在`ntdll.dll`模块的`_LdrpVectorHandlerList`全局变量里,可通过该模块的`RtlpAddVectoredHandler`函数找到这个地址,这是一个循环链表
- UEF:保存在`kernel32.dll`模块的`_BasepCurrentTopLevelFilte`全局变量里,可通过该模块的`SetUnhandledExceptionFilter`函数找到,就单纯一个全局变量.
- 除了SEH外,回调函数地址都是经过`RtlEncodePointer`加密的,需要`RtlDecodePointer`解密才是真正的函数地址.

## SEH 异常函数地址

`fs:[0]`指向`TEB`结构的开始,其中第一个字段是一个结构体`NtTib`,`NtTib`的结构为：

```text
typedef struct _NT_TIB          //sizeof  1ch  

{  

 00h   struct _EXCEPTION_REGISTRATION_RECORD  *ExceptionList; 

 04h   PVOID                            StackBase;

 08h   PVOID                            StackLimit;

 0ch   PVOID                            SubSystemTib;  

 10h   union {  

           PVOID                FiberData;  

           DWORD                Version;  

        };  

 14h   PVOID                            ArbitraryUserPointer;  

 18h   struct _NT_TIB                   *Self; 

}NT_TIB;
```

其中`NtTib`的第一个字段`ExceptionList`是一个指针指向记录SEH的信息的结构体`_EXCEPTION_REGISTRATION_RECORD`,该结构体结构为：

```text
typedef struct _EXCEPTION_REGISTRATION_RECORD

{

    struct _EXCEPTION_REGISTRATION_RECORD *Next；//指向下一个SEH异常处理函数

    PEXCEPTION_ROUTINE Handler;//SEH 异常处理函数

}
```

看来这个结构是一个单向链表,当`Next=0xFFFFFFFF`时，表示链表结束.

总结一下找SEH：

1. 从`FS:[0]`得到`ExceptionList`
2. `ExceptionList->Handler`获取一个SEH异常处理函数地址



3. `ExceptionList->Next` 如果不是 `0xFFFFFFFF`，获取下一个 `ExceptionList`，重复第2步

总结：

1. 在`kernel32`中找到`SetUnhandledExceptionFilter`

2. 找到`_BasepCurrentTopLevelFilte`这个全局变量的地址（可通过`mov _BasepCurrentTopLevelFilter, eax`这个汇编语句获取）

3. `_BasepCurrentTopLevelFilte`的内容就是当前UEF回调函数的地址，当然是加密的地址，需要经过`RtlDecodePointer`解密才是真正的函数地址。

## 总结

- SEH：保存在`FS:[0]`，这是一个链表

- VEH,VCH：保存在`ntdll.dll`模块的`_LdrpVectorHandlerList`全局变量里，可通过该模块的`RtlpAddVectoredHandler`函数找到这个地址，这是一个循环链表

- UEF：保存在`kernel32.dll`模块的`_BasepCurrentTopLevelFilte`全局变量里，可通过该模块的`SetUnhandledExceptionFilter`函数找到，就单纯一个全局变量。

- 除了SEH外，回调函数地址都是经过`RtlEncodePointer`加密的，需要`RtlDecodePointer`解密才是真正的函数地址。
