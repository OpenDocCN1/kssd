# DLL劫持自动化检测

## 简介

本文将介绍动态链接库（DLL）搜索顺序劫持的概念，以及如何实现在Windows上的持久化攻击。MITRE ATT&CK对DLL搜索顺序劫持的描述详见<a href="elink@d4bK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6S2N6s2c8S2j5$3E0Q4x3X3g2E0K9i4c8J5k6g2)9J5k6h3!0J5k6#2)9J5c8Y4c8W2j5$3S2F1K9i4q4#2k6i4y4Q4x3V1k6f1x3e0f1%4y4q4)9J5c8U0l9H3x3g2)9J5c8R3`.`.">DLL Search Order Hijacking (T1038)</a>。
DLL劫持对攻击者很有用，原因有很多，但本文会重点介绍与开机自启程序结合使用时的持久化攻击。例如，由于Slack和Microsoft Teams开机自启（默认情况下），因此，只要用户登录，这些应用程序中的DLL劫持将允许攻击者能够持久访问攻击目标。
在介绍DLL、DLL搜索顺序和DLL劫持的概念后，我会阐述DLL劫持自动化检测的过程<<mark class="encrypted">25fK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6K6L8s2W2V1x3r3N6Q4x3V1k6p5e0p5I4t1K9h3A6S2j5$3E0f1k6i4y4@1</mark>>。本文将涉及Slack、Microsoft Teams以及Visual Studio Code相关的DLL劫持检测。
最后，我注意到很多DLL劫持会同时作用于多个程序。我调查了底层原因，发现调用某些位于`C:\Windows\System32\`下的Windows API的程序容易成为DLL劫持的目标。
这里我要感谢我的同事，Josiah Massari（<a href="elink@f48K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6@1N6$3W2@1N6r3g2J5i4K6u0W2j5$3!0E0i4K6u0r3j5h3W2J5P5X3g2J5L8K6t1@1">@Airzero24</a>）。是他最早发现的这些DLL劫持案例并解释其方法和原理，促成了我将检测做成自动化。

### DLL是什么

*DLL是一个包含可被多个程序同时使用的代码和数据的库。*（定义源于<a href="elink@b6fK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6K6N6i4m8H3L8%4u0@1i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3S2W2L8s2m8Q4x3V1j5^5x3e0f1H3y4U0g2Q4x3V1k6%4K9r3q4@1i4K6u0V1K9i4y4Q4x3X3c8S2i4K6u0V1k6r3I4D9">Microsoft</a>）
Windows程序可以调用<a href="elink@784K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3I4A6j5X3I4G2j5h3c8W2M7X3q4H3K9g2)9J5c8X3&6X3i4K6u0V1L8r3W2T1L8r3!0S2k6r3g2J5j5i4m8A6i4K6u0V1L8r3!0S2k6r3I4A6j5Y4u0S2M7Y4W2S2">`LoadLibrary`</a>系列函数来使用DLL中的功能。程序可以引用自定义的DLL，也可以引用System32中Windows自带的DLL。开发者可以加载System32中的DLL，使其程序使用Windows的现成功能，而不必重新造轮子。
例如，开发者需要发起HTTP请求时，可以使用WinHTTP库（`winhttp.dll`），而无需用原始套接字开发并实现HTTP功能。

### DLL搜索顺序和劫持

由于DLL也是存储在磁盘上的文件，那么程序是如何知道从哪里加载DLL的呢？Microsoft在<a href="elink@c8eK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3c8D9L8s2y4Q4x3V1k6V1P5h3&6S2L8h3W2U0i4K6u0V1L8r3W2F1K9#2)9J5k6r3I4A6j5Y4u0S2M7Y4W2Q4x3X3c8K6k6h3q4J5j5$3S2Q4x3X3c8G2M7X3c8W2M7R3`.`.">此</a>详细记录了DLL搜索顺序。
自Windows XP SP2起，安全DLL搜索模式默认开启（`HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\Session Manager\SafeDllSearchMode`）。当安全模式启用时，搜索顺序如下：
1. 程序安装目录。
2. 系统目录。使用<a href="elink@427K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6V1k6i4y4C8N6r3!0H3i4K6u0r3j5i4m8A6i4K6u0r3M7%4W2K6K9h3&6X3L8$3q4H3K9g2)9J5c8X3&6X3i4K6u0V1M7%4W2K6K9h3&6X3L8$3q4H3K9g2)9J5k6r3N6W2N6s2y4&6M7%4c8W2L8h3c8A6M7X3g2U0N6r3!0J5P5h3p5`.">`GetSystemDirectory`</a>获取该目录路径。
3. 16位系统目录。没有函数可以获取该目录路径，但该目录会被搜索。
4. Windows目录。使用<a href="elink@29bK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6V1k6i4y4C8N6r3!0H3i4K6u0r3j5i4m8A6i4K6u0r3M7%4W2K6K9h3&6X3L8$3q4H3K9g2)9J5c8X3&6X3i4K6u0V1M7%4W2K6K9h3&6X3L8$3q4H3K9g2)9J5k6r3N6W2N6s2N6A6L8X3c8G2N6%4y4V1K9i4u0W2j5%4c8G2M7Y4W2S2">`GetWindowsDirectory`</a>获取该目录路径。
5. 当前目录。
6. PATH环境变量中的目录。注意，这不包括`App Paths`注册表键指定的程序路径。`App Paths`键不会参与DLL搜索路径的计算。
*系统可包含动态链接库（DLL）的多个版本。程序可通过指定完整路径或使用比如manifest的其他机制来控制加载特定的DLL。*（定义源于<a href="elink@916K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3c8D9L8s2y4Q4x3V1k6V1P5h3&6S2L8h3W2U0i4K6u0V1L8r3W2F1K9#2)9J5k6r3I4A6j5Y4u0S2M7Y4W2Q4x3X3c8K6k6h3q4J5j5$3S2Q4x3X3c8G2M7X3c8W2M7R3`.`.">Microsoft</a>）
如果程序没有加载指定的DLL，Windows会默认执行上述的DLL搜索流程。DLL搜索的第一顺位，即程序的安装目录，是攻击者最感兴趣的。
如果开发者想要从`C:\Windows\System32\`加载 DLL，但并没有写清楚让程序这么做，那么程序安装目录下的恶意DLL就会优先于System32下的合法DLL被加载。这里恶意DLL指的是DLL劫持，攻击者用来在受信/签名程序中加载恶意代码。

## 方法论：理解共有DLL劫持

我观察了下Slack加载`WINSTA.dll`、`LINKINFO.dll`、`ntshrui.dll`、`srvcli.dll`和`cscapi.dll`的栈轨迹。

### 延迟加载DLL

我注意到当`WINSTA.dll`、`LINKINFO.dll`、`ntshrui.dll`、`srvcli.dll`和`cscapi.dll`被加载时栈轨迹存在共性。

![Code.exe加载WINSTA.dll时的栈轨迹](upload/attach/202007/747358_4NFZGJT23ZZRQDT.jpg)

![Teams.exe加载LINKINFO.dll时的栈轨迹](upload/attach/202007/747358_WGG78AY5BX4QVYR.jpg)

![Slack加载ntshrui.dll时的栈轨迹](upload/attach/202007/747358_FJXE253JAQH75WN.jpg)

栈轨迹都调用了`_tailMerge_<dllname>_dll`和`delayLoadHelper2`，之后还调用了`LdrResolveDelayLoadedAPI`。三个程序都出现了这种情况。

## 简介

本文将介绍动态链接库（DLL）搜索顺序劫持的概念，以及如何实现在Windows上的持久化攻击。MITRE ATT&CK对DLL搜索顺序劫持的描述详见[DLL Search Order Hijacking (T1038)](https://bbs.kanxue.com/elink@c66K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6S2N6s2c8S2j5$3E0Q4x3X3g2E0K9i4c8J5k6g2)9J5k6h3!0J5k6#2)9J5c8Y4c8W2j5$3S2F1K9i4q4#2k6i4y4Q4x3V1k6f1x3e0f1%4y4q4)9J5c8U0l9H3x3g2)9J5c8R3`.`.)。

DLL劫持对攻击者很有用，原因有很多，但本文会重点介绍与开机自启程序结合使用时的持久化攻击。例如，由于Slack和Microsoft Teams开机自启（默认情况下），因此，只要用户登录，这些应用程序中的DLL劫持将允许攻击者能够持久访问攻击目标。

在介绍DLL、DLL搜索顺序和DLL劫持的概念后，我会阐述DLL劫持自动化检测的过程[a06K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6K6L8s2W2V1x3r3N6Q4x3V1k6p5e0p5I4t1K9h3A6S2j5$3E0f1k6i4y4@1](https://bbs.kanxue.com/elink@f27K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6K6L8s2W2V1x3r3N6Q4x3V1k6p5e0p5I4t1K9h3A6S2j5$3E0f1k6i4y4@1)。本文将涉及Slack、Microsoft Teams以及Visual Studio Code相关的DLL劫持检测。

## 结论

简要回顾下，DLL劫持是攻击者在签名/受信的程序中执行代码的一种方法。我开发了自动检测DLL劫持的工具。利用此工具，我发现了Slack、Microsoft Teams和Visual Studio Code中的DLL劫持。

我注意到这三个程序存在共有DLL劫持的情况，并调查了根本原因。我重点介绍了研究的方法，并了解了延迟加载DLL，以及定位到了两个API调用，这两个API会引入DLL劫持到调用它们的程序中：

+ `NetShareEnum`加载`cscapi.dll`

+ `NetShareGetInfo`加载`cscapi.dll`

### DLL是什么

*DLL是一个包含可被多个程序同时使用的代码和数据的库。*（定义源于[Microsoft](https://bbs.kanxue.com/elink@c55K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6K6N6i4m8H3L8%4u0@1i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3S2W2L8s2m8Q4x3V1j5^5x3e0f1H3y4U0g2Q4x3V1k6%4K9r3q4@1i4K6u0V1K9i4y4Q4x3X3c8S2i4K6u0V1k6r3I4D9)）

Windows程序可以调用[`LoadLibrary*`](https://bbs.kanxue.com/elink@c44K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3I4A6j5X3I4G2j5h3c8W2M7X3q4H3K9g2)9J5c8X3&6X3i4K6u0V1L8r3W2T1L8r3!0S2k6r3g2J5j5i4m8A6i4K6u0V1L8r3!0S2k6r3I4A6j5Y4u0S2M7Y4W2S2)系列函数来使用DLL中的功能。程序可以引用自定义的DLL，也可以引用`System32`中Windows自带的DLL。开发者可以加载`System32`中的DLL，使其程序使用Windows的现成功能，而不必重新造轮子。

例如，开发者需要发起HTTP请求时，可以使用WinHTTP库（`winhttp.dll`），而无需用原始套接字开发并实现HTTP功能。

### DLL搜索顺序和劫持

由于DLL也是存储在磁盘上的文件，那么程序是如何知道从哪里加载DLL的呢？Microsoft在[此](https://bbs.kanxue.com/elink@1fdK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3c8D9L8s2y4Q4x3V1k6V1P5h3&6S2L8h3W2U0i4K6u0V1L8r3W2F1K9#2)9J5k6r3I4A6j5Y4u0S2M7Y4W2Q4x3X3c8K6k6h3q4J5j5$3S2Q4x3X3c8G2M7X3c8W2M7R3`.`.)详细记录了DLL搜索顺序。

自Windows XP SP2起，安全DLL搜索模式默认开启（`HKEY_LOCAL_MACHINE\System\CurrentControlSet\Control\Session Manager\SafeDllSearchMode`）。当安全模式启用时，搜索顺序如下：

1. 程序安装目录。

2. 系统目录。使用[`GetSystemDirectory`](https://bbs.kanxue.com/elink@bb5K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6V1k6i4y4C8N6r3!0H3i4K6u0r3j5i4m8A6i4K6u0r3M7%4W2K6K9h3&6X3L8$3q4H3K9g2)9J5c8X3&6X3i4K6u0V1M7%4W2K6K9h3&6X3L8$3q4H3K9g2)9J5k6r3N6W2N6s2y4&6M7%4c8W2L8h3c8A6M7X3g2U0N6r3!0J5P5h3p5`.)获取该目录路径。

3. 16位系统目录。没有函数可以获取该目录路径，但该目录会被搜索。

4. Windows目录。使用[`GetWindowsDirectory`](https://bbs.kanxue.com/elink@838K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6V1k6i4y4C8N6r3!0H3i4K6u0r3j5i4m8A6i4K6u0r3M7%4W2K6K9h3&6X3L8$3q4H3K9g2)9J5c8X3&6X3i4K6u0V1M7%4W2K6K9h3&6X3L8$3q4H3K9g2)9J5k6r3N6W2N6s2N6A6L8X3c8G2N6%4y4V1K9i4u0W2j5%4c8G2M7Y4W2S2)获取该目录路径。

5. 当前目录。

6. `PATH`环境变量中的目录。注意，这不包括`App Paths`注册表键指定的程序路径。`App Paths`键不会参与DLL搜索路径的计算。

*系统可包含动态链接库（DLL）的多个版本。程序可通过指定完整路径或使用比如manifest的其他机制来控制加载特定的DLL。*（定义源于[Microsoft](https://bbs.kanxue.com/elink@689K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3c8D9L8s2y4Q4x3V1k6V1P5h3&6S2L8h3W2U0i4K6u0V1L8r3W2F1K9#2)9J5k6r3I4A6j5Y4u0S2M7Y4W2Q4x3X3c8K6k6h3q4J5j5$3S2Q4x3X3c8G2M7X3c8W2M7R3`.`.)）

如果程序没有加载指定的DLL，Windows会默认执行上述的DLL搜索流程。DLL搜索的第一顺位，即程序的安装目录，是攻击者最感兴趣的。

如果开发者想要从`C:\Windows\System32\`加载 DLL，但并没有写清楚让程序这么做，那么程序安装目录下的恶意DLL就会优先于`System32`下的合法DLL被加载。这里恶意DLL指的是DLL劫持，攻击者用来在受信/签名程序中加载恶意代码。

## 方法论：理解共有DLL劫持

我观察了下Slack加载`WINSTA.dll`、`LINKINFO.dll`、`ntshrui.dll`、`srvcli.dll`和`cscapi.dll`的栈轨迹。

### 延迟加载DLL

我注意到当`WINSTA.dll`、`LINKINFO.dll`、`ntshrui.dll`、`srvcli.dll`和`cscapi.dll`被加载时栈轨迹存在共性。

![Code.exe加载WINSTA.dll时的栈轨迹](https://bbs.kanxue.com/upload/attach/202007/747358_4NFZGJT23ZZRQDT.jpg)

![Teams.exe加载LINKINFO.dll时的栈轨迹](https://bbs.kanxue.com/upload/attach/202007/747358_WGG78AY5BX4QVYR.jpg)

![Slack加载ntshrui.dll时的栈轨迹](https://bbs.kanxue.com/upload/attach/202007/747358_FJXE253JAQH75WN.jpg)

栈轨迹都调用了`_tailMerge_<dllname>_dll`和`delayLoadHelper2`，之后还调用了`LdrResolveDelayLoadedAPI`。三个程序都出现了这种情况。

我认为这种情况与[延迟加载DLL](https://bbs.kanxue.com/elink@4fdK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8X3y4H3M7q4)9J5c8X3u0#2K9h3I4V1i4K6u0r3M7X3g2X3k6i4u0W2L8X3y4W2i4K6u0r3L8r3W2F1K9$3g2J5i4K6u0V1M7%4g2H3M7r3!0J5N6q4)9J5k6r3k6G2M7W2)9J5k6r3c8W2L8r3q4&6i4K6u0V1L8r3!0S2k6r3g2V1i4K6u0V1k6r3I4D9M7#2)9K6c8Y4k6A6k6i4N6Q4x3@1c8$3M7#2)9J5k6o6t1H3x3e0V1`.)有关。当`WINSTA.dll`被加载时，从栈轨迹可以看到，`wtsapi32.dll`导致了延迟加载。

在[Ghidra](https://bbs.kanxue.com/elink@e3dK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9r3W2V1M7X3q4Q4x3X3c8K6M7X3g2Q4x3X3g2G2M7X3N6Q4x3V1j5`.)中打开`wtsapi32.dll`，设置 Search -> For Strings -> Filter: `WINSTA.dll`。双击查找的结果会看到其内存地址。

![wtsapi32.dll中“WINSTA.dll”字符串](https://bbs.kanxue.com/upload/attach/202007/747358_RHR54JXACQYSNNR.jpg)

右键点击内存地址，可以找到对该地址的引用。

![WINSTA.dll引用](https://bbs.kanxue.com/upload/attach/202007/747358_HYKW2FPC9GJAGWB.jpg)

我们看到`WINSTA.dll`被传递至名为`ImgDelayDescr`的结构体。查看该结构体的[说明文档](https://bbs.kanxue.com/elink@1daK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6y4K9h3y4J5L8%4y4G2k6Y4c8p5L8$3y4K6i4K6u0r3j5%4m8H3i4K6u0V1k6r3!0U0M7#2)9J5c8X3u0D9L8$3u0Q4x3V1k6E0j5i4y4@1k6i4u0Q4x3V1k6V1L8$3y4K6i4K6u0r3j5Y4g2A6L8r3c8Q4x3V1k6J5k6h3k6W2M7X3g2F1j5$3g2Q4x3V1k6K6N6s2u0#2j5%4c8#2M7X3g2Q4x3X3c8S2L8X3c8Q4x3X3c8U0L8$3&6K6N6r3q4F1N6q4)9J5k6r3c8W2k6X3W2F1K9i4c8A6L8$3&6K6i4K6u0W2L8h3b7`.)，可以确定其与延迟加载DLL有关。

```
typedef struct ImgDelayDescr {

    DWORD        grAttrs;        // attributes

    RVA          rvaDLLName;     // RVA to dll name

    RVA          rvaHmod;        // RVA of module handle

    RVA          rvaIAT;         // RVA of the IAT

    RVA          rvaINT;         // RVA of the INT

    RVA          rvaBoundIAT;    // RVA of the optional bound IAT

    RVA          rvaUnloadIAT;   // RVA of optional copy of original IAT

    DWORD        dwTimeStamp;    // 0 if not bound,

                                 // O.W. date/time stamp of DLL bound to (Old BIND)

    } ImgDelayDescr, * PImgDelayDescr;

```

该结构体可被传递至[`__delayLoadHelper2`](https://bbs.kanxue.com/elink@d0fK9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6Y4K9i4c8Z5N6h3u0Q4x3X3g2U0L8$3#2Q4x3V1k6y4K9h3y4J5L8%4y4G2k6Y4c8p5L8$3y4K6i4K6u0r3j5%4m8H3i4K6u0V1k6r3!0U0M7#2)9J5c8X3u0D9L8$3u0Q4x3V1k6E0j5i4y4@1k6i4u0Q4x3V1k6V1L8$3y4K6i4K6u0r3j5Y4g2A6L8r3c8Q4x3V1k6J5k6h3k6W2M7X3g2F1j5$3g2Q4x3V1k6K6N6s2u0#2j5%4c8#2M7X3g2Q4x3X3c8S2L8X3c8Q4x3X3c8U0L8$3&6K6N6r3q4F1N6q4)9J5k6r3c8W2k6X3W2F1K9i4c8A6L8$3&6K6i4K6u0W2L8h3b7`.)，后者会通过[`LoadLibrary`](https://bbs.kanxue.com/elink@c19K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3I4A6j5X3I4G2j5h3c8W2M7X3q4H3K9g2)9J5c8X3&6X3i4K6u0V1L8r3W2T1L8r3!0S2k6r3g2J5j5i4m8A6i4K6u0V1L8r3!0S2k6r3I4A6j5Y4u0S2M7Y4W2S2)/[`GetProcAddress`](https://bbs.kanxue.com/elink@e74K9s2c8@1M7s2y4Q4x3@1q4Q4x3V1k6Q4x3V1k6V1L8$3y4K6i4K6u0W2L8h3W2U0M7X3!0K6L8$3k6@1i4K6u0W2j5$3!0E0i4K6u0r3k6h3&6Q4x3X3c8#2M7#2)9J5c8Y4N6A6L8X3c8G2N6%4y4Q4x3V1k6%4K9h3^5K6x3W2)9J5c8X3q4H3K9g2)9J5c8X3I4A6j5X3I4G2j5h3c8W2M7X3q4H3K9g2)9J5c8X3&6X3i4K6u0V1L8r3W2T1L8r3!0S2k6r3g2J5j5i4m8A6i4K6u0V1k6$3g2@1M7s2u0G2j5$3q4V1k6s2u0W2M7%4x3`.)加载特定DLL，并且会修正延迟加载导入地址表（IAT）中导入函数的地址。

## 结论

简要回顾下，DLL劫持是攻击者在签名/受信的程序中执行代码的一种方法。我开发了自动检测DLL劫持的工具。利用此工具，我发现了Slack、Microsoft Teams和Visual Studio Code中的DLL劫持。

我注意到这三个程序存在共有DLL劫持的情况，并调查了根本原因。我重点介绍了研究的方法，并了解了延迟加载DLL，以及定位到了两个API调用，这两个API会引入DLL劫持到调用它们的程序中：

- `NetShareEnum`加载`cscapi.dll`
- `NetShareGetInfo`加载`cscapi.dll`
