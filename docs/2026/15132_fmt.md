

# [原创] 360 加固逆向脱壳之过反调试

## 写在最前

本来是想把 360 加固全部脱壳后，写一篇教程。不过在我过了 360 加固调试后，最后卡在了 `native void onCreate` 函数的提取。最后就无结果了。

但又发现许多人卡在了 360 加固的反调试，为了帮助其他人能成功（其实我没有这么伟大，只是发现写这篇文章对我没有害处，就决定放出来），而且希望，如果有人把 `native void onCreate` 函数 dump 下来的话，请觅我，我真的很想知道 360 加固的原理与逆向方法（这才是重点）。

哦，对了，360 加固版本是 1.3。如果用的是 Android 的 ART 模式，在网上有一篇文章是修改系统的，可直接 dump 出源码，不过我没有亲测。而我用的是 Dalvik 模式，主要是为了弄清 360 加固的加固原理与反调试原理。

我的 360 加固 1.3 样本下载地址：

`0f7K9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8Y4m8S2L8W2)9J5k6h3u0S2K9h3c8#2i4K6u0W2j5$3!0E0i4K6u0r3M7#2)9J5c8U0q4H3d9#2y4b7x3U0u0F1`

好了，让我们开始吧。

## 一、使用系统

我用 Android 4.4 编译了一个自己的 Android 系统，并且运行在虚拟机上运行。（由此不用把 APK 改为什么 Debug 模式了，因为我用的系统就是 Debug 模式。）

修改的地方是在 `Native.cpp` 文件中的 `dvmLoadNativeCode` 函数中，在下面语句之前加入 `sleep(20)`：

```cpp
version = (*func)(gDvmJni.jniVm, NULL);
```

之后 IDA 会自动断点在 `sleep` 之后，是不是很神奇？

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_7v4h04vtyxshppy.png)

## 二、启动虚拟机

启动虚拟机，并使用编译好的 Android 系统包。具体怎么编译，是另外的一篇教程了，可以网上搜索到，很多的。不过也可以直接使用 `jdb` 作为桥接。

### 关于 APK 解压

写在第三步之前，其实这里面还有一个可有可无的东西，需要把 APK 用 `apktool` 解压，但是直接用现有的 `apktool` 解压会失败。

解决方法是直接去获取 `apktool` 的源码，并且修改一个地方就 OK 了。至于修改哪里，有兴趣的朋友可以自己查找，应该都能过的。

## 三、启动调试服务

虚拟机启动后，打开一个 `cmd`，在其中输入：

```bash
adb forward tcp:23946 tcp:23946
```

再打开一个 `cmd`，在其中运行 `adb shell`，然后再运行 `/data/local/tmp/android_server`。

`android_server` 是用 IDA 里面的 `android_server`，放入到虚拟机中，并且修改了权限，网上有很多教程，可搜索。

然后在虚拟机中运行 `Test360_2`，也就是我制作的一个 360 加固的 `hello_world` 样本，已经签名好了。

## 四、使用 IDA 附加进程

然后就开始用 IDA attach `Test360_2` 进程了。关键性的东西来了。

一开始，IDA 会自动断点在这里：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_w78fnx3rsbhc2dv.png)

经过 4、5 步 `F7` 后，来到 `libdvm.so`。

红色圆圈是我在系统源码中打的调试信息，然后在 `BLX R10` 处按 `F7`，也就是进入函数 `jni_onload()`，然后来到并在红色处按 `F7`。

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_r5gjbrb90kn6a7u.png)

来到红色处，按 `F7`。

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_4yyj9jy8ozz2hcj.png)

来到红色处，按 `F7`。

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_z0kqucow6g7go40.png)

进入上面第一个红色位置后，鼠标滚轮往下找到 `switch` 函数，并在 `case 25` 下断点，如下图：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_378ybcuxy4fl148.png)

然后按 `F9`（好像是按了 2 次 `F9`，呵呵），反正是来到 `case 25`，然后在 `case 14` 下断点，如图：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_eqbzuqjb6njccrw.png)

按 `F7` 进入。

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_nzu8eabwsnwazdt.png)

多次单步按 `F7` 后，来到：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_gsb8phpx6hag1zb.png)

把 `R3` 寄存器的 `6000010` 改为 `A000010`。（这里的反调试检测，可能是检测 `rtld_db_dlactivity` 函数，不过不太确定，因为没有看见源代码。）

然后单步，把 `case 14` 与 `case 25` 的断点取消掉，并在 `case 29` 下断点，然后进入。

当 `BLX LR` 调用 `strtol` 的时候，需要单步出来修改一些值，来到 `MOV R7,R0` 的时候：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_1r6x8o8nyg2h5uc.png)

修改 `R0` 的值为 `0`。

并且把 `R1` 的十六进制处改为 `0`，如下图红色处，需要修改为 `0`：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_o2dme3ufrwoluhl.png)

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_w7d7w441j62rcgr.png)

这里以上是检测 `TracePID`。

然后继续按 `F9`，在多次对 `case 29` 下断点后，来到：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_ydb09kpy44t76kj.png)

在 `CMP` 处，把 `R0` 的值修改为 `0`。（这里是检测调试端口。）然后按 `F9`。

还是来到：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_fkgzkm686zmzi3j.png)

在 `MOV R7,R0` 处下断点，并修改 `R0` 与 `R2` 的值。

修改为堆栈中的值。可能你的这个值不一样，因为这个值是之前调试的时候的一个时间。这里是时间检测。

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_kkqxdikucfrq21v.png)

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_vaa3r3ch81hp910.png)

然后就没有反调试的代码了，多次按 `F9` 后，就来到了：

![图片](https://bbs.kanxue.com/upload/attach/201610/334351_cxatxejd3vjyoo8.png)

来到了全新的世界。可是我最后没有 dump 出 `native void onCreate`，遗憾。
