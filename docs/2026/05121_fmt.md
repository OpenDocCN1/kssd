
# [原创]自己动手修复`ImpREC`的Bug

## 通过`OD`给`ImpREC`打补丁

（在一次给`inc2l.exe`脱壳的作业中发现的问题）

用来测试BUG的程序：`RadASM`中Tools的`inc2l.exe`

首先用`OD`加载，发现他是一个加壳的程序，

![](https://bbs.kanxue.com/upload/attach/201509/611802_yaty6wvuf5xvmql.png)

入口有保存环境的代码（一般的加壳程序都会保存环境）：

`push eax`，单步步过这条指令，

找到栈顶，数据窗口跟随

![](https://bbs.kanxue.com/upload/attach/201509/611802_w1xxdw3k3cd6beo.png)

然后下硬件访问断点，因为它保存了环境，势必会在他恢复代码之后还原环境的，

![](https://bbs.kanxue.com/upload/attach/201509/611802_ce5k1mbpq41c9zs.png)

然后就可以等着他来了，放开程序跑，F9

第一次来到是一个`0x7C…`开头的地址，可能是系统Dll的代码略过，继续F9

![](https://bbs.kanxue.com/upload/attach/201509/611802_j7ghuv5q1t8xww2.png)

直到断在主程序的地址

![](https://bbs.kanxue.com/upload/attach/201509/611802_v6ou5yj3fmw8im3.png)

经过两次F9后顺利来到了主程序的代码，然后把代码往下翻，看哪里有`jmp`，因为一般还原完代码都会有个`jmp`跳回OEP，不远处就发现了有个`jmp`，选中该行F4程序跑到`0x40AC1E`处

![](https://bbs.kanxue.com/upload/attach/201509/611802_c5ufn6m5ob1ccz4.png)

![](https://bbs.kanxue.com/upload/attach/201509/611802_al4zb58w27zizo5.png)

发现代码已经被还原了，`OD`分析出是模块入口点。

F7单步过去，

![](https://bbs.kanxue.com/upload/attach/201509/611802_fue9z2sbx14z12c.png)

然后右键脱壳，点脱壳，保存文件为`dump.exe`

![](https://bbs.kanxue.com/upload/attach/201509/611802_d4l168aqdhuvnxv.png)

一运行发现崩了，因为他这个程序的导入表在程序加载到内存的时候被抹掉了，这里用到`ImpREC`来修复导入表

![](https://bbs.kanxue.com/upload/attach/201509/611802_tplv8bw2xf4yz41.png)

![](https://bbs.kanxue.com/upload/attach/201509/611802_ymxn78v3qmyeaa3.png)

因为这个程序是要通过手动定位IAT信息通过反推获取导入表信息（程序自带的自动查找IAT不准确），所以需要借助`OD`手动查看IAT表的起始位置和大小。在`OD`里面随便选择一个API点击一下，然后数据窗口跟随，选择数据窗口中跟随地址

![](https://bbs.kanxue.com/upload/attach/201509/611802_ahbeljeg0ikeuh6.png)

再在数据窗口选择长型地址，就发现API名称跟地址都出来了

![](https://bbs.kanxue.com/upload/attach/201509/611802_x7a2l2yy5x5gztu.png)

再通过肉眼过滤，一般API都在很大的地址，所以得到从

![](https://bbs.kanxue.com/upload/attach/201509/611802_7mztsjzri7z5fsf.png) 开始到

![](https://bbs.kanxue.com/upload/attach/201509/611802_gjmymp303ktzva1.png)

大小`0x1F0` ![](https://bbs.kanxue.com/upload/attach/201509/611802_lr4imneazm31zcy.png)

然后在`ImpREC`里填`RVA`：`0x8050`，`Size`：`0x1F0`，然后点获取导入表，发现导入表函数都是有效的，然后点修复。

![](https://bbs.kanxue.com/upload/attach/201509/611802_agwhqsa6hyxd077.png)

选择刚保存的那个`dump`文件，确定

![](https://bbs.kanxue.com/upload/attach/201509/611802_0abrozweeekt5g6.png)

生成了一个 ![](https://bbs.kanxue.com/upload/attach/201509/611802_q3n2im1dhljr7q3.png)`dump_.exe`文件

然后打开发现这次不是访问内存错误了，直接是报应用程序初始化失败。到这里之前不会解析PE出错，只有用了`ImpREC`之后才出了错，然后我们来分析PE格式

![](https://bbs.kanxue.com/upload/attach/201509/611802_jv0968fl7lci3wi.png)

用`WinHex`打开`dump_.exe`，手工分析PE结构，由于刚才我们修复转存文件的时候`ImpREC`添加了一个新节，不知道是不是节区文件的问题，首先看是不是没有修改节的个数，发现是4个节，对照一下是对的。

![](https://bbs.kanxue.com/upload/attach/201509/611802_8z5c25nknkyh2dj.png)

经过仔细对比之后，发现最后添加了一个节区之后，PE头部的总大小变成了`0x218`，然后`ImpREC`并没有修改PE中的`SizeOfHeaders`的大小`0x200`。现在我们通过`WinHex`手动修改它的值为`0x218`保存，然后程序正常运行了。

## 思路

我们要修改PE中的`SizeOfHeaders`，且要在写文件之前，前面我们看到源程序有修改PE的`SizeOfImage`的操作，所以可以找到源程序修改`SizeOfImage`的代码区域，然后在那附近找到合适的代码地址覆盖`jmp`，跳到源程序没有使用的内存空间添加我们修改`SizeOfHeaders`的代码，修改操作完成后添加`jmp`覆盖的指令，再`jmp`回去。

### 如何定位该区域呢？

首先我们知道程序要创建并写文件，所以会调用`CreateFileA`、`WriteFile`。所以我们可以通过API的参数知道写文件的`Buffer`在哪里，然后再通过给`SizeOfImage`的4字节设访问断点可以定位源程序修改PE的`SizeOfImage`代码的地址了。

## LAB

用`OD`打开`ImpREC`程序，F9让他跑，选择`inc2l.exe`的进程，填写`RVA`、`Size`，获取导入表，然后点击修复转存文件，先不要点保存，回到`OD`右键查找当前模块的名称，找到`CreateFileA`，右键设置在每个参考上设置断点，然后回到`ImpREC`选择`Dump`文件点保存，

![](https://bbs.kanxue.com/upload/attach/201509/611802_yabbsbhod2ybmqk.png)

`OD`断了下来，查看堆栈窗口，发现不是我们想要的`dump_.exe`

![](https://bbs.kanxue.com/upload/attach/201509/611802_wgejyu5m27bs20l.png)

放开跑，第二次是创建我们想要的`dump_.exe`

![](https://bbs.kanxue.com/upload/attach/201509/611802_4pj0n1s9enmcwx6.png)

跑到这里肯定会有写文件的操作，再下一个`WriteFile`断点。

然后F9，写文件的时候触发断点，查看堆栈窗口的`buffer`，

数据窗口跟随，他写入的大小是整个文件的大小，

![](https://bbs.kanxue.com/upload/attach/201509/611802_41v0zhu794rr6b7.png)

![](https://bbs.kanxue.com/upload/attach/201509/611802_p6r5or49nkvnyy9.png)

从这里可以印证添加了一个节，源程序修改了`SizeOfImage`，找到该程序操作这块内存的位置下访问断点，从而定位代码

![](https://bbs.kanxue.com/upload/attach/201509/611802_xdoe3j36vb538ly.png)

通过对PE格式的分析，定位到`0XC5CDD0`，右键下断点，一个`DWORD`长度，然后重新跑程序，操作从LAB开始。

之后势必会在访问这个地址的时候断下来，F9的同时观察数据窗口PE数据是不是被读到内存中来了，如果没有，继续F9。之后在`0x42CA12`的地址又触发了断点，发现他的上一条指令就是修改`SizeOfImage`

![](https://bbs.kanxue.com/upload/attach/201509/611802_m09u7wmfzust38j.png)

这一切都是发生在写文件之前的，所以我们可以在这附近找一个合适的地方插`jmp`，跳到别的地址添加代码，然后修复覆盖的指令，再`jmp`回来。一个`jmp`指令对应的机器码是5个字节，我们只要找到一条指令大于等于5字节就可以了。刚好在`0x42CA0F`的下一条指令是6个字节，可以在这里插`jmp`，首先记下这条指令`MOV EAX, DWORD PTR SS:[ebp+420]`，因为插入自己的代码之后还是要还原原指令的（我们只能添加代码，不能修改原有的代码），到代码的最后面找一块空白的地方，

![](https://bbs.kanxue.com/upload/attach/201509/611802_8a1gqgne2uw7d80.png)

在`0x448930`修改这里为`jmp`过去的地址，于是选中`0x42CA12`修改汇编代码：

```
jmp 0x448930
```

![](https://bbs.kanxue.com/upload/attach/201509/611802_qy1wrhsyc0b2psr.png)

![](https://bbs.kanxue.com/upload/attach/201509/611802_pmeztct6kvs9ys0.png)

然后：

1. 再`0x448930`的地址添加汇编代码修改`SizeOfHeaders`：

```
ADD DWORD PTR DS:[EAX+3C],28
```

每次都加一个节的大小`0x28`。

2. 保存`jmp`覆盖的原指令：

```
MOV EAX,DWORD PTR SS:[EBP+420]
```

3. 修改完之后要跳回去继续执行原来的代码，添加：

```
jmp 0x42CA18
```

![](https://bbs.kanxue.com/upload/attach/201509/611802_qhz156snw467k4b.png)

然后全选复制到可执行文件，再保存为`ImpREC_fix.exe`。到这里已经修复完了。

## 2015-09-16 修改

由于上次是用了`OllyDump`的时候没有取消它的默认选项重建导入表，但是`OD`并没有修复成功，又多出了一个节表。

然后我用`ImpREC`再次修复IAT的时候又多添加了一个节表，然后就出现了我遇到的问题……

我取消了重建输入表选项，之后用`ImpREC`修复就没有问题了。

这里多谢“Kisesy”的提醒。

然后我又想给它打个补丁，**让其在`Dump`出`.exe`后，无论添加多少个节表，用`ImpREC`修复都不会出错。**

### 分析

可能是`ImpREC`修复的时候没有检查`Dump`出来的文件有多少个节，直接在后面添加一个节，然后写导入表信息。我们可以在其写`dump_.exe`文件之前，算一下内存中`dump`文件的节表个数，写入`SizeOfHeaders`就行了。

### 修复

从上次最后修改补丁的地方开始。

覆盖原来的修改代码，加入如下汇编代码（经过分析PE格式写出的，望大家指教）：

```
    pushad									;保存环境
    lea eax, dword ptr ss:[eax+0x98]				;获取MZ头地址

    mov ecx, dword ptr ds:[eax+0x3C]
    lea edx, dword ptr ds:[eax+ecx]				;获得PE标志地址	IMAGE_NT_HEADERS

    lea esi, dword ptr ds:[edx+0x18]
    xor ecx, ecx
    mov cx, word ptr ds:[edx+0x14]
    add esi, ecx								;求得节表的首地址
    mov cx, word ptr ds:[edx+6]					;节表个数：edx+8
    imul ecx, 0x28							;求出当前的节表总大小
    add ecx, 0x28							;求出修复后的节表总大小
    add esi, ecx								;节表尾地址
    sub esi, eax								;节表尾减MZ头求出SizeOfHeaders
    mov dword ptr ds:[edx+0x54], esi				;复制SizeOfHeaders到Buffer
    popad									;还原环境
    MOV EAX,DWORD PTR SS:[EBP+420]			;修复jmp覆盖的代码
    jmp 0042CA18
```
