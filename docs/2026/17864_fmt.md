
# [原创] CVE-2014-0322 IE与Flash结合利用 绕过ASLR+DEP

## 前言

Flash与html结合利用在前几年的攻防对抗中非常火爆，Flash使用的脚本语言是ActionScript，Html使用的是JavaScript，两种脚本语言各有其特性，ActionScript通过`Vector<uint>`对内存读写数据来定位模块基址以及堆喷射，JavaScript通过字符串占位来覆盖释放后的对象，最后调用shellcode的任务是ActionScript完成的，其实一开始我也比较困惑，既然漏洞是JavaScript代码造成的，那Shellcode怎么会是ActionScript执行的？这也是这个漏洞利用有趣的地方!

漏洞详情:

Use-after-free vulnerability in Microsoft Internet Explorer 9 and 10 allows remote attackers to execute arbitrary code via vectors involving crafted JavaScript code, CMarkup, and the onpropertychange attribute of a script element, as exploited in the wild in January and February 2014.

收集异常时基本信息：

浏览器载入poc代码，`x64dbg`附加进程，运行后断到`0x649F1B97`, 看下`EDX`处内存，发现已经被覆盖成`0x19FFFFF3`了，如果异常时`EDX`指向的堆中的数值没有出现被覆盖的情况，那也是正常的，多加载几次poc总能撞出一次的，这是因为`title`属性占位成功几率有点感人，大家凑合着用吧，`EAX`指向`0x19FFFFF3`这个地址，这个地址现在是不可访问的，因为现在还没有结合FLASH脚本利用，在后面的ActionScript中会进行堆喷射，在堆喷射后`0x19FFFFF3`这个地址才会有效;

IDA看下这个异常函数, 函数名为`CMarkup::UpdateMarkupContentsVersion`，`EDX`很明显是对象指针，从这个情况分析是`CMarkup`对象释放后被占位了

创建`CMarkup`对象代码在`CDoc::CreateMarkupFromInfo`函数中的234行

对`CDoc::CreateMarkupFromInfo`下断，根据栈回溯信息来看，创建这个`CMarkup`对象的JavaScript代码为 `c = b.appendChild(c);`

`CMarkup`的释放由`CMarkup::`scalar deleting destructor`函数完成

对`CMarkup`释放函数下断，断下来后发现是设置`outerHTML`属性导致的释放的

异常分析总结：

根据之前异常和调试收集来的信息，在JavaScript中 `c = b.appendChild(c)` 执行时创建`CMarkup`，`this.outerHTML=this.outerHTML`导致释放`CMarkup`，而释放后的占位是`g_arr[a].title = d.substring(0, d.length)` 完成的，`d`这个字符串偏移`0x94`、`0x98`、`0x15c`处写入的固定数值是为了结合Flash利用和防止程序崩溃，具体的作用还得自己动手调试才能完全理解;

### Exploit代码分析总结

在浏览器中输入指定地址并进入，会找HTTP服务器要HTML代码，HTML代码在客户端执行时又会通过

`embed`



标签向HTTP服务器要`swf`脚本，`swf`脚本执行时把`AsXploit`的构造当作入口点并调用，在`swf`入口函数中先进行堆喷射初始化堆内存与`Flash`对象，再通过`Flash`提供的扩展接口调用`JavsScript`的`trigger`函数触发漏洞，触发漏洞时破坏`Flash`中`Vector`对象的内存，将`Vector`长度设置为`0x010003F0`，之后通过创建定时器检查漏洞是否触发，检查的条件就是`Vector`的长度是否被破坏成了`0x010003F0`，确认漏洞触发后停掉当前定时器，并拿到被破坏的`Vector`索引`i2`，通过`i2`这个索引在内存中反向扫描找到`FLASH`模块基址的偏移给`baseflashaddr_off`，接下来就可以通过`Vector+baseflashaddr_off`越界访问指定的内存，能访问指定的内存就能对内存中的`DLL`做`PE`格式分析，通过`PE`文件分析就能拿到导入的函数地址，这样即使`ntdll`在内存中位置是随机的也无所谓了，在这份代码中扫描导入表拿到了`VirtualProtect`地址，目的是通过`VirtualProtect`设置堆内存属性，让堆内存拥有执行代码的权限，这样的话`DEP`也就可以无视了，`DEP`能绕过后还需要一条可以切栈的指令让栈寄存器指向堆来执行代码，在代码中寻找切栈指令的是`getSP`函数，在函数中一样是通过分析文件`PE`格式来找到代码节，再在代码节中去找可以利用的切栈指令，为什么在代码节中找？那是因为数据节的数据是可变的，有了切栈指令和`VirtualProtect`就可以调用`buildPayload`函数构建`ROP`了，在`buildPayload`函数中除了构建`ROP`，还有一个比较关键的点就是故意去破坏`Sound`对象虚表，破坏`Sound`对象虚表的目的是让`Sound`对象调用`toString`虚函数时转而去执行切栈指令达到代码利用的目的，在一切准备就绪后直接使用了被破坏的`sound`对象并调用其成员函数`toString`去完成了利用，通过目前掌握的信息可以看得出来，写这份`Exploit`代码的作者一定对`Flash`的内存情况了如指掌，想要彻底理解这份代码还需要各位看官自己实际动手调试，特别是`Flash`越界访问内存这里我个人认为是非常经典的！
