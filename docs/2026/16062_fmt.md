### `registerHook`函数

我们现在主要分析`registerHook`函数。

先来分析参数。

在 Hook 之前我们首先要注册这个函数。

函数声明：

```cpp
HOOK_STATUS registerHook(
    Elf_Addr orginalFunAddr,
    Elf_Addr newFunAddr,
    Elf_Addr* callOrigin
);
```

参数：原始函数地址、新函数地址、调用原始函数。

函数主要流程：

1. 注册函数信息，计算 Hook stub。

   首先判断`originFunAddr`和`newFunAddr`是否是函数地址。

   `auto info = getHookInfo(originFunAddr);` 得到函数信息。

   然后判断函数是否已经被 Hook。

2. 检查判断指令类型（Thumb、ARM、x86 等）。

3. `createStub(info)` 创建 stub，就是 Thumb 下创建`ldr.w pc, [pc], addr`来执行跳转到`newFuncAddr`的功能。

4. `createCallOriginalStub(info)` 创建`originalFunAddr`的 stub，主要会涉及一些对 PC 相关指令的处理。

```cpp
// register hook
FAInHook::HOOK_STATUS FAInHook::registerHook(
    Elf_Addr orginalFunAddr,
    Elf_Addr newFunAddr,
    Elf_Addr *callOrigin) {
    // register hook information, calc hook stub at the same time.
    if (!FAHook::MemHelper::isFunctionAddr((void *) orginalFunAddr)
        || !FAHook::MemHelper::isFunctionAddr((void *) newFunAddr)) {
        return FERROR_NOT_EXECUTABLE;
    }

    auto info = getHookInfo(orginalFunAddr);

    if (nullptr != info) {
        auto hookStatus = info->getHookStatus();

        if (FAHook::HOOKED == hookStatus) {
            return FERROR_ALREADY_HOOKED;
        } else if (FAHook::REGISTERED == hookStatus) {
            delHookInfo(info);
        }
    }

    // check for FunctionType
    auto type = FAHook::Instruction::getFunctionType(orginalFunAddr);

    if (FAHook::ERRTYPE == type) {
        return FERROR_UNKNOWN;
    }

    info = new FAHook::HookInfo(
        (void *) orginalFunAddr,
        (void *) newFunAddr
    );

    info->setOriginalFunctionType(type);

    FAHook::Instruction* instruction = nullptr;

    switch (type) {
#if defined(__arm__)
        case FAHook::ARM:
            instruction = new FAHook::ArmInstruction();
            break;
        case FAHook::THUMB:
            instruction = new FAHook::ThumbInstruction();
            break;
#elif defined(__aarch64__)
        case FAHook::ARM64:
            instruction = new FAHook::Arm64Instruction();
            break;
#elif defined(__i386__) || defined(__x86_64__)
        case FAHook::X86:
        case FAHook::X64:
            instruction = new FAHook::IntelInstruction();
            break;
#elif defined(__mips64__)
        case FAHook::MIPS64:
            instruction = new FAHook::Mips64Instruction();
            break;
#elif defined(__mips__)
        case FAHook::MIPS:
            instruction = new FAHook::MipsInstruction();
            break;
#endif
        default:
            assert(false && "not support abi");
            return FERROR_UNKNOWN;
            break;
    }

    if (!instruction->createStub(info)
        || !instruction->createBackStub(info)
        || (callOrigin != nullptr)
            ? !instruction->createCallOriginalStub(info)
            : false // want a callback
    ) {
        delete instruction;
        delete info;
        return FERROR_MEMORY;
    }

    addHookInfo(info);
    info->setHookStatus(FAHook::REGISTERED);

    if (callOrigin != nullptr) {
        *callOrigin = (Elf_Addr) info->getCallOriginalIns();
    }

    delete instruction;
    return FERROR_SUCCESS;
}
```

#### 判断该地址是否是函数地址

1. 打开`/proc/self/maps`，读取每行的信息，用`strstr`根据权限做出判断。（`r-x`表示可读可执行，即为 code。）

2. `addr >= startAddr && addr <= endAddr`

```cpp
bool FAHook::MemHelper::isFunctionAddr(void *addr) {
    char buf[MAX_BUF];
    auto fp = fopen(maps, "r");

    if (nullptr == fp) {
        return false;
    }

    while (fgets(buf, MAX_BUF, fp)) {
        if (strstr(buf, "r-xp") != nullptr) {
            void* startAddr = (void*)strtoul(
                strtok(buf, "-"),
                nullptr,
                16
            );

            void* endAddr = (void*)strtoul(
                strtok(nullptr, " "),
                nullptr,
                16
            );

            if (addr >= startAddr && addr <= endAddr) {
                fclose(fp);
                return true;
            }
        }
    }

    fclose(fp);
    FLOGE(this functionAddr is not a function!);
    return false;
}
```

#### 得到 Hook 地址的信息，判断是否已经 Hook

```cpp
    return it->second;
```

#### 接下来，我们分析最重要的过程

1. `info = new HookInfo(originFunAddr, newFunAddr);`

2. `info.setOriginalFunctionType(type);` 设置指令类型为 ARM 或者 Thumb。

3. `instruction = new FAHook::ArmInstruction();` 新建 ARM 或者 Thumb 指令对象。我发现无构造函数。

4. `instruction->createStub(info);` 创建 stub。（stub 为 jump stub，用来跳转到`newFuncAddr`。）

5. `instruction->createCallOriginalStub(info)` 创建原函数的 callback stub。

在查看`HookInfo.h`时，我们可以看到`FAHook`是一个`namespace`，而里面主要包含了一个`HookInfo`类。

### 分析`createStub(info)`

我们这里分析`FAHook::ThumbInstrution::createStub(FAHook::HookInfo *info)`：

1. 将地址按 4 字节对齐。



2. 保存我们的`stub`指令, (方便之后`path`)指令为: `LDR.W PC, [PC]`. 可参考(<mark class="encrypted">b1eK9s2c8@1M7q4)9K6b7g2)9J5c8W2)9J5c8X3g2D9k6e0N6W2L8Y4S2^5K9q4)9J5k6h3y4G2L8g2)9J5c8V1q4F1k6s2u0G2K9h3c8Q4x3X3c8m8M7X3#2Q4x3X3c8u0L8X3I4A6L8X3g2Q4x3X3c8t1L8$3!0C8i4K6u0W2K9s2c8E0L8q4)9J5z5g2)9J5k6b7`.`.</mark>

```
bool FAHook::ThumbInstruction::createStub(FAHook::HookInfo *info) {
    auto stubSize = 0;
    uint8_t *stub = nullptr;
    uint32_t addr = (uint32_t)info->getOriginalAddr();
    auto clearBit0 = addr & 0xFFFFFFFE;
    if (clearBit0 % 4 != 0) { // need to align 4, just patch with nop
        stub = new uint8_t[10];
        ((uint16_t*)stub)[stubSize++] = 0xBF00; //NOP
    } else {
        stub = new uint8_t[8];
    }
    ((uint16_t*)stub)[stubSize++] = 0xF8DF;
    ((uint16_t*)stub)[stubSize++] = 0xF000; // LDR.W PC, [PC]
    ((uint16_t*)stub)[stubSize++] = (uint32_t)info->getHookAddr() & 0xFFFF;
    ((uint16_t*)stub)[stubSize++] = (uint32_t)info->getHookAddr() >> 16;
    info->setJumpStubLen(stubSize * 2);
    info->setJumpStubBack(stub);
    return true;
}
```

### 下面分析 `createCallOriginalStub(HookInfo *info)`:

`thumbInstruction.cpp`的实现:

基础知识:

`reinterpret_cast<uint16_t*>` 为类型转换

1. 处理`ldr.w`指令.
2. 调用`createExecMemory(length);` // 分配`buffer`空间
3. 修正`pc`相关指令. (`ldr` `liternal`. `b`. `b`. `bl`. `cbz`. `ldrw`. `add`)

`为什么要修正pc相关指令?`

举例分析: `b <label>`:

指令编码分析: `[15:12] 1101 [11:8] cond [7:0] imm8`

解析时: `imm32 = ZeroExtend(imm8:'0', 32);`

`BranchWritePC(PC+imm32)`

可以看到, `b`指令的指令编码中, 存放的立即数为`imm8`, 而真实的跳转地址为`(pc + imm32)`.

由于我们是要`inlineHook`, 所以我们的`hook`函数执行完成之后还有继续执行我们原来的函数,那么我们就要执行被`patch`掉的那些指令（我们已经将这些指令保存了下来），但由于存放这些指令的内存是我们`mmap`出来的,所以我们 要想能够在这里成功运行`pc`相关指令的话, 我们需要将`pc`相关的指令转换为其它`pc`无关的指令。

# MSGetInstructionWithThumb

调用`used += MSGetInstructionWithThumb(reinterpret_cast<uint8_t *>(area) + used);`

`MSGetInstructionWithThumb`的参数为`uint16_t*`。

`T$32bit$i`的作用：

`(指令(ic) & 1110 0000 0000 0000) && (ic & 0001 1000 0000 0000 != 0x0000)`

第一个判断用于确定高位3个bit（即`bit[15]`、`bit[14]`、`bit[13]`）为1。第二个判断用于确保`bit[12]`、`bit[11]`有值（即至少这两位中有1位为1）。

### createExecMemory

```cpp
void *FAHook::MemHelper::createExecMemory(uint32_t size) {
    if(size & 1) {
        size++;
    }
    if(size > page_size) {
        return nullptr;
    }
    if(gMemHelper.current_page != nullptr && page_size - gMemHelper.page_ptr_ >= size) {
        auto funPtr = (void*)((size_t)gMemHelper.current_page + gMemHelper.page_ptr_);
        gMemHelper.page_ptr_ += size;

        // Align 4
        while(gMemHelper.page_ptr_ & 0x3) {
            gMemHelper.page_ptr_++;
        }
        return funPtr;
    }

    // scroll to next page
    auto newPage = mmap(nullptr, page_size, PROT_READ | PROT_WRITE | PROT_EXEC, MAP_ANONYMOUS | MAP_PRIVATE, 0, 0);
    if(newPage != MAP_FAILED) {
        gMemHelper.alloc_memory_page_.push_back(newPage);
        gMemHelper.current_page = newPage;
        gMemHelper.page_ptr_ = 0;
        return createExecMemory(size);
    }
    return nullptr;
}
```

### patchMemory

```cpp
bool FAHook::Instruction::patchMemory(void *dest, void *src, uint32_t len) {
    if(dest == nullptr || src == nullptr || len == 0) {
        return false;
    }
    if(!MemHelper::unProtectMemory(dest, len)) {
        return false;
    }
    memcpy(dest, src, len);
    MemHelper::protectMemory(dest, len);
#ifdef __arm__
    cacheflush((Elf_Addr)dest, (Elf_Addr)dest + len, 0);
#endif
    return true;
}
```

首先会调用`unProtectMemory`函数，将对应内存修改为`rwx`；然后调用`memcpy`来修改内存；最后调用`protectMemory`，将对应内存修改为`r-x`。

## 总结

现在我们就基本对该项目进行了简单的分析，这里总结一下：

1. `registerHook`

   主要操作其实就是：

   - `createStub`：创建代理（这个代理就是要执行跳转到`newFuncAddr`函数）。
   - `createCallOriginalStub`：创建callback代理（这个代理就是执行回调，回调我们的`originalFunAddr`）。主要涉及处理PC相关指令，原因在文中已经有介绍。

2. `doInHook`

   - 主要就是`patchMemory`，将`originalFunAddr`函数起始处的几个指令patch为`stubInstruction`。之后函数涉及PC相关指令的修复，方便继续执行原函数。

3. `unHook`

   - 也是`patchMemory`，就是将原函数的原始指令进行复原。

### registerHook函数

我们现在主要分析`registerHook`函数。

先来分析参数。

在Hook之前我们首先要注册这个函数。

函数声明：

```cpp
HOOK_STATUS registerHook(Elf_Addr orginalFunAddr, Elf_Addr newFunAddr,
                         Elf_Addr* callOrigin);
```

参数为原始函数地址、新函数地址、调用原始函数。

函数主要流程：

1. 注册函数信息，计算Hook stub。

   首先判断`originFunAddr`和`newFunAddr`是否是函数地址。

   `auto info = getHookInfo(originFunAddr);` 得到函数信息。

   然后判断函数是否已经被Hook。

2. 检查判断指令类型（Thumb、ARM或x86等）。

3. `createStub(info)`：创建stub，就是在Thumb下创建`ldr.w pc, [pc], addr`来执行跳转到`newFuncAddr`的功能。

4. `createCallOriginalStub(info)`：创建`originalFunAddr`的stub，主要会涉及一些对PC相关指令的处理。




```cpp
// register hook

FAInHook::HOOK_STATUS FAInHook::registerHook(
        Elf_Addr orginalFunAddr, Elf_Addr newFunAddr, Elf_Addr *callOrigin) {
    // register hook information, calc hook stub at the same time.

    if (!FAHook::MemHelper::isFunctionAddr((void *)orginalFunAddr)
        || !FAHook::MemHelper::isFunctionAddr((void *)newFunAddr)) {
        return FERROR_NOT_EXECUTABLE;
    }

    auto info = getHookInfo(orginalFunAddr);

    if (nullptr != info) {
        auto hookStatus = info->getHookStatus();

        if (FAHook::HOOKED == hookStatus) {
            return FERROR_ALREADY_HOOKED;
        } else if (FAHook::REGISTERED == hookStatus) {
            delHookInfo(info);
        }
    }

    // check for FunctionType

    auto type = FAHook::Instruction::getFunctionType(orginalFunAddr);

    if (FAHook::ERRTYPE == type) {
        return FERROR_UNKNOWN;
    }

    info = new FAHook::HookInfo((void *)orginalFunAddr, (void *)newFunAddr);
    info->setOriginalFunctionType(type);

    FAHook::Instruction* instruction = nullptr;

    switch (type) {
#if defined(__arm__)
        case FAHook::ARM:
            instruction = new FAHook::ArmInstruction();
            break;

        case FAHook::THUMB:
            instruction = new FAHook::ThumbInstruction();
            break;

#elif defined(__aarch64__)
        case FAHook::ARM64:
            instruction = new FAHook::Arm64Instruction();
            break;

#elif defined(__i386__) || defined(__x86_64__)
        case FAHook::X86:
        case FAHook::X64:
            instruction = new FAHook::IntelInstruction();
            break;

#elif defined(__mips64__)
        case FAHook::MIPS64:
            instruction = new FAHook::Mips64Instruction();
            break;

#elif defined(__mips__)
        case FAHook::MIPS:
            instruction = new FAHook::MipsInstruction();
            break;
#endif

        default:
            assert(false && "not support abi");
            return FERROR_UNKNOWN;
            break;
    }

    if (!instruction->createStub(info)
        || !instruction->createBackStub(info)
        || (callOrigin != nullptr)
            ? !instruction->createCallOriginalStub(info)
            : false  // want a callback
       ) {
        delete instruction;
        delete info;
        return FERROR_MEMORY;
    }

    addHookInfo(info);
    info->setHookStatus(FAHook::REGISTERED);

    if (callOrigin != nullptr) {
        *callOrigin = (Elf_Addr)info->getCallOriginalIns();
    }

    delete instruction;
    return FERROR_SUCCESS;
}
```

### 分析 `createStub(info)`

这里分析`FAHook::ThumbInstrution::createStub(FAHook::HookInfo *info)`：

1. 将地址按4字节对齐。
2. 保存`stub`指令，方便之后回写。指令为：`LDR.W PC, [PC]`。可参考相关指令文档。

```cpp
bool FAHook::ThumbInstruction::createStub(FAHook::HookInfo *info) {
    auto stubSize = 0;
    uint8_t *stub = nullptr;

    uint32_t addr = (uint32_t)info->getOriginalAddr();
    auto clearBit0 = addr & 0xFFFFFFFE;

    if (clearBit0 % 4 != 0) {  // need to align 4, just patch with nop
        stub = new uint8_t[10];
        ((uint16_t*)stub)[stubSize++] = 0xBF00;  // NOP
    } else {
        stub = new uint8_t[8];
    }

    ((uint16_t*)stub)[stubSize++] = 0xF8DF;
    ((uint16_t*)stub)[stubSize++] = 0xF000;  // LDR.W PC, [PC]
    ((uint16_t*)stub)[stubSize++] = (uint32_t)info->getHookAddr() & 0xFFFF;
    ((uint16_t*)stub)[stubSize++] = (uint32_t)info->getHookAddr() >> 16;

    info->setJumpStubLen(stubSize * 2);
    info->setJumpStubBack(stub);

    return true;
}
```

### 分析 `createCallOriginalStub(HookInfo *info)`

`thumbInstruction.cpp`的实现。

#### 基础知识

`reinterpret_cast<uint16_t*>`为类型转换。

1. 处理`ldr.w`指令。
2. 调用`createExecMemory(length);`分配`buffer`空间。
3. 修正`PC`相关指令（`ldr literal`、`b`、`b`、`bl`、`cbz`、`ldrw`、`add`）。

#### 为什么要修正 PC 相关指令？

以`b <label>`为例：

指令编码分析：`[15:12] 1101 [11:8] cond [7:0] imm8`

解析时：

```text
imm32 = ZeroExtend(imm8:'0', 32);
BranchWritePC(PC + imm32);
```

可以看到，`b`指令的指令编码中存放的立即数为`imm8`，而真实的跳转地址为`PC + imm32`。

由于我们使用的是`inlineHook`，所以`hook`函数执行完成之后还要继续执行原来的函数。因此，我们需要执行被`patch`掉的那些指令（这些指令已经被保存下来）。但由于存放这些指令的内存是通过`mmap`分配出来的，所以如果想要在这里成功运行`PC`相关指令，就需要将`PC`相关指令转换为其他与`PC`无关的指令。

### MSGetInstructionWithThumb

调用`used += MSGetInstructionWithThumb(reinterpret_cast<uint8_t *>(area) + used);`

`MSGetInstructionWithThumb`的参数为`uint16_t*`。

返回结果：这条指令占用多少字节（`4`或`2`）。

`T$32bit$i`的作用：

`(指令(ic) & 1110 0000 0000 0000) && (ic & 0001 1000 0000 0000 != 0x0000)`

第一个判断用于确定高位的3个bit（即`bit[15]`、`bit[14]`、`bit[13]`）为1。第二个判断用于确保`bit[12]`、`bit[11]`有值（即至少这两位中有1位为1）。

其实就是判断该`thumb`指令是否为`thumb32`指令。

`thumb32`指令的判断依据是`b[15:11]`为`0b11101`、`0b11110`或`0b11111`。

`MSGetInstructionWithThumb`：

```cpp
static size_t MSGetInstructionWidthThumb(void *start) {
    uint16_t *thumb(reinterpret_cast<uint16_t *>(start));   //

    return T$32bit$i(thumb[0]) ? 4 : 2;
}
```

`T$32bit$i`：

```cpp
static inline bool T$32bit$i(uint16_t ic) {
    return ((ic & 0xe000) == 0xe000 && (ic & 0x1800) != 0x0000);
}
```

### 分析`MemHelper`类

有4个方法：

1. `static bool isFunctionAddr(void* addr);`
2. `static bool unProtectMemory(void* addr, uint32_t size);`：移除写保护。
3. `static bool protectMemory(void* addr, uint32_t size);`：添加写保护。
4. `static void* createExecMemory(uint32_t size);`：创建一块可执行内存。

有4个field：

1. `std::vector<void*> all_memory_page;`
2. `void* current_page = nullptr;`
3. `uint32_t page_ptr = 0;`
4. `static uint32_t page_size;`：构造函数中执行`page_size = sysconf(_SC_PAGESIZE);`。

我们现在分析一下`createExecMemory(uint32_t size)`：

1. 可以看到，分配内存的操作是通过`mmap`实现的。
2. `all_memory_page`是一个`vector`，每个单位保存一个指针，指向`mmap`分配的内存。

`createExecMemory`：

```cpp
void *FAHook::MemHelper::createExecMemory(uint32_t size) {
    if(size & 1) {
        size++;
    }

    if(size > page_size) {
        return nullptr;
    }

    if(gMemHelper.current_page != nullptr && page_size - gMemHelper.page_ptr_ >= size) {
        auto funPtr = (void*)((size_t)gMemHelper.current_page + gMemHelper.page_ptr_);

        gMemHelper.page_ptr_ += size;

        // Align 4
        while(gMemHelper.page_ptr_ & 0x3) {
            gMemHelper.page_ptr_++;
        }

        return funPtr;
    }

    // scroll to next page
    auto newPage = mmap(nullptr, page_size, PROT_READ | PROT_WRITE | PROT_EXEC, MAP_ANONYMOUS | MAP_PRIVATE, 0, 0);

    if(newPage != MAP_FAILED) {
        gMemHelper.alloc_memory_page_.push_back(newPage);

        gMemHelper.current_page = newPage;
        gMemHelper.page_ptr_ = 0;

        return createExecMemory(size);
    }

    return nullptr;
}
```

```cpp
bool FAHook::Instruction::patchMemory(void *dest, void *src, uint32_t len) {
    if(dest == nullptr || src == nullptr || len == 0) {
        return false;
    }

    if(!MemHelper::unProtectMemory(dest, len)) {
        return false;
    }

    memcpy(dest, src, len);
    MemHelper::protectMemory(dest, len);

#ifdef __arm__
    cacheflush((Elf_Addr)dest, (Elf_Addr)dest + len, 0);
#endif
```

首先会调用`unProtectMemory`函数，将对应内存修改为`rwx`；然后调用`memcpy`来修改内存；最后调用`protectMemory`，将对应内存修改为`r-x`。

## 总结

现在我们就基本对该项目进行了简单的分析，下面总结一下：

1. `registerHook`

   主要操作其实就是：

   - `createStub`：创建代理。这个代理用于跳转到我们的`newFuncAddr`函数。
   - `createCallOriginalStub`：创建`callback`代理。这个代理用于执行回调，回调我们的`originalFunAddr`。该过程主要涉及处理与`pc`相关的指令，原因在文中已经有介绍。

2. `doInHook`

   - 主要就是`patchMemory`：将`originalFunAddr`函数起始处的几个指令修改为`stubInstruction`。之后会涉及与`pc`相关指令的修复，以便继续执行原函数。

3. `unHook`

   - 同样是`patchMemory`，用于将原函数的原始指令复原。
