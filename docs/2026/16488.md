# [原创]Linux kernel debug设计浅析

## QEMU启动参数

linux版本5.2.0-rc4

```
qemu-system-x86_64  -smp 4 -kernel bzImage  -m 4096 -hda ~/stretch.img  -serial stdio -append "earlyprintk=serial console=ttyS0 kgdboc=ttyS0 kgdbwait root=/dev/sda nokaslr" -enable-kvm -cpu host  -s -S -display none
```

## 内核命令行参数分析

图2看到kdb是从一个int3中断进入的。分析参数后发现是kgdbwait参数最后调用kgdb\_breakpoint()也就是int 3的原因。

![](https://bbs.kanxue.com/upload/attach/201907/603450_G2ZQ7YSGTWWU2AR.png)

图3

从int3中断向上找关键函数。发现kgdb\_cpu\_enter()是kdb的入口。重启虚拟机对kgdb\_cpu\_enter（）下断点。发现kgdb\_cpu\_enter（）并不是中断一次

![](https://bbs.kanxue.com/upload/attach/201907/603450_QEGN3BHEW2NAWPD.png)

图4

这次是从nmi中断进入的。也就是还有代码给cpu发送了一个nmi导致。最后找到是kgdb\_cpu\_enter（）发送的nmi中断。

![](https://bbs.kanxue.com/upload/attach/201907/603450_WYENVRSA8EXQU5G.png)

图5

代码给了解释。原来是int3中断只能让一个核进入kdb。对于多核系统仅让一个核进入kdb其他核正常运行显然不合理，所以要让所有核都进入kdb。kgdb\_cpu\_enter()--->kdb\_stub()--->kdb\_main\_loop()--->kdb\_parse ()执行1054行对应每个命令的处理函数

![](https://bbs.kanxue.com/upload/attach/201907/603450_QPVVZBJDNTASVRG.png)
