![图片描述](upload/attach/202308/945828\_53C4HGMGWZX62FN.png)
## 1.3 遍历/proc/self/task/xx/stat文件，读取当前线程状态是否为tracing
![图片描述](upload/attach/202308/945828\_DHC5ADE4DP8KCB6.png)
实际过程中stat的输出格式是 pid (name) status xxxxxxx
该方法就是判断读取到的status是否为“T”(会通过 |0x20 将其转为“t”,ASCII码为116)
## 1.4 （猜测）检测到异常后的处理方式-等待其他大佬指正~
处理代码未作详细分析，这里只说说我根据一些字符串的猜测：
在上述三个方法检测到异常后，会调用JNI\_GetCreatedJavaVMs方法
![图片描述](upload/attach/202308/945828\_VW59PXGRJMVNRRR.png)
而这个方法是获取已经创建的 Java 虚拟机实例，根据“使用frida-spwan模式hook会导致应用短暂卡顿后，frida进程退出，应用恢复运行”的现象，我猜测是把被hook进程干掉了，以一个新进程运行了上面的Java 虚拟机实例。

![图片描述](upload/attach/202308/945828\_86PAA3VS9VG28FN.png)
确定hook特征后 通过执行svc执行进行退出（具体执行会动态解密）
![图片描述](upload/attach/202308/945828\_CS3G686YJVGW4S6.png)
## 2.5 检测到异常后的退出逻辑
在上述检测逻辑后，部分使用的是直接的函数调用exit(0)，另外一部分是使用svc调用 exit\_group，所以仅hook libc的exit函数是无法做到绕过检测的。
