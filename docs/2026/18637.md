返回地址显然确实有些问题。

Vs如果开启了GS编译选项，那么它会在堆栈上插入一个安全cookie来测试返回地址是否被修改，这个值会被存放在堆栈中的开始某处,在函数结束前通常会会调用检测函数来对比这个值

通常会有如下类似汇编代码：

```
Mov ecx,[esp+var_coookie]     //通常ecx为当前返回地址的值
Call  __security_check_cookie;
```

`__security_check_cookie`函数内部只有几行代码比较`ecx`看是都与原返回地址一致,一致就正常返回，不一致就跳转到`report_failure`（该函数将调用`__security_error_handler`）

因为`BGCloudSH_1_0_0_1__750_!DllUnregisterServer+0x1cf5d`还处在`__security_check_cookie`代码内

所以我们需要查看`BGCloudSH_1_0_0_1__750_!DllUnregisterServer+0x26fb`所在函数的代码，这个时候用`IDA`看更直观，所以我们上`IDA`。当然在这之前需要查看一下模块所在地址：
