//原程序在 sub\_4D1BD0

```

short CalcNum(int a1, char *pszName, int nNameLen)
{
    unsigned short* psTable=(unsigned short*)g_szTable;
    int v5=0;
    char *pBuf=pszName;
    int nTemp=a1;
    for(int i=0;i<nNameLen;i++)    
    {
        v5=(*pBuf)^nTemp;
        nTemp=psTable[LOBYTE(v5)]^(nTemp>>8);
        pBuf++;
    }
    return nTemp;
}
```


算法就是根据传入的字符串和字符串长度进行某些运算后查表然后得到一个值。
4.程序会根据用户输入的用户名通过CalcNum计算出一个值，然后调用sprintf之类的函数把值转成字符串，然后用这个字符串的前两位与用户输入的注册的3,4位分别比较，相等则继续，不相等则结束。
5.接着程序根据用户输入注册码的第2-最后这个字符串通过CalcNum计算出一个值，然后调用sprintf之类的函数把值转成字符串，然后用这个字符串的前两位与用户输入的注册的1,2位分别比较，相等则继续，不相等则结束。
说的可能有点绕，举个例子可能就清楚了。
假如用户名是test ,注册码输入的是12345678
用户名是test用calcNum函数算出来并转成字符串是“F82E”，程序接着就会拿F8跟23这两位比较，不相等就结束了。
假如他们相等了，就用345678这一串调用calcNum函数算出来并转成字符串，然后跟12比较是否相等。

这个算法比较长也比较蛋疼，不再写算法，只大致写下过程。
这个算法的前半部分是生成一个加密字符串，后半部分是保存这个加密的license。
加密字符串长度是固定的：
> +0 固定值 //DB892918
> +4 保存的是一个长度值
> +6 保存的是一个长度值
> +8 保存的是用户名和注册码加密后的字符串
>
> nLen1=用户名长度+注册码长度+2
> nLen2=nLen1/100+nLen1+0xC
> +4 位置的数据算法：
> 取出g\_dw0x5c1da4处的值【182989DB】也就是前四位转成DOUBLE值，然后把这个值作为srand函数的种子然后在调用rand()函数得到一个值A 然后用A+nlen1 再取低两位的值
> +6 位置的数据算法：
> 取出g\_dw0x5c1da4处的值【182989DB】也就是前四位转成DOUBLE值，然后把这个值+1作为srand函数的种子然后在调用rand()函数得到一个值B 然后用B+用户名和注册码加密后的长度 再取低两位的值
> +8 ：
> 加密函数sub\_ 00503CD0(arg1,arg2,arg3,arg4)
> 参数1：new出来的空间 长度nLen2 存放加密后的字符串
> 参数2：int\*指针 传入是new空间的长度 传出加密后字符串长度
> 参数3：用户名和注册码按照[用户名长度 用户名字符串 注册码长度 注册码长度]这样格式排列的字符串
> 参数4：参数3字符串的长度
> 具体加密算法太长就不跟了。


这么拼接的字符串最后保存在：（xp下其他系统可能有变化）

3.Reg\_u.ini 的License字段中
