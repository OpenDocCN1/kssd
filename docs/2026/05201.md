
# [原创]0基础破解一款经典游戏反作弊器的过程

## 前言

我是出于对反作弊代码实现的好奇，和想知道这款软件中有无恶意代码，所以想跟踪一下；同时声明本次破解并无恶意，仅仅是作为一次尝试和练习的过程。

我是真正的0基础开始学习，并无编程经验，也非IT魔界人士，只是对计算机安全感兴趣，看过不少相关资料的书籍；也经常浏览看雪论坛中各位大神的技术分享，收获颇丰，本次就自己斗胆尝试了一下破解的过程。

当然，这次破解我选择的破解对象也比较简单，如果您是高手的话完全可以路过的。下面是这款游戏（Cs1.5）反作弊登陆器的界面：

![](upload/attach/202101/916753\_PEGJHTRTPW4PH9K.png)

当然这是一款比较老的游戏，如今也只有少数痴迷、热爱的朋友在玩。（是不是暴露年龄了？）

## 思路和步骤

### 1.判断软件是基于什么编译系统开发的，并且有无壳的保护

用`PEiD`查看，发现是Dephi开发的，这里就不截图了。我对于Dephi比较陌生，可以说是完完全全的小白，以为什么平台在底层看来其实都无所谓，尤其是从汇编看，所以开始有点盲目的开心和自信了。同时发现，这款反作弊的登陆器居然没有壳；这是令我高兴的，高兴的是，事情又简单了一步，（其实大错特错，这完全属于小白的盲目自信和无知的傻开心）；但又有点小失望，因为我还是想试一下破壳的，可惜这次没遇到机会。

其实`PEiD`仅仅能起到参考作用，因为很多软件的反调试完全可以迷惑`PEiD`的，就是提示是Dephi并不一定真的就是，所以不要认真了。反正代码跟踪就是真么真真假假的。（个人体会）

### 2.熟悉反作弊登陆器的功能，判断反作弊的机制是什么

通过几次使用登陆器确定游戏过程中，反作弊登陆器有截图，并上传服务器的过程，所以推测基本就是依靠截图判断玩家是否使用了作弊器。如下截图：

![](upload/attach/202101/916753\_MUEXCXU2SFHCVJ8.png)

![](upload/attach/202101/916753\_GHCVYF9AHU5K7YA.png)

如果玩家使用了透视作弊，截图是能发现的。熟悉这款游戏的朋友可能问，如果是自动瞄准呢？如果作弊器隐蔽程度很高的话，侦测起来就难了（大佬请提供一下思路）；所以这次，主要是破解软件的截图功能。

了解反作弊机制的目的就是为了方便之后进行代码定位。既然登陆器使用的是截图，那就清楚了，只要跟踪到截图功能的代码就可以了。其实，这样的思路没错，但可能忽视了一个关键问题，那就是截图究竟是登陆器实现的，还是游戏软件自身实现的？我在这个问题上绕了很多弯路，这个问题表面看起来简单，但对于我这小白来说确实是个不小的挑战；因为，登陆器和游戏是两个软件，系统里看是两个进程，这就涉及到两个进程间的通信机制，这个问题就难了。于是，就边做边学，啃了网上很多Windows平台的进程通信方面的资料，跟踪了几处代码，发现都不是，这着实令人头大了。

### 4. 关键的问题：登陆器是如何监护游戏进程，进行截图反作弊的

这是Windows平台进程通信机制的问题，正如前文所述，对于我这技术小白来讲只能查资料，一步步排除，这个过程很繁琐；但，只要明白了几种通信机制的原理，大体可以判断出来用什么实现的。

首先肯定的是，登陆器不能一直打扰游戏进程，不能进行大量的数据通信和处理，因为这会降低游戏进程的效率，这种方式是不可取的，也完全没有必要。所以，一定要通过一种最简单、效率最高的方式进行进程间协作。

其次，进程间主要进行的是图片的操作和处理，这里涉及文件的操作、图片的操作，因此可以从这两个方向进行代码定位。但是，经过跟踪排查，这两个方向均是错误的。

当定位文件操作时，发现Dephi的代码并无明显的文件操作函数，因为我对Dephi不熟悉，跟踪`SaveToStream`函数时，发现并非截图相关代码。这里边走了很多弯路。

而且，Dephi里边有个巧妙的应用，就是窗口函数的跟踪，消息的处理机制虽然底层依然是基于Windows消息驱动机制，但是Dephi做了优化和处理，也就是通过跟踪代码理清消息究竟到了哪个窗口过程，是很不容易的。后来，查了资料，有大佬指出，Dephi的这种机制其实是可以进行代码保护的，就是把窗口函数私有化，即使DDDark也是不容易找到入口的，因此，当初的确小瞧了Dephi和这款软件没有加壳了，不加壳不等于没有反跟踪保护的。

定位File相关函数，如`fopen`、`fwrite`、`fread`等，用WinDbg跟踪拦截均失败，说明显然两个进程之间没有通过文件进行协作的；准确的说，跟踪登陆器进程的文件操作代码，并没有拦截到游戏进程的截图和文件操作；这说明，截图和保存均是在游戏进程中实现的。这个问题就更复杂了，难道是登陆器能够控制游戏进程进行文件操作？这其中的代价有点高吧？

我当初首先想到的是hook，以为登陆器可以hook游戏进程进行截图，但这也是不对的，因为如果是这样的话，游戏进程需要在截图完成后通知登陆器进程进行上传操作，这又是进程间通信，而且hook游戏进程难度较大（并不是说软件作者技术无法实现），而且会带了很多问题。

当时，进行到这里，的确是把我难住了。如果文件函数定位失败，那就换个思路。
