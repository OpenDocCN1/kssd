
# [旧帖][原创]一个软件漏洞的简单利用0.00雪花

## 1. 漏洞的发现

经过尝试，当txt中为1234时，程序正常运行。

为了重现漏洞，所以首先构造了一个很大的文档，但是此时溢出并没有发生，而是在程序运行过程中出现了异常，所以卡到了中间某个地方，不知道是怎么回事。

经过调试，发现卡到了`memcpy`函数，进而可以找到是在`004018C0 F3:A5 REP MOVS DWORD PTR ES:[EDI],DWORD PTR DS:[ESI]`这条语句上，怀疑是由于长度太长所以`edi`所指向的空间已经不允许再写了。

决定换个方向，因为是对话框显示的，所以不会太长。经过测试，发现当文件长度大于12个字节时，就会发生溢出。进一步，在12字节后加4个字节`41613441`，发现发生了溢出，并且`EIP`变成了`0x41346141`，说明这就是溢出点。

![](https://bbs.kanxue.com/upload/attach/201209/466732_g52wf31vor3esdp.png)

![](https://bbs.kanxue.com/upload/attach/201209/466732_xcnvpq9tjedthiq.png)

图1. 溢出点演示

找到了溢出点，用OD调试可以知道是在程序最后一个`ret`时出错。利用IDA对程序进行反汇编，可以看到，程序一共为文件分配了12个字节的空间，当文件内容长度大于12字节时，就会发生溢出。

![](https://bbs.kanxue.com/upload/attach/201209/466732_rgwvmgwcmpdbuhk.png)

图2. 程序分配空间

## 2. 覆盖返回地址

经过上述的分析，我们知道当文件长度为16字节时，最后4个字节即为覆盖地址。利用通用返回地址`7ffa4512`，填充到文件13-16字节，调试成功。

## 3. 写入shellcode

为了尽量满足各个版本系统的通用性，所以我首先写了一个较为通用的shellcode。编写完成后，转化为二进制代码，加入到`jmp esp`后，运行时发现出现了刚开始实验时的现象，看来是shellcode太长了。

经过调试，发现`memcpy`函数最多可以拷贝119个字节，当文件长度大于119字节时，就会因为`[00130000]`不可写而终止。

![](https://bbs.kanxue.com/upload/attach/201209/466732_b4ja6ujq77frlyp.png)
