回到第一题，正如官方wp所说，时间大部分在于逆向上，相比第二题，洞还是很好看出来的。因为这是一道典型金手指式的ctf题，洞因为肯定在金手指附近嘛。
看了下官方wp，基本是打tcache\_struct来获得unsorted bin,个人觉得繁了，毕竟这题是任意add one的金手指啊，个人觉得自己的方法还是不错的。

题目大概意思就是能以老师学生两种身份执行一些功能：老师身份有一个菜单，学生身份一个菜单。审计代码后粗略得到两个结构体：student 和 teacher
```
struct Student
{
Teacher \*teacher;
\_\_int64 unknown;
\_\_int64 pray\_score;
int is\_lazy;
int is\_reward;
\_\_int64 unknown2;
};
struct Teacher
{
int question\_num;
int score;
char \*comment;
\_\_int64 comment\_size;
};
```
学生checkReview函数可以得到金手指：如果分数超过131时可以获得堆地址，还能在任意字节处add one
![图片描述](upload/attach/202204/945391\_ZYB6QEU52ZV6QUU.png)
因此考虑分数，回到teacher giveScore函数，发现is\_lazy为1时可以减10，如果原得分小于10就会溢出。只要question\_num为1原分数一定小于10
![图片描述](upload/attach/202204/945391\_RBMM2X7JRS9URB8.png)

## 解题思路
1. add student时设置question\_num为1，学生身份pray，教师身份giveScore,学生身份checkReview，获得金手指
2. 注意teacher的comment系统，comment在金手指前是有读写权限的，金手指后也有写权限，范围由comment\_size决定。
如果我们扩大comment\_size就可以堆块任意写了，\*\*我们只要在(&comment\_size+n)处addone(n<8)，就可以大幅度扩大这个数\*\*
3. 由于student1金手指丧失了读权限，我们用已知的堆地址对student2一直fake到student2的comment\_size,至此堆块完全可读可写
4. 为了leak libc,我们得拿到unsorted bin，此处我想到两种方式：
+ 比赛时，我先分配一个0x310的chunk，然后和前面一样错位add1变成0x410再释放
+ 比赛后，我发现其实任意写fake就行了
但两种方式都需要辅助一些chunk，让unsorted bin的next chunk是正常的
5. 对student2卸磨杀驴，直接把它的comment指针改成free\_hook写system就行了
可以看出，我的方法基本不用任何堆分配机制，和入门题是一样的
