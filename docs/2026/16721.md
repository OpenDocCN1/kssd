## 0x01.安装Textobot.deb

前置申明，下文`TBROOT`是指本产品的根目录。

`Textobot.deb`就是一个普通的Cydia插件安装包，需要注意的是它依赖`RocketBootstrap`这个插件。所以如果你的手机还没有安装`RocketBootstrap`这个插件，就把`TBROOT/iOS/RocketBootstrap-1.0.7.deb`和`TBROOT/iOS/Textobot.deb`一并拷贝至手机`/tmp`目录，然后依次执行下述命令：

- `dpkg -i /tmp/RocketBootstrap-1.0.7.deb` # 可选，如果还未安装才需要；
- `dpkg -i --force-overwrite /tmp/Textobot.deb`

等安装过程出现“finished, press CTRL+C to exit...”时，就表明`Textobot`正确安装至手机了。我们可以通过如下命令验证`Textobot`的后台服务是否正在运行:

```
iPhone:~ root# ps -ef|grep server
0  5068     1 ... /usr/libexec/hybrage-iserver
0  5070  5068 ... /usr/libexec/frida-server -l 0.0.0.0
```

另外，如果你的`iOS`版本低于`10.0`，则还需要安装`TBROOT/iOS/Util/SimulateTouch-iOS8_9.deb`才可以使用点击、滑动等操作的API。

至此，`iPhone`手机端的环境就部署好了。如果你对`Textobot`手机端的组件也感兴趣，那就接着往下看吧。不感兴趣可以忽略下面的内容直接跳到0x07.下篇再见。`Textobot`手机端一共分为5大部分，如下图：

![](https://bbs.kanxue.com/upload/attach/202001/461021_YF8QB8996D8QF8S.jpg)

1. 管理器`Textobot.app`负责`TB`插件的状态切换，比如`start`、`stop`、`uninstall`等，同时也提供一个简易的`shell`工具；
2. 注入库`textobot.dylib`负责获取进程的状态数据并生成事件汇报给调度器；
3. 启动器`textobot-server`负责启动`Textobot`后台服务，用于重启手机重新越狱之后使用；
4. 注入器`frida-server`负责发送`TB`插件的`JavaScript`代码至指定的进程运行；
5. 调度器`hybrage-iserver`负责整个`TB`插件体系的驱动工作，它自身集成了`Frida`、`Python`等核心模块；

## 0x02.管理器Textobot.app

![](https://bbs.kanxue.com/upload/attach/202001/461021_27SWH4Q5FDA9KV3.jpg)

管理器提供执行/保存/加载`shell`命令、启动/停止/卸载`TB`插件、检查`Textobot`后台服务是否正常运行等功能。

虽然管理器`App`目前还非常原始和不完善，但是在设计理念和功能上，我们是将它对标`CydiaApp`的。

## 0x03.调度器hybrage-iserver

![](https://bbs.kanxue.com/upload/attach/202001/461021_V6V277FKKQBST5Y.jpg)

调度器是`Textobot`的核心驱动，它接受`VSCode`和管理器的`HTTP`请求、注入库的`IPC`事件、控制`frida-server`执行命令等核心任务。

`TB`插件的`Python`代码就执行在调度器中，`TB`插件的`JavaScript`代码由`frida-server`负责发送至`textobot.dylib`所在的进程执行。

## 0x04.注入器frida-server

![](https://bbs.kanxue.com/upload/attach/202001/461021_6D4DBK5P7GXVR6S.jpg)

`Frida`是2015年面世的一个跨平台开源逆向框架，经过将近5年的发展，现在已经非常强大。包括`JavaScritp`代码远程注入、`Native`调用封装等等非常重要的功能，这也是我们选择它作为核心执行引擎的关键原因。

通常的用法是`Frida`客户端跑在电脑端、`frida-server`跑在手机端，`Textobot`为了简化电脑端的部署，我们把完整的`Frida`统一编译进手机端了，这样脱离电脑端一样可以使用`Frida`的完整功能，方便进行`TB`插件管理。关于`Frida`更详尽的信息，请参考它的`github`项目文档和源码。

## 0x05.注入库textobot.dylib

注入库`textobot.dylib`就是一个普通的`deb` `tweak`插件，它是调度器事件源发送者，包括进程启动、退出、`UI`更新等事件都会汇报给调度器，然后由调度器发送给`TB`插件处理。同时注入库还导出了一些实用`API`方便`JavaScritp`调用，比如点击、滑动等`API`。这样一来，我们就可以真正做到只用动态型脚本语言开发具有`deb`一样功能的插件，并且维护、更新方便许多。

## 0x06.启动器textobot-server

最开始是没有设计启动器这个工具的，而是采用了`iOS Daemon`的机制，这样越狱后可以重新自动激活，使用起来更方便。但是，从`iOS 11`开始，系统对后台进程的资源使用限制非常严格，这对于集成了`Frida`、`Python`这样庞大模块的进程而言，进程会因为资源限制而被系统`Terminated Due to Resource`。而通过`root`用户手动启动就没有这个限制，所以为了更稳定的使用`Textobot`服务端，采取了手动启动的模式。如果手机重启重新越狱之后，就需要通过`textobot-server`命令重新启动服务。如果嫌每次连接`ssh`麻烦，推荐使用`TBROOT/iOS/Util/MTerminal-1.4.5.deb`，这样在手机端就可以输入命令，记得装完之后执行`uicache`刷新主界面图标，否则`MTerminal`的图标不会出现在`SpringBoard`界面。
