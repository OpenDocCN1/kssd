# 微软公式编辑器(EQNEDT32)漏洞样本分析

## CVE-2018-0798漏洞分析

公式编辑器存在多个漏洞`CVE-2017-11882`和`CVE-2018-0802`

该样本利用的漏洞为`CVE-2018-0798`

出现漏洞的函数为`sub_443F6C`（无随机基址），该函数内部并没有对参数 `v12` 的长度做限制

![图片描述](upload/attach/201908/830989_QBTKPJFMNEZ346M.png)

从而导致栈溢出

![图片描述](upload/attach/201908/830989_XWHM5U48RVRE5VR.png)

在`OD`里面比较直观，我们可以看到，在长度不限的情况下，我们是可以覆盖到上层函数的返回地址，这样我们便可以劫持到`EIP`，执行我们的`shellcode`

![图片描述](upload/attach/201908/830989_M9Z27MYJUM2UW6Q.png)

然而该样本并没有直接劫持`EIP`跳转到`shellcode`，而是用了下述的方法（该组织的`shellcode`也是相当有意思）

在上述中我们有看到 `sub_443F6C` 函数执行了两次，两次执行后，只是为了构造下面函数的参数

![图片描述](upload/attach/201908/830989_CN9CDEE7DJAJERQ.png)

第4个参数的内容

![图片描述](upload/attach/201908/830989_ES6WAEAYCSDXSTB.png)

我们可以看到`a4`是第4个参数，因此我们可以控制`memcpy`源地址的内容

![图片描述](upload/attach/201908/830989_REV24BAXSF6QG87.png)

通过控制第二个和第三个参数，修改该区域指令为`jmp`短跳，并把想要复制的内容放进来

![图片描述](upload/attach/201908/830989_2MBSSFXSAT8Y4MV.png)

到这里已经淹没了返回地址，一个短小的`ROP`链，还是比较容易理解

![图片描述](upload/attach/201908/830989_BVH63EUNKJYTSAG.png)

继续执行便到了我们刚才复制过去的数据，因为公式编辑器并没有开启`DEP`，所以可以直接执行

![图片描述](upload/attach/201908/830989_GGQFH3RAQW3VVZQ.png)

这里是之前构造的代码，对`eax`进行计算从而跳转到`shellcode`。

![图片描述](upload/attach/201908/830989_V7MUDRA8WUG7F2B.png)

到这里有个疑问，为什么要计算出，`0x45BD3C`这个地址呢？

其实这是一个基址，这个地址里保存的值永远是 `0x12F560`

![图片描述](upload/attach/201908/830989_VYV7EYGS7WEY9GW.png)

而对`0x12F560+0x14=0x12F574` 又进行取值，这里边保存就是我们的`word`程序传入的`buffer`了

取出来的值+固定的`offset`，就是真正的`shellcode`了

![图片描述](upload/attach/201908/830989_KDWHRVK6ZHZ78WE.png)

![图片描述](upload/attach/201908/830989_JSYEZTXNXW65DTZ.png)

## 恶意代码分析之shellcode

之前的介绍中，已经调试到`shellcode`部分

该段`shellcode`首先会通过异或`0xb9`解密自身

![图片描述](upload/attach/201908/830989_V6SD3A4Q8E2GF6H.png)

通过`PEB`的方法，获取`msvcrt.dll`，`kernel32.dll`的基址

![图片描述](upload/attach/201908/830989_GWAWKAGWRR5Y35W.png)

获取`msvcrt`模块的`clearerr`函数地址，并修改其地址属性

![图片描述](upload/attach/201908/830989_ERBUV76SZPDX2N4.png)

进行`inlineHook`

![图片描述](upload/attach/201908/830989_X4BP6QKEG9Z7X5A.png)

`hook`之后，可以传入，字符串从而获取`API`的地址，不是用普通的`GetPorcAddress`

而是调用了`ntdll`的 `LdrGetProcedureAddress`

![图片描述](upload/attach/201908/830989_8C42W4NQREB3SNH.png)

![图片描述](upload/attach/201908/830989_MUM9NM9CZXTBGR2.png)

然后读取临时目录下的`8.t`，并在内存中解密

![图片描述](upload/attach/201908/830989_SR7M2TQ6XMD3GF3.png)

因为当前是调试状态，他会通过`GetModuleFileName`获取当前模块名，并创建一个同名的线程

![图片描述](upload/attach/201908/830989_JYBX6JHRFAMJFRA.png)

傀儡进程技术，写入真正要执行的代码，就是释放的`8.t`，然后`ResumeThread`并结束自身

![图片描述](upload/attach/201908/830989_2Y956VUC4PZQZDQ.png)

![图片描述](upload/attach/201908/830989_W9UBNH6AC9ZRRGN.png)

## 白名单程序分析

如图释放的`exe`为有签名的白名单文件，是一个白利用程序

![图片描述](upload/attach/201908/830989_4HXR7AW6BA3G94F.png)

`wce.dll`是被更改过的黑`dll`，该`dll`获取导出函数`_run@4`并调用

![图片描述](upload/attach/201908/830989_UMHH5JK8PESJFKK.png)

该函数解密域名后会进行链接，`nicetiss54.lflink.com`

![图片描述](upload/attach/201908/830989_CGY8BRCFR7USJEV.png)

发送的数据为 `GET`请求 `image/logo.png`

![图片描述](upload/attach/201908/830989_TVTNM3Z7BSKKCSV.png)

该图片应该是一个`PE`文件，会去执行他的导出函数

![图片描述](upload/attach/201908/830989_YCAP3RE476M5UPP.png))
