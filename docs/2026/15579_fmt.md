经过测试, 有效的校验参数只有`sign`;

根据`r0ysue`的逻辑:

1. 逆向永远要站在开发的思路上解决问题
2. 逆向永远要比开发更底层

so, 任何一个开发都不想单独写个方法混淆字符串, 都是被逼无奈, 所以常规操作, 上来先搜字符串;

`sign`, `"sign"`的结果都太多了, 最后用的是`url`地址`encryptedLineDetail`定位到可以位置;

![图片](https://bbs.kanxue.com/upload/attach/202009/852210_EZJVXMSPC2Z65RE.jpg)

使用`objection`监控第一个`watch`第一个`a`方法:

```bash
android hooking watch class_method dev.xesam.chelaile.sdk.k.b.a.d.a --dump-args --dump-return
```

手动触发请求, 结果如下:

![图片](https://bbs.kanxue.com/upload/attach/202009/852210_KYP7ZBABMB6R7QK.jpg)

返回的是一个`object`, 使用`Wallbreaker`打印对象的内容, 看看`sign`是否已经生成:

查找对应的`object`地址

`plugin wallbreaker objectsearch dev.xesam.chelaile.sdk.f.y`

![图片](https://bbs.kanxue.com/upload/attach/202009/852210_V3XP53UMZXXZZF3.jpg)

打印对应的地址`0x4386`;

![图片](https://bbs.kanxue.com/upload/attach/202009/852210_5D97R43DDM5BPTW.jpg)

直接打印出`sign`的内容了,`a()`方法直接生成了`sign`;

分析一下`a`方法的生成逻辑:

![图片](https://bbs.kanxue.com/upload/attach/202009/852210_HNSGC5C6B9A48F5.jpg)

该类的构造函数`d(Context context, ppVar, z zVar)`调用了`o.a(this.f30583a)`, 返回的结果调用了`getParams()`方法, 跟进去看一下;

![图片](https://bbs.kanxue.com/upload/attach/202009/852210_45XVBS2SAM5RN4C.jpg)

整个加密代码都找到了, `getParams`方法调用了`a()`, 并将结果赋值给了`AppLinkConstants.SIGN`也就是`sign`; `a()`调用了`a(String str, String str2)`进行加密, 参数为时间戳和字符串: `"" + System.currentTimeMillis()`和`woqunimalegebi1234567890`(真的很有素质);

![图片](https://bbs.kanxue.com/upload/attach/202009/852210_BMSPV475847B3VC.jpg)

用`frida`直接`hook`这个方法, 生成时间戳然后调用即可, 请求的时候带上一样的时间戳就可以保证正常请求了;

返回的`response`内容是加密的, 解密位置就在发送请求回调的位置:
