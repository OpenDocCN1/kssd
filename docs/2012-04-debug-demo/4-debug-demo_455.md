> 我也没破完全，不过给你一个我的追踪经验∶
>
> 0\. 使用原版的 `sg.exe` 不要用您修改过的 `sg.exe` (我是用 `win98` 来追的)
>
> 1\. 将 `CALL deviceiocontrol` 後，的 `eax` 改成 `00000000`
>
> 这样就跟您的修改一样了，可是我的这种改法，後续上会有不同的结果
>
> 2\. 设以下的中断你试试看:
>
> ```
> bpx 415e09
> bpx 405040 do "r ip 5133;g 406cea"
> bpx 406cea do "r ip 6cfb"
> ```
>
> 此法设下去，每次中断出来後，就按下 `ctrl+d` 跳出 `sice`，让上述的断点自动修改
>
> 3\. 选择 "神光生命线" <--目前我只追了这个!
>
> 这样竟然就可以显示出支撑点，压力点，不过可以看到，数值太大太大了，有几百亿，所以还是会溢位。

> 不晓得你有没有发现，进入 `sg.exe` 後，会自动生成 `temp.dat` (必须在未结束 `sg.exe` 时，此档才会存在)
>
> 我猜这个东西非常的重要，程式可能有将 `keypro` 内的资料写到 `temp.dat` 内
>
> 要运算的时候在去此 `temp.dat` 找公式来算，所以才会造成溢位!

> 不过这个程式有个极为弱的弱点∶
>
> 如果你有原版 `keypro`，用比对法，就可以抓到哪里的数值不一样!!!
>
> 如果只是 `jz` 或 `jnz` 的差异，那改一改就可解决。如果真如我说，会去读 `temp.dat`，那完了....
