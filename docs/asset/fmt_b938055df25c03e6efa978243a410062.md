
# Asprotect 判断加壳标志

> 原文：[`www.pediy.com/kssd/pediy02/forum213.htm`](https://www.pediy.com/kssd/pediy02/forum213.htm)

## 问题背景

`Asprotect` 判断被其加壳的程序的标志是什么？——答案就在下文中。

### 前言

这次不写作者等无关内容，只希望大家多多交流。

`Asprotect` 是如何判断被其加壳的程序呢？我找到以下一处（可能还有其他地方，未进行更多测试）。

以下是程序代码。找个 `PE` 结构说明一对照，很简单。

```assembly
:0043F85C 8B4034            mov eax, dword ptr [eax+34]     ; 得到 IMAGE_NT_HEADERS 首地址
:0043F85F 05F4000000        add eax, 000000F4
:0043F864 F6400210          test [eax+02], 10               ; 判断字节是否为 10
:0043F868 7403              je 0043F86D                     ; 相同，说明是被其加壳过的程序
:0043F86A B001              mov al, 01
:0043F86C C3                ret
:0043F86D 33C0              xor eax, eax                    ; 设标志
:0043F86F C3                ret
```

## 说明

由于脱壳后的程序一般比原程序大得多，因此一旦把程序脱壳破解后，通常会用压缩软件重新压缩。但是对 `Asprotect` 加壳的程序脱壳后，该标志未改变。若想重新加壳，必须改变此标志。

### 步骤说明

1. 用 `Hex WorkShop` 打开脱壳后的可执行文件。
2. 将光标定位到偏移 `176` 地址处（因为一般 `80` 处为 `PE` 标志：`80 + F4 + 2 = 176`）。
3. 此时加壳过的程序在该位置应显示 `10`，将 `10` 修改为 `00` 即可。
4. 用 `Asprotect` 重新加壳。

## 后记

对已用 `Asprotect` 加壳过的程序不要修改标志，否则 `Asprotect` 再次加壳时会出错。否则，若每个软件作者都用此法多次加壳，将给使用者带来困扰。

相反，也可以改变此标志，使未加壳的程序让 `Asprotect` 误认为已加壳。
