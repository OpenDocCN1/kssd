# 2. 定位崩溃函数

仔细浏览 `Rva+Base` 栏，可以发现第一个比崩溃地址 `0x0040104a` 大的函数地址是 `0x00401070`。因此，在 `0x00401070` 地址之前的那个入口就是产生崩溃的函数，即以下行：

```
0001:00000020      ?Crash@@YAXXZ              00401020 f    CrashDemo.obj
```

发生崩溃的函数是 `?Crash@@YAXXZ`。所有以问号开头的函数名称都是 C++ 修饰的名称（Mangled Name）。在我们的源程序中，它对应的是 `Crash()` 函数。

现在我们已经轻而易举地知道了发生崩溃的函数名称。接下来，我们将介绍更精准的定位方法。

# 3. 定位崩溃代码行

请注意 `MAP` 文件的最后部分——**代码行信息**（Line numbers information），它通常以如下形式显示：

```
13 0001:00000020
```

*   **第一个数字**：代表在源代码中的代码行号。
*   **第二个数**：是该代码行在所属代码段中的偏移量。

若要查找代码行号，需要使用下面的公式进行十六进制减法运算：

$$ \text{崩溃行偏移} = \text{崩溃地址}(\text{Crash Address}) - \text{基地址}(\text{ImageBase Address}) - 0x1000 $$

**原理解释：**

1.  **为什么减去基地址？**
    细心的朋友可能会留意到 `Rva+Base` 栏，我们得到的崩溃地址都是由 `偏移地址(Rva) + 基地址(Base)` 得来的。在计算行号偏移时，需要还原为纯偏移量，因此要减去基地址。一般情况下，基地址的值是 `0x00400000`。
2.  **为什么减去 0x1000？**
    由于一般的 `PE` 文件的代码段通常是从 `0x1000` 偏移开始的，所以也必须减去 `0x1000`。

**计算示例：**

$$ \text{崩溃行偏移} = 0x0040104a - 0x00400000 - 0x1000 = 0x4a $$

浏览 `MAP` 文件的代码行信息，寻找不超过计算结果（`0x4a`）且最接近的数。在 `CrashDemo.cpp` 对应的映射中，最接近的是：

```
16 0001:00000046
```

这表明崩溃发生在源代码的第 16 行。让我们看看源代码：

```
16      i /= j;
```

**结论：**
果然就是第 16 行！

# 4. 总结与应用

方法已介绍完毕。从今以后，我们可以精确地定位到源代码中的崩溃行。只要编译器可以生成 `MAP` 文件（包括 `VC`、`MASM`、`VB`、`BCB`、`Delphi` 等），本方法都适用。

虽然常抱怨 `M$` 产品的质量，但实际上 `M$` 有意无意间提供了很多有价值的信息，只是我们往往不懂得如何利用。通过掌握此方法，你可以更从容地面对“非法操作”提示。甚至你可以要求用户提供崩溃地址，从而在家中舒适地找到出错的那行代码并进行修正。
