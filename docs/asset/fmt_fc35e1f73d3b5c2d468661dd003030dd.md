#### `Vm_IMUL8`

注意结果保存方式，`[esp]`、`[esp+4]`都用了

```
if(flag.Stack){   imul [esp+4],[esp] (OperandSize = 8/16/32 位)}
```

与 `opcode 06` 比较，前者不支持 8 位，只保存结果的低位部分

#### `Vm_DIV`

```
if(flag.Stack){   div [esp+8]:[esp+4],[esp] (OperandSize = 8/16/32 位)}
```

`div` 为 16b/8b,32b/16b,64b/32b,vm 栈上实际有 3 个 `dword`，按需要解释其 `size`，注意计算结果的保存方式

#### `Vm_IDIV`

`idiv` 为 16b/8b,32b/16b,64b/32b,vm 栈上实际有 3 个 `dword`，按需要解释其 `size`，注意计算结果的保存方式

#### `Vm_BSWAP`

```
if(flag.Stack){    bswap [esp] ; (OperandSize = 8/16/32 位)}
```

Bug？从 Intel 手册看，`bswap` 只应对 32 位寄存器使用。Themida 对 8/32 位操作用 `bswap eax`，对 16 位用 `bswap ax`（用 `0x66` 前缀），可能有问题
